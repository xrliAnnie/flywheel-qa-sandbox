③ 数据 / 结构模型(变更合同)
项规格
目标文件README.md(仓根,惰性文件)
操作文件末尾 append 恰好一行,保留结尾换行
行格式issue ID + 用途 + UTC 时间戳(与仓内既有先例同形态)
Commitdocs(FLY-135): append 5-spawn race marker (FLY-SBX-4)
PRbase main,body 链接 FLY-135,test plan 注明 doc-only waiver
FLY-135 5-spawn race marker 20260723T<HHMMSS>Z
时间戳取 implement 执行时刻,保证 5 个并发 sibling(FLY-SBX-1…5)的 marker 行互不相同、可溯源。仓内先例:FLY-1375 land E2E marker 20260722T023540Z
④ 关键取舍与被否方案
  1. 已选README.md 被否CLAUDE.md — CLAUDE.md 会注入每个后续 session 的上下文,反复 append marker 会持续污染所有 agent 的 context;README 是惰性文件且 marker 先例都在这里。
  2. 已选append 单行 @EOF 被否per-issue 独立文件 — 单行 append 改动面最小、review 平凡。已知代价:5 个 sibling 分支顺序 merge 时,第 2 个及以后的 PR 会在 EOF 冲突;行内自带 issue ID + 时间戳使冲突解决(update branch 后重放自己那一行)平凡化。独立文件能消掉冲突,但会改变 QA 套件依赖的稳定 spec,被否。
  3. 已选不写测试 — doc-only 单行 append 无可测行为,PR test plan 显式 waiver;强行加测试违反最小改动原则。
⑤ 诚实边界

✓ 本设计做

  • 定义 implement 节点的单行 append 合同
  • 定义 commit / PR / gate 流程形态
  • 为 5-spawn race 提供可溯源 marker 格式

✗ 本设计不做

  • 不改 QA 套件,不自动化 5-PR 并发 merge 的 EOF 冲突(归 ship 路径所有)
  • 不关闭、不修改 FLY-135 issue(永久保持 open)
  • 不产生任何代码/配置变更
