●关键取舍与被拒方案
采用README.md 末尾追加
已有先例(FLY-1375 等 marker 行就在 README 末尾);README 是惰性文档,追加噪音行零副作用。
拒绝追加到 CLAUDE.md

拒绝每次新建 marker 文件
QA 反复跑会让仓库积攒碎文件,且偏离既有 README 先例。
拒绝空 commit(no-op)
issue spec 明确要求 doc-only content change。
●诚实边界 — 本设计做什么、不做什么
做
  • 给 implementation 节点一个零歧义、可直接执行的一行变更规格(D2)。
  • 保证 5 个并发 Runner 的落点各自唯一、可事后核对。
  • 严守 issue DO-NOT:不关 issue、不改 scope、不引入真实工作。

  • 不动任何代码/配置,不动 CLAUDE.md,不清理 README 单调增长的 marker(sandbox 仓预期形态)。
