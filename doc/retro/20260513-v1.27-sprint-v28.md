## Root Causes

### RC-1: Ship workflow 误关 PR cascade (PR #178)
- **Category**: Tooling Gap
- **Chain**: Ship #177 → delete head branch → GitHub auto-close PRs whose base is that branch (#178)
- **Why?** Ship workflow 没有"check downstream open PRs before delete" 步骤
- **Mitigation**: filed FLY-150 (Discord plugin reconnect replay 同类问题) + memory note 加 "Conservative revert + squash" pattern
- **Status**: 这次手动 revert 救了，未来 follow-up issue 可以加 guard

### RC-2: better-sqlite3 silent compile fail (2 个月暗病)
- **Category**: Configuration Drift
- **Chain**: Node v25 spike (2026-03-06) → `onlyBuiltDependencies: []` 锁死所有 native compile → flywheel-comm (3-22) + inbox-mcp (4-06) 后续加 better-sqlite3 没改 allowlist → FLY-115 加 `pnpm rebuild` workaround 也被 allowlist 拦 = silent no-op → 任何 fresh worktree clone 撞
- **Why?** pnpm 10+ 默认拒绝 native build，allowlist 是 opt-in；spike 时一次性锁死后没人 review
- **Root cause**: **spike commit 应该有 expiration / review note**。短期 workaround 锁死的 config 应该有 "TODO: revisit when X" 注释。
- **Fix landed**: `onlyBuiltDependencies: ["better-sqlite3"]` + `doc/qa/framework/dependency-build-policy.md` 文档化 allowlist 维护规则
- **Status**: 已修 + 文档化 + pnpm 11 迁移路径已 outline

### RC-3: 4-slot QA framework 测不了 multi-Lead cascade
- **Category**: Test Infrastructure Gap
- **Chain**: 每 slot 独立 channel → FLY-152 "shared channel reply discipline" 是 cross-Lead 行为 → framework 物理上无法重现 prod 拓扑
- **Why?** FLY-96 framework 设计时 scope 是 per-Lead 独立测试 (FLY-115 加了 real Runner 但 channel 拓扑没改)
- **Root cause**: 测试 framework 拓扑跟 prod 拓扑 drift 了
- **Fix landed**: FLY-153 mirror mode — 3 Leads (cos/product/ops) 共享 `#test-core-mirror` channel + TEST OVERRIDE banner 条件性保留 channel-scoped rules
- **Status**: 已修 + smoke verified
