## What Didn't（教训）

### D-1: CI lint 漏跑全仓（只跑 test + 按文件 biome）
FLY-224 ship 前我跑了 test + 按**文件** `biome check --write`，**漏跑全仓 lint** → CI 挂在 lint 步（`LeadInputRouter.test.ts` 两处 `noAssignInExpressions`）。
**教训**:ship 前 **lint + typecheck + test 三个都跑,而且跑全仓不按文件** —— 和"只跑子集会漏全套"同一个道理（同轮 dashboard.test.ts 没-leads 崩也是只跑 lead-backends 子集漏的）。

### D-2: Belle repoint 漏了
companion Lead 上线后，Mufasa 切 Codex 时 Belle 的 repoint/收尾有遗漏（运维侧补）。
**教训**:多 Lead 同类操作要逐个核对清单，别只盯当前 issue 的那一个。

### D-3: Runner 自动继承 Lead 模型这点没提前讲清
FLY-241 per-agent 模型开关：Runner **自动继承 Lead 模型**是设计行为，但 apply 到 Fable 全队时这点容易被忽略（Lead 改 model，Runner 跟着变）。
**教训**:模型/配置这类"会向下传染"的开关，apply 时要显式说明传染范围。

### D-4: 实现者只跑子集就报"测过"
两次（lint 漏、dashboard 崩）都是因为只跑了改动相关的子集就以为绿。全套跑才暴露。
**教训**:声明"测过/可 ship"前跑 CI 同款全量（lint + typecheck + 全 test）。

## Key Learnings

1. **跑全量,不跑子集** —— lint、test 都一样;子集绿 ≠ 全绿。
2. **架构残留正确归 issue,别硬塞 scope** —— 冒用完整 per-Lead auth = Bridge 认证模型重构 → FLY-246;founder action path → FLY-245。fail-close 是 interim 安全,不假装"修好了"。
3. **真机 cutover 先求零生产侵入** —— direct 出站 + 隔离 CODEX_HOME + 无-pane 看门狗跳过 = 第一次测不碰生产。
4. **fail-closed 设计真机验过才算数** —— Mufasa 配额耗尽时"宁可不回也不发坏"是真机验证的安全行为,不是空谈。
