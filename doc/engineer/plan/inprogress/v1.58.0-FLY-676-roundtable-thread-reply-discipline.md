# Plan: Roundtable thread 回话纪律 — 活跃参与者『在 thread 即跟』

**Version**: v1.58.0 (tentative — re-version at ship)
**Issue**: FLY-676 ([bug] roundtable thread 内 requireMention 卡断一来一往)
**Date**: 2026-06-29
**Source**: Brainstorm gate (Tadashi approved 方向 + 选 A), codebase audit
**Status**: codex-approved (Codex design review 4 rounds: R1 CHANGES → R2 CHANGES → R3 CHANGES → R4 APPROVED)

## Problem / Root cause (verified)

在 `#leads-roundtable` 的 topic thread 内,对**兄弟 Lead(bot 作者)**仍要求每句显式 `@`,导致两个 Lead 在同一 thread 来回时,只要某句没 `@` 对方,另一方就收不到 → 一来一往断掉。

证据链:

- 生产 `~/.flywheel/.env`:`FLYWHEEL_ROUNDTABLE_REPLY_IN_THREAD=1`(开),但 **`FLYWHEEL_ROUNDTABLE_THREAD_AUTOCONTINUE` 未设** → `autoContinue=false`。
- **Claude 插件** `external_plugins/discord/roundtable-thread-policy.ts::decideTopicThreadHandling` 第 (2) 步:`if (!cfg.autoContinue) return { handle: input.isExplicitMention }` → bot 作者在 thread 内永远需要 `@`。
- **Codex 侧** `packages/teamlead/src/lead-backends/codex/mention-gate.ts`(`buildMentionGate` 的 `isDynamicThread` 分支)+ `codex-lead-runtime.ts:594`(`autoContinue = env... === "1"`)同款:`autoContinue` off → `return isMentioned(...)`。Mufasa 有同款潜在 bug。

复现路径:Tadashi 顶层 `@` Asha 开头 → Asha 回(被 `@` → 是 thread member)→ 之后双方不带 `@` 的后续被 drop → 断。

## Goal

让 thread 的**活跃参与者**(member = 被顶层 `@` 拉进来过 / 发过言,Discord 自动加成员)默认**跟着 thread 走**、不需要每句被 `@`;非 member 维持顶层 `requireMention`(决定『要不要插进这个话题』,不变);保留 FLY-220/FLY-576 防回环/防 melee 的**硬熔断**(有界 budget)。

两条 backend 路径(Claude 插件 / Codex)行为对齐(vendor-neutral)。

## Design (Tadashi approved — Option A for member-follow + Option B for Codex proactive initiator)

reply-gate 判定加『我是不是这个 thread 的活跃参与者』:

| 情形 | 行为 |
|------|------|
| **member** bot,thread 内 | 跟 thread(免每句 `@`),受有界 budget 约束 |
| **非 member** bot,thread 内 | 维持 `requireMention`(显式 `@` 给一次回复,不开放自由续聊) |
| human(founder/operator) | 已有 FLY-576 默认放行(member 免 `@`),不变 |

**防回环 backstop(选 A)**:保留有界 per-thread per-lead budget,但**默认值从 2 提到 12**;budget 在 human 消息时重置(已有逻辑)。→ 自然多轮对话不触顶(human 在 loop 里就一直重置);bot-bot 死循环仍有硬上限(≤ budget/lead),FLY-220 不复发;FLY-576 防群聊乱回的天花板保住。

**默认开 + kill-switch**:把 member-follow 从现在的 `autoContinue` 显式 `=1` opt-in 改成**默认开**(沿用 FLY-569 给 `replyInThread` 默认开的先例),env `FLYWHEEL_ROUNDTABLE_THREAD_AUTOCONTINUE=0` 作 kill-switch 回退到旧 mention-required 行为。

## Exact changes

### A. Claude 插件 (`xrliAnnie/claude-plugins-official`)

**`external_plugins/discord/roundtable-thread-policy.ts`**

1. 新增导出常量 `export const DEFAULT_ROUNDTABLE_THREAD_BUDGET = 12`。
2. `loadRoundtableConfig`:
   - `autoContinue` 默认开:`const autoContinue = env.FLYWHEEL_ROUNDTABLE_THREAD_AUTOCONTINUE !== "0"`(原 `=== "1"`)。
   - `budgetN` 默认用常量:`... ? rawN : DEFAULT_ROUNDTABLE_THREAD_BUDGET`(原 `: 2`)。
3. `decideTopicThreadHandling` — bot 路径重构(self / human 分支**完全不动**):
   ```
   // (2) BOT author.
   // member-follow:仅当 autoContinue 开(默认)且 membership 已证实为 member 时,
   //   放松 @ 要求,改由有界 budget 收敛。@ 也消耗 budget、绝不绕过;missing=exhausted。
   if (cfg.autoContinue && input.isMember === true) {
     const remaining = store.budgets.get(input.threadId) ?? 0
     if (remaining > 0) { store.budgets.set(input.threadId, remaining - 1); return { handle: true } }
     return { handle: false }
   }
   // 其它一切(非 member / 未知 membership / autoContinue off=kill-switch)→ requireMention。
   //   这与当前生产(autoContinue off → 所有 bot 走 isExplicitMention)字节一致。
   return { handle: input.isExplicitMention }
   ```
   **唯一行为变化 = member bot**:从『每句需 @』→『budget-follow 免 @』。

   **非 member / 未知 membership 行为 = 当前生产字节一致**(`isExplicitMention`),且**不依赖 `autoContinue`** —— 即 FLY-676 不引入任何新的非-member 回话面。这点直接回应 Codex R1#1:autoContinue-ON 下非-member 的判定与 autoContinue-OFF 完全相同,不存在『从 fail-closed 变成 passthrough』的新侧门。

   > 与旧 autoContinue-ON 代码(`if (isMember !== true) return false`,会把被 @ 的非-member 也 drop)相比,这是**一次正确性修正**而非放松:`@` 一直是顶层显式门(顶层频道的 `@` 从来不计 budget),所以 thread 里被 `@` 的非-member 给『一次回复』与顶层语义一致、也正是 prompt 规则(cross-dept-channel-rules.md 121-125『mid-thread @ … pings them for that one reply』)承诺的行为。被 budget 收敛的只是**免-@ 的 member 续聊**(真正的 relaxation),它**要求 proven membership**(`isMember === true`),unknown/非-member 一律退回 `@`-required → fail-closed on the relaxation。

`shouldProbeTopicThreadMembership` 无需改:`autoContinue` 默认开后,bot 路径返回 `true` → 探测 membership(member-follow 决策需要)。membership 探测有 `rtMemberThreads` 缓存(200 后缓存,后续不打 API)→ 每 thread 仅首次付一次 5s-bounded 探测,成本可忽略。

4. **Initiator-seed(回应 Codex R2#1 — 否则发起者听不到回复)**:发起 top-level topic 的 Lead 会 self-skip 自己的顶层消息 → 永不 seed 本地 budget → member-first budget path 会把兄弟的第一条回复(连显式 `@`)drop。修复 = 在**出站发到 roundtable parent**(= 发起一个 topic,thread id == 发出消息 id)时 seed initiator budget:
   - 新增纯谓词 `export function shouldSeedInitiatorBudget({ sentToChannelId, cfg }): boolean`(`cfg.autoContinue && sentToChannelId === cfg.channelId`),单测覆盖(沿用 `shouldProbeTopicThreadMembership` 的 pure-seam 模式)。
   - `server.ts` reply handler:`sendReplyChunks` 成功后,若 `shouldSeedInitiatorBudget({ sentToChannelId: chat_id, cfg: RT_CFG })`,对返回的 `sentIds`(未来 thread id)逐个 `seedThreadBudget(rtBudget, id, RT_CFG.budgetN)`。这是薄胶水(像 1417 行的入站 seed)。
   - **restart-safe**:进程重启丢失该 seed;发起者不会重发顶层 → 不会误 re-seed → 重启后该 thread 回到 mention-required(= FLY-314『missing = exhausted』安全侧),与既有契约一致。

**`external_plugins/discord/server.ts`**:仅新增 initiator-seed 薄胶水(上 §4);判定逻辑仍全在纯策略模块。

## Anti-loop 安全论证(保住 FLY-220 / FLY-576)

承重论证(不依赖任何未证实的平台契约):

- **免-@ member 续聊由 budget 硬界**(每 lead per-thread ≤ 12),只能被 human 消息 / 新顶层话题重置 → bot-bot 免-@ 死循环 ≤ budget 步终止。这是 FLY-676 **新引入**的免-@ 路径的唯一收敛来源,已用 budget 钉死。
- **Initiator-seed 也是有界事件**:发起者在出站发顶层时 seed 一次(N),与被 addressed 方对称;两边都只在『真正发起/参与一个新 topic』时 seed,bot 续聊照样被各自 budget 收敛。重启丢 seed → 安全侧(回 mention-required),不放大循环。
- **非 member 永不被无 `@` 卷入** → 『活跃参与者而非所有人』scoping。
- **非 member / `@` 路径 = 当前生产字节一致**:今天生产跑 autoContinue=off,所有 bot thread 消息已走 `isExplicitMention`(无 budget)。FLY-676 **不改这条路径**,故相对生产**未新增**任何 bot-bot 回话面;其收敛由 `@`-per-message 要求(与顶层频道同款、顶层从来无 budget)+ prompt 纪律(不回自己 / 只实质补充 / 自然安静)治理,与今天一致。
- kill-switch(`=0`)一键回退到 ship 前 mention-required。

次要(**非承重**)缓解:一个在 thread 内发言的 bot 通常被 Discord 自动加为 thread member,之后其判定转入 budget 路径自收敛。Codex R1#1 指出该自动加入是平台契约、repo 内无证明 —— 故本计划**不让安全性依赖它**;它只是额外的收敛加成。真机 QA(529 Room)会顺带观测此行为但不作为 ship 门槛。
