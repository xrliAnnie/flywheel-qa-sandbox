## 4. `notion.sh` 设计

`#!/usr/bin/env bash` + `set -euo pipefail`，header 注释块（Usage + 子命令 + env seam），风格对齐 `video-watch/scripts/gemini-watch.sh`，**shellcheck 零豁免**。依赖：`curl` + `jq`（启动检查，缺则 fail-closed 报错）。

### 4a. Token 解析（`resolve_token`）+ 测试 seam
解析顺序：
1. `$NOTION_TOKEN` env 非空 → 用（为 phase-2 MCP / 显式 export 留口）。
2. 否则解析 `${NOTION_ENV_FILE:-~/.flywheel/.env}`：匹配 `^[[:space:]]*(export[[:space:]]+)?NOTION_TOKEN[[:space:]]*=`，取**最后一条**，trim 外层引号 + CR + 前后空白。**不 `source`**（避免对任意文件副作用执行）。
3. 否则 legacy `${NOTION_LEGACY_TOKEN_FILE:-~/.config/notion/api_key}`（首行 trim）。
4. 否则 → stderr 报错 + 指向 `notion.sh setup` + `exit 1`（fail-closed，绝不静默、绝不打印 token）。
- **seam**：`NOTION_ENV_FILE` / `NOTION_LEGACY_TOKEN_FILE` 让测试注入 temp file，绝不碰真实 `~/.flywheel/.env`（Codex R1#3）。

### 4b. 子命令（薄封装；curl 抽成 `_notion_api`；JSON 一律 `jq -n --arg` 构造）
| 子命令 | Notion API | 用途 |
|--------|-----------|------|
| `check` | `GET /v1/users/me` | preflight：验 token + 列 integration |
| `search "<q>"` | `POST /v1/search`（jq 构造 body） | 找页面/库 |
| `databases` | `POST /v1/search` filter object=database | **discover 兜底**：列可访问库 |
| `database-info <db_id>` | `GET /v1/databases/<id>` | 看库结构（含是否已 multi-source，Codex R1#5） |
| `query <db_id> [filter_json]` | `POST /v1/databases/<id>/query` | 查库；filter_json 先 `jq -e .` 校验 |
| `new-note "<title>" [body]` | `POST /v1/pages`（parent=Notes 库，jq 构造） | 记 idea |
| `append <page_id> "<text>"` | `PATCH /v1/blocks/<id>/children`（jq 构造） | 日记 append |
| `raw <METHOD> <path> [json]` | 透传；json 先 `jq -e .` 校验 | 逃生口 |
| `setup` | 见 §6 | 写 token |

- **JSON 构造（Codex R1#6）**：所有含任意文本（title/body/text/filter）的 payload 用 `jq -n --arg x "$x" '...'` 构造，绝不 shell 字符串拼接 → 引号/反斜杠/换行/中文/emoji 安全。user-provided JSON（`query` filter、`raw` body）发送前 `jq -e .` 校验，非法即 fail-closed。
- headers：`Authorization: Bearer <token>`、`Notion-Version: 2022-06-28`、`Content-Type: application/json`。
- 非 2xx：打印 Notion error body（含 `code`/`message`）+ `exit 1`。
- **测试钩子**：`NOTION_DRY_RUN=1` → `_notion_api` 打印 `METHOD URL`（token 脱敏）+ body 而不发网络 → 断言。

### 4c. Notion API 版本策略（Codex R1#5）
v1 **故意 pin `Notion-Version: 2022-06-28`**（与现有 local command + 复用 integration 一致）= intentional legacy compatibility，**非最新**（最新 2026-03-11；2025-09-03 起 database/data_source 拆分）。failure mode 写进 `databases`/`query`/`new-note` 错误说明：若目标 DB 已变 multi-data-source，旧 `database_id` parent/query 可能失败 → 用 `database-info` 诊断，迁 `data_source_id` 留 follow-up。文档不暗示这是最新 shape。

## 6. Setup（安全红线，Codex R1#2/#3）
- `notion.sh setup`：**交互式 `read -rsp` 从 TTY 读 token**（或 `--stdin` 管道）；**绝不接受 token 作 positional arg**（不进 shell history / argv / process list）。
- 流程：把 candidate token **直接注入 `_notion_api`** 做 `check`（GET /v1/users/me）——**验证 candidate、不是 `resolve_token` 当前结果**（防误验旧 token 却写坏新 token）。check 通过才 upsert，失败则不写 + 报错。
- upsert `~/.flywheel/.env`：`umask 077` + 写 temp file + 原子 `mv`；**拒绝 symlink** env file；保持/设 `0600`；替换已有 `NOTION_TOKEN=` 行（不重复）。**全程不回显 token**，只显示验证结果 + 写入路径。
- **Runner 红线**：实现/测试期绝不 `cat`/`cp`/echo Annie 的 `~/.config/notion/api_key`、绝不把真 token 写进 `.env`。真 setup 由 Annie/Tadashi 执行。

## 7. TDD 测试计划（RED → GREEN → REFACTOR；零网络/零真 token；全用 seam + temp file）
1. token 解析:env 优先;`.env` 解析含 `export NOTION_TOKEN=`、`NOTION_TOKEN = `(空格)、引号、CR、多行取最后一条;legacy fallback;全缺失 → exit≠0 + 错误指向 setup。
2. 每个子命令 → 正确 METHOD+URL+headers+body(dry-run 断言)。
3. JSON 边界(Codex R1#6):title/body/text 含 `"`、`\`、换行、中文/emoji → jq payload 合法;`query` filter / `raw` body 非法 JSON → fail-closed。
4. `new-note` parent=Notes 库 id;`append` 指定 page。
5. 非 2xx(mock)→ 打印 error + exit≠0。
6. `setup`(Codex R1#2/#3):token 走 stdin/`NOTION_SETUP_TOKEN_FILE` fixture 非 argv;candidate check 失败 → 不写;**旧 token 可用 + candidate bad → 不写**;成功 → 原子 upsert 替换已有行、0600、不回显、不重复;symlink env file → 拒绝。
7. `jq`/`curl` 缺失 → 启动 fail-closed。
8. shellcheck 干净(CI 门③)。
9. SKILL.md contract 本地断言:description 含触发词、≤350、无 over-broad 词;body 含 setup 命令 + token 解析顺序 + discover。
