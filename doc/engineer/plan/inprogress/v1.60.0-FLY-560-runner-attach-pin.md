# Plan: Runner tmux-attach 命令置顶（FLY-560 Feature C）

**Version**: v1.60.0 (tentative — ship 时按 batch 重定)
**Issue**: FLY-560
**Date**: 2026-06-27
**Source**: Linear FLY-560（scope 收窄后）, brainstorm gate `btdzz5cbd`（Tadashi APPROVED A–E + machine-aware）
**Status**: codex-approved（design review round 2 APPROVED；round 1 的 6 项全 fold）

---

## Goal

在每个 `[FLY-XX]` Discord chat thread 里 **post + 置顶**一条 `tmux attach -t <session>` 命令。Annie 复制即可在 terminal attach 到该 issue runner 的 tmux session（看/救卡死的 runner）。runner 变化（重起/换 backend）时自动更新置顶命令；runner 结束后命令失效（可接受 —— 那时也不用 attach）。

**Scope**:Feature A（emoji 前缀）已 ship、Feature B（状态板）已砍。本 plan 只做 Feature C。

## 背景事实（审计 + 实测确认）

- `[FLY-XX]` thread 由 `ChatThreadCreator`（`packages/teamlead/src/bridge/ChatThreadCreator.ts`）创建。Feature A 在 `event-route.ts::stampStageEmojiForSession`（`stage_changed` 事件，handler 在持久化 stage 后重新 `getSession` 拿到完整 session）盖 emoji —— 本 feature 复用同一挂点。session 含 `execution_id` / `project_name` / issue 身份 / title / labels。
- runner 的 tmux 权威来源 = **CommDB 的 `tmux_window`**（如 `runner-flywheel:@46`，格式 `<session>:@<id>`），封装在 `tmux-lookup.ts::getTmuxTargetFromCommDb(execId, projectName)`（返回 `{ tmuxWindow, sessionName }`）。`StateStore.tmux_session` 生产不可靠，不用。
- cmux 给每个 runner 窗口建 **linked session `cmux-<window_name>`**（`scripts/flywheel-cmux-sync.sh` `VIEW_PREFIX="cmux-"`，且用 `=` 精确匹配 target）。**实测**:窗口 `runner-flywheel:@46`、`window_name=FLY-560-claude-Discord-issue-title-emoji-board-cmu` → cmux session `cmux-FLY-560-claude-Discord-issue-title-emoji-board-cmu`。
  - 它正好落在该 runner 窗口、与共享 base session 隔离、**名字跨重起稳定**（`window_name`=issueId+runner+title 不变，而 `@id` 每次重起都变）→ 适合做置顶命令的 attach 目标。
- **Discord pin API（实测 + 文档核对）**:pin 已从 Channel Resource 迁到 Message Resource。
  - 新（canonical）:`PUT /channels/{channel_id}/messages/pins/{message_id}`，需 **`PIN_MESSAGES`** 权限，成功 = 204。实测该 route 存在（无权限时 403；`GET /channels/{id}/messages/pins` 返回新分页结构 `{items, has_more}`）。
  - 旧（deprecated 但仍可用）:`PUT /channels/{channel_id}/pins/{message_id}`（需 `MANAGE_MESSAGES`）。**不用**（不从 deprecated route 起家）。

## 设计决策（gate 已拍 + Codex round1 修订）

| 决策 | 选定 |
|------|------|
| A) attach 目标 | `cmux-<window_name>` linked session（**精确 `=` 匹配**）+ base-session fallback |
| B) 更新机制 | 原地 **edit** 置顶消息；命令没变且**已确认 pin** 才幂等跳过（见 pin 状态机） |
| C) feature flag | `FLYWHEEL_ISSUE_ATTACH_PIN` **独立** flag（与 emoji 的 `FLYWHEEL_ISSUE_STATUS_EMOJI` 互不耦合）；默认 ON |
| D) demo-first | 已发 product-lead-test（见下「demo 状态」） |
| E) bot 权限 | pin 用**新** endpoint → 需 **`PIN_MESSAGES`**；QA 实测确认哪种 grant 解 403 → 部署前提 |
| 多机未来 | 命令拆成结构化 `<可选 ssh 前缀> + tmux attach -t <session>`；现单机只渲染后半段，留扩展点 |

## 组件 & 文件

1. **`packages/teamlead/src/bridge/tmux-lookup.ts`** — attach 目标解析:
   - `resolveCmuxAttachTarget(tmuxWindow): Promise<AttachTarget>`:
     - `display-message -p -t '<tmuxWindow>' '#{window_name}'` 取 window_name（实测可行）；
     - cmuxSession = `cmux-${windowName}`；`has-session -t '=cmuxSession'`（**`=` 精确**，实测 absent 报 "can't find session"）；
     - 命中 → `{ kind: "cmux", session: cmuxSession }`；未命中 → `{ kind: "base", sessionName, tmuxWindow }`。
     - tmux 任何 indeterminate 错误（timeout/ENOENT）→ 返回 base fallback（绝不假装 cmux 在）。
   - `buildAttachCommand(target, opts?): string` —— machine-aware:`opts.sshHost`（**现不传**，预留前缀拼接），渲染**精确 `=` target**:
     - cmux: `tmux attach -t '=cmux-<window_name>'`；
     - base fallback: `tmux attach -t '=<base>' \; select-window -t '=<base>:@<id>'`（degraded：会改共享 base session 的当前窗口，文档标注）。

2. **`packages/teamlead/src/bridge/chat-thread-utils.ts`** — Discord 封装（沿用 5s AbortController 模式）:
   - `pinThreadMessage(threadId, messageId, botToken)` → `PUT /channels/{threadId}/messages/pins/{messageId}`（**新 endpoint**）。返回 `{ ok, status }`:204/2xx=ok；403=缺权限（仅日志、不 throw、不记 pinned）；404=消息没了（上层据此重发）。

3. **`packages/teamlead/src/bridge/ChatThreadCreator.ts`** — 主逻辑 `ensureRunnerAttachPin(ctx, threadId, command)`:
   - **per-thread 串行链**（仿 `stampChains`，防并发双 POST / 乱序）。
   - 读 `store.getChatThreadAttachPin(issueId, channelId)` → `{ messageId, command, pinnedAt }`。**pin 状态机**:
     | 状态 | 动作 |
     |------|------|
     | 无 messageId | POST message（含命令代码块 + `allowed_mentions:{parse:[]}`）→ 存 messageId+command（pinnedAt=NULL）→ pin → 成功则写 pinnedAt |
     | 有 messageId + command 变了 | PATCH message 内容（`allowed_mentions:{parse:[]}`）→ 更新 command；保留/补 pin（pinnedAt 没有就 pin） |
     | 有 messageId + command 同 + **pinnedAt 已记** | 全跳过（零 churn、零 Discord 调用） |
     | 有 messageId + command 同 + **pinnedAt = NULL**（上次 pin 失败） | **retry pin**（幂等 PUT）→ 成功则写 pinnedAt（**= 权限补好后自愈**） |
     | PATCH/pin 返回 404（消息被删） | **同一 serialized 调用内**清 messageId+pinnedAt 并立即重发 POST+pin（不等下个 stage；Codex round2 澄清点 → 定为 repost-now） |
   - 全 fire-and-forget；5s AbortController；任何失败不阻塞 stage transition。

4. **`packages/teamlead/src/StateStore.ts`** — 持久化:
   - `chat_threads` 加列 `attach_pin_message_id TEXT`、`attach_pin_command TEXT`、`attach_pin_pinned_at TEXT`（幂等 ALTER TABLE，仿 `migrateChatThreadsArchivedColumn`；老 DB ALTER、新 DB CREATE 里直接带）。
   - `setChatThreadAttachPin(issueId, channelId, { messageId, command, pinnedAt })` / `getChatThreadAttachPin(issueId, channelId)` / `clearChatThreadAttachPin(...)`。

5. **`packages/teamlead/src/bridge/event-route.ts`** — 挂点:
   - 新增 `pinRunnerAttachForSession(deps, session)`:解析 lead/channel/token + thread（同 `stampStageEmojiForSession`），`getTmuxTargetFromCommDb` → `resolveCmuxAttachTarget` → `buildAttachCommand` → `ensureRunnerAttachPin`。tmux_window 没解出（runner 还没注册）→ 静默 return（下个 stage reconcile）。
   - `createEventRouter` 签名加**显式独立** gate（不再靠"传不传 creator"耦合）:`{ chatThreadCreator, issueStatusEmojiEnabled, issueAttachPinEnabled }`。stage_changed handler:emoji 段 gated by `issueStatusEmojiEnabled`、attach 段 gated by `issueAttachPinEnabled`，各调各的。

6. **`packages/teamlead/src/bridge/plugin.ts`** — flag 接线:
   - `issueAttachPinEnabled = process.env.FLYWHEEL_ISSUE_ATTACH_PIN !== "0"`。
   - `chatThreadCreator` 传进 router 的条件改为 `chatThreadsEnabled && (issueStatusEmojiEnabled || issueAttachPinEnabled)`；两个 boolean 一并传入。**四组合**全干净（emoji/attach 各自 on/off 互不影响），字节兼容 Feature A。

## Failure modes / edge cases

- **tmux_window 还没注册**(首个 stage 太早):`getTmuxTargetFromCommDb` 返回 undefined → skip；下个 stage reconcile。
- **cmux 没跑 / linked session 不在 / tmux 探测 indeterminate**:fallback 到 base-session+select-window 命令（degraded，文档标注）。
- **pin 403（缺 PIN_MESSAGES）**:message 已 post（命令可见），pinnedAt 不记 → **下个 stage 自动 retry pin**；权限补好后自愈（无需 command 变化）。不 retry 循环（只在每个 stage 边界各试一次）。
- **并发 stage_changed**:per-thread 串行链保证只 POST 一次 message。
- **Bridge 重启**:messageId+pinnedAt 存 DB → 重启后不重复发；pinnedAt 已记则跳过、未记则补 pin。
- **消息被手删**:命令不变 + pinnedAt 已记 → 不主动探测（bounded，避免 GET-every-stage）；若发生在 pin 未确认期，下轮 PUT 撞 404 → 清记录重发。命令一旦变化也会经 PATCH 404 重发。**接受的退化**:已 pin 成功后被手删，要等命令变化或 runner 变化才重建。
- **runner 结束**:命令失效，attach 报「session not found」—— 设计接受。

## 部署前提（QA 必验）

- 生产每个 lead bot 需在其 chat channel 有 **pin 权限**，否则 pin 403。demo 已证 test bot 缺权限（新旧 endpoint 都 403）。
  - **权限名歧义（QA 实测拍板）**:新 endpoint `/messages/pins/` 按 Discord 新文档要求 **`PIN_MESSAGES`**（2025 新拆出的独立权限）;旧 endpoint 用 `MANAGE_MESSAGES`。Discord 常对新拆权限做 grandfather，`MANAGE_MESSAGES` **可能**也满足新 endpoint，但未实测确认（bot 现两权限都没有）。
  - **建议**:给 bot role 同时加 `MANAGE_MESSAGES` + `PIN_MESSAGES`（trusted bot，最稳）;QA 实测确认新 endpoint 在该 grant 下解 403（204）。
  - 权限改动 = Discord access-control，**由 Annie 加（或 setup 脚本）**，实现 runner 不自改。

## 多机扩展点（不实现，仅留）

`buildAttachCommand` 结构 = `<sshPrefix><attachCmd>`。未来多机:`sshPrefix = "ssh <tailscale-host> -t '"`、attachCmd 末尾补 `'`。**session 长在 runner 所在机器**;跨机需把 runner host 落库（可后续在 `tmux_window` 注册时一并记 host）。本期不做。

## Test plan（TDD）

**单元（vitest）**:
- `tmux-lookup`:`resolveCmuxAttachTarget` —— cmux 命中/未命中→fallback / indeterminate→fallback；window_name 含特殊字符。`buildAttachCommand` —— cmux 形（`=` 精确）、base fallback 形、machine-aware `sshHost` 前缀拼接。
- `ChatThreadCreator.ensureRunnerAttachPin`（mock fetch + store）—— **pin 状态机全分支**:首发 POST+pin 204+记 pinnedAt；`POST ok → pin 403 → 存 message 不记 pinnedAt → 下轮同 command → pin 204 → pinnedAt 记上`（自愈）；command 同 + pinnedAt 已记 → 零 Discord 调用；command 变 → PATCH；PATCH/pin 404 → 清记录重发；并发两调用只 POST 一次（串行链）；POST/PATCH 都带 `allowed_mentions:{parse:[]}`（title 含 `@everyone` 断言不解析）。
- `pinThreadMessage`:URL 精确断言 = `/channels/{id}/messages/pins/{id}`（防回退 deprecated route）。
- `StateStore`:三列迁移幂等（老 DB ALTER、新 DB CREATE）；set/get/clear round-trip。
- **flag 四组合 reverse-compat**:emoji-on+attach-off / emoji-off+attach-on / both-on / chat-threads-off —— 各自只跑该跑的、Feature A 字节兼容。
