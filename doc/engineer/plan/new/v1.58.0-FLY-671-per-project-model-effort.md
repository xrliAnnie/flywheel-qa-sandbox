## 1. Goal & Context

省钱（cost savings）。Annie 要能 **per-项目（per-Lead + per-runner）** 设更便宜的 model（Sonnet/Haiku）和更低的 reasoning effort（high/medium 而非 xhigh），便宜够用的项目降下来。本 issue 只做 **per-项目/Lead 静态配置**；『按任务动态路由模型』是另一个 feature，不在此。

### 已 verify 的现状（纠正 issue 两处假设）

| 项 | 现状（已核） |
|----|------|
| 生产 Lead model | **不是** account-default —— 全部显式钉在 `claude-opus-4-8[1m]`（Opus 1M, FLY-360）。Mufasa = Codex（model null）。所以「降 Sonnet」= 把值改成 `claude-sonnet-4-6`。 |

### 架构决策（brainstorm gate 已拍 = 方案 1）

Runner 的 model/effort 来源 = **沿用现成 `roles.runner`**（项目 `.flywheel/config.yaml`），新增 `roles.runner.effort`。「runnerModel 从项目配置 resolve」字面已满足（`roles.runner.model` 就是项目配置，FLY-241 全队铺 Fable 即此机制）。**runner 是 token 大头**（干重活、数量多）→ `roles.runner` 的 model/effort 是最大省钱杠杆，确保清晰可设。
- **不做** follow-lead 自动继承（runner 跟发起 Lead 的 fleet model）—— 多 Lead/项目时「跟哪个 Lead」是真设计问题，留 **follow-up**。

## 3. Byte-compat 不变式（贯穿全 PR）

每个新字段 **absent ⇒ 行为逐字不变**：
1. `LeadConfig.effort` 不设 → manifest 无 `effort` → plist 无 `FLYWHEEL_LEAD_EFFORT` → `claude-lead.sh` 对非-companion 不发 `--effort`（argv 逐字不变）。**companion 仍钉 `--effort xhigh`**（FLY-583 sentinel 必须绿）。
2. `roles.runner.effort` 不设 → `runnerEffort` undefined → runner 无 `--effort`（现状）。
3. `CLAUDE_TIER_OPTIONS` 加项 = **扩大** `allowedModelTargets` 白名单 → 旧值仍合法（reverse-compat）；不缩小、不改顺序语义（仅追加）。
4. fleet change record 加可选 `effort` 维度 → 只带 `model` 的旧 change 仍合法（effort 维度 **absent** = 不动 effort，见不变式 6 三态）。
5. 显式 effort **覆盖** companion 默认：companion 设了 `effort` 用设的值；未设 → xhigh（现状）。
6. **effort 的三态语义（Codex R1 BLOCKER-3）**：change 的 `to.effort` 有三个语义态 —— **absent**（键不存在）= 不动 effort（保留现值）；**`null`** = 删字段/回 account 默认；**string** = 设。shell 侧 **禁止** `jq '.to.effort // null'`（会把 absent 与 null 合并 → 旧 model-only apply 静默删 effort）；必须用 `has("effort")` 区分 absent。同理 `from.effort` 仅在 `from` 显式带 effort 时纳入 baseline 校验。
7. **Codex backend out-of-scope（Codex R1 BLOCKER-4）**：effort 白名单 **backend-aware** —— Claude = `[null,low,medium,high,xhigh,max]`，Codex(`codex-app-server`) = `[null]`（display-only，chip readonly，route 拒非-null effort 转换），镜像 `computeAllowedModelTargets` 对 Codex 的处理。`codex-lead.sh` 不接 `--effort`。

## 5. Implementation — Part B（Per-Lead effort 端到端）

**effort 常量放在低层模块，不能反转依赖（Codex R1 MEDIUM-7）**。今天 `fleet-capabilities.ts` 从 `ProjectConfig.ts` import `LeadConfig` 类型（bridge 依赖 config，不反向）。若把 `EFFORT_LEVELS` 只放 `bridge/fleet-capabilities.ts` 再被 `ProjectConfig.ts` import，会让核心 config 解析依赖 bridge UI 代码。

→ **新建低层模块** `packages/teamlead/src/lead-effort.ts`（与 `ProjectConfig.ts` 同层、无 bridge 依赖）作运行时白名单单一真相：
```ts
export type LeadEffort = "low" | "medium" | "high" | "xhigh" | "max";
export const EFFORT_LEVELS: readonly LeadEffort[] = ["low","medium","high","xhigh","max"];
export const isLeadEffort = (v: unknown): v is LeadEffort =>
  typeof v === "string" && (EFFORT_LEVELS as readonly string[]).includes(v);
```
- `ProjectConfig.ts` 和 `fleet-capabilities.ts` 都 import 它（依赖方向正确：bridge→低层，config→低层）。
- `packages/config`（runner 侧，跨包）保留**本地副本** `RoleEffort`/`ROLE_EFFORT_LEVELS`（同集），避免 config 包依赖 teamlead 包（FLY-123 既有跨包边界）。

`fleet-capabilities.ts` 提供 console 选项 + **backend-aware** 白名单：
```ts
import { EFFORT_LEVELS } from "../lead-effort.js";
// effort chip 选项：null = 默认（companion→xhigh / 其它→account 默认）
export const EFFORT_OPTIONS: readonly TierOption[] = [
  { id: null, label: "默认" },
  ...EFFORT_LEVELS.map((e) => ({ id: e, label: e })),
];
// Codex effort chip readonly（display-only，与 model 一致）
export const CODEX_EFFORT_OPTIONS: readonly TierOption[] = [{ id: null, label: "默认", readonly: true }];
export function computeEffortOptions(backend: LeadBackendId): readonly TierOption[] {
  return backend === "codex-app-server" ? CODEX_EFFORT_OPTIONS : EFFORT_OPTIONS;
}
export function computeAllowedEffortTargets(backend: LeadBackendId): Array<string|null> {
  // 镜像 computeAllowedModelTargets：Codex 只有 null（不可切），Claude = levels ∪ {null}
  return backend === "codex-app-server" ? [null] : [null, ...EFFORT_LEVELS];
}
```
- 并入 `computeLeadCapabilities` / `LeadCapabilities`：加 `effortOptions` + `allowedEffortTargets`（backend-aware）。
