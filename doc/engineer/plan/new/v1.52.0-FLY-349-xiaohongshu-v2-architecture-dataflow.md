## 0. 锁定前提（Annie 已拍）

- **接入方式 = #4**：预下载本地 → 离线并行分析。**温和串行 fetch**（Annie 明确接受"比较慢的那种"）。

- **signed-API（#3）默认 off**：first-run 真嫌慢再议（动 Annie 真账号，带月坏维护 + 封号代价）。
- **否决** #1（不存在）/#2/#5（不破天花板 + 崩机/封号）/商用（隐私+成本）。

## 1. 端到端数据流（producer-consumer）

```mermaid
flowchart TD
  subgraph S0[Stage 0 · 准入 单 Runner]
    L[acquire-lease 复用] --> LG{load gate<br/>load 高→降档/暂停}
  end
  LG --> S1

  subgraph S1[Stage 1 · PRODUCER 串行·单浏览器·token-fresh·温和]
    M[get_collection_content<br/>→ 元数据 noteId/title/type/xsecToken] --> D[xhs-state diff<br/>first-run=全量 / recurring=增量]
    D --> LOOP[每条 note 顺序:]
    LOOP --> FD[get_feed_detail MCP<br/>~60s retry-after-idle]
    FD --> DL[立刻下媒体 token<15min<br/>图 sips→png / 视频 yt-dlp 720p]
    DL --> ND[(per-note 目录<br/>detail.json+imgs/+video)]
    ND --> BP{queue 背压<br/>count+bytes 任一超→阻塞}
  end
  BP -->|有空位| Q[[bounded queue]]

  subgraph S2[Stage 2 · CONSUMER 池·离线·无 MCP/token·load 节流]
    Q --> W1[worker: 读 per-note 目录<br/>gemini 读视频/读图 + 文本蒸馏 → keyPoints]
    Q --> W2[worker ...]
    W1 --> PR[(per-note 结果 JSON<br/>modalRead+keyPoints+judgment)]
    W2 --> PR
    PR --> CL[删该 note temp 目录]
  end
  PR --> S3

  subgraph S3[Stage 3 · AGGREGATOR 串行·单点·所有副作用]
    COL[收齐 per-note 结果] --> JC[judge + enforce first_run_cap]
    JC --> CI[串行 auto-create issue<br/>Linear MCP·opId 幂等·provenance·triage 落点 复用 FLY-286]
    CI --> AS[(AnalysisStore run schemaVersion:2<br/>posts[]+summary 复用+扩)]
    AS --> DV[deliver review 页 复用]
    DV --> MP[mark-processed 仅成功条<br/>失败/降级→pending 复用]
  end
  MP --> S4

  subgraph S4[Stage 4 · 异步 下一 tick 复用 FLY-286]
    DV --> WL[web-local review 页] --> FS[(FeedbackStore)]
    FS --> FC[feedback-consume<br/>close 仅本-op untouched / promote / 学标准]
  end

  MP --> FIN[set-next-due + release-lease + complete no_code 复用]
```

**一句话**：串行温和 fetch+即下（守天花板）→ bounded queue 背压 → 离线并行分析（只产结果 JSON、零副作用）→ 单一 aggregator 串行收口（建单/存/交付/mark）→ 异步 feedback。**Stage 1 是安全瓶颈（接受慢），Stage 2 是并行加速点，Stage 3 是安全收口。**

## 2. 各 Stage 数据契约（输入→输出，desk 定）

| Stage | 角色/并发 | 输入 | 处理 | 输出（数据 artifact） | 触碰外部？ |
|-------|-----------|------|------|----------------------|-----------|
| 0 | 单 Runner | 触发参数 + state | 取 lease + 读 load gate | 持有 lease | lease 文件 |
| 1 PRODUCER | **串行 1 个** | collection_id | `get_collection_content`(元数据) → diff → 逐条 `get_feed_detail` + 即下媒体 | **per-note 目录**（§3.1） | 🔴 是（RedNote MCP + cdn 下载，温和串行，唯一碰 xiaohongshu 的地方） |
| 2 CONSUMER | **bounded 池**（video/img-text 分档，§load） | per-note 目录 | gemini 读视频/读图 + 文本蒸馏 → keyPoints 精提取 | **per-note 结果 JSON**（§3.2）→ 删 temp | 仅 Gemini（离线，无 xiaohongshu、无 token） |
| 3 AGGREGATOR | **串行 1 个** | 全部 per-note 结果 | judge + cap + 建单(幂等) + 组 run + 交付 + mark | **AnalysisStore run**（§3.3）+ Linear issues + review URL | Linear MCP（串行、幂等、founder 边界不变） |
| 4 异步 | 下一 tick | FeedbackStore | close/promote/学标准 | state 更新 + memory | Linear MCP（受限 close） |

> 🔴 **副作用单点（codex R1#4，本设计核心不变量）**：只有 Stage 3（+Stage 4）碰 Linear/state/交付；Stage 2 worker **绝不**建单/写共享 state/交付——只产 per-note 结果 JSON。这样既拿并行速度又保 FLY-286 的 cap/幂等/owner-fence 正确性。

## 3. 数据 artifact 形（concrete schema）

### 3.1 per-note 临时目录（Stage 1 产，Stage 2 消费后删；**不进持久层**）
```
$WORKDIR/notes/<noteId>/
  detail.json   # {noteId,title,desc,comments[],imageUrls[],videoInfo?,xsecToken,type}
  imgs/<n>.png  # sips 转换后（webp→png）
  video.mp4     # 仅 video_opt_in，yt-dlp -S res:720 --max-filesize 200M
```
- 生命周期：该 note 的 Stage 2 结果 commit 后**立即删**（封顶磁盘）。崩溃 → 下轮按 `runToken` 清残留。**raw 媒体字节绝不进 AnalysisStore。**

### 3.2 per-note 结果 JSON（Stage 2 产 → Stage 3 聚合；worker 的唯一产物）
```jsonc
{
  "noteId":"...", "type":"video|normal",
  "mediaKinds":["text","image","video"],
  "rawCounts":{"images":4,"videoSeconds":15},     // 下了多少，非 bytes
  "modalRead":{ "text":"正文/评论蒸馏", "images":"读图结论", "video":"Gemini 读视频结论(video-grounded)" },
  "keyPoints":["对 Flywheel 有用的可执行点 1","2"],  // 精提取
  "judgment":{"useful":true,"reason":"..."}
}
```

## 5. 两模式数据流差异（同管线，按量自动选档）
- **first-run**（`bootstrapped=false`→`analyze_baseline`）：Stage 1 全量 diff（125），Stage 2 点燃并行池（保守并发，§load），Stage 3 受 `first_run_cap` 建单。一次性 ~2h 温和 fetch（Annie 接受），后台/分批。
- **recurring**（`bootstrapped=true`）：Stage 1 增量 diff（每周 5-10），量小 → Stage 2 走低并发/串行（不背 first-run 复杂度），Stage 3 同。几分钟。
- 选档：引擎读 `bootstrapped` + diff 的 `new` 数（`new ≤ 阈值` → 轻量；`>` → 并行池）。

## 6. 负载安全在数据流里的挂点（🔴 宁慢勿崩，desk 定值、实现/first-10 校准）
- **Stage 0 load gate**：起跑前读 `uptime`，高于阈值 → 推迟/降档。
- **Stage 2 分档并发**：video 与 image/text 并发分开；first-10 video=1 / back-apply 起步 2 / 硬顶 4（详见主 plan §4.3）；滞回 ramp-down；每条超时。
- **Stage 1↔2 背压**：queue count + bytes 双约束，封顶磁盘 + 在制品。
- **kill switch**：`FLYWHEEL_XHS_PARALLEL=0` 退纯串行。
- 详细曲线/阈值 = first-10 实测表（主 plan §7）推导，**不在 desk 阶段拍死数字**。

## 7. 错误 / 崩溃恢复（复用 FLY-286 fail-soft）
- Stage 1 某条抓取/下载失败（flaky/超时）→ 留 pending、不前移 processed，下轮重试。
- Stage 2 某条 Gemini 超时 → 该条降级（图文+文字、标注未读视频）、pending。
- Stage 3 建单/交付前崩 → 下轮经 opId marker reconcile（不重复建）；mark-processed 仅在交付成功后。
- temp 目录崩溃残留 → 下轮按 runToken 清。

## 9. v2 设计增补（Phase-1 实战发现 + Annie 迭代要求）

> 这些在 Phase-1 spike + full-flow 验证 + Annie review 中定下，覆盖/补充前文。实现轮按此走。

### 9.1 Gemini 接入（覆盖原"gemini CLI `-p @file`"，Phase-1 F1；🔁 实现期安全审查再次修正）
- gemini **CLI 的 OAuth 路已死**（IneligibleTierError，Google 弃用个人 Code Assist client）→ 不能用 `gemini -p "@file.mp4"`。
- 实现期安全审查曾就 `agy`（带工具/fs 的智能体 CLI）在不可信内容上用 `--dangerously-skip-permissions` 提出 prompt-injection→工具执行风险。
- 🔵 **Annie 的最终决定（已拍，lead-instruction 737653df）= agy（免费 Google Pro, gemini-3.1-pro）作默认主路，不加 sandbox**。她的理由:这些笔记是她**亲自看过+收藏+人工 review 过**的(非随机抓取),injection 风险她 own + 接受。安全审查已向她明示,她知情接受。
- **付费 Gemini File API = fallback**:仅当 agy auth/失败时切,切时 notify Lead(~$0.05/note)。
- **保留 #1 参数注入修复**(noteId/token/url 校验 + `--` 终止符):零成本纯防御,不影响免费路,留着。
- **load gate（硬约束）**：宁慢勿崩（load>30 绝对暂停 + 滞回）；load 不可测时 bias-to-pause（不崩不盲跑）。

### 9.2 🔴 手机可访问的交互式 review 页（Annie 要求，3bfcaeef）
- **痛点**：Annie 不守 Mac，要手机上 review/留意见。
- **约束（已实证）**：① `publish-report` 托管路径 **strip 交互**（CSP + sanitize <script>）→ 交互页变空壳；② web-local 是 **localhost**，手机够不着。
- **候选方案（v2 finalize 时定）**：
  1. **安全隧道**：`cloudflared`/`tailscale funnel` 把 Bridge 的 web-local review 路由（FLY-286）暴露成临时 HTTPS URL → 手机可开、保留 same-origin POST 写后端。成本低，按需起隧道。
  2. **真托管 review app**：小型公网服务（Vercel/自建）+ 写后端 + token 鉴权 + founder-consent（= FLY-298 的范畴）。成本高、有公网写面。
  3. **statically.io/gist** 托管交互页（JS 真跑）+ 写回走隧道/公网后端。
- **倾向**：先 **方案 1（隧道）** —— 复用 FLY-286 现成 web-local 路由（先得启用 `FLYWHEEL_XHS_REVIEW`）、最小新面、按需开关。FLY-298 的公网写后端作长期。
- 当前迭代仍用**自包含本地 HTML**（不急），v2 finalize 设计进去。

### 9.3 🔴 保留策略 = C（Annie 定，217d5eb3 + e2ec4a92；覆盖原"全部即删"）
- **值得建 issue 的笔记**：保留 **caption/文本 + 视频转录（speech→text）+ 关键帧截图**。
- 🔴 **存哪儿（e2ec4a92 定，覆盖之前"content store"）**：**直接存进对应的 Linear issue**（attachment / comment），**不进 repo、不另设独立 content store**。理由：repo 干净（self-host 单写者纪律）+ 留存物**跟 issue 走、实现时可追溯**。→ 即 "content store = Linear issue 本身"。
- **非 issue 笔记**：删 raw（省盘）。
- **raw video 不默认留**；只有 Annie 手动标"重要"的才留完整视频。
- → Stage 3 aggregator 建/留 issue 时，把 retention artifacts 作 comment/attachment 写进该 issue；§4.1 的"用完即删"改为"**issue-worthy → 留存物进 issue；非 issue → 删 raw**"。
- **full-flow 验证已按此做**（FLY-352/353/354/356/358 各有一条 `📎 Retention` comment：caption（已取到的）+ Gemini 深读文本；关键帧/作者名/完整转录待 MCP 重登后补，125 正式跑按完整 C 存）。

### 9.4 MCP 健康（Phase-1 893c6db8）
- xiaohongshu MCP 登录是**账号级 session**：Annie 在别处（她 Chrome）登同一小红书账号会**踢掉 MCP 的 session**（实测：跑着跑着变"未登录"→ fetch 返空）。**不是** Chrome-profile 共享问题（MCP 用自己的隔离 headless Chromium）。
- **建议**：① **MCP 用专用小红书账号**（与 Annie 个人账号分开）→ 她日常用小红书不再踢自动 fetch；② run 前先 `check_login_status`，未登录就 **alert Annie 重扫 QR**（`get_login_qrcode`），**绝不静默空跑**当成"没新帖"。
- run 前 MCP 必须 healthy（已登录）——否则 125 fetch + 新鲜 token 链接都失败。

### 9.5 原帖链接格式（Phase-1，给 review 页/issue 用）
- 可打开格式：`https://www.xiaohongshu.com/explore/<id>?xsec_token=<token>&xsec_source=pc_feed`（缺 token 会跳登录页，打不开）。token 有时效 → review 页同时给"复制标题在 app 内搜"兜底。run 时现抓的新鲜 token 才可靠。
