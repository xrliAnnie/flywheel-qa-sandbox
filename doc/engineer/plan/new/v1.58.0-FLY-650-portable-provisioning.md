## 1. 一句话方案

linux=systemd --user，含 service/timer/path 三类单元，container→FLY-652），配置**物理

## 2. 设计原则

1. **核心 = 平台无关**；2. **核心/项目物理分开（D2=B）**；3. **字节兼容 / 默认零变化**
（darwin 后端 == 今天行为；host.json 全字段默认值 = 今天写死值；旧 manifest 当 darwin
默认；reverse-compat sentinel 覆盖 **plist 渲染 + wrapper env**，不只新 API）；
4. **保留 FLY-519 红线**（secret-scan 含 host.json、dry-run 默认、token gate、
idempotent、双实例守卫、事务 journal）；5. **简单优先**；6. **为产品化留地基**（清晰
两份配置 = 之后向导/GUI 落点，本 issue 不做 UX 层）；7. **真跑可运行（D3=B）**

### 3.1 配置物理分家（D2=B）+ host-config 契约

两份**运行时**配置物理分开：

| 文件 | 角色 | 谁碰 | 内容 |
|---|---|---|---|
| `~/.flywheel/projects.json`（已存在，**不动**） | **项目配置** | 用户（最终经向导） | 项目名册：projectName/projectRoot/projectRepo/leads[]/generalChannel/linear/memoryAllowedUsers。 |
| `~/.flywheel/host.json`（新增） | **核心/host 配置** | 安装时/运维（最终经安装器） | platform / supervisorBackend / flywheelDir / stateDir / skillsRepo / viewerBackend + 预留 leadEnablement（§3.6）。 |

**host-config 契约（新 `scripts/lib/host-config.sh`，必要时 TS 加载器）—— 回应 R1#3：**
- **missing host.json = 文档化默认值**（= 今天写死值：flywheelDir=`$HOME/Dev/flywheel`、
  stateDir=`$HOME/.flywheel`、skillsRepo=`xrliAnnie/flywheel-skills`、
  supervisorBackend=按平台推导、viewerBackend=darwin:`cmux`/linux:`tmux-only`）。
- **malformed JSON / 类型错 / 未知 backend = fail-closed**（不静默回退默认，防启动错
  checkout）。**未知字段** = 忽略但 warn（向前兼容 follow-up 加字段）。
- **路径展开**：`~` / 相对路径按 `$HOME` / cwd 明确规则展开；只接受非 secret 字段。
- **导出契约**：统一 `FLYWHEEL_DIR`、`FLYWHEEL_STATE_DIR`、可选 `FLYWHEEL_HOST_CONFIG`，
  **所有脚本**（daemon / bridge-wrapper / restart-services / lead-wrapper / capture）
  一致 source 这个 lib，消除今天写死 `~/Dev/flywheel` 的不一致 + 让 env 完整传播进
  launched 进程（Bridge 用 host config 时 Lead wrapper 不能还用旧路径）。
- **委托 plist/unit 渲染消费 host config**：committed aux plist 里的绝对
  `/Users/xiaorongli/...`（`scripts/launchd/com.flywheel.bridge.plist`、
  `com.flywheel.updater.plist`）改为渲染期注入，darwin 渲染默认值逐字等于今天 →
  **reverse-compat sentinel 测 darwin 无 host.json 时 Bridge/aux/Lead plist 输出字节不变**。
- **capture**：fleet-capture.sh 把 host.json 一并快照，且过同一 staged
  `scan_for_secrets` gate（红线）。
- **演进（本 issue 不做）**：两份清晰边界 = 之后傻瓜 setup 向导/GUI 的数据落点。

### 3.2 Supervisor seam（D1=A）+ service-spec 层（回应 R1#1）

新 `scripts/lib/supervisor.sh`，**先有 service-spec 层再有后端**。一个被管单元声明：

```jsonc
{ "name": "flywheel-bridge", "kind": "service",  ... }      // 常驻
{ "name": "updater",         "kind": "path",    "watch": "<queue dir>" }  // 队列/路径触发
{ "name": "daily-standup",   "kind": "timer",   "schedule": "<cal>" }     // 定时
{ "name": "skills-update",   "kind": "timer",   "schedule": "<cal>" }
{ "name": "cmux-watcher",    "kind": "service", "darwinOnly": true }      // 仅 mac
```

统一接口：`supervisor_backend / install <spec> / start / stop / restart / status /
is_loaded`。后端按 host.json `supervisorBackend`（或 `uname`）选：

- **darwin 后端** = 包住已有 launchd 机制（`flywheel-daemon.sh` / `restart-services.sh`
  / launchctl），各 kind 映射回今天的 plist 形态（service=KeepAlive、
  timer=StartCalendarInterval、path=QueueDirectories）→ **零行为变化**，现有测试全绿。
- **linux 后端** = `systemctl --user`：
  - kind=service → `<name>.service`（含 per-lead 服务）；
  - kind=timer → `<name>.service` + `<name>.timer`（OnCalendar）；
  - kind=path → `<name>.service` + `<name>.path`（PathExistsGlob / DirectoryNotEmpty，
    对应 launchd QueueDirectories 的 updater self-ship 唤醒）；
  - `darwinOnly` 单元在 linux **跳过**（cmux-watcher）；
  - 渲染类比现有 plist `__HOME__` sed；`systemd-analyze verify` 类比 `plutil -lint`；
  - `loginctl enable-linger`（开机自启、登出不停）—— runbook + preflight 覆盖。
- **container 后端** = `supervisor_backend` 认 `container`，install/start 走
  foreground/process-supervisor —— 本 issue **只留接口 + fail-loud 桩**（"not
  implemented, see FLY-652"）。
- 枚举要装的辅助单元：bridge / per-lead / updater(path) / daily-standup(timer) /
  skills-update(timer) / cmux-watcher(darwinOnly)。**xiaohongshu** 当前是 guarded
  pilot → 默认**不装**，host.json/flag 显式开启才装（避免 Linux 装上不该跑的）。
- provisioner `phase_launchd` 泛化为 `phase_supervisor` 调抽象；`phase_validate`
  loaded 检查走抽象。hermetic 测试断言 linux 渲染出 `.service`/`.timer`/`.path` 且
  enable 正确。

### 3.3 平台化 deps（回应 R1#5）

manifest `deps[]` 升级为归一化 schema：

```jsonc
{ "name": "jq", "required": true,
  "platforms": {
    "darwin": { "channel": "brew", "formula": "jq" },
    "linux":  { "apt": "jq", "dnf": "jq" } },
  "check": { "command": "jq", "version": "--version" } }
```

- 旧单层 `channel/formula` 经 normalize 函数当 **darwin-only** 解析（向后兼容旧
  manifest）。
- `phase_deps` 按平台 + 包管理器（apt/dnf 探测）装；支持 **present-check-only**
  （node/pnpm 走 nvm/corepack 时只校验存在、不强装）；pnpm 走 `corepack enable` +
  verify；**AI CLI（codex/claude/kimi/agy）+ cmux** = manual，给清晰手动安装诊断
  （它们不映射 brew/apt 单字段）。cmux 标 darwin-only。

### 3.4 Viewer 后端开关 + Linux 可见性规则修订（回应 R1#4）

**冲突**：项目硬规则（FLY-398）= production Codex Lead/Runner 必须 **windowed/可见于
cmux、绝不 headless**；但 dispatch 路径今天总是 wire `openTmuxViewer`
（`run-dispatcher.ts`），`openTmuxViewer` 排 osascript（macOS 专属）。Linux 无 cmux。

- 新 `host.json.viewerBackend`（或 env `FLYWHEEL_TERMINAL_VIEWER`）取值
  `cmux | terminal-app | tmux-only | none`；`onTmuxWindowCreated` / dispatch 的
  viewer 接线按它 gate（缺省 darwin=`cmux`=今天行为，linux=`tmux-only`）。
- **显式规则修订（写进 runbook + plan）**：Linux/WSL2 host 上 production 可见性 =
  `tmux attach` / Windows Terminal 手动 attach（`tmux-only`），**这是对"绝不 headless"
  规则的 Linux 显式修订** —— 不是悄悄改。⚠️ **需 Tadashi/Annie 点头**：Annie 选 D3=B
  跑 Linux 时已隐含接受 Linux 无 cmux；本 plan 把 viewer 故事写成 `tmux-only`（仍可
  attach 看，非真 headless），如需别的 Linux viewer 方案请指出。
- runtime 改动最小：只在 viewer 接线处 gate，不重写可视化逻辑；osascript 路径
  darwin-only（已是 best-effort，linux 不触发）。

### 3.5 Clean-host Lead materialization（回应 R1#2，新 WI）

**问题**：今天 provisioner **不**自动装 Lead 服务，因为 Lead manifest 由首次
`claude-lead.sh` 运行生成、wrapper 缺 manifest 即 fail（`flywheel-lead-wrapper.sh`），
provisioner 只 narrate 手动序列。D3=B「真跑通」要从 projects.json **确定性**到可跑
Lead 服务，不能靠运维即兴。

- 新跨平台命令 **`materialize-lead-manifests`**（读 projects.json → 写每个 Lead 的
  canonical manifest，**不启动**任何未托管的重复 Lead 进程），或给 `claude-lead.sh`
  加 `--write-manifest-only` dry 路径。
- 之后 `supervisor install lead` 确定性从 manifest 装服务（darwin=daemon install /
  linux=systemd unit）。
- 若刻意保留"首次手动跑"模型：runbook 给每 Lead 精确命令 + linux 后端**测 missing-
  manifest 失败路径**。
- 新 WI 覆盖此项 + hermetic 测试（projects.json → manifests，无重复 Lead 启动）。

### 3.6 预留 leadEnablement（fail-loud；回应 R1#7）

- host.json `leadEnablement` 本 issue = **docs-only 预留块 + 校验**：absent/空 = 今天
  行为（projects.json 全部 lead 都起）；**非空 = fail-loud**（"not implemented; see
  follow-up issue"），**不做**静默无效 read（避免看着像支持其实没接线）。
- 保留 absent=全起测试；follow-up issue 接线"按 enablement 选起哪些"。
