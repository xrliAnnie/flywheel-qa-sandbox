## Background — 纠正 issue 前提

Issue 假设「Opus 4.8 是 ~200K,有一个单独的 1M-context 变体」。审计后(claude-api 权威目录)实情:

- **`claude-opus-4-8` 本身就是 1M context、标准定价 `$5/$25` per MTok、无 long-context 溢价。**
- 所谓「1M 变体」**不是另一个 API 模型**,而是 **Claude Code CLI 的有效窗口选择器**:model id `claude-opus-4-8[1m]`。
  - 不带 `[1m]` → Claude Code 把有效上下文窗口压到 ~200K(= Annie pane 看到的 `Opus 4.8/xhigh`、ctx 70-82% 频繁逼近压缩的默认行为)。
  - 带 `[1m]` → 真用满 1M context。
- **启用方式 = `--model claude-opus-4-8[1m]`,不需要 beta header。**(本 issue 的 runner 自己就跑在这个 id 上,实证。)

所以「让 Lead 跑 1M」= 让该 Lead 的启动模型 id = `claude-opus-4-8[1m]`。

## Mechanism — per-Lead 模型链路已就绪

FLY-241 + FLY-247 已建成完整的 per-Lead 模型机制,单一真源 = `~/.flywheel/projects.json` 的 `leads[].model`:

```
projects.json leads[].model
  → manifest (~/.flywheel/manifests/<project>-<lead>.json) .model
  → launchd plist EnvironmentVariables FLYWHEEL_LEAD_MODEL   (flywheel-daemon.sh / flywheel-fleet.sh)
  → claude-lead.sh: FLYWHEEL_LEAD_MODEL 非空 → CLAUDE_ARGS += (--model <id>)   (FLY-241)
```

该链路对带方括号的 id **全程已接受**,无需改动:
- `ProjectConfig.ts` 的 `lead.model` 校验只挡 NUL/C0 控制字符(`/[\u0000-\u001f\u007f]/`);`[`/`]`/`1`/`m` 全是可打印字符 → 通过。
- `flywheel-daemon.sh generate_plist_to`:`xml_escape` 处理,方括号非 XML 特殊字符 → 安全。
- `claude-lead.sh`:bash array + 引号传 `--model "<id>"` → 安全。

当前 12 个 production Lead **全是 default(`model` 字段缺省 = 账号默认 = 200K-窗口的 Opus 4.8)**。

## Gap — 唯一缺口在 FLY-247 fleet console

FLY-247 把 fleet console(Dashboard + `flywheel-fleet.sh` CLI)做成模型管理的单一入口。其可选模型档由 `packages/teamlead/src/bridge/fleet-capabilities.ts` 的 `CLAUDE_TIER_OPTIONS` 定义:

```ts
export const CLAUDE_TIER_OPTIONS: readonly TierOption[] = [
  { id: "claude-fable-5", label: "Fable 5" },
  { id: null, label: "Opus 4.8" },   // account default = 200K 窗口
];
```

没有 1M 档。后果:

1. **授权缺口(限 Bridge/console stage API)**:`computeAllowedModelTargets(backend)` 由 `CLAUDE_TIER_OPTIONS` 派生 → console 的 `allowedTargets()`(`fleet-console.ts` → `buildSnapshot()` → `lead.allowedModelTargets`)在 `fleet-routes.ts::handleStage` 发 token 前做 server 端 fail-close 校验。没有 1M 档 → **经 Dashboard / Bridge stage API** 切 1M 会被拒。
   - **注意(Codex R1 纠正)**:`scripts/flywheel-fleet-batch.sh` 只把 `to.model` 校验成 `string|null`,`scripts/flywheel-fleet.sh apply` 直接读 `projects.json` 的 desired model —— **shell CLI 侧没有 model-id 白名单**。所以 `CLAUDE_TIER_OPTIONS` **只授权 Fleet Console / Bridge stage API**;CLI batch engine 和直接 `flywheel-fleet.sh apply` 是 **trusted local 执行路径**,过了 config/baseline 闸后结构上接受任意可打印 model 串(也不会拒 `[1m]`)。本 PR **不**新增第二层 shell 白名单(那会改变信任模型,非本 issue 目标)。
2. **显示缺口**:即便直接手编 `projects.json` 写入该 id,console 的 `modelLabelFor` 找不到匹配 tier → 退回显示裸 id `claude-opus-4-8[1m]` 而非友好 label。

## Goal

让 1M 成为 fleet console 的**一等可管模型档**,使 Annie 能用现有 console/CLI 把任意 / 全部 Lead 切到 1M(显示友好 label + 授权该 id 为合法 `to.model`)。**本 PR 只 ship 使能代码 + 测试 + rollout runbook;不翻任何生产 Lead 配置、不重启任何 Lead**(那是 restart-gated 部署,Annie 拍哪些 Lead、搭下次 cutover 做)。

## Change — 最小代码改动

### `packages/teamlead/src/bridge/fleet-capabilities.ts`

`CLAUDE_TIER_OPTIONS` 增加一档:

```ts
export const CLAUDE_TIER_OPTIONS: readonly TierOption[] = [
  { id: "claude-fable-5", label: "Fable 5" },
  { id: "claude-opus-4-8[1m]", label: "Opus 4.8 (1M)" },
  { id: null, label: "Opus 4.8" },   // account default (~200K window)
];
```

这一处改动**自动流经**全部下游(无需改别处):
- `computeTierOptions("claude-code")` → Dashboard tier chips 多出「Opus 4.8 (1M)」。
- `computeAllowedModelTargets("claude-code")` → `allowedTargets()`(**仅** console / Bridge stage route 的 server-side 校验,见上文 Gap-1 的 Codex 纠正)授权 `claude-opus-4-8[1m]`。
- `fleet-console-model.ts::modelLabelFor` → 设了该 id 的 Lead 在 console 显示「Opus 4.8 (1M)」。
- 前端下拉(`fleet-console-html.ts`)直接渲染 `tierOptions`,无额外 allowlist → 新档自动出现。

**同步更新该文件顶部的 canonical model facts 注释**(现写「Fable 5 + Opus 4.8 account default」),补充区分:`Opus 4.8`(account default,~200K 有效窗口)vs `Opus 4.8 (1M)`(显式 CLI 选择器 `claude-opus-4-8[1m]`,1M 窗口)。

注意现有不变量保持:`computeAllowedModelTargets` 末尾 `null` 去重逻辑不受影响(列表里已含 `null`),Codex 后端仍 `[null]`(只读 GPT-5 不受影响)。

### 为什么 NOT 改 `claude-lead.sh` 默认值

不把「无 `FLYWHEEL_LEAD_MODEL` 时默认 `claude-opus-4-8[1m]`」写进 `claude-lead.sh`,因为:
- 破 **FLY-231 reverse-compat sentinel**(unset 时 argv 必须字节不变,T8 golden 无 `--model`)。
- 破 **vendor-neutral**:Codex 后端 Lead(Mufasa)不吃 `--model claude-...`;硬编 Claude id 会污染 Codex 启动。
- 绕过 FLY-247 的 per-Lead 单一真源,夺走 Annie 的逐 Lead 控制。

## Cost / Speed 分析 + rollout 建议(报 Tadashi → Annie 签)

- **成本(美元)**:Opus 4.8 的 1M context **无 per-token 溢价**(标准 `$5/$25`)。且 Lead 走 **Claude 订阅**非 per-token 计费(见 CLAUDE.md tech stack「Cost tracking: N/A」),所以真实「成本」= **usage-cap(5h/7d 额度)消耗**:当 context 真的变大时,每请求 token 更多 → 更快逼近订阅额度上限。
- **速度**:更大 context 单请求延迟略高(更多 token 处理);prompt caching 对稳定前缀可缓解大头。
- **换来的收益**:Lead 是常驻长会话,默认 200K 窗口频繁触发 compact/clear → **丢上下文 + 重读代价 + 可能加剧工具调用 malform(FLY-306,Belle 高压下 reply 泄成文本)**。1M 把这些反应式压缩几乎消除。
- **建议**:全员可上(1M 无溢价);若要保守分批,**companion(Mufasa/Belle)+ 重 context Lead(cos/eng-lead 等)优先**。**最终哪些 Lead = Annie 决定**,本 PR 不翻生产。

## Rollout runbook(本 PR 含文档,执行留给 Annie/cutover)

写 `doc/engineer/implementation/FLY-360-1m-context-rollout.md`(中文)。**两次重启是不同的东西,必须分清(Codex R1 #4):**

- **步骤 A — 部署本 PR(需重启 Bridge)**:merge + 生产 `git pull` 后,**重启 Bridge** 才能让 fleet console 暴露出新的「Opus 4.8 (1M)」档。单独重启 Bridge **不会**让任何在跑的 Lead pane 换 model —— 它只是让 console 能选这个档。
- **步骤 B — 应用 model(Fleet 引擎重启选定 Lead)**:经 Fleet Console / 批准的 `flywheel-fleet.sh` 流程把选定 Lead 的 `model` 设为 `claude-opus-4-8[1m]`。这是单一真源 = projects.json 的事务化切换 + plist 重生 + **由 Fleet 引擎重启那些被选中的 Lead** 才生效。哪些 Lead = Annie 拍。
- **攒批纪律**:步骤 A 的 Bridge 重启最省事搭下次 cutover / 别的 Bridge 侧 PR 一起做(MEMORY「多个 Bridge 侧 PR 攒一次重启」);步骤 B 也可同窗做。
- **回滚**:把该 Lead 的 `model` 清回缺省(account default = ~200K)→ 经同一 Fleet 流程重启那些 Lead。
- **验证**:步骤 A 后 console 出现「Opus 4.8 (1M)」档;步骤 B 后选定 Lead 的 pane 显示 `claude-opus-4-8[1m]` 且 ctx% 不再频繁逼近压缩。

同时**更新** `doc/engineer/implementation/fly-247-fleet-migration.md`(现只述 Fable 5 / Opus 4.8)补一笔新 tier(Codex R1 #5)。
