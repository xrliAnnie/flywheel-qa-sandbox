## 2. Shared delivery — TWO separated responsibilities (codex R1#4 + R3#1)
**Artifacts (pure, no owner) vs owner-fenced state mutation are SPLIT** so the teamlead adapter (whose `ReviewChannel.deliver(run)` has no owner) and the CLI (which needs `--owner`) can both reuse the shared part:
- `deliverReviewArtifacts(deps)` — **pure**, in `packages/flywheel-comm/src/xiaohongshu-review-delivery.ts`. Injected deps (`analysis`, `writeLocator`, `run`, `baseUrl`, `randomToken`, `now`). Validates base URL, mints `reportToken`, writes the **locator FIRST**, then the delivered run; returns `{reportToken, url, deliveredRun}`. **No owner / no state mutation.** BOTH `createWebLocalReviewChannel` (teamlead) AND the `deliver` CLI call this → one impl, no drift.
- `recordAnalysisDelivered(...)` (lib) / `xhs-state record-analysis-delivered --owner` (CLI) — the **owner-fenced state mutation** (§3), used ONLY by the CLI path AFTER artifacts succeed. The teamlead adapter does not mutate XHS state (PR-2 contract intact).

**Write order + failure semantics (codex R1#5, MED)**: write the **locator FIRST**, then the delivered run + state pointers, emit the URL **only after all writes succeed**. An orphan locator (run write failed after) is harmless — the GET route 404s when the run is absent. Failure-injection tests: locator-write fail, run-write fail, state-write fail → no half-delivered URL returned; retry is idempotent (same reportToken minter seam in tests).

## 3. Durable state on delivery (codex R1#2, HIGH)
`deliverReview` (and a new `xhs-state record-analysis-delivered --run-token <r> --report-token <t> --owner <o>`) updates `XiaohongshuState` **under `withCollectionLock` + owner fencing**: `lastAnalysisRunToken = runToken`, `lastReportToken = reportToken`, append-dedup `runToken` into `pendingFeedbackRunTokens`. So the next skill run can discover, via `$FLYWHEEL_COMM_CLI`, exactly which runs await feedback. New `xhs-state` mutators added with the existing fence pattern + tests.

## 4. `flywheel-comm xhs-analysis` CLI (codex R1#1/#3/#6/#7/#8)
JSON on stdout; validation → stderr + exit 2 (mirrors `xhs-state`):
- `write-run --file <run.json>` → **narrow runtime validation** of `XiaohongshuAnalysisRun` (required fields, enum `status`/`mediaKinds`, `posts` is array, summary counts numeric, no raw-byte-like fields, safe project/collection/runToken) → `AnalysisStore.writeRun`. (codex R1#6)
- `deliver --file <run.json> --owner <RUN_KEY> [--base-url <url>]` → validate run; **base-url fail-closed** (`--base-url` or `$FLYWHEEL_BRIDGE_URL`; trim trailing `/`; `new URL` parse; reject non-http(s); prefer loopback for web-local). **Acquire the collection lock and verify `lease.owner === owner` BEFORE any write** (codex R3#2: a stale owner must not leave an orphan locator/run); then `deliverReviewArtifacts` (locator-first, §2) → `recordAnalysisDelivered` (owner-fenced state, §3) → emit the URL **only after all writes succeed**. **`--owner` REQUIRED**; stale owner → exit 2, **no locator/run/state written, no URL**. On success print exactly `{reportToken,url}`. (codex R1#8 + R2#1 + R3#1/#2)
- `read-feedback (--report-token <t> | --project <p> --collection <c> --run-token <r>)` → resolve → `FeedbackStore.readFeedback` → print the feedback JSON or `null`. **Supports `--run-token` to align with `pendingFeedbackRunTokens`** (the consume step reads state → iterates pending run tokens → reads feedback by run-token; report-token lookup only for URL/report resolution). (codex R1#3) **Non-throwing token guard** (same `{1,128}` charset+length as the route): unknown safe token → `null` exit 0; malformed/overlong → JSON error + exit 2 (no `ENAMETOOLONG`/stack trace). (codex R1#7)
- `mark-feedback-consumed (--report-token <t> | --project <p> --collection <c> --run-token <r>) --op-id <id> --result <text> --owner <o>` → resolve → **under the collection lock, read the current `XiaohongshuState` and REJECT unless `lease.owner === owner`** (mirror the `xhs-state` fence — the feedback file is outside the state, so the lock alone doesn't prove ownership; a stale Runner that lost the lease must not mark consumed), then read-merge-write the feedback file appending/dedup `consumedActions` by `opId` (idempotent retry). `--project/--collection` required with `--run-token` (mirror read-feedback). (codex R1#1 + R2#2 + R2#4)
- `xhs-state clear-pending-feedback --project <p> --collection <c> --run-token <r> --owner <o>` → owner-fenced; removes `runToken` from `pendingFeedbackRunTokens` (idempotent when already absent). The consume loop calls it once ALL of a run's actions are consumed, so the pending queue drains instead of growing unbounded. (codex R2#3)

**Consume loop (skill, PR-4)**: `xhs-state read` → for each `pendingFeedbackRunTokens` → `read-feedback --run-token` → for each action not in `consumedActions`: `record-feedback-op-intent` (#280) → apply via Linear MCP (`close_created` only if the op's issue is still untouched; `promote_candidate` → create) → `mark-feedback-consumed`. When all of a run's actions are consumed, the skill calls `xhs-state clear-pending-feedback --run-token <r> --owner` to drop it from `pendingFeedbackRunTokens` (owner-fenced, idempotent). The Runner (MCP + founder-only) owns the Linear writes; no server consume worker (codex R1 GOOD #4).
