# Plan: Roundtable `allowBots` Self-Healing Provisioning — FLY-282

**Version**: v1.48.0 (tentative — re-version at ship; held PRs in flight)
**Issue**: FLY-282
**Date**: 2026-06-16
**Source**: brainstorm gate (Tadashi approved Option A + authoritative ids), `cross-dept-channel-rules.md`, root-cause investigation
**Status**: codex-approved (Codex design review, 2 rounds, APPROVED)

## Problem

In `#leads-roundtable` (`1512578695468941333`), a Lead **bot** that @-mentions
another Lead bot gets **no reply**; the founder (human) @-mentioning the same Lead
works. Observed: Aunt Cass → Simba (2026-06-16).

### Root cause (verified against deployed configs + authoritative bot ids)

The Discord plugin fork (`claude-plugins-official/external_plugins/discord/server.ts:1112-1114`)
drops any `author.bot` message **unless** the author's bot id is in the recipient
Lead's `access.json` `allowBots`:

```ts
if (msg.author.bot) {
  const access = loadAccess()
  if (!access.allowBots?.includes(msg.author.id)) return   // DROP
}
```

It is **not** a blanket bot-drop — it's a per-Lead **whitelist**. The bug is the
whitelist mesh is **incomplete**: e.g. Simba's `allowBots` lacks Cass's real id
`1516205086890786917`, so Cass→Simba is dropped. Every newly-onboarded Lead misses
the manual "everyone adds my bot id to `allowBots`" step (`cross-dept-channel-rules.md`
documents this as a manual onboarding step → exactly the gap that bit FLY-282).

The roundtable channel + `requireMention:true` are already correctly configured in
every Lead's `groups`; the design (`cross-dept-channel-rules.md`) already **intends**
sibling-lead @-mentions. So this is purely a provisioning-completeness gap.

> **Authoritative-id lesson:** while investigating I read the bot ids from
> `access.json` self-entries and **swapped Cass/Tadashi**. Bot ids resolved from the
> token via Discord `/users/@me` are the only reliable source. Hence: **no
> hand-maintained static roster.**

## Decision (brainstorm gate — Tadashi)

**Option A**: stay in the flywheel repo, keep the explicit whitelist, but make it
**self-healing with authoritative ids**. (Option B — relaxing the plugin's bot filter
in the `claude-plugins-official` fork — rejected: separate repo / different land flow
/ larger blast radius / loses the auditable whitelist.)

Mechanism (Lead-delegated specifics): each Lead at startup
1. resolves its **own** real bot id via its **own** token → Discord `/users/@me`
   (authoritative),
2. **publishes** `{leadId, botUserId, name}` to a shared **registry**,
3. **unions** all registered peer bot ids into its own `access.json` `allowBots`
   (idempotent → self-heals on every restart).

Mesh = all roundtable siblings (companions Mufasa/Belle + new Flywheel Leads
Cass/Tadashi + existing Simba/Peter/Oliver/Hiro/Asha). Loop-safety unchanged
(self filtered by `server.ts:1111`; `requireMention` untouched; the set-union de-dupes).

## Design

### New module: `packages/teamlead/src/roundtable-allowbots.ts`

Pure, dependency-injected logic (fetch + fs paths injectable for vitest).

- `resolveSelfIdentity(token, fetchImpl, timeoutMs=4000)` → `{ id, name }` via
  `GET https://discord.com/api/v10/users/@me` (`Authorization: Bot <token>`).
  **Bounded by a timeout** (Codex HIGH-1): the whole fetch+json is raced against a
  timer (`AbortController` aborts the real request; the race also bounds a test
  double that ignores the signal) so a stalled/half-open Discord call can never
  hang Lead startup. Timeout / network / 4xx → throws; caller treats as
  best-effort (skip publish, still consume existing peers).
- `parseRegistry(dir, readers)` → `RegistryEntry[]` — read every `*.json`, skip
  missing/corrupt (never throw on a bad file).
- `unionAllowBots(existing: string[] | undefined, peers: string[])` →
  `{ allowBots: string[], changed: boolean }` — preserve existing order, append
  only genuinely-new ids, de-dupe. `changed=false` when the set is unchanged.
- `isRoundtableMember(access, channelIds)` → boolean — any `channelId` present in
  `access.groups`. Non-member ⇒ whole reconcile is a **no-op** (byte-compat).
- `reconcile(opts)` orchestrator (IO via injected deps):
  1. read this Lead's `access.json`; if absent OR not a roundtable member → no-op.
  2. best-effort `resolveSelfIdentity` → if ok, atomically write
     `<registryDir>/<leadId>.json` = `{leadId, botUserId, name, channelIds, updatedAt}`.
  3. `parseRegistry` → peer ids; `unionAllowBots` into `access.allowBots`.
  4. if `changed`, atomically rewrite `access.json` (temp+rename, mode `0600`),
     **preserving every other field**. Log added ids.

### New CLI: `packages/teamlead/src/roundtable-allowbots-cli.ts`

Thin `process.argv` wrapper (compiled to `dist/roundtable-allowbots-cli.js`):
`--lead-id --token-env --access-file --registry-dir --channel-ids <csv>`.
Always exits `0` (best-effort; never block Lead startup). Logs to stderr.

### `claude-lead.sh` integration

A `provision_roundtable_allowbots()` function called **once**, after the dry-run
early-exit (line ~1799) and **before** the supervisor `while true` loop (line ~1826):

- skip when `FLYWHEEL_LEAD_DRY_RUN=1` (keep the launch-plan sentinel byte-compat);
- skip when `DISCORD_BOT_TOKEN` empty or `FLYWHEEL_LEAD_CROSS_DEPT_CHANNEL_IDS` unset;
- `node "${SCRIPT_DIR}/../dist/roundtable-allowbots-cli.js" ... || true` (fail-open —
  a provisioning failure must never abort a Lead launch).

Registry dir: `${FLYWHEEL_ROUNDTABLE_REGISTRY_DIR:-$HOME/.flywheel/roundtable-registry}`.
Roundtable channel ids: reuse the existing FLY-267 env
`FLYWHEEL_LEAD_CROSS_DEPT_CHANNEL_IDS` (already `=1512578695468941333`). No new
hardcoded channel constant, no static roster.

## Why this is safe / scoped

- `allowBots` is **global per-Lead** in the plugin. Widening it only lets a peer bot
  **past the intake bot-filter** (`server.ts:1112-1114`). Whether that peer then gets
  a **reply** is still gated, per matched group in `gate()`, by: the channel being in
  the Lead's `groups`, `groupAllowFrom`, `requireMention`, AND the peer bot having
  Discord permission to post there. For `#leads-roundtable` (`requireMention:true`)
  that is the intended path.
- **Accurate boundary (Codex MEDIUM-2):** this is **not** strictly "roundtable-only" —
  a non-roundtable group with `requireMention:false` and empty `allowFrom` would also
  process a whitelisted peer bot that can post in that channel. In practice
  cross-project peers are not members of another project's channels, and this trust
  is **pre-existing** (each Lead's `allowBots` already listed most peers); this change
  only **completes** the mesh, it does not introduce a new global-trust posture.
  `reconcile()` emits an **advisory log** (`findOpenNonRoundtableGroups`) when a
  roundtable member has such an open non-roundtable group, so operators can see it.
  Tightening those group policies (or the plugin's per-channel allowBots) is a
  separate concern, out of scope here (we do not edit the plugin fork).
- Only roundtable members publish ⇒ only real siblings ever enter any `allowBots`.
- Idempotent + atomic ⇒ re-runs are no-ops; a crash mid-write can't corrupt access.json.
- **No production restart** (scope lock): the mechanism converges as Leads restart
  on their normal deploy/launchd cycle.

## Non-goals (deliberate)

- No stale-registry TTL prune in v1 (a dead Lead's id lingering in `allowBots` is
  benign — the plugin simply never receives messages from a non-existent bot).
- No periodic in-session re-sync (restart-time convergence is the agreed model).
- No change to message-handling loop-safety / rate-limit (unchanged per Lead).
- No edit to the plugin fork.

## Test plan (TDD — vitest, `packages/teamlead/src/__tests__/`)

- `unionAllowBots`: adds missing, preserves existing+order, de-dupes, `changed` flag.
- `isRoundtableMember`: member vs non-member.
- `parseRegistry`: valid set; skips corrupt/empty/non-json; tolerates missing dir.
- `resolveSelfIdentity`: maps `/users/@me` 200; throws on non-200 (mock fetch);
  **never-resolving fetch rejects within the timeout** (HIGH-1).
- `findOpenNonRoundtableGroups`: flags `requireMention:false`+empty-`allowFrom`
  non-roundtable groups; ignores the roundtable channel + gated/restricted groups.
- `reconcile` (temp dir + mock fetch): writes registry file; unions peers; idempotent
  second run = no write; non-member = no-op + access.json untouched; identity-resolve
  failure ⇒ still consumes existing peers, no crash; preserves all other access fields;
  **stalled identity fetch does not hang — returns within timeout, still consumes**
  (HIGH-1); **surfaces open non-roundtable groups in the advisory field** (MEDIUM-2).
