## 0. Scope 边界

- **做**：Layer A（on-merge 钩子）+ Layer B（boot reconciler sweep），均**纯 Bridge 侧、与 runner 存活解耦**。
- **不做**：runner-liveness 根因（FLY-586 自退 / FLY-597 close 不原子 / FLY-369 状态回传）—— Layer A+B 对其鲁棒即可，不重做 lifecycle。
- **不做**：存量 38 个的清理已在 FLY-603 research session 手动 + Lead 门控完成，不在本代码 PR 内。
- **字节兼容 + kill switch**：默认行为对现有 happy path 是「多删一个 clean+merged 的 stale worktree」；对不满足判据的一律保留 → 不破坏任何在飞工作。env 逃生口 `FLYWHEEL_WORKTREE_AUTOCLEAN=0` **同时关 Layer A finalization stage 和 Layer B boot reconciler**（默认 on；两路都加 reverse-compat 测试）。

## 0.5 核心安全原则（Codex R1 收口）

**绝不把 `removeIfExists()` 当 post-merge 安全删除。** 实测 `removeIfExists()`→`remove()` 是 **forceful**：rename + `git worktree prune` + 后台 `rm -rf`（WorktreeManager.ts:173-206），对未注册目录用 `fs.rm({recursive,force})`（:248-258），**全程无 `git status --porcelain` dirty 检查**。它是为 create-前-清同名旧树（FLY-99 rerun）设计的、可接受强删。post-merge / reconciler 删除**必须 dirty-safe**：用 `git worktree remove`（**无 `--force`**，脏/锁自动拒删，正是存量止血用的法），删除路径**必须 path-based + clean-guarded + live-guarded**。

## 1. Layer A — on-merge 钩子

### A1. 共享 `deriveWorktreeKey()` helper（**完整复刻 Blueprint sanitize；先做，阻塞 A2/A3**）
worktree 命名是 **role-aware**（Blueprint.ts:401-405）：

```ts
const role = (ctx.sessionRole ?? "main").replace(/[^a-zA-Z0-9-]/g, "").toLowerCase() || "main";
const worktreeIssueId = role === "main" ? node.id : `${node.id}-${role}`;
```

- `node.id` = **human identifier**（`FLY-603`，非 UUID；盘上目录 + sessions `worktree_path` 列实测印证）；`issueIdentifier` 单独在 event envelope（Blueprint.ts:349-356）。
- **只 sanitize role，identifier 逐字保留（Codex R4 MEDIUM）**：`identifier` 是 opaque、**byte-for-byte 原样**（`FLY-603` 不可变 `fly-603`）；**仅 role** 走 `replace(/[^a-zA-Z0-9-]/g,"").toLowerCase() || "main"`。抽成 exported edge-worker `deriveWorktreeKey(identifier, sessionRole)`（= `main`→identifier，非 main→`${identifier}-${sanitizedRole}`），**Blueprint 改调它**（消除两处漂移）。
- **测试 parity**（对齐现有 Blueprint.v0.2.integration.test.ts:452-497）：`QA/../hack`→`qahack`、全非法 role→`main`、大写→小写、undefined role→`main`、`("FLY-603","main")`→`FLY-603`、`("FLY-603","qa")`→`FLY-603-qa`。

### A2. 注入清理能力 + 三 call-site 穿线（Codex R2 HIGH-2）
- **不能假设 run-infra.ts 能给 event-route 传参** —— HTTP `/events` 路径在 `plugin.ts` 经 `createEventRouter(...)` 构造（event-route.ts:348），其签名**不接** worktreeManager；DES 在 run-infra.ts:460/552 构造（紧邻 WorktreeManager）。
- 修法：`runPostShipFinalization` 增**可选 cleanup 闭包**入参 `removeCleanWorktree?(executionId)`；从 Bridge/plugin composition root 造一个**共享 cleanup dep**（绑定 WorktreeManager + StateStore），**同时传给** DirectEventSink **和** `createEventRouter`，确保**三个** `runPostShipFinalization` call-site（DES emitCompleted、event-route session_completed、W2 stage_changed=completed repair）拿到**同一闭包**。
- **dep 要 hoist 够高**（Codex R3 note）：`WorktreeManager` 现 local 在 `setupRunInfrastructure`（run-infra.ts:459），`/events` 在 `createBridgeApp`（plugin.ts:721）构造 → 把 cleanup dep 提到 `startBridge`/composition root 才能同喂两边。
- 测试覆盖**全部三条调度路径**。
- **branchless/detached Layer A target**：与 Layer B 一致 **skip + audit**，不删（避免删后 branch -D 失败半态）。

### A3. 新增 worktree-cleanup stage（**path-based + clean + positive-live guarded**）
位置：`runPostShipFinalization` 内，**stage (1) postMergeTmuxCleanup 之后、(2) notifier 之前**。逻辑：

1. `session = store.getSession(opts.executionId)`。
2. **positive-live guard（Codex R2 BLOCKER-2）**：`postMergeTmuxCleanup` 无 tmux target 时返 `{tmuxClosed:false, errors:[]}`（post-merge.ts:48/87）—— 只查 `errors.length>0` 会漏「没确认关过 tmux 就删」。故要求**正面证据 `cleanup.tmuxClosed === true && cleanup.errors.length === 0`**；否则 **skip + audit `tmux_not_confirmed_closed`**，留给 Layer B 待 live 证据消失后再清。
3. **target 解析（Codex R2 MEDIUM-1：不重写 private 路径数学）**：优先 `session.worktree_path`（持久化、最权威）；缺失才用 **WorktreeManager 新 public resolver**（非 teamlead 重写 private `worktreeDir/Name`）推期望 `{key, path}`。branch **不假设 session 有**（`worktree_ready` 只存 path 不存 branch，event-route.ts:521）→ 由 `git worktree list` 精确 path 匹配 或 `git -C <path> branch --show-current` 解析。
4. **path-guard**：确认 target 是预期 project worktree 路径（前缀 + key 匹配），否则 skip + audit `path_mismatch`。
5. **clean-guard**：`git -C <worktreePath> status --porcelain` 非空 → **skip + audit `dirty`**。
6. 全过 → 新方法 `removeCleanWorktreeByPath(mainRepoPath, worktreePath, branch)`：`git worktree remove <path>`（**无 --force**）成功后 `git branch -D <branch>`。audit `worktree_cleanup_done`。
7. fire-and-forget + try/catch 自审计，**绝不 throw**。
8. `FLYWHEEL_WORKTREE_AUTOCLEAN=0` 时整 stage 跳过。

### A4. 测试（RED→GREEN）
- merge + 干净 + **tmuxClosed===true** → `removeCleanWorktreeByPath` 被调**恰一次**、入参 = 持久化 worktree_path、**在 tmuxCleanup 之后**（call-order）。
- **tmux 未正面确认关**（`tmuxClosed=false` 且 errors 空 = 无 target 场景）→ **不删**、audit `tmux_not_confirmed_closed`。
- tmux cleanup 有 error → 不删。
- 工作树 dirty → 不删、audit `dirty`。
- target path 不符 → 不删、audit `path_mismatch`。
- 删除/分支命令抛错 → orchestrator 不 throw、notifier/teardown 仍跑、audit `worktree_cleanup_failed`。
- 三条调度路径（DES / event-route session_completed / W2）各验闭包被传 + 调用。
- `FLYWHEEL_WORKTREE_AUTOCLEAN=0` → stage 跳过。

## 2. Layer B — boot reconciler sweep（**基于 list() 的精确 path/branch**）

### B1. 新 `worktree-reconciler.ts`（围绕 `ExternalWorktree{path,branch,head}`）
入参注入纯函数：`{ mainRepoPath, projectName, protectedKeys:Set<string>, probeLiveRunner(wt)→"live"|"dead"|"unknown", isMergedHead(branch, headSha)→bool, hasOpenPr(branch)→bool }`。

**HEAD 源（Codex R2 HIGH-1）**：`list()` 现只返 `{path,branch,isDetached,isBare}`，parser 忽略 `HEAD` 行（WorktreeManager.ts:333）。修：**扩 `ExternalWorktree` + `parsePorcelain()` 加 `head:string|null`**（+ parser 测试）。detached/branchless（`branch===null`）由 step 1 的 branch-prefix 过滤**显式跳过**。

算法（逐 `wt ∈ list(mainRepoPath)`，**全程只用 `wt.path`/`wt.branch`/`wt.head`，绝不从 key 重算路径**）：
1. 仅本 project sibling worktree（`wt.branch` 前缀 `<repoSlug>-` + `wt.path` 前缀匹配；`branch===null`/main repo 跳过）。
2. **排除嵌套父**：`wt.path` 是任何其他注册 worktree path 前缀 → skip。**用 path-boundary 语义**（`path.relative(parent, child)` 不以 `..` 开头且非绝对）**而非裸 `startsWith`**（Codex R3 note：避免 `FLY-60` 假匹配 `FLY-603`）。
3. **role-aware protected 判定（Codex R2 BLOCKER-1 + R3 HIGH-1：path-authoritative）**：worktreeKey = `wt.branch` 去 `<repoSlug>-` 前缀（即 `FLY-603-qa` 完整 key）；`protectedKeys.has(worktreeKey)` → skip。protectedKeys 由 B2 构造，**优先从 session.worktree_path 解析权威 key**（非靠未强制的 issueId==identifier 假设）。
4. **独立 live-runner guard（Codex R2 BLOCKER-2 + R3 HIGH-2 + R4 HIGH-2：tri-state fail-closed + pathless fallback）**：`probeLiveRunner(wt) → "live"|"dead"|"unknown"`，**绝非 boolean**。现有 `getTmuxTargetFromCommDb` 把 `error`/`gone` 都塌成 `undefined`（tmux-lookup.ts:77-92），advisory 监控可接受、**删除闸不可**——「证不出活」≠「证明死」。契约：
   - **先按 exact `session.worktree_path === wt.path`** 映射 session → probe 那些 exact execId 的 tmux（`lookupTmuxTarget` + `probeTmuxWindowLiveness`）。
   - **pathless fallback（R4 HIGH-2，关键）**：`worktree_path` 可空（Blueprint `emitWorktreeReady` 失败被 catch 后继续，Blueprint.ts:433-445）→ 「无 exact-path session」**不等于** dead。对本 project **缺 `worktree_path`** 的 session，用 `deriveWorktreeKey(issue_id|issue_identifier, role)` 算候选 key，若任一 == `wt.branch` 的 key → probe 那个 execId；**多个 plausible pathless session 命中同 key → `unknown`**。
   - 判定：任一候选 `alive` → `live`；全部候选 `dead` → `dead`；**CommDB 读错 / tmux timeout|ENOENT|EACCES / 行畸形 / 歧义 → `unknown`**。
   - `live` 或 `unknown` → **保留 + audit**；仅 `dead` 放行。
5. `git -C wt.path status --porcelain` 非空 → skip。
6. `hasOpenPr(wt.branch)` → skip。
7. merged 铁证：`git merge-base --is-ancestor <wt.head> origin/main` 成功 **或** `isMergedHead(wt.branch, wt.head)` → 否则 skip。
8. 全过 → 新方法 `WorktreeManager.removeRegisteredWorktree(mainRepoPath, wt, {deleteBranch:true})`：用 `wt.path` 精确 `git worktree remove`（**无 --force**）+ `branch -D wt.branch`。audit `worktree_reconciled`。
9. `FLYWHEEL_WORKTREE_AUTOCLEAN=0` → 整 reconciler 入口跳过。

### B2. protected 集 = **path-authoritative role-aware worktree keys**（Codex R2 BLOCKER-1 + MEDIUM-2 + R3 HIGH-1 + R4 HIGH-1）
**层次边界（Codex R4 HIGH-1）**：`StateStore` 只有 session 行、**不知** `project.projectRoot` / WorktreeManager 的 repoSlug/baseDir 语义（`projectName` 不保证 == repoSlug）→ **不能**让 StateStore 自己解析 key（否则退化成 basename 猜测 / 假设 projectName==repoSlug，重新引入漂移）。分层：
- **StateStore 只返行**：`listWorktreeProtectionSessions(projectName, statuses)` → `{issue_id, issue_identifier, session_role, worktree_path, status}[]`。
- **composition 层 helper 建 key 集**：`buildProtectedKeys(project, worktreeManager, rows)`（在 Bridge 组装处，能拿到 `project.projectRoot` + worktreeManager 路径解析）。每行按优先级（**fail-closed**）：
  1. **有 `worktree_path`** → 用 **WorktreeManager 新 public helper** 从 exact path 解析权威 key（同 `list()`/`worktreePrefix` 语义）。最权威 —— 因 `node.id`==identifier 不变量**源码未强制**（`/api/runs/start` 收 caller 的 issueId 单独 fetch identifier；`run-dispatcher` 把 `req.issueId` 直接当 `node.id` 传 Blueprint，runs-route.ts:237 / run-dispatcher.ts:539）。
  2. **无 path 但 `issue_id`≠`issue_identifier`（都有）** → 两个 key 都保护：`deriveWorktreeKey(issue_id, role)` + `deriveWorktreeKey(issue_identifier, role)`。
  3. 否则现有那个 + role。
- **受保护状态集（坐实）**：`{running, awaiting_review, approved_to_ship}` **+ `pending`**（`pending` 真持久态，`sessions.status` 默认 `pending` StateStore.ts:293；`worktree_ready` upsert 缺失 session 成 `pending`，event-route.ts:521）。`starting/queued` 经核非 `sessions` 持久态、不纳入。
- 测试：`issue_id="uuid-123"` + `issue_identifier="FLY-603"` + `role="qa"` + `worktree_path`→真实 `flywheel-uuid-123-qa` → protected 匹配**真实 key（uuid-123-qa）非 FLY-603-qa**；**`projectName !== repoSlug` + `WorktreeManager({baseDir})` fixture**（断言不靠 projectName/basename 假设）；`pending` 行受保护。

### B3. merged/open 信号实现（fail-closed + repo-scoped；Codex R1 #5）
- `isMergedHead` / `hasOpenPr` 经 `gh pr list --state merged|open --json headRefName,headRefOid`，**每 project 各拉一次缓存**。
- **repo scoping**：gh 调用必须 `cwd = project.projectRoot`（或 `-R <owner/repo>` 从 `git remote get-url origin` 派生）—— Bridge 启动 cwd 不保证在各 project repo 内、且多 project。
- **bounded data**：显式高 `--limit`；候选 branch 不在缓存页时 fallback `gh pr list --head <branch> --state all`。
- **gh 失败/超时/underfetch → 「未证实 merged」=保留**（fail-closed，绝不因拿不到数据误删）。

### B4. 接入 boot + 测试
- `run-infra.ts` 每 project 现有 `pruneOrphans` 调用点**之后**加 reconciler（同 try/catch non-fatal）。**不新增周期 timer**（boot-only 起步；周期化 = follow-up piggyback 现有 poller）。
- `parsePorcelain` head 解析测试（含 detached）。
- fake porcelain 多 worktree fixtures，注入 fake 判定：squash-merged(is-ancestor=false 但 headRefOid-match)→清；merge 后推新 commit(headRefOid 不等)→保留；ancestor-of-main→清；dirty/openPR→保留；**role-aware protected**（`flywheel-FLY-603-qa` 在 protectedKeys）→保留；**pending session 有 worktree path**→保留；嵌套父（path-boundary 非 startsWith，`FLY-60` vs `FLY-603`）→保留；gh 失败→fail-closed 保留；删除走 `wt.path` 精确路径（断言不重算）。
- **live-runner guard 回归（重点）**：(a) status=completed、merged+clean、有 worktree_path 但 tmux 仍活 → **保留**；(b) **`worktree_path=NULL`**、branch/key 匹配、merged+clean、tmux 活或 CommDB probe indeterminate → **保留 + audit**（pathless fallback，绝不当 dead）；(c) CommDB 读错 / tmux probe error → `unknown` → 保留。
- **protected builder 层次**：`projectName !== repoSlug` + `WorktreeManager({baseDir})` fixture → 断言 protected key 由 worktreeManager 路径解析得出、不靠 projectName/basename 假设。

## 4. 风险 & 缓解

| 风险 | 缓解 |
|------|------|
| `removeIfExists` 强删脏树/活 runner cwd | **不用它**；A3/B 全走 `git worktree remove` 无 --force + dirty-guard + tmux-fail skip |
| worktree key role 漂移 | `deriveWorktreeKey` 逐字复刻 Blueprint sanitize + parity 测试；A3 优先用持久 `worktree_path` |
| Layer B 路径重算漂移（nested/baseDir/test） | 围绕 `list()` 的 `ExternalWorktree{path,branch}`，删除用精确 `wt.path` |
| active 判定漏态 | 专用 `getWorktreeProtectedIssueKeys`，状态集中一处 + 坐实真实持久态 |
| squash 误判 | 双铁证（ancestor OR headRefOid-match）+ fail-closed |
| gh 限速/离线/错 repo | repo-scoped(cwd/-R) + 高 limit + branch fallback + fail-closed 保留 |
| orchestrator 多 stage 破坏原子性 | 复用既有 claim；stage 自吞错误不 throw |
| 字节兼容 | `FLYWHEEL_WORKTREE_AUTOCLEAN=0` 同盖 A+B + reverse-compat 测试 |

## 4.5 实现注意（Codex R5 APPROVED 的 3 条非阻塞）

1. **Layer B live candidate 集 additive**：exact `worktree_path` session **与** pathless 同 key session **都纳入候选**再判 `dead` —— 防「旧 exact-path session 死、但新 pathless session 还活/不确定」时误删被复用的同 key worktree。
2. **所有本地 git/gh/status probe 错误 = retain + audit**（含注册路径上的 `git status` 失败）；删除闸的 fail-closed 行为要有显式测试。
3. **绝不把 worktree 清理挂到 `plugin.ts` approval-time `onApproved` 回调** —— 该回调只跑 `postMergeTmuxCleanup`、缺最终 merged 证据；清理只属 finalization（Layer A）+ boot reconciliation（Layer B）。
