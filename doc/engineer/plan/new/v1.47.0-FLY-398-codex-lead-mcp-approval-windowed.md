## 5. Part B = Option A 设计 — windowed full-access TUI Lead

### 5.1 架构

TUI Lead = `codex remote-control` daemon（长驻 codex app-server，读 config.toml）+ 两个客户端:
sidecar（`codex-lead-tui-runtime.ts` daemon-WS，拥有 thread、服务 Discord）+ founder TUI 窗
（`codex resume --remote`，Annie 在 cmux 看/打字）。两客户端**共享同一 thread + daemon**。
full-access = 把这个 daemon 的 sandbox 从 read-only 翻成 workspace-write + net-on（Claude-equal，
无 gateway/broker/release-gate），唯一控制 = `founder-only-authority` 合同 + main branch protection。

### 5.2 翻五层 pin（read-only → workspace-write + net-on，仅 full-access profile）

> Codex R1 HIGH-1：原『四层 pin』漏了 daemon 生命周期 —— remote-control daemon 是**长驻**进程，
> `remote-control start` 幂等，`WsTransport.kill()` 只关 sidecar WS **从不**停 daemon
> (`WsTransport.ts:81-89`)，`ensure-daemon` 仅在 read-deny 下 stop（`codex-lead-tui-home.sh:313-320`)。
> 故一个已在跑的 read-only/read-deny daemon **不会**因为改了 config.toml/起新 sidecar 就重读
> sandbox/writable_roots/MCP/approval/token。这是真正的**第五层 pin**。

- ① `codex-lead-tui-runtime.ts:646`：`if (sandboxMode!=='read-only')` 改为允许
  `codexProfile==='full-access'`（其余非 read-only 仍 fail-closed，FLY-245 write-capable 不变）。
- ② `codex-lead-tui-home.sh` ensure-home：full-access 写 `sandbox_mode="workspace-write"` +
  `[sandbox_workspace_write] network_access=true` + `writable_roots=[<projectRoot>]`（**不**写
  read-deny profile —— full-access = Claude-equal 读盘）。沿用 headless `resolveFullAccessProjectRoot`
  的 realpath 校验（projectRoot 不 overlap ~/.flywheel/state/CODEX_HOME）。
- ③ `tui-window.ts buildTuiCommand`：full-access 传 `-s workspace-write`（替 `-s read-only`）。
- ④ sidecar thread params：full-access 复用 headless `buildThreadParams`/`buildFullAccessArgv`
  逻辑（sandbox=workspace-write、cwd=projectRoot、approvalPolicy=never）。
- ⑤ **daemon 生命周期 + env ownership（Codex R1 HIGH-1）**：full-access = **runtime-owned**
  daemon 启动（像 content-coordination），**不**让 launcher 预 ensure。
  - `run-codex-lead-mufasa-tui.sh`：full-access **跳过**预 ensure-daemon（交给 runtime）。
  - `codex-lead-tui-home.sh ensure-daemon`：full-access/profile 切换时 **stop-before-start**
    （镜像 read-deny 的 stop/start 理由），保证 daemon 重读新 config/env；陈旧 read-only daemon
    不能满足 full-access boot（加断言）。
  - `codex-lead-tui-runtime.ts` ensureDaemon：full-access 用 **`buildFullAccessEnv(...)` + 解析出的
    `DISCORD_BOT_TOKEN`/`CODEX_HOME`/非密坐标** 起 daemon（**不**用 raw 继承 env —— 否则 daemon
    拿到比 headless H-1 allowlist 更多的 secret-shaped env）。content-coordination 的 wash 路 + companion
    的 raw 路 byte-compat 不动。
  - 新 shell/单测：full-access 启动**先 stop 再 start**、daemon env ⊆ full-access allowlist、
    陈旧 read-only daemon 不能满足 full-access boot。

### 5.3 TUI config parse 支持 full-access

`parseCodexLeadTuiRuntimeConfig` 接受 `codexProfile='full-access'` + `sandboxMode='workspace-write'`，
profile↔sandbox 一致性断言（镜像 headless `parseCodexLeadRuntimeConfig` 的 §3.5 lockstep）。

### 5.4 lead_actions MCP（proactive discord_send）经 config.toml + approve-config

- `codex-lead-tui-home.sh::append_lead_actions_mcp`：full-access 变体写 `[mcp_servers.lead_actions]`
  + `default_tools_approval_mode = "approve"`（修 discord_send）+ `env_vars = ["DISCORD_BOT_TOKEN"]`
  （full-access = Claude-equal，token 在 daemon env，**by NAME** 转发，**无 broker** —— content-
  coordination 的 broker 路不变，byte-compat）。
- `assertLeadActionsConfigGate`：改 **discriminated gate**（Codex R1 MED-3：**不是**放宽现 gate，
  而是按 mode 分叉）—— `mode: "broker-confined" | "full-access"`（或两个具名函数 + 各自 expected 类型）：
  - **broker-confined（content-coordination/TUI，不变）**：APPROVED_SERVER_KEYS 仍 `{command,args,env,
    enabled_tools}`、**仍拒 `env_vars`**、精确非密 env key/value（broker-only 不变量 byte-compat）。
  - **full-access**：仅额外放行**恰好** `default_tools_approval_mode === "approve"` +
    `env_vars` **恰好** `["DISCORD_BOT_TOKEN"]`；仍拒 literal secret env 值、额外 MCP、alt transport、
    意外 enabled tools。
  - 负测：full-access 的放行**绝不 bleed** 进 confined（confined 仍拒 env_vars / approve 键）。

### 5.5 daemon env（Claude-equal，正向 allowlist —— 非 raw、非 wash）

full-access daemon 由 **runtime** 以 headless `buildFullAccessEnv` 同款正向 allowlist 起（Claude-pane
镜像 + gh auth）+ 注入解析出的 `DISCORD_BOT_TOKEN`/`CODEX_HOME`。**不**用 raw 继承 env（Codex R1
HIGH-1：raw 会给 daemon 比 H-1 allowlist 更多 secret-shaped env），也**不** wash（content-coordination
的 wash 路 + companion 的 raw 路 byte-compat 不变）。token + gh keyring 经 HOME 到位。daemon env 受
allowlist 界定（与 §5.2 ⑤ 同一处接线）。

### 5.6 profile 激活 + founder-only-authority 合同 + persona（Codex R1 MED-4）

- **profile 激活**：当前 `run-codex-lead-mufasa-tui.sh` 只从 projects.json 派生 content-coordination
  （`:128-157`），**不**认 full-access、**不**设 `FLYWHEEL_CODEX_LEAD_SANDBOX=workspace-write`。
  → 新建/改造 full-access TUI launcher：识别/硬设 `codexProfile=full-access` +
  `FLYWHEEL_CODEX_LEAD_SANDBOX=workspace-write`，并**显式 `FLYWHEEL_CODEX_LEAD_READ_DENY=0`**
  （陈旧 wrapper/.env 的 read-deny flag 不能误选 read-deny config 路 —— 受控 fail，可诊断）。
- **governance**：TUI full-access 经**共享 `lead-rules-bundle.sh`**（同 `run-codex-lead-mufasa-fullaccess.sh`
  + `codex-lead.sh:94-114`）装 `founder-only-authority.md` + cross-dept 规则 + Mufasa identity.md persona。
  当前 TUI launcher 的 prompt-file 只选 companion/content 合同 —— full-access 必须走 rule-bundle，
  不能停留 companion。

## 11. Codex code review — Round 1 (PR #312)

R1 CHANGES REQUESTED → 2 HIGH + 1 MED + 1 LOW, all addressed:

- **HIGH-1 (daemon stop-before-start broken in the runtime path)** — `buildFullAccessEnv`
  STRIPS `FLYWHEEL_CODEX_LEAD_PROFILE`, so the runtime→home `ensure-daemon` call did NOT
  trigger stop-before-start (a stale read-only daemon could survive the flip; the shell
  unit test passed only because it pre-set the var). FIX: extracted a testable
  `buildTuiDaemonEnv` that RE-PINS `FLYWHEEL_CODEX_LEAD_PROFILE=full-access` +
  `READ_DENY=0` in the full-access daemon env + a boundary unit test.
- **HIGH-2 (writable_roots from unvalidated cwd)** — the shell wrote `writable_roots`
  from independently-overridable `FLYWHEEL_CODEX_TUI_CWD`, not the runtime-validated
  project root. FIX: (a) launcher DERIVES `FLYWHEEL_CODEX_TUI_CWD` from
  `FLYWHEEL_CODEX_LEAD_PROJECT_DIR` (single source) + (b) new `assertFullAccessSandboxConfig`
  asserts config.toml `sandbox_mode`/`network_access`/no-`default_permissions` +
  `writable_roots === [fullAccessProjectRoot]` (fail-closed on drift), wired into the
  runtime full-access block + the shell→gate xcheck.
- **MED-3 (shared-daemon concurrency unproven in code)** — accepted as a **HARD
  pre-flip QA gate**: NO merge/flip without the real-daemon adversarial QA artifact
  (founder TUI long-write/git-index-hold vs sidecar Discord write/commit → record
  queue/reject/interleave). If it shows interleaving, implement the sidecar
  foreign-turn-active deferral BEFORE flip. This is part of the founder-gated §6/§7 QA.
- **LOW-4 (cross-dept formatting coupling)** — shell now normalizes the cross-dept value
  (split/trim/filter) to match the runtime's `join(",")`.

**Process lesson**: these scripts run under macOS `/bin/bash` 3.2 — ALWAYS verify with
`/bin/bash -n` (bash 5 accepted a heredoc-body apostrophe that 3.2 mis-parses).
