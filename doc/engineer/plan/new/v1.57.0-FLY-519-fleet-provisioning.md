## 0. 设计原则

- **编排，不重造**：复用 `flywheel-daemon.sh` / `flywheel-fleet.sh` / `flywheel-cmux-install.sh`
  / wrapper / `skills-sync.sh`。FLY-519 = 胶水 + capture + 干净机器缺口 + 校验 + runbook。
- **idempotent**：每 phase 用 `command -v` / `[ -e ]` / `brew list` guard，重跑收敛，已存在不破坏。
- 🔴 **密钥红线**：占位 + 非空校验，绝不碰真值；capture 产物零 secret + secret-scan 闸。
- **本机安全**：provision 默认 dry-run，须 `--apply`，检测到本机已 live fleet 时拒绝 (除非 `--force`)。
- **v1 不在本机跑**：只交付脚本 + hermetic 测试 + runbook (同 FLY-516)。

## 2. `scripts/lib/fleet-sanitize.sh` (共享脱敏库)

源 guard：`[ -n "${FLEET_SANITIZE_SOURCED:-}" ] && return 0; FLEET_SANITIZE_SOURCED=1`。

- **`redact_env_to_keys <env-file> <out-file>`**
  - 整个 .env 当 tainted：输出安全合成 header + **仅**识别到的 assignment key 名
    (`KEY=` / `export KEY=`)。**绝不**写 value；**丢所有源注释/空行/未识别行**
    (注释可能藏低熵密码, 原样复制会绕过 scanner)。
  - 处理含 `=` 的 value、带引号 value、`export ` 前缀。
- **`scan_for_secrets <path...>`** (文件或目录递归)
  - 命中以下任一 pattern → 打印命中位置 (脱敏显示) + 返回非零：
    - Discord bot token：`[MNO][A-Za-z0-9_-]{23,}\.[A-Za-z0-9_-]{6}\.[A-Za-z0-9_-]{27,}` + `mfa\.[A-Za-z0-9_-]{20,}`
    - Slack：`xox[baprs]-[A-Za-z0-9-]{10,}`
    - OpenAI：`sk-[A-Za-z0-9_-]{20,}`、`sk-proj-`
    - GitHub：`gh[pousr]_[A-Za-z0-9]{30,}`、`github_pat_[A-Za-z0-9_]{30,}`
    - AWS：`AKIA[0-9A-Z]{16}`
    - JWT：`eyJ[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}\.`
    - 通用：`(TOKEN|SECRET|KEY|PASSWORD|PASSWD|APIKEY)\s*[=:]\s*\S` 且右侧**非空非占位**
      (占位定义：空 / `__PLACEHOLDER__` / `<...>` / `CHANGE_ME` / `xxx`)。
  - 实现：`grep -rEn` 组合 pattern；排除已知二进制；返回码语义清晰 (0=干净, 1=命中, 2=用法错)。

## 3. `scripts/fleet-capture.sh`

用途：在**当前活机**跑，把 `~/.flywheel/` 拓扑脱敏快照成 `fleet/` (默认输出 `<repo>/fleet/`)。

```
fleet-capture.sh [--home <dir>] [--out <dir>] [--force]
```

步骤：
1. **projects.json** → 拷到 `fleet/projects.json`。先 `scan_for_secrets` 它本身 (理论上只有
   token env 名，但防御性扫；命中即 abort 不写)。
2. **env keys** → `redact_env_to_keys ~/.flywheel/.env fleet/env.example` (只 key 名)。
3. **repos** → 对 projects.json 里每个 `projectDir` + flywheel 本身：
   `git -C <dir> remote get-url origin` → 写 `fleet/manifest.json` 的 `repos[]`
   (name / cloneUrl / targetDir)。
4. **launchd 清单** → 列 `~/Library/LaunchAgents/com.flywheel.*.plist` 的 **label** (非内容) →
   `fleet/manifest.json` 的 `launchdJobs[]` (区分 lead 派生 vs 辅助任务)。
5. **skills-sync wiring** → 记录 skills-sync repo URL + skills-update plist 存在性 →
   `fleet/manifest.json` 的 `skills{}`。
6. **deps 清单** → 静态写入已知 deps 列表 (node/pnpm/tmux/gh/jq/cmux/codex/claude/kimi/agy +
   版本提示) → `fleet/manifest.json` 的 `deps[]`。
7. **最终 secret-scan 闸**：`scan_for_secrets fleet/` → 命中即**删除刚写的产物 + 非零退出**
   (Tadashi 红线：绝不让 secret 进 git)。
8. capture metadata (date 由 `--date` 传入或 `date` 命令；host 可选, 默认不记)。

**绝不** capture：`.env` 值 / `*.db` / `codex-homes/` / `~/.config/gh` / `*.bak` 含值文件。

## 4. `scripts/provision-fleet-host.sh`

用途：在**干净新机**跑，从 `fleet/` artifact materialize。**默认 dry-run**。

```
provision-fleet-host.sh [--apply] [--from <phase>] [--only <phase>]
                        [--fleet-dir <dir>] [--skip-token-check] [--force]
```

**安全闸 (preflight)**：
- 非 root；macOS + arm64 检查 (警告非阻塞)。
- `--apply` 且 `~/.flywheel/projects.json` 已存在且含 leads → **拒绝** (除非 `--force`)：
  防在 live fleet 主机误跑。
- 默认 dry-run：每 phase 只打印「将执行 X」，不动系统。

**Phases** (各 idempotent，可 `--only`/`--from` 单跑)：

1. `preflight` — 上述安全闸 + 读 `fleet/manifest.json`。
2. `deps` — 装 Homebrew (缺则装) + `brew install` 缺失 formulae (node/pnpm/tmux/gh/jq) +
   cmux/codex/claude/kimi/agy (按各自渠道, `command -v` guard)。dry-run 列将装项。
3. `repos` — `git clone` manifest.repos 里缺失的 (存在则 skip)；flywheel repo 跑
   `pnpm install && pnpm -r build`。
4. `flywheel-home` — 建 `~/.flywheel/` 骨架目录 (logs/manifests/bin/pids/comm/...)；
   `cp fleet/projects.json ~/.flywheel/projects.json` (存在则 skip, 不覆盖)；
   装 `~/.flywheel/bin/` 运行时脚本 (从 repo `scripts/` + `scripts/lib/`)。
5. `tokens` — `~/.flywheel/.env` 不存在则从 `fleet/env.example` 占位生成 (**绝不覆盖已存在**)；
   **校验**所有 required key 在 `.env` 中**存在且非空非占位** → 列出仍是占位的 key。
   缺失 → 非零 (除非 `--skip-token-check`，给分阶段 provision 用)。
6. `skills` — 装/wire `skills-sync.sh` + `com.flywheel.skills-update.plist`；跑一次首同步
   (含 global skills 如 notion)。dry-run 列将 wire 项。
7. `launchd` — 部署 plists：
   - Bridge：从 `scripts/launchd/com.flywheel.bridge.plist` 装 + bootstrap。
   - 辅助：cmux-watcher (template 渲染) / daily-standup / skills-update / updater。
   - leads：**operator 真机执行的 manifest-first 序列**（不是 `flywheel-fleet.sh apply`
     —— 那是 carrier-diff cutover 引擎, clean host 报 no-carrier）。每个 Lead: 先手动跑
     一次 `claude-lead.sh` 生成 manifest → 停 → `flywheel-daemon.sh install <lead>`
     生成 plist + bootstrap。provision 只 narrate 此步, 真机执行 + 验证见 runbook。
   - **token gate**：phase 5 校验未过则 launchd phase 拒绝 (除非 `--skip-token-check`)。
8. `validate` — 健康检查 + PASS/FAIL 汇总：
   - Bridge up：`curl -fsS $BRIDGE_URL/api/runs/active` (带 auth header) → 期望 2xx/JSON。
   - 每个 plist `launchctl print gui/<uid>/<label>` → loaded。
   - 进程活：`pgrep` lead/bridge。
   - dispatcher smoke：探 dispatch 入口可达 (有界, 不真跑 issue) —— 探 `/api/runs/active`
     或等价只读端点返回正常 (非 429/5xx)。429 视为「dispatch gate 在限流」→ 报 warn 非 fail。
   - Discord-online (bot 绿点) = **外部, 不自动化** → runbook 手动核对清单。

## 6. Tests (hermetic, 无 live 执行)

照 `scripts/__tests__/*.test.sh` idiom (HOME sandbox / env stub / pass-fail / exit 1)：

1. `fleet-sanitize.test.sh`：
   - `redact_env_to_keys`：含真值/含`=`的值/带引号/`export ` 前缀的 `.env` → 输出**只有 key 名零值**。
   - `scan_for_secrets`：植入各类假 secret → **命中非零**；纯 key-name 产物 → **干净 0**；
     占位值 (`__PLACEHOLDER__`/空) → **不误报**。
2. `fleet-capture.test.sh`：
   - fixture `$HOME` (假 projects.json + 假 .env + 假 LaunchAgents + 假 git repo) → 跑 capture →
     产物结构正确 (projects.json/env.example/manifest.json) + **`scan_for_secrets fleet/` 干净** +
     env.example 无值。
   - **植入 secret 到 fixture .env 值** → 若 redact 漏 → 最终 secret-scan 闸**必须拦截非零**
     (Tadashi 明确要的「capture 产物 grep 不到 secret」回归测)。
3. `provision-fleet-host.test.sh`：
   - PATH stub 掉 brew/git/launchctl/curl/pnpm (记录调用, 不真执行) + HOME sandbox。
   - dry-run：打印计划、**零真实副作用** (无文件改、无 launchctl)。
   - `--apply` 到 fixture：phase 幂等 (跑两次 = 第二次全 skip / 无 diff)。
   - token gate：占位 .env → phase tokens/launchd **拒绝非零**；填值 → 放行。
   - 安全闸：fixture HOME 已有含-leads projects.json + `--apply` 无 `--force` → **拒绝**。

biome 不管 shell；push 前跑 `bash -n` 语法检查 + `shellcheck` (若装) + 全测试套件。

## 7. 风险 / 边界

- capture 真跑会读活机 → 留给 Annie 迁移前跑 (本 PR 不跑)。secret-scan 是最后防线。
- deps 渠道 (cmux/codex/claude/kimi/agy) 安装方式各异 → manifest.deps 记**渠道**, provision
  用对应安装器；未知渠道 → dry-run 列出让人工装 (不硬失败)。
- launchd phase 真 bootstrap 有副作用 → dry-run 默认 + live-fleet 拒绝闸保护本机。
- `fleet/` 误入 secret 风险 → 三层防：redact + 最终 scan 闸 + `fleet/.gitignore`。

REQUESTED, 4 个对抗性发现, 全采纳:

- **HIGH-1** `fleet-sanitize.sh` 泛用 secret 层只认 shell `KEY=val`, JSON/注释里的

  case-insensitive key (catches camelCase apiKey/botToken) + JSON/yaml/comment 形,

  存活 → **修**: 加 post-move 全 OUT_DIR scan 闸 (成功 = 整个 committed dir 干净)。
- **HIGH-3** `provision-fleet-host.sh` phase 失败被吞 (无 set -e, main 不查返回码) → **修**:
  `run()` apply 失败即 die + main 检查每个 phase 返回码 → fail-closed, 不再假 done/exit 0。
- **MEDIUM** launchd phase 用 `flywheel-fleet.sh apply` (carrier-diff 引擎, clean host
