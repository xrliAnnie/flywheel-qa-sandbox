## 0. 一句话

无专属 agent 的 Runner(sub / JoyCon 等)spawn 时,在它的 fallback 提示词里**显式让它走 Superpowers 的 RPC 流程**,并用一条**"headless-Runner 通则"**(覆盖 Superpowers 所有"等终端真人"的点)+ 三条"Flywheel 覆盖项",把"等真人在对话里批准"的硬门改接到我们现成的 **Discord/Lead 审批 gate**、把文档落点改到 **doc-flow 路径**(按 docTier 精确产文件)、简单档**保过程跳文件**。同时把同文件里几条与现实/FLY-208 基线矛盾的旧措辞(`SendMessage` 升级、"every gate must pause for human")就地理顺。

**本期只改一个纯文字文件**:`agents/generic-executor.md`。零代码、零 schema、零 config。

## 1. 为什么是这个最小切片

research 查实:① Superpowers 已作为 plugin 在本机 user 级启用,靠 SessionStart hook 自动注入,**对 Runner 大概率已生效**;② 无 agent 的 fallback 提示词正文 = `agents/generic-executor.md`(`AgentDispatcher` 命中 `shipped-generic` 时由 `Blueprint` 作为 agentContext 前置),它**已散文式描述了一套 RPCI**,只是没接 Superpowers 的 skill 引擎、也没说清 gate 通路;③ Superpowers 自己写明"项目/用户指令优先级高于它的 skill"——所以**在这个文件里写覆盖项是它认的合法做法**。

因此最小、最稳、可逆的动作就是改这一个文件。改错 = revert 一个 md。不碰 `Blueprint.ts`、不碰 `AgentDispatcher.ts`、不碰 config schema。

**明确不做(本期非目标)**:
- 不改 `Blueprint.ts` 按 `matchMethod` 注入(那是 research §2.2 的"中档"方案,等最小切片验过再评估是否需要)。
- 不碰有 agent 的 Runner(它们由 agent.md 驱动,Superpowers 自动让位;本期不动)。
- 不做 Superpowers 的装机分发(决策④,归 FLY-216 装机链 / computer-bootstrap,另开工单或并入,不在本 PR)。
- 不动 Superpowers 本体(第三方、明文拒 fork 改动)。

### 2.1 新增节(正文,已落 `agents/generic-executor.md`)

```markdown
## Default Workflow — Superpowers RPC (no agent role assigned)

This machine runs the **Superpowers** skill system (a Claude Code plugin, active for
every session including yours). Because no project-specific agent role matched this
issue, your DEFAULT working method is the Superpowers RPC flow. Drive it with the
`Skill` tool, in order:

1. `superpowers:brainstorming` — turn the issue into an agreed design
2. `superpowers:writing-plans` — turn the approved design into a step-by-step plan
3. `superpowers:test-driven-development` — implement RED → GREEN → REFACTOR
4. `superpowers:requesting-code-review` — an OPTIONAL self-review before you open the PR

These are HOW you carry out the brainstorm / plan / implement stages the rules above
already require — keep reporting stages with `flywheel-comm stage set <stage>` as
usual. Where a Superpowers skill and the rules in THIS prompt disagree, **the rules in
this prompt win**.

**If the `Skill` tool or the Superpowers plugin is unavailable**: do NOT stop on a
missing skill. Carry out the same brainstorm → plan → TDD → review shape manually
following the Baseline Rules above.

### The headless-Runner rule (read this before running ANY skill)

**No human is watching this terminal.** Every Superpowers skill that tells you to
"ask the user" / "get the user's approval" / "wait for the user to review" /
"which approach do you want?" assumes an interactive human. You have none. Resolve
each such point:

- **Design approval** → route through the Flywheel **BRAINSTORM GATE** (override A).
  The ONE point that must reach a human.
- **A genuine blocker only a human can resolve** → `flywheel-comm ask` if available;
  else record assumption, proceed, report afterward.
- **Everything else** (clarifying Qs, "which approach", "review my spec", style) →
  **decide yourself**, state it briefly, continue. Never end your turn waiting for
  terminal input. After `writing-plans`, pick the Flywheel execution path; don't ask.

### Three Flywheel overrides (these WIN over the Superpowers skill text)

**A. Design approval from your LEAD via the gate — NOT the terminal.** Follow the
**BRAINSTORM GATE** block's own steps; act on the response: affirmative → continue to
`writing-plans`; **corrections → revise then run a NEW `gate brainstorm`, repeat until
affirmative**(单条 gate 被首个响应解决,改后必须再开一道门拿 sign-off,不在未批准的初版上推进、也不无下一步地停);explicit
stop/reject → `complete --route blocked`;**非零退出 = STOP**(fail-close)。**Exit 0
alone is NOT approval**——只表示 gate 返回,Lead 原话才算数,silent/empty/negative 都不是绿灯。
**exit 0 但无真回复(fail-open 超时,门故意放行)→ 不循环重门、不冻住,简述设计 best-judgment 推进**(Codex code R1 #2)。无
BRAINSTORM GATE 块 → 不阻塞;简述设计、best judgment、**有 Lead 通道才**事后回报。

> Codex code review 加固(均守"headless 不悬停"):① escalation 的 `flywheel-comm ask` 是**非阻塞**→ 明文走 **ask→check** 规范(继续干活 + 周期 `flywheel-comm check`,**不空闲待唤醒**——plain ask 只写 CommDB 不发 mailbox 唤醒,空等会永久挂;真卡死则 `complete --route blocked`)。R2 抓出我 R1 初版误写"结束本轮待唤醒"(那是 gate/approve 流才有的 mailbox 唤醒),已改对 Blueprint.ts:622 的 ask/check 契约;② override A 补 **fail-open 超时(exit 0 无真回复)的确定动作**(best-judgment 推进,不循环不静默停)。

**B. Docs to the doc-flow path — NOT Superpowers' default.** If a **DOC-FLOW** block
is present elsewhere in this prompt it is authoritative for BOTH the folder
(`<dept>/doc/<issue>-<slug>/`) and **which files** by tier: `full` → exploration.md +
research.md + plan.md; `plan_only` → plan.md only; `none` → no process-doc file. Use
its folder / exact filenames / header — NOT Superpowers' dated names or `specs/`. No
DOC-FLOW block → Superpowers' default is fine.

**C. `none` tier: keep the process, skip the file.** Run the `brainstorming` PROCESS
but write NO separate design/spec file. **有 BRAINSTORM GATE** → 设计放 gate message;
**无 gate**(override A 退化路径)→ 简述设计后 best-judgment 继续。

> Scope note: the four skills omit Superpowers' execution-orchestration / finishing
> skills (nested-subagent dispatch). Flywheel drives execution + shipping itself.
> `requesting-code-review` is a pre-PR self-check, NOT a replacement for Flywheel's
> Codex gate — still `flywheel-comm stage set pr_created`.
```

### 2.3 为什么"指针到 prompt 里的 GATE 块 + 遵循该块自身步骤"而不是写死命令/exit-0

`generic-executor.md` 是静态文件,拿不到运行时 `leadId / exec-id / comm 路径`。`Blueprint` 已在 base prompt 注入带真实值的 **BRAINSTORM GATE** 块(仅当启用 brainstorm checkpoint)。覆盖项 A 因此(a)指向"this prompt 里别处的 BRAINSTORM GATE"而非重写命令(避免漂移)、(b)**明令遵循该块自身步骤**(读响应、有更正先改、非零退出=停)而非把 `exit 0` 当批准——Codex R1 抓的真洞:`gate brainstorm` 对 Lead 任何响应(含拒绝/更正)及 fail-open 超时都返 0,把 exit 0 当批准会在被拒/无响应后照样写码。

### 2.4 就地理顺的旧措辞(同文件,纯文字)

| 旧行 | 问题 | 改后 |
|------|------|------|
| NEVER "Make product decisions on the user's behalf. Every gate must pause for human review." | 与 headless "everything-else 自己决定" + 无-gate 退化矛盾 | 改为"非平凡 product/scope/architecture 决定才走 gate/`flywheel-comm ask`;常规技术选择自己定;无 gate 无 Lead 则记假设推进" |
| Escalation "Stop and **SendMessage** to Lead" | FLY-208 基线明禁 `SendMessage`(黑洞) | 改为"`flywheel-comm ask`(NOT SendMessage)or open gate" |
| Pipeline "Bug fixes may skip brainstorm/research" | 与 NEVER skip brainstorm + override C 矛盾 | 改为"可跳 brainstorm/research **文档**,但仍做快速设计 pass(override C)" |
| Interaction "One question at a time … let the user think/breathe" | 暗示终端有真人作答 | 改为"有 Lead 通道时一次一问;绝不在终端干等真人(见 headless 通则)" |
