## 1. Locator contract (R1#1, HIGH)

The merged stores key on `(project, collectionId, runToken)` — `runToken` alone can't locate a run. So `deliver()` mints an **opaque 128-bit `reportToken`** and persists a **locator** `{reportToken, project, collectionId, runToken, createdAt}`:
- Locator file: `<stateDir>/__review-locators/<reportToken>.json` (`reportToken` = hex safe-segment; atomic `0600`; symlink-safe under the trusted state root — reuse the foundation's hardening discipline). A fixed top-level `__review-locators` dir (NOT under a collection dir, so resolution needs no prior knowledge of the collection).
- `GET /xhs-review/:reportToken` → read locator → `AnalysisStore.readRun(project, collectionId, runToken)`. Unknown/absent locator → 404.
- `ReviewChannel.collectFeedback(reportToken)` resolves via the same locator → `FeedbackStore.readFeedback(...)`.

## 2. Token / replay model (R1#2, HIGH)

The page needs MANY independent one-action POSTs, so a single-use token is wrong:
- `GET` mints a **short-TTL (e.g. 30min) run-scoped session token** + embeds it (nonce) in the page; it allows multiple POSTs within TTL.
- Each rendered action carries a **per-action idempotency key** (deterministic, §3).
- `POST` verifies: same-origin + loopback + the run-scoped session token (valid, not expired, bound to THIS reportToken) → persists ONE action (dedup by idempotency key) → returns ok. Forged/expired/cross-run token → 401.
- Tests pin: forged token, expired token, cross-run token, replayed action (idempotent no-op), a second DISTINCT action from the same page succeeds, and **no `TEAMLEAD_API_TOKEN` appears in the served HTML/JS** (watchpoint #4).

## 3. Feedback merge / idempotency (R1#3, HIGH)

`FeedbackStore.writeFeedback` writes the WHOLE file → naive read-then-write races/clobbers. So the POST handler:
- Runs the read-merge-write **under the collection-scoped mutex** (`withCollectionLock` from `flywheel-comm/xiaohongshu-state`, keyed `(stateDir, project, collectionId)`) → serializes concurrent POSTs for a run.
- Computes a deterministic **action key** `sha256(runToken + "\0" + noteId + "\0" + action + "\0" + (targetOpId ?? candidateId ?? "") + "\0" + normalizedEditJson)` and **upserts** (replace the action with the same key, else append) → duplicate POST/retry is a no-op; a changed action for the same note replaces.
- Comments append to `comments[]` (free text; never drive close/create — plan §2/R1#8).
- Tests: duplicate POST (one action), two distinct actions (both survive), parallel POSTs (both survive under the lock).

## 4. Security model (R1#5/#6, MED — Fleet-mirrored, GET≠POST)

- Mount `/xhs-review/*` **before** the `/api` Bearer middleware (browser has no apiToken), only when `FLYWHEEL_XHS_REVIEW=1` (else NOT mounted → 404, no Bearer challenge — R1#9).
- Reuse `loopbackSelfOrigin(host)` + `isSameOrigin(headers, selfOrigin)` — **extracted to a shared `packages/teamlead/src/bridge/loopback-origin.ts`**; `fleet-routes.ts` re-imports them (no behaviour change; Fleet tests stay green).
- **GET** (top-level navigation — founder may paste the localhost URL, so Origin/Referer may be absent): require **valid loopback Host + valid reportToken locator**; do NOT require Origin/Referer.
- **POST**: require **loopback Host + matching Origin/Referer + run-scoped token** (write path).
- **scoped CSP** (this route only; does NOT touch FLY-203's report CSP): `default-src 'none'; script-src 'nonce-<n>'; style-src 'nonce-<n>'; form-action 'self'; base-uri 'none'; frame-ancestors 'none'; img-src 'none'` (no images — the merged schema has no thumbnail field, R1#7; the page LINKS the note `url` as text/anchor only).
- **XSS + URL sanitization (R1#6)**: HTML-escape ALL note/founder text; note `url` rendered in an `href` only after parse + scheme allowlist (`https:`) + host allowlist (`xiaohongshu.com`/`xhslink.com`/`rednote.com`); a `javascript:`/malformed/foreign-host url is rendered as inert text, not a link. Tests: `<script>` in title/summary/comment, `javascript:` url, quote-breaking attribute.
