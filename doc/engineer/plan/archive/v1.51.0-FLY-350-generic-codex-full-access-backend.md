## 2. Design

### 2.1 Runtime: a full-access path (headless app-server)
- `parseCodexLeadRuntimeConfig`: add `full-access` to `CODEX_LEAD_PROFILES`. Cross-field (fail-loud): `full-access` requires `sandbox=workspace-write` + `readDeny=false` + NOT companion. Absent profile → companion/read-only (no implicit default).
- `buildCodexLeadRuntime`: branch on **profile**, not `sandboxMode !== read-only`:
  - `full-access` → SKIP `assertWriteCapableRelease`/`buildConfinementArgv`/gateway/`SecretBroker`. New **`buildFullAccessArgv()`**: `sandbox=workspace-write` + `-c sandbox_workspace_write.network_access=true` + `writable_roots=[<projectRoot>]`. NO gateway MCP (model uses local `gh`/`git`).
  - `write-capable` (Z) / companion / read-only → UNCHANGED (byte-compat; Z dormant).
- **Project cwd/root (M-1 fix)**: do NOT reuse the Z `workspace` scratch field. Add a distinct `fullAccessProjectRoot` derived from `FLYWHEEL_CODEX_LEAD_PROJECT_DIR` (+ optional SUBDIR), realpath-canonicalized + validated. `buildThreadParams` full-access → `cwd=fullAccessProjectRoot`.
- **Env (H-1 fix — Claude-EQUIVALENT, not raw process.env)**: `spawnCodexAppServer` for full-access does NOT pass raw `process.env`. Define a **positive env allowlist** mirroring what a Claude Lead pane actually gets (`claude-lead.sh:901` set) PLUS the exact GitHub auth vars `gh`/`git` need (and confirm which: stored `~/.config/gh` keyring vs a `GH_TOKEN`/`GITHUB_TOKEN` env — pick the same auth path Claude uses; do NOT leak `.env` tokens Claude panes never see). Ship an **env-inventory/diff test**: full-access Codex env ⊆ (Claude-Lead env ∪ {explicit gh auth}); assert no extra `*TOKEN*`/`*SECRET*`/`*KEY*`.

### 2.2 Governance rule bundle (H-2 fix — the retained gate, role-aware)
Claude's rule bundle is assembled in `claude-lead.sh`, not a single env file. So:
- **Extract a shared, role-aware rule-bundle resolver** (e.g. `lead-rules-bundle.ts`/shared sh) that both `claude-lead.sh` and `codex-lead.sh` use to compute the ordered rule files for a role (cos / dept / companion / + founder-only-authority + project rules). `codex-lead.sh` (currently `:127` just execs the runtime) must ASSEMBLE this bundle into `FLYWHEEL_LEAD_SYSTEM_PROMPT_FILES` (→ Codex `baseInstructions`).
- **Fail-closed**: a full-access Codex Lead MUST get `founder-only-authority.md` (+ the role's dept/cos rules); a missing required governance file aborts boot.
- **Test (parity)**: full-access Codex Lead resolves the SAME founder/dept/cos/project rule set as the corresponding Claude Lead of that role.
