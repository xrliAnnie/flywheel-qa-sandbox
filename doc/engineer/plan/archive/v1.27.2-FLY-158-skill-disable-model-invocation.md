## TL;DR (v3)

- **症状**: AI executor (Designer / QA / QA-Parallel / Operations / Marketing / Backend / Frontend / Product / General + plan-generator + qa-plan-generator — 共 **11 个 executor，11/11 全受影响**) 调 `Skill(skill="onboard-*")` / `Skill(skill="brainstorm")` / `Skill(skill="plan-to-linear")` 等被 Claude Code harness 直接 block。
- **根因**: `~/Dev/GeoForge3D/.claude/skills/` 下 **21 个项目自有 SKILL.md** frontmatter 带 `disable-model-invocation: true` — Claude Code 官方约定 = 该字段 true 时 model autonomously 不可调用、不可 preload，只允许 user explicit 调（`/<skill>` slash command 或显式 `Skill(...)` 工具调用同样被 model loop 拒）。Skill 默认 `false`，所以删行即放开。
- **范围明确**: `.claude/skills/` 共 **47 filesystem entries** = 28 个真实 project-owned dir + 19 个 symlink 进 `../../.agents/skills/`（其中 14 个 symlink 当前 resolve 到一个 `SKILL.md`，因此 `.claude/skills/*/SKILL.md` glob 会展开成 42 个 `SKILL.md` paths — `28 real + 14 symlinked`）。21 个 project-owned SKILL.md 带 blocker，本 plan **只动这 21 个**（symlink 路径**不动**，§9 sed loop 用 §3.4 显式 path list 而非 glob，避免误改 `.agents/skills/` 上游 source）。
- **方案（Codex 认可方向）**: **Option A — 移除 `disable-model-invocation: true` 行**（21 个 SKILL.md 各删 1 行）。
- **Worktree 不动**（Annie 决策 Q3）。**GeoForge3D 单 repo 主 PR**（Q4）+ Flywheel doc-trail PR。
- **防回归**: 新增 `.github/workflows/skill-invocation-guard.yml` (dedicated workflow，触发条件含 `.claude/skills/**`) + `scripts/check-skill-invocation.sh`（用 extended regex 容忍 indentation/quotes/comments）。
- **Hot-reload (v2 重写)**: 按 Claude Code 官方 docs (https://code.claude.com/docs/en/skills)，Claude Code watch existing skill dirs，SKILL.md edit 当 session 内生效 — **无需** force restart。但**已 invoke 过的 skill** 在同一 conversation 不会 re-read 内容；只有还没 invoke + 走 metadata cache miss path 的 skill 会立即 pickup new frontmatter。故残余风险 = 已 preload / 已 invoke 的旧 metadata 卡住，**对 21 个 disable-model-invocation skill 来说零影响**（旧 metadata 本来就是 blocked，新 metadata 是 allowed — 旧 session 没法主动 invoke，新 session 会 pickup）。

## 2. 三 candidate 评估（回应 Brainstorm Q1）

| Option | 改动 | Pros | Cons | 推荐 |
|--------|------|------|------|------|
| **A: 删 `disable-model-invocation: true` 行** | 1 行 / 文件 | 简洁；frontmatter 最小化；和上游 default 对齐；维护负担最低 | 未来若需 toggle 关掉某个 skill 要重新加 | ✅ **推荐** |
| B: 改 `disable-model-invocation: false` | 1 行 / 文件 | 显式；未来 toggle 一行就够 | 多一行噪音；和 default 等价但更啰嗦 | ❌ |
| C: 加 `allowed-tools` allowlist 同时设 false | N+1 行 / 文件 | 最严 security posture | 工程量大 — 21 skill 每个枚举 tool；与 FLY-158 核心问题正交（allowed-tools 是 sub-permission，不解决主问题） | ❌ |

**推荐 Option A 理由（4 点）**:
1. **维护性**: 删行 = 恢复 Claude Code default，frontmatter 干净。
2. **一致性**: 上游 marketplace 大多数 skill 也是 default（不设这条 flag），repo 跟齐惯例。
3. **可逆性**: 未来要禁用某个 skill 的 AI 入口，单文件加一行 `disable-model-invocation: true` 即可，反向操作对称。
4. **范围 fit**: FLY-158 解决的是「AI 调不动」— Option A 精确对症，C 是 security hardening 应另开 issue（如 FLY-150x）。

### 4.1 新增 `scripts/check-skill-invocation.sh`（GeoForge3D repo）

**Codex r1 issue 5 修正**：扩展 regex 容忍 indentation / quoted values / trailing comments；**不**加 `allowed-tools: []` inverse check（Codex r1 issue 6：docs 说 `allowed-tools` 是 pre-approval list，empty/missing **不**等于 block，加 inverse check 会误伤）。

```bash
#!/usr/bin/env bash
# scripts/check-skill-invocation.sh
# Fails if any SKILL.md under .claude/skills/ has disable-model-invocation truthy.
# Matches: `disable-model-invocation: true`, `  disable-model-invocation:true`,
#          `disable-model-invocation: "true"`, `disable-model-invocation: 'true'`,
#          `disable-model-invocation: true   # comment`.
# Does NOT follow symlinks (community .agents/skills/ out of scope per FLY-158).
set -euo pipefail

ROOT="${1:-$(git rev-parse --show-toplevel 2>/dev/null || pwd)}"
SKILLS_DIR="${ROOT}/.claude/skills"

if [[ ! -d "$SKILLS_DIR" ]]; then
  echo "ℹ️  No .claude/skills/ directory at $SKILLS_DIR — nothing to check."
  exit 0
fi

# -E extended regex; tolerate leading spaces, optional quote, optional trailing comment.
# -P would be cleaner but BSD grep on macOS doesn't have it; -E is portable.
PATTERN='^[[:space:]]*disable-model-invocation[[:space:]]*:[[:space:]]*"?'\''?[Tt][Rr][Uu][Ee]'\''?"?[[:space:]]*(#.*)?$'

# find ... ! -type l skips symlinks; -name SKILL.md only the canonical file.
OFFENDERS=$(find "$SKILLS_DIR" -mindepth 2 -maxdepth 2 ! -type l -name 'SKILL.md' -print0 2>/dev/null \
  | xargs -0 grep -lE "$PATTERN" 2>/dev/null || true)

if [[ -n "$OFFENDERS" ]]; then
  echo "❌ FLY-158 regression: the following SKILL.md files block AI invocation"
  echo "   (disable-model-invocation truthy → model cannot autonomously load/invoke)"
  echo
  echo "$OFFENDERS"
  echo
  echo "Fix: remove the 'disable-model-invocation: true' line from frontmatter,"
  echo "or rename to a value other than true if user-only is intentional."
  echo "See doc archive: doc/engineer/exploration/archive/FLY-158-skill-invocation-architecture.md"
  exit 1
fi

echo "✅ All project-owned SKILL.md files allow AI invocation"
```

**设计选择**:
- **不跟 symlink**: `.agents/skills/` 19 个 symlink（其中 14 个 resolve 到 SKILL.md）指向上游 community share，作者约定是 user-only，强 follow 会误伤 → 用 `! -type l` 显式跳过。
- **正则容忍 quote/space/comment**: `disable-model-invocation: "true"` / `disable-model-invocation:true` / `disable-model-invocation: true  # legacy` 都能抓到。
- **大小写**: `[Tt][Rr][Uu][Ee]` 容忍 `True` / `TRUE` 等 YAML 合法变体。
- **不查其他字段**: Codex r1 issue 6 — `allowed-tools` empty 不等于 block；本 guard 专修 FLY-158 单点症状，未来其他 blocker 单独加诊断脚本。

### 4.2 CI wiring — 新增 dedicated workflow

**Codex r1 issue 1 修正**: GeoForge3D **没有** `.github/workflows/ci.yml`。现有 19 个 workflow 都是 `backend-*` / `frontend-ci.yml`，带 `paths:` filter 排除 `.claude/`。纯 SKILL.md 改动不会触发任何现有 workflow → 需新 workflow。

新增 `.github/workflows/skill-invocation-guard.yml`:

```yaml
name: Skill Invocation Guard (FLY-158)

on:
  pull_request:
    paths:
      - '.claude/skills/**'
      - 'scripts/check-skill-invocation.sh'
      - '.github/workflows/skill-invocation-guard.yml'
  push:
    branches: [main]
    paths:
      - '.claude/skills/**'
      - 'scripts/check-skill-invocation.sh'
      - '.github/workflows/skill-invocation-guard.yml'

jobs:
  check-skill-invocation:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Run skill invocation regression guard
        run: bash scripts/check-skill-invocation.sh
```

`<1s` 跑完。Path filter 保证只在 skill / 脚本 / workflow 自身改动时跑，不污染其他 PR。

## 5. Hot-reload / Active Session 处理（回应 Brainstorm Q3 + Codex r1 issue 4 重写）

### 5.1 Claude Code skill metadata load 行为（按官方 docs 校正）

**Codex r1 issue 4 修正**: 原 §5 说 "Claude Code 不监听文件变化，merge 后跑着的 Runner / Lead 拿不到 new frontmatter" — **错误**。

按 https://code.claude.com/docs/en/skills 实际行为:

| 场景 | Claude Code 行为 |
|------|-----------------|
| **已 existed 的 skill dir 改 SKILL.md** | watch + 当 session 内 pickup new metadata（包括 frontmatter） |
| **新增 top-level `.claude/skills/` 目录** | 需要 restart session |
| **已 invoke 过的 skill 在同一 conversation 内 SKILL.md 内容改了** | 不会 re-read（执行内容已 in-context） |

对 FLY-158 21 个 skill 来说：
- 这些 dir 已存在，metadata watch 生效
- 旧 metadata = `disable-model-invocation: true` → model 永远没办法 invoke → 不会出现"已 invoke 过 stuck on stale content"的 case
- merge 完成后下次 model 尝试 `Skill(skill="onboard-designer")` 时，Claude Code 重新 evaluate metadata → 看到 `disable-model-invocation` 不存在/false → 放行

**结论**: 已 spawn 的 Runner / Lead 在 merge 后**会**自动 pickup new frontmatter，下一次 invoke 即生效。**无需** force restart。

### 5.2 残余风险（small）

| 残余风险 | 处理 |

| Lead `--print` 模式 session 启动时缓存 metadata 后续不刷新（如果存在这种 mode） | 待 verify；Lead daemon 长跑 session 走 watch path，应不受影响 |
| 上游 docs 行为后续变化 / 不同 Claude Code 版本行为差异 | E2E 测试覆盖（§7.2），实测为准 |
