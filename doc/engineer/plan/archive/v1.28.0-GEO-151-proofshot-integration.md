## Round 5 Revision Note (superseded by R6 above)

R4 confirmed Round 4 architecture is converging but caught 3 HIGH-severity API shape errors and several MED issues. Round 5 fixes:

1. **`MailboxTransport.writeVerified()` real shape** — signature is `writeVerified({leadName, recipient, payload})` where `payload: MailboxPayload = {from, to, content, metadata?}`. NO top-level `flywheelId`. Idempotency goes in `payload.metadata.flywheelId`. Round 5 updates §3.4 snippet + AC2 accordingly. CommDB fallback uses `insertInstruction("bridge", execId, instructionMd)`.
2. **`appendLeadEvent()` real signature** — `(leadId, eventId, eventType, payload: string, sessionKey?): number` returning numeric seq. Does NOT return an envelope. Lead identified by `agentId`, not `id`. Round 5 §3.5 generates `eventId` + `JSON.stringify(payload)` then constructs envelope manually for `runtime.deliver`.
3. **No generic LeadEvent retry loop exists** — `HeartbeatService.getUndeliveredGuardrailEvents()` only retries `GUARDRAIL_EVENT_TYPES` (stuck/orphan/stale/idle). Round 5 either (a) adds `artifact_delivery` to the retryable set + calls `recordDeliveryFailure(seq, error)` on `{delivered:false}`, OR (b) treats first-shot delivery as best-effort and surfaces failure to Annie via Lead event. Plan picks (a) since artifact loss = silent silent UX regression.

Plus 5 MED/LOW fixes:
4. **`resolveLeadForIssue` throws** on unknown project, returns `{lead, matchMethod}` (not nullable). Same for `resolveWithLead`. Round 5 wraps in try/catch + `markRunFailed`.
5. **`setSessionParams` is overwrite-only**, not merge. Round 5 spec explicitly uses read-modify-write pattern + adds `patchSessionParams(execId, patchFn)` helper. Also: `session_started` doesn't have flywheelConfig.skills in event-route — Round 5 wires config via `DirectEventSink.emitStarted()` (where Blueprint context lives) or a separate handshake `proofshot_config_loaded` event.
6. **Bypass generic event-route push** — `event-route.ts` "always deliver ALL events to Lead" block would double-deliver `artifact_emitted`. Round 5 §3.5 returns early after `handleArtifactEvent` registers the typed `artifact_delivery` envelope. Test asserts single Lead inbox message per `artifact_emitted` POST.
7. **V1 self-vision ordering** — auto-`--notify` shipped artifacts before Runner Read defeats self-verification. Round 5 splits: `visual-capture` always writes manifest but `--notify` defaults FALSE; instruction template adds explicit notify step AFTER Read; manual override `--notify` flag stays for advanced flows.
8. **L4 local model URL doesn't work** — public 3dviewer.net cannot fetch `file:///` paths. Round 5 spawns a tiny local HTTP server (ProofShot's own dev server OR `python3 -m http.server` on free port) serving the model dir, then loads `http://127.0.0.1:<port>/model.glb`. B8 verifies actual viewer camera control surface first.
9. **Stale references** — §1.1 / rollout / §13 R2 table now flagged as historical where superseded.

Detail in §15 R4 resolution table.

## TL;DR

把 ProofShot (browser visual verification, L2/L4) + native macOS `screencapture` (L3 app window) + Runner self-vision (V1) + tri-channel artifact delivery (Linear D1 / GitHub PR D2 / Discord D3) 接入 Flywheel pipeline。**单 PR / 三段 (Stage A/B/C) / 11 commits** (Round 4 dropped C11)。

**核心 design (post Codex R3)**:
- 主触发 = Bridge `event-route.ts` 收 `stage_changed` → `handleProofShotAutoTrigger` 读 `session_params.proofshot` 配置 → 通过 `MailboxTransport.writeVerified()` 投递 Runner instruction (recipient = `runner-{execId.slice(0,8)}`, lead resolved via `resolveLeadForIssue`)
- Runner mailbox 收 instruction → 跑 `flywheel-comm visual-capture` wrapper (atomic mkdir lock + ProofShot start --output + selectVisionArtifacts + write manifest.json 含 dedup_key/attempt). `--notify` default FALSE — Runner step 2 Read 自检, step 3 显式调 `flywheel-comm notify --paths-from <manifest>`. (R6#1 V1 self-vision ordering)
- Runner notify: POST `/events artifact_emitted` 为主 (exit ≠0 if fail), CommDB `type='progress' content_type='artifact'` audit (fail-open)
- Bridge `/events artifact_emitted` handler → 构造 `HookPayload {event_type: "artifact_delivery", ...}` → `store.appendLeadEvent(...)` → `runtime.deliver(envelope)` → mark delivered on success → MailboxLeadRuntime.formatEnvelope 渲染指令 → Lead Claude CLI 自调 `mcp__plugin_discord_discord__reply(files=[paths])`
- L3 = Lead-side prompt skill (Bash + Discord reply MCP), prompt 由 `claude-lead.sh` 显式 append + `LEAD_DISABLE_SCREENCAPTURE_SKILL=1` env-gate
- ProofShot state machine = `{state, dedupKey, attempt, updatedAt, lastError}` 写 `session_params.proofshot.runs[dedupKey]`, TTL stale recovery
- Capture/Interpret/Delivery 三层独立, 不抽象

## 3. Architecture & Touch Map (post Codex R4 重写)

### 3.1 数据流 (R4 修正版)

```
Runner Edit .tsx → Runner 主动 `flywheel-comm stage set test`
  ↓
stage CLI POST /events {event_type: stage_changed, stage: test, exec_id, issue_id, project_name}
  ↓
Bridge event-route.ts stage_changed switch
  ↓ (新 handler, 跟 handleCodexAutoTrigger 平行)
handleProofShotAutoTrigger(store, projects, event, stage):
  - 读 session = store.getSession(execId); 若不存在 → 早退
  - 读 cfg = session.session_params.proofshot.config (A1 经 DirectEventSink.emitStarted() 持久化, R4#5)
  - 若 !cfg?.enabled → 早退 (AC16)
  - 若 cfg.capture_stages.includes(stage) 不成立 → 早退 (AC4)
  - 读 labels = store.getSessionLabels(execId); 若含 'no-vision' → visionEnabled=false (但仍 capture)

  - captureKind = (project_name === "GeoForge3D" && lastModel) ? "3d" : "ui"
  - dedupKey = `${execId}|${stage}|${captureKind}`
  - 读 runs = session.session_params.proofshot.runs ?? {}
  - 若 runs[dedupKey]?.state in ('pending','running') 且 updatedAt 在 TTL 内 → skip (AC14)
  - 若 runs[dedupKey]?.state == 'completed' → skip (AC14 dedup)
  - attempt = (runs[dedupKey]?.attempt ?? 0) + 1
  - patchSessionParams(store, execId, cur => ({...cur, proofshot: {...cur.proofshot, runs: {...cur.proofshot?.runs, [dedupKey]: {state:'pending', dedupKey, attempt, updatedAt: Date.now(), lastError: null}}}}))   (R4#5 — read-modify-write, setSessionParams overwrites entire JSON)
  - 渲染 instruction markdown 含 visual-capture 命令 (`--notify` flag default FALSE, R4#7) + 显式 Read step + 显式 notify step. 命令含 `--dedup-key <dedupKey> --attempt <attempt>` 传给 manifest (R4#4 correlation)

  - flywheelId = `proofshot-${dedupKey}-${attempt}`
  - 默认 backend = mailbox: await new MailboxTransport(AgentTeamTransportFactory.fromEnv())
       .writeVerified({
         leadName: lead.agentId,
         recipient,
         payload: {
           from: 'bridge',
           to: recipient,
           content: instructionMd,
           metadata: {flywheelId, execId, eventType: 'proofshot_auto_trigger', stage, captureKind, attempt, dedupKey},
         },
       })   (R4#1 真签名 — flywheelId 在 metadata 内, payload 是 MailboxPayload)
  - commdb backend fallback (FLYWHEEL_COMM_BACKEND=commdb): db.insertInstruction('bridge', execId, instructionMd)   (R4#1 真签名)
  - writeVerified 抛错 → markRunFailed(execId, dedupKey, err.message) → 早退 (AC15)
  - 成功 → 不立刻改 state, 等 handleArtifactEvent 推进
  ↓
Runner Claude CLI session mailbox poller 读到 instruction → 注入 conversation
  ↓
Runner 按 instruction step 1 跑:
  `flywheel-comm visual-capture --kind ui --description "..." --output <abs-dir> --dedup-key <dedupKey> --attempt <N>`
     → wrapper 内:
       1. acquire atomic mkdir lock /tmp/flywheel-proofshot-port.lockd (stale cleanup if pidfile process dead)
       2. free-port detect (lsof -i :PORT) 试 3000-3010
       3. 若 captureKind='3d': 启 local Node http.createServer 服 path.dirname(modelPath), encode URL `http://127.0.0.1:<sport>/<basename>`  (R4#8 — 不依赖 serve-static, 用 built-in http + fs.createReadStream)

       5. 串 `proofshot exec snapshot` + screenshot 序列 (UI) 或 4-angle eval+screenshot (3D)
       6. `proofshot stop`
       7. read <abs-dir>/* → 调 selectVisionArtifacts(files, budget) → SelectionResult
       8. write <abs-dir>/manifest.json (**wire JSON**) {selected, dropped, totalTokens, captureKind, execId, issue_id, project_name, stage, dedup_key, attempt}   (R4#4 + R7#4 wire snake_case)
       9. 释放 lock + finally { http server.close() if 3D }   (R4#8 — cleanup)
       10. stdout JSON (wire) {selected, dropped, manifest_path, totalTokens, dedup_key, attempt}   (R7#4 wire snake_case)
  ↓
Runner step 2: Read 每个 selected path (V1 multimodal; 若 labels 含 no-vision 则跳过). 若发现 UI bug → Edit 修 → 重跑此流程 (new attempt). 若 OK → step 3.   (R4#7 V1 ordering)
  ↓
Runner step 3: `flywheel-comm notify --paths-from <manifest_path>`
  → POST /events {event_type:'artifact_emitted', exec_id, issue_id, project_name, payload:{kind, paths, dedup_key, attempt}}   (R4#4)
  → CommDB INSERT type='progress' content_type='artifact' attachments=JSON.stringify(paths) (best-effort audit, fail-open)
  ↓
Bridge /events artifact_emitted handler → handleArtifactEvent(store, projects, registry, event):
  - 读 session
  - labels = store.getSessionLabels(execId) ?? []
  - try { ({lead} = resolveLeadForIssue(projects, session.project_name, labels)) } catch → log warn + return {handled:false}   (R4#4)
  - chat_thread_id = await resolveChatThreadId(store, session.issue_id, lead.chatChannel)   (R4#3 — LeadConfig.chatChannel, 不是 chat_channel_id)
  - hookPayload: HookPayload = {
      event_type: 'artifact_delivery',
      execution_id: session.execution_id,                    (R4#3 — HookPayload required)
      issue_id: session.issue_id,
      issue_identifier: session.issue_identifier,            (R4#3 — HookPayload required)
      project_name: session.project_name,                    (R4#3 — HookPayload required)
      paths: event.payload.paths,
      kind: event.payload.kind,
      chat_thread_id,
      dedup_key: event.payload.dedup_key,                    (R4#4 — correlation)
      attempt: event.payload.attempt,                        (R4#4)
      size_cap_bytes: 25 * 1024 * 1024,
      file_count_cap: 10,
      oversize_fallback_text: '部分文件 >25MB ...',
    }
  - eventId = event.event_id ?? randomUUID()
  - sessionKey = `${session.issue_id}::${session.execution_id}`
  - seq: number = store.appendLeadEvent(lead.agentId, eventId, 'artifact_delivery', JSON.stringify(hookPayload), sessionKey)   (R4#2 真签名)
  - envelope = {seq, event: hookPayload, sessionKey, leadId: lead.agentId, timestamp: new Date().toISOString()}   (R4#2 手动构造)
  - try { resolved = registry.resolveWithLead(projects, session.project_name, labels) } catch (err) → store.recordDeliveryFailure(seq, err.message); return {handled:true}   (R4#4)
  - try { result = await resolved.runtime.deliver(envelope) } catch (err) → store.recordDeliveryFailure(seq, err.message); return {handled:true}
  - 若 result.delivered === true → store.markLeadEventDelivered(seq) + patchSessionParams 推进 runs[dedupKey].state='completed' **只在 runs[dedupKey].attempt === event.payload.attempt 时** (R4#4 防 stale artifact 完成错误的 run)
  - 否则 → store.recordDeliveryFailure(seq, 'runtime returned {delivered:false}'); HeartbeatService.retryUndeliveredGuardrailEvents() 会重投 ('artifact_delivery' 在 RETRYABLE_LEAD_EVENT_TYPES from lead-runtime.ts shared export, R4#5)
  - return {handled:true}
  ↓
/events route: handleArtifactEvent 返回 {handled:true} → return; 不走 generic "always deliver" block (R4#6 — 避免双投)
  ↓
MailboxLeadRuntime.formatEnvelope() 看到 envelope.event.event_type === 'artifact_delivery' → 读 proofshot-deliver.md template + 替换 paths/chat_thread_id/oversize_fallback_text → 渲染 instruction text → 投到 Lead mailbox
  ↓
Lead Claude CLI session 读到 instruction → 调 mcp__plugin_discord_discord__reply({chat_id: chat_thread_id, message="...", files=[paths]})
  - 单文件 > 25MB: 在 message body 加 fallback markdown link, files 数组只放 ≤25MB 文件
  - files 数组 > 10: 分批 multiple reply 调用 (Discord plugin 限 10 files/msg)
  ↓
Annie 在 Discord 看到附件
```

### 3.4 Bridge `handleProofShotAutoTrigger` (R4 修正后 — real API shapes)

```typescript
// packages/teamlead/src/bridge/event-route.ts (新增, 在 handleCodexAutoTrigger 旁边)
const PROOFSHOT_TTL_MS = 30 * 60 * 1000;  // 30min — stale pending recovery

interface ProofShotRunRecord {
  state: 'pending' | 'running' | 'completed' | 'failed';
  dedupKey: string;
  attempt: number;
  updatedAt: number;
  lastError: string | null;
}

async function handleProofShotAutoTrigger(
  store: StateStore,
  projects: ProjectsContext,
  event: StageChangedEvent,
  stage: string,
): Promise<void> {
  const session = store.getSession(event.execution_id);
  if (!session) return;
  const params = store.getSessionParams(event.execution_id);
  const proofParams = getProofShotParams(params);            // R7#1 — typed accessor
  const cfg: ProofShotConfig | undefined = proofParams.config;
  if (!cfg?.enabled) return;  // AC16 kill switch
  if (!(cfg.capture_stages ?? DEFAULT_CAPTURE_STAGES).includes(stage)) return;  // AC4

  const labels = store.getSessionLabels(event.execution_id) ?? [];
  const lastArtifact = getLastArtifact(params);              // R7#1 — typed accessor
  const isGeoForge3D = session.project_name === 'GeoForge3D';
  const captureKind: 'ui' | '3d' = isGeoForge3D && lastArtifact.model_path ? '3d' : 'ui';
  const dedupKey = `${event.execution_id}|${stage}|${captureKind}`;

  // structured state with TTL stale recovery
  const runs = proofParams.runs ?? {};
  const prev = runs[dedupKey];
  const now = Date.now();
  if (prev) {
    if (prev.state === 'completed') return;  // AC14 dedup
    if ((prev.state === 'pending' || prev.state === 'running')
        && now - prev.updatedAt < PROOFSHOT_TTL_MS) return;
    // else: stale pending/running or prior failed → fall through to retry (incremented attempt)
  }

  const attempt = (prev?.attempt ?? 0) + 1;
  // R4#5 — read-modify-write (setSessionParams overwrites entire JSON)
  patchSessionParams(store, event.execution_id, (cur) => {
    const curProofs = getProofShotParams(cur);
    return {
      ...cur,
      proofshot: {
        ...curProofs,
        runs: { ...(curProofs.runs ?? {}), [dedupKey]: { state: 'pending', dedupKey, attempt, updatedAt: now, lastError: null } },
      },
    };
  });

  const visionEnabled = cfg.vision_default !== false && !labels.includes('no-vision');
  const outputDir = `~/.flywheel/screens/${event.execution_id}/${randomUUID()}`;
  const instructionMd = renderProofShotInstruction({
    stage,
    cfg,
    captureKind,
    attempt,
    dedupKey,                                                  // R7#1 — pass dedupKey to template
    angles: captureKind === '3d' ? (cfg.model_capture_angles ?? DEFAULT_ANGLES) : undefined,
    modelPath: captureKind === '3d' ? lastArtifact.model_path : undefined,
    modelViewerUrl: cfg.model_viewer_url,
    visionEnabled,
    outputDir,
    execId: event.execution_id,                                // R7#1 — for manifest write
    issueId: session.issue_id,
    projectName: session.project_name,
  });

  // R4#4 — resolveLeadForIssue throws on unknown project
  let lead: LeadConfig;
  try {
    ({ lead } = resolveLeadForIssue(projects, session.project_name, labels));
  } catch (err) {
    markRunFailed(store, event.execution_id, dedupKey, `resolveLeadForIssue: ${errMessage(err)}`);
    return;
  }

  const backend = resolveCommBackend();  // R6#3 — normalize 'mailbox' | 'commdb'; unknown → mailbox + warn
  const recipient = `runner-${event.execution_id.slice(0, 8)}`;
  const flywheelId = `proofshot-${dedupKey}-${attempt}`;

  try {
    if (backend === 'mailbox') {
      const transport = new MailboxTransport(AgentTeamTransportFactory.fromEnv());
      await transport.writeVerified({
        leadName: lead.agentId,
        recipient,
        payload: {
          from: 'bridge',
          to: recipient,
          content: instructionMd,
          metadata: {
            flywheelId,
            execId: event.execution_id,
            eventType: 'proofshot_auto_trigger',
            stage,
            captureKind,
            attempt,
            dedupKey,                                          // R7#1 — internal TS naming (camelCase)
          },
        },
      });
    } else {
      // R4#1 — commdb fallback: real signature is insertInstruction(fromAgent, execId, content)
      const db = openCommDB(session);
      db.insertInstruction('bridge', event.execution_id, instructionMd);
      db.close();
    }
  } catch (e: unknown) {
    markRunFailed(store, event.execution_id, dedupKey, errMessage(e));  // AC15
    return;
  }
  // 不立刻改 state: handleArtifactEvent 才推 'completed' 当 artifact 真到达. TTL 兜底 stuck.
}

// R4#5/#6#4 helpers — typed accessors + patch (since setSessionParams overwrites)
interface ProofShotSessionParams {
  config?: ProofShotConfig;
  runs?: Record<string, ProofShotRunRecord>;
}
interface LastArtifactParams {
  model_path?: string;
}

function getProofShotParams(params: Record<string, unknown> | undefined): ProofShotSessionParams {
  return (params?.proofshot as ProofShotSessionParams) ?? {};
}
function getLastArtifact(params: Record<string, unknown> | undefined): LastArtifactParams {
  return (params?.last_artifact as LastArtifactParams) ?? {};
}

function patchSessionParams(
  store: StateStore,
  execId: string,
  patchFn: (cur: Record<string, unknown>) => Record<string, unknown>,
): void {
  const cur = store.getSessionParams(execId) ?? {};
  store.setSessionParams(execId, patchFn(cur));
}

function markRunFailed(store: StateStore, execId: string, dedupKey: string, errorMsg: string) {
  patchSessionParams(store, execId, (cur) => {
    const proofParams = cur.proofshot as Record<string, unknown> ?? {};
    const runs = (proofParams.runs as Record<string, ProofShotRunRecord>) ?? {};
    const prev = runs[dedupKey];
    if (!prev) return cur;
    return {
      ...cur,
      proofshot: {
        ...proofParams,
        runs: { ...runs, [dedupKey]: { ...prev, state: 'failed', updatedAt: Date.now(), lastError: errorMsg } },
      },
    };
  });
}
```

### 3.5 Runner→Lead artifact event channel (R6 修正 — identity resolution + correlation)

```typescript
// packages/flywheel-comm/src/commands/notify.ts
export interface NotifyArgs {
  execId?: string;          // optional — falls back to manifest then FLYWHEEL_EXEC_ID
  issueId?: string;
  projectName?: string;
  kind: 'artifact' | 'status';
  paths?: string[];         // explicit paths
  pathsFrom?: string;       // read manifest.json
  dbPath: string;
  bridgeUrl?: string;       // from FLYWHEEL_BRIDGE_URL
  ingestToken?: string;
  dedupKey?: string;        // optional — falls back to manifest field
  attempt?: number;
}

interface ResolvedIdentity {
  execId: string;
  issueId: string;
  projectName: string;
  dedupKey: string | null;   // null for non-proofshot notifies
  attempt: number | null;
}

/**
 * R7#5 — parseAttempt: accept finite positive integers (or numeric strings like "1");
 * fail closed for anything else by returning null. Caller decides if null is acceptable.
 */
function parseAttempt(raw: unknown): number | null {
  if (typeof raw === 'number' && Number.isFinite(raw) && raw >= 1 && Number.isInteger(raw)) return raw;
  if (typeof raw === 'string' && /^\d+$/.test(raw)) {
    const n = Number(raw);
    return n >= 1 ? n : null;
  }
  return null;
}

/**
 * R6#2 — identity resolution order: CLI flag > manifest > FLYWHEEL_* env. Fail closed.
 * R7#5 — for kind='artifact', dedupKey + attempt are also required (fail closed).
 */
function resolveIdentity(
  args: NotifyArgs,
  manifest: Record<string, unknown> | null,
): ResolvedIdentity {
  const execId = args.execId ?? (manifest?.execId as string) ?? process.env.FLYWHEEL_EXEC_ID;
  const issueId = args.issueId ?? (manifest?.issue_id as string) ?? process.env.FLYWHEEL_ISSUE_ID;
  const projectName = args.projectName ?? (manifest?.project_name as string) ?? process.env.FLYWHEEL_PROJECT_NAME;
  if (!execId || !issueId || !projectName) {
    throw new Error(`notify: missing identity — execId=${execId} issueId=${issueId} projectName=${projectName}. Provide via CLI flag, manifest, or FLYWHEEL_* env.`);
  }
  const dedupKey = args.dedupKey ?? (manifest?.dedup_key as string) ?? null;
  const attempt = parseAttempt(args.attempt ?? manifest?.attempt);  // R7#5
  if (args.kind === 'artifact') {
    if (!dedupKey) throw new Error(`notify: kind=artifact requires dedup_key (via --dedup-key, manifest.dedup_key)`);
    if (attempt === null) throw new Error(`notify: kind=artifact requires positive integer attempt (got: ${args.attempt ?? manifest?.attempt})`);
  }
  return { execId, issueId, projectName, dedupKey, attempt };
}

export async function notify(args: NotifyArgs): Promise<void> {
  let manifest: Record<string, unknown> | null = null;
  let rawPaths: string[] = args.paths ?? [];
  if (args.pathsFrom) {
    manifest = JSON.parse(fs.readFileSync(args.pathsFrom, 'utf8'));
    rawPaths = (manifest.selected as string[]) ?? [];
  }
  if (rawPaths.length === 0) throw new Error('No paths to notify');

  const identity = resolveIdentity(args, manifest);  // R6#2

  // normalize + expand + validate paths
  const expanded = rawPaths.map(p => fs.realpathSync(expandTilde(p)));
  const allowlist = readAllowlistFromConfig() ?? DEFAULT_ALLOWLIST;
  for (const p of expanded) {
    if (!allowlist.some(rx => new RegExp(rx).test(p))) {
      throw new Error(`Path not in allowlist: ${p}`);
    }

    db.close();
```

```typescript
async function handleArtifactEvent(
  store: StateStore,
  projects: ProjectsContext,
  registry: RuntimeRegistry,
  event: ArtifactEmittedEvent,
): Promise<{ handled: boolean }> {
  const session = store.getSession(event.execution_id);
  if (!session) return { handled: false };
  const labels = store.getSessionLabels(event.execution_id) ?? [];

  // R4#4 — resolveLeadForIssue throws; wrap try/catch
  let lead: LeadConfig;
  try {
    ({ lead } = resolveLeadForIssue(projects, session.project_name, labels));
  } catch (err) {

  }

  // R4#3 — LeadConfig field is chatChannel (not chat_channel_id)
  const chatThreadId = await resolveChatThreadId(store, session.issue_id, lead.chatChannel);

  // R4#3 — HookPayload is current interface with required execution_id/issue_id/issue_identifier/project_name.
  // event_type is discriminator; optional artifact-specific fields added in hook-payload.ts.
  const hookPayload: HookPayload = {
    event_type: 'artifact_delivery',
    execution_id: session.execution_id,
    issue_id: session.issue_id,
    issue_identifier: session.issue_identifier,
    project_name: session.project_name,
    paths: event.payload.paths,
    kind: event.payload.kind,                  // 'ui' | '3d'
    chat_thread_id: chatThreadId,
    dedup_key: event.payload.dedup_key,        // R4#4 — correlation
    attempt: event.payload.attempt,             // R4#4 — correlation
    size_cap_bytes: 25 * 1024 * 1024,
    file_count_cap: 10,
    oversize_fallback_text: `部分文件 >25MB, 已跳过 Discord 附件; 见 GitHub PR comment.`,
  };

  // R4#2 — real appendLeadEvent: (leadId: string, eventId: string, eventType: string, payload: string, sessionKey?: string): number
  const eventId = event.event_id ?? randomUUID();
  const sessionKey = `${session.issue_id}::${session.execution_id}`;
  const seq: number = store.appendLeadEvent(
    lead.agentId,                              // R4#2 — agentId, not id
    eventId,
    'artifact_delivery',
    JSON.stringify(hookPayload),
    sessionKey,
  );

  // Build envelope manually (appendLeadEvent returns numeric seq, not envelope)
  const envelope: LeadEventEnvelope = {
    seq,
    event: hookPayload,
    sessionKey,
    leadId: lead.agentId,
    timestamp: new Date().toISOString(),
  };

  // R4#4 — resolveWithLead throws if runtime not registered
  let resolved;
  try {
    resolved = registry.resolveWithLead(projects, session.project_name, labels);
  } catch (err) {
    store.recordDeliveryFailure(seq, `resolveWithLead: ${errMessage(err)}`);
    return { handled: true };
  }

  let result: { delivered: boolean };
  try {
    result = await resolved.runtime.deliver(envelope);
  } catch (err) {
    store.recordDeliveryFailure(seq, `deliver threw: ${errMessage(err)}`);
    return { handled: true };
  }

  if (result.delivered === true) {
    store.markLeadEventDelivered(seq);
    // R4#4 — advance run state ONLY when attempt matches (defend against stale artifact)
    patchSessionParams(store, event.execution_id, (cur) => {
      const proofParams = (cur.proofshot as Record<string, unknown>) ?? {};
      const runs = (proofParams.runs as Record<string, ProofShotRunRecord>) ?? {};
      const dedupKey = event.payload.dedup_key;
      const expectedAttempt = event.payload.attempt;
      const run = runs[dedupKey];
      if (!run) return cur;                      // unknown dedupKey — ignore stale artifact
      if (run.attempt !== expectedAttempt) return cur;  // R4#4 — stale artifact, don't mark
      if (run.state !== 'pending' && run.state !== 'running') return cur;  // already terminal
      return {
        ...cur,
        proofshot: {
          ...proofParams,
          runs: { ...runs, [dedupKey]: { ...run, state: 'completed', updatedAt: Date.now() } },
        },
      };
    });
  } else {
    // R4#5 — recordDeliveryFailure increments attempts; HeartbeatService retry loop
    // picks up 'artifact_delivery' via RETRYABLE_LEAD_EVENT_TYPES shared export.
    store.recordDeliveryFailure(seq, 'runtime returned {delivered:false}');
  }

  return { handled: true };
}
```
