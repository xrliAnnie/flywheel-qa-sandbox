### 4.2 Gap 2 — `test-auto-approve.sh`（OQ1 = Option A，contract 按真实 API）

**Root cause**: Sandbox Runner 跑 Blueprint Step 6 `flywheel-comm gate approve_to_ship`，阻塞在 `CommDB.readResponse(gateId, blocking=true)`。解除 = Bridge POST `/api/actions/approve` → `approveExecution()` → `CommDB.insertResponse(gateId, "bridge", {approved:true})`（`packages/teamlead/src/bridge/actions.ts:300-340`）。

**关键竞态**（Codex R1 #2 指出，源码注释坐实 `actions.ts:301-304`）：
> "if Annie approves before Runner creates the gate question, gateUnblocked will be false. ... If we ever add programmatic auto-approve, add a retry or check session state in the gate polling loop."

plan 若只看 HTTP 200 就 exit 0 → 脚本会在 pending gate 写入 CommDB 之前 approve，出现“HTTP success 但 Runner 仍卡住”的假阳性。

**真实 API 合约**（Codex R1 #1 核对）:
- `POST /api/actions/approve` body: `{"action":"approve","execution_id":"<uuid>","leadId":"<slot botName>"}`（`packages/teamlead/src/bridge/actions.ts:785-823`）
- Response body (200): `{success:true, message, action:"approve", identifier, gateUnblocked:true|false}`
- Health: `GET /health`（不是 `/api/health`）（`scripts/test-deploy.sh:488`）
- Session lookup: `GET /api/sessions/:id` 返回 `execution_id` snake_case（`packages/teamlead/src/bridge/tools.ts:140-158`）
- Slot schema：`.slots[${SLOT_IDX}]`（`scripts/inject-linear-issue.sh:51`）

**新脚本** `scripts/test-auto-approve.sh`:

```bash
#!/usr/bin/env bash
# FLY-115 v1.24.2: Unblock a sandbox Runner stuck at flywheel-comm gate
#                 approve_to_ship by POSTing /api/actions/approve.
#
# Usage:
#   scripts/test-auto-approve.sh <slot> <execution-id> [--timeout 60] [--poll-interval 2]
#
# Exit codes:
#   0 — gateUnblocked=true in approve response (Runner can proceed)
#   2 — Bridge /health unreachable
#   3 — timeout: Runner never reached awaiting_review within --timeout seconds
#   4 — approve POST non-2xx or response gateUnblocked=false
#   5 — usage / arg error
#
# This is a READ-after-STATE-CHECK script: it polls until both
#   (a) GET /api/sessions/:id returns status="awaiting_review"
#   (b) CommDB comm.db has a pending approve_to_ship gate question
# before POSTing approve, closing the race documented at
# packages/teamlead/src/bridge/actions.ts:300-304.
set -euo pipefail

usage() {
  echo "Usage: $0 <slot> <execution-id> [--timeout SECONDS] [--poll-interval SECONDS]" >&2
  exit 5
}

[[ $# -lt 2 ]] && usage
SLOT="$1"
EXECUTION_ID="$2"
shift 2

TIMEOUT=60
POLL=2
while [[ $# -gt 0 ]]; do
  case "$1" in
    --timeout) TIMEOUT="${2:?}"; shift 2 ;;
    --poll-interval) POLL="${2:?}"; shift 2 ;;
    *) echo "ERROR: unknown arg '$1'" >&2; usage ;;
  esac
done

SLOTS_FILE="${HOME}/.flywheel/test-slots.json"
[[ -f "$SLOTS_FILE" ]] || { echo "ERROR: $SLOTS_FILE missing" >&2; exit 5; }

SLOT_IDX=$((SLOT - 1))
PORT=$(jq -r ".slots[${SLOT_IDX}].bridgePort // empty" "$SLOTS_FILE")
BOT_NAME=$(jq -r ".slots[${SLOT_IDX}].botName // empty" "$SLOTS_FILE")
[[ -n "$PORT" && -n "$BOT_NAME" ]] || { echo "ERROR: slot $SLOT not in $SLOTS_FILE" >&2; exit 5; }

API="http://localhost:${PORT}"
PROJECT_NAME="test-slot-${SLOT}"
COMM_DB="${HOME}/.flywheel/comm/${PROJECT_NAME}/comm.db"

log() { echo "[test-auto-approve] $(date +%H:%M:%S) $*" >&2; }

# Phase 1: health
curl -fsS "${API}/health" >/dev/null 2>&1 \
  || { log "Bridge unreachable at $API"; exit 2; }

# Phase 2: poll until awaiting_review AND pending gate exists in CommDB
DEADLINE=$(( $(date +%s) + TIMEOUT ))
STATUS=""
GATE_READY=0
while [[ $(date +%s) -lt $DEADLINE ]]; do
  STATUS=$(curl -fsS "${API}/api/sessions/${EXECUTION_ID}" \
    | jq -r '.status // "unknown"' 2>/dev/null || echo "unknown")
  if [[ "$STATUS" == "awaiting_review" ]]; then
    # Check CommDB for pending approve_to_ship gate. Mirrors
    # getPendingGateByRunner() at packages/flywheel-comm/src/db.ts:249-265.
    # Real schema (packages/flywheel-comm/src/db.ts:8-37): single `messages`
    # table; gate question = (from_agent=executionId, type='question',
    # checkpoint='approve_to_ship'); response = child row with type='response'
    # and parent_id pointing at the question. Pending = question with no
    # response child and not expired.
    if [[ -f "$COMM_DB" ]]; then
      GATE_READY=$(sqlite3 "$COMM_DB" "
        SELECT COUNT(*) FROM messages q
        WHERE q.from_agent = '${EXECUTION_ID}'
          AND q.type = 'question'
          AND q.checkpoint = 'approve_to_ship'
          AND NOT EXISTS (
            SELECT 1 FROM messages r
            WHERE r.parent_id = q.id AND r.type = 'response'
          )
          AND q.expires_at > datetime('now');
      " 2>/dev/null || echo 0)
      if [[ "$GATE_READY" -ge 1 ]]; then
        log "status=awaiting_review + pending gate present; proceeding to approve"
        break
      fi
    fi
  fi
  sleep "$POLL"
done

if [[ "$STATUS" != "awaiting_review" || "$GATE_READY" -lt 1 ]]; then
  log "timeout after ${TIMEOUT}s (status=$STATUS pending_gate=$GATE_READY)"
  exit 3
fi

# Phase 3: POST approve
RESPONSE=$(curl -sS -w '\n__HTTP__%{http_code}' \
  -X POST "${API}/api/actions/approve" \
  -H 'Content-Type: application/json' \
  -d "$(jq -n --arg eid "$EXECUTION_ID" --arg lead "$BOT_NAME" \
      '{action:"approve", execution_id:$eid, leadId:$lead}')")

HTTP_CODE=$(sed -n 's/.*__HTTP__//p' <<<"$RESPONSE")
BODY=$(sed 's/__HTTP__.*//' <<<"$RESPONSE")

if [[ "$HTTP_CODE" != 2* ]]; then
  log "approve failed: HTTP $HTTP_CODE body=$BODY"
  exit 4
fi

GATE_UNBLOCKED=$(jq -r '.gateUnblocked // false' <<<"$BODY" 2>/dev/null || echo "false")
if [[ "$GATE_UNBLOCKED" != "true" ]]; then
  log "approve HTTP 200 but gateUnblocked=false — runner likely still stuck"
  exit 4
fi

log "approved: exec=${EXECUTION_ID} gateUnblocked=true"
echo "approved ${EXECUTION_ID}"
```

**CommDB schema — 已按真实 schema 落地**（R2 #1 修正）：上文 SQL 列名 `messages.from_agent/type/checkpoint/parent_id/expires_at` 来自 `packages/flywheel-comm/src/db.ts:8-37` 的 SCHEMA + `db.ts:82-99` 的 ALTER TABLE（`checkpoint` 列通过 migration 追加），与 `getPendingGateByRunner()`（`db.ts:249-265`）100% 同构。Implement 阶段第一步依然执行 `sqlite3 ~/.flywheel/comm/test-slot-1/comm.db '.schema'` 做 sanity check（确认本机 DB 已跑完 ALTER TABLE migrations）。

**契约覆盖 Annie OQ3 — auto_approve + needs_review**：两路由都经 `awaiting_review`（`packages/teamlead/src/bridge/event-route.ts:331-344`，测试 `packages/teamlead/src/__tests__/event-route.test.ts:241-263` 已断言），脚本仅依赖 `awaiting_review` 状态 + pending gate，两种路由共用。

**验证**:
- Positive: sandbox issue 注入 → Runner 到 Step 6 → 另一 shell 跑 `scripts/test-auto-approve.sh 1 <EXECUTION_ID>` → 退出码 0，Runner 继续
- Negative 1: `scripts/test-auto-approve.sh 1 fake-uuid --timeout 5` → exit 3
- Negative 2: Bridge killed → exit 2
- Negative 3: 人工塞一个状态为 `completed` 的 session → exit 3（因 `GATE_READY=0`）
- Race covering: Runner 刚到 awaiting_review 但未写 gate，脚本继续 poll 直到 gate 写入，不会假阳性 exit 0

**风险**: 中。主要风险 = CommDB schema 与脚本 SQL 列名不匹配，implement 第一步就验证并修正。

### 4.5 Gap 3.2 — Orphan `cmux-<window_name>` linked session（不按 slot 命名）

**Root cause**（Codex R1 #4 关键修正）: `flywheel-cmux-sync.sh:14` 定义 `VIEW_PREFIX="cmux-"`，linked session 命名是 `cmux-<window_name>`，其中 `<window_name>` 是 Runner tmux **window** 的名字（由 Runner 生成），**不保证**含 `slot-N` 字样。研究文档里举的 `cmux-FLY-115-claude-Issue-FLY-115` 就是反例 — `^cmux-.*-slot-${SLOT}` 会漏掉它。

**Fix — 按实际 window name 推导，不按 slot 号猜正则**:

```bash
# In teardown_slot(), BEFORE killing runner-test-slot-${SLOT}:
local RUNNER_TMUX="runner-test-slot-${SLOT}"
local CMUX_LINKED=()

if tmux has-session -t "$RUNNER_TMUX" 2>/dev/null; then
  # Enumerate all windows in the slot's Runner tmux session; their cmux-linked
  # session names are "cmux-<window_name>".
  while IFS= read -r wname || [[ -n "$wname" ]]; do
    [[ -z "$wname" ]] && continue
    CMUX_LINKED+=("cmux-${wname}")
  done < <(tmux list-windows -t "$RUNNER_TMUX" -F '#{window_name}' 2>/dev/null || true)
fi

# Kill linked cmux sessions FIRST (they hold viewer handles on the Runner windows)
if (( ${#CMUX_LINKED[@]} > 0 )); then
  for s in "${CMUX_LINKED[@]}"; do
    if tmux has-session -t "$s" 2>/dev/null; then
      echo "  killing cmux linked session: $s"
      tmux kill-session -t "$s" 2>/dev/null || true
    fi
  done
fi

# Existing runner kill...
if tmux has-session -t "$RUNNER_TMUX" 2>/dev/null; then
  tmux kill-session -t "$RUNNER_TMUX" 2>/dev/null || true
fi
```

> Lead tmux 窗口同理由 `${PROJECT_NAME}-${AGENT_ID}` 推导 — teardown 当前已 kill lead supervisor + lead tmux（见 `test-teardown.sh:142-167`），Lead 侧不新增逻辑。

**兜底 sweep**（防止 Runner tmux 已被意外清但 cmux-* 残留的 edge case）：在 runner kill 之后再扫一遍，按 `cmux-*` 检查是否有 cmux session 其 first window 的 `session_name` 属性曾是 `runner-test-slot-${SLOT}`。这个检查 tmux 不直接给，简化为：**扫所有 `cmux-*` session，若对应的“源” target 已不存在，kill 之**。

```bash
# Secondary sweep: stale cmux-* sessions whose linked target no longer exists
while IFS= read -r s || [[ -n "$s" ]]; do
  [[ -z "$s" ]] && continue
  # "cmux-FOO" links to window named FOO somewhere; if no window "FOO" exists
  # anywhere in tmux, the cmux session is stale.
  local winname="${s#cmux-}"
  local found
  found=$(tmux list-windows -a -F '#{window_name}' 2>/dev/null | grep -Fx "$winname" || true)
  if [[ -z "$found" ]]; then
    echo "  killing stale cmux session (no live window): $s"
    tmux kill-session -t "$s" 2>/dev/null || true
  fi
done < <(tmux list-sessions -F '#{session_name}' 2>/dev/null | grep -E '^cmux-' || true)
```

**注意**: secondary sweep 是 best-effort 全局扫描，**不收窄到 `-t flywheel`**。原因（R2 #2）：`flywheel-cmux-sync.sh:29-53` 同时把 `flywheel` session 和所有 `runner-*` session 当作 source；如果 slot 1 teardown 把 "live window" 判据收窄到 `tmux list-windows -a -t flywheel`，那么 slot 2 仍然活跃时其 live runner window 还留在 `runner-test-slot-2` 里，slot 1 的 secondary sweep 就会把 `cmux-<slot2-window>` 误判为 stale 并杀掉。所以这里保留 `tmux list-windows -a -F '#{window_name}'` 的全局 live-window 检查 — 代价是若本机存在非 flywheel 的 cmux session 且其对应 window 恰好已销毁，会被一并扫掉。若后续需要更精细归属判定，只能引入"primary phase 枚举出来的 `cmux-${window_name}` 白名单 + 历史记录里 Flywheel 创建过的 cmux session 登记"这类额外归属信息，而不是简单换 target session。

**验证**:
- Deploy slot 1 + Runner 跑起来 → `tmux list-sessions | grep cmux` 有若干 cmux-* session → teardown 1 → 再 list 该 slot 对应的都没了
- Edge case: 手动 `tmux kill-session -t runner-test-slot-1` 再跑 teardown → secondary sweep 把 orphan cmux-* 扫掉
- Negative: deploy slot 1 和 slot 2 同时 → teardown 1 不影响 slot 2 的 cmux-*（primary phase 用 `list-windows -t runner-test-slot-1` 只列 slot 1 的 window；secondary 只杀已无 live window 的）

**风险**：中。Secondary sweep 是全局扫 `cmux-*` + 全局 `list-windows -a` 判 live。若有其他来源（非 flywheel）的 cmux session 且其 window 恰好已销毁，会被连带杀掉。**不能用 `-t flywheel` 收窄**：`flywheel-cmux-sync.sh:29-53` 本身同时扫 `flywheel` 和所有 `runner-*` session 当 source，收窄到 `flywheel` 会让 slot N+1 的 live cmux linked session 被 slot N teardown 误杀（因为 slot N+1 的 window 还留在 `runner-test-slot-N+1` 里而非 `flywheel`）。缓解：Annie 开发机 cmux 仅 flywheel 用途 — 可接受；若后续必须精细归属，只能引入"primary phase 白名单 + Flywheel 创建登记"这类额外信息，而不是切 target session。

### 4.6 Gap 3.3 — Orphan `claude` CLI process（用 `lsof` 验 cwd）

**Root cause**（Codex R1 #5 修正）: `pgrep -f "claude.*${CANONICAL_SLOT_DIR}"` 有两个问题：
1. **误杀**：参数里碰巧含 slot 路径的宿主 `claude`（如 Annie 的主 Claude Code session 打开 slot 目录做 debug）
2. **漏杀**：cwd 在 slot 内但 argv 不含 path 的 orphan（`claude --print "hi"` 只有 argv = `claude --print hi`，无 path）

**Fix — pgrep 枚举候选 + lsof 验 cwd 精确匹配**:

```bash
# Sweep orphan claude processes whose cwd is inside this slot's workspace.
local CANONICAL_SLOT_DIR
CANONICAL_SLOT_DIR=$(cd "${SLOT_DIR}" 2>/dev/null && pwd -P || echo "")
if [[ -n "$CANONICAL_SLOT_DIR" && "$CANONICAL_SLOT_DIR" != "/" ]]; then
  # Step 1: enumerate all 'claude' candidate pids (not all system processes)
  local CANDIDATES=()
  while IFS= read -r pid || [[ -n "$pid" ]]; do
    [[ -z "$pid" ]] && continue
    CANDIDATES+=("$pid")
  done < <(pgrep -x claude 2>/dev/null || true)

  # Step 2: for each candidate, use lsof to check if cwd is under slot dir
  local ORPHAN_PIDS=()
  if (( ${#CANDIDATES[@]} > 0 )); then
    for pid in "${CANDIDATES[@]}"; do
      # lsof -a -p $pid -d cwd prints the cwd line; NAME col has the path.
      # Format: FD=cwd, TYPE=DIR, NAME=/canonical/path
      local cwd
      cwd=$(lsof -a -p "$pid" -d cwd -Fn 2>/dev/null \
        | awk '/^n/{print substr($0,2); exit}' \
        || echo "")
      # Canonicalize cwd (lsof on macOS usually already gives /private/tmp/...)
      [[ -z "$cwd" ]] && continue
      # R2 #3: append trailing slash before prefix compare so slot-1 doesn't
      # match slot-10 or slot-1-old. Normalize both sides: strip any trailing
      # slash from the canonical path, then append exactly one slash.
      local slot_prefix="${CANONICAL_SLOT_DIR%/}/"
      local cwd_norm="${cwd%/}/"
      if [[ "$cwd_norm" == "$slot_prefix"* ]]; then
        ORPHAN_PIDS+=("$pid")
      fi
    done
  fi

  # Step 3: two-phase SIGTERM → SIGKILL
  if (( ${#ORPHAN_PIDS[@]} > 0 )); then
    echo "  found ${#ORPHAN_PIDS[@]} orphan claude process(es) with cwd under ${CANONICAL_SLOT_DIR}; SIGTERM"
    for pid in "${ORPHAN_PIDS[@]}"; do
      kill -TERM "$pid" 2>/dev/null || true
    done
    sleep 2
    for pid in "${ORPHAN_PIDS[@]}"; do
      if kill -0 "$pid" 2>/dev/null; then
        echo "  pid $pid survived SIGTERM; SIGKILL"
        kill -KILL "$pid" 2>/dev/null || true
      fi
    done
  fi
fi
```

**关键改动 vs R1 plan**:
- `pgrep -x claude`（精确匹配程序名）替代 `pgrep -f "claude.*path"`（argv 模糊匹配）
- 对每个候选用 `lsof -p $pid -d cwd -Fn` 读真实 cwd，`awk '/^n/'` 提取 NAME 行
- 只有 cwd 真正落在 `${CANONICAL_SLOT_DIR}` 下才加入 kill 列表
- 保留 SIGTERM→2s→SIGKILL 两阶段

**macOS 路径 canonicalization**：`/tmp` → `/private/tmp` symlink。`pwd -P` 在 SLOT_DIR 里拿 canonical；lsof 默认给 canonical 路径。两边对齐，`==` 前缀匹配可靠。

**边界保护**：`[[ "$CANONICAL_SLOT_DIR" != "/" ]]` + `pgrep -x claude` 精确程序名 + `lsof` cwd 严格前缀匹配。

**风险**：低-中。lsof 对某些 macOS 权限配置可能需要 sudo；若返回空 cwd，fallback 是跳过该 pid 不杀（保守）。implement 阶段在干净 slot + 手工 orphan 组合下验证。
