## Design

### Part A — 检测:两层(Codex MED-5,保 legacy)

**Layer 1（detect → nudge,tool-agnostic）**:
- 保留现有 `LEAK_RE`(匹配 reply,**含截断/无闭合**——T1–T16 的 T3 截断 nudge 必须保住)。
- **新增** Write(及配置集)的 leak 检测(含截断/malformed)→ 命中即 **nudge**。这覆盖 FLY-584(Write leak 现在被抓+nudge)。
- 不在 `DETECT_TOOLS` 集合内的工具名 → 不命中(维持 FLY-387 低误伤;绝不对任意 tool-call 报警)。
- **per-tool 真调用抑制(R2-LOW)**:某工具的 leak **只在该工具自身**有真 `tool_use` 时才抑制(现有 `reply_called` 改成 per-tool)。即:真 reply 调用 → 抑制 reply leak,但**不**抑制同轮 Write leak;真 Write 调用 → 抑制 Write leak,但不抑制 reply leak;真无关工具调用 → 不抑制任何 leak。

**Layer 2（eligibility → auto-exec,只 reply）**:
- 只从**完整闭合**(有 `</invoke>`)的 invoke-block 提取候选;auto-exec allowlist = `{reply}`。
- 截断/无闭合的 reply → 只走 Layer 1 nudge,**绝不 auto-exec**(Codex Keep#3)。

### Part B — reply silent auto-execute(Tier B only)

`main()` Tier B 分支:

```
detected = layer1_detect(rows)                 # 所有 leak(reply/Write/…，含截断）
if not detected:                 return 0       # 无 leak（含刻意沉默）
candidates = layer2_eligible_reply(rows)        # 完整闭合 + reply + 通过 eligible()
if not is_tier_b:                return nudge(detected)   # D3
if len(candidates) != 1:         return nudge(detected)   # Codex HIGH-4: 单候选才 exec；0/多 → nudge
c = candidates[0]
if detected_has_other_leak_blocks_besides(c):  return nudge(detected)  # 别静默丢掉别的 leak 块
verdict = reply_guard(projectName, leadId, c.chat_id, c.text)   # D6/HIGH-1
if verdict != ALLOW:             return nudge(detected)   # deny / 不可达 → nudge（R2-MED: 故意更严）
claim = atomic_claim(key(c))                    # R2-HIGH: 显式 state machine（见下）
if claim == SENT:                return 0                 # 已发 → 静默
if claim == FRESH_PENDING_OTHER: return 0                 # 别的 hook 正持有/发送 → 静默不 nudge（绝不双发驱动）
if claim == STALE_POSTING:       alert_ambiguous(key); return nudge_ambiguous(detected)  # 不自动重发
# claim == OWNER（O_EXCL 成功 / stale-claimed 安全 reclaim：从未 POST 过）
write_status(key, POSTING)
ok, msg_id, http = discord_post(c, token)       # Python urllib, allowed_mentions:{parse:[]}
if ok:  write_status(key, SENT, msg_id, http); audit(...); return 0   # silent-approve
else:   write_status(key, FAILED); return nudge(detected)             # owner 失败才 nudge
```

**`eligible(c)`(D1/D3)**:`fully_closed` + 数字 `chat_id` + 有 `text`/`message` + **无 `files`** + `len(text) < 1900` + **无 `reply_to`**。

**`reply_guard()`(D6/HIGH-1 + R2-MED:故意比插件更严)**：`POST {BRIDGE_URL}/api/discord/reply-guard` body `{projectName, leadId, chatId, text}`。**只有显式 `allow=true` 才 auto-exec**;`allow=false` → nudge;**guard 任何不可达(404 无路由 / timeout / 网络 / 非 2xx)→ nudge,绝不 auto-exec**。这**有意比插件 `callReplyGuard` 更保守**:插件在 Bridge outage 时对 core channel / roundtable thread / free-form fail-open(因为它没有第二条安全网),但 auto-exec 这里**有 nudge 兜底**——验不了 guard 就退回 nudge,让 agent 走真 reply 工具(它自己再过 guard)。文档里显式声明这条"stricter-than-plugin"语义,避免被误读成 guarded 等价漏了 outage 分支。

**`discord_post()`（HIGH-1/HIGH-7）**：**Python `urllib.request`**（非 curl，token 不进 argv；可注入 transport 供测试）。body = `json.dumps({"content": text, "allowed_mentions": {"parse": []}})`。`Authorization: Bot <token>` 走 header。token 经 `(PROJECT_NAME|FLYWHEEL_PROJECT_NAME, FLYWHEEL_LEAD_ID)` 双键从 `projects.json` 解 `botTokenEnv`（**同 lead-alert.sh 双键,绝不退回首个匹配 lead**,Codex MED-6）。

**`atomic_claim()` — 显式 state machine（R2-HIGH:dedupe 本身绝不诱发双发）**:key = `sha256(tool|chat_id|content)`,单文件持久记录(status/ts/pid/project/lead/channel/tool/hash/msg_id)。状态机:

- `open(<key>, O_CREAT|O_EXCL|O_WRONLY)` 成功 → **OWNER**,写 `CLAIMED`。**只有 owner 能 POST、只有 owner 失败才 nudge**。
- O_EXCL 失败(已存在)→ 读现状:
  - `SENT` → return 0(已发,静默)。
  - `CLAIMED`/`POSTING` 且 **fresh(<TTL)** → `FRESH_PENDING_OTHER`:**return 0,绝不 nudge、绝不 POST**(别的 hook 正持有/发送;nudge 会驱动 agent 重发 = 双发,这正是 R2-HIGH 的洞)。
  - **`POSTING` 且 stale(>TTL)** → owner 可能在 POST 中途崩了、**Discord 是否已收下未知**:`STALE_POSTING` → **不自动重发**(Discord create-message 无幂等 nonce,重发可能双发)→ 写 FLY-368 metadata alert + `nudge_ambiguous`(明确告诉 agent"上一次发送结果不确定,确认后再决定,别盲目重发")。
  - **`CLAIMED` 且 stale(>TTL,从未进 POSTING)** → owner 在 POST **之前**崩了、**确定没发过** → **安全 reclaim**(原子改写为本进程 owner)→ 当 OWNER 继续。
- owner POST **2xx** 后写 `SENT`(带 msg_id);失败写 `FAILED`(同 owner 可 bounded 重试,见 retry)。目录 bounded(TTL + 上限,旧 `SENT`/`FAILED` 清理)。

> 唯一残留双发窗 = owner 在 `POSTING` 中途崩 **且** Discord 实际已收下 **且** 之后 `nudge_ambiguous` 致 agent 重发 —— 极窄(crash-mid-POST)、**显式 alert 标记可见**、不系统性。真要消除需 Discord 幂等 nonce(本 PR out-of-scope,记 follow-up)。

**retry（LOW-9,pinned）**：≤2 次,总 wall-clock ≤8s,honor `Retry-After`(上限 5s),网络 timeout 计入;耗尽 → nudge（**不 blind queue**,会话 reply 要快不能让 Claude 觉得 hang）。

**audit（MED-8,成功后 metadata-only）**：project/lead/tool/channel/content-hash/text-len/transcript/assistant-uuid/HTTP status/Discord msg-id/hook-version/ts。**绝不写 token / 全文**。

**silent-approve 正确性**：成功 return 0 → turn 正常结束、不被重 prompt → 不立刻重发;下轮 Annie 新消息开启,旧 leak 在新 genuine prompt 前不重扫;原子 claim 兜并发/后续轮同内容。

## Security analysis（Codex R1 后）

| 风险 | 缓解 |
|---|---|
| RCE / 任意工具 | auto-exec allowlist 仅 `{reply}`;Write/任意工具**永不** auto-exec(D5/HIGH-2)。 |
| 绕过 reply-guard / mention 安全 | auto-exec **先调 reply-guard** + `allowed_mentions:{parse:[]}`(HIGH-1)= 与真 reply 工具等价。 |
| Write 写盘面 / config poison / TOCTOU | **不 auto-exec Write**(HIGH-2)。 |
| 并发双发 | **原子 O_EXCL pre-send claim**(HIGH-3)。 |
| 多 leak 块静默丢 | **单候选才 exec,否则 nudge**(HIGH-4)。 |
| 误判→真发错 | 仅 Tier B + 完整闭合 + 必填齐 + 剥围栏 + reply-guard(D3/HIGH-1)。 |
| prompt injection(leak 体不可信) | 只提结构化参数(chat_id 纯数字/text)、不解释内容;reply-guard 拦 issue-token;body 经 json.dumps。 |
| token 泄漏 | Python urllib header(不进 argv,HIGH-7);**绝不进 log/marker/reason/audit**(secret-canary 测试)。 |
| 截断 leak 被执行 | auto-exec 要求 `fully_closed`;截断只 nudge(Keep#3/MED-5)。 |
| Stop hook 失败/wedge | 任何失败/不满足 → 退回 nudge(不劣于今天);`stop_hook_active` bounded 保持(Keep#5)。 |
| 投递无 tool_use 审计 | metadata-only audit 留证(MED-8)。 |

## Code review corrections (Codex code review R1 → applied)

Codex code review caught 7 real code-level issues; all fixed. One reversed a design-review decision (Lead-approved):

- **#2 (HIGH, design correction) — reply-guard policy: stricter → plugin-equivalent HYBRID.** The design's "any guard-unreachable → nudge" was **self-defeating for the FLY-583 target Belle**: FLY-231 clears companion Bridge auth → Belle's guard call always 401 → always nudge → Belle never auto-execs. Fixed to **exactly match the production plugin's hybrid fail policy** (FLY-162/173/314): explicit `allow=true`→exec, `allow=false`→nudge, no-verdict (401/404/5xx/timeout) → **issue-bearing text fail-CLOSED (nudge), free-form fail-OPEN (exec)**. So Belle's free-form replies auto-exec while @-mentions stay neutralized by `allowed_mentions:{parse:[]}` and cross-issue posts fail-closed. **Lead-approved as an engineering decision** (restores the verified baseline, not new risk). This is the **core independent-QA acceptance point**: real-machine verify "Belle free-form auto-sends when guard unreachable, Annie receives."
- **#1 (HIGH) — claim race**: stale-CLAIMED reclaim is now serialized by an O_EXCL `<key>.lock`; every owner carries a nonce; `claim_set` is a nonce CAS → a lost-race process can never POST.
- **#3 (HIGH) — single-candidate**: gate now requires exactly ONE reply leak opener total (closed OR truncated) + one eligible candidate; eligible+ineligible/truncated → nudge.
- **#4 (MED) — FAILED claim**: explicit FAILED state → nudge (no longer silently swallowed).
- **#5 (MED) — retry**: single wall-clock deadline for the POST loop; per-request timeout bounded by remaining budget; honors 429 Retry-After (capped); never sleeps past the deadline.
- **#6 (MED) — defensive**: isinstance guards (resolve_bot_token), safe ts parse (atomic_claim), whole auto-exec path wrapped → corrupt config/marker falls back to nudge, never crashes the global hook.
- **#7 (LOW) — audit**: success + ambiguous audit rows carry transcript path + leaking assistant uuid (still never token / content).

**Tests: 87 passing** (legacy byte-compat + auto-exec + claim state machine + hybrid guard). Install suites 6+6 green.
