## 2. Current State (Codebase Audit — Round 2 corrected)

### 2.1 Critical fact: shared tmux session + per-runner window

> Codex Round 1 的关键发现：之前 Y' 方案的整个前提错了。

**Shared session model** (FLY-102 PR #146)：
- `run-infra.ts:302` 把 sessionName 设成 `runner-${projectName}` —— **一个项目所有 Runner 共用一个 tmux session**
- `TmuxAdapter.execute()` (`TmuxAdapter.ts:174-200`) 每个 Runner **新开一个 window**，CommDB 注册 `tmuxWindow = ${sessionName}:${windowId}` (e.g. `runner-flywheel:@42`)
- `closeRunner()` → `killTmuxWindow(tmuxWindow)` 是 **`tmux kill-window`**（`tmux-lookup.ts:128-160`），不是 `kill-session`
- 注释明确：`Using kill-window preserves other Runners sharing the same session`

**含义**:
- 一个 Runner window 被 kill **不会** 让 session-level `tmux attach` 退出（其他 Runner window 还活着）
- 因此前一版 Y' 的"`kill tmux → attach exit → wrapper close`"链子根本跑不通
- Y' 方案被否决

### 2.2 Opener — `packages/core/src/tmux-viewer.ts` (FLY-277 / GEO-277)

`openTmuxViewer(sessionName)` 131 行 two-phase AppleScript:
- Phase 1: 等 tmux client attach (max 120s)
- Phase 2: 轮询（delay 3s）`processes of viewerTab`，tmux 进程消失 → `close viewerWindow`

**关键问题**:
- 调用方只传 `sessionName`（共享 session 名），没 `windowId` / `executionId` / `sessionRole` → tab 标识只能用 sessionName，多 Runner 撞名
- 当前 Phase 2 的"tmux 进程消失"判定在共享 session 模式下意义不大：session 进程一直活着（其他 Runner 撑着），tmux process check 永远返回 true。**Phase 2 实际没在工作**——Phase 2 是 dead code，但因为 attach 在 window kill 时会 detach 回 shell（而 shell 还在 tab 里），导致 tab 不关。

调用方（`run-dispatcher.ts:73`, `run-dispatcher.ts:272`, `DagDispatcher.ts:63`）都传共享 sessionName。

### 2.3 Lead-driven close — `packages/teamlead/src/bridge/close-runner.ts` (FLY-102 R3)

`closeRunner(opts, store)` 流程：
1. 校验 `session.status ∈ CLOSE_ELIGIBLE_STATES` (`completed / failed / blocked / rejected / deferred / shelved / terminated`)
2. 从 commDB 拿 `target.tmuxWindow` (e.g. `runner-flywheel:@42`)
3. `killTmuxWindow(target.tmuxWindow)` → `tmux kill-window`
4. 写 audit (`lead_close_runner` / `lead_close_runner_failed` / `lead_close_runner_blocked`)
5. 不 osascript 关 Terminal tab —— 依赖 (失效的) Phase 2 watcher

返回 contract: `{closed, alreadyGone?, error?}`，Bridge route 把 `success: result.closed` 暴露给 Terminal MCP（`terminal-mcp/src/index.ts:402-410`）。

### 2.4 Post-merge cleanup — `packages/teamlead/src/bridge/post-merge.ts:42-83`

`postMergeTmuxCleanup(opts, store)` 在 ship/approve 后 fire-and-forget 跑：
1. `getTmuxTargetFromCommDb(executionId, projectName)`
2. `killTmuxWindow(target.tmuxWindow)` —— **同样不关 Terminal tab**
3. audit (`post_merge_completed` / `post_merge_partial`)

→ **遗漏点**：如果只 hook closeRunner 加 Terminal close，post-merge 路径还会留 dead tab。需要 shared helper 在两边都调。

### 2.5 Status taxonomy

`OUTCOME_STATUSES` (StateStore.ts:6-16):
```
completed, approved, approved_to_ship,
blocked, failed, rejected, deferred, shelved, terminated
```

**Hybrid (Annie Q2.5)** — 按行为切：

| Status | 类别 | tmux window | Terminal tab |
|--------|------|-------------|--------------|
| `completed` | success | kill (existing) | **close** (new) |
| `rejected` | success | kill (existing) | **close** (new) |
| `shelved` | success | kill (existing) | **close** (new) |
| `deferred` | success | kill (existing) | **close** (new) |
| `terminated` | success | kill (existing) | **close** (new) |
| `failed` | **crash** | preserve (changed) | preserve |
| `blocked` | **crash** | preserve (changed) | preserve |

→ `failed` / `blocked` 在 closeRunner 调用时不再 kill window，使 Annie 能切过去看输出。等用户后续 `retry` / `shelve` / `defer` / `terminate` 触发再清。

## 3. Why dead tab accumulates (revised root-cause)

之前一版 hypothesis 部分对，但 Codex Round 1 揭示了真正 root cause：

**当前架构下 Phase 2 watcher 实际上不工作** —— 因为共享 session 始终活着，`processes of viewerTab` 始终包含 tmux，所以 Phase 2 永远不触发 close。Tab 内 `tmux attach` 在 window 被 kill 时只是 detach 回 shell（attach 是连 session 不是连 window），shell 还跑着 → tab 不关 → 累积 dead tab。

→ FLY-116 的本质：**新增一条事件驱动的 per-window Terminal tab close path**，**移除/重构** 失效的 Phase 2 polling。同时处理 macOS 重启场景留下的孤儿 tab。

## 4. Selected Approach: W'' — Window-Aware close + One-Shot Boot Reaper

> **Y' 已否决** (Codex Round 1 issue #1)。本节正面写 W''。

### 4.1 核心设计

1. **Opener 接受 per-window 唯一标识**：`openTmuxViewer({sessionName, executionId, windowId, sessionRole, projectName})`，给 Terminal tab 设 unique custom title。
2. **新增 shared helper `closeRunnerTerminalView()`**：osascript exact-match close 单 tab。
3. **`closeRunner` 在 success states 调** `closeRunnerTerminalView()`；**crash states 改为不 kill tmux window**（保留 tab + tmux 让 Annie 看）。
4. **`postMergeTmuxCleanup` 也调** `closeRunnerTerminalView()`（不能漏）。
5. **Bridge startup one-shot reaper**：启动时扫一次 Terminal tabs，根据 commDB 状态关 success-state 或 tmux window 已死的孤儿 tab。**只跑一次，非 polling**。
6. **Phase 2 watcher 移除**（dead code）—— 用事件驱动 close 替代轮询。

#### 4.2.3 Tab title

精确格式（per-execution unique，含 sessionName）：

```
flywheel:runner:<sessionName>:<projectName>:<executionId>:<windowId>:<sessionRole?>
```

举例：
- `flywheel:runner:runner-flywheel:flywheel:exec_abc123:@42:engineer`
- `flywheel:runner:runner-flywheel:flywheel:exec_xyz789:@43:qa`

- `windowId` — tmux window id (e.g. `@42`)
- `sessionRole` — engineer/qa/designer/...（来自 `StateStore.session_role`）

为啥含 `sessionName`：reaper/closeRunner 不再 reconstruct `runner-${project}`，直接从 title 解析或 commDB 查 `target.tmuxWindow`。

  projectName: string;

  windowId: string;
  sessionRole?: string;

export function formatViewTitle(p: ViewTitleParts): string {
  const role = p.sessionRole ? `:${p.sessionRole}` : "";
  return `flywheel:runner:${p.sessionName}:${p.projectName}:${p.executionId}:${p.windowId}${role}`;
}

export function parseViewTitle(title: string): ViewTitleParts | null {
  // flywheel:runner:<sessionName>:<projectName>:<executionId>:<windowId>[:<role>]
  const m = title.match(/^flywheel:runner:([^:]+):([^:]+):([^:]+):(@[^:]+)(?::(.+))?$/);
  if (!m) return null;
  return { sessionName: m[1], projectName: m[2], executionId: m[3], windowId: m[4], sessionRole: m[5] };
}

/**
 * Resolve the unique Terminal viewer identity for a given Runner session.
 * Returns null if target.tmuxWindow is malformed.

 * NOTE: sessionRole comes from StateStore.sessions.session_role (FLY-59),

export function resolveTerminalViewIdentity(

### 4.3 实现细分

#### 4.3.1 Opener 重构 — per-viewer linked tmux session + onTmuxWindowCreated callback

> **Codex Round 2 主要 blocker** (issues #1, #2, #3) 解决方案：
> - **#1 timing**: opener 必须在 window 创建后立即调（而不是 `await TmuxAdapter.execute()` 完才调，那时 Runner 已跑完，Annie 看不到运行过程）。
>   *实际上* 当前 dispatcher 在 `await TmuxAdapter.execute()` *前* 就调了 `openTmuxViewer(sessionName)` —— 但那时 windowId 还没生成。
>   方案：改用 **callback 模式**，dispatcher 把 viewer-open 函数作为 callback 传入 `TmuxAdapter.execute()`，TmuxAdapter 在 `new-window` 拿到 `windowId` 后立即调 callback (在 `waitForCompletion` 之前)。
> - **#2 dedup**: 当前 session-level `list-clients -t =sessionName` 在共享 session 下永远命中第一个 Runner 的 attach client，导致后续 Runner 都被 skip 不开 tab。改成**按 custom title** dedup：osascript 开 tab 之前先扫一遍 windows × tabs，看有没有 title 已存在的 → 存在则 skip。
> - **#3 attach 语义**: `tmux attach -t session:@windowId` 不是合法命令（attach-session 只接 session target）。方案：**每个 Runner 开自己的 linked viewer session**，attach 到 linked session（每个 viewer 有独立 current-window pointer），互不影响。

##### 4.3.1.1 Linked viewer session 机制

每个 Runner viewer 一个独立 tmux **linked session**（`tmux new-session -t base-session`），它共享 base session 的 windows 但有独立 current-window pointer。

```sh
# 创建 linked viewer session (windows shared with base, current-window 独立)
tmux new-session -d -s viewer-${executionId} -t ${baseSession}

# 设 viewer session 的 current window 为目标 Runner window
tmux select-window -t viewer-${executionId}:${windowId}

# Terminal 内 attach linked session
tmux attach -t =viewer-${executionId}
```

清理时：
- success: kill linked viewer session (`tmux kill-session -t viewer-${executionId}`) → attach 退出 → osascript close tab
- crash: 留 linked viewer session + tab

注意 linked session 命名 `viewer-<executionId>` 短于 9 chars 的 UUID prefix 可能冲突；用完整 executionId（UUID）保证 unique。

##### 4.3.1.4 伪代码

```ts
export function openTmuxViewer(opts: TmuxViewerOpts): void {
  const tmuxPath = resolveTmuxPath();
  if (!tmuxPath) return;

  const customTitle = formatViewTitle({
    sessionName: opts.baseSessionName,
    projectName: opts.projectName,
    executionId: opts.executionId,
    windowId: opts.windowId,
    sessionRole: opts.sessionRole,
  });
  const safeTitle = escapeAppleScript(customTitle);
  const viewerSession = `viewer-${opts.executionId}`;

  // Codex Round 4 #4: in-process opening guard prevents TOCTOU race
  // (two concurrent openTmuxViewer() calls for the same title both seeing dedup miss).
  if (openingTitles.has(customTitle)) {
    console.log(`[tmux-viewer] open already in-flight for ${customTitle}, skip`);
    return;
  }
  openingTitles.add(customTitle);

  // dedup: 检查是否已有相同 custom title 的 tab，避免重复开
  // (run async; if dedup hit, skip create)
  const dedupScript = [
    'tell application "Terminal"',
    `  set targetTitle to "${safeTitle}"`,
    "  repeat with w in windows",
    "    repeat with t in tabs of w",
    "      try",
    "        if (custom title of t as text) is targetTitle then return \"exists\"",
    "      end try",
    "    end repeat",
    "  end repeat",
    "  return \"open\"",
    "end tell",
  ].join("\n");

  execFile("osascript", ["-e", dedupScript], (err, stdout) => {
    if (!err && stdout.trim() === "exists") {
      console.log(`[tmux-viewer] viewer already open for ${customTitle}, skip`);
      openingTitles.delete(customTitle);
      return;
    }
    try {
      actuallyOpen();
    } finally {
      // clear guard once osascript spawn fired — concurrent calls in the meantime
      // were correctly blocked. (Don't clear on success only; we always need to
      // release so a future legitimate re-open after close can proceed.)
      // Use timer to outlast the small spawn window so very-fast double-calls collapse.
      setTimeout(() => openingTitles.delete(customTitle), 1000);
    }
  });

  function actuallyOpen() {
    // race guard: closeRunnerTerminalView 可能 cancel 我们 (Codex Round 3 #5)
    if (cancelledExecutions.has(opts.executionId)) {
      console.log(`[tmux-viewer] opener cancelled for ${opts.executionId}, skip spawn`);
      openingTitles.delete(customTitle);
      return;
    }

    // === Idempotent linked viewer setup (Codex Round 3 #6) ===
    // Pre-kill stale viewer session synchronously via execFile (NOT shell),
    // so we know our subsequent new-session creates fresh state.
    // This runs in Node before launching Terminal — no shell escaping needed.
    try {
      execFileSync(tmuxPath, ["kill-session", "-t", `=${viewerSession}`], {
        stdio: "ignore", timeout: 3000,
      });
    } catch {
      /* benign — viewer session may not exist yet */
    }
    try {
      execFileSync(tmuxPath, ["new-session", "-d", "-s", viewerSession, "-t", `=${opts.baseSessionName}`], {
        stdio: "ignore", timeout: 5000,
      });
    } catch (err) {
      const msg = (err as Error).message;
      if (!/duplicate session/.test(msg)) {
        // setup may fail if the base session vanished; select-window validation below will abort safely.
        console.log(`[tmux-viewer] viewer session create warn: ${msg}`);
      }
    }
    // Codex Round 4 #3: select-window failure is NOT benign — attaching to the wrong
    // current window shows a different Runner. Bounded retry; abort opener if cannot select.
    let selectOk = false;
    for (let attempt = 0; attempt < 5; attempt++) {
      try {
        execFileSync(tmuxPath, ["select-window", "-t", `${viewerSession}:${opts.windowId}`], {
          stdio: "ignore", timeout: 3000,
        });
        selectOk = true;
        break;
      } catch {
        // window may still be initializing; sleep briefly between attempts.
        // Use sync `sleep` shell binary (no Promise — execFileSync is sync).
        try { execFileSync("sleep", ["0.5"], { stdio: "ignore", timeout: 1000 }); } catch { /* sleep unavailable on host? best-effort */ }
      }
    }
    if (!selectOk) {
      console.warn(`[tmux-viewer] select-window failed after 5 attempts for ${viewerSession}:${opts.windowId} — aborting viewer open`);
      // cleanup the linked viewer session we created so we don't leak it
      try { execFileSync(tmuxPath, ["kill-session", "-t", `=${viewerSession}`], { stdio: "ignore", timeout: 2000 }); } catch {}
      return;
    }

    // shell command for Terminal tab — POSIX-safe quote escaping (Codex Round 3 #7).
    // sessionName/windowId/viewerSession 来自项目 config + UUID, 已 alphanumeric+dash+@.
    // defense-in-depth: properly POSIX-escape (' → '\'')
    //
    // At this point sync execFile already (a) killed any stale viewer session,
    // (b) created the linked viewer session, (c) successfully selected the target window.
    // The in-tab shell only needs to attach. No fallback `new-session` here — that masks bugs.
    const safeViewer = posixEscape(viewerSession);
    const shellCmd = `exec ${tmuxPath} attach -t '=${safeViewer}' 2>/dev/null`;

    const script = [
      'tell application "Terminal"',
      `  set viewerTab to do script "${escapeAppleScriptShellCmd(shellCmd)}"`,
      `  set custom title of viewerTab to "${safeTitle}"`,
      "  activate",
      "end tell",
    ].join("\n");

    execFile("osascript", ["-e", script], (err) => {
      if (err) console.warn(`[tmux-viewer] open failed: ${err.message}`);
    });
  }
}

function escapeAppleScript(s: string): string {
  return s.replace(/\\/g, "\\\\").replace(/"/g, '\\"');
}

/**
 * AppleScript-string-escape a shell command (which itself contains
 * already-shell-escaped POSIX strings). The shell command is going INSIDE
 * an AppleScript double-quoted literal in `do script "..."`.
 */
function escapeAppleScriptShellCmd(s: string): string {
  return s.replace(/\\/g, "\\\\").replace(/"/g, '\\"');
}

/**
 * POSIX single-quote escape (Codex Round 3 #7).
 * Replaces every ' with '\'' so the result can be wrapped in '...' safely.
 */
function posixEscape(s: string): string {
  return s.replace(/'/g, "'\\''");
}
```

#### 4.3.2 新 helper `closeRunnerTerminalView()` (`packages/core/src/tmux-viewer.ts`)

```ts
export interface CloseTerminalViewOpts {
  baseSessionName: string;       // for linked viewer session name parsing
  projectName: string;
  executionId: string;
  windowId: string;
  sessionRole?: string;
}

/**
 * Close Runner Terminal tab + linked viewer tmux session.
 * 1. tmux kill-session viewer-<executionId> (causes attach to exit; safe — only kills viewer linked session, not base)
 * 2. osascript close tab by exact custom title (in case attach-exit didn't auto-close)
 * Exact-match selector — closes at most 1 tab. Failure is non-fatal (warn log).
 */
export async function closeRunnerTerminalView(opts: CloseTerminalViewOpts): Promise<{
  killedViewerSession: boolean;
  closedTab: boolean;
  error?: string;
}> {
  const tmuxPath = resolveTmuxPath();
  const viewerSession = `viewer-${opts.executionId}`;

  // 1. kill linked viewer session (attach exits; base session unaffected)
  let killedViewerSession = false;
  if (tmuxPath) {
    try {
      await execFileAsync(tmuxPath, ["kill-session", "-t", `=${viewerSession}`], { timeout: 5000 });
      killedViewerSession = true;
    } catch (err) {
      const msg = (err as Error).message;
      // benign: viewer session already gone
      if (!/can't find session|session not found|no server running/.test(msg)) {
        console.warn(`[tmux-viewer] kill viewer-session failed: ${msg}`);
      }
    }
  }

  // 2. osascript close tab (best-effort; in case attach didn't exit cleanly)
  const target = formatViewTitle({
    sessionName: opts.baseSessionName,
    projectName: opts.projectName,
    executionId: opts.executionId,
    windowId: opts.windowId,
    sessionRole: opts.sessionRole,
  });
  const safe = escapeAppleScript(target);

  const script = [
    'tell application "Terminal"',
    `  set targetTitle to "${safe}"`,
    "  repeat with w in windows",
    "    repeat with t in tabs of w",
    "      try",
    "        if (custom title of t as text) is targetTitle then",
    "          close t",
    "          return \"closed\"",
    "        end if",
    "      end try",
    "    end repeat",
    "  end repeat",
    "  return \"not_found\"",
    "end tell",
  ].join("\n");

  return new Promise((resolve) => {
    execFile("osascript", ["-e", script], (err, stdout) => {
      if (err) {
        console.warn(`[tmux-viewer] close tab failed: ${err.message}`);
        resolve({ killedViewerSession, closedTab: false, error: err.message });
        return;
      }
      resolve({ killedViewerSession, closedTab: stdout.trim() === "closed" });
    });
  });
}
```

**安全保证**:
- `is targetTitle` (exact equality) — 不是 `contains`
- `close t` 单 tab — 不是 `close window`
- `return` 在第一 match 后立即退出 — 不会关多个
- AppleScript 字符串转义（`escapeAppleScript`）— defense-in-depth
- `tmux kill-session -t '=viewer-<exec>'` 严格 match `=` 前缀 → 只关 linked viewer session，不影响 base session
- 整个流程在 try wrap，失败 warn log，主流程不阻塞

#### 4.3.3 `closeRunner` 行为切片

> Codex Round 4 #5: 这一节是单一权威 sketch。`forcePreserved` gate logic 跟 §4.3.9.1 一致（同一段代码不同视角）。

```ts
// close-runner.ts
import { closeRunnerTerminalView } from "flywheel-core";
import { resolveTerminalViewIdentity } from "./terminal-view-identity.js";

export async function closeRunner(
  opts: CloseRunnerOpts,
  store: StateStore,
): Promise<CloseRunnerResult> {
  const session = store.getSession(opts.executionId);
  if (!session) return { closed: false, error: "session_not_found" };

  const auditKey = `${opts.executionId}-${opts.leadId ?? "unknown"}`;
  const isPreserveState = CRASH_PRESERVE_STATES.has(session.status);
  const forceClose = !!opts.forcePreserved && isPreserveState;

  // CRASH preserve gate: 不 kill window, 不 close tab — UNLESS forcePreserved override
  if (isPreserveState && !opts.forcePreserved) {
    store.insertEvent({
      event_id: `close-runner-preserved-${auditKey}`,
      execution_id: opts.executionId,
      issue_id: opts.issueId,
      project_name: opts.projectName,
      event_type: "lead_close_runner_preserved",
      source: "bridge.close-runner",
      payload: {
        status: session.status,
        reason: "crash_preserve",
        leadId: opts.leadId,
      },
    });
    return { closed: false, preserved: true, reason: "crash_preserve" };
  }

  // Eligibility gate: AUTO_CLOSE_STATES OR force-closing a preserve-state runner
  if (!AUTO_CLOSE_STATES.has(session.status) && !forceClose) {
    return { closed: false, error: `status_not_eligible:${session.status}` };
  }

  const target = getTmuxTargetFromCommDb(opts.executionId, opts.projectName);
  if (!target) {
    // No CommDB target → tmux already gone. Audit + return; do NOT attempt
    // osascript close here — without target.tmuxWindow we can't reconstruct
    // viewer identity. Orphan tab cleanup is the boot reaper's job.
    // (Codex Round 2 #5 — fix unreachable orphan-close branch.)
    store.insertEvent({
      event_id: `close-runner-${auditKey}`,
      execution_id: opts.executionId,
      issue_id: opts.issueId,
      project_name: opts.projectName,
      event_type: "lead_close_runner",
      source: "bridge.close-runner",
      payload: { closed: true, alreadyGone: true, reason: opts.reason, leadId: opts.leadId },
    });
    return { closed: true, alreadyGone: true };
  }

  // success path: resolve identity, kill tmux window, then close Terminal viewer
  const identity = resolveTerminalViewIdentity(session, target);
  const killRes = await killTmuxWindow(target.tmuxWindow);

  // Terminal close — non-fatal, requires resolved identity
  if (identity) {
    await closeRunnerTerminalView({
      baseSessionName: identity.sessionName,
      projectName: identity.projectName,
      executionId: identity.executionId,
      windowId: identity.windowId,
      sessionRole: identity.sessionRole,
    }).catch((e) => console.warn(`[close-runner] terminal close warn: ${e.message}`));
  } else {
    console.warn(`[close-runner] could not resolve viewer identity for ${opts.executionId}; skipping terminal close`);
  }

  // Audit eventType differentiates natural close from forced-preserved
  const eventType = forceClose ? "lead_close_runner_force_preserved" : "lead_close_runner";
  const outcomePrefix = killRes.error ? "close-runner-failed" : (forceClose ? "close-runner-force" : "close-runner");
  store.insertEvent({
    event_id: `${outcomePrefix}-${auditKey}`,
    execution_id: opts.executionId,
    issue_id: opts.issueId,
    project_name: opts.projectName,
    event_type: killRes.error ? "lead_close_runner_failed" : eventType,
    source: "bridge.close-runner",
    payload: {
      closed: killRes.killed,
      forcedPreserved: forceClose || undefined,
      reason: opts.reason,
      leadId: opts.leadId,
      tmuxError: killRes.error,
    },
  });
  return { closed: killRes.killed, error: killRes.error };
}
```

> **Metadata 来源 (Codex Round 2 #4)**: `resolveTerminalViewIdentity()` (定义于 §4.2.4) 从 `session` (StateStore) 拿 `session_role`，从 `target.tmuxWindow` 解析 `sessionName` + `windowId`。`session_role` 字段已在 `StateStore.sessions` 表（FLY-59 ship）；implementation Step 1 verify。

#### 4.3.5 Bridge startup one-shot reaper — status-dominant

新文件 `packages/teamlead/src/bridge/terminal-tab-reaper.ts`：

> **Codex Round 2 fixes**:
> - **#6** 不再 reconstruct `runner-${project}` — 从 title 解析 `sessionName`，或者用 commDB `target.tmuxWindow`
> - **#7** **Status-dominant policy**: `failed` / `blocked` 永远不被 reaper 关，即使 tmux window 已死（保留 scrollback 给 Annie）

```ts
import { execFile } from "node:child_process";
import { parseViewTitle } from "flywheel-core";  // Codex Round 4 #1: pure helper lives in core
import type { StateStore } from "../StateStore.js";
import { isTmuxWindowAlive } from "./tmux-lookup.js";

const AUTO_CLOSE_STATES = new Set(["completed", "rejected", "deferred", "shelved", "terminated"]);
const PRESERVE_STATES = new Set(["failed", "blocked"]);

/**
 * One-shot scan of macOS Terminal tabs at Bridge startup.
 * Status-dominant: PRESERVE_STATES never closed, even if tmux window is dead.
 * Otherwise close iff status ∈ AUTO_CLOSE_STATES OR (no session row AND tmux window dead).
 *
 * NEVER matches by `[exited]` or broad pattern. Only exact custom title.
 */
export async function reapTerminalTabs(store: StateStore): Promise<{
  scanned: number;
  closed: number;
  preserved: number;
  errors: string[];
}> {
  // 1. enumerate tabs with custom title prefix flywheel:runner:
  const listScript = [
    'tell application "Terminal"',
    "  set out to {}",
    "  repeat with w in windows",
    "    repeat with t in tabs of w",
    "      try",
    "        set ttl to (custom title of t as text)",
    '        if ttl starts with "flywheel:runner:" then',
    "          set end of out to ttl",
    "        end if",
    "      end try",
    "    end repeat",
    "  end repeat",
    '  set AppleScript\'s text item delimiters to linefeed',
    "  return out as text",
    "end tell",
  ].join("\n");

  const titles = await runOsascript(listScript).catch(() => "");
  const lines = titles.split("\n").map(l => l.trim()).filter(Boolean);

  const result = { scanned: lines.length, closed: 0, preserved: 0, errors: [] as string[] };

  for (const title of lines) {
    const parsed = parseViewTitle(title);  // includes sessionName field (Codex #6)
    if (!parsed) continue;
    const { sessionName, projectName, executionId, windowId } = parsed;

    const session = store.getSession(executionId);

    // STATUS-DOMINANT (Codex #7): preserve states never close
    if (session && PRESERVE_STATES.has(session.status)) {
      result.preserved++;
      continue;
    }

    // tmuxWindow constructed from title sessionName (NOT reconstructed from project name)
    const tmuxWindow = `${sessionName}:${windowId}`;
    const tmuxAlive = await isTmuxWindowAlive(tmuxWindow);

    // close iff:
    //   (a) status ∈ AUTO_CLOSE_STATES (final outcome states that should auto-close), OR
    //   (b) no session record AND tmux window dead (true orphan)
    //
    // Codex Round 3 #8 + Round 4 #2: no-session+!tmuxAlive case is "true orphan cleanup".
    // The reaper is only invoked from Bridge bootstrap *after* StateStore.create() resolves
    // successfully, so by the time `reapTerminalTabs(store)` runs the store is fully initialized.
    // We don't add a separate `isReady()` API — instead the reaper's call site is the gate:
    // it lives in `bridge/plugin.ts` startup sequence after store init, not in any background loop.
    // (See §9 Step 10 for the bootstrap call site.)
    const shouldClose =
      (session && AUTO_CLOSE_STATES.has(session.status)) ||
      (!session && !tmuxAlive);
    if (!shouldClose) continue;

    // close this exact tab
    const closeScript = [
      'tell application "Terminal"',
      `  set targetTitle to "${title.replace(/\\/g, "\\\\").replace(/"/g, '\\"')}"`,
      "  repeat with w in windows",
      "    repeat with t in tabs of w",
      "      try",
      "        if (custom title of t as text) is targetTitle then",
      "          close t",
      "          return",
      "        end if",
      "      end try",
      "    end repeat",
      "  end repeat",
      "end tell",
    ].join("\n");

    try {
      await runOsascript(closeScript);
      // also kill the linked viewer session for this exec (best effort)
      try {
        await execFileAsync("tmux", ["kill-session", "-t", `=viewer-${executionId}`], { timeout: 3000 });
      } catch { /* benign — viewer session may already be gone */ }
      result.closed++;
      store.insertEvent({
        event_id: `terminal-reaper-${executionId}-${windowId}-${Date.now()}`,
        execution_id: executionId,
        issue_id: session?.issue_id ?? "unknown",
        project_name: projectName,
        event_type: "terminal_tab_reaped",
        source: "bridge.startup-reaper",
        payload: { title, sessionStatus: session?.status, tmuxAlive, sessionName },
      });
    } catch (e) {
      result.errors.push(`${title}: ${(e as Error).message}`);
    }
  }

  return result;
}

function runOsascript(script: string): Promise<string> {
  return new Promise((resolve, reject) => {
    execFile("osascript", ["-e", script], { timeout: 10000 }, (err, stdout) => {
      if (err) reject(err);
      else resolve(stdout);
    });
  });
}
```

## 6. Specific Answers to Codex Open Questions

### Round 3 (9 implementation-detail blockers)

1. **Callback threading**: §4.3.1.5 — `BlueprintContext` + `AdapterExecutionContext` 加 `onTmuxWindowCreated`，`Blueprint.runInner()` forward 到 adapter，`TmuxAdapter.execute()` 在 new-window 后立即 fire。Dispatcher set callback into `BlueprintContext`。
2. **Helper package boundary**: §4.2.4 — `formatViewTitle` / `parseViewTitle` 在 `packages/core/src/terminal-view-identity.ts`；`resolveTerminalViewIdentity` 在 `packages/teamlead/src/bridge/terminal-view-identity.ts` import core helper。`core` 不依赖 `teamlead`。
3. **forcePreserved gate**: §4.3.9.1 — `forceClose = opts.forcePreserved && isPreserveState`；preserve-state gate 仅在 `!forcePreserved` 时挡；`!AUTO_CLOSE_STATES → status_not_eligible` gate 加 `&& !forceClose` 让 force-close 通过。
4. **actions.ts real hook points**: §4.3.9.2 — `handleTerminate` 加 closeTerminalView call；`handleRetry` 调 `closeRunner({forcePreserved:true})`；`reject/defer/shelve` 走 `transitionSession()` post-success hook (no separate handler today)。
5. **Opener vs close race**: §4.3.1.6 — `cancelledExecutions` Set + `cancelOpener(executionId)` API。`closeRunnerTerminalView` 入口先 cancel；opener 的 `actuallyOpen()` spawn osascript 前查 cancelled flag。
6. **Linked session idempotent**: §4.3.1.4 — pre-kill `viewer-${exec}` via `execFileSync` 同步，再 `new-session`。`select-window` 同步 bounded retry (5 次) 验证后才 spawn Terminal；in-tab shell 只 attach 到已验证的 viewer linked session。
7. **POSIX shell escaping**: §4.3.1.4 — `posixEscape(s) = s.replace(/'/g, "'\\''")` 标准 POSIX single-quote escape；execFile 直接调 tmux 不走 shell（无需 escape）。AppleScript 字符串单独 escape via `escapeAppleScript`。
8. **Reaper no-session age guard**: §4.3.5 — reaper 仅从 Bridge bootstrap (StateStore.create() 后) 调用，bootstrap 顺序本身即 gate；无独立 `isReady()` API。文档化 "true orphan cleanup" 接受 (no scrollback worth preserving once StateStore loses row)。
9. **Stale text**: §1 header / §7 / §10 — Round 4 update。

## 7. Risks & Constraints

- **绝不**用 broad osascript pattern（`contains` / `[exited]` / `every tab whose ...`）— 全部 exact match + 单 tab close + return after first
- 现有 `tmux-viewer.test.ts:120-149` Phase 2 polling 断言 **会破** — 必须重写测试覆盖新行为（custom title 设置 + linked viewer session model + race guard + custom-title dedup）
- **macOS Automation 授权**: 第一次跑会弹，CI 环境拒绝 → osascript 失败做 warn log，不阻塞主流程；README 加首次 note
- **StateStore schema**: 依赖 `Session.session_role` 字段（FLY-59 已 ship）。`getTmuxTargetFromCommDb` 只需返 `tmuxWindow` (现有 shape 即够 — `windowId` 从 `tmuxWindow` 解析，`sessionRole` 从 StateStore 拿)。Implementation Step 1 verify。
- **FLY-110 sync**: FLY-110 worker 需协调 — success 路径的 cmux pane-exited cleanup 跟 Terminal tab close 时机要 align
- **Reaper StateStore 依赖** (Codex Round 3 #8 + Round 4 #2)：reaper 只从 Bridge bootstrap 调用，bootstrap 顺序保证 `StateStore.create()` 已 resolve。无独立 `isReady()` API — bootstrap 本身是 gate。无 session 行 + tmux dead 才走 orphan-cleanup path
- **Race condition** (Codex Round 3 #5): opener 是 fire-and-forget，cancellation registry (cancelOpener / cancelledExecutions Set) 防 close 跑了 opener 还在创建 stale tab 的 race
- **Linked viewer session lifecycle**: 每 Runner 一个 `viewer-${exec}` linked session。pre-kill 用 execFile (sync) 保证 idempotent；kill 单一 viewer session 不影响 base + 其他 Runner viewer
