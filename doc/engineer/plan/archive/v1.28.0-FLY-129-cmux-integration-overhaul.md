## 3. Implementation Phases

**关键 sequencing 决定**：本 plan ship 为**单 PR**（squash merge），按 §3.1 起的顺序在同一 PR 内 commit。若 PR 过大允许拆：

1. **PR-A (foundation)**: Phase 0 (refresh-surfaces spike) + Phase 1 (lock 下沉) + Phase 2 (log spam silence) — 三条独立、低风险、立即收益的修。
2. **PR-B (refactor)**: Phase 3 (JSON parsing + helpers) + Phase 4 (ghost) + Phase 5 (state drain) + Phase 6 (dedup) — 内部 state 模型改造，互相依赖。

### Phase 0 — `cmux refresh-surfaces` Spike for H2 (NEW, Codex R1 Issue 10)

**目标**: 验证 `cmux refresh-surfaces [--workspace <ref>]` 是否能 invalidate cmux Electron 渲染端 cache、修 H2，从而把 Phase 8 从 close-and-recreate (~51s UI 闪烁) 缩到 refresh-surfaces (instant)。

**Spike 步骤**:
1. 在 dev 机器上 reproduce H2: kill ops-lead `claude-lead.sh` 进程 → wait Lead daemon 重启 → 打开 cmux UI 找到对应 workspace → 观察是否显示空 zsh（不是 active Claude）。
2. 如 1 复现 H2 → 跑 `cmux refresh-surfaces --workspace workspace:<N>` （N 为 ops-lead workspace ref）→ 立即看 cmux UI 是否切到 active Claude。
3. 重复 2 次以上 (Lead restart cycle) 确认 reproducibility。
4. **写 spike report** 到 `doc/engineer/research/new/FLY-129-refresh-surfaces-spike.md` (3-5 段)：步骤 + 结果 + 结论 + 对 Phase 8 的影响。

**决策树**:
- **Spike PASS** (refresh-surfaces 修 H2) → Phase 8 实现 = `trigger_cmux_refresh` 在 `--refresh` 之后调 `cmux refresh-surfaces` (覆盖所有 lead workspace refs)；删 `--close-for-restart` mode + audit log；删 51s UI 闪烁的 trade-off。**这是首选路径**。
- **Spike FAIL** (refresh-surfaces 不修 H2) → Phase 8 走 close-and-recreate + 增强（见下文 Issue 4 修订）：pending-invalidation file 让 watcher 在 cmux 恢复后才执行；session-missing case 改为 retry up to 30s。

**Test plan (Phase 0)**: spike 本身就是 manual verification；无 unit test。spike report 进 PR description。

### Phase 6 — Sidebar Dedup (scope #3, Codex R1 Issue 5 + Round 2 R2-6)

### 6.2 可靠性边界

| 故障场景 | 行为 |
|---|---|
| cmux app 完全离线 | watcher 静默 wait（指数 backoff cap 5min），tmux 侧 hook + event 流仍记录 → cmux 恢复后 sync_additive 重建 missing workspaces |
| watcher crash | EXIT trap 释放 lock；in-flight events 留在 `EVENT_FILE.processing` |
| Lead restart at refresh-surfaces 调用时刻 cmux 离线 (R2-7) | `cmux refresh-surfaces` exit 非 0；log 一行；下一次 Lead restart 时再试。**H2 stale cache 残留** 直到下次 close/recreate 或 Annie 手动 close — limitation 写进 PR description。（原 hybrid plan 的 Path B pending-refresh 文件兜底已删除 2026-05-22。） |
| cmux JSON 解析失败 (rc≠0 或 malformed) | `get_cmux_workspaces_json` fail-closed 返非 0；callers (`reap_ghost_workspaces` / `dedup_workspaces_by_title` / `reconcile_existing_workspaces` 的 cmux 部分 / `create_workspace_for_window` race-check) 该 tick `return 0` skip cmux mutation；transition log 1 行；下次 tick 重试 (R2-1) |

### 6.3 Rollback strategy

PR squash merge。Rollback = `gh pr revert <PR>` + 在每台 Lead 机器：
1. `git pull` 拉 revert
2. `pkill -f "flywheel-cmux-sync.*--watch"`（kill 新版 watcher）
3. 下次 cmux pane 启动会触发 autostart 重新拉起旧版（git pull 后的 HEAD）

无 schema 变更，无 DB 迁移。Audit log 不向后兼容（rollback 后旧版没这格式），可忽略。
