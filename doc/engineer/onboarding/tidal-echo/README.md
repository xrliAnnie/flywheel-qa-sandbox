# tidal-echo — onboarding materials (FLY-284)

**Staged, NOT live.** This directory is the reviewable, cutover-ready package for
standing up Annie's brand-new content project **tidal-echo** through Flywheel.
Nothing here is wired into a running system — it is delivered in the PR for
review. Live cutover happens separately, with Annie present (see `CUTOVER.md`).

## What tidal-echo is

A content / 自媒体 project that helps Annie make content. Two Leads from day one:
- **Triton** — Chief of Staff (triage, routing, founder roll-up; no Runners).
- **Ariel** — Content Lead (research direction → produce weekly; spawns Runners).

Content production itself (digital human / voice / video / platform strategy) is
**out of scope** for FLY-284 — Annie shapes that directly with Ariel after cutover.

## Files

| File | What it is |
|---|---|
| `config.yaml` | tidal-echo's `.flywheel/config.yaml` (team `TIDE`, doc-flow on, single content alias). |
| `registry.yaml` | tidal-echo's stable node registry overlay and backend-owned display label. |
| `content.md` | the content node's Runner prompt. |
| `cos-lead.identity.md` | **Triton** — bespoke CoS identity. |
| `content-lead.identity.md` | **Ariel** — bespoke Content Lead identity. |
| projects.json entry | draft `~/.flywheel/projects.json` entry — **inlined in `CUTOVER.md`** (machine-local; added at cutover). |
| `CUTOVER.md` | the live, founder-gated cutover runbook + Annie-manual checklist. |

## How it was made

`config.yaml` + `registry.yaml` + `content.md` are generated by the reusable scaffolder
`flywheel/scripts/setup-new-project.sh` (FLY-284). tidal-echo is that script's
first real run. The two identities are bespoke (persona + tidal-echo specifics)
on top of the script's skeleton. See the plan:
`doc/engineer/plan/inprogress/v1.49.0-FLY-284-from-scratch-onboard.md`.
