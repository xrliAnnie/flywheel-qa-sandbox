### S6 — Post-ship cleanup chain [AC-11]

❌ **FRAMEWORK-BLOCKED**, root cause is v1.24.2 Gap 2:

1. `scripts/test-auto-approve.sh` polls `comm.db.messages` looking for an `approve_to_ship` gate question:
   ```sql
   SELECT COUNT(*) FROM messages q
     WHERE q.execution_id = ?           -- ❌ column does not exist
       AND q.checkpoint = 'approve_to_ship'
       AND q.type = 'question'
   ```
   The `messages` table schema (verified):
   ```
   CREATE TABLE messages (
     id, from_agent, to_agent, type, content, parent_id, read_at,
     created_at, expires_at, checkpoint, content_ref, content_type, resolved_at
   )
   ```
   There is no `execution_id` column. The query fails silently (returns 0) which causes `test-auto-approve.sh` to time out at the 60 s poll deadline.

2. Even if the SQL were corrected to e.g. join via `parent_id` or `content_ref`, no gate exists: the FLY-108 Runner's `flywheel-land` skill writes `land-status.json` and exits without calling `flywheel-comm gate ask approve_to_ship`. The Round 3 runner pane is idle at the prompt with ctx=6%, no further work is being attempted.

Manual fallback `POST /api/actions/approve` succeeded (HTTP 200, FSM advanced to `approved_to_ship`, `action_executed` event fired) but the response carried `gateUnblocked=false` and Bridge logged:

```
[actions] approve succeeded but gate NOT unblocked for e957ccd5-…
Runner may need manual intervention if it's waiting on approve_to_ship gate.
```

So the post-ship chain (approve unblock → Runner merges PR → Runner exits → tmux `runner-test-slot-2` closes → chat thread archives) cannot be exercised under v1.24.2. **Gap 2 needs a v1.24.3 patch**.

## Verdicts

### FLY-108 PR #155 — **PASS for the fix's claimed scope**

The fix targets the exact bug pair fixed in `feat/v1.23.0-FLY-108-session-status-flip`:

- Runner-driven `session_completed` event fires reliably with valid payload (route + pr_number).
- Bridge route guard correctly flips `sessions.status` from `running` → `awaiting_review` → `approved_to_ship` on the real-Runner code path on a file-backed DB.

S6 (post-ship cleanup chain after Annie's :cool:) cannot run under v1.24.2 due to the framework Gap 2 defect, but that is a framework-side concern, not a PR #155 product concern.

**Ship recommendation**: green to ship FLY-108 PR #155.

### FLY-115 v1.24.2 framework — **Partial**

3 of 4 gap categories ship-ready (Gap 1, Gap C, Gap 3.x). **Gap 2 must be respun** in v1.24.3:

1. **Fix `test-auto-approve.sh` SQL** — join CommDB messages to executions via the actual schema (likely `content` JSON-extract or a new index). The current `q.execution_id = ?` predicate cannot succeed.
2. **Decide where the `approve_to_ship` gate should be created** — either Runner posts via `flywheel-comm gate ask` after writing `land-status.json`, or Bridge auto-creates the gate when it observes `awaiting_review + ready_to_merge`. Either is fine but one of them must exist or `gateUnblocked=true` is unreachable in test-slot.

Until v1.24.3 ships these two fixes, Round 3+ for any future PR will be limited to the same S6-blocked outcome.
