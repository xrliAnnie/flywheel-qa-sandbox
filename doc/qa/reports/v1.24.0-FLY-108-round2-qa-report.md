## FLY-115 Framework UX Feedback

Round 2 was the first real-user shakedown of the FLY-115 real-mode framework. Three UX pain points encountered:

### Fixed in v1.24.1 ✅

1. **Tail pipe blocking Runner start** — In v1.24.0, `test-deploy.sh` piped Runner tmux output through `tee | head -n 1000` which caused SIGPIPE when the Runner produced > 1000 lines. Runner hung silently. **Fix shipped in v1.24.1**: redirect to `${SLOT_DIR}/runner.log` with no pipe.
2. **Runner trust prompt blocks tmux input** — Claude Code CLI first-run prompts for "Trust this folder?". Runner never saw the prompt because the tmux window was detached at spawn. **Fix shipped in v1.24.1**: `--dangerously-skip-permissions` injected via wrapper + trust-prompt auto-ack.
3. **Teardown `sqlite3` delete error** (sub-bug a) — `test-teardown.sh` tried to drop tables from `:memory:` DB after Bridge had exited. **Fix shipped in v1.24.1**: conditional skip when DB path is `:memory:`.

### Still gaps (for v1.24.2)

4. **`botToken=MISSING` blocks Discord product verification** — Slot 2 (and all QA slots) has no per-slot bot token. `DirectEventSink.updateTag` skips with `botToken=MISSING`. This is the single biggest gap: without a Discord bot in the slot, S5 / S6 cannot observe real 🏁 / "需要你 review" messages. **Ask**: v1.24.2 should provision per-slot test bot tokens + register them in `access.json`, so `updateTag` actually posts and QA can assert Chrome Discord observation.
5. **Sandbox repo `auto-merge` not configured** — Runner correctly writes `land-status.json` with `status=ready_to_merge, prNumber=1`, but the sandbox PR never auto-merges. Bridge would normally listen for GitHub `pull_request.closed` webhook → final `completed` transition. In test-slot, webhook is not wired. **Ask**: v1.24.2 should either (a) wire a mock webhook on `gh pr merge`, or (b) post a synthetic `pull_request.closed` event to the slot Bridge after the Runner signals `ready_to_merge`.
6. **Discord `thread_id=none` + `chatThreads=false`** — Slot config disables forum threads entirely, so `DirectEventSink.updateTag` returns `no_thread`. AC-3 observation depends on a thread existing. **Ask**: v1.24.2 should provision a test forum + threads per slot, parallel to prod.

### Observed but not blocking

- `session_events.payload` stored as empty/NULL for `session_started` and `session_completed`, while `stage_changed` payloads are stored (22 / 21 bytes). Functional impact: none — FSM + DirectEventSink consumed the payload correctly before storage. Might be an intentional schema choice (metadata-only for those two types). Flagging for awareness.
- `IdleWatchdog` emitted `runner_idle_detected` once at 03:44 (90s stall while Runner was between stages). No impact — this is the expected watchdog cadence, and the Runner resumed. Noting in case future QA needs to suppress this for deterministic tests.
