# fleet/ — captured fleet topology (ZERO secrets)

This directory holds the **sanitized snapshot** of a Flywheel fleet host,
produced by `scripts/fleet-capture.sh` and consumed by
`scripts/provision-fleet-host.sh` (FLY-519).

## 🔴 Zero-secret contract

Everything committed here MUST be free of real secrets. The capture tool
enforces this with three layers (`scripts/lib/fleet-sanitize.sh`):

1. `~/.flywheel/.env` is **redacted to key names only** → `env.example`
   (every value stripped).
2. `projects.json` carries only token ENV **names** (e.g. `CASS_BOT_TOKEN`),
   never values — and is scanned anyway.
3. `scan_for_secrets` runs as a **hard gate** before anything is written; a
   single secret-looking match aborts the capture and writes nothing.
4. `fleet/.gitignore` is a final backstop against committing real `.env`/`*.db`/
   auth files.

**Before committing a fresh capture, eyeball it** and run:
`bash -c 'source scripts/lib/fleet-sanitize.sh; scan_for_secrets fleet/'`

## Files

| File | What it is |
|------|------------|
| `projects.json` | fleet lead config (FLY-247 single source of truth) — env NAMES only |
| `env.example` | every required env key, **zero values** (Annie fills the real ones on the new host) |
| `manifest.json` | repos to clone, launchd jobs, skills wiring, dep list, capture metadata |
| `example/` | a synthetic, hand-written sample artifact (no real fleet data) showing the shape |

The real `projects.json` / `env.example` / `manifest.json` are generated by
running `scripts/fleet-capture.sh` on the **current** host before a migration.
They are intentionally NOT generated on the build/runner machine.

## NOT captured (Annie-handled — see the runbook)

Real token values, memory DBs, `codex-homes/` auth, `gh` auth, thread-id
continuity. These are restored by hand per
`docs/operations/fleet-provisioning-runbook.md`.
