基于: 无(本 issue 的第一份文档)

## 这是什么活

父 EPIC **FLY-908** 要把 Flywheel 从「工程师内部用的系统」重定位成「**非工程小企业也能用**的产品」。第一个真实客户 = Hooves & Paws(非工程公司)。本 issue(FLY-909)= 竞品扫描,**喂这条对外定位线**,不碰技术实现。

## 要回答的问题(产品 Lead brainstorm gate 已确认)

1. 市面上做「AI 开发团队 / 自主编码 / 让非工程也能造软件」的都有谁?逐个:定位一句话、目标用户、产品形态、onboarding、亮点 feature、定价。
2. **哪些形态 / feature 值得我们借鉴?**
3. **我们跟谁像、跟谁不一样?**(差异化线索)

Lead 追加两个横切交付物(比逐个拆更喂定位):
- ① 一张「各家用什么产品形态服务非技术用户」对比表;
- ② 明确的**差异化候选清单**(我们比他们独特在哪)。

## Lens(已与 Lead 对齐)

压在「**各家怎么服务 / onboard 非技术用户**」这一侧,不做工程师工具全景。

- **no/low-code AI builder 档**(Lovable / v0 / Bolt / Replit / Base44 …)= 最贴目标客户,**重点挖**:非技术人怎么上手、onboarding、产品形态、定价。
- **teammate 形态档**(Slack/Discord AI 同事)= **重点看** —— Flywheel 本身就是 Discord 为总线的 teammate 编排形态,这档最能照出「像谁 / 不像谁」。
- **自主编码 agent 档**(Devin / Cursor / Claude Code / Codex …)= **只看形态与定位打法**,不深挖工程细节。

## 对比基线 = Flywheel 现有形态

- 一整个 **AI 团队**:AI Lead(部门头)管 AI Runner(工程师),各自是 Claude Code / Codex 会话。
- **Discord = 总线**:founder 在 Discord 跟 Lead 聊,Lead 派活、汇报、升级。
- **Linear = 单一真相**:issue 驱动;issue → Runner → 自动 PR。
- **founder 只管两头**:给方向 + 验收,中间自治。
