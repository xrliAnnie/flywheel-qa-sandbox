## ⏳ 还开着的(**只有两条**)

**这两条可能是同一条,但现在不许合并成结论。**

### 1. 早说话反而更差 —— 只有形状,没有解释
```
音频早到 +8s    ⇒ 0/8 活
音频晚到 +36s   ⇒ 2/8 活
```
⇒ 由此生出一个**带反例的猜测**:「音频可能不是能救它,而是会触发它」。
⚠️ **反例**:音频在死线前到达的**十**场里,**九死一活** —— 活的那场是**她本人第四场**(聊了六分钟、28 个来回)。
⇒ 正确措辞:**音频不能救它,但也不足以说音频触发它。**

### 2. 同样没音频,为什么有时候不触发
```
v3-01  首次出声 +36.4s  ⇒ 活
v3-07  首次出声 +36.4s  ⇒ 死于 +34.9s     ← 到达时刻逐字相同,结局相反
```
⇒ **差别只能在死线本身触没触发。八场同样静默,六场触发两场没触发。**
⇒ **这一条比第 1 条更基础**:在问「声音能不能救它」之前,先要知道「没声音时它为什么有时不死」。

### 验它的实验(**规格已写死,等 founder 拍板才跑**)
```
asker 完全不发音,其余一字不改;至少八场;开跑后脚本冻结
判据:明显比 35.2 秒活得久 ⇒ 音频触发说成立
      仍然约 35.2 秒死     ⇒ 与音频无关,是纯计时
```
⚠️ **Lead 的倾向是不跑** —— 选 v2 这个决定已经不需要更多数据。**花不花这个时间由她定。**
