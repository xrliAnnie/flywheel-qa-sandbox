发布门具体怎么跑（你 round-2 问得最细的一块）

6h beta 机制 · 命名 · promote · publish→拉取→更新

1) 6h 自动打 beta，到底怎么跑

  • 一个定时任务（每 ~6h 醒一次，GitHub 上的定时 CI）：看这 6h 内 main 有没有新代码。
  • 6h 内 5 个 commit → 对，拿最新那条（当前 main）打一个 beta 版本，一次覆盖这 5 个改动。✓ 你理解对。
  • 6h 内 0 个 commit → 跳过，不打。没新东西就不发版，省得堆一堆一模一样的版本。

别人怎么做：Next.js 几乎每次 merge 就发一个 canary（一天好几个）；Docusaurus 每个代码 commit 自动发 canary（~10 分钟）；Expo 是每晚一个快照。所以「有新代码才打、没有就跳过」是通行做法。

2) publish → 拉取 → 更新：怎么就在你/客户电脑上更新了

关键澄清你问的：是的，「发布」= 往 npm 推一个新版本包；「更新」= 机器自己定时去 npm 拉。这是两条独立的线（你 ② 说的 detached，对的）。

怎么「拉」：机器上跑 flywheel update —— 去 npm 问「我这条通道有没有更新的版本」，有就下载、装进新目录、切过去、重启。CLI 工具自更新都这么做（查 registry 的通道 → 比版本 → 装）。

3) 版本怎么命名 + 正式版怎么 promote（给你 3 个 option）

「提升成正式版」上一版我说得太模糊。真去查了 —— 通行做法是移一个「通道标签」，不是重新做。三个 option：

Option 1 · 移标签（最省、最忠实）别人最常用

beta 叫 v1.56.0-beta.3（带 -beta.N，一眼是 beta）。提升 = 把「正式版」这个标签挪到你验过的那个 beta 上（npm dist-tag add …@1.56.0-beta.3 latest）。不重做、字节一模一样 = 你验过的那个原样变正式版。

小缺点：客户装「正式版」拿到的版本号还写着 -beta.3，看着像 beta，可能困惑。

Option 2 · 重发一个干净版本号（客户看着最清楚）

beta 是 v1.56.0-beta.3；提升 = 从同一份代码出一个干净的 v1.56.0（去掉后缀）发到正式版通道。客户拿到干净的 v1.56.0。

小缺点：多一次「重发」（新版本号），不是纯移标签。

Option 3 · beta 不带后缀，只靠通道区分

beta 就叫 v1.56.0（不带 -beta），发到 beta 通道；提升 = 把正式版标签移到验过的那个。版本号完全一样，只有「在哪个通道」区分 beta / 正式。

小缺点：光看版本号看不出是不是 beta，得看它在哪个通道。

别人怎么做：npm 官方文档说 promote 就是 npm dist-tag add pkg@版本 latest 把「latest」标签挪过去，是推荐做法，不用重发。所以 Option 1 最贴通行做法；但如果你更在意「客户看到干净版本号」，Option 2 更直观。

4) beta 一定要 6h 吗？

不一定。查了别人：有的每次 merge 就发（Next.js，一天好几个）、有的每晚一个（Expo）、有的每个 commit（Docusaurus）。6h 是个合理的中间值（不会太吵、又够新）。正式版则通常隔几周一次（npm 官方 CLI 自己是 2-4 周一次）。

就是你猜的：一个像 S3 的私有存储放各版本 payload + 一个小函数当门卫（验 key → 给一个几分钟内有效的下载链接）。这叫「presigned URL（预签名链接）」模式，是业界服务私有文件的标准做法之一。我们这边可复用已经验证过的托管（FLY-203 那套私有存储 + 薄函数）。成本 = 存储 + 流量，没有「发多少版本」的上限。

option B · 用现成商用平台（Keygen 这类）

Keygen = 一个「license + 分发」的现成服务：你把 payload 传上去，它帮你管 license key、分档（免费/付费）、按客户吊销、gated 下载。少写基建，但 ——

查到真定价了（这条你最关心）：Keygen 免费档（Dev）上限 = 只能有 10 个 release（超了直接 402 拒绝）。我们每 6h 一个 beta ≈ 一个月 120 个 —— 免费档瞬间就撞爆，必须上付费档（Std）。付费档的确切月费它藏在 slider / 要联系销售后面，UNKNOWN，我查不到具体数字。结论：以我们的发版频率，Keygen 免费档用不了，一定进付费。

诚实权衡：自己搭（A）没有「发多少版本」的上限、全在自己手里、便宜，但免费/付费分档、key 等级要我们自己写一点；Keygen（B）分档/吊销现成、正好贴你要做付费，但按我们频率一定花钱、且价格不透明。

顺到「免费 + 付费高级版」

你选的 B 渠道（薄壳 + key + payload）本身就是免费/付费的开关。免费版 = 装了就能用的基础档；付费高级版 = 付费 key 换高级 payload。现在把这套搭起来，以后加档只是「多一个 key 等级 + 多一个 payload 档」，不用重构。现在不用做计费系统 —— 那是以后。
