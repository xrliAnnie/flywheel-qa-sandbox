第 0 步 · 地基:装一个 agent CLI改

装一个 agent CLI(Claude Code / Codex / 任一,不写死)+ 登录你自己账号,是最前面的地基 —— Onboarding Buddy 本身就跑在它上面,没它就没 buddy。

第 1 步 · 欢迎锁

Buddy 第一句是暖场、像终于见面的同事,不马上派活;顺带交个底(免费/数据在你机器/机器常开)。

第 2 步 · 建你自己的 Discord锁

用户只做 4 件(建 server / 建 bot 拿 token / 开 2 个开关 / 点邀请),bot 一进群自动建好频道/角色/webhook 全套结构。

第 2 步 · 接后台本子(Linear)锁

团队记「要做啥、做到哪」用的后台本子,你平时不用打开,点一下授权就行、不贴密钥。

第 2 步 · 接 GitHub改

GitHub 接(作基础工具之一)—— 团队做的东西(代码/产物)存 GitHub,安全、有版本、搬得走;点一下授权就接好、不贴 token。

第 3 步 · 地基齐了,才问「你想先干哪件事」锁

setup-first:基础工具搭完才问,不提前。你用大白话说今天正手动盯着、还挺烦的那件事。

第 4 步 · 从你那句话长出一个小团队

按你说的建一个 Team(一个 Captain 帮你把关 + 一个 Crew 去干),名字随你改,你确认。

第 5 步 · 先跟 Captain 打个招呼(welcome-first)锁

Captain 上线,先像同事一样问好(按你的用例说、不写死订单),不马上派活;真正要干啥打完招呼再说。

第 6 步 · 接你这件事要用的系统

只接这件事要的那 1–2 个(不前置连全部),一次一个,能点授权就点授权、不能才贴 key,只读。

第 7 步 · 自动安顿上线

建工作区 / 配好团队 / 让它们常驻 / 上线自检;产物推到你自己的 GitHub 仓。你喝口水的功夫。

第 8 步 · 它真帮你干成第一件事

回 Discord 让 Captain 真干一件事,≤60s 拿到一个可信的结果(比如「#1234 卡了不是丢单,是确认邮件没读到」)——不是一个 dashboard。
