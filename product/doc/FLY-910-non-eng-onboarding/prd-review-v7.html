① 问题 + 给谁用

问题:非技术小企业现在 onboard 要手动搞一天、强耦合工程。给谁:第一版 = 时间紧、懂点电脑但非程序员的经营者(电商/social),跑在他自己机器上(自托管)。

② 目标 / 不做的

做:一条命令 → Onboarding Buddy 自助带 → 有个能跑的 system + 第一个真产出;非技术看得懂、不用懂工程。
这版不做:managed 云托管(=V2)· 收费(=placeholder,待竞品分析)· 工程实现本身(交 Tadashi)· PM 验收(未来 FLY-830)。

③ MVP 范围 + 已知取舍

MVP = 自托管(半技术经营者、上线快);managed = V2(接更广非技术那群)。已知取舍:自托管要一台常开机器、会挡掉纯非技术小白 —— 现在诚实接受、换 ship 速度,V2 managed 来补。现在免费全试。

④ 成功怎么算(北极星)

北极星 = 拿到第一个真产出的时间(首个结果 ≤60s;整个 onboarding 理想一个 session 内)。成功 = 客户拿到第一个成品,不是「环境装好了」。次级:完成率、卡点转人工率、首周留存。

⑤ 怎么拆给工程(8 个 build 块)

收敛后按这 8 块拆成 issue 挂给 Tadashi 的工程队列(你不用管细节,眼熟一下就行):
  • 一条命令 + 装 agent CLI 地基 + 起 Buddy
  • Onboarding Buddy 本体(话术 + 记忆续传 + 决策)
  • 基础工具接入(Discord / Linear / GitHub)
  • 业务系统连接器 + 按需接入
  • 自动安置(建工作区 / 推 GitHub / 常驻上线)
  • 早聊一句 + 第一个产出编排
  • 卡住转人工支持通道
  • Discord 4 步截图/短视频素材
