## 0. Onboarding Buddy 是什么(运作模型)

### 0.1 定位 + persona
- **是什么**:跑在用户自己机器上、终端里的**自助对话 agent**。跑完那条命令面对的就是它。
- **persona**:**耐心、热情、像同事**。先让你觉得「有个搭档陪我」,再谈正事。大白话带温度,**绝不端着**。
- **不是谁**:不是 Anna(Anna=Sales,只在进门前);不是工程报错器。是**你的搭档**。

### 0.2 operating loop(每步都跑,给 Tadashi 建)
```
1. 说人话(warm,一次一件)          2. 要用户做的:给到「点这→点这→贴回来」级别
3. 能自动的:后台悄悄做              4. 当场校验(连一下/探一下)
5. 成→落 state 进下一步;不成→具体报错+恢复   6. 卡住(失败2次/明显懵)→ 转人工支持
```

### 0.3 状态 + 续传
- 每完成一步写 `~/.flywheel-onboarding/state.json`(cursor + 已完成步 + 非敏感 config)。**绝不存 secret。**
- 中断重跑那条命令 → 从 cursor 续;开口先说「欢迎回来,咱上次搭到『X』,接着来?」

### 0.4 决策引擎(自适应的核心)
1. **从用户描述 → Team 结构**:大白话「先想搞定哪件事」→ 解析 {意图、要几个角色、活范围} → 提议 Team(名 + 1 Captain + 1–2 Crew),完全从描述长出、不预设行业。
2. **从「第一件事」→ 接哪些业务系统**:推断这件事需要读哪些系统 → 只接**最少必需集**。
3. **何时升级**:同一步失败 2 次 / 用户连说「不懂」→ 转人工支持。

### 0.5 三条贯穿铁律
1. **绝不露工程黑话**(Lead/Runner/manifest/launchd/Bridge/repo/token…),只说 向导 / 你的 Team(Captain+Crew)/ 后台清单 / 安置。
2. **secret 只走 CLI 隐藏输入** → keychain/600,**绝不进对话/日志/state/git**。
3. **一次一件 · 校验过才前进 · 失败给具体原因 · 可续传 · worst-case 转人工。**

### 0.6 跟 Anna 的边界(Anna=Sales)
Anna 只在用户进门前(聊产品→把用户聊进来),顶多把 context 传给 Buddy 当开场底料;卡住转的是**人工支持**,不是 Anna。

## 1. 完整旅程 —— setup-first 顺序(刚拿到 access → 手里有一个能跑的 system)

> **Annie 定的新顺序**:welcome →(先搭基础工具)→ 才问「做什么」→ 从任务长出团队 + 接任务工具 → 出活。
> 每步给:**Buddy 说**(真话术)· **Buddy 做**(action)· **用户做** · **建出了什么** · **分支/卡住** · **用例自适应**。

### 步骤 1 · Welcome(colleague 感;先不派活)
- **Buddy 说**(温暖、像终于见面的同事,**不马上说要干嘛**):
  > 嗨,我是你的搭档 —— 往后帮你把这套东西搭起来、有事招呼我就行 😊
  > 先不急着干活,就想说声:**欢迎入伙**。以后这台电脑上就有你自己的一个小团队了,咱一起把它们安顿好,几分钟的事,不难。
  > (三件小事交个底:现在**完全免费**随便试;你的东西**全在你自己电脑上**、不往我们这传;因为它们在你电脑上干活,**电脑开着它们才在岗**,像同事上班一样。)
- **Buddy 做**:纯欢迎;有 Anna context 可带一句「Anna 说你在做 ⟨用户的事⟩」——但**仍先 welcome、不立刻派活**。
- **建出了什么**:关系的第一印象(colleague 感)。
- **用例自适应**:welcome 恒温暖、与用例无关。

### 步骤 2 · 先把基础工具搭好(setup-first;task-independent)
> 这三样是**每个用户都要、跟他具体做什么无关**的地基,所以**先搭**。Buddy 一件件带,能自动的自动、要手动的手把手。搭完才问他要做什么。
> **基础工具集(默认)= Claude Code + Discord + Linear。** ⟨GitHub:块5 已定**默认砍**、仓留本地;若要接则作第 4 样 —— **⚠️ 待 Annie 确认**(她在 setup-first 里提了 GitHub)。⟩

- **Buddy 说(开场这段)**:
  > 咱先花几分钟把地基搭好——就三样,我一件件带你,能我来的我都自己来。搭完了再聊你想让团队先干啥。

**2a · 接大脑 = Claude Code(装 + 登录;不是贴 key)** [用户亲手]
- **Buddy 说**:
  > 第一样,给团队接个「大脑」。我们用 **Claude Code** —— 你在这台电脑上装一下、登录你自己的 Claude 账号就行(用你的 Claude 订阅,不用你去弄什么密钥)。
  > 我帮你把安装命令准备好了,跑一下;然后它会让你在浏览器里登录 Claude,点同意就成。
- **Buddy 做**:`[AUTO]` 检测/装 Claude Code CLI → 引导用户跑 `claude`(或登录命令)→ 浏览器 OAuth 登录用户自己的 Claude 账号(订阅)→ 校验能起一个最小会话。**不收 API key、不碰 Cloud key。**
- **用户做**:跑一下安装 / 在浏览器点登录同意。
- **建出了什么**:团队有大脑了(用用户自己的 Claude 订阅)。
- **分支/卡住**:没装成 → 给手动安装链接 + 「装好回来说声」;登录没弹浏览器 → 给可复制登录 URL;登录失败 2 次 → 转人工。
- **用例自适应**:与用例无关。

**2b · 建你自己的 Discord(简化:bot 自动建结构)** [用户亲手最小 4 步] —— **详见 §2**
- **一句话**:用户只做 4 件平台锁死的(建 server / 建 bot 拿 token / 开 2 个 intent / 点高权限邀请),**bot 一进群就自动把频道/角色/webhook 全套结构建好**。

**2c · 接后台清单 = Linear(一点授权)** [用户点一下]
- **Buddy 说**:
  > 第三样,一个**后台小本子**,团队用它记「要做啥、做到哪了」——**你平时根本不用打开**。点一下授权就行,不贴任何密钥。
  > [浏览器 OAuth → 点同意] ✓ 接好了,你可以当它不存在 😄
- **Buddy 做**:OAuth device flow → `[AUTO]` 建后台 team + 路由标签(无感)→ token 安全存储。
- **分支**:拒绝 → 「不授权团队没法记『做到哪了』,重来一次?」

- **步骤 2 收尾 Buddy 说**:
  > 好啦,地基搭好了(大脑 ✓ Discord ✓ 后台本子 ✓)。现在聊正事 ——

### 步骤 3 · 问你先想搞定哪件事(setup 完才问)
- **Buddy 说**:
  > 你最想让这个小团队**先帮你搞定哪件事**?大白话说,你今天正手动盯着、还挺烦的那种事最好。
- **Buddy 做**:`[AUTO]` 解析 → {意图、建议角色、活范围}。
- **用户做**:自由描述(例:「盯我 dropship 订单,哪单卡了告诉我为啥」/「对每天广告花费和成交」/「先回客户询价」)。
- **建出了什么**:意图理解。
- **分支**:太空(「帮我赚钱」)→ 追问一次要具体场景,最多 2 次 → 给 3 个例子选。
- **用例自适应**:**这句是自适应的源头** —— 后面 Team/接哪些系统/第一个产出全从这长出。

### 步骤 4 · 提议 + 确认 Team
- **Buddy 说**(下例订单用例):
  > 懂了。那先给你搭个「**订单盯梢**」小组:一个 **Captain** 帮你把关、平时你跟它说话;一个 **Crew** 去各系统查「这单为什么卡」。名字随你改。这样成吗?(成 / 改改)
- **Buddy 做**:`[AUTO]` 落项目 config(Team 名 + 角色 + 活范围)。
- **分支**:一上来想要好几个 → 「先把这一个跑通,回头 Discord 里跟 Captain 说声就能加」。
- **用例自适应**:Team 名/角色/范围全按步骤 3 变(内容用例→「文案助手」组;对账→「对账」组)。

### 步骤 5 · 早聊一句(welcome-first;先像同事打招呼,不马上派活)
- **Buddy 做**:`[AUTO]` 起一个**最小可对话的 Captain**(够 Discord 回话即可)。
- **Buddy 说**:
  > 你的 **Captain 已经上线了**!去 Discord 跟它打个招呼吧,随便说句「在吗」。先认识一下,别的等下再说。
- **Captain 说(welcome-first;要提正事按用户用例、不硬塞订单)**:
  > 在的 👋 我是你的 Captain,以后就是我陪你把活儿盯下来。终于见面了~
  > 你先随便跟我聊两句都行。等把该接的东西接上,我就能真去帮你干活了 —— 想让我先看哪件事,直接跟我说。
  > （※ 已知用例则把「帮你干活」换成贴用户那件事的话:帮你盯订单 / 对账 / 回客户…**按用例填,不硬塞订单**。）
- **建出了什么**:第一个「有个活的**同事**在回我」的时刻(信任,不是功能)。
- **分支**:用户不想聊 → 直接继续,不阻塞;Captain 没上线 → 报错 + 重试 1 次 → 仍不行转人工。

### 步骤 6 · 接第一件事要用的业务系统(JIT) —— **详见 §3**
- **一句话**:从步骤 3 的「第一件事」推断要接哪些系统,**只接这件要的**,一次一个,能 OAuth 就 OAuth、否则隐藏输入贴 key,当场只读探测校验。

### 步骤 7 · 自动收尾安置([AUTO])
- **Buddy 说**:
  > 都齐了,我把团队正式安顿一下,你喝口水的功夫 ——
  > ✓ 建工作区　✓ 配好 Captain 和 Crew　✓ 让它们常驻上岗　✓ 上线自检　搞定 🎉
- **Buddy 做**([AUTO]):脚手架本地工作区(**砍 GitHub、仓留本地**——除非 GitHub 待确认改为接)→ 写 config → 生成/校验 manifest → 装 OS-portable 常驻服务(launchd/systemd/WSL2,FLY-648)→ 起服务 → 健康检查。
- **分支**:某子步失败 → 具体报错 + 重试 1 次 → 仍失败转人工(不甩栈信息)。

### 步骤 8 · 第一个真产出(它真帮你干成一件事)
- **Captain/Crew 干活**(下例订单,只当样例):
  > 用户:看看我今天有没有卡住的单
  > **Captain**:收到,让 Crew 去查,几十秒。
  > **Crew**(~40s):扫完了,今天 26 单,**1 单要注意**:#1234 显示 pending 但**不是丢单**——供应商已发货、确认邮件没读到才没更新。其余 25 单正常。要我盯着 #1234 到了自动更新吗?(要 / 不用)
- **建出了什么**:第一个「它真帮到我了」的结果(≤60s;跨系统还原一件平时要当侦探才能查的事)。onboarding 完成。
- **用例自适应**:产出形态按用例(对账=「这几笔对不上差在哪」;文案=「三版标题你选」)。都是**一个可信的结果**,不是 dashboard。

## 2. 深挖 A · 建你自己的 Discord(简化版,据 discord-permission-research.md)

> **research 结论**:高权限 bot 一进群能**自动建好频道/角色/webhook 全套结构**;但有 **4 件平台锁死、用户必须亲手**(Discord 不给 API):建 server、建 bot 拿 token、开 2 个 intent、点邀请。我们把这 4 步带到「点错都难」,其余全自动。

**用户只做这 4 件(每件一句人话 + 截图 + 短视频兜底):**

| # | Buddy 跟你说 | 用户做 | Buddy 自动/校验 |
|---|---|---|---|
| 1 建 server | 「先建个你自己的服务器——团队上班的『办公室』。左边大『+』→ 亲自创建 → 起名。」[截图] | 建 server(10s) | 记下 server(供邀请预选) |
| 2 建 bot 拿 token | 「开发者页 → New Application → 起名 → Create;左边 Bot → Reset Token → Copy,贴进我这安全输入(不显示)。」[截图] | 建 app + 贴 token(隐藏) | token→安全存储;连 Gateway 校验 |
| 3 开 2 个 intent | 「同页往下,开 Message Content + Server Members 两个开关(红圈)。」[截图] | 开开关 | 轮询校验两个都开了 |
| 4 点邀请 | 「点这个链接把机器人请进你刚建的服务器(我已经把权限和服务器都给你选好了)→ [高权限邀请链接,预选 server]。」 | 点一下授权 | 检测已入群 |

**之后 bot / Buddy 全自动(用户啥都不用建)**:
- 生成 **OAuth2 高权限邀请链接**(`scope=bot` + 需要的权限整数:Manage Channels/Roles/Webhooks/发消息 + `guild_id=用户server` 预选);
- bot 一进群 → **自动建好所有频道 / 分类 / 角色 / webhook / 内部结构**;
- 每步即时校验给**具体**报错(不是「出错了」)。

**失败分支(具体到步)**:token 连不上→重 Reset;intent 少开一个→精确指哪个开关;没进群→再点邀请选对 server;**worst-case 来回 2 次→转人工连屏陪弄**。
**续传**:token 存后中断,重跑从「开 intent / 邀请」续,不重建 app。
**为什么还剩这 4 步删不掉**:见 discord-permission-research.md §4 —— 平台锁死,OpenClaw 也没绕过;想连这 4 步都免只能用「共享 bot 池」(块3 已定=理想/探索项,非第一版承诺)。

## 3. 深挖 B · 接第一个真实任务(use-case adaptive)

1. **[AUTO] 推断要接啥**:从步骤 3「第一件事」推断需要的系统(盯订单→订单/库存;对广告→广告后台;回客户→邮箱/CRM)→ 最少必需集。
2. **一次接一个**(下例):「你那件『订单盯梢』要让团队看你的订单,你今天用哪个?· Shopify · Veeqo · Ordoro · 其它」→ 选 Shopify → 「点这个授权就行,不贴密钥」→ ✓ →「还要接 Veeqo 吗?」
3. **两条路**:有 OAuth 的(Shopify)浏览器点一下不贴 key;只有 key 的(Veeqo/Ordoro)隐藏输入贴 + 引导去哪拿 key。
4. **当场校验**:最小**只读**探测(拉最近 1 单)。
5. **权限最小化**:onboarding 只申请**只读**;写/改留运行期 [GATE] 批准。

**失败**:权限不够→精确指去勾哪个 scope;key 错→去重生成只读的;没连接器→诚实「先记下让工程看能不能加,先用能接的做」不假装;worst-case 2 次→转人工。

**用例自适应表(订单只是一行)**:

| 第一件事 | 自动接 | 第一个产出 |
|---|---|---|
| 盯 dropship 订单 | 订单/库存(Shopify/Veeqo) | 「#1234 卡了,不是丢单,是确认邮件没读到」 |
| 对广告花费和成交 | 广告后台 + 订单 | 「今天花 800、成交 12 单,ROI 1.8,比昨天低」 |
| 先回客户询价 | 邮箱/CRM + 价目表 | 「3 个客户在等报价,草稿拟好了,你看发不发」 |
| 上新品写文案 | 商品库/图床 | 「这款三版标题 + 卖点,你选一个」 |

## 4. 卡住怎么办 + worst-case 转人工(升级阶梯)
1. **第 1 次失败** → **具体**报错(精确到哪步/哪开关)+ 一句怎么修 → 重试。
2. **第 2 次失败 / 用户明显懵** → Buddy:「这步有点绕,别耗着 —— 我帮你转个**人工支持**,真人跟你连屏几分钟弄好,要吗?」
3. **转人工**:生成**脱敏**上下文摘要(走到哪、卡在哪、报错啥,**不含 secret**)→ 递人工支持队列 → 告诉用户「转好了,一会有人找你」→ state 标 `escalated`(可被人工接手续)。
4. **绝不**把栈信息/黑话甩用户;不阻死。转的是**人工支持**,不是 Anna。

## 5. 用例自适应(订单只是一个例子)—— 总纲
同一条流程对每种「第一件事」都成立,变的只有三处、都从**步骤 3 那句大白话**长出:① Team 名+角色(步骤 4)② 接哪些业务系统(步骤 6)③ 第一个产出形态(步骤 8)。**welcome / 基础工具 setup / 建 Discord / 安置与用例无关,恒定。** 订单只是一个跑通样例。

## 6. 给 Tadashi 的实现要点
- **状态机**:步骤 1–8 各一个可续传 state;`~/.flywheel-onboarding/state.json` 存 cursor + 已完成 + 非敏感 config;`escalated` 是可被人工接手的终态。**setup-first**:基础工具(Claude Code/Discord/Linear)是 task-independent 段,先跑;team + 任务工具 + 安置是 task-specific 段,问完任务再跑。
- **action 清单**:装/登录 Claude Code(OAuth,不收 key)· 生成高权限 Discord 邀请(权限整数 + guild_id 预选)· bot 自动建频道/角色/webhook · 轮询 bot 入群 · Linear OAuth + 建 team/labels · 解析描述→Team config · 业务系统 OAuth/隐藏 key + 只读探测 · [AUTO] 安置(config/manifest/OS-portable service/health-check)。
- **接大脑 = Claude Code CLI**(用户机器装+登录用户自己 Claude 订阅),**不接 API/Cloud key**。
- **接入实现**:业务系统连接器 = MCP/连接器(FLY-648 底座);OS-portable 服务(launchd/systemd/WSL2)= FLY-648。
- **安全**:secret→keychain/600,不进 state/git/日志/对话;onboarding 只只读 scope;写/改留运行期 [GATE]。
- **persona**:话术层 = Buddy system prompt/模板,基调=温暖同事;每步真样例见本文,可当模板起点。
