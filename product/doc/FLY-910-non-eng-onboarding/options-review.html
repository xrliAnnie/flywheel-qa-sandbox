问题 1 / 5

怎么起步(第一步长什么样)

别人怎么做

自托管这类(OpenClaw / Hermes)都是「粘一条命令 → 进一个一问一答的引导」,默认给快路、全控藏在后面。 网页那类(Raft / Matrix)是「注册 → 连你的订阅 → 装个小程序 → 进频道」。OpenClaw 还专门留了「先别接那么多、直接进去聊一句」的快路。

我们的 option
A
终端一条命令 → 命令行里一问一答(默认走快路,想全控加个 --advanced)。贴「客户懂点电脑」,不用先建网页,授权那几步才弹浏览器。
B
网页注册 → 网页里引导(像 Raft / Matrix,更亲民),但要先做一个网页、我们得替他多跑一些。
C
A 再加一条早聊路:命令起步,一旦 Discord 和模型接好,先让他跟 Captain 说上一句话(哪怕业务工具还没全接),完整结果随后再来。★ 我建议 A+C
你挑哪个? 这块也顺便答两个小确认:① 认这个「命令 + 一问一答、默认快路」形态吗?② 要不要那个「工具没全接就先打个招呼」的早时刻?
□ A□ B□ A+C(我建议)□ 新想法
问题 2 / 5

第一版谁来带客户接进来

别人怎么做

Matrix / Lovable / Base44 都是纯自助(自己下、自己跑)。Paperclip 是自助 + 一堆现成模板。 没有谁把「真人陪你接进来」做成产品(但大家都还很早期、都有卡壳)。做小生意的通行智慧:先用人手把第一批客户跑通,再谈自动化。

我们的 option
A
第一版 Anna 人肉陪:带头几个客户手把手接进来,客户只体验「聊需求 + 收结果」两头,中间工程步骤我们替他兜。先跑通、边跑边学真痛点。★ 我建议 先A后C
B
第一版全自助:客户自己走完引导,只有卡死了才喊 Anna。
C
混合:自助为主 + 最容易卡的那一步(建 Discord 机器人)Anna 待命随时上来陪。
你挑哪个?
□ 先A后C(我建议)□ B 全自助□ C 混合□ 新想法
问题 3 / 5

Discord 机器人怎么给客户配

别人怎么做

OpenClaw 手把手引导用户自己去 Discord 后台建机器人(这一步谁都自动化不了,Discord 没有替建的接口)。 Raft 是装个本地小程序连你自己账号。「给一个现成机器人直接邀请」这种捷径没人做过 —— 这是我们独有的一招(我们已有一个机器人池)。

我们的 option
A
默认让客户自己建:手把手带他去后台建一个属于他自己的机器人(配截图 + 15 秒短视频)。机器人完全是他的。贴「你自己拥有」的卖点。
B
默认给现成的:我们给一个预建好的机器人,客户只点一下「邀请进我的服务器」,跳过整个后台。最省事,但机器人身份是我们托管的、不是他完全自有。
C
默认自建(A),同时把「想省事?」的一键捷径(B)露出来当可选。要掌控的走自建,怕麻烦的选捷径。★ 我建议 C
你挑哪个?
□ A 自建□ B 给现成的□ C 自建+捷径(我建议)□ 新想法
问题 4 / 5

怎么收费 + 隐私怎么讲

别人怎么做

Paperclip 完全免费开源、你自付基建(它没有托管云 = 想要「别人替我跑」的人它接不了)。Matrix 公测免费送额度,母平台按订阅 + 额度。 Cowork 跟着 Claude 订阅走。自托管软件的成熟范式(n8n):社区版免费自托管,商用/高级功能要一个每天联网校验的 license key。 行业趋势:按人头收费在退潮,按「几个 AI 员工 / 几个部门」收更贴「搭 AI 公司」的感觉。

我们的 option(收费骨架)
A
license key 订阅(月/年)门商用和规模,自托管核心可免费试;按「几个 Team / 几个在岗 AI 人力」分档(不按人头);Anna 陪接入当一个服务档。以后加云托管版不用推倒重来。★ 我建议 A
B
完全免费开源先冲量(像 Paperclip),以后再想怎么收。
C
纯订阅网页服务(像母平台 flowith)—— 但这跟我们「跑在你自己机器、数据不碰我们」的卖点有点打架。
隐私 + 两个小问题(自托管天生强项:数据永远在客户自己机器、从不碰我们)

这对「要掌控」的第一批客户是吸引他的理由,不是要安抚的顾虑。

1
把「你的数据跑在你自己机器上、从不碰我们」写成开场一句显式卖点?★ 我建议 要
2
给「1 个 Team 免费试」(降门槛 + 拉新)?★ 我建议 要
3
加 license 条款「给你自己的 AI 公司用、不许转售」(防别人白嫖)?★ 我建议 要
你挑哪个收费骨架 + 三个小问题各是/否?
