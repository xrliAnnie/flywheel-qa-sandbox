## ① 我对「非工程快速 onboarding」的 framing 理解(一段)

**解什么**:让一个**没有工程能力的小企业**,不碰命令行 / 不懂 repo/Discord bot/config,就能**快速**把 Flywheel 用起来 —— 从起步,到把自己的业务接进来,到**很快拿到第一个对他们有用的产出**。**给谁**:非工程小企业的老板/运营(第一个真实样本 = Hooves & Paws)。**成功长啥样**:一个非技术人在很短时间内(理想 = 首个 session 内)拿到一个「这东西真帮到我了」的具体产出,全程没被任何工程概念卡住;而且这套体验细到能直接交 Tadashi 落地,不用 Annie 再跟工程掰「具体怎么做」。

> ⚠️ 这段是**我的理解、待 Annie 确认**,不是定论 —— 尤其「成功长啥样 / 第一个产出是啥」强依赖定位(FLY-908),正是要问透的。

## ② 我的 research + hypothesis(每条都想请 Annie 判「对不对」)

**我扫了一轮别人怎么给非技术用户做 onboarding(2026),几个稳的参照点**:
- **对话式 > 设置向导**:传统 wizard 只做技术配置、教不会用户「怎么用出价值」,到不了 aha;对话式引导(用大白话描述你想要啥)对非技术人友好得多(Lindy 这类 no-code 的打法)。
- **从最显而易见的用例起步,不是最高级的**:别上来就多 agent 复杂系统;先自动化一件最明显、最省时间的事,快速出可量化的产出。
- **time-to-first-value 要短**:理想 5-15 分钟 / 首个 session 内摸到第一个成功;越快摸到有意义的结果,留存越好。
- **集成深度 > 原始能力**:能接进他们现有工具的 agent,比更强但孤立的 agent 有用得多。
- **AI 起草、人批准**:客户面的活,AI 建议 / 人拍板 —— 这恰好是 Flywheel 现成的 founder-gated 模型。

**我据此的 hypothesis(带问号,请 Annie 判):**
1. **「一条 command」可能不该是字面的终端命令,而是「一句话 / 一段对话」**。非技术人可能连终端都不开。我猜真正的起步 = 一个对话式入口(像他们已经在用的 Discord 里,直接跟一个 agent 说「我想让你帮我做 X」)。—— 我这么想对不对?
2. **第一版 onboarding 很可能是「concierge / 半人工」而不是全自助**。参照 minimalist-entrepreneur 的 manual-first → processize → productize:第一个客户(Hooves & Paws)大概是 Anna/Annie 帮着把项目接进来,客户只体验「聊需求 + 收产出」两头,中间那 10 步工程 cutover 先我们手动兜。—— 先手动跑通再谈自动化,对不对?
3. **onboarding 的北极星 = 「第一个有用产出的时间」**,不是「装好了没」。把成功定义成客户拿到第一个成品,而不是环境 ready。—— 认同这个成功指标吗?
4. **非技术人全程不该看到 Lead/Runner/manifest/launchd/Bridge 这些词**;这些是我们内部机制,对他们要么隐藏、要么换成业务语言。—— 有没有你已经想好的对外说法?
5. **接进来的第一件事该是「最明显的一件小事」**,不是让客户先描述宏大项目。先做一件他们今天就头疼的小事,拿到产出建立信任,再扩。—— 对不对?

## ③ 给 Annie 的 clarification questions(按主题分组,问透)

> Honey Lemon 筛选 + 逐块带聊。标 ⭐ 的是我觉得**最该先问透**的(卡住后面所有设计)。

**A. 定位 / 终点(⭐ 最先,依赖 FLY-908)**
- A1 ⭐ 一个非工程小企业 onboard 进来,**最终要拿 Flywheel 产出什么 / 干嘛**?(报告?自动化流程?内容?客服?运营动作?)
- A2 拿 Hooves & Paws 具体说:他们最想让 Flywheel 帮他们做的**第一件事**是什么?
- A3 我们是想做「什么都能帮」的通用体,还是先锁定某一类产出打透?

**B. 目标用户 & 入口**
- B1 ⭐ 第一版目标用户画像:是老板本人?运营?他们的技术水平到哪(会用 Discord 吗、用不用别的工具)?
- B2 客户从哪来、第一次怎么接触我们?(Anna 采访完直接引导?网站?邀请链接?)
- B3 ⭐ 第一版是**全自助**(客户自己走完)还是**concierge**(我们帮着接)?你心里更偏哪个?

**C.「一条 command」到底是什么形态(⭐)**
- C1 ⭐「一条 command」你脑子里是字面的一条命令,还是**一句话 / 一段对话 / 一个按钮**?
- C2 客户起步时**在哪个界面**里?(Discord?一个网页?我们代跑?)
- C3 起步后到「接入项目」之间,你希望客户**自己填/说多少**,vs 我们**替他兜多少**?

**D. 首次产出 & Aha moment**
- D1 ⭐ 客户**第一次拿到的东西**你希望长啥样?(一份文件?一条消息?一个做好的自动化?)能不能举一个理想样例?
- D2 多快拿到算成功?(当场?当天?一周?)
- D3 什么信号算「他被打动了、会继续用」?

**E. 非技术体验标准 & 词汇**
- E1 全程客户**绝对不该需要懂**哪些东西?
- E2 我们内部的 Lead/Runner 这些,对客户你想用什么说法(或干脆不露出)?
- E3 出错 / 卡住时,客户该看到啥、找谁?(自愈?找 Anna?)

**F. 交付细度 & 边界**
- F1 你说的「细到能直接交 Tadashi」—— 交付物你想要到什么颗粒度?(逐屏 UI + 文案 + 流程图 + 每步触发什么 + 产出样例?)
- F2 这一版 onboarding **先做哪一段就够**?(先做「接入机制解耦」= 我审计出的那 10 步手动 cutover,还是先做「首次产出体验」?)
- F3 有没有**明确不在这一版**里的东西?
