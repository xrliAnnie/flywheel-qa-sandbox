## 0. 一句话定位(对外主线)

> **「一个一直在线、记得一切、还自己把活往前推的公司 —— 你只做判断。」**

**反差辅线(按受众分两版)**:
> **对外(非技术 operator)**:「不是零人公司 —— **你做判断,AI 帮你把系统和执行往前推。**」
> **内部 / dev 受众**:「不是零人公司,是你做判断、**AI 做工程**。」

—— 主线卖「常驻 + 记忆 + 自运转(Push)」的体验;辅线诚实地把我们从「Zero-Human Company」品类里切出来(人留在判断这一端)。**对非技术 operator 讲「把系统和执行往前推」,「工程」这个词留给内部/dev 受众**(经营者听不懂也不该被工程语言吓退)。

## 1. 目标客户(beachhead + vision)

- **Beachhead(现在专攻)= 非技术的 OPC operator** —— 自己做电商、自己做 social media 的**一人公司**。他有「**一个人干一个团队的活**」的痛,但**不是程序员、自己拼不出来 → 需要 done-for-you**。
- **不专攻程序员 OPC**:他们技术够、能自己拼(OpenClaw + Cowork + Codex 攒一套),不需要我们、也抢不过 —— **能用我们产品,但不是专攻的人**。这条同时化解了「引擎没护城河」的顾虑:会钻这个空子(DIY)的人根本不是我们攻的客户。
- **Vision(later)= 非技术小生意主**(更广)。节奏:等 social media 起来后,**两边试、用数据选**收窄哪一群。

### 核心 job-to-be-done(钉死 —— 这条让整篇定位落地)
非技术电商/social operator 的**核心痛不是「想要个 AI 公司帮我做杂活」,而是「我得持续地建 + 养 我的业务软件 / 自动化 / 内容系统」**:上新品要改站、要接支付/物流、要跑营销自动化、要养一套内容生产流水线 —— 这是**持续的建设 + 维护**,不是一次性杂活。
- → 我们的差异「**替你建 + 养一个真软件产品/系统**」正好对上这个 job。
- → 这同时消掉 codex 担心的错位(「客户听到『经营团队』、但产品实际证明的是『工程维护』」):**因为这群人的痛本来就是工程维护性质的 —— 只是他们不是程序员、自己做不了**。定位实了。

### 不服务谁(NOT for —— 划清边界,别摊大)
- **不给想自己搭 agent framework 的人** —— 那是程序员/DIY 群,他们自己拼(OpenClaw+Cowork+Codex),不是我们攻的人。
- **不是一个通用知识助手** —— 不是「帮我总结/写邮件/查资料」那种 Cowork/ChatGPT 用法。
- **不是完全无人经营的公司** —— 我们不卖「零人自动赚钱」;人留在判断/验收这一端。

## 2. 真差异(诚实 · 引擎层无护城河)

> **诚实前提**:「把 agent 编排成一支队」这个引擎,现在是 Claude(Cowork / Code Agent Teams)和 OpenAI(Codex subagents)的一方功能,还有开源的 Paperclip/OpenClaw —— **我们在编排引擎层没有护城河**。真差异不在引擎,在下面两条 + done-for-you 的组合。

1. **协调,不是 agent 数量**:别讲「我们多部门 vs 它单个助理」——**多开几个 OpenClaw 也能凑成多部门,这框站不住**。真差异 = **N 个 OpenClaw = 各自为战、不互通、你得自己 juggle(当人肉调度)**;**我们 = 一个被协调的常驻组织**(Leads 互通、共享 backlog、跨项目复用、部门分工)——**对外是一家公司在动,不是 N 个你得盯的助理**。
2. **Push Model**:系统**自运转**——每条线自己往前推,**只在要你拍板时才来找你**,接管了「盯进度、调度」这件你以前得自己干的事,**把你的注意力还给你**。非技术 operator 不用当追十条线的项目经理。

**⚠️ 最该警惕**:**Claude Cowork**(Anthropic 自己)—— 它已经是「非技术 + done-for-you + 描述结果 review 成品」,定位上跟我们最贴。若它指向「从手机替你建并维护一个软件产品」,我们空间会被压缩。我们的赢面全押在**更早把「协调 + Push + done-for-you + 真软件维护」这套组合,替一个非技术 operator 真正做通**(现在还没到)。

## 2.5 Why now(为什么「被协调的常驻 AI 组织」现在第一次可产品化)

它不是今天才想得到,是今天才**做得成** —— 五件事同时成熟:
1. **模型编码力**:够强的模型能真写 + 维护业务软件(不是只出一次性 demo)。
2. **agent 工具链**:subagent / 编排 / 记忆 / 工具调用成了一方基建(Claude / Codex / 开源都有)。
3. **界面基建**:Discord(手机原生 chat)+ Linear(第二大脑)现成 —— 不用自己造指挥面。
4. **OPC 需求**:一人公司越来越多,「一个人干一个团队的活」的痛真实且在放大。
5. **竞品在教育市场**:Matrix / Paperclip / OpenClaw / Cowork 已经把「你指挥一支 AI 队」这个概念替我们教给了市场。

→ 五者交汇,「被协调的常驻 AI 组织」**第一次可产品化**。窗口期就在现在。

## 3. 看家本领(核心两支柱)

对外主打 Value 工件 5 支柱里的**前两根**当看家本领:

- **支柱 1 · 常驻组织 = 记忆 + 掌控**:always-on 的 Lead + long-term memory + Linear 第二大脑 —— 始终握着项目全局,想法不丢、不用每次重新同步 context。
- **支柱 2 · Push Model**:活自己推进、需要你才 ping 你 + **thread 持久 = 不半途而废**(没做完的一直在,下月接着做,想法/半成品不丢)。

另外三根(支撑,不当主线):③一支多视角团队(工程/管理/产品几个帮手,不用你啥都懂;跨项目 global skill 复用)· ④供应商中立整合 —— **降为「未来设计原则 / 可信方向」,不当现在对外主打**(诚实:现在不是主卖点;它是我们「不锁死你」的一个可信承诺,真建全是后话)· ⑤(已起步/待打磨)成本+价值可视(token daily-post 已在跑,财报化 + eval 面板待打磨)。

## 4. 信任(非技术 operator 怎么感知,不读 PR/CI)

非技术老板读不懂 PR/CI —— 工程纪律沉在引擎盖下当**底气**,不是卖点。他能亲身感知的信任 = 四件事:

1. **⚓ 结果证明(锚点)**:东西**一试真能跑、下周还能跑**(不崩、持续维护不烂)—— 非技术唯一能自己验证的信任,也是 Matrix(coding 弱)/Paperclip(generic)做不到的地带。**⚠️ 诚实:我们现在也还没做实(还一堆 bug),这是要争的,不是已经赢了。**
2. **关系型 · 能对话的 named Lead**:在 Discord 里直接问「为什么这么做」「改一下」,像信一个员工/承包商。
3. **可读的审批 · 批决定不批 diff**:Lead 白话说「我打算做 X,行吗」,你批听得懂的决定。
4. **能感知的护栏**:不 surprise 账单(可借 Paperclip 月预算自停)+ 能喊停。

---

## 4.5 最大反对 & 答案(objection handling)

**非技术 operator 最大的反对(必须正面答,不答清楚定位立不住)**:
> 「我怎么敢让它**真动我的业务**?会不会**乱改、乱花钱、做完就坏**?」

这是把业务命脉交出去的恐惧。答案 = 六道他能亲身感知的保障:
1. **可读的审批**:动手前用大白话说「我打算做 X,行吗」,你批的是听得懂的决定,不是一屏代码。
2. **能喊停**:随时叫停,不失控。
3. **预算护栏**:花费有上限、可预测,不 surprise 账单(可借 Paperclip 月预算自停)。
4. **named Lead**:有个你能对话、能追问、对结果负责的「人」,不是黑箱。
5. **结果可验**:东西一试真能跑,你自己验得了(不用读代码)。
6. **持续维护**:不是做完就扔 —— 像真团队一样养着,下周还能用。

→ 一句话:**它动你的业务,但每一步你都看得懂、拦得住、验得了。**

## 5. 竞品诚实结论(喂定位,详见 FLY-909 competitor-scan)

| 玩家 | 是什么 | 跟我们(诚实) |
|---|---|---|
| **Matrix**(flowith) | 桌面「0 人公司」,组织骨架撞我们 | 好推广、建得平庸(coding 弱、跑营销生意);桌面 app;组织壳区分不开,靠领域+界面+可信切分 |
| **Paperclip**(@dotta) | 开源免费「AI 公司」控制平面(~70K star) | 起源同源(管一堆 Claude Code);generic 框架 + 自托管 + BYO agent;还「原型穿产品外衣」;bootstrap 打法(先立具体旗舰)该学 |
| **Claude Cowork** | Anthropic 非技术知识工作者 done-for-you 桌面 app | **最贴、最该警惕**;做文件知识工作不是建养软件产品;桌面端;锁 Claude |
| **Codex app** | OpenAI 开发者 agent 指挥中心 | 开发者-导演工具、锁 OpenAI —— 非我们目标人群 |
| **Open Cloud / OpenClaw** | 开源个人 AI 助理(IM 驱动、29 渠道) | **界面赌注最像 + 是我们起点**;单个自托管助理、多开也各自为战;爆红-回落(定价套利+安全)给「持久 vs 昙花」一课 |
| **WorkBuddy**(腾讯) 〔FLY-1003 折进〕 | 大厂云的全场景职场 AI 智能体(桌面+9 IM 渠道、100+ 专家、14 模型 TokenHub、13M DAU) | **最强大厂威胁 · 覆盖面+目标都撞**(官方直接打「一人公司/自由职业者」+ 电商选品/落地页/客服);手机 IM + 供应商中立经它正面覆盖已退出;**活着的候选差异 = 长期拥有并演进一套软件/业务系统的 lifecycle + 被协调组织自推进 backlog**,靠产品化速度守 |

**总结**:引擎商品化、我们不占引擎;占的是**协调 + Push + done-for-you + 真软件维护**替一个非技术 operator 做通。

**OpenClaw 踩的坑 → 我们怎么避(持久 vs 昙花)**:①硬定价别做套利泡沫 ②安全别裸 provision ③可靠性要 managed(替你托管的可靠)。

## 6. GTM(building-in-public 为主)

1. **Building-in-Public**:创始人第一人称连载做产品的过程,中文圈用**小红书**(Annie 就是在 XHS 刷到 Matrix 的;Matrix/Base44/Paperclip/OpenClaw 全靠这套零广告起量)。
2. **产品当众干活的病毒 demo**:让人看到**一支队在你手底下热闹地干活** —— **有趣 + drama + 真实**(不表演质量、表演有趣性质),**voice 让它像真人在干**。
3. **Operator 语言**:不跟开发者讲,用经营电商/social 的一个人听得懂的话讲(对标 Paperclip「给 operators 不给开发者」)。
4. **⭐ OpenClaw 起源故事**(真实、极强的 build-in-public 素材):**「我最早在 OpenClaw 上搭这套系统,搭到撞墙(各自为战、你得自己 juggle、不持久),才做了 Flywheel —— 一个被协调的常驻组织。」** 起源可信、痛点真实、还自带 OpenClaw 375K star 社区的相邻流量势能。

## 7. 诚实边界 & 待验(不假装已经到位)

- **产品化还没到**:「非技术真能自己用」现在谁都没做到(连 Paperclip 都还是原型状态),我们也没到 —— 这是赛道共同未解题,谁先把 done-for-you 真产品化跑通谁赢。对外**坦诚「正在把它做成 done-for-you」**而不是假装已经是(和品类一起早,反而可信)。
- **结果证明还没做实**:信任锚点(一试真能跑、下周还能跑)是要争的地方,不是已赢。
- **供应商中立 —— 已退出差异清单(经 Raft + WorkBuddy 覆盖;见下条 FLY-1003 折进)**:曾当「能讲的差异」,但云厂商(腾讯 TokenHub 一键切 14 模型)+ 同形态第三方(Raft runtime-agnostic)都原生做多模型 → 它是 **table stakes、不是差异**;作为「不锁死你」的可信承诺仍可留(且与 Annie「setup 先不做 agent-agnostic」不冲突),但**不当定位差异主打**。
- **Cowork 是结构性威胁**:引擎层无护城河,防御全在 done-for-you 组合的产品化速度。
- **〔FLY-1003 折进〕WorkBuddy(腾讯)= 量级最大的大厂威胁,逼差异再收窄**(诚实结论,详见 `FLY-909/workbuddy-deepdive.md`):(a)**手机 IM + 供应商中立**经 WorkBuddy(官方 9 渠道 + 14 模型 TokenHub)正面覆盖,**退出差异清单**(「第一方结构上不做多模型」被云厂商腾讯证伪);(b)**目标用户不再是差异** —— WorkBuddy 官方直接打「一人公司/个体创业者/自由职业者」+ 电商选品/落地页/客服,正面重叠 beachhead;(c)活着的 **Push 只剩「自发起 backlog 分诊 + 跨 Lead 协调 + 持续 ownership」半**,「记忆 + IM 后台派发/回报」半已商品化(「always-on daemon」⚠️存疑,官方只证个性化记忆);(d)**当前最像还站得住的候选差异 = 「长期拥有并演进一套软件/业务系统的 lifecycle(给非技术 operator)」+「被协调组织自推进 backlog」**,两条都更窄、靠**产品化速度 + 长期 ownership 专注**守,不靠形态独有。**均写「候选/待 911」;主线/beachhead/支柱不因本条改动 —— 定位大结论仍 Annie 拍。**
