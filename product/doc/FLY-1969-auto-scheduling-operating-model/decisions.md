#### ⚠️ 然后这里发生了第二个错,而它比第一个重要

第一版(我写的、也存进了整机记忆)把结论写成「第三点**杀死了 ①**」。**不对。**

> **它杀死的是「① 是唯一解释」,不是「① 为假」。**

因为同一批证据里还有一件饱和解释不了的:

| 读数 | 是什么 |
| --- | --- |
| health / linear / send 全 **200**,只是 13 / 17.7 / 31.1 秒 | 这是「**慢**」 |
| `/api/linear` **502** | 这是「**错**」,不是慢 |

📌 **一个饱和的系统会慢慢地返回 200,它不会返回 502。**
⇒ 真相是**三件事叠加**:饱和(Tadashi)+ Linear 上游 502(HL)+ publish 60 秒超时(FLY-1963)。

**判据的正确表述:**
```
❌ 第三点在两个假设里二选一
✅ 第三点区分的是「单一饱和足以解释全部」vs「饱和之外还另有伤」
   ①预测第三点仍快 · ②预测它居中 · 实测单调递增 ⇒ 排除「单一的 ①」
   ⛔ 但这不等于 ① 的成分不存在 —— 502 就是它留下的
```

#### 📌 由此立名的两条(比那三个水位更值得记)

> **① 一条错的【教训】,比一条错的【结论】传得远得多 —— 因为教训天生是拿来复用的。**
> 错的结论只污染一格;**错的教训会被套到它从没见过的场合上。**
> 实证:HL 的过度更正**在几分钟内就通过他传进了我的整机记忆**,变成我以后每个项目都会套用的判据。
> ⇒ **收到任何立名,都可以要它的反例边界**:「这条在什么情况下不成立?」今晚这条的边界 = **它排除的是「唯一解释」,不是「存在」。**

> **② 推翻推理 ≠ 作废观测。结论被推翻时,要重新问一遍证据还剩什么意思。**

> 而它始终指向一个饱和盖不住的第三个伤。
> ⚠️ **「你对我错」是最省事、最显得诚恳、也最容易顺手把证据一起丢掉的回应。**

### 第 6 个「两种状态留下相同痕迹」的实例 —— 这次在**方法层**

> **「被证据打脸」 vs 「设计实验去打自己的脸」 —— 共用的痕迹:假设都死了。**

- **被打脸**:先信了一个假设,现实**恰好经过**,带来一个杀死它的观测。**靠运气。**
- **设计打脸**:主动问「什么观测能杀死我现在这个假设」,然后**去取那个观测**。**任何时刻都能做。**

⚠️ 读报告的人看到的都是「他证伪了 X」,**看不出是设计的还是撞上的**。

### 判据的自检:**一条判据要能反过来量【用它做出的那个更正】**

> **只能往一个方向用的判据,多半是在选边,不是在判断。**

**本单的实例**:HL 用「让下一个人找对人」这条理由**替 PM 争取**那次证伪的归属。
PM 拿**同一条理由**回头量他的更正,发现仍然太粗 ——「证伪人」会把要**设计下一个实验**的人引过来,
而 PM 手上是**那次证伪的现场**,不是一个待验证的机制假设 ⇒ 用同一条判据把归属**收窄了**。

⚠️ 注意方向:这次判据指向的是**对自己不利**的一边(削自己的功)。

## 📌 诊断方法的一条正面规矩(本轮同一晚,一好一坏两个实例)

> **鉴别实验要挑【两个假设预测相反】的那一点,不是挑【最容易测】的那一点。**
> 先想「两个假设在哪一点上预测相反」,再去测那一点 —— ⛔ 不是「先测手边最方便的,再回头解释」。

```
✅ 好   ① 库太大 ⇒ 预测【读也慢】  ② 有写者持锁 ⇒ 预测【读很快】(走 WAL 快照)
        实测 16ms / 14ms ⇒ ① 死。两假设指向相反,一次测量就砍掉一个。
❌ 坏   linear 502@19.3s(贵慢) vs sessions 200@0.5s(便宜快)
        「路径专属故障」和「整体饱和」都预测这个组合 ⇒ 零区分度,却据此宣布排除了一个。
```
📌 差别不在谁更仔细,**在下手顺序**。

**这条测量的下游用途(候选机制,⛔ 不是结论)**:「有写者长期持锁」正好能解释 FLY-1974 悬着的假设 B

#### 🔴 但「另一个人」不是承重的那一格 —— **「另一个维度」才是**

> **接住自查的错,要另一个人用【另一个维度】核。人不同、维度相同 = 零增益。**
> ⇒ 判据:**问「我们俩的检查,失败模式是不是同一个?」** 是 ⇒ **那不是第二道,是第一道的副本。**

## ✅ 常设做法(报告/消息):**先落文件,再从文件发**

```
⛔ 不要   flywheel-comm ask ... --report "……正文里有反引号……"
✅ 要     正文写进文件 → flywheel-comm ask ... --report "$(cat msg.txt)"
```
理由:命令替换的展开结果**不会被再次求值**。实证:本轮**直接在命令行拼正文的两次都出事,用文件的那几次一次没出事**。
📌 「记住不要用反引号」不是解法 —— 那条规矩记忆里早就有(FLY-372 / FLY-1813 正典),**当晚照样犯了两次**。

### ✅ 已验证,但**对照本身做砸了一半**(两件都记)

**验证结果**:发出去的那一份 payload 里,**5 对反引号全部存活、句子无断裂无吞字**(收件端独立逐个点过)。
⇒ 「先落文件再发」这条做法**真的挡住了它**。

**做砸的那一半**:我在正文里申报「故意留了**三**处」,实际埋了 **5 对**(事后 grep 自证);中途我还在别处说成「四处」。
⇒ 结论(全活)仍成立,但**对照的严谨性打折** —— 多出来的两处**不属于对照的一部分**。

> 📌 **阳性对照的效力,取决于收件端【知道你埋了什么】。**
> ⇒ 正确做法:**把数量和位置写在正文之外**(开头写「本条埋了 N 处,在 X/Y/Z 段」),让收件端能**独立核对数量**,而不是只能核「有没有坏的」。

⚠️ 我那次申报**错了两次、两个方向都有**(说 3、又说 4、实为 5)。⇒ **凡是要被别人拿去当判据的数字,发之前 grep 一次。**

> ### 📌 说准这个对照到底证了什么:
> **一个对照如果连自己埋了多少都记不准,它能证明的就只剩「没坏」,证不了「全都在」。**
> 「没坏」= 收到的那些都完整;「全都在」= 没有任何一个在途中消失。**后者才是要防的那个。**

✅ **闭环已跑通**:下一条报告开头改成「本条埋了 0 处对照」⇒ 收件端独立数出零个反引号 ⇒ **申报与实收一致**。
上一次做不到,正是因为**那个数字只活在发出方脑子里**。

### ⛔ 这个做法的边界(已证的只有一格)
```
✅ 已证   经文件传参这条路径,在本次保住了【反引号】
⛔ 未证   其它 shell 元字符($ / ! / 反斜杠 / 引号 / 换行组合)· 其它发送路径 · 其它长度
```
⛔ 不许把「反引号安全」推广成「文件法什么都安全」。对「不在命令行拼正文」这条规矩,已证的这一格够用。

### ⚠️ 一处我说错、被 HL 推翻的判断(留着,因为纠正后的版本更难防)

我写:「如果我没回头读自己的 payload,**谁都不会发现**。」**错。**
那几个洞在收件人那份里是**可见**的(「死因: 撞上 ,我的…」「而且这条我没信 。」)—— **他读了,而且读过去了。**

> 📌 真正的形状不是「不可见」,是:**一段大体通顺的话,不会让人停下来盯它的空洞。**
> **连贯性会掩盖缺失 —— 眼睛把空格补成了语义。**
> ⚠️ 这比不可见更难防,因为**它看起来像是已经检查过了**。

**⇒ 两端各一道,不是二选一:**
```
发出端   发完回读【发出去的那一份 payload】,⛔ 不是回读草稿
收件端   读到任何可见的空洞 / 断句 / 多余空格 ⇒ 停下来问,⛔ 不许脑补
```
⭐ 本轮是**发出端**自己抓到的 ⇒ 发出端那道更早、更有效;但收件端那道也不能不装。
