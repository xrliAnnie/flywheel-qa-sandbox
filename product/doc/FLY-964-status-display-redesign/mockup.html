三段式跑到哪了?一眼看懂「你在这里」

一个任务在 设计 → 实现 → QA 三步里走。目标:你扫一眼 Discord,就知道 现在在哪一步、卡没卡、球在不在你手里 —— 不用点进去翻。

🎨 设计🔨 实现🧪 QA 粗信号放标题 · 细信号放置顶准 + 可信

核心思路:两个信号,各管一层

现在「乱」是因为标题和置顶各说各的、拼不成一句话。理想态让它们分工、且永远一致。

粗 标题 = 现在哪一步

只显示走到哪个 phase(设计/实现/QA)。只在跨 phase 时才改名 —— 全程最多改 2 次,绕开 Discord「10 分钟只能改 2 次名」的限制,所以永远不卡。

细 置顶 = 你在这里(权威)

置顶消息 不受改名限制,想更新就更新。承载全部细节:当前小步、球在谁手里、下一步、卡没卡、去哪看终端。你真正读的是这一条。

🔗
为什么两者永远一致(cohere):标题和置顶都从 同一份真实状态 自动算出来(不是两套各写各的),所以不会出现「标题说实现、置顶说 QA」的打架。这是这次重设计的地基。
✅ 完成 ▶ 进行中 ◾ 未开始 🔴 受阻 🤖 = 不用你  ·  ⏳ = 球在你手里

标题两种画法 — 你挑一个

都只在跨 phase 时改名(不触发限流)。区别只是「显不显示整条路走到哪」。

修复 · FLY-962

活跃的线程不再被误归档

以前:重启时把 还在跑 的线程也归了档 → Discord 不让改归档线程的标题 → 今早状态改名 失败 6060 次 → 标题卡在旧值。

✅ 现在:只有真正 做完 / 已上线 才归档,活跃线程永不归档 → 标题永远改得动、永远是最新。

修复 · FLY-959

ship 不再弹太早

以前:QA 还没全过 就弹「请你 ship」→ 你被叫来、其实没准备好 → 显示不可信。

✅ 现在:QA 全部 PASS 才把球交给你。你看到「等你批」= 真的能批了。

一句话

粗放标题、细放置顶,两者同源不打架;活跃不归档、QA 全过才弹。

凑成一句你一眼能读的:「现在在哪一步 · 卡没卡 · 该不该我出手」。准了、你才愿意看它。
