0 · 一句话

把 Feature Flag 的「开/关值」从「散在 Bridge 全局 .env、进程启动读死、改了要重启」,改成「存在 Bridge 已有数据库(SQLite)的三张新表里、进程用到时现读、Dashboard 改完立即生效、不重启、每项目一份」。

方案 A 已由你在 co-eval 中选定 本 PRD 把它写到 Tadashi 照着能建。
Codex 评审纠正的关键事实(已全部改进 PRD): ① 读方是 Bridge/Lead/Runner 多个独立进程 → 要跨进程 reader 契约;② 数量 83 个 flag = 77 env + 6 项目配置、10 个能直切;③ 「每项目不一样」和「无损回滚到任意旧版本」不可兼得 → 用分阶段 cutover 模型;④ 清除开关用 tombstone(墓碑标记)不删行,防并发 bug。

1 · Problem(病根,数字按实际代码校正)

  1. 改一个 flag 要重启整个项目 —— 不可接受。 83 个 flag = 77 env + 6 项目配置;只有 10 个现在能不重启切。真正「必须改代码」的规模由迁移清单(M0)得出,不写死一个数。
  2. flag 值不分项目。 77 个 env flag 现在全是「全局一份」;「某项目先开、别的先不开」今天做不到。
  3. 值和意图不分。 登记表只记「flag 是什么 + 当前值」,不记「意图」—— 分不清关着的 flag 是「故意关」还是「忘了开」。
  4. 只增不减。 env flag 一周从 40→77,从没删过一个。
  5. 代码合了 ≠ 功能活了。 merge 与打开之间的空窗(FLY-929 睡 2 天、auto-QA 数周没触发)。
本 PRD 范围 主攻 ①②③(动态、每项目、记意图)。④⑤ 的清理规范 + 83 个 flag 逐条 audit = 单独的 FLY-1136;本 PRD 只留数据基础(intent 字段 + change-log),不实现清理/提醒机制。

2 · Users

  • 唯一用户 = 你(founder)。 在 Dashboard(FLY-1038)按项目自助开关、立即生效、不重启、不找工程。
  • 读方 = 确有 flag 读点的进程(Bridge / Runner;Lead 有没有真实读点由 M0 核实,没有就不当 reader)。它们是独立进程 —— 本设计核心约束。

3 · Goals

  • G1 改一个已迁移 flag 不重启即生效,延迟即时~几秒(不是「每小时」)。
  • G2 flag 值 每项目一份。
  • G3 你在 Dashboard 自助开关、不走 PR;每次改留 change-log。
  • G4 值和意图分开记:能查关着的 flag「为什么关 / 谁定的 / 到期日(仅记录)」。
  • G5 不引入新服务、不上外部 flag 工具;复用 Bridge 现有数据库 + 现有鉴权。

5 · ⭐ 方案 A — 动态 flag store(核心设计)

5.1　store = Bridge 现有 SQLite 加三张新表

Bridge 已在跑一个 native SQLite(StateStore,库 ~/.flywheel/teamlead.db,已开 WAL + 事务),当前 16 张表。flag store = 新增三张表:

  • feature_flags(第 17 张)—— current-value,每项目一份;
  • feature_flag_changelog(第 18 张)—— 变更日志;
  • feature_flag_cutover(第 19 张)—— 迁移阶段 + 镜像状态的持久权威。

不新起数据库、不新起服务。

5.2　表结构(每项目一份 + tombstone 清除 + 结构化 change-log)

-- 第 17 张:每行 = 一个 scope 对一个 flag 的 override(含 tombstone 行)
CREATE TABLE IF NOT EXISTS feature_flags (
  scope_kind   TEXT    NOT NULL,           -- 'project' | 'global'（显式列，不用魔法项目名）
  project      TEXT    NOT NULL DEFAULT '',-- project 时非空；global 时必须 ''
  flag_name    TEXT    NOT NULL,
  has_override INTEGER NOT NULL,           -- 1=有 override；0=tombstone(=无 override,回退 legacy)。清除不删行
  raw_value    TEXT,                       -- has_override=1 时非空；=0 时 NULL
  intent       TEXT,                       -- 意图，nullable，data-only
  expires_at   INTEGER,                    -- 到期日，nullable，data-only（本期不实现提醒）
  revision     INTEGER NOT NULL,           -- 对 key 永久单调(乐观锁)；set/clear 每次 +1，绝不因删行重置
  updated_by   TEXT    NOT NULL,           -- server 可信上下文生成，不信浏览器
  updated_at   INTEGER NOT NULL,
  PRIMARY KEY (scope_kind, project, flag_name),
  CHECK (scope_kind IN ('project','global')),
  CHECK ((scope_kind='global' AND project='') OR (scope_kind='project' AND project<>'')),
  CHECK (has_override IN (0,1)),
  CHECK ((has_override=1 AND raw_value IS NOT NULL) OR (has_override=0 AND raw_value IS NULL)),
  CHECK (revision > 0)
);

-- 第 18 张:每改一次一行；结构化列区分 never-set / explicit / clear / metadata
CREATE TABLE IF NOT EXISTS feature_flag_changelog (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  scope_kind TEXT NOT NULL, project TEXT NOT NULL DEFAULT '', flag_name TEXT NOT NULL,
  action       TEXT NOT NULL,             -- 'set' | 'clear' | 'metadata'(仅改 intent/expires)
  from_present INTEGER NOT NULL, from_raw TEXT,
  to_present   INTEGER NOT NULL, to_raw   TEXT,
  from_intent TEXT, to_intent TEXT,        -- 可回看 intent 前后
  from_expires INTEGER, to_expires INTEGER,
  changed_by TEXT NOT NULL, changed_at INTEGER NOT NULL, reason TEXT,
  CHECK (action IN ('set','clear','metadata')),
  CHECK ((action='set' AND to_present=1) OR (action='clear' AND to_present=0) OR (action='metadata' AND to_present=from_present))
  -- …（其余 scope/present/value 一致性 CHECK 略）
);

-- 第 19 张:每 flag 的 cutover 阶段 + 镜像状态的持久权威
CREATE TABLE IF NOT EXISTS feature_flag_cutover (
  flag_name         TEXT    NOT NULL PRIMARY KEY,
  epoch             TEXT    NOT NULL,      -- 'shadow' | 'global-compatible' | 'project-capable'
  epoch_revision    INTEGER NOT NULL,      -- 阶段转移的乐观锁版本，单调 +1
  mirror_state      TEXT    NOT NULL,      -- 'in_sync' | 'pending'
  mirror_target_rev INTEGER,              -- pending 时:要镜像到 .env 的目标 revision
  last_mirror_error TEXT, last_attempt_at INTEGER,
  CHECK (epoch IN ('shadow','global-compatible','project-capable')),
  CHECK (mirror_state IN ('in_sync','pending')),
  CHECK (mirror_state='in_sync' OR (mirror_state='pending' AND epoch='global-compatible'
         AND mirror_target_rev IS NOT NULL AND mirror_target_rev > 0)),
  CHECK (mirror_state='pending' OR mirror_target_rev IS NULL)
);

清除 = tombstone(墓碑):清除一个 flag 不删除行,而是把它标成「无 override」+ revision+1。为什么不删行:删行会让 revision 重置,配合乐观锁产生并发 bug(create→clear 后又回到「无行」,过期请求能蒙混过关)。tombstone 保证版本号永远单调,这是 Codex 抓出的一个真坑。

5.3　读机制:共享只读 reader + 用到时现读

  • 每个读方进程持一个只读的长期连接 + 预编译查询(不每次判断重开库)。Dashboard 改 → Bridge 写行 → reader 下次判断该 flag 就读到新值。
  • 性能(答你担心的「每小时太慢」):预编译的主键单行查 ≈ 1 微秒/次(Codex 本机实测)—— 即时,明确不是每小时。只读连接不与写互斥。
  • 读点查询与「用量统计」拆开:本期不在每次命中同步写库(那会拖慢)。极热点可选加几秒缓存,默认不用。
⚙️ eng-reality-check(Tadashi):reader 连接生命周期、热读点、跨进程一致性,收 PRD 前 Tadashi 过一眼确认。

5.4　写 / 自助契约

复用现有的鉴权外壳(loopback + 单次 confirm token + 审计),但写数据库用新契约:乐观锁 CAS(stage 后若有人抢先改 → 409 冲突,防漂移)+ 按类型定值(75 bool / 6 数值 / 2 枚举,不套老的布尔接口)+ 清除走 tombstone + 只改意图/到期走独立 metadata 动作。改的人由服务器可信上下文生成,不信浏览器传的字段。

5.5　数据流

Dashboard（选 scope+项目+flag，set/clear）
   │ stage（校验）→ apply（乐观锁事务:UPSERT/tombstone + change-log
   │                        + global-compatible 期同事务写 cutover.pending）
   ▼
Bridge SQLite ── feature_flags（第17，current-value）
   │            ├ feature_flag_changelog（第18，审计）
   │            └ feature_flag_cutover（第19，阶段/镜像权威）     ← Bridge 唯一 writer
   │  reconciler 按 cutover.pending + 目标 revision fencing 镜像 .env
   ▲  只读连接 + 预编译主键查（reader 先读 cutover.epoch 决定 legacy vs DB，再读 flag，~1µs）
确有读点的进程（Bridge / Runner；Lead 待 M0 核实）

5.6　⭐ 跨进程 reader 契约(Codex 抓出的核心缺口)

Bridge、每个 Lead、每个 Runner 是独立进程(部分在 tmux/worktree)。改 Bridge 内存对它们无效。好在半条链已在(Runner 已拿到 Bridge 精确库路径、verify-approval 已用只读方式打开该库)。补齐:

  • Bridge = 唯一 writer;所有 reader 只读,用一个共享 reader client。
  • 逐进程矩阵(M0 填满):每个 reader 的真实读点位置 / 项目上下文来源 / 库路径来源 / 连接生命周期 / 库不可读时怎么办。Lead 有没有真实读点 M0 先证明,没有就从数据流移除。
  • 必须真机多进程 E2E:已运行的 Bridge 写值后,已运行的 Runner 在下一决策点看到新值。

5.7 – 5.9　意图/失败/迁移阶段(简版)

§5.7 意图/到期 = 只存数据:本期不实现提醒/扫描,归 FLY-1136。

§5.8 失败语义:「tombstone/无行」= 正常回退旧值;但「库不存在/损坏/报错」绝不静默当无行(否则已写的 OFF 会被旧值 ON 取代)。治理门/关键 kill switch 保持旧路径直到有 fail-closed 方案。

§5.9 ⭐ Cutover-epoch 模型(「每项目不一样」和「无损回滚」不可兼得的正解):每个 flag 走一条单调前进的兼容阶段 —

阶段语义生效源回滚底线
shadowDB 只存候选、不生效;reader 同时算两边、记差异但返回旧值legacy任意旧版本
global-compatible只允许全局 override;DB 与 .env 双写DB(与 .env 一致)任意旧版本(仍单一全局值)
project-capable证明旧 reader 清零后,才允许每项目分歧DB only只能回滚到含新 reader 的版本

阶段的持久权威 = 第 19 张表;转移用乐观锁 + 只走合法单调边。双写期定 DB 为准 + 有界重试 reconciler(用目标 revision fencing,防并发把旧值标成已同步 —— Codex R4 抓的并发 bug)。降级契约诚实收紧:降到不含 writer 的旧版前先冻结 flag 修改。

6 · 与登记表(registry)的关系

登记表仍是「flag 定义」的单一真相,但本期要小改:加一个「作用域」标记(全局 / 每项目)+ 逐个读点标明「项目身份从哪来」。优先级定死:项目 DB override > 全局 DB override > 旧的项目配置/env > 登记表默认值。
