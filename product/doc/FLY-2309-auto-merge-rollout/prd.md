## 4. Requirements —— 影子跑怎么跑(R1)

### 4.1 影子跑的定义(一句话)

> **每一单照常走今天的流程、照常由她过卡、一次都不真的自动合并;
> 系统在旁边把「如果自动道开着会发生什么」记下来。**

她的动作零变化、省下的时间为零、出事风险为零。这是补法 C 的全部意义。

### 4.2 每一单必须同时落的四条记录

| # | 记什么 | 落在哪 | fail 行为 |
| - | ------ | ------ | --------- |
| ① | **机器判的类** —— 这一单的**全部** PR(主仓 + 每个 nested target repo)是否都落在 6 个文档前缀下 | 扩展后的分类快照 | 任一 PR 拿不到分类 ⇒ 判 `unknown` ⇒ **不算纯文档**(fail-closed) |
| ② | **人判的类** —— Lead 在 ship 卡上声明这一单属于哪一类 | 新台账,**枚举字段不是自由文本** | 没声明 ⇒ 该单不进两周表的分子分母,单独计入「未声明」一栏 |
| ③ | **强度二两半** —— (a) 在 529 房把链路从头到尾真跑过一次 (b) 留下**外部可查、能被重跑**的记录 | 新台账,两半各一个字段 | 缺任一半 ⇒ 判**不满足**。「跑过」这件事**只认台账,不认自称** |
| ④ | **她实际有没有打回** —— 以及打回的是不是她本人 | `workflow_rework_request` + 新的 exact-head 绑定 | 绑不到 head ⇒ 计入「绑定失败」一栏,**不许猜** |

🔴 **③(b) 是这一整套里最容易被悄悄省掉的一格。** 2261 里她第一次读只读到 (a)。
少了 (b),强度二退化成强度一,而强度一对那 8 条「说做完了但没真跑过」**一条都拦不住**。
⇒ 实现时 (b) 必须是**独立字段 + 阳性对照测试**:一条自称跑过但没有记录的,必须被判不满足。

### 4.3 影子跑期间不做的事

- ❌ 不真的自动合并任何一单
- ❌ 不改她的任何动作、不改任何 Lead 规矩(见 §6)
- ❌ 不因为「机器判了纯文档」就少给她看一张卡

## 5. Requirements —— 两周后那张表 + 放手判据(R2)

### 5.1 交付物:一张表,三个数

| # | 数 | 定义 | 为什么要它 |
| - | -- | ---- | ---------- |
| **N1** | **纯文档类错判率(她本人口径)** | 分母 = 被机器判纯文档且到过 founder 门的单;分子 = 其中**她本人**打回的单 | 这是放手判据本身 |
| **N2** | **纯文档类错判率(founder 权限口径)** | 同上,分子放宽到全部 `authority='founder'` 的打回 | 上界。`authority` 是**权限**不是**作者**,两个口径必须都出,不许只报好看的那个 |
| **N3** | **被判会自动合并的单里,她原本会打回几条** | 在 N1 分母上,逐条列出她实际打回的内容 | 「率」会掩盖「这一条有多严重」。她要看的是**具体是哪几条** |

**同时必须报的三个分母卫生指标**(否则一张漂亮的 0 可能只是「什么都没记上」):

- 四条记录线各自的**覆盖率**(应为 100%);
- 「未声明人判的类」的条数;
- 「绑定失败」的条数。

> 🔴 记忆库教训:`cmd | grep … || echo none` 会把「命令当刻失败」静音成「不存在」。
> 一张错判率 = 0 的表,和一张什么都没记上的表,长得一模一样。
> ⇒ **报 0 的时候必须同时报全集规模**:「30 个里 0 条」才是结论,「0」不是。

### 5.2 放手判据(事先定死,不许事后调)

> ### **N1 = 0 才放手。不为 0,连纯文档类也不开,回来重想。**

- N2 > 0 而 N1 = 0 时:**不自动放手**,把那几条拿给她看一眼再决定 —— 因为「是不是她本人」是我读 verbatim 判的,不是外部事实。
- 任一覆盖率 < 100%:**这张表不作数**,补齐再跑,不许拿残缺的表去换放手。
- 这三条**现在写死在这里**,就是为了两周后不能靠「解释」把不达标说成达标。

### 5.3 起跑时刻

**两周从 B1(全仓判定)落地那天起算**,不是从本 PRD 合并那天起算。
理由见 §2:用有洞的分类器跑出来的表,错在偏乐观的方向。

## 6. Requirements —— 规矩改哪几条(R3)

### 6.1 ⭐ 影子跑期间:**一条规矩都不用改**

这是**影子跑最大的好处**,也是它值得先跑的原因。逐条核过:

| 规矩 | 影子跑要不要改 |
| ---- | -------------- |
| `founder-only-authority` R1(merge 授权契约) | **不改** —— 影子跑不合并任何东西 |
| ship 卡什么时候能出现在她面前(`reviewHoldReason()`) | **不改** |
| 她过卡 / 打回的动作 | **不改** |
| Lead 的派工与验收规矩 | **不改**(只多一个「声明这单属于哪一类」的动作,是**加一个记录**,不是改一条规矩) |

⇒ 影子跑是**纯增记录**,不是改行为。这就是为什么它的风险是零。

### 6.2 放手那天要改的规矩(**现在只写下来,不改**)

| # | 要改什么 | 现状 |
| - | -------- | ---- |
| M1 | `founder-only-authority` R1 增开一个**窄口**:同时过三道闸的单可以不经她过卡直接合并 | **只有她本人能改这份契约** |
| M2 | ship 卡的呈现:走了自动道的单,事后要有一个**她能看见、能一键 revert**的入口 | 未建 |
| M3 | 「她在卡上加新要求」这个入口关掉后的补位:改成事后入口 | 2261 T4,未定案 |

🔴 **M1/M2/M3 三条本单一律不动。** 写在这里是为了让她知道**放手那天的账单有多长** ——
影子跑跑完不等于第二天就能自动合并,还有这三条要她拍。

## 7. Success metrics(本单自己的成败,≠ 放手判据)

本单**不是**靠「错判率是不是 0」来判成败的 —— 那是两周后的事,而且答案是什么都算这一单做对了。

| # | 指标 | 目标 |
| - | ---- | ---- |
| S1 | 四条记录线的**覆盖率** | 影子跑开始后 100%(缺一条这张表就不作数) |
| S2 | 两周表**可被独立重算** | 任何人拿只读库副本 + 一份 SQL 能复现出同样的 N1/N2/N3 |
| S3 | 她在影子跑期间的**动作变化量** | **0**(变了就说明我们偷偷改了她的流程) |
| S4 | 放手判据的**不可事后调整性** | 两周后的报告直接引用 §5.2,一字不改 |

> 北极星长期看的是「她每周被 ship review 打断几次」。
> 但**影子跑期间这个数按定义不变**,所以它现在不是本单的指标 —— 拿它当指标会诱导我们提前放手。

## 8. Build issues(交 Tadashi 队列 / team FLY / project Flywheel)

依赖顺序:**B1 ∥ B2 ∥ B3 → B4 →(两周后)→ B5**

### B1 —— 纯文档判定必须覆盖这一单的全部仓 【P0 · 影子跑前置】

- **问题**:`ship_relevant_diff_snapshot` 260 条里 259 条是主仓;nested target repo 的 PR 从未被分类。实测 8/33 的纯文档单其实带 nested 代码 PR。
- **要求**:一单判「纯文档」的充要条件 = 该单**全部** PR(主仓 + 每个 nested target repo)的改动文件都落在 6 个文档前缀下,且**合计** ≤ 50 文件。
- **fail-closed**:任一 PR 拿不到分类快照 ⇒ 整单判 `unknown` ⇒ 不算纯文档。缺失 = founder-held,与今天 `ship_relevant_diff_snapshot` 「missing row is authorization-unknown」的既有语义一致。
- ⚠️ 我一度在此写过「这个洞今天已经在生效(免掉 QA 证据要求)」—— **该断言已撤回**,见 research.md §2b:那 8 个单的快照全挂在 `qa` 角色会话上,在 `review-hold.ts:153` 的 `if (!mainRole) return null` 就退出了,从未走到 docs-only 那一支。**B1 的必要性与优先级不变**,它是关于**未来自动道**的前置,不是一条现行的证据门缺口。
- **未决项(不许假装已解决)**:权威的 target repo 清单从哪来。本单是从 `codex_review_record.target_repo_identity` **反推**的,反推不能当判定依据。
- **验收**:
  - 阳性对照:回溯重跑那 33 个单,**8 个带 nested 代码的必须全部翻成非纯文档**;
  - 反向对照:22 个不带 nested 的必须**仍然**判纯文档(不许靠一刀切全判成 unknown 来「达标」);
  - 新表/新列登记进 `scripts/lib/fly-2006-retention-registry.mjs`(不登记会直接 `schema_unclassified` 打红)。

### B2 —— founder 门的判决必须绑到 exact head 【P0 · 影子跑前置】

- **问题**:`founder_gate` 是门节点,`execution_id` **恒 NULL(实测 358/358)**;55 条 founder 门返工按 `(run_id, node_id, attempt)` join 到 execution 的有 **0 条**。今天只能靠 run 级松 join 近似,而影子跑要的是精确。
- **要求**:每一条 founder 门的过卡 / 打回,都能查到它当时绑的 `(repo, pr_number, head_sha)`,以及**是不是她本人**(不是 `authority` 字段 —— 那是权限不是作者)。
- **验收**:新数据 100% 可绑;回溯 55 条报出可绑比例(不要求 100%,要求**报出来**);`authority='founder'` 与「她本人」必须是**两个可分辨的字段**,并配一组「Lead 以 founder 权限提交」的样本做阳性对照。

### B3 —— 强度二证据台账 【P0 · 影子跑前置】

- **问题**:`auto_qa_record` / `codex_review_record` 都没有任何字段表示「这是在真环境跑的」或「记录在哪、怎么重跑」。**闸② 今天是一句话不是一道闸。**
- **要求**:一条记录至少含 —— 绑的 head、在哪跑的(529 房 / 其它)、跑的是哪条链路、**外部可查的记录地址**、**怎么重跑**。两半((a) 真跑过 / (b) 有记录)是**两个独立字段**。
- **fail-closed**:没有台账行 = 不满足强度二。**只认台账,不认自称。**
- **验收**:阳性对照 —— 一条「自称跑过但没有记录」的样本必须判**不满足**;一条「有记录但记录地址打不开」的样本也必须判**不满足**。
- **已知不解**:强度二挡不住 FLY-1833 那种 flaky(一个 flaky 的端到端测试照样会偶然全绿)。**本单没有新解法,照旧明写在验收里,不假装解决。**

### B4 —— 影子跑记录线 + 两周表 【P1 · 依赖 B1/B2/B3】

- **要求**:每一单同时落 §4.2 的四条记录;**一次都不真的自动合并**;两周后按 §5.1 产出 N1/N2/N3 + 三个分母卫生指标。
- **新增的唯一人类动作**:Lead 在 ship 卡上声明「这单属于哪一类」——**枚举字段,不是自由文本**。
- **验收**:S1 覆盖率 100%;S2 可被独立重算(交一份 SQL);S3 她的动作零变化。

### B5 —— 放手那天要改的规矩清单 【P2 · 文档单 · 依赖 B4 结果】

- **要求**:把 §6.2 的 M1/M2/M3 写成可执行的改动提案,**交给她拍**。
- ⛔ **本单及 B5 都不实际修改 `founder-only-authority`。** 改契约只有她本人能做。
