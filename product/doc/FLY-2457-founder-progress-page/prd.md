## 1. 问题

⚠️ v1 把问题写成「今天四页并存」—— 那是**我们的内部视角**。她的原话是:

> 「我理解的现在也只有一页吧,就是我让他手写的,**完全是我中间手动让他出的**。但我希望之后就变成完全一页,**不需要我再手动让他去出一页**。」

⇒ **真正的问题不是「页太多」,是「那一页要她开口才存在」。**

| | 她今天拿到的那一页 |
|---|---|
| 怎么来的 | **她开口要**,Lead 手写 |
| 会不会旧 | 会 —— 它是一次性的快照 |
| 谁维护 | 只有那个 Lead 在的时候 |
| 通用吗 | ⛔ 不通用,写死在具体的人和项目上 |

而机制侧已经有一份**自己会刷新、固定地址**的页面(`epic-page`,`StateStore.ts:10055` 同 project 复用 token ✅),但它平铺 17 张卡、满屏机器话、不能留言 ✅(实抓 218KB 页面字节)。

⇒ **本单 = 让那份自己会刷新的页面长出她要的形状,从此不需要她开口。**

## 2. 用户

- **主用户 = founder**。场景:随时打开一个固定链接,**30 秒内**知道「有没有事等我 → 哪些 Epic 在跑 → 每个到哪一步」。手机要能读。
- 次要读者 = **任意部门 Lead**(拿它替掉自己手搓的页)。
- ⛔ **通用性是硬约束**(她的原话):主语必须是「**任意 Lead × 任意项目**」。⛔ 页面、字段、文案里**不许出现具体人名**;凡指人处一律写**角色**(工程 Lead / 产品 Lead)。

## 3. 目标 / 非目标

**目标**
- G1 一个固定链接,**不需要她开口就一直是最新的**。
- G2 打开即答三问:哪些 Epic 在跑 / 每个到哪一步 / 哪里等我。
- G3 不会旧:每格有出处与时间,页面自报自己多旧。
- G4 她能在上面**留言**;并且有**一个地方可以被 update**(她的原话)。

**非目标(本版明确不做)**
- ⛔ **不做「哪些该进 In Progress」的排期页** —— 她把这件事拆成两页,明说「现在都只做后面那个」。
- ⛔ **不做「哪个先做、哪个后做」** —— 她明说不在本 PRD 解决。
- ⛔ **不另存她的排期决定** —— 她说「不用存下来」;一致性由 §4 的流程约束解决,不由第二个账本解决。
- ⛔ 不做「founder 在页面上直接改 Linear」(她问过能不能,本版答:能留言、不能改;要做是新的一块,由她另开)。
- ⛔ 不做留言自动回传(页面无出站权限 ✅ CSP `default-src 'none'`)。
- ⛔ 不做多项目聚合。
- ⛔ 不改 Linear 的任何数据(只读投影)。

## 4. 先讲清楚一条分界:两个「决定」不是同一个东西

> Lead 2026-09-09 裁定:这条必须在 PRD 里明写,否则下一个读的人会以为我们自相矛盾。

她这一轮说了两句听上去打架的话:

| 她的话 | 说的是什么 |
|---|---|
| 「**不用存下来**……直接显示 Linear 里面的状态就可以了,不会出现两个 source of truth」 | **排期决定** —— 这件事**做不做 / 什么时候做** |

⇒ **它们答的不是同一个问题,所以不构成两个 source of truth。**

⇒ 页面上这两类信息必须**视觉可分**:她要能一眼看出哪句是机器测的、哪句是人写的(承她第 ⑤ 条与「丙」)。

## 6. 五个洞与结论

### 6.1 洞 A · 子单不知道自己属于哪个 Epic(✅ 实核)

`epic-page show --format json` 的每个 item 字段是
`acceptance / attempt / blocked_by / blocks / carriers / founder_named / gates / identifier / land / priority / run / session / signal_sources / signals / state / title / url`
—— **没有 parent**。做草样只能把父子关系**硬编码进脚本**,不可持续。

⇒ **新增字段 A**:`items[].parent`(Cell 型,出处 = Linear `issue.parent`);缺失显式缺(`no_parent`),不许静默。

### 6.2 洞 B · Epic 状态怎么来 ✅ **已裁定:照抄 Linear**(founder 2026-09-09T20:26Z)

曾经有两句可能冲突的话:第 ③ 条「Epic 自己也要状态:没开始 / 在做 / 全做完」推出「由子单算」;
后一轮「直接显示 Linear 里面的状态就可以了,不会出现两个 source of truth」推出「照抄」。

**她的裁定 = 照抄 Linear。** 落地形状(⛔ 写死,不再是候选):

| | |
|---|---|
| **Epic 徽标** | **= Linear 的 `state`,唯一真相**。⛔ 不再算第二个状态、⛔ 不另存判断 |
| **子单计数** | 照留在徽标旁边(如「0 在跑 · 1 未开始」)—— 信息还在,但它**不是状态** |

📌 **裁定时页面上正好有一个活例子**(✅ 实测):FLY-2369 徽标显示 `In Progress`,同一行的计数是「0 在跑 · 1 未开始」。
⇒ 两者并存不矛盾:**徽标回答「它是什么状态」,计数回答「它下面有多少活在动」**。她要的正是这个 —— 状态只有一个来源,细节仍然看得见。

⇒ 由此:`rollup` 字段**不新增**(§11);原开放问题 Q0 **关闭**。
⚠️ 已知代价(承 §14-6):存量没对齐时(她说「以后」但状态仍是 In Progress 的单),页面会如实显示 Linear 当时的样子。这是她选照抄的代价,页面不替她纠正。

> 「没挂大块的散活,我建议放一个专门的 Epic。那个 Epic 可以起名叫『其他』或者『日常』之类的。」

## 7. 「现在要你看」的固定格式(R5 · 对应 F11)

每行**恒定四段**,缺任何一段显式写「不知道」,⛔ 不许省略整段:

| 段 | 内容 | 出处 |
|---|---|---|
| ① **这是什么东西** | 类型词(固定词表)+ 单号 + 标题 | 下表 + Linear |
| ② **需要你去做什么** | 动作词,一句祈使句 | derived · `attention.v1` |
| ③ **等了多久** | 「自 HH:MM 起,已等 N 小时」 | `since` |
| ④ **去哪儿做** | 跳 Discord thread(不可用时灰掉 + 原因) | §6.3 |

| 类型词(①) | 动作词(②) |
|---|---|
| 在等你按一下(门开着) | 去 thread 里回一句「同意」或「打回」 |
| 体在问你一句话 | 去 thread 里回答它的问题 |
| ship 卡在你手里 | 去 thread 里点 :cool: 或说停 |
| 你点过名要回来找你 | 去看一眼,决定继续还是停 |

⬜ **开放问题 Q1**:「体说它卡住了」要不要进这一块?它**不需要她动手**,混进去会稀释「不按就不动」的含义。🔶 建议移出,放到 Epic 卡里当子单状态。

- **R3 · 子单**:在跑 → 未开始;终态子单默认不列,折叠区给一行计数(⬜ Q2)。

## 9. 依赖(R4 · 对应 F10)

## 10. 「Lead 判断」这一格怎么工作(F12 · 丙 的落地)

- **字段**:`items[].lead_note` 与 `roots[].lead_note`(Cell 型)。
- **写入**:任意 Lead 用一条 CLI 写入(与既有 `dependency add/remove/note` 同构 ✅ `commands/dependency.ts` 已在仓)。⛔ 不是页面上写,页面无入站。
- **出处**:`{ kind: "lead_note", role: <角色>, written_at: <时间> }` —— ⛔ **存角色不存人名**(F13)。页面显示「**工程 Lead · 2 小时前写**」。
- **不写会怎样**:只显示机器那句(`run.current_node_label` …)。⛔ **不伪造判断**,不用「暂无」占位假装有人看过。
- **过期**:`written_at` 与页面 `generated_at` 一同显示;🔶 超过 N 天的判断在视觉上淡化(N 由实现单定,不硬编码进 PRD)。
- ⛔ **它不覆盖状态,只并列**:机器那句仍在,两句视觉可分(§4)。
