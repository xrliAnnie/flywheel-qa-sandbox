### E21 — B5：Codex 兑换卡【FLY-2688 生产代码 bug，可直接修】

**已证实（可直接动手）**

- 上游 `account/rateLimits/read` 的返回值**最外层**有可选字段 `rateLimitResetCredits`，
  形状是 `RateLimitResetCreditsSummary | null`：
  ```
  { availableCount: int64（必需）,
    credits: RateLimitResetCredit[] | null }
  RateLimitResetCredit = { id, resetType, status, grantedAt,
                           expiresAt: int64|null, title, description }
  ```
  取证：对本机 `codex-cli 0.153.2` 跑 `codex app-server generate-json-schema`，
  读 `v2/GetAccountRateLimitsResponse.json`。
- `packages/teamlead/src/codex-quota/rate-limit-detail.ts` 的 `parseResetCredits`
  **只接受 null / number / 数字字符串**，收到对象会落到 `{ known: false }`，
  页面于是印「重置兑换未暴露」。
- ⇒ **必修**：按上面的对象形状解析。**取值位置是对的（最外层），不要去桶里找。**

**两条语义陷阱（别踩）**

- `credits.length` **可以小于** `availableCount`（后端会截断列表）。
  ⇒ 「有几张」**只能**取 `availableCount`；截断时如实说「还有 N 张，明细未给全」。
- `credits: null` = 只知道张数；`credits: []` = 查过且无可用卡。**这两个不是一回事。**

**还没证实的一半（B0 第一步）**

- 该字段是**可选**的，而现有解析器对「字段缺席」和「字段是对象」会落到**同一个** `known:false`。
  ⇒ **不能**把当前六个号的空值唯一归因于解析器。
- ⇒ B0 要在**授权窗口内**抓一次真实 raw result 落盘留证，
  区分 absent / null / object。
  ⚠️ 真调要碰共享 Codex auth 与账号池，按 FLY-2591 的既有纪律：
  挑没有在飞作业的窗口、由有权限的人做。

**页面效果**

- Codex 第五列命名「兑换卡」，**每张卡单独一行、各写各的到期日**（与 Claude 充值卡同一规则；founder：每个号都各有一张）。同一账号的其它列不重复。
- ⛔ **不准因为读不到就把这一列画空或拿掉**（原则二）。稿上是示例值，见 E24。
