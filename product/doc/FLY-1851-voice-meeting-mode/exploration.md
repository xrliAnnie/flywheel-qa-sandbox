## 8. C 和 B(FLY-1850)的分界 —— 别抢地盘

```
B  一个 agent 对她一个人。她不看屏幕,单向播报 + 她回话        失败方式 = 念错 / 转达错 / 吵到她
C  多方同时在场、要收敛出一个共同产物(PRD)                    失败方式 = 抢答 / 聊完没结论 / 结论落不了地
```

**判别口诀**:凡是「她一个人 + 不看屏幕 + 被动接收」的,归 B;
凡是「多方在场 + 主动开一场 + 要出一个共同产物」的,归 C。

⚠️ **一处会重叠的地方,先标出来**:两条线都需要「Lead 能说话、能听」。
这个共同底座**不属于任何一张 PRD**,应该在 C5 定形之后单独交给 Tadashi。

Discord 语音房收音 `EarsReceiver`(只订真人不订 bot = 结构性防回声,带 350ms backchannel 门,

既不能默认它会到(否则漏掉的那轮会静默丢失),也不能默认它不会到(否则会白等一条其实已经在门里的答案)。

### 为什么这条值得单独记

**这是「一次失败被概括成一条机制」的典型。** 一轮没送到 → 归因到「附件」这个特征 →
写成通则 → 下一轮就拿这条通则去解释世界。**但只有一个样本。**
第二个样本一来,通则就塌了 —— 而**塌的时候,前面所有依赖它的判断都要重看**。

⇒ **判据**:n=1 的失败可以记成**事件**,不能记成**机制**。要写成机制,先问「反例长什么样、我找过没有」。

### 18.1 升级是怎么发生的 —— Honey Lemon 的自诊断(比我原来的写法更准,原样收)

> 「我甚至在更早那条里还写过『**大概率**』—— **然后自己把『大概率』升成了『结构上』,中间没有任何新证据。**
> 这一步是我犯的,不是措辞不严谨,是**把一次观察升级成了一条定律**。」

⚠️ **这才是这条教训的真正机制**:不是「一开始就写得太满」,而是
**同一个判断在复述中被逐步加固** —— 「大概率」→「结构上」,**而中间没有任何新证据进来**。
⇒ **可查的信号**:同一件事你第二次说的时候,**用词是不是比第一次硬了?** 如果硬了,
**新证据在哪?** 找不到就退回去。

### 18.2 这条概括塌掉时波及了什么(它的牙齿)

Honey Lemon 补的后半句:

> 「**塌的时候前面所有依赖它的判断都要重看**」——
> 一条被当成机制的错概括,**不只是它自己错,它污染的是所有引用过它的推理**。

**本次波及两条线**(B 与 C 都按「gate 接不住附件」在操作)。
⇒ **他已同步 B 线**,连同「两种都要接住」的姿态。

### 18.3 一个副产品:**转述的忠实度这次有了实测**
