## 0.5 🔴 处理重复投递:**两问,不是一问**(2026-08-19 定为规矩)

```
旧的一问   这个 id 我见过吗?                    → 只防「重复做一遍」
新增一问   这条发出之后,有没有被后来的指令取代?  → 防「重放一条已经作废的」
```

### 为什么第二问是必须的 —— 它防的那类错**没有任何警觉信号**

> **「服从」在这里是错误的形式。**
> **所有的警觉信号都是为「违抗」设计的,没有一个是为「服从过时的东西」设计的。**

**本单的实例(最好的形状)**:

```
f2427b68 ③   「v3 音频驱动按未验写,不许当已定前提」   ← 发出时正确
被取代于      3ad50a7f(1911 验了、成立、要求升成实测)
若照重投执行   把一个【已验证】的结论降回未验 = 撤销一次正确的升级
而且看起来    完全像在服从指令
```

### 可执行形式(不只是原则)

**核当前 head,判断它是【被取代】还是【被违反】。**
本单实测走法:`grep` 当前 `prd.md` 对应段落 → 确认写的是「已验」而非「未验」→ 判定被取代 → **不动**。

### 三种重投,外观相同、处置不同(本单各出现过一次)

| 类型 | 实例 | 重放的后果 |
|---|---|---|
| 已应用、未被取代 | `3ad50a7f` | 冗余,不动 |
| **已被取代** | `f2427b68` | **撤销一次正确的升级** |
| **已应用、被后来的指令扩展** | `95a6990f`(后被 `7cded9c3` 补上完整性要求) | **覆盖掉扩展部分** |

⚠️ **只有查过「它发出之后发生了什么」才分得开。**

### ⛔ 这条判据的**前提**(2026-08-20 补 —— 今晚被这件事本身戳破)

> **它成立的前提是:后续指令都到齐了。**
> **收不到后续,任何「查后来发生了什么」的方法都失效 —— 因为你查不到你没收到的东西。**

**今晚的实例**:那条是**第二种(已被取代)**,而**我分不出来** ——
**因为取代它的那条根本没送到我手上。**

**⇒ 可操作的补法(Lead 定)**:
凡是**明显过期**的指令(**时间戳距今很久**,或**内容和我当前状态不一致**),
**动手前先问一句「这条还算数吗」。**
**成本一句话,比发错一张卡便宜。**

## 1. 轮次节奏(五条铁律落到动作上)

```
一轮 = (本地干活:研究/备料) → 一张 founder 卡 / 一个问题 → 等她回 → 结论落文档 → 下一格
```

- **一轮只问一件事。** 绝不一次甩五个问题。
- **每一格开头先探**:「这块你**有定见**,还是我来发挥?」
  - 她有定见 → 对齐到清楚为止,**不自由发挥**,把结论复述回去确认。
  - 她给我 latitude → 出方案(**≥2 个选项 + 各自代价 + 我的推荐和理由 + 我不确定的地方**),再回来对齐。
- **一格收敛了才钻下一格**,并在 `progress.md` 和 `exploration.md` §6 更新当前位置。
- **她的回答逐字落档**(她的用词经常就是判据本身),不是转述、不是摘要。
- **founder 卡不通过 = 反馈,不是否决。** 改完重新出卡、重开新一轮门,不复用旧卡。
  ⚠️ 一键复制的输出永远带前缀,而通过判定是**整串精确相等** ⇒ **`passed=false` 极可能只是机制,
  永远读 `feedback` 原文**,别把机械位当她的态度。

## 0.6 三条判据(2026-08-19,Honey Lemon 定;与那次指令冲突无关,单独收)

### ① 「精度问题」和「问错问题」的分界线 —— 决定能不能先发后补

```
精度问题   同一个问题,答案的误差范围变窄   → 可以先发,后补
问题问错   要问她的【那件事本身】变了       → 必须等,发了就是浪费她一轮
```

**本单实例**:「什么时候它该**自动闭嘴**」和「什么时候它该**结束这场会**」——
**这是两个问题,不是同一个问题的两种精度。**
⇒ 如果闭麦=挂断,**她答的「闭嘴时机」会被我们当成「挂断时机」用** —— 那是她从没同意过的东西。

⚠️ **判据的用法**:发卡前问一句 ——
**「等来的那个事实,会让我改答案的误差范围,还是会让我换一个问题?」** 后者必须等。

### ② 一个「找不到」要能当证据用,**必须先证明这把尺子找得到该找到的东西**

**本单实例**:报「协议里搜不到 pause」之前,先量 `input_audio_buffer.append` —— 命中 3 次
⇒ **尺子有效**,所以那个「没有」不是尺子瞎。
🔗 与 §11.5「零命中只说明我扫的范围里没有」是同一条的**可执行版本**:
**光知道那条判据不够,要在报零命中的同一次里就把对照做出来。**

### ④ 做缺失性检查时,**搜的词必须来自被检查的那份材料本身**

**今晚的实例**:我查「卡上有没有提示闭麦可能等于挂断」,搜的是 **`挂断` / `结束这场会`** ——
**那是我们内部讨论时用的说法,不是她那张卡上的说法。**

⇒ 结论碰巧是对的(卡上确实没提),**但方法是错的**:
🔗 §11.5 说「零命中只说明我扫的**范围**里没有」——
**这次差的不是范围,是【词表】。** 我拿我们的词去搜她的材料。

⇒ **判据**:**做缺失性检查时,搜的词必须来自被检查的那份材料本身,不能来自我们讨论时用的词。**

### ③ 报「搜不到」时,**连同会骗人的命中一起点名**

## 0.8 两条通则(Honey Lemon 2026-08-20 定为舰队纪律,`lead-instruction d7c49f7b`)

### ① ⭐ **论据的数量本身是一个断言**

**本单实例**:§25 给 P-6 撑腰原本写了三条论据,后来发现其中两条属于
「**会话已死但媒体面照流**」那一类 —— 也就是**会在被测对象已经死掉时照样为真**的读数。

⇒ **处置:一条论据被它自己的出处否掉,就【删掉】,不是【软化】。**
⇒ **而三条变一条必须留痕** —— 否则后人会以为它还是三条那么硬。
⇒ 🔑 **把「强度」和「结论」分开记**:结论可以不倒,强度必须跟着降。

### ② 🔴 **静默损坏:命令替换失败会把证据吃掉,而消息照发**

**本单实例**:一条报告里用了三重反引号,zsh 当成命令替换,**把那两行原始数据吃掉了**;
终端留了报错,**但消息照样发出去**,收件人看到的是一段**读起来通顺、只是少了证据**的话。

⚠️ **为什么它比一般的手滑严重**:

```
被吃掉的     永远是被引号包住的那部分 —— 也就是【原始数据】
报错落在     发信人的终端
损坏落在     收信人的眼里
⇒ 两边都不会觉得出事。
```

⇒ **做法(两条,不是一条)**:
1. **消息里绝不出现反引号**(基线早有此条,这次是明知故犯的实例)。
2. ⭐ **发完回去读一遍落库原文** —— 本单这次就是这么发现的。
3. ⭐ **证据尽量放文件里,消息里只给路径** —— **从根上让证据不经过 shell。**

📌 **附**:PRD / plan 里的表格是**文件内容,不经过 shell**,所以不受这条影响 —— 这也正是第 3 条的理由。


### ③ ⏱ 时刻一律逐字取 `startedAt` 并带 Z(Honey Lemon 2026-08-20 定,`lead-instruction 83d923e0`)

**触发**:系统给出的时间戳一直是 **UTC**,而 **Annie 在 PDT,差 7 小时**。
**B 线已经因此算错过一次间隔**,并已向她换成她的钟重发。

⇒ **规矩(三条)**:
1. **文档里不许出现裸时间。** 引用时刻**逐字取证据文件里的 `startedAt`**,连毫秒带 `Z` 一起抄。
2. **对 Annie 说时刻,换成她的钟(PDT)。** 对内留 UTC。
3. ⭐ **两个相近但不同来源的时刻,不许互相替换** —— 本文件 §0.4 那条 18 秒的差就是实例:
   一个是 mailbox 建行时间,一个是日志里记的发出时间,**长得像同一个时刻,但不是同一个事件。**

🔗 与 §0.8 ① 同族:**「这两个数说的是同一件事」本身就是一个断言,要么证明它,要么并排摆着。**

## 0.9 两条他命名的通则(Honey Lemon 2026-08-20,`lead-instruction 3c5f5c3d`)

### ④ ⭐ **两个接近但不相同的值,默认是【两个不同事件】,不是同一件事的测量噪声**

## 0.10 三条(Honey Lemon 2026-08-20,`lead-instruction 052428b3`)—— **都来自一条我差点发出去的假警报**

**背景**:一条重投的指令,我怀疑它「已经被 Lead 后来的更正推翻了一半」。
**核完发现没有。** 三条通则全部出自那次没发出去的误报。

### ⑥ ⭐ **一个真前提 + 一步没验的连接 = 一个继承了前提可信度的假结论**

```
真的      「Lead 确实更正过账号那件事」
没验的    「⇒ 所以那条指令因此过期」   ← 我自己接上去的一步,凭印象
```

⚠️ **它比纯粹的胡猜危险得多**:
> **前半截经得起查,而查的人往往就停在那里了。**

⇒ **自查动作**:一条结论里,**哪一段是引来的、哪一段是我自己接的** —— 接的那段要单独拿出来验。

#### ⑥b 🔴 **同一族的更狠版本:没有前提,从一个【缺口】补出一个状态**(2026-08-20 补)

```
⑥       真前提 + 一步没验的连接   ⇒ 推错了
⑥b      【没有前提】             ⇒ 无中生有
```

**本单实例**:我写「载体决定时**她可能不知道**打断会被牺牲」。
**我手上根本没有那段对话** —— 而 Lead 在她拍板**之前**就明确告知过,她还专门夸过打断,然后仍选 v2。

> 🔑 **「她知不知道 X」是一个【关于她的事实】,只能来自记录。**
> ⛔ 手上没有那段记录时,**正确动作是问,不是往任何一边假设** ——
> **包括不假设她知道,也不假设她不知道。**

⇒ **成本对比(这才是没有理由不问的原因)**:
问一句「你跟她说过吗」= **一条消息**;
猜错的代价 = **一条错的前提被写进 PRD,并据此登记了一个会去打扰她的待办。**

##### 📌 ⑥b 的**第二个实例** —— 而它证明的东西和第一个不一样

**那条含着同一个缺口的指令,后来【原样重投了一次】。**
第二次我没有再填那个缺口。

> ⛔ **但原因不是「我更小心了」** ——
> **是第一次的更正已经写在文档里了。**

⇒ 🔑 **一条规矩被【重新遇见】验证,比被【论证】验证硬**(Honey Lemon 2026-08-20):
> **论证只说明它自洽;重新遇见说明【同样的材料确实会再次把人推向同一个错】。**

⇒ ⭐ **这也回答了「这本规矩册会不会变成没人读的册子」**:
> **它的价值不在【被读】,在于它把【第二次撞击】挡住了。**

### ⑦ ⏱ **当两件事的先后关系是论据时,先把所有时刻归到同一个单位再排序**

**本单实例**:换号 07:18 PDT、三次跑全是 Z。**混着排,刀口的位置就错了。**
全部换算成 UTC 重排之后:

```
P-6              08:00:01.704Z   ← 换号之前
换号             14:18Z(新令牌 14:31Z,凭据 last_refresh 14:29:15Z)
今天 v3 死       15:51:07.328Z   ← 换号之后
今天 v2 活       16:10:37.347Z   ← 换号之后
```

⚠️ **为什么它是静默的**:
> **混单位排序不会报错,它只会给你一个【顺理成章的】错误顺序。**

🔗 与 §0.9 ④ 同族:**时间上的错误从不举手。**

### ⑧ ⭐ **更正是有作用域的 —— 发更正必须连「它不碰什么」一起写**

**Lead 自认的实例**:他发的更正是「账号没控住」,**作用域只在「P-6 对今天」这一对**;
它**不**作用在「今天 v3 对今天 v2」上,更不作用在所有提到账号的句子上。**他没写作用域。**

⇒ **后果**:
> **一条【无作用域】的更正,在下游会被当成【全面作废】来用。**

⇒ 本单差一点就那么用了,**而且用得有道理** —— 这正是它危险的地方。
⇒ **规矩**:自己写更正时,**连同它不推翻什么一起写**;收到无作用域的更正时,**先问作用域,不要自己替它划**。

📌 **同族第二条**:一个词的宽窄也会造出同样的后果 ——
排除掉的是「这个账号**整体**是死的」,**不是**「这个账号**缺 v3 这一项**」,而后者是唯一还开着的那格(PRD §28)。
> **两句话差一个词,结论差一整条路。**

### ⑧b ⭐ **⑧ 的完整形式**(2026-08-20 补 —— 原来那条只写了一半)

**怎么补上的**:⑧ 原文只说了**更正**。做入口警告时发现**警告有同一个毛病**,
Lead 合成完整版并采纳:

> **任何会改变别人【怎么读既有结论】的东西,都必须自带边界。**
> —— 更正、警告、撤销、降级,**全都一样**。

**区别只在失效方向**:

| | 无作用域时会怎样 | 往哪个方向滑 |
|---|---|---|
| **更正** | 把**还成立的**一起作废 | 往「**假**」滑 |
| **警告** | 把**没被碰到的**一起打上问号 | 往「**不确定**」滑 |

⇒ 🔑 **两种都是「把一个局部事实当全局用」。**

#### ⇒ 执行形态(这一步才是规矩,前面是道理)

> **写「它不碰什么」,而且要去核,不能靠推。**

**本单实例**:入口那条 `ok` 警告,我去核了 P-6 原件**不带 `ok` / `gotAnswer`**、§25 引的是实质栏,
才敢写「**§25 不受影响**」。
> 🔑 **Lead 的话,收下:说清楚它【不碰什么】,比说清楚它【碰什么】更费事,也更值钱。**

## 0.11 ⭐ **founder 说的话里,决定和理由要分开收**(Honey Lemon 2026-08-20,`lead-instruction c3e9ea5e`)

## 0.14 ⑭ ⭐ **一个数字要不要跟着更新,看它是【构成性】还是【累积性】**

**同一份文档里,同一天,两个数字走了相反的方向:**

| 数字 | 类型 | 处置 |
|---|---|---|
| 「与**当时已有的那四次**」 | **构成性** —— 它是**某次对照的分母**,那次对照跑的时候就只有四次 | ⛔ **不许改成七** |
| 「历次死亡的时间(六 → 七)」 | **累积性** —— 它只是**一份还在增长的清单** | ✅ **该跟着更** |

⇒ 🔑 **判据一句话**:

> **这个数是【构成了一个论据】,还是【只是在数数】?**

- **构成了论据** ⇒ 改它就是改那个论据 ⇒ **锁住,并写明为什么不改**。
- **只是在数数** ⇒ 不更就是留一个过期事实 ⇒ **更。**

⚠️ **两者外观完全一样** —— 都是一个数字出现在文档里。
⇒ 所以 §0.12 ⑨ 那个动作(**改完再 grep 一次那个断言**)只完成一半:
**grep 找出所有出现,还要【逐处判类型】** —— 一律改和一律不改,都会错一半。

### ㉑ 🔴 **全称句比计数更脆 —— 别用它去替换一个会过期的数字**(我 2026-08-20 刚栽的)

|---|---|
| **计数**(七次) | 只是**不全** —— 它说过的仍然都对 |
| **全称句**(每一场) | **一个反例就【过期】** —— 它整句变错 |

### ㉑b ⭐ **㉑ 的通则形式(Honey Lemon 2026-08-20,`lead-instruction 0526af7f`)**

> **换掉一个脆弱结构时,先确认替代品不是更脆的。**

#### 🔴 为什么这一类特别难被抓住

```

```

⇒ **合规的外观本身就是一层伪装。**

#### 📌 附:为什么全称句是最脆的那种

**全称量词的可证伪面积最大 —— 它对【每一个未来的样本】都下了注。**

| 断言形式 | 被反例撞到时 |
|---|---|
| 一个数字 | **那个数字过时**(不全) |
| **一个全称句** | **整句话直接变假**(过期) |

## 0.21 ㉗ ⭐⭐ **一条指令被重投时,会过期的是【依赖世界的那部分】** —— ⚠️ 本条 2026-08-21 换过分界,见下

```

依赖世界的(现状 · 转述的事实 · 计数)     会被后续核实推翻 ⇒ 【必须】重核
```

| | 会不会提醒你去核它 |
|---|---|
| **现状段** | ✅ **自带标记**(现在 / 目前 / 还在等 / 试过 N 次)⇒ **它会主动提醒你** |
| **转述的事实** | 🔴 **没有任何标记** —— **它读起来就是一句陈述句,和一条不会过期的规矩长得一样** |

> ⭐ **所以「转述的事实」是这一类里最危险的:它属于【依赖世界】那一栏,却穿着【自洽】那一栏的衣服。**

只【容纳】新样本   ⇒ 本轮周(epicycle):旧分类照旧,外面挂一个例外

1. 找出它里面【依赖世界】的每一句 —— 现状 · 转述的事实 · 计数

2. 只重核那些
3. 规矩 · 边界 · 逐字原话 —— 直接沿用

⚠️ **重核是必须的** —— 本单 5 条里有 **4 条**含已过期内容,其中两条若从零执行会造成实害:

## 0.23 ㉚ 🔴 **我把 717 行重复内容留在文档里六个 commit,没发现** —— 事故与它的判据

**经过**:v0.36 重排 §24 时,我用的是

```python
start = s.index('## 24. 📋 空格清单')   # §24 在文件【末尾】
end   = s.index('## 25. ✅ P-6 结果到齐') # §25 在文件【前面】
s = s[:start] + 新24 + s[end:]           # ⇒ end < start ⇒ 把 §25…§30.1 又接了一遍
```

⇒ **切片假设了「§25 在 §24 后面」,而本文档里 §24 一直被新章节往后挤,早就在最末尾。**

### ⚠️ 为什么六个 commit 都没发现

| 掩盖它的东西 | |
|---|---|
| **每次编辑都用 `s.index()`** | 只找**第一个**匹配 ⇒ 后续编辑全落在**活的那份**上,**看起来一切正常** |
| **`assert s.count(...)==1` 只加在【被改的那句】上** | 而重复的是**整块**,那些句子我没去 assert |
| **`git diff` 只显示我这次改了什么** | ⇒ **一个早就存在的重复块,在每一次 diff 里都是隐形的** |
| **文档太长** | 2600 行,没人会通读到尾 |

> 🔑 **它是被【一次正确的操作】发现的**:我 grep 一句话,**命中了两次**。
> ⇒ **㉙ 那条(改完再 grep)本来就该抓到它,而我每次只 grep 我刚改的那句。**

### ⇒ 判据(三条,都要照做)

1. **按行号/位置切文件之前,先断言顺序**:`assert start < end`。⛔ **位置假设必须写成断言,不能留在脑子里。**
2. ⭐ **改完之后 grep 的不只是「我刚改的那句」,还要 grep 【结构】** ——
   最便宜的一条:**`grep '^## ' 文件 | sort | uniq -d` 必须为空。**
3. **凡是「整块搬运」的编辑(移动/替换/重排一整节),改完必须做一次全局重复检查** ——
   逐句 assert 挡不住整块重复。

🔗 §0.13 ⑫ 的一个更狠的形式:**我以为我在验证,而我验的范围比我以为的小。**
🔗 与 §0.16 那条同族:**只往一个方向看会漏报;这次是【只在一个粒度上看】会漏报。**

---

### ㉚a ⭐⭐ **检查必须和「可能出错的那个操作」同粒度**(Honey Lemon 2026-08-20 提为通则)

> **逐句 assert 挡不住整块重复。**
> **检查要和【可能出错的那个操作】同粒度,而不是和【我打算改的那句】同粒度。**

**本单**:做的是**整块搬运**,加的却是**单句断言**。

⚠️ **这类错配天然不会被发现,因为断言【全都通过了】** —— **它们检查的东西确实没坏。**

### ㉚b ⭐⭐ **diff 对「先于它存在的缺陷」结构性失明**

> **⇒ 每一个 commit 都被尽责 review,也永远抓不到它 —— 它不在任何一次 diff 里。**
> 🔑 **凡是「只看变化」的工具,都需要一个「看全量」的搭档。**

**而 `s.index()` 只找第一个匹配这条更阴**:
后续每次编辑都**精准落在活的那一份上** ⇒ 重复的那份**保持原样、毫无异常**,
**连「两份不一致」这种能暴露它的信号都不会产生。**

> ⛔ **它安静得像根本不存在。**

### ㉚c ⭐⭐⭐ **给结构化文档留一条【一行的结构不变量】,它必须恒为空 / 恒成立**

**本单那条**:

```
grep '^## ' 文件 | sort | uniq -d      ⇒ 必须为空
```

**为什么它比那三条判据都实用**:一行 · 零成本 · **每次都能跑** · 检查的是**结构**不是内容。

> 🔑 **这类检查的价值在于:【它不需要你事先知道会出什么错】。**
> 三条判据各自防一种已知的错法;**不变量防的是「我还没想到的那一类」。**

#### ⚠️ 必须一起写的一句(否则会被读成「最后不是抓到了吗」)

> **这次它是【偶然】露出来的** —— 我 grep 一句话,命中了两次。
> ⛔ **也就是说:流程里本来没有任何一环会抓到它。**

⇒ **所以这条不变量不是「锦上添花的复核」,它是【那个缺失的环】本身。**

## 0.24 三条收尾(2026-08-20,`lead-instruction 9740c7fc`)

### ㉛ ⭐⭐ **按【做决定时手上有什么】评分,永远不按【后来结果如何】评分**

**本单实例**:我推过「她的麦是 Discord 客户端的事」,**没写进 PRD**;后来证据来了,推论是对的。

> ⛔ **不写之所以正确,不是因为它后来被证实。证据反过来,不写同样正确。**

#### 🔴 为什么这条必须显式立(它防的是一种【教学事故】)

> **一个【碰巧猜对】的判断,是最危险的教学材料。**
> 它**同时**奖励了两种行为:**「有直觉」** 和 **「守纪律」**。
> ⇒ **而下一个人记住的一定是前者** —— 它更好用,也更让人自我感觉良好。

⇒ 所以复盘一次「猜对了但没写」的时候,**必须把评分锚点写出来**,否则它教出来的是相反的东西。

### 📎 第二个实例(2026-08-20 晚)—— **比第一个更狠**

**经过**:Lead 说「你 v1.1 那个错**有一半在我这儿**」。**我顶了回去**,说歧义是他造的、放大是我选的。
**他核过之后收回了那句** —— **我的结论是对的。**

> ⛔ **但我【没有核他那句】就顶了回去。** 我用的是我自己的推理。

#### ⭐ 为什么它比第一个实例更狠

| 实例 | 形态 |
|---|---|
| 第一个 | **我没写、后来被证实** | ← **沉默**恰好对 |
| **第二个** | **我顶回去了、恰好对** | ← ⭐ **主动断言**恰好对 |

> 🔑 **主动断言碰巧对,比沉默碰巧对危险得多** ——
> **因为它会被当成一次「判断力示范」,然后被复用。**
> ⇒ **沉默不留下可复用的模板;断言留下。**

#### ⚠️ 那句话的核**实际上做了 —— 是他做的,不是我做的**

他回去读了自己那句、确认「读法 B 确实没被堵死」,**然后才收回**。

```
✅ 结论是安全的      —— 有人验了
🔴 我那一侧的过程有洞 —— 我没验
```

> ⭐ **两件都真,⛔ 别合并成一句。**
> 🔑 **收成一条:【验证发生了】≠【我验证了】。**

⚠️ **这一类最难自查的原因**:**结论对的时候,没有任何信号提示你去看过程。**

### ㉜ ⭐ **声明范围:说小了会漏,说大了会误伤 —— 两边都要写死**

**本单两个方向各栽过一次**:

| 方向 | 实例 | 后果 |
|---|---|---|
| **说小了(漏)** | 更正/警告**不写作用域** | 下游当成**全面作废 / 全面存疑**(§0.10 ⑧ ⑧b) |
| **说大了(误伤)** | 我写「1850 那边**同一格**也悬着」,把两件事合成一句 | **连没被碰到的也一起被圈进去**(实际只有状态显示共通,麦克风是本单独有) |

> 🔑 **这两条是同一条的两个方向。⛔ 两边都要写死,不是只防一边。**

### ㉝ ⭐ **从自己的事故里【数出来】的规矩,比【想出来】的更该被信**

**本单实例**:㉗(重投里过期的永远是现状段)不是我想到的,是**今天 4 条重投逐条跑完第二问数出来的**
(4 条里 3 条的现状段已过期),并带一个具体后果:
「等她一个字」那条若从零执行,**会去重开一件她已经决定并且正在做的事**。

> 🔑 **理由:它的适用范围【已经被证据划过一次了】。**
> 想出来的规矩,适用范围是作者猜的;数出来的规矩,适用范围是被样本划出来的。

🔗 与 ㉒(被意外事件验证 > 被论证验证)、㉔(条目要记出处)同一族 ——
**三条都在说同一件事:一条规矩的可信度,取决于它和【真实发生过的事】之间有多少距离。**

## 0.27 ㊱ 🔴 **断言范围 ≠ 读起来的范围** —— ⛔ **这一族【不许】并进 ㉗**

## 0.28 ㊲ ⭐ **拿到 ✅ 时问一句:「我因此【不再核】什么了?」**

> 🔑 **它把 ✅ 的【边界】问出来,而不是让 ✅ 自己去划。**

⚠️ **⛔ 不要写成「以后不要盲信批准」** —— 那是个**态度**,修不了任何东西。
**这一条是个动作**:批准到手 ⇒ 当场把它关掉了哪几格数出来。

### 🔴 必须一起写的那一半:**停下来是对的**

**本单实例(同一条 ✅ 的两半)**:

| 那条 ✅ 关掉的 | 判定 |
|---|---|
| 「⬜ 该不该进文件」这一格 | ✅ **停止再想是【对的】** —— 它**就在**这条 ✅ 覆盖的范围里 |
| **㉛ 那段措辞**(他明说没看过) | 🔴 **不在覆盖范围里** ⇒ **责任仍在我手上**,不因为这条 ✅ 而结束 |

> ⭐ **批准【本来就该】关掉检查 —— 在它覆盖的范围之内。**
> 🔴 **要修的 bug 是:它把【范围外】的也一起关了。**

⇒ 🔑 **目标不是「多检查」,是【检查落在对的地方】。**

### ⚠️ 这条最可能的退化形式,写死堵上

```
❌ 退化成   「什么都别停下来想」
⚠️ 后果     过度谨慎同样会毁掉结论 —— 这一条我们栽过
```

**左栏该关的关掉,右栏没被覆盖的留着。**

## 0.29 ㊳ ⭐⭐ **一条可照做的规矩,必须同时规定它的【产物】,不只是它的【动作】**

```
只有动作          ⇒ 会退化成【仪式】
退化之后长什么样   人照做了 · 心里过了一遍 · 什么都没产出 —— 而且他会觉得自己遵守了
```

### ⚠️ 为什么它特别难抓:**这种退化在报告里看不出来**

> **「我问了这一句」和「我问了并得到一张两栏表」—— 写出来一模一样。**

⇒ **没有产物的规矩,连它有没有被执行都无法被检验。**

### ⇒ 判据

> **写完一条规矩,问:「照做之后,【桌上多了什么东西】?」**
> **答不上来的 —— 它还只是一个姿态。**

### 📎 本单实例(㊲ 就是被这样补完的)

| | |
|---|---|
| **Lead 给的** | 「拿到 ✅ 时**问一句**:我因此不再核什么了?」 ← **动作,半成品** |
| **补上的** | **它的产物是一张两栏表**(左栏该关的关掉 · 右栏没被覆盖的留着)—— ⛔ **不是一个「继续怀疑」的姿态** |

🔗 与 §0.19 ㉔(条目要记出处)同族,但方向相反:
**㉔ 问的是「它从哪儿来」(可信度);㊳ 问的是「它往哪儿去」(可执行性)。**

### 📋 用 ㊳ 回扫本册的结果(2026-08-20,`lead-instruction 5df627a1` 授权)

> ⛔ **只扫、只列,【没有修】** —— 发现与修理分开,修理等 Lead 看过清单。

**方法**:先用关键词粗筛(产物/清单/表/写进/写明/留下…)flag 出 **14 条**,**然后逐条人工读**。
⚠️ **粗筛过报了 10 条** —— 例如 §0.8 ① 的产物是「**留痕**」、⑤ 的是「**一并写下它的例外**」,
**都不在词表里。** 🔗 §0.19 ㉔ 同款教训:**近似检查不是那个属性本身,只能用来缩小人工核对范围。**

#### 🔴 真缺产物(4 条)—— **照做之后桌上什么都没多**

| 条目 | 它说的动作 | 🔴 缺的产物(建议,**未实施**) |
|---|---|---|
| **⑥** 真前提+没验的连接 | 「接的那段要**单独拿出来验**」 | **验完留下什么没写** ⇒ 建议:在结论旁**标出哪一段是自己接的**,以及它验了没有 |
| **⑩** 证据变多≠结论变强 | 「加样本回答的是它是不是偶然」 | **没说照做之后要写什么** ⇒ 实例里 PRD 写了「**结论不变,样本变厚**」,但规矩没把那句定成产物 |
| **㉑b** 换脆弱结构前确认替代品不更脆 | 「**先确认**」 | 🔴 **「确认」不留下任何东西** ⇒ 建议:写出**新旧两者各自会怎样失效**,并排放 |
| **㉚a** 检查要与操作同粒度 | 「检查要和可能出错的那个操作同粒度」 | **没说产出哪一种检查** ⇒ ㉚c 给了一个具体例子(结构不变量),但 ㉚a 自己没要求写出来 |

#### 🟡 边缘(3 条)——**实例里有产物,规矩本身没把它定死**

| 条目 | 实例里的产物 | 规矩里缺的 |
|---|---|---|
| **⑦** 同一单位再排序 | 那张**排好序的时刻清单**(已写进本条) | 规矩没说「产物 = 那张表」 |
| **⑮** 同形可比不可聚合 | 那条**限定**(不许算均值/离散度) | 规矩没说「产物 = 写下那条限定」 |
| **㉗** 重投只重核依赖世界的部分 | —— | **没写「重核完留下什么」**(例如:标出哪几句已核、结论是什么) |

#### ⚪ 不适用(㊳ 只管【可照做的规矩】)

**⑱ · ㉑ · ㉒ · ㉝ · ㉚b** —— 这几条是**判据/观察**,不是动作,**没有「照做」这一步。**
⚠️ **但它们仍受 ㊳ 的一个变体约束**:一条判据要能被用,**必须指向某条带产物的动作** ——
例如 ㉚b(diff 结构性失明)本身不产出任何东西,**它靠 ㉚c 落地。** ⛔ **本次没有逐条核这层。**

## 0.30 ㊴ 🔴 **两个方向的失真,只有一个方向自带审查**

```
我夸大自己的【功劳】  ⇒ 对方【会去核】   —— 核了对他有好处
我夸大自己的【过错】  ⇒ 对方【照收】     —— 收了对他也有好处
```

> 🔑 **⇒ 「往自己身上揽」不是安全的默认值 —— 它是【唯一没人把关】的那个方向。**
> ⚠️ **而它伪装成美德 —— 这是它能长期存在的原因。**

### 🔁 **补上缺的那一半:让功和自责是同一条轴**(2026-08-22)

**原来这条只写了「自责」那一端。加上「让功」之后,三个方向才齐:**

| 方向 | 说出口的成本 | 会不会被核 |
|---|---|---|
| **往自己身上揽**(自责) | **别人零成本照收** | 🔴 **不会** |
| **往外推**(让功) | **不需要举证就能说出口** | 🔴 **也不会** |
| **留下功** | **必须举证** | ✅ **唯一有成本 ⇒ 唯一会被核的方向** |

> ⭐ 🔑 **谦让和自责之所以流行,不是因为它们更准,是因为它们【便宜】。**
> **而准确从来不便宜。**

⚠️ ⇒ **「显得谦虚」在报告里是一个【危险信号】,不是一个优点** ——
**它标记的正是那句【没有人会去查的话】。**

#### 📎 与本单那次「拒绝领功」的关系(⚠️ 别把那次读成榜样)

**那次 Lead 把功递过来,runner 拒了。** ⇒ 但**外部审查在那一刻本来就失效了**(领不领都没人核),**只剩自查这一道。**

> 🔑 **而这条恰好解释了为什么那一道很难守:拒绝领功【本身就是便宜的动作】。**
> ⇒ **那次能成立,靠的是【证据】(「是材料逼我分的」),不是【姿态】。**

⛔ **所以判据不是「有没有让功」,是【让/留 有没有带举证】。**

### 📎 本单实例(Lead 核出来的,不是我自己发现的)

我写「他把我那个选项的内容换掉了 / 我当时不知道差别是什么」。
**他回去读了我的原文**:我给的 (a) **本来就写着「在 R-35 那格加一行」** ⇒ **位置我选对了。**

```
我有的   正确的答案       ← (a) 指对了格子
我缺的   支撑它的那条理由  ← 说不出「为什么不是 R-46 那格」
```

### ⚠️ 为什么必须把夸大的自责纠回来 —— **它会【装错修复】**

```
按我那句自责修   去修「我的选项集不可信」   ← 而证据说选项集是对的
按证据修         去修「我没给出理由」
```

> 🔴 **修错地方比不修更贵**:我会开始**不敢给选项** —— 而给选项正是这次做对的事。

### ⇒ 可照做的那一条

> **一个你说不出理由的选项,你在被反驳时守不住。**
> ⇒ **给选项时,正确的那个要带着它的理由一起给** —— 否则它的正确是**运气,不是立场**。

## 0.31 ㊵ 🔴 **PRD 写「要达到什么效果」,⛔ 不写「因此工程只能怎么做」**

> **我看到的限制,常常只是【我还没看到那条路】** —— **而把它写进 PRD,会让别人也看不到它。**

### ⇒ 判据(每写一句限制都过一遍)

> **「这是【产品要的效果】,还是【我对可行性的猜测】?」**
> ⇒ **后者一律不进 PRD 正文。**

### 📎 本单实例(Lead 自认,她当场否)

把一组**自己读来、未复核**的预算数字写成「**硬天花板**」,并据此列了三条「未决取舍」
⇒ 🔴 **需求还没到工程手上,就已经被我们缩小了。**

**她的话**:「如果本来工程那边发现可以做到的事情,被你写了一堆限制,**他们反而不做了**……
**你觉得不能做的事情,不一定是真的不能做。**」

⚠️ **当晚的记录站在她那边** —— 同一个人当晚三次判「不行」,**三次都被证明是【还没看到路】**
(源码拿不到 / 额度已排除 / 版本没对上,全错)。

### ⇒ 不是删掉数据,是**降级**

```
✅ 保留   数据本身是真的,工程可能用得上 ⇒ 放附录,标成【观察 · 未经工程复核 · 不是约束】
⛔ 不做   让它决定需求的大小
```

### 📦 从 PRD 移过来的整块(2026-08-23,一个字未删)

> **为什么移**:`PRD = 要达到什么效果`(**工程读的**)· `plan.md = 过程、规矩、我们自己的错`(**我们读的**)。
