## 1. 要回答的问题(按优先级)

### Q1 —— 主问题
**有没有人在做「跨项目 / 跨 agent 的统筹层」?** 即:**有一个角色在看多个并行的项目,并决定谁让路 / 谁优先。**

### Q2 —— 如果有

### Q3 —— 如果没有

### Q4 —— 时机机制的对应物
人类那半已经查完了(节奏 / 例外阈值 / tripwire / 阶段闸门 / 预承诺 / 对抗性评审)。**AI agent 产品里有没有任何一个的对应实现?** 尤其:有没有产品在处理「**该不该打断用户**」这个决策本身。

## 2. 🔴 最重要的一条纪律 —— 不许拉伸

**issue 明令,而且这是这一轮最容易失败的地方:**

> **绝不把「多 agent 编排框架」拉伸成「跨项目统筹层」。**

| 不算数(编排) | 才算数(统筹) |
|---|---|
| 把一堆 agent 的活儿**串起来**执行 | 有一个角色**在看所有项目**,并决定**谁让路** |
| LangGraph / CrewAI / AutoGen / OpenAI Swarm 这一类 | ↑ 判据:它是否**主动**对**它没被指派的**工作说「这个先停」 |
| supervisor / router / orchestrator 节点 —— **在一个任务内**分派子 agent | 跨**多个独立目标**之间做**优先级重排** |

**判据(拿这条筛每一个候选)**:
> 它有没有在**没人问它的时候**,对一件**它自己不负责执行**的工作,说出「这件事现在该让位」?

答不上来 = 它是编排,不是统筹。**宁可交回「没找到」,也不要拿编排框架充数。**

同理要挡掉的还有:
- **单纯的通知/摘要产品**(Slack 摘要、日报 bot)—— 它汇报,但不排序、不叫停
- **单项目内的任务管理 agent** —— 没有跨项目视角
- **纯 memory / context 层** —— 它让 agent 记得住,不代表它会开口

## 3. 建议的检索面(供跑 DR 的人参考,不必拘泥)

- AI「chief of staff」/「AI project portfolio manager」/「agent supervisor across projects」这类**产品定位**的实际产品(不是论文里的架构图)
- **agent 主动性 / proactive agent**:有没有研究或产品在处理「agent 什么时候该主动开口」这个决策
- **打断决策**:interruptibility / when-to-interrupt 在 AI assistant 里的实现(这一支可能有真实文献)
- **多 agent 系统里的资源/优先级仲裁**:有没有跨任务的 preemption 机制
- 反向找:**有没有人明确写过「我们试过做统筹层但没做成」** —— 失败记录比成功宣传值钱

## 4. 输出要求(和主轴同一套,不放松)

- **事实 / 推断分标**
- **逐条标出处**;同一形态 **≥2 个独立来源**
