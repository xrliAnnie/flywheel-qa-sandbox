## 1. Annie 真正在问什么

她的原话里,钥匙是这一句:

> 「做提醒的话可能有很多形状嘛……一种就是最简单的比如说**每周定时它去 review 一下我们整个的项目**……另外一种可能就需要它**比较智能一点,能够在正确的节点来给我正确的提醒**。那这个说实话我现在还没有想好要怎么样去做。」

她**不是**在问「要不要主动提醒」—— 那个她已经倾向 B(会提醒)。她卡住的是**形状**:

- **节奏型**(每周固定 review → 汇总)—— 简单、可预期、但可能报的都是废话
- **择时型**(在正确的节点给正确的提醒)—— 理想、但「怎么知道现在是正确的节点」没有答案

这是一个**触发条件设计**问题,不是一个「要不要」问题。

### 她自己给的三条线索(逐字)

1. **现在的 agent 怎么做** —— 「不知道有没有人在做一个类似的方向,那他们怎么去做的」
2. **参考人类社会** —— 一个 director「他可能也会在 some point 去说 ok,A team 的东西这个东西可能暂时不做了,然后我们要去 prioritize 其他的东西,**所以他是有这个能动性的**」;她想知道「人类社会它是用**什么样的制度**来确保说我们能够在做正确的 prioritization」
3. **hierarchy 本身也可以参考** —— 「我们这个总管有点像是最上面的一个 maybe director 或者是真正的 chief of staff」

她自己把 ② 和 ③ 连起来了:**同一套「人类机构如何组织与排序」的知识,既回答提醒形状,也回答层级形状。**

### 2.2 真正的空白:**时机**这一维

FLY-1045 问的是「**谁**有权决定、**谁**该知道、**怎么**学会」。
FLY-1854 问的是「**什么时候**开口」。

这是不同的问题。FLY-1045 里唯一擦到边的是那句 WBR 结论 —— 「if every team has a standard review object **and exception thresholds**」—— 但它把 exception threshold 当成一个待补的实现细节带过去了,**没有展开「人类机构到底怎么设这些阈值」**。

而这恰恰是 Annie 卡住的地方。所以 FLY-1854 的重心应该压在:

- 人类机构的**固定节奏**都有哪些真实形态,各自解决什么、代价是什么
- 人类机构的**事件触发**(tripwire / exception / kill criteria)怎么设、谁来设、什么时候失效
- 两者的**混合**怎么做(几乎所有真实机构都是混的,不是二选一)
- **打断本身的代价** —— 这一维在 FLY-1045 里完全没有(告警疲劳、注意力残留)

### 2.3 FLY-942《Watchdog + Lead 主动汇报》— 相邻但不同 🟡

FLY-942 已经收敛完(PRD 全 converged)。它做的是**机器层面的故障兜底**:runner 卡死了、Lead 压着没 relay、30min 超时才 @Annie。

**边界要划清楚**:942 报的是「机器坏了」,1854 问的是「方向该转了」。前者有客观真值(pane 卡没卡死),后者没有 —— 「A team 该让路了」不存在一个可以被检测的 ground truth。**这个差别决定了 942 的那套阈值方法论不能直接搬过来**,是本研究要说清的一件事。

### 2.4 FLY-1410 / FLY-1704《夜间研究 → 早报》— 节奏型的一个已落地实例 🟢

已有 PRD + UI 方向。它就是「每天固定时间产出一份汇总」这个形状的具体实现。**可以当作节奏型的本地样本引用** —— 我们不是没试过节奏型,我们试过了,而且它的经验教训应该进这份研究。

## 3. 我打算怎么切这个问题

### 主轴:时机机制(节奏 vs 触发)

不按「机构类型」切(那样会变成组织学罗列),按**触发条件的类型**切:

1. **纯日历节奏** —— 周会、月度、季度评审、年度规划。问:它靠什么保证「到点了真有话说」?
2. **节奏 + 例外过滤** —— management by exception、预算差异分析、WBR 的 exception threshold。问:阈值谁定、多久重定一次?
3. **预设触发器(tripwire)** —— 事先写死「一旦 X 发生就重新开会」。问:谁写、写在什么时候写、为什么人类需要**提前**写?
4. **阶段闸门(stage-gate)** —— 到某个里程碑强制做 go/kill 决策。问:它和日历节奏的关键区别是什么?
5. **资源闸** —— 预算/人头的重新分配本身构成打断。问:没有预算的机构靠什么替代?

每一类都要答同一组问题:**解决什么 / 代价是什么 / 什么时候失效 / 它假设了人有什么**(FLY-1045 传下来的筛子)。

### 副轴之一:能动性从哪来(她点名的那句)

「director 是有这个能动性的」—— 一个不直接干活的人,凭什么可以说「A 先停一停」?

FLY-1045 答了**授权形态**(Type 1/2、七档、advice process),但没答**这种角色的权力来源**。要补的是:chief of staff / chief strategy officer / PMO 这类角色的实证文献 —— 他们的权力是**借来的**(borrowed authority),这带来什么后果、怎么防止变成瞎指挥。

### 副轴之二:层级形状

FLY-1045 已给了骨架(中层=压缩器、span 无魔法数、holacracy 证据混杂)。这里只补**具体的减层案例与其代价**,给她的 hierarchy 二选一提供外部参照 —— **不替她拍**。

### 副轴之三:有没有人在做类似的 agent ⚠️

她自己列的第 ① 条。issue 里已经预判「这一轴很可能是薄的」。

**我的处理原则**:查到什么写什么,查不到就明写查不到。**缺席证据也是证据** —— 如果 2026 年 8 月还没有人做「跨项目的 agent 统筹层」,那这件事本身就是给她的信息(要么是没人需要,要么是没人做得出来,要么是我们在前面)。绝不为了凑内容而把「多 agent 编排框架」拉伸成「跨项目统筹层」—— 那是两回事。

## 4. 显式假设(便于 Annie 直接否决)

1. **假设她要的是「形状清单 + 每个的代价」,不是「推荐一个」。** issue 里写死了不给结论,我按这个做。
2. **假设「正确的时刻」不存在客观真值。** 和 FLY-942 的机器故障不同,「该转向了」没有 ground truth,所以任何机制都是在**误报**(打扰了不该打扰)和**漏报**(该提醒没提醒)之间选点。我会把每个形状放在这条轴上,而不是问「哪个更准」。
3. **假设 founder 注意力是被打断的那一方**,所以「打断的代价」必须被量化进来(FLY-1045 没做这一维)。
4. **假设人类机构的证据要过「它假设了人有什么」这道筛子** —— 沿用 FLY-1045 的方法,凡是依赖薪酬/晋升/职业焦虑/社会声誉的,标注出来。
5. **假设 doc-only。** 不改代码、不动配置、不设计我们的方案、不替她拍 hierarchy。

## 5. 证据纪律(issue 里的硬要求,写下来自查)
