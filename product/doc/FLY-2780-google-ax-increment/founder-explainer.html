谷歌开源的 AX —— 我们能借什么

FLY-2780 · 2026-09-22 · 只看 7 月之后的增量 · 细节在 research.md

一句话结论

谷歌把「让闲着的 agent 腾出机器」这件事做成了能力,但没做成自动的 —— 什么时候该让它睡,谷歌也是留给上层自己判断的。
所以对我们有用的不是它的代码,是这句:「等你审核的那段时间,该由我们自己来决定不留活进程。」

顺带三件事:①它确实开源了(Apache-2.0),7 月那个没核实的问号可以销账; ②「几十亿 agent」是传播时拧出来的,谷歌自己写的是「数亿个注册」;③网上的吐槽站得住脚。

1 · AX 是什么(30 秒)

一个「派活给 AI agent 的调度台」。你写一个 YAML 描述一份活儿,一条命令交上去,它替你把这份活儿 关进一个隔离的盒子里跑,并且能随时看进度。它一共只有四个概念:

它的概念管什么我们有没有
活儿 Task一份隔离的、带内存上限的、随时能丢掉的工作有(就是我们的 runner),但我们没有上限和隔离
工位 Workspace提前把代码仓库、工具、技能包摆好,agent 一上来就是热的有(worktree + CLAUDE.md + skill)
闸门 Gateway只允许它连白名单上的网站没有,也不太需要
模型配置 Model用哪个模型、什么参数、密钥放哪,全集群改一处有,而且我们的更贴身
要跑起来它,你得先有一整套谷歌式的服务器集群(Kubernetes)加镜像仓库加 Redis。 我们是一台 Mac。不可能直接用 —— 这跟 7 月的结论一样,没变。

2 · ⭐ 你最关心的那句话,哪半句是真的

帖子说:「闲着的 agent 会被存档挂起,等模型回话、等工具、等人工审批的时候把算力让出来,恢复不到一秒。」

这半句真假依据
能把进程连同内存整个存下来、再原样恢复,不到一秒真机制写在架构文档里,恢复速度是他们自报的口径
闲着就会自动被挂起假我翻了控制台全部代码:没有任何计时器。「按闲置时长自动回收」还躺在他们的「以后可能做」清单里
等人工审批时会自动让出算力假更空:他们把「要不要人批」这个配置项从接口里删掉了,只留了个「有一件待批」的空格子,代码里从没被填过
我觉得这才是最值钱的发现:连谷歌都没敢把「什么时候该睡」自动化 —— 因为通用的「闲置检测」很难判准。而我们这里有一个百分百准的闲置点:卡发给你的那一刻起, 到你回复为止,那个 runner 什么都不做。这是别人没有、我们独有的条件。

3 · 这件事在我们这儿值多少(刚在你机器上量的)

但它的真正价值在「时间」不在「一时的 GB」 —— FLY-2769 已经用 0.38 GB 钉了将近 20 小时。 等得越久省得越多;卡答得快,本来就没什么可省。
顺带查到一件让人松口气的事:另外 15 张等你按 ship 的卡,持卡的 runner 全都已经退出了,一个都不占内存。 所以这个毛病今天只出在「审阅卡」这一种上。

4 · 三条路,我推荐第一条

✅ 我推荐:发出卡之后,不留活进程。
把「进程在等你」改成「记录在等你」:卡发出去 runner 就退出,内存全还给系统;你回复了,再把它拉起来。
为什么选它:这是唯一不用换操作系统就能把「停在卡上那部分」还回去的做法。 它省的是上一节那个数 —— 停在卡上的 runner,此刻约 0.38 GB;Lead 的 4.65 GB 它碰不到。 值不值得做,看的是「卡平均要等多久」,不是一时的 GB 数。
怎么「拉起来」有两条路(我上一版只写了第一条,漏了第二条):
① 照着进度账本重来一遍 —— 上下文是新的,但要重读一堆东西;
② 按会话号直接续上(claude --resume / Codex 的 resume)—— 对话本身就存在磁盘上,拉起来便宜得多。这条在你这台 Mac 上就能走,不用搬去 Linux。
两条各有取舍(②便宜但把旧上下文一起接回来),选哪条已经单开在 FLY-2782,这里不展开。
共同的代价:都不是「不到一秒」那种恢复。
  • ⚠️ 中间方案:只冻结不关掉。把进程按暂停键,CPU 归零 —— 但内存还占着,上一节那笔钱一分也拿不回来。如果第一条太贵,这是个便宜的半步。
  • ⛔ 不建议:照抄谷歌那种「存档恢复」。那套技术只在 Linux 上有。要拿到它,得把所有 runner 从你的 Mac 搬进 Linux 容器 —— 那是整台机器的架构改造,不是「借一个点」。
另外三样明确不建议借:它的网络白名单、它让 agent 自己开子 agent 的那套树、以及整个集群层。对单机是纯负担。

5 · 你问的另外两件事,短答

「一句话描述环境、让 agent 自己装工具链」有用吗 → 用处很小。 它确实存在(工位上可以写一句「把 Go 工具链装好」,首次启动时让一个 agent 去装)。 但它解决的是「一个空白盒子怎么变成能干活的环境」—— 我们没这个问题,工具链就在你机器上, 而且我们现在是确定性的脚本,拿它换成让 agent 去猜,是往下走。

网上的吐槽成立吗 → 成立,但要分开看。吐槽的是「说自己很轻,实际要先搭一整套集群」—— 这点它自己的说明书就写着,不用辩。不过底下那一层(Substrate)确实是通用的, 甚至有个现成的 demo 就是三个 Claude Code 挤在两台机器上轮流跑。吐槽打中的是上面那层。
