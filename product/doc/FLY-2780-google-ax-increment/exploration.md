## 这一单到底在问什么

founder 2026-09-22 晚在 #flywheel-product 转了一篇小红书帖（noteId `6ab1034b000000003400d6d0`，作者 Borgle），
标题「谷歌开源 Agent 编排器 AX，可跑几十亿 Agent」，要求派 runner 研究「有没有什么值得学习的地方」。

关键约束：**2026-07-27 我们已经研究过 Agent Substrate 的一部分**，本单只做增量。

7 月那次的结论（Lead 记忆，当时已对照 Google 官方博客核实）：
- Agent Substrate 开源、建在 K8s 之上，核心洞察是「agent 大部分时间在空闲，不该占着昂贵的控制面」。
- 我们**不能直接采用** —— 它是 K8s 原生，我们的 runner 是单台 Mac 上的 tmux 进程。
- 能借的是**原则**：空闲就挂起 + checkpoint、不占热资源、按需快速恢复。
- 当时 **AX（Agent Executor）是否开源未核实** —— 第三方说开源了，Google 自己的帖子没说。

## 所以增量只有五格

| # | 增量问题 | 为什么它是增量 |
|---|---|---|
| 1 | AX 确认开源了吗？什么 license？ | 7 月明确标为「未核实」，是唯一一个挂在账上的悬而未决项 |

| 4 | generative workspace 对我们有没有用？ | 7 月完全没涉及，是 AX 这一层独有的东西 |
| 5 | HN 的质疑（庞大栈、不低侵入）成不成立？ | 帖子里有，需要一手复核 |

## 为什么第 3 条被标成 ⭐

我们的 runner 在等 founder 审核卡的时候，进程是**活着**的 —— 它什么都不做，但整份内存被钉死。
FLY-2769 的 runner 到 2026-09-22 晚已经等了 15 小时以上。这跟 Substrate 那句
「agent 大部分时间在空闲，不该占着昂贵的控制面」是同一个病，只是我们的「昂贵控制面」是 Annie 的那台 48 GB Mac。

「空闲 runner 占资源」与 FLY-1893（codex-homes 回收）同属资源侧。

## 取证口径（本单自我约束）

- **小红书只是影子。** 决定能不能用的前提只存在于原始出处 —— GitHub 仓库、Google 官方博客、HN 原帖。
  凡是只在二手媒体/帖子里出现、一手来源查不到的说法，一律标成「未证实」而不是写成结论。
- 断「某功能存在/不存在」只看 proto、源码、架构文档；媒体转述和 demo README 的宣传句只算现象。
- 涉及我们自己的数量级（内存占用），用本机实测，不用估。
