**禁止**手写 lorem ipsum、禁止编造条目、禁止改写任何 `what` / `why` / `relation` / `borrow` / `code` 的文字内容。

> ⚠️ 唯一允许的文本加工：方向 A/B/C/D 都需要一个「标题式论断」。
> 它**不新写**，一律来自既有 `why` 字段。
>
> **🔴 但「取首句当标题」会丢字 —— 实测 13 条深读里有 8 条的 `why` 是多句的。**
> 所以规则不是"截取"，是**切分**：
>
> ```js
> splitLead(why) -> { lead, rest }   // lead = 导语; rest = 剩下的原文
> ```
> **导语的精确定义**（不是笼统的「第一句」）：
> **第一个在 markdown 标记外结束的句子**；若整段以 `**加粗论断**` 开头，
> 则**整个加粗跨度**算导语 —— 即使跨度里不止一句。
> （当前数据里 `paperclipai/paperclip` 就是这种。这是刻意的：那一整跨度是作者自己
> 划出来的「一句话论断」，从中间切开会切断 `**` 配对，星号会印到页面上。）
> **标题 = `lead`，正文接着写 `rest`。两段拼起来逐字等于原 `why`，一个字不丢、也不重复。**
> 这正好是 Import AI 的形状（加粗引导句 + 同段继续）。
> `rest` 为空（单句 `why`，如全部 6 条 X）时正文自然不显示，也没有丢失。
>
> **自检合同统一写在 §2「构建期硬断言」**（A 层：`lead + rest === why` 逐字相等）。
> 这里不另立一套 —— 两处各写一套规则正是会互相打架的来源。

## 2. 四个方向共同遵守的约束（来自 research.md §3）

这四条是**研究结论**，不是我的偏好，四个方向都必须满足；差异只在 §3 的四种摆法。

| 约束 | 具体取值 | 依据 |
|---|---|---|
| **零字段名** | 页面上 `这是什么 / 为什么值得你看 / 跟我们什么关系 / 哪里能借鉴` 作为**独立标签**出现次数 = 0 | 四个参考物全为 0；v8 实测 74 个 |
| **零卡片边框** | 条目之间靠留白 + 细线分隔，不用 `border` 围一圈 | 同上 |
| **窄正文栏** | 正文栏 **540–580px @ 15.5px** ⇒ **34–37 汉字/行** | 参考物 355–435px 是**西文**值；中文全角，按字数折算取 34–37 字/行 |
| **单一视觉入口** | 每条有且只有一个最重的元素（标题/论断），其余降级 | 四个参考物共同点 |

**验收方式 —— 🔴 必须防「换个 class 名就假通过」**：

v8 版 `measure.js` 是按 v8 的 class（`.row .k` / `.card`）写死的。
拿它去量新 mockup 会**必然拿到 0**（新页面根本没有 `.row .k`），那是**假绿**，不是通过。

所以生成器**必须发出稳定的测量锚点**，与 class 名和方向无关：

| 锚点 | 打在哪 | 用途 |
|---|---|---|
| `data-fw-item` | 每一个条目的根元素（24 个，含浅扫和 X） | 遍历**全部**条目，取最差值而不是第一个 |
| `data-fw-prose` | 每个条目里**最长的那段正文** | 量真实行宽（不会量到页头文案或隐藏内容） |
| `data-fw-label` | 任何**独立字段名**（如果还有的话） | 目标是全页 **0 个**；靠锚点而不是靠 class 猜 |

改写后的 `measure.js` 必须：

0. 🔴 **双模式，且把模式打印出来。** v8 没有新锚点（它是 `.row .k` / `.card` / `.row .v`）。
   脚本先探 `document.querySelector('[data-fw-item]')`：
   有 → `mode: "anchor"`；没有 → `mode: "legacy-v8"`，回落到 v8 选择器。
   **输出里必带 `mode` 字段** —— 否则「新脚本量 v8 拿到 0」这种假绿看不出来。
   两种模式下 `itemCount` 都必须 > 0，为 0 直接报 `MEASURE_FAILED: no items found`（**不许静默返回 0**）。
1. `labelCount` = 全页 `[data-fw-label]` 数量 **＋** 一条**与模式无关**的兜底扫描：
   任何元素的 `textContent.trim()` **完全等于** `这是什么 / 为什么值得你看 / 跟我们什么关系 /
   哪里能借鉴 / 为什么没深入` 之一，且该元素**没有子元素**（叶子节点）。
   **两条都要为 0** —— 兜底那条防的正是"换个 class 继续放字段名"，且它在 v8 上必须能量出 74 才算尺子是准的。
2. 🔴 **量之前先 `expandAll()`**：把所有 `<details>` 设 `open`、所有手风琴展开
   （方向 D 的正文默认全在收起的展开区里，不展开会拿到 **0 个样本**然后"通过"）。
   `expandAll()` 后**逐条目**断言：**每个** `[data-fw-item]` 内部恰好有 **1 个可见的** `[data-fw-prose]`。
   （只查总数相等挡不住"这条 2 个、那条 0 个"的假绿。）任一条不满足就
   `MEASURE_FAILED: item <key> has N visible prose`。展开态量出来的才是"她读的时候"的真实行宽。
3. `cjkPerLine` = 对**所有** `[data-fw-prose]` 取值，报 **min / median / max**，不是第一个。
4. `boxedPerItem` = 对**每个** `[data-fw-item]` 统计带边框或非白底的元素数，**含条目根元素自身**，报 **max**。
5. 🔴 **`fullyBoxedItems` 单独一项**：条目根元素**四边都有可见边框**的条数。
   `boxedPerItem ≤ 3` 挡不住"每条都围一圈"（一圈只算 1 个），
   所以「零卡片边框」必须由这一项独立验收：**必须 = 0**。
   单边分隔线（只有 `border-top` 或 `border-bottom`）和方向 D 的斑马底色**不算**，是允许的。

**门槛**：`mode` 如实 · `labelCount = 0`（两条都是）· `cjkPerLine.max ≤ 40` ·
`boxedPerItem.max ≤ 3` · **`fullyBoxedItems = 0`** · `visibleProseCount = itemCount`。

**四个方向 + v8 用同一份脚本跑**（v8 走 legacy 模式），数字并排放进对比页 ——
Annie 直接看到「v8: 74 个字段名 / 46 字每行 / 9 个框」vs 各方向的值。同一把尺子才有可比性。

> **尺子自检**：新脚本在 v8 上必须复现旧脚本那组数（74 / 46 / 9 / 10.9 屏）。
> **复现不了就是尺子坏了，不是 v8 变好了** —— 先修尺子再量 mockup。

### 内容完整性（不许偷偷丢东西）

**🔴 数据集不是同构的 —— 一共 24 条，三种形状。** 这是实测（`node -e` 数出来的）：

| 类型 | 条数 | 独有字段 | 没有的字段 |
|---|---|---|---|
| **GH 深读** | **13** | `code`（我读了源码） | — |
| **GH 浅扫** | **5** | `no_code_reason`（为什么没深入） | ❌ 无 `why` `relation` `borrow` `code` |
| **X** | **6** | `summary_cn`（中文小总结）· `quote`（原推摘录）· `author` · `views` | ❌ 无 `code` `lang` `stars_today` |

**四个方向都必须渲染全部三种，不许只做深读那一种。** 逐字段去处：

| 字段 | 属于 | A 电报 | B 简报 | C 杂志 | D 工作台 |
|---|---|---|---|---|---|
| `lead`(=why 首句) | 深读·X | 导语（粗） | 论断标题 | 标题 | 行内一句话结论 |
| `rest`(=why 余下) | 深读 | 正文续写 | 正文续写 | 展开区 | 展开区 |
| `what` | **全部三种** | 正文 | 正文 | 正文/展开 | 展开区 |
| `relation` `borrow` | 深读·X | 行内加粗引导句 | 行内加粗引导句 | 展开区 | 展开区 |
| `code` | 深读 | `▸` 折叠 | 弱容器正文段 | 头条展开·其余折叠 | 展开区 |
| **`no_code_reason`** | **浅扫** | 正文（灰、轻） | 正文（灰、轻） | 清单项展开 | 展开区 |
| **`summary_cn`** | **X** | **主正文**（她 v7 明确要它在最上面） | **主正文**（论断标题之下第一段） | 同 B | 展开区第一段 |
| **`quote`** | **X** | `▸ 看原推` 折叠 | 折叠 | 折叠 | 展开区折叠 |
| `author` `views` `url` | X | 元数据行 | 左栏 | 元数据行 | 表格列 |
| `stars_today` `lang` | GH | 元数据行 | 左栏 | 元数据行 | 表格列 |
| `check` + `check_note` | 全部 | 行内小字 | 左栏 + 脚注 | 脚注 | 表格列 + 展开区 |
| 编号 | 全部 | ✅ | ✅ | ✅ | ✅ |
| 备注框（可 copy paste） | 全部 | ✅ | ✅ | ✅ | ✅ |
| 「复制我写的全部备注」 | 页级 | ✅ | ✅ | ✅ | ✅ |
| `scan`（底数）· `cross_finding` · `x.blocked_banner` · `x.summary` | 页级 | ✅ 页顶 | ✅ 页顶 | ✅ 页顶 | ✅ 页顶 |
| **`x.tone`**（⚠️ 营销号密度高、6 条都只扫了没核） | X 分区级 | ✅ X 分区标题下 | ✅ | ✅ | ✅ X 筛选行下 |

> 🔴 `x.tone` 是**诚实声明**（「标记如实写成『只扫了』，不是『可信』」），
> 跟底数面板同级 —— **四个方向都必须显示，不许当装饰删掉。**
> 它属于 X 分区，不属于任何单条，所以放在 X 区块的开头。

**浅扫 5 条的处理原则**：v8 明写「没读代码，因为跟我们无关」—— 这条**诚实标注不许丢**，
但它们视觉上必须**明显更轻**（不然 5 条无关项和 13 条深读项等重，等于稀释）。
四个方向都把它们收成一个次级区块。

**构建期硬断言**（写进 `build-mockups.mjs`，失败即 `process.exit(1)`）：

🔴 **不能拿原始字符串直接 `html.includes(field)`** —— 数据里大量字段含 `**加粗**` 和 `<名字>`，
经 `rich()`（`**x**`→`<strong>`）+ HTML 转义（`<`→`&lt;`）+ `stripTags` 之后
**已经不逐字等于原文了**。直接比会**误红**；反过来，只在整页文本里找又会**假绿**
（`scanned` 这种重复值，全页出现一次就能替所有条目蒙混过关）。

所以是**两层、按条目**：

```
normalize(s) = stripTags(rich(esc(s)))      // 原文和渲染结果走同一条管道
```

1. **A 层（精确）**：`splitLead(why)` 断言 `lead + rest === why`（原始字符串逐字相等，不经管道）。
2. **B 层（逐条目）**：把 HTML 按 `data-fw-item="<key>"` **切成 24 段**，
   对**每一条**断言：该条**散文字段**的 `normalize(值)` 出现在**它自己那一段**里。

   🔴 **`key` 必须是派生的 —— 18 条 GitHub 没有 `id` 字段**（只有 X 有）。定义：
   ```
   itemKey(it) = it.id ? `x:${it.id}` : `gh:${it.repo}`
   ```
   构建时断言这 24 个 key **两两不重复**，否则切段会串。

   🔴 **只断言散文字段，不是"每个非空字段"** —— `depth` / `check` / `stars_today` / `lang` / `views`
   是**显示时会重排的**（`scanned`→`⚪只扫了`、`1148`→`+1,148 星`、`15924`→`15.9k 浏览`），
   拿原值去比会**必然误红**。散文白名单按类型：

   | 类型 | 断言这些字段 |
   |---|---|
   | GH 深读 | `repo` `code` `what` **`lead`** **`rest`** `relation` `borrow` `check_note` |
   | GH 浅扫 | `repo` `what` `no_code_reason` `check_note` |
   | X | `author` `quote` `what` **`lead`** **`rest`** `relation` `borrow` `check_note` `summary_cn` |

   🔴 **断的是 `lead` 和 `rest` 两个，不是整个 `why`。** 因为版式**故意**把它们放在不同位置
   （方向 D 尤其明显：`lead` 在表格行里、`rest` 在展开区），中间必然夹着别的 DOM 文本，
   拿整条 `why` 去找连续匹配会**必然误红**。
   `why` 的完整性由 **A 层**（`lead + rest === why` 逐字）保证 —— 那才是它该被验的地方。
   `rest` 为空（单句 `why`）时跳过该条断言。

   （`check_note` 可能是 `null`，非空才断言。`url` 单独断言出现在该段的某个 `href` 里。）
3. **页级字段**单独断言在页面里：`scan.*` / `cross_finding.title` / `cross_finding.body` /
   `x.blocked_banner` / `x.summary` / **`x.tone`**。
4. 断言报告打印 `24/24 items · N fields OK · 6 page-level OK`，
   任何一条失败就打印**是哪条 key、哪个字段**再 `exit(1)`。

**这两层才是「一段不丢」的证据，不是我的口头承诺。**

**备注框是 Annie v7 的明确要求，本单不擅自砍。** 四种摆法本身就是给她挑的一部分：
A = 一行「+ 备注」点开才展开 · B = 左栏一个铅笔图标点开 · C = 头条常驻/清单项点开 · D = 行尾图标，有内容则点亮。
**持久化一律 `localStorage`**（同 v8），页面明写「存在你这台机器上」。

## 3. 四个方向的规格

> 📐 **屏数一律指整页 24 条（含浅扫 5 + X 6）在 1280×900 下的实测总高**，不是某个分区。
> 计划里写的是**目标**；实测值以 `measure.js` 的 `screensAt900` 为准，**实测数字进对比页，达不到就照实写**。

### 方向 A — 「电报」Wire
> 赌：**扫得快**。学 TLDR。

- 单栏 560px。无 tab —— 三个分区各一行小标题：
  `⌘ GitHub 深读 13` / `⌘ GitHub 只扫了 5` / `𝕏 For you 6`。
- **深读条** = `①` 轻编号（大号、浅色、衬线）+ **仓库名即链接**（粗体 + 下划线）+ 同行尾部灰色小字
  `+1,148 · TypeScript · ✅核过`。
  下面**只有一段**：`lead`（粗）→ `rest` → `what` → 然后 `relation` / `borrow` 以
  **行内加粗引导句**续写（`**跟我们的关系 ——** …` / `**能借的 ——** …`），全在**同一段落流**里。
  `code` 收进 `▸ 我读到的代码`（`<details>`，默认收起）。
- **浅扫条**（次级区块，字号小一档、整体降透明度）= 编号 + 仓库名链接 + `what` + `no_code_reason`（灰）。
  无折叠区（本来就没有 `code`）。
- **X 条** = 编号 + `lead`（粗，即 `why`）+ `@author · 15,924 次浏览 · ⚪只扫了` +
  **`summary_cn` 做主正文**（Annie v7 硬要求：中文总结在最上面）→ `what` → 加粗引导句 `relation` / `borrow`。
  `quote` 收进 `▸ 看原推`（含 `url` 链接）。
- 备注：条末一行浅灰 `+ 备注`，点开变 textarea。
- 目标：**整页 ≤ 5 屏**（v8 是 10.9 屏）。

### 方向 B — 「简报」Briefing
> 赌：**读的时候不被打断**。学 Linear（左栏元数据）+ Import AI（加粗引导句）。

- 两栏：左 **150px** 固定元数据栏｜右 **560px** 正文栏，中间 40px 沟。
- 左栏（从上到下）：大号浅色编号 · 类型相关的量（GH: `+1,148 星` / `TypeScript`；X: `@author` / `15,924 浏览`）
  · `✅ 核过原物` · 一个铅笔图标（备注入口）。
- 右栏**一个字段名都没有**：
  1. **加粗论断标题** = `lead`（不是 repo 名 —— repo 名/推文链接做标题下方的链接行）
  2. 接着 `rest`（`why` 的余下原文）
  3. 正文段 = `what`；**X 条在这之前先放 `summary_cn`**（她要中文总结在上）
  4. 灰底细排的代码观察段 = `code`（唯一保留的弱容器，因为它是"我亲自读了"的证据）
  5. `**这跟我们的关系 ——** …` + `relation`
  6. `**能借的 ——** …` + `borrow`
- **浅扫条**：同样两栏，但右栏只有 repo 链接标题 + `what` + `no_code_reason`（灰）；
  整条降一档字号 + 降透明度，归入「只扫了没深入」次级区块。
- **X 条**：`quote` 收进 `▸ 看原推`。
- 条目之间：**一条 1px 细线 + 48px 留白**，无边框。
- ≤900px 宽塌成单栏（左栏元数据变成标题下的一行小字）。

### 方向 C — 「杂志」Magazine
> 赌：**替她做减法**。学 NextDraft。

- **三级分层，覆盖全部 24 条**：
  - **头条 1 条**（从 13 条深读里选）：大号中文标题（`lead`）+ `rest` + 完整内容全部展开。占近一屏。
  - **要闻 3 条**（深读）：中等标题（`lead`）+ `rest` + `what` + `relation` 直接可见，
    `code` / `borrow` 折叠。
  - **其余 20 条**（9 条深读 + 5 条浅扫 + 6 条 X）：紧凑清单，每条一行标题 + 一句话，
    **点开就地展开该类型的完整内容**（深读给全部字段、浅扫给 `no_code_reason`、X 给 `summary_cn` + `quote`）。
    清单内部按 `GitHub 深读 / GitHub 只扫了 / X` 三段分节，段间一行小标题。
