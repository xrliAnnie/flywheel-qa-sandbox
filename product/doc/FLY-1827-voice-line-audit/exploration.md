## 2. 一开始就存在的一个判断:什么算「PRD」

这单最容易糊弄的地方是把 **EPIC 描述当 PRD**。

采取的判据:**有没有成文的问题定义 / 用户 / 目标 / 非目标 / 需求 / 成功指标 / 交互规格。**
按这条:

- FLY-906 → **是** PRD(42KB、v0.17、Annie 2026-07-06 APPROVED、10 轮共创、段落齐全)
- FLY-1451 语音总管 → **不是** PRD(只有 EPIC 描述 + 一棵 7 块 topic 树,自述「共创中,尚未拆单」)

这条判据后来被证明是这单最有价值的产出之一 —— 因为它把「我们有 PRD」和「**我们有的是哪一个世界的 PRD**」分开了。

## 4. 三个方向性的发现(不是结论,是现状)

### 4.1 「我们有 PRD」这句话是有歧义的

FLY-906 那份 PRD 是**真的、你批过的、段落齐全的**,但它锁的三条里**至少两条已被推翻,而 PRD 从没更新**:

| PRD 锁的 | 后来变成 | PRD 更新了吗 |
|---|---|---|
| 命令名 `/meet`(R10 亲自锁定) | 代码里是 `/glaw` | **没有** |
| per-Lead 独立声线 = **硬需求**(§17) | 2026-07-21 co-eval 砍成「单声 + 身份报头」 | **没有** |

→ 它不能直接当今天的施工图,要先对一遍哪些还算数。

### 4.2 建了很多,但今天全是休眠的

三个 package(voice-core 65 / voice-bridge 106 / voice-headphone 16 源文件)全在 main,
四条管线里只有 `/gemini` 过了 founder 真机验收。

**今天(2026-08-17)**:无 launchd job、无进程、9878 无响应、`projects.json` 无 `huddle` 块(fail-closed)。
→ 重新用起来不是「打开开关」,是要重新接一遍线。

### 4.3 她描述的那个「跨项目 CoS」的位置,今天确实是空的

实测 `~/.flywheel/projects.json`:**6 个项目 / 16 个 Lead / 只有 3 个 CoS,而且每个只管一个项目**;
growth / joycon-typeless / personal-assistant 三个项目**根本没有 CoS**。
唯一跨项目的 surface 是 `#leads-roundtable` —— **一个让 Lead 互相说话的房间,不是一个掌握全局的角色**。

→ 这是**结构性印证,不是方向建议**。陈述那个位置是空的,不等于建议去填它。

## 6. 这一单自己犯过的错(留档,因为它们是同一类)

三次自我更正,全部同一个病:**把上游/近似物当权威,没自己复核**。

1. **轮 1**:更正了我 7/23 给她的「V3 = GPT-Live 全双工」这个等号 —— 那是我自己加的,原报告没这么说。
2. **轮 4 补录**:我引用原报告说「不能把 version 与 voice 隔离」——**报告这句是错的,我照抄了**。
   E1 vs D3 同一 voice、只差 version,已经隔离了。
3. **随后被 FLY-1844 纠回**:E1/D3 **隔离了 version 但没隔离 transport** ——
   两次都固定 websocket,而 websocket 对 v1 和 v3 都是错的路。
   **我把「除 X 外都相同」当成了「除 X 外都受控」,而共同固定的那个值本身就是错的。**

**沉淀出的两条通则**(已写进 runner 记忆):

- **读错误消息要读「它要求什么」,不是只读「它拒绝了什么」** ——
  E1 那句 `Quicksilver sessions require WebRTC.` 一直在告诉我们真因,被读成了「v1 特有的怪癖」。
- **新发现抽掉某任务的动机时,必须显式宣告动机作废**,不能只更新结论 —— 因为下游读的是任务,不是结论。
