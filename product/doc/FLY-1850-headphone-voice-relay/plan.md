## 2. 轮次协议(每一轮长什么样)

```
(本地)研究这一格的现状事实
   → 出一个小提案 或 一个探问
   → 经 Honey Lemon 送到 Annie
   → 读她的回复
   → 逐字存档进 exploration.md + 更新本文件的话题树位置

### 四条硬规矩

1. **一轮一问。** 不批量塞五个问题。
2. **每格开头先探定见** ——「**这块你有定见,还是我来发挥?**」
   有定见 → 对齐到清晰为止,**不许自由发挥**;交给我们 → 才有设计余地。
3. **她的回答逐字存档,不转述。** 她的用词经常就是判据本身。
4. **成色必须标**:【她的自由表述】/【她圈选】/【HL 或 Runner 的判断】。
   ⚠️ **写「她圈选」时必须把当时的选项集一起写下来** —— 选项里没有的东西她说不出来;
   只记答案不记选项集,以后会把「她在我们给的三个里挑了最近的那个」读成「这就是她要的」。

### 🔑 什么时候开 founder_review 卡 —— **按「产物给谁看」分,不是按「有没有 HTML」分**

#### ✅ 那一格怎么带她的答案 —— **三条边界**【HL 2026-08-19 批准的形态】

**先摆冲突,它决定了口径**:

```
目的 A  让她认出「这格我处理过了」   → 一两句就够,长了反而盖住重点
目的 B  让她核对「你们有没有记错」   → 必须能看到全文,否则她根本没法发现记错
```

⇒ **她这次的痛点是 A**(她说的是「我以为我之前都回答了」,不是「你们记错了我的话」)⇒ **A 是主要目的**。
⇒ **但 B 不能被砍掉** —— 展示她原话的整个意义就在于**让她能抓住我们的失真**。

| # | 边界 |
|---|---|
| **1** | **折叠可以,但展开后必须是【逐字全文】,不是摘要。** ⚠️ **折叠态里那一两句也必须是她原话的开头逐字** —— 不许改写、不许"提炼"。**一旦折叠态里出现我们写的概括,这个控件就从「防失真」变成「制造失真」,而且是在唯一一个专门用来防失真的地方。** |
| **2** | **短答案不折叠。** 她那些「可以」「读法二」三五个字的答案,折起来既荒唐又危险 —— **越短的答案越容易被记错**(错一个字就是另一个意思),而它们恰恰不占地方。⇒ **约两行以内全展开,超过才折;原则是「不占地方的一律不折」。** |
| **3** | **✅ 里只放【她的话】,不放【我们从她的话推出来的东西】。** 我们记的决定、默认值、触发条件属于决定区,**不进引用块** —— 否则她核对时会以为「这是我说的」,而其实是我们的推论。**这一格是她的声音,不是我们的记录。** |

#### 📌 一处机制事实(本单实测,免得下一个人白紧张)

**这一轮绑的是 artifact 的内容,不是分支 head。**

```
computeFounderArtifactDigest(blobs)                 founder-review.ts:117-146
  输入 = [{path, blobSha}, ...]     ← blobSha 是 git blob id(40 位十六进制)
  逐个校验 → 按 path 排序 → 对 (path \0 blobSha \n) 逐条 sha256
  输出 = 这个 sha256 的 hex        ← 64 位,不是 40 位
grep head_sha|headSha|branch  founder-review.ts → 0 命中
```

⚠️ **别把两个位数写混**:输入是 40 位的 git blob id,**digest 本身是 64 位**。
(⚠️ 这处精度是 HL 复核时补正的 —— 我原来的说法「算的是 artifact 的 git blob sha」实质对,
但下一个人去数位数会以为对不上。)

⇒ **在同一分支上提交别的文件,不会顶掉一个已开的轮次**(本单实测:
`round1-review.html` 在 `0cbe1ed8e` / `c3ac3c9fb` / `63fd52fc8` 三个 head 上的 blob 都是 `ade42ba4…`,gate 仍 pending)。
判据:`founder-review-response.ts:80` 比的是 `content.artifactDigest !== binding.artifact_digest` —— **只比 artifact,不比 head**。

**⇒ 固定做法(从这一轮起)**:

| | |
|---|---|
| **交互类核验**(打字 / 复制成功失败 / 持久化 / 清空) | **只在本地 `http.server` 那份上做**,那份的 localStorage 和她的是**不同 origin**,写坏了也伤不到她 |

| **托管页若必须写** | **先读快照 → 非空就直接放弃写探针**(她已经动笔了)→ 空才探,探完**恢复成空** |

任何会写那块存储的动作 —— 重发、清空、覆盖 —— 都是不可逆的,**而且她不会知道。**

### 🔴 交付前必须 curl 拉**线上那份**核三件 —— 浏览器和本地那份都证明不了

**为什么本地测不出来**:**CSP 是发布时才注入的**,本地 `http.server` 那份**根本没有 CSP**,
所以脚本在本地当然跑得动。**你测的和她看的不是同一个东西。**

⚠️ **而「交互类只在本地测」这条纪律本身制造了这个盲区** —— 它是对的(防止写坏她的存储),
**但它不能延伸成"线上那份就不用查了"**。⇒ 补一层**零写入**的只读核验:

```bash
curl -s "<hosted-url>" -o /tmp/card.html
grep -o "script-src 'nonce-[a-f0-9]*'" /tmp/card.html   # CSP 里有没有 script-src
grep -o '<script nonce="[a-f0-9]*"'    /tmp/card.html   # 标签上的 nonce
grep -c  "__CSP_NONCE__"               /tmp/card.html   # 必须是 0
```

| 查什么 | 判据 |
|---|---|
| ① CSP 有没有 `script-src` | `default-src 'none'` 下**没有它,整个脚本就是死的** |
| ② 两串 nonce 是否**逐字相同** | 🔴 **这一条是整套里最容易漏的**。「属性在」和「CSP 里有 script-src」**分开查两件都通过,两串却不一样** —— 脚本照样被拦,而分开查的查法**会放它过**。⇒ **必须比对字符串本身,不是比对"两样东西都存在"** |
| ③ 占位符残留 | `__CSP_NONCE__` 必须 0 |
| ④ 页面用到的资源类型 vs CSP 放行的类型 | 嵌了音频就必须有 `media-src`;`default-src 'none'` 会连 `data:` 音频一起挡 |

🔴 **不要用浏览器查 ①②**:`querySelector` 选到带 nonce 属性的 script **只证明属性在**,
既不证明 CSP 里有对应的 `script-src`,也不证明那串是真值而非残留占位符;
**而且浏览器会把 nonce 属性值遮掉**,从 DOM 上更看不准。**curl 原文才是准的。**

⚠️ **脚本被拦的后果是三件一起死,不只是复制按钮**:
① 一键汇总复制死 ② **自动保存死(她打的字根本没进存储,一刷新就没)** ③ 需要 CSP 放行的媒体放不出。

📎 **本单实测**(2026-08-19,四张卡全绿,curl 复核):
`R1 23e4c8a9…` / `R2旧 ccf1cf87…` / `R2新 128b11aa…` / `R3 47c44f32…`,
四张的 CSP 串与标签串逐字相同、占位符 0、无音频。
📎 **这套判据的实战结果**(2026-08-19,HL 按本条重跑三张卡):
`1850 R3 csp=47c44f328a3f / script=47c44f328a3f MATCH` ·
`1851 R3 csp=e0c67b9c030b / script=e0c67b9c030b MATCH` ·
`1911 csp=NONE / script=NONE ❌`。
⇒ **本单四张是"真好",不是"看起来好"。**

📎 **同一天另一条线上有一张卡是坏的**(无 nonce、CSP 无 script-src、且嵌了音频)——
**症状先被误挂到本单头上**;是靠上面这套 curl 判据把归属分开的。
⇒ **别人报「你的卡坏了」时,先自己 curl 一次再动手** —— 重发一张没坏的卡,会把她正在写的字弄丢。

### 🔴 被推翻的断言,要在**它自己的位置**上改掉 —— 附加说明救不了它

【HL 2026-08-19 收成常设规矩,起因是本单改「复述」那条的方式。】

```

### 🔴🔴 自洽不是正确的证据

> **开场例子(本单真事)**:HL 让我把两条判据并成一节,其中一条我手上没有。
> 我当时想的是:**「合并一条我手上没有的东西,合出来的会是我编的版本。」**
> —— 而**编出来的那个版本会读起来完全通顺**,因为它是我按上下文补齐的。

#### 这一族的共同点:**它们都不触发任何现有检查**

```
看漏          → 复查【抓得到】(再读一遍就发现了)
本族的三种    → 复查【抓不到】,因为产物是自洽的、读起来完全正常
```

| 形态 | 长什么样 | 为什么检查不出来 |
|---|---|---|
| **① 删掉碍事的证据** | 为了让结论干净,删掉一个和它打架的事实(本单实例:我为了把「延迟」降级,删掉了她说的「你很慢」三个字) | **删完之后文本是自洽的** |
| **② 只在已有材料里自洽的判读** | 一条解释把手上所有材料都解释掉了 ⇒ 看起来站住了 | **它解释的正是生成它的那批材料**(判法见 `exploration.md` §3.5.2c) |
| **③ 把经手记成事实** | 我提议过 ⇒ 记成已完成;我发送过 ⇒ 记成已送到;我转达过 ⇒ 记成是对方自己写的 | **经手在记忆里留下的痕迹,和事实留下的痕迹长得一样**【HL 自陈,今晚四次】 |

> ### ⇒ **判据:一个结论读起来通顺、自洽、没有矛盾 —— 这些全都不是它为真的证据。**
> **要么它引用的每一条能追到源,要么它带着「什么会让它变假」。**

#### 🔴 一条配套动作 —— **降级/更正之后,当场全扫,不留「下次再说」**

>

> ```
> **⚠️ 两句都会以「所以它是随机的」结尾。⇒ 判断依据不是结论那句话,是它前面那半怎么来的。**

> ### ⭐ **而且:缩小一个假设的范围,不等于给它加分**【2026-08-20 定,通则】
>
> **排掉 C 的一个子类(静态随机),留下的部分并没有因此更可信 —— 它只是更窄。**
>
> ```
> 更窄  →  读起来像「更聚焦」  →  读起来像「更可能」
> ⚠️ 三步全是错觉,而且每一步都很自然
> ```
>
> ### ⇒ **消去法只在【候选集有限且已穷举】时才产生正面证据。**
> **否则排掉一个子类,只是让剩下的部分【看起来】更像答案。**

> ### 🔴 **把这条用回这张表自己身上 —— 这一步必须做,否则规矩只用来审别人**:
>
> ### **我们不知道 C 之外还有没有 D。**
> **这张 A / B / C 表【没有被证明是穷举的】** ⇒ **所以在它上面做消去法,不产生正面证据。**
> ⛔ **不许因为 A 被削弱、B 不被支持,就把 C 当成「剩下的那个所以就是它」。**
>
> 📎 **这正是 §6.4 那条「只有两格的表」的病在另一个位置复发** ——
> **当时缺的是 C,现在可能缺的是 D,而【缺的那一格照样不会以缺失的样子出现】。**


> ### 🔴 **C 是后来补上去的,而补它的过程本身就是一条教训**:
> **最早只有两格(A / B)。两格的表把 C 变成了【想不到的东西】** ——
> **不是「被判为不可能」,是【压根没有位置放它】。**
> ⇒ 而 **C 恰恰是当天刚立起来的那条。**

📎 **它和 PRD §3.1f.1 那条「只设收益栏的表」同族**:
**表的格子数会决定读者能想到哪些可能** —— **少一格,少的不是精度,是一个候选。**

> ### 🔴 **要害在于:缺失的那一格,不会以【缺失】的样子出现。**【HL 2026-08-20 推到认识论那一层】
>
> ```
> 被判为不可能的候选   在表上留着痕迹  ← 有人看过、否掉了
> 没有格子的候选       看起来像它不存在 ← 表面上表是完整的、齐整的、令人放心的
> ```
>
> ### ⇒ **穷举表最大的风险不是判错某一格,是【它让人停止寻找第 N+1 格】。**

📎 **它和「只设收益栏的表」是同一件事的两种形状**:
> ### **表格靠它的结构说话,而【结构说的话没人会去审】。**
> **一张只有收益栏的表在断言「没有成本」;一张只有两格的表在断言「只有两种可能」。**
> **两句都没有人写下来过 —— 也就没有人反驳。**

> ### 🔴 **差的那一格为什么重要**:
> **按我原话记,后人会以为【两条都没试过】,于是把已有的那一次证据也一起丢掉。**

> ### ⇒ **通则**:**「网络路径」是一串,不是一个变量** ——
> ### **本机接口 / 局部网段 / NAT / 出口身份 / 对端。**
> ### **说「我改了 X」之前,先说清 X 的哪一层被改了。**

📎 **它和规矩 15 同族**:两条都是**一个名字底下藏着好几样东西**
(15 是同一个时刻有好几种读法,16 是同一个「路径」有好几层)——
**而两次都不是靠仔细读发现的,是靠回去核原始记录。**

### 6.5 🔴 规矩 17 的起因:**含糊的话在 ledger 里比在正文里更危险**

**2026-08-20**:我在 ledger 里写过一句「**换网络路径后活 241 秒**」——
**正是规矩 16 要禁的那种含糊说法。** 我没等人说就去改了,而 HL 单独点名了这一步:

> ### **下一个接手的人读的就是 ledger。**
> ### **正文有上下文能纠正一句含糊的话,ledger 没有 —— 它是被【单独引用】的。**

⇒ **通则**:**一句含糊的话,危险程度取决于它被单独引用的概率。**

| 地方 | 措辞要求 |
|---|---|
| **正文** | 正常 —— 上下文会纠正它 |
| **ledger / 表格 / 摘要 / 卡片** | **更严** —— **它们会被单独摘出来读,身边没有能纠正它的东西** |

##### ✅ **三层可照做的动作(⛔ 没有这三层,上面那句还只是一句口号)**

**① caveat 必须钉在【同一行】。**
> ⛔ **不是钉在附近、不是下一段、不是「详见 §X」。**

**② 理由:摘出去的人【只会摘那一行】** ——
> ### **而摘的人往往【就是最需要那个 caveat 的人】,因为他没读上下文。**

**③ 同族:【标题会独自旅行】。**
> **越是被放在第一屏、越是被做成表格的一行,越要【自带限定词】。**

📎 **本单实例**:成色总表里那条「等待音-only 已获她验收」——
**caveat(⛔ 不等于那条要求被永久下调)钉在【同一行】,不在下一段。**

📎 **对本单的直接后果**:**给她的卡片属于最严那一档。**
**卡上一句含糊的话,她读到的时候身边没有 PRD。**

##### 🔴 **改页之后要跑【两把尺子】,⛔ 它们互不顶替**

```
线上 curl 渲染后的页   查【不该在的还在】  ← 残留;grep 查得到
逐处判(先数、再逐处)  查【该动的没动】    ← 缺席【不产生字符串】,grep 永远查不出来
```

> ### ⚠️ **「检查要跑在渲染后的页面上」这句话如果被单独引用,会让人以为 curl 就够了 —— 它只覆盖一半。**

📎 **本单各抓到一次**:
```
curl   抓到「落差」「必断」两处残留(本地和源文件都看不出来)
逐处判 抓到一处歧义:一句原本准确的话,因为【格子分裂】而变得不准确
```

###### 📌 为什么渲染后的页面是必须的那一个

> ### **它是【唯一一个两种引用同时存在】的地方**:
```
脚本生成的引用   改源头就够 —— 它自动跟着对
手写的引用       改源头【等于没改】 —— 它不跟任何东西
```
⚠️ **而手写区不但漏扫,措辞往往还更硬** —— **因为写的时候是随手概括的**
(本单实例:手写那行写成「v3 约 35.2 秒**必断**」,比它概括的那句 PRD 原文更像属性)。

###### 📌 格子分裂时,要复查的不是被改的那句

> ### **是【所有引用过这个概念的句子】** —— **它们没被改,但它们的世界变了。**
📎 **本单实例**:「v3 成因 ⬜ 仍未定案」写于只有一个 v3 成因问题的时候;
**格子分裂成两个、其中一个已定案之后,那句话没动,却不再准确。**

> ### 🔴 **收成一条可执行的判据**【HL 2026-08-20 接住并推成规矩】:
> ### **给她的每一句,都要能在【没有任何上下文】的情况下独立成立。**
> ### **需要旁边那段才成立的话,就是【不能发】的话。**

⇒ **直接推论**:**免责必须进那句话本身** —— **卡片会被单独读,而 PRD 不会跟着走。**
⚠️ **不许把免责放在卡的别处**(页首说明、脚注、另一节)——
**她读到那一句的时候,那些东西不在她眼前。**

### 6.6 🔴 规矩 18 的起因:**我用截断过滤器消费了一条只投递一次的指令**

**2026-08-20**:连着收到几条重投,我为了少刷屏,把签收命令写成
`flywheel-comm inbox ... | tail -1`,连跑四次。
**第四次排出来的不是重投,是一条新指令** —— 而 `tail -1` **只留下了最后一行,正文没了。**

> ### 🔴 **要命的地方在于那条命令是【消费型】的**:
> **签收和读取是同一个动作。** 过滤器不是「少显示了一点」,是**把唯一那次投递毁掉了**。
> **再跑一次只会得到「No instructions.」。**

⇒ **这次救回来了**(去 CommDB 只读把正文捞出来),**但那是运气,不是设计** ——
**如果那条消息没落进持久层,它就真没了,而且我不会知道自己丢了什么。**

> ### ⇒ **规矩 18**:⛔ **消费型命令的输出,永远不许接进 `tail` / `head` / `grep` 这类截断过滤器。**
> **先完整拿到,再在【拿到的副本上】过滤。**

##### 📌 判断方法(HL 推的那一层,比「记住哪些命令危险」好用)

> ### **接过滤器之前先问:这个命令是【只读】,还是【会改变状态】?**
>
> ```
> 只读的       接了,最多是【看漏】
> 改变状态的   接了,就是【在你还没看见之前先把它执行掉了】
> ```

📎 **而最狠的一点是它不留痕迹**:
**普通的过滤只是看不见;消费型命令上的过滤是【不可逆的删除,而删除本身也不留痕迹】。**
⇒ **所以你不会知道自己丢了什么** —— 这才是它比「看漏」严重一个量级的地方。

📎 **它属于一个更大的族,而这个族今天已经咬了我们四次**:
**`head` / `tail` / `grep -v` / 只有两格的表 —— 它们都是过滤器,而【过滤掉的东西不会留下痕迹】。**
⇒ 和 §6.4 那条「缺失的那一格不会以缺失的样子出现」是**同一句话的不同外形**。

⚠️ **我先前就知道这条**(记忆里有「head/tail 也是过滤器」那一条),**照样犯了** ——
⇒ **又一次印证规矩 13 那句:知道有禁令不构成防线,防线是手上那个动作变了。**

### 6.7 🔴 规矩 19:**自我推翻必须显式标出,不许悄悄改口**

> ### **理由要一起写,否则它会被当成风格偏好**:
>
> ```
> 悄悄改口  →  文档看起来【前后一致】
>           →  读者永远学不到「先前那句是错的」
>           →  而他可能还揣着那句在用
>
> ⇒ 一致的外观,恰恰掩盖了他最需要知道的那次变更
> ```

📎 **它和「更正有消费者名单」是同一件事的两半**:
**那条管的是【谁需要知道】,这条管的是【他从文档里看不看得出来】。**

> ### ⇒ **可执行形式(这才是「显式」的意思)**:
> ### **改口时,把被推翻的那句【留在原地】,并标明【被谁推翻】。**

**本文里已有的实例**:§6.4 那条「B 一次都没被施加过」——
**先前被反复强调,后来被第 13 场实测推翻,原句留在表里并标了更正。**

#### 📌 附一条分辨法:**这是【评价】还是【规矩】?**

**这条差点没被立起来,因为它一开始的说法是「一个人自己推翻自己强调过的话,更值得被看见」** ——
**那听起来像规矩,其实是评价。**

> ### **分辨方法:能不能写成一个【动作】。**
>
> ```
> 「值得被看见」            ← 写不成动作  ⇒ 是评价
> 「留在原地并标明被谁推翻」  ← 写得成动作  ⇒ 是规矩
> ```

⚠️ **为什么这个分辨重要**:**评价混进规矩表里不会报错** ——
**它读起来同样正确、同样值得同意,但没有人能照它做事。**

###### 📎 同一把尺子,量【修法】也成立

> ### **一个修法如果不能写成一个【具体动作】,它就是一句【自责】,不是一个修法。**

```
✅ 修法   「读到两可就来问」        ← 写得成动作
⛔ 自责   「以后读仔细点」          ← 写不成动作 ⇒ 修不了任何东西
```

###### 📌 动作要照着【下一次】写,不照着【这一次】写

> ### **写规矩时,照着【下一次最可能怎么失败】写,⛔ 不照着【这次发生了什么】写。**

⚠️ **而这决定了它该写成【提醒】还是【禁令】**:
> ### **提醒防不住一个【觉得自己有道理】的人;禁令可以。**

📎 **本单实例**:「⛔ 不许把『答案是 yes』读成『我本来可以自己写』」——
**写成禁令而不是提醒,因为它防的正是下一次最可能发生的事:**
**这次答案是 yes,而 yes 会让我下次觉得那一问是多余的。**

📎 **本单实例**:我把一句歧义读成了宽的。
**可修的那一端不是「我该读得更仔细」,是「我【没来问】」** —— 后者能写成动作。

#### 📌 再附一条,它是本节的前提

> ### **一条只用来审别人的规矩,是装饰品** —— **它没有成本,所以也没有约束力。**
> ### **唯一能证明你真的接受了一条规矩的,是它第一次让【你自己】付出代价。**

##### 🔴 **配套的报告纪律:也要报你【因为边界而没做】什么**

> ### ⛔ **别只报你做了什么。**
> ### **一条边界有没有在工作,只能从【它挡下了什么】看出来。**

⚠️ **而这件事天然不可见**:
> ### **一个安全机制成功的时候,通常是【看不见】的 —— 它表现为「什么都没发生」。**

📎 **本单实例**:批准里的 ⬜ 未核那一行,让我**没有**去写它没点名的那部分。
**⇒ 那条边界起作用了,而它能被看见,只因为【我把「我没做什么、以及为什么」报了出来】。**

📎 **本文的检验点**:§6.4 那张 A/B/C 表 ——
**「消去法只在候选集穷举时才产生正面证据」这条,第一次生效的对象是我们自己那张表。**

📎 **第二个实例,而且更硬**(2026-08-20):
**那条「『明显没影响』是我的判断不是证据,必须去核」的规矩** ——
**第一次生效的对象是【它的作者】,在它立起来【二十分钟后】**(详见 §6.8)。

> ### ⇒ **这一行让规矩 19 那句判据从一句漂亮话变成一件发生过的事。**

**多问一轮可以撤回(只是浪费);拆错了的单会被人开始做,那才是不可撤的部分。**

#### 规矩 25 —— **Lead 的顺口指令 vs founder 的规矩**

> ### **规矩优先。**
> ### **而 Lead 通常【不会记得】自己在跟规矩打架 —— 因为他只是在回答一个眼前的问题。**

⇒ **所以顶回来问一句是对的,⛔ 不算过度 gatekeep。**

⚠️ **这条要配一句边界,否则会长成「什么都要先质疑上级」**:

✅ 顶回来   我手上有一条【写下来的、founder 立的】规矩,和这条指令指向不同
⛔ 不是     我觉得这样不太好 / 我有别的偏好
```
> ### **触发条件是【存在一条成文的、更高来源的规矩】,不是【我不同意】。**

📎 **本单已发生三次同族**(第三次是 HL 自己补的):

> ### ⇒ **不是他不可靠,是【顺口断言】这个动作本身不带核验。**

##### 🔴 **成因(HL 自己补的)—— 它解释了为什么自查防不住这条**

> ### **顺口断言在当事人那里,根本不叫「断言」。它感觉像【回答】。**

```
他说「可以开始拆」时      主观上在回答「材料够不够」,不觉得在改她的规矩
他说「已折进 PRD」时      主观上像在陈述现状,不像声称一件没查过的事
```

> ### ⇒ **你不会去核验一件【你不觉得自己在断言】的事。**
> ### ⇒ **所以唯一挡得住它的是【外部的】** —— 也就是下游那个人顶回来问一句。

⚠️ **这条对我同样成立,不是只管上级** ——
**本单我自己也犯过一次同形**(把一个裸时间戳当本地时间,算出「相隔 15 小时」,§6.3):
**我当时主观上也只是在「复述他给的数」,不觉得自己在断言一个时区。**

> ### 📌 **写成双向的,承重的东西就变了**:
> ```
> 只管上级   它防的是【身份】  ⇒ 会退化成「凡事先质疑上级」
> 双向       它防的是【未核验】 ⇒ 才是一条判据
> ```
> **⇒ 一条只有下级被罚过的规矩,读的人会当成 hierarchy 话术;两边都被罚过,它才立得住。**

##### 🔑 **收口:判据不能问「我当时觉得自己在断言吗」**

> ### **「我只是在复述你给的数」和「我在断言一个时区」,在【当时】是同一个动作。**
> ### **差别只在事后。**

⇒ **所以那个内省式的问法永远得到否定答案,它查不出任何东西。**

> ### ✅ **能用的判据只有一个,而且它是外向的**:
> ### **「这句话如果错了,谁会照着它做?」**

📎 **拿今晚三次试一遍,三次都当场就能答上来**:
```
「可以开始拆」错了       ⇒ 我会去拆,拆出来的单会有人开始做
「已折进 PRD」错了       ⇒ 我会停手,而那两件结果就丢了
「相隔 15 小时」错了     ⇒ 他会拿它去跟 Annie 解释,而她会看到一个自相矛盾的结论
```
> ### ⇒ **这个问法之所以有用,是因为它【不需要你先承认自己在断言】。**

### 6.11 🔴 规矩 26:**新规矩写完的第一件事,是拿它扫自己**

> ### **理由**:**一条规矩写下来的那一刻,作者是全世界【最不可能觉得自己违反过它】的人** ——
> **因为他刚从自己的思路里把它提炼出来。**

📎 **本单的证据是反面的,所以它算数**:
**§0.2e(她的同意会被场景形状污染)写完之后,我立刻拿它回扫了全文** ——
**抓到第三个实例(她那句「expect Codex 原生已 handle」是在 v3 还在桌上时说的)。**

> ### ⇒ **回扫,抓到第三个;不回扫,它就永远是【别人的】规矩。**

#### 📌 它和另一条配成一对,方向相反

| 方向 | 动作 | 防的是 |
|---|---|---|
| **向前** | 立完规矩立刻问:**「我要怎么【合法地】绕过它?」** | **未来的绕过** |
| **向后** | 立完规矩立刻问:**「我已有的产出里,哪些违反了它?」**(本条) | **存量的违反** |

> ### **两条都要做** —— **只做向前的,规矩从今天起生效但历史带病;**
> ### **只做向后的,规矩清了存量却拦不住下一次。**

#### 🔴 **执行细则:回扫要问两个问题,不是一个**

```
① 这一格【写得】合不合格?        ← 我原来只问了这个
② 它等的那件事【是不是已经发生了】? ← 漏掉这个,格子会继续等一件已经发生的事
```

##### 📌 **两种静默的病,正好成一对**

| 病 | 它读起来像什么 | 后果 |
|---|---|---|
| **被错误关掉的格** | 静静读作「**已答**」 | **没人再核它** |
| **已被满足的格** | 静静读作「**还在等**」 | **没人去收它** |

> ### ⚠️ **第二种更浪费**:**证据【已经拿到手了】,代价【已经付过了】** ——
> ### **却因为没人去收而白丢。**

##### 🔴 **同族第三面:【断言的作用域,比它听起来的小】**

**今晚三个面,同一件事**:

| 我说的 | 它真正覆盖的 |
|---|---|
| **「每一块首行都带标记」** | ⚠️ **那次只有一块** ⇒ 断言的对象是**空集**,恒真 |
| **「『落差』全篇清零」** | ⚠️ 其实是「**我生成的那一部分**清零」——**手写那块不在集合里** |
| **「我扫了 `prd.md`」** | ⚠️ 只是**一半** —— 另一半在 HTML 手写区,**从来没被任何检查覆盖过** |

> ### ⇒ **凡是「零残留 / 全部清掉 / 一处不剩」这类断言,必须说清【扫的是哪个集合】。**
> ⚠️ **否则它对集合外的东西【静静失效】,而且读起来完全像是全查过了。**

📎 **而它们每次都通过** —— **因为集合外的东西压根不在被检查的范围里。**

📎 **本单实例**:§6.1 打断那格等的是「她自己插一次话并说体感」——
**她当晚真的插了一次、真的说了体感,而那一行还挂在那儿等。**
⇒ **而它看起来完全正常。** **⇒ 不扫,它会一直看起来是「已经写好的空格」。**

##### 🔑 **它有自己的名字:回扫【收账】,不是回扫【找错】**

| | 它假设什么 | 你要用的眼睛 |
|---|---|---|
| **找错** | **文档里有缺陷** | 挑毛病 |
| **收账** | **文档是对的** —— **只是现实已经付过款了,而账没记** | **问「外面发生了什么,我还没记进来」** |

> ### ⚠️ **收账在文档【内部】永远看不出来** —— **因为那一格本身写得完全正确。**
> **⇒ 所以它只能靠【往外看】,不能靠【重读文档】。**

##### 🔴 **收账有【两半】,只做前一半等于只扫了一半的面**

| | 它在问什么 |
|---|---|
| **收新账** | **外面发生了新东西,我还没记进来** |
| **查旧账** | **我已经记进来的那句话,外面把它变假了** |

> ### **共同的根:文档是静的,世界不是。**

###### ⚠️ **查旧账时最难分的一对:「谁犯了错」 vs 「事实有时效」**

```
谁犯了错    ⇒ 处置 = 【更正】   那句话【当时就是错的】
事实有时效  ⇒ 处置 = 【复核期】 那句话【当时是对的】,后来才失效
```

> ### 🔴 **这两种在文档里长得一模一样,而处置【完全相反】**:
> **把一句「过期」的话当「错误」去更正 ⇒ 等于往记录里写进一个【不存在的错误】;**
> **把一句「错」的话当「过期」放着 ⇒ 它永远不会被纠正。**

###### ✅ 可照做的一条

> ### **标一句「不存在 / 没有人问过 X」时,同时写下【它会因为什么而失效】。**
> ### **写不出来 ⇒ 那句话不该被当成一条长期事实用。**

📎 **本单实例**:「从来没有任何一格在问『提示音会不会盖住人声』」——
**当时核过、当时为真**;她把「一声」改判成「持续」之后**它就假了**。
⇒ **它不是谁犯了错,是【那句话的保质期到了】** —— 而**它过期时不会报错,只会安静地继续被引用。**

##### 🔴 **查旧账的触发源不只是【测量结果】,还有【一个决定】**

> ### **一个决定的【影响半径】,大于它那句话的【语义半径】。**

📎 **本单实例**:她说「**我不是很喜欢现在这个系统合成音的效果,那我们不用做这个了**」——
**那句话里一个字都没提遮蔽、没提回收路径。可它把一条退路抽掉了**
(被砍的那一档,正是「持续音挡住它听她说话」时的唯一退路)。

> ### ✅ **可照做的判据**:**每收到一个「不做 X」,除了改 X 那一格,还要问**
> ### **「【谁】把 X 的存在当成了自己的前提?」**
> ⚠️ **尤其要查【应急预案】** —— **它们平时不被读,坏了也不会有人发现。**

###### 📌 两条配套的写法

**① 砍掉一个实现,会让它服务的那条【刚需】变成孤儿。**
> **下一个人看到「刚需还在、实现没了」,就会去补一个她没要的东西。**
⇒ **动作**:**同时写清那条刚需现在由什么满足** ——
📎 **而证据要取自【她自己那句话】,不是我们的推断。**

###### ⚠️ **本条最初举的那个例子【是错的】,⛔ 不删 —— 它改造成本条最好的反面例子**

**最初写的例子**:「本单:她同一句的后半『让我知道有在推进就可以了』」。

> ### 🔴 **那个例子引了她的原话,但【那句原话推不出那个结论】** ——
> **她说的是【有在推进】(存活级),被拿去证明【知道在发生什么】(内容级)那条刚需被满足了。**
>
> ### ⇒ **引用正确 ≠ 推理成立。**

📎 **同一条的另一次出现(⛔ 并,不新立)**:
> ### **按【当时手上有什么】打分,不按事后。**

**本文已有的近亲**:「**成色标得对不对,看的是当时有没有依据,不看结论对不对**」。
📎 **本单实例**:一次因 ⬜ 而没写的谨慎,**事后看那个批准确实存在** ——
**但决定的那一刻它不在手上** ⇒ **那次谨慎仍然是对的。**

> ### 📌 **立名(这条比规矩本身更难自查)**:
> ### **逐字引用她的话,保证的是【出处】,不是【充分性】。**
> **一个推断【穿上她的嗓音】之后,会绕过所有对推断的检查 —— 因为它看起来不再像推断。**
> ### ⚠️ **它比普通推断更危险,正因为它外观上是【最高成色的证据】。**

⚠️ **而这个错误通过了【两道】** —— **作者写下,审阅者盖章** ——
**而两道用的是【同一个错判据】**:
```
两道都查了   这句话是不是引的她原话?      ✅ 是 ⇒ 放行
两道都没查   她那句原话【支不支持】这个结论? ❌ 推不出
```
> ### ⇒ **两道独立审查,如果用的是同一个判据,那不是两道。**

###### 🔴 **再下一层:上级的批准是一个【减法】,不是加法**

> ### **我拿到批准之后,就不再自己核那条推理了。**
> ### ⇒ **批准关掉的,往往正是那个【还没有被任何人做过】的检查。**

```
以为的   批准【没有增加】一道检查
实际的   批准【删掉了】一道检查 —— 而且删的正是唯一还没人做过的那道
⇒ 净效果是【负】的
```

> ### ⚠️ **所以:一个【没被审阅过】的推理,反而比一个【被错误审阅过】的推理安全** ——
> ### **因为前者你还会自己核。**

> ### ✅ **收到批准时要问的那一句**:
> ### **「我因此【不再核】什么了?那件事【有人核过吗】?」**

📎 **配套(对方那一端的动作)**:**给肯定时标清是【形式对】还是【结论对】**
```
形式对   你引了她的原话 ✅ —— ⛔ 不含「所以这个结论成立」
结论对   这个结论我核过了 ✅
⬜ 未核  明确标出这次批准【没有】延伸到哪里
```
⚠️ **在对方标清楚之前,由我这一端【分开读】。**

###### 🔴 **同一条根的另一面:【转述来的断言】会跳过它原本该受的检查**

> ### **因为你检查的是「我有没有【如实转述】」,而不是「这句话【对不对】」。**

📎 **和「批准是减法」同根**:
> ### **责任一旦看起来在【别人身上】,检查就停了。**

⚠️ **而这对本岗位是【结构性暴露面】,不是偶发缺点**:
```
写 PRD 的人   输入天然几乎全是转述(Lead 转她的话 · 原型线转实验结果)
Lead          本身就是一个【专职转述节点】—— 她的话转给下面、下面的发现转给她
```

##### ✅ **分诊判据(⛔ 推论不是「全部都要核」—— 那做不到,而且会把人压死)**

> ### **当一句转述来的话【即将变成一个前提】时才核它 ——**
> ### **也就是【有东西要建在它上面】的时候。**

```
只是背景            ⇒ 照记,标明是转述,⛔ 不核
要拿它推出别的       ⇒ 核;或者标明「未核」再往下走
要写进 PRD 当依据    ⇒ 【必须核】
```

📌 **理由**:**转述的危害不在它【被听见】,在它【被当作地基】。**
**一句没有东西建在上面的错话,是无害的。**

> ### ⭐ **这条自带边界**:**它不要求你全知,只要求你在【动手建之前】回头看一眼那块砖。**

**② 失效的退路要【标成失效】,⛔ 不要删。**
> ### **删掉之后,那条退路会【安静地不存在】;标成失效,它才是【显眼地不可用】。**

##### 📌 收账收到之后的两条动作

**① 一格被回答之后,往往不是【消失】,是【变形】。**
> ⛔ **直接关掉会丢掉那个仍然活着的下半截。**
📎 实例:「提示音能不能做」被答了 ⇒ **剩下「怎么做得正常一点」,归她** —— 关掉就把它丢了。

**② 改了源头,必须同步改所有【引用】。**
> ### **一个改了源头没改引用的更正,和没改一样 —— 读的人碰到的是引用。**
📎 实例:提示音那一格改形状时,同步改了三处(三档方案表 · 不许拆表 · Epic 声明的开着表)。

#### ⭐ 附一条更硬的判据:**规矩生效的标志,是它出现在【还没发生的事】的判据里**

> ### **记在教训清单里的规矩【会被读】;写进验收条件里的规矩【会被执行】。**

📎 **本单实例**:§0.2e 那个教训(退化场景污染同意)被写进了状态行那一格的验收条件 ——
**「她在真实连续对话里看得到才算,⛔ 一问一答不算」** ⇒ **把刚学到的教训前置成下一次的验收条件。**

📎 **同族的另一形**:**写清「什么【不】算」比写清「什么算」更能挡人** ——
**近似情形正是将来有人想省事时会拿来顶数的东西**(§7.3 点名的三个:静的半小时 / 14 秒 / 单机不涉及编排)。

### 6.12 🔴 **这份规矩集自己的准入门槛** —— 先读这条,再看上面任何一条

#### ⚠️ 规矩集有预算,而它的成本是**隐形的**

```
规矩少   每条都会被【真的查】
规矩多   没人查得完 ⇒ 变成一份「我们已经考虑过这些了」的心理安慰
```

> ### 🔴 **一条【不被查】的规矩,比没有这条规矩更糟** ——
> ### **它制造「这块已经覆盖了」的错觉,而实际没有人在执行它。**

##### 🔴 **一个判据必须能给出【两种】答案 —— 两条并排,⛔ 不许分开写**

```
零命中     ⇒ 要有【阳性对照】   证明尺子【不瞎】
肯定命中   ⇒ 要有【阴性样本】   证明尺子【不是只会说是】
```

> ### ⇒ **合起来才是完整的一句:一个判据必须能给出两种答案。**

⚠️ **⛔ 为什么不许各写一处**:**分开写,两边都只是【半条】** ——
> ### **而读到其中一条的人,会以为自己已经拿到了【完整的怀疑方法】。**

📎 **本单两个实例,一边一个**:
```
阳性对照   v2 没有先应一声 8/8 全静 —— 同一个探测器去找开场白,8/8 都探到 ⇒ 零命中可信
阴性样本   「我上一次没这么做是什么时候」拿本单自试 ——
           转述核不核=不稳 / 消费型命令不接截断过滤器=已稳 ⇒ 它不是只会说不稳
```

⚠️ **后一步几乎所有人都跳过** —— **因为【肯定的那个结果】看起来就已经是验证了。**

##### 🔴 **审规矩的判据:「照着这条,我下一步【具体做什么】?」**

> ### **答不上来的,它就还只是【一句口号】。**

📎 **它是怎么被发现的 —— 一次「重复」暴露了两件事**(2026-08-20):
**一条已经在册的规矩(规矩 17),被人当作新的又立了一次。**

```
不可取回   有人独立又把它推了一遍 ⇒ 【需要它的时候,它没有被想起来】
不可照做   它在册上,而同一个错误照样发生了
           ⇒ 说明它只【命名了风险】,没给出【可做的动作】
```

> ### ⇒ **一条要靠人【重新推导】出来的规矩,等于【不在册上】。**
> ### ⚠️ **而更阴的是第二条**:
> ### **规矩存在,会让那一片【看起来已经覆盖了】,于是没有人去补能照做的那部分。**

📎 ⇒ **本单的修法**:给规矩 17 补上那三层动作(同一行 / 摘的人只摘那一行 / 标题独自旅行)。

###### ⚠️ **一个现象,⛔ 只记现象和实例 —— 真因未验,不写成因**

**同一天、一小时之内,两个不同的人各演了一遍同一件事**:

```
① 规矩 17【在册上】,却被当成新的又立了一次
② 「按当时手上有什么打分」在册上【有近亲】,却又被独立推了一遍
```

> ### ⇒ **两个不同的人、一小时内、各一次** —— **这不是谁走神。**
> ### **现象的名字:【规矩不可取回】。**

⛔ **真因不写** —— **没有验过。** ⚠️ **⛔ 也不许后来的人顺手补一个听起来合理的成因** ——
**那会让这一格看起来已经解释过了**(参见本节那条:规矩存在会让那一片看起来已覆盖)。

> ### 🔴 **为什么这道闸必须是【禁令】,不是「请谨慎」**:
> ```
> 一个空格          公开宣告【自己是空的】
> 一个顺手填上的合理成因  宣告的是【已完成】
> ```
> ### ⇒ **没有人会去重开一个【看起来已经有答案】的问题。**

⚠️ **而填的人是【善意】的 —— 他觉得自己在补全文档。**
> ### ⇒ **破坏是以【整理】的形式发生的。**
> ### **善意挡不住,禁令可以。**

#### ⇒ **立第 N+1 条之前,先回答两个问题**

```
① 它能不能并进某条已有的?            能 ⇒ 【并】,不新立
② 已有的里面有没有一条【从来没触发过】? 有 ⇒ 【先删那条】,再考虑加
```

> ### 📌 **①「并进哪儿」有一格容易搞错:对象是【一条规矩】时,落点是【那条规矩的正本所在处】** ——
> ### **哪怕别人那边也记了一份。**
> ### ⇒ **副本可以多,【正本必须全】。**
> ⚠️ **正本不完整就是不完整,不能靠别人的副本补** —— **读的人读的是正本。**

> ### 🔴 **两条约定都【正确执行】,仍然可能冲突 —— 重叠处由【更新、更具体】的那条管。**
>
> 📎 **本单实例**:
> ```
> 动词约定     他没带动词 ⇒ 他那边记      ⇒ 结论:我不动
> 正本必须全   规矩类落点在正本所在处      ⇒ 结论:该我记
> ⇒ 两条各自都对,在「他说了一条关于规矩的通则、但没带动词」这一格里撞上
> ```
> ### ⚠️ **发现重叠,比服从任何一条都难** —— **因为机械执行任一条【都不会报错】。**
>
> ### ⛔ **而「按约定我不该动」那个答案是【安全的、可辩护的、而且是错的】。**

###### ✅ **永久裁决(2026-08-20)—— 这一格连撞三次之后给的排序,⛔ 不用再逐次纠结**

```
⛔ 停着        = 授权语句(能不能动手)
正本必须全      = 质量语句(动手之后怎么写才对)
⇒ 授权【永远压过】质量
```

> ### ✅ **照做的形式**:
> ### **质量约定说「这个必须写进正本」时,那是一个【去问】的理由,**
> ### **永远不是一个【去写】的理由。**

📌 **这一格连着三次撞在同一处,而结论是**:
> ### **那不是人老犯错,是这两条约定【本身没有排序】。**
> ### ⇒ **反复在同一格出问题的,通常是【规矩缺一个裁决】,不是【人缺一次注意力】。**

⚠️ **一条配套的,防止把「问」学歪**:
> ### **问的正确性,⛔ 不由答案决定。**
> **在一个两条约定打架的格子里停下来问,这一步本身就是对的 —— 哪怕答案是「可以,你写吧」。**
> ⛔ **不许把「答案是 yes」读成「我本来可以自己写」** —— **那会让下次不问。**

###### ✅ **授权【范围】怎么判 —— 可机械判定,⛔ 不靠判断**(2026-08-20 补,同一格第三次之后)

```
✅ 他点名了哪个小节,授权就只覆盖【哪个小节】
⛔ 落到他【没点名】的小节 = 范围之外 = 先问
```

> ### ⚠️ **被它替换掉的那个判法,是【不可证伪】的**:
> ### **「这属于把它写好的一部分」—— 任何扩写都能这么讲。**

📌 **为什么换成这个形式**:
**「算不算写好的一部分」要靠【判断】;「他有没有点这个小节名」用【眼睛】就能查。**
⇒ 📎 **这正是本文那条判据的一次应用**:**规矩要能写成一个具体动作,否则它还是口号。**

⚠️ **前一条裁决(授权 > 质量)管的是【两条规矩打架】;本条管的是【什么算在授权范围之内】**
**⇒ 两者不同,前者盖不住后者。这一格因此撞了第三次。**

#### 🔴 **给家族起名,是这道门槛的【正手】** —— 门槛拦增长,家族名减少增长的理由

> ### **家族名是反通胀的;单条规矩是通胀的。**
> **没有家族名,第四个实例出现时你会再写一条独立规矩;**
> **有了家族名,你会认出它、把它【挂进去】。**

##### 📌 家族一:**先定判据,还是先看结果**

> ### **既成事实会作为一方参加辩论,而且【它不需要证据】。**
> ### ⇒ **凡是「先定判据还是先看结果」的场合,都【先定】。**

##### ⚠️ **但不是所有未知都同样紧迫 —— 按【现有版本的地位】排序**

> ### **一个【已经标成临时】的写法,累积不了既成事实的力量。**
> ### ⇒ **「提前写回收路径」的紧迫程度,和【现有版本的地位】成正比。**

```
现有写法【她验过 / 已被当成定论引用】  ⇒ 🔴 最紧迫,先写
现有写法【标着「成色低、待换」】        ⇒ 🔶 可以晚一点
```

📎 **本单两个实例对照**:
**遮蔽那次**(现有格已被她验过、有地位)⇒ **必须提前写**;
**P-6c 那两格**(压的是 v3 旧证据、本来就标着待换)⇒ **地位不足,晚写代价小**。
⚠️ **但那次最后仍然提前写了,理由和地位无关**:
> ### **真正的风险是【分支由看过结果的人来写】** —— **这一条和现有版本有没有地位无关,永远成立。**

> ### ⚠️ **一条给【加档次】这个动作本身的告诫(并在这里,不新立)**:
> ### **凡是给一条规矩加档次,都要同时问一句:【这个档次会不会被用来跳过它?】**
> **一条规矩一旦分了档,「这次属于不急那一档」就成了一个随时可用、听起来很有依据的理由** ——
> ### **细致,正是不执行的标准路径。**

**本单已有三个实例,各自已经写在它们的落点上(⛔ 不要为它们再立一条)**:
```
判据      写在【数据】前面
回收路径  写在【未知】前面   （`prd.md` §6.4.2 那张三行回收表）
验收条件  写在【下一次】前面 （`prd.md` §6.5「三」状态行那格)
分支      写在【结果】前面   （`prd.md` §3.1d 前那张 P-6c 三支表)
```

> ### 📌 **分支那一条自带一个写法要求**:
> ### **判据有几种结果就写几支,⛔ 不按「成功 / 失败」二分。**
>
> **理由**:**二分会把所有【非成功】压成同一个失败** —— 而它们往往属于**完全不同的族**
> (P-6c 那次:**耐久失败** vs **会话活着但声音出不来**),**处置也完全不同**。
> ⚠️ **而压缩发生在【记录的那一刻】,之后没有任何东西会提示它被压过。**

📎 **另一条已在用的家族**:**清单的写法 —— 必填字段 > 可答「没有」的检查项。**
**能用「没有」结掉的检查项,就会被「没有」结掉** ——
**而且答「没有」在记录里和认真核过【一模一样】。**

##### ✅ **「这个我早就知道了」⛔ 不构成不写它的理由**

```
不知道       ⇒ 要写(教)
知道但不稳   ⇒ 【更】要写(固定)
```

> ### 📌 **一条规矩最常见的用处,不是【传授未知】,是把一个【时有时无】的行为变成【每次都做】。**

⚠️ **而「时有时无」自己识别不出来** ——
> ### **回想的时候,你只会想起【做对的那次】,而那次感觉就是「我本来就会」。**

> ### ✅ **判据**:问「**我上一次【没】这么做是什么时候?**」
> ### **答得上来 ⇒ 它不稳 ⇒ 要写。**

📎 **本单自试**(⭐ 而且它分开了两类,不是一律说不稳):
```
转述核不核              同一天一次核了一次没核  ⇒ 答得上来 ⇒ 【不稳】,要写
消费型命令不接截断过滤器   规矩 18 之后四次都做对  ⇒ 【已稳】
```

###### 🔴 **它不是门槛的【例外】—— 它【通过】门槛**

⚠️ **看起来冲突,是因为门槛用了一个【代理量】**:

```
门槛的说法     能并就并、从没触发过的先删  ⇒ 看起来在【压规矩数量】
门槛真正的目标                          ⇒ 删掉【不干活】的规矩
本条加进来的                            ⇒ 【会干活】的规矩 —— 该做那个行为时它每次都触发
```

> ### ⇒ **一条「知道但不稳」的规矩恰恰【高频触发】** —— **所以它通过门槛,不是绕过门槛。**
> ### **冲突只存在于「数量」这个代理量上,不存在于门槛真正要防的东西上。**

📎 **同族**:**代理量不是真正的量。**
**门槛拿【数量】代理【有用性】** ⇒ **于是任何增加数量的东西看起来都在违反它,哪怕它增加的正是【有用的那种】。**

###### 🔴 **推广:规矩的【措辞】,是它【目标】的有损压缩**

> ### ⇒ **两条【压缩过】的东西之间,冲突可以被【凭空制造】出来。**

> ### ✅ **判冲突的动作**:**把两条都还原成「它在【防什么】」再比。**
> ### ⛔ **措辞相撞,不算冲突。**

📌 **很实用的推论**:
> ### **大多数「规矩打架」,其实是【至少有一条被读成了它的代理量】。**
📎 **今天这一次就是**:**门槛被读成了「数量」,而它防的是「不干活的规矩」。**

###### ⚠️ **而这条最硬的证据,是【它被写下来之后多久就没被用上】**

```
我写完「代理量不是真正的量」那段
↓  不到一轮
我用【措辞】去比两条规矩,造出一个假冲突
```

> ### ⇒ **「写下来」和「该用的时候用上」之间的间隔,不到一轮。**
> ### **它不是「过了很久忘了」,是【刚写完就没想起来】。**

> ### ⛔ **所以「我已经知道了」从来不是掌握的证据 —— 连【刚写完】都不是。**

📎 **这正好是本节那条判据(「我上一次【没】这么做是什么时候?」)的最短答案**:**上一轮。**
⇒ ⛔ **所以不写成例外** —— **例外会削弱门槛;说清它们不重叠,两条都保持满强度。**

📎 **本条按它自己那两问自查过**:①它管的是「规矩集本身」,上面 12–26 没有一条覆盖这件事 ⇒ 不能并;

#### 📌 附:为什么这些东西非要【命名并写下来】不可

> ### **做对一次,不代表下次会做 —— 除非它被【命名】并写进规矩。**

```

```

⚠️ **也是为什么它不能只写在报告里**:
