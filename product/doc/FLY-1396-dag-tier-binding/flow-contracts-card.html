产品部这三种活,流程形状不一样 —— 请你看一眼对不对

机制部分已经全部定完了。剩下这一件:这三套流程各自长什么样。
每一节下面都有留言框,想到什么随手写,底部能一键汇总。

为什么要分三套

是你说的 ——「我们还是必须得有 designer 和 prototype 的模板吧,因为它和产品出 PRD 完全是不一样的 flow 呀」。

所以判据不是「模板越少越好」,而是:只差用哪个模型的合并;流程形状不同的分开。下面三套就是形状不同的那三种。

写 PRD 最常见

把一件事想清楚,写成工程能照着做的东西。

研究→ 写→ 评审→ 你拍板
做出来的东西
研究记录 → PRD 稿 → 评审记录
谁拍板
评审过了之后,终态你拍你
不过怎么办
评审不过 → 回去改稿
最多来回几次
评审最多 3 轮

designer 先确认方向,再花力气

先给你看粗略的样子,方向对了再做精细的。

粗略草图→ 你确认方向→ 做精细版→ 评审→ 你拍板
做出来的东西
粗略草图 → 方向确认 → 精细版(或能点的原型)→ 评审记录
谁拍板
方向你拍,之后来回磨到你说「定了」也你拍你 · 多次
不过怎么办
精细版或评审不过 → 退回粗略草图那一步重来。
方向错了就回到最便宜的那步,不在精细版上反复磨。
来回几次
不设上限 —— 方向定了之后,细节可以来来回回磨(你说的:三四次五六次十次都可能)。你说「定了」才算完;你没回不等于自动通过,它会等你,不会替你定稿。
这跟「方向错了退回最粗那步」是两回事:那是推倒重来,这是方向对、细节磨。

prototype 做出来给你亲手试

搭一个真能跑的东西,让你自己上手,然后判定这条路走不走得通。

搭一个能跑的→ 你亲手试→ 你判定
做出来的东西
一条命令能跑起来的原型 → 你的实际体感 → 判定结论
谁拍板
试和判定都是你你
跑不起来怎么办
先修到能跑,不许拿给你试。
不能让你去试一个跑不起来的东西。
最多来回几次
修最多 2 轮
结局
「能做」和「不能做」都算成功收工
能做 → 交给工程去产品化;不能做 → 停掉,并写清楚为什么。

一处诚实边界

上面写的「最多几轮」是提案值,不是算出来的。真跑起来如果发现太紧或太松,是可以调的 —— 不用现在就定死。

要你回的就一件事

这三套的形状对不对 —— 尤其这三处,它们决定了你会被打断几次、在哪被打断:

  • designer 是开放来回,你说「定了」才收敛 —— 按你说的,方向对了细节可能磨很多次,不设固定轮数 ✓(已按你定的改)
  • designer 做砸了退回最粗那一步,而不是在精细版上改 —— 同意吗?
  • prototype 的「不能做」也算成功收工 —— 这条你认吗?
