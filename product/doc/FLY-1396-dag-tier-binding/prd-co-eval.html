产品部的三种活流程不一样 → 三套模板。下面是改完后的样子。

1 问题

现在所有走 DAG 的单 —— 哪怕只写份报告 —— 都被塞进最重的工程流水线（设计→实现→QA），中间很多废阶段。活样本 FLY-1378 一份研究报告因此跑了 3 轮设计 + 3 轮代码评审。

2 你定的判据：什么该合、什么该分

你说的：「我们还是必须得有 designer 和 prototype 的模板吧，因为它和产品出 PRD 完全是不一样的 flow 呀」

写进 PRD 当原则了 —— 不是模板越少越好：

  • 只差「用哪个模型」的 → 合并：工程的重/中/轻三档流程完全一样，只是每步换模型 → 合成一套工程模板 + 一个模型旋钮。
  • 流程「形状不同」的 → 分开：产品部三种活形状根本不同 → 三套，不是重复。
产品部的角色它的流程形状
写 PRD研究 → 写 → 评审 → 过闸
designer低保真 mockup → 确认方向 → 再往下
prototype搭一个能点的东西去验证

3 改完后：哪种活走哪套模板

部门是每件活的属性（看它的标签），不是项目 —— 同一个项目里工程的活和产品的活各走各的。

活是什么走哪套模板
工程工程模板（一套 + 轻/中/重模型旋钮）
产品 · 写 PRD产品-PRD 模板（现有那套，直接用）
产品 · designer产品-designer 模板要新建
产品 · prototype产品-prototype 模板要新建
其余 / 认不出角色通用模板（最轻，一个 session 直接做）
连部门都判不出不猜 —— 退回 triage（不静默塞进最重的）

模板总数：现在 6 套 → 改完 5 套（工程 3 合 1 省了 2、产品新建 2、研究并进通用省了 1）。

4 机制怎么落

一件活 → 部门早就算好了 ✓ ✂ 缺这一根 ✂ → 挑模板

系统在派发那刻早就算好这件活归哪个部门，只是这个结果没接到「挑模板」那一步。要做的就是接上这根线 + 一张对照表 + 允许每单手动指定。

新增的一层：怎么知道是 designer 还是 PRD？ 我去核了代码和你的真单 —— 角色现在只在标题前缀里（你的单都是 [PRD·HL] / [Designer·HL] / [Research·HL]，标签里只有部门、没有角色）。所以取角色按这个优先级：派单时直接指定 > 标题前缀 > 角色标签 > 都没有就走通用模板。（标题这条系统里已经有同款先例在用。）

5 怎么上线（安全顺序）

  • 先把 5 套模板都建好、装进库（含新建的 designer / prototype 两套）。
  • 再把旧的「一律最重」默认改成通用模板 + 给每种活补上对应的行（你手动改过的不动）。
  • 再接那根线 + 旋钮。
  • 全部验收通过前，DAG 一直关着，最后才单独开。

6 一条诚实边界

「研究单自动走最轻的」不是靠部门就能自动保证的 —— 工程部内部，系统分不清「建代码」和「写研究」。要让研究单走轻，得在建单/triage 时给它对的部门或角色。没夸大成全自动。
