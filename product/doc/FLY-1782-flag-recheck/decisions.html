② 批准门的应急开关

DECISION 2 / 8

「必须你批准过才算数」门 —— 关掉它的那个开关

这道门检查什么

一个 PR 就算已经被合并了,也必须能查到「你批准过」这条记录,才算真正完成。 查不到就把它挂起来、并且响亮报警 —— 这是防止有人绕过你把东西合进去。

门坏了会怎样

批准记录的链路出问题(查不到、写不进)⇒ 所有已合并的东西都卡在「不算完成」,一直挂着报警,后面的流程接不下去。

删掉这个开关意味着什么

这道门是直接守着你的授权的。删掉它的应急开关 = 以后这条链路出问题时,没有办法临时放行。

「必须有 QA 通过记录」门 —— 关掉它的那个开关

④ CI 证据门的应急开关

DECISION 4 / 8

「GitHub 上 CI 必须是绿的」门 —— 关掉它的那个开关

这道门检查什么

在批准和最终放行这两步,实时去 GitHub 查一次:这个 PR 的 CI 是不是绿的。 不绿就不放行。它查的是 GitHub 那边的实况,不是我们自己库里的记录。

门坏了会怎样

这道门依赖的是外部系统 —— GitHub 挂了、API 限流了、凭据过期了,都会让它查不到答案。查不到就当作「不绿」⇒ 放行被卡住,而问题根本不在我们这边。

这一条和前三条有个区别值得你知道:前三条坏在我们自己家里,我们能修;这一条可能坏在别人家里,我们只能等。

删掉这个开关意味着什么

GitHub 那边出问题的时候,我们这边完全没有手段继续推进 —— 只能干等对方恢复。

⑤ 设计校验门的应急开关

DECISION 5 / 8

「design 节点必须交出设计 HTML」门 —— 关掉它的那个开关

这道门检查什么

design 这个环节要收工的时候,必须交出一份给你看的设计 HTML,而且要带上能证明「这份就是这次改动对应的那份」的证据。 交不出来就不许收工。
