1 · ⭐ 纠正「固定节点」:节点类型是 per-category + 可扩展

你 v4 co-eval 纠的:「不是只有 Design/Implement/QA。eng 是这 3 个;创作视频 = Research / 生成视频(新节点类型)。新类别定义新节点类型(在 YAML/注册表里定义,不是跑中插)。别让人误解成全局只那 3 个。」

「固定节点」的准确含义(两条,缺一不可):

  • ① 模板内固定 —— 一个类别的模板,节点在定义时(YAML)就定死,跑之前就知道有哪些节点。
  • ② 跑中不 node-inject —— 跑起来不临时长新节点(动态只靠 loop+skip)。
  • ≠ 全局只 3 种 —— 节点类型是 per-category、可扩展的:新类别在注册表里定义自己的新节点类型。
类别节点类型(定义时定,跑中不变)

新类别在注册表里定义自己的新节点类型(§6 第二层)

一句话:节点类型「定义时可扩展(注册表加)、跑中不可变(不 inject)」。QA→Implement→QA 这种循环 = loop,能实现(§3 有硬证据:已跑过一个硬编码版)。

2 · 动态 = loop + skip(作用在该类别的节点上)

一个类别的节点定死后,动态全来自两个算子:

  • skip = 条件跳过某节点。例:Product skip QA(纯 doc 不测)· 简单任务 skip Design(直接干)。同套节点、不同任务不同路。
  • loop = 某节点/子图重复到条件(§3 展开)。

节点类型定义时可扩展(§1)+ loop/skip 跑时造动态 = 表达千变万化的流程,全程不加新节点。

6 · ⭐⭐ 两层定义:YAML 管结构、注册表管行为v5 关键新节

你定的关键分层:「YAML(第一层)= DAG 形状(哪些节点/顺序/loop/skip,按名字引用)。节点类型注册表(第二层)= 每节点『是什么』(design 节点 = session prompt + 带哪些技能 + 模型)。『design 具体做什么』在注册表、不在 DAG YAML。就是 three-stage-phases.ts 泛化成每节点类型一份。」

第一层 · YAML = 结构(形状)

哪些节点(按名字引用)· 顺序 · 哪里 loop · 哪里 skip。轻、好读、好覆盖。

第二层 · 注册表 = 行为(是什么)

每个节点类型:prompt(session 提示词)+ skills(带哪些技能)+ model。= 泛化 three-stage-phases.ts(它现在只管 model/phase → 加上 skills+prompt)。

放一起看(示意):

# ── 第一层:DAG 形状 eng.yaml —— 只按名字引用节点,不管它们怎么干 ──
nodes: [design, implement, qa]
edges:
  design    -> implement
  implement -> qa
  qa -> implement  {loop_when: fail}     # loop
skip:
  qa {when: category == product}          # skip

# ── 第二层:节点类型注册表 —— 每个『是什么』(泛化 three-stage-phases.ts)──
node_types:
  design:    {model: fable, skills: [brainstorm, research, design-review], prompt: "你是设计阶段…"}
  implement: {model: fable, skills: [test-driven-development],            prompt: "你是实现阶段…"}
  qa:        {model: opus,  skills: [qa-verify],                         prompt: "你是 QA 阶段…"}
  # 创作视频类别 → 在这里加新节点类型:
  research:      {model: fable, skills: [deep-research], prompt: "…"}
  generate_video: {model: fable, skills: [gemini-video], prompt: "…"}

为什么两层好:

  • YAML 管结构 = 改流程只动形状(加条 loop 边 / skip 条件),不碰行为。
  • 注册表管行为 = 节点类型可跨模板复用(design 到处引用一份定义);新类别加新节点类型只动注册表(§1 的可扩展就是这么落的)。
  • 「design 做什么」= 注册表(prompt/skills/model),不塞进 DAG YAML → YAML 保持轻。
