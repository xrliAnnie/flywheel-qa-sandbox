0 · ⭐ 红线(整张图服从它,不变)

你的北极星:模板 = 轻的 / 默认的 / 可覆盖的,不是死板紧身衣。模板是起手式默认、模型可偏离,不 micro-manage 每步。真正耐用的价值在治理,不在把模型推理钉死。

翻成三条贯穿约束:① 模板只钉粗脚手架(几个 session / 每个哪个模型 / gate·QA 卡哪),不定节点内部怎么想 · ② 默认可偏离,偏离走正门 · ③ 先怀疑「要不要建」再想「怎么建」,宁可少建。

1 · 主线:三段式只是 eng 那一块乐高(你这轮点透的)

你 co-eval 的核心:「三段式(设计→实现→QA)只对 eng。product / designer 要不同的 session / 节点 —— 这才是这层的核心。DAG 搭积木的价值 = 加一套新模板很省事。」

这就是整层的主轴。 今天系统里三段式是唯一被表达出来的形态,而且是 eng 的形态。问题:

  • product 的活形状不一样 —— 写 PRD / 调研 = 探索 + 收敛,没有「实现→QA」这个尾巴。硬套三段式是错的形状。
  • designer 的活又不一样 —— 出稿 / 评审 / 迭代,可能是「探索几版 → founder 挑 → 精修」,也不是三段式。
  • 今天没有地方表达「这类活这样跑」 —— 所以要么裸跑、要么被 eng 三段式误套。

乐高价值(你的原话): 底层是同一套「积木」(节点 = 一个带模型的 fresh session + 它的 gate/QA 位置)。eng 拼成三段式、product 拼成短的、designer 拼成另一种。加一类任务 = 拼一套新积木,不动引擎。 —— 这层要给的,就是这个「拼法随任务类型变」的能力。

2 · ⭐ 头号动机:Auto-QA 误触发(最具体的痛,直接证明「不够 generic」)

你点的头号动机:「老的自动 spawn QA 对 Product(纯 doc、根本不需要 QA)会误触发 —— 这就是不够 generic 的铁证。per-category DAG 正好治它。」

现状(核过码): Auto-QA(FLY-579)是「一刀切」的:一个 PR 过了 code review,Bridge 就自动 spawn 一个独立 QA Runner 去验(auto-qa-coordinator.ts,项目级 qa.auto opt-in)。它不分任务类别 —— 你只能全项目开/关,没法说「eng PR 要 QA、product doc PR 不要」。

痛在哪: 一个「写份 PRD」的 product issue 走到 PR,auto-QA 照样 spawn 一个 QA Runner 去「验证」一份文档 —— 没有可验的功能,纯浪费一个 runner + 一次 founder 干扰。这正是「一个模板套所有」的代价。

per-category 模板怎么治: QA 不再是全局开关,而是模板里的一个节点。
· eng 模板:设计→实现→QA 节点(在) —— 该验的验。
· product 模板:探索→收敛,没有 QA 节点 —— 从根上不会误触发,不用 opt-out 补丁。
「要不要 QA」变成「这类活的模板里有没有 QA 这块积木」的自然结果,而不是一个全局布尔去猜。

一句话:Auto-QA 误触发 = 「一个模板套所有」最疼的具体证据;per-category 模板把「要不要 QA」放进模板形态里,从根上 generic 了。

4 · 核心张力:模型越来越强,还要模板干嘛?(压缩版,论证不变)

三档:🅐 不要模板(全自由,但成本没治 / 无独立 QA / 状态面板没锚点 / gate 位置看心情)· 🅑 轻默认可覆盖(提议) · 🅒 死板每步(拖住强模型,❌ 否掉)。

回答你的挑战: 模板挂住的全是治理/基建钩子(profile 成本 / 独立 QA 位置 / gate 落点 / context 隔离 / 状态可观测)——没一样是替模型想,而且模型变强也不会让它们过时。节点内部怎么推理完全放开。→ 落 🅑。

5 · 提议的最小形态(v2 改:default = 裸 session)

你 co-eval 定的默认:「default 就是一个裸 session —— 没定义模板,agent 就随便做(= 无模板)。per-category 模板是 opt-in、后续加。」采纳。

最小可用 = 三件事,没有新引擎:

6 · 节点级能力:先把 inject / fork / loop 分清(你这轮问得最关键)

6.1 两种 inject —— 别混(你点破的)

你的分辨:「inject 有两种:我们已有『消息 inject』(人中途插指令/feedback);homerail 那种是『节点 inject』(往跑着的 DAG 图动态加/改节点,如 design→拆 4 个 PR→回去跑剩下)。别混。」
消息 inject节点 inject
是什么往跑着的 session 插一条指令/feedback(内容变,图不变)往跑着的 DAG 图 动态加/改/跳节点(图的形状变)
例子你中途跟 runner 说「顺便也改下 X」design 节点发现要拆成 4 个实现 → 图上长出 4 个 implement 节点 → 跑完回主线
我们已有 flywheel-comm send→mailbox · brainstorm gate净新 固定三段式做不到
homerail它的 inject 其实也是这种(往 node 注入指令 + 记 intervention),核过码部分/UNKNOWN homerail 靠 loop + skip 拿动态性,没有干净的「自由插新节点」;所以「节点 inject」largely 是净新,不是照抄

收敛:消息 inject 我们有、不用建;节点 inject 才是值得 deep-dive 的净新能力(而且诚实说,homerail 也没干净做,别把它当现成方案抄)。

6.2 inject / fork / loop 各治什么(你 4-PR 串行 = loop,不是 fork)

你的澄清:「fork = 并行分支(两种实现同时试);我那个 4-PR 串行 = loop(重复 implement),不是 fork;并行独立才 fork。」对,画清:

节点 inject 净新

跑中改图:加/改/跳节点
治:开跑才发现「这活其实要拆/要多一步」。固定图做不到。

fork later

从一个节点并行岔两条独立分支(两种实现同时试,择优)
治:方案不确定、想并行比。成本翻倍要治理。homerail:checkpoint fork 干净 session。

loop later

同一节点重复迭代(串行,做完一个再下一个 / 迭代到满足)
治:你的 4-PR 串行 = implement 循环 4 次。homerail:loop_gateway + loop_sources。

profile 已有:每节点绑模型(three-stage-phases.ts),无争议,MVP 直接用。

MVP 边界 + 留你拍(⑦): MVP 只吃 profile(已有)。节点 inject / fork / loop 我深挖清楚了 —— 都建议 Later,请你拍板:它们最像「重建 homerail 的 run 内引擎」,在一个模型越来越能自理的系统里,最该问「现在就要、还是等真痛」。有没有哪个你现在就有具体场景非要?

7 · 「可覆盖」怎么落(deviation 走正门)

  • 换整套模板 —— 单 issue 用 label/dispatch 参数指定别的模板(泛化今天的 no-three-stage)。
  • 调这套的节点 —— 单 issue 跳某节点 / 换某节点模型(per-run override)。
  • 裸兜底 —— 不挂模板 = 裸 session(§5),永远有个「不套流程」的出口。

原则:默认省心、覆盖顺手、偏离不惩罚。绝不逼一个单步能完的活跑三段式。

8 · 讲清三件不同事:自定义模板 / DSL / 编辑器(你要求区分)v2 新节

东西是什么homerail 有吗(核过码)我们 MVP
自定义模板让用户定义自己的模板(超出 shipped 那几套)有(YAML 模板文件可加)不做 · 远期
DSL(写模板的小语言)一套文本格式/小语言去写模板有 —— YAML orchestration 模板(assets/orchestrations/*.yaml.template)。注:homerail 的 TOML 是它的 UI widget 格式、不是模板格式(常被误传)不做 · 起步几套写死够
编辑器(可视化 UI)拖拉拽画模板的界面没找到 —— homerail 模板是手写 YAML;它的 agent-ui(Vue)是语音/run 状态界面,不是模板编辑器不做 · 最远期

MVP 明确边界: 几套写死模板 + 裸 session 默认。不做 DSL、不做编辑器、不做用户自定义。等真跑出「这几套不够、需要自己写」的具体痛,再谈 DSL(大概率也是 YAML 文件,不是可视化编辑器)。

9 · 分阶段(default-off,抄三段式那套上线纪律)

  • 阶段 1(MVP):裸 session 作默认 + per-category 模板 opt-in(eng 三段式抽数据 + product 短模板)+ profile 复用 + QA 变成模板节点(治 §2)+ 可覆盖。default-off、字节兼容,照 pipeline.three_stage opt-in 纪律。
  • 阶段 2:节点 inject / fork / loop(若你拍要)、更多模板。

安全阀在第二层(353)治理里(founder gate + 接管叫停 + 出错升级),所以这层可以「轻」。
