0 · ⭐ 红线(不变)

1 · ⭐ 大收敛:节点固定,动态全靠 loop + skip(不加新节点)

你这轮 nail 的:「节点就固定那几个(Design / Implement / QA)。动态来自 loop + skip,不是加新节点。」

这是整个设计的收敛点,极简:

  • 节点(固定调色板):Design / Implement / QA —— 就这几块积木,不动态增减种类。
  • skip:某类任务跳过某个节点(同套节点、不同任务走不同路)。
  • loop:某个节点/子图重复,直到条件满足。

一句话:固定节点 + loop(回边)+ skip(条件边)= 我们要的全部动态。不需要 node-inject(随意加节点)。

2 · skip = 条件跳过节点(同套节点、不同任务不同路)

你的例子:Product skip QA(纯 doc 不需验)· 简单任务 skip Design(直接干)。

skip 让同一套固定节点适配不同任务 —— 不是给每类任务造新节点,是条件性地不走某个节点:

  • Product:走 Design→Implement,skip QA → 从根上不会触发 auto-QA(见 §6)。
  • 简单任务:skip Design → 直接 Implement(→ QA)。
  • eng 常规:一个都不 skip,全走。

3 · loop = 重复直到条件 + 你的两个例子

你的例子= loop今天
① QA↔Implement 来回loop(Implement↔QA) 直到 QA 过已硬编码 FLY-939 kickback(QA fail→唤醒 parked implement 重做,phase-orchestrator.ts)—— loop 需求真到已焊死,但焊在一个模板里、不可声明
② Design→4 PRloop 那个 (Implement→QA) 子图 4 次做不到 焊死的 kickback 表达不了「重复 4 次」,是新 loop 形状

两个例子的解都是 loop(重复子图),不是 fork(并行)、也不是加节点。升级 = 把 loop 从「焊死在一个模板」变成可声明的回边。

5 · ⭐ 明确不做:node-inject(加新节点)· fork(你确认)

你确认的:「node-inject(加新节点)不需要 —— 节点固定,loop+skip 就够动态。」
  • node-inject(跑中随意加节点) 不做 —— 从 Later 降级到不做。loop+skip 覆盖你所有动态需求;随意加节点更复杂、更难治理,连 homerail 都没干净做(§7)。
  • fork(并行独立分支) 不做 / 远期 —— 你的痛是串行 loop,不是并行。
  • MVP 动态 = loop + skip 就这两个 + profile(已有)。干净、可治理、够用。

8 · ⭐ YAML 定义『哪些节点 / 顺序 / 哪 loop / 哪 skip』收敛版

你定的:DAG 用 YAML 定义(homerail 也是);MVP 要轻 YAML(节点+顺序+loop+skip),不做可视化编辑器。

一份 YAML 就把「固定节点 + loop + skip」全表达了(示意):

# 固定节点调色板(每个绑模型 = profile,已有)
nodes:
  design    {model: fable}
  implement {model: fable}
  qa        {model: opus}

edges:
  design    -> implement
  implement -> qa
  qa -> implement  {loop_when: fail}     # ← loop 回边:验不过就回去,重复直到过

# 每类任务:同套节点,靠 skip 走不同路
skip:
  qa      {when: category == product}    # ← Product 跳 QA(纯 doc,不误触发 auto-QA)
  design  {when: trivial}                # ← 简单任务跳 Design

# default = 不挂 YAML = 裸单 session(agent 随便做,满足红线)
  • nodes {model:…} = profile(已有升成字段)· edges = 走向 · loop_when = loop 回边 · skip {when:…} = skip 条件。
  • 整份 YAML 就是「哪些节点 / 顺序 / 哪 loop / 哪 skip」—— 没有「加节点」的语法,因为不需要。
  • 不做:可视化编辑器、用户随便自定义、node-inject、fork。YAML 是我们/Tadashi 写模板的轻格式,你永远只在 Discord 指挥,不碰 YAML。
