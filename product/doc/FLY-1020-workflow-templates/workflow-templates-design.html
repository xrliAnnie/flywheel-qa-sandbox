2 · 动态 = loop + skip(作用在该类别的节点上)

  • skip = 条件跳过某节点(Product skip QA / 简单任务 skip Design)。同套节点、不同任务不同路。
  • loop = 某节点/子图重复到条件(§3)。

节点类型定义时可扩展 + loop/skip 跑时造动态 = 表达千变万化的流程,全程不加新节点。

6 · ⭐⭐ 三层定义:YAML 结构 + 注册表 + Markdown 步骤(最底层今天不变)v6 关键

你 v5 co-eval 的关键澄清:「其实是三层,最底层是 Markdown(今天这套、不变):①YAML=DAG 形状 ②注册表=每节点带哪些技能+模型 ③Markdown=每个技能具体怎么做(brainstorm.md/research.md/design-review.md)= 我们今天这套 Markdown 结构、不动。YAML+注册表 = 加在现有 Markdown 之上的编排层、不替代 Markdown。」
第一层 · YAML = 结构(形状)
哪些节点(按名字引用)· 顺序 · 哪 loop · 哪 skip。轻、好读、好覆盖。新增
↓ 节点按名字引用
第二层 · 注册表 = 每节点带哪些技能 + 模型
design = {skills:[brainstorm,research,superpower,design-review], model:fable}。= 泛化 three-stage-phases.ts。新增
↓ 技能按名字引用
第三层 · Markdown = 每个技能/步骤怎么做
brainstorm.md · research.md · design-review.md …… = 我们今天这套 Markdown,一个字不改。今天这套 · 不变
⭐ 打消一个误解:不是用 YAML 重写 brainstorm/research。 那些 Markdown 技能定义原封不动。YAML + 注册表只是加在上面的编排层 —— design 节点说「用这些技能」,每个技能具体怎么做还是各自的 Markdown 说了算。新增的只有『怎么把节点/技能编排起来』,没动『每个技能怎么做』。

三层放一起(示意):

# ── 第一层 YAML:结构(新增)──
nodes: [design, implement, qa]
edges: design -> implement -> qa;  qa -> implement {loop_when: fail}
skip:  qa {when: category == product}

# ── 第二层 注册表:每节点带哪些技能 + 模型(新增,泛化 three-stage-phases.ts)──
node_types:
  design:    {model: fable, skills: [brainstorm, research, superpower, design-review]}
  implement: {model: fable, skills: [test-driven-development]}
  qa:        {model: opus,  skills: [qa-verify]}

# ── 第三层 Markdown:每个技能怎么做(= 今天这套,不动)──
skills/brainstorm.md      ← 不变
skills/research.md         ← 不变
skills/design-review.md    ← 不变

分工:YAML 管「节点怎么连」· 注册表 管「每节点用哪些技能+模型」· Markdown 管「每个技能怎么做」(不变)。新增只在上两层。
