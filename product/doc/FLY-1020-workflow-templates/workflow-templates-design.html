6 · homerail 是静是动?(核过码,诚实)

homerail = 动态,但靠 loop,不是随意加节点:

  • loop:loop_gateway 节点 + loop_sources,子图可回环迭代(核过码)—— 跟我们要的 loop 同一个东西。
  • 它的 inject:是消息 inject(往跑着的 node 注入指令 + 记 intervention),不是改图。所以「homerail 有 inject」≠「它随意加节点」。
  • 随意加节点:没找到 —— homerail 靠 loop + skip 拿动态性,没有干净的「跑中自由插新节点」。所以 node-inject 对谁都是净新、险活。

印证 §3:loop 是成熟、真实、连竞品都在用的动态原语;node-inject 是连 homerail 都没干净做的险活。

7 · ⭐ 怎么定义这个动态图 = 轻 YAML(采纳,修正 v2)v3 大改

你这轮定的:「DAG 要有定义格式,YAML 最合适(homerail 就用 YAML)。MVP 要简单 YAML 模板(节点+边+loop),不做可视化编辑器。」→ 采纳,并修正 v2 我说的『不做 DSL』:轻 YAML DSL 要、编辑器不要。

模板 = 一个轻 YAML 文件:声明节点(每个绑模型 = profile)、边、以及 loop 边。长这样(示意):

# eng.yaml —— 工程模板(带 QA↔implement loop)
nodes:
  - design    {model: fable}
  - implement {model: fable}
  - qa        {model: opus}
edges:
  - design    -> implement
  - implement -> qa
  - qa -> implement  {when: fail}   # ← loop:验不过就回去,重复直到过

# product.yaml —— 产品模板(短,无 QA 节点 → 不会误触发 auto-QA)
nodes:
  - explore  {model: fable}
  - converge {model: fable}
edges:
  - explore -> converge

看这张 YAML 就懂全设计:

  • 节点 + {model:…} = profile(已有,升成字段)。
  • 边 = 图的走向。
  • qa -> implement {when: fail} = loop(把今天焊死的 kickback 变成一行可声明的边)。
  • product 模板没有 qa 节点 = 从根上不误触发 auto-QA(治 §4)。
  • default = 不挂 YAML = 裸单 session(agent 随便做,满足红线)。
MVP 边界(修正后): 要:轻 YAML 模板(节点+边+loop)+ 几套 shipped(eng/product)+ 裸 session 默认 + profile。不要:可视化编辑器、用户随便自定义、node-inject/fork。—— YAML 是给我们(和以后 Tadashi)写模板的轻格式,不是给你碰的;你永远只在 Discord 指挥。

8 · 「模板会不会束缚强模型?」(压缩版,论证不变)

YAML 只钉粗脚手架(几个节点 / 每个哪个模型 / QA 在不在 / 哪里 loop)——全是治理/基建钩子(成本、独立 QA、context 隔离、可观测),没一样是替模型想,而且模型变强也不会让它们过时。节点内部怎么推理完全放开;不挂 YAML = 裸 session 完全自由。→ 不束缚,反而给自由套了个「花多少钱、在哪停下给你看」的轻架子。

9 · 可覆盖(deviation 走正门)

  • 换整套 YAML 模板(单 issue 指定别的)· 调节点(跳某节点 / 换模型)· 裸兜底(不挂 = 裸 session)。

默认省心、覆盖顺手、偏离不惩罚 —— 绝不逼单步能完的活跑三段式。
