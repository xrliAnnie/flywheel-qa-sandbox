1 · 定稿锁定了什么(一屏看全)

  • 三层:YAML(图形状)→ 注册表(每节点用哪些技能+模型+能力)→ Markdown(每个技能/角色怎么做,今天这套不变)。
  • 动态 = loop + skip,跑在固定节点上,不加新节点。
  • agent.md = 角色(WHO),DAG = 引擎内编排(永不甩给 Claude);通用节点 = 跑任意 agent.md(非工程师零代码扩展)。
  • 轻/默认/可覆盖:不挂模板 = 裸单 session;不配置 = 今天行为一字不变。
一句话验收:eng 走三段式(QA 不过自动回去重做)· product 走短模板(不再被误 spawn QA)· 非工程师写个 agent.md 挂通用节点就能加自己的角色 · ship 永远你点头。

2 · ⭐ 三层架构(一张图)

打消误解:不是用 YAML 重写 brainstorm/research。 上两层只是加在现有 Markdown 之上的编排层;每个技能/角色怎么做,还是它自己的 Markdown 说了算。

3 · ⭐ 自上次看的卡以来的一处工程决定(请看)

⚠️ MVP 的节点是:Design / Implement / QA + 一个「通用节点」 你要的「非工程师定义自己 agent.md」—— 落地成一个 通用节点(跑任意 agent.md),和三段式并列进 MVP。「任意具名新节点类型」不做(大概率永远不必)。

为什么这样最好(你上轮的洞察,工程验证了): 系统里 design/implement/qa 三个名字硬编码在 8 个生产面(存的角色、展示、ship 收尾、retry、重启对账、TURN 恢复…)。

  • 开放任意具名节点类型 = 每加一种都要动这 8 处 → 每种付一次账。
  • 一个通用节点 = 只动这 8 处一次;之后任何人写自己的 agent.md 就能用,零代码。
而且它天然安全:agent.md 里就算写「我能 ship / 用某模型」也没用 —— 系统不读那些字段(有代码为证)。扩展性给出去了,权限没给出去。
请你拍:同意「MVP = 三段式三节点 + 通用节点;任意具名新类型排后面」吗?(这是唯一动了你上次验收面的点。)

4 · 动态 = loop + skip(不加节点)

算子做什么你的铁例
loop某段重复到条件(串行)QA↔Implement 直到过 · Design→4 个 PR 逐个做
skip条件跳过某节点product 跳 QA(治误触发)· 简单任务跳 Design
有硬证据:「QA 不过回去重做」这个 loop 今天已经存在,只是焊死在三段式里。升级 = 把它变成一行可声明的边 + 加「最多重复几次」的上限(到上限就停下报人,绝不无限打转)。

5 · 安全 + 评审救回的坑(值得你知道)

Codex 六轮严审,抓出并让我修掉两个真问题:

  • 会锁死 ship 的死锁:我第一版想让模板内部的 QA 复用系统现有的放行开关 —— 那个开关要一份「独立 QA 写的记录」,而模板 QA 从不写它。真建出来,eng 的 PR 会永远合不进去。已改成模板专用通道(绑代码 head、head 一变作废;老路径一字不动)。
  • 静默数据损坏陷阱:系统对「不认识的节点角色」会悄悄当成普通 session 处理(不报错、行为全错)。已要求:任何新节点角色没登记就直接失败报错,绝不悄悄降级。
红线守卫(可验收):只用我们内置的模板 · 用户能加角色不能加能力/选模型(物理保证)· 节点内部怎么想模板不管 · 不挂模板永远能裸跑 · 不引入自由表达式 DSL。
