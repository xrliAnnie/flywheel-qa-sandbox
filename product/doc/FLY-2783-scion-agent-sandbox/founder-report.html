Scion 是给谁用的？我们该不该动？

FLY-2783 · 2026-09-22 · 一手核实了仓库和文档，并在这台 Mac 上真跑了它的命令行
一句话

Scion 不是 Google 的产品，是一个挂在 Google 名下、主要由一个人维护的开源实验项目。它给「已经在同时跑好几个 AI 助手、开始被互相踩脚和账号混乱折磨」的人用——个人和小团队都行，不需要服务器集群，Mac 能跑，订阅登录也支持。它跟 Flywheel 长得几乎一样。但我不建议我们迁过去，建议抄它两件事。

它到底是什么，靠不靠谱

一个开源的「AI 助手班组管理器」谨慎

你手上如果同时有五个 AI 助手在改同一个项目，会遇到三个麻烦：它们互相改乱对方的文件、共用一个账号把额度撞爆、你不知道谁在干嘛。Scion 就是专门管这三件事的：每个助手关在自己的小盒子里，用自己的账号，有自己的一份代码副本，它们之间能互相发消息、派活，你能随时探头进去看。

项目实测值怎么读
身份挂在 Google Cloud 名下，但说明书第一句就写「这不是 Google 官方支持的产品」别当官方背书
版本所有版本都标着「预览版」，没有一个正式版随时会变
开发速度过去 7 天改了 200 次，一年改了 4387 次快得有点吓人
谁在写最近 200 次改动里，191 次出自同一个人一个人扛
受欢迎程度1718 个收藏有人在看
开源协议Apache-2.0，我们可以自由参考和使用没有法律障碍

我自己撞到的三处「说明书和实际不一致」：版本号标的是 preview.3、程序自报 preview.1；说明书说 Mac 上默认用苹果自带的容器，实测它选的是 Docker；说明书说默认只装两个助手，实测装了九个。单条都不致命，但合起来说明——它的文档不能当承诺看，只能当线索看。

谁会去用它，用来干嘛

四类人，和一类明确不该用的人

谁什么场景合不合适
个人开发者一台笔记本上同时跑三五个 AI 助手改同一个项目，要它们互不打架，还能随时探头看某一个在干嘛最贴合
2–10 人的小团队租一台便宜机器当中枢，大家从各自电脑派活，在网页看板上看进度，在 Slack / Discord 里跟助手对话合适，但要有人管机器
公司里做内部工具的团队拿它当地基，往上长自己公司的「AI 助手工作台」：身份、权限、密钥、审计、多人隔离它都有它最高配的形态就为这个设计
研究「AI 助手怎么协作」的人这是它的本命。Google 内部拿它做过软件移植、市场调研；公开案例里有一个 AI 剧组拍片的项目，还有一个纯靠文字说明书定义的多助手解谜游戏本命场景
想要一个稳定工具、不想当小白鼠的人要保证、要不折腾、要出事有人兜底不该用

划线人群：已经在同时跑多个 AI 助手、并且开始被「互相踩脚 / 账号混在一起 / 看不见谁在干嘛」折磨的人。只跑一个助手的话，Scion 给的一切都是纯成本。

那 AX 呢？（你同时问到的那个）

AX 跟我们不相干，它是另一个量级的东西

AX（google/ax，7766 个收藏）自称是「Google 的开源 AI 助手调度运行时」，目标写得很直白：在一个服务器集群里跑几十亿个助手任务。它的用法是写配置文件然后一条命令下发，风格跟运维大型服务器集群的工具一模一样。

关键差别：AX 的安装前置是一整套集群设施——一个服务器集群、一个打镜像的工具、一个集群能拉取的镜像仓库，外加另一个它依赖的底层服务。笔记本上不是「装不了」，而是得先把这一整套自己搭起来，这个前置本身就把它挡在了单机场景之外。所以它的人群是「我要给全公司几百个工程师提供 AI 助手算力，要配额、要网络管控、要成本控制」的基础设施团队。

成熟度也别读错：它 9 月 20 日确实发了一个 v0.3.0（不带预览标记），但仍然是 0.x，接口还标着「第一版草案」，说明书首屏的警告框明写「稳定版之前很可能引入重大不兼容改动」。比 Scion 规整，但同样不是能押生产的东西。

打个比方：AX 是给 AI 助手用的「机场调度系统」，Scion 是「一个车队的排班表」。我们是后者的尺寸。AX 这条线我建议直接不看。

Mac 能跑吗？我们的订阅账号能用吗？

两个都能实测

Mac：能。我把它的官方 Mac 版程序下到临时目录里真跑了一遍——启动、体检、建项目都成功。它对电脑的要求只有两样：git 和 tmux，我们本来就有。顺带一个有意思的发现：Scion 也是用 tmux 装 AI 助手的会话，跟 Flywheel 一模一样，它连「抓登录令牌」都是从 tmux 的屏幕回滚里扒的。

订阅登录：能，而且设计得很细。它不强迫你用按量付费的 API key。它的流程是：先让助手在没有账号的状态下起来，掉到一个命令行里；你进去手动跑一次登录（Claude 是 claude setup-token，Codex 是 codex login）；然后它把登录结果抓下来存成这个项目的密钥，以后新起的助手就自动是登录好的。找不到账号时它不报错崩掉、而是告诉你该跑哪条命令——这个体贴设计本身就值得我们抄。

但有两个它解决不了的坑，我必须说清楚：

  • 本机的 Claude Code 登录信息存在 macOS 钥匙串里、不是文件（我实测确认了：那个文件不存在，Codex 的存在）。所以它文档里「直接拷贝登录文件」那条路在我们这儿是空的，只剩「手动生成令牌」这一条路能走。能走通，但要知道只有这一条。
  • 一份订阅喂给十个盒子，还是一份订阅。它给的是「每个助手一套独立账号」的机制，不是「每个助手一个独立订阅」。十个助手同时用同一个订阅，照样撞额度上限；Codex 那种会自动轮换令牌的，多个盒子同时刷还会互相踢掉线——这个我们自己踩过。Flywheel 现在的账号池和自动切号，Scion 里没有对应的东西。
跟 Flywheel 比，值得抄的两件事

① 明确告诉每个助手「你这份代码是独占的还是共享的」几乎零成本

Scion 把「代码怎么分」定义成三个有名字的档位：全共享 / 各自一份工作副本 / 各自一份完整拷贝。然后它把当前档位直接告诉助手本人，还在说明书里写死每档下必须守的规矩（比如共享档：「不许假设你读完到写回之间文件没被别人改过」）。

我们事实上跑的就是中间那档，但从来没告诉过 Runner 它在哪一档。最近一次事故正是这个形状——一个已经验收完的 Runner 去合并主干，把被绑定的那个版本挪走了。如果它开工时就知道「你在共享区，这几件事禁止做」，源头就能拦住。

代价：加一个环境变量 + 一段固定说明文字。这是最便宜的一条，建议第一个做。

② 闲着的助手怎么收 — 已经在做了，归 FLY-2782不在这张单里

你要的「跑完退下、打回再拉起」已经是 FLY-2782 的活，已经有人在做原型，这里不重复展开。只从 Scion 捞一句最值钱的留给那边：让助手自己说「我在等某件事」，用这句话把「故意在等」和「意外卡死」区分开——这个歧义我们现在是靠猜的。

③ 把「盒子活着没」和「助手在想什么」拆成两件事低成本

Scion 用两个互不干扰的维度描述一个助手：一维是基础设施状态（正在创建 / 运行中 / 正在停 / 已暂停 / 崩了），另一维是它在干嘛（在干活 / 在思考 / 在等人回话 / 在等别人 / 干完了 / 撞额度了 / 疑似卡住）。

好处很直接：你的面板要回答「这个 Runner 是没在动，还是在等我回话？」时，现在是靠推断，拆开之后是直接读出来的。

还可以顺手学的小东西

  • 助手退出时把真实退出码捞回来分类：正常收工 / 撞额度 / 真崩了——三者不再混为一谈。
  • 项目级的权限天花板：单次派活能给多大权限，被项目的上限压住，比我们现在散落各处的护栏好审计。
  • 它把「谁有权删掉一个助手」写成了一张表，其中一条我们踩过：「提交了不等于推上去了，有没推送的活不许删」。

我的建议：两条路，我推荐哪条

选项 A：整体迁到 Scion 上去不推荐

好处：一步拿到真正的盒子级隔离、现成的网页看板、现成的多人权限体系，不用自己造。

代价：① 非官方产品、没有正式版、一个人在写、一周改 200 次——把生产押上去，它哪天大改我们就得跟着改；② 我们的 Runner 要用这台 Mac 的 tmux、cmux 窗口、Chrome、钥匙串、开机服务，这些全都在盒子外面，关进盒子等于全部重做；③ 我们现在 50 个工作副本，一个助手一个盒子就是 50 个盒子，这台 Mac 的内存和硬盘顶不住。

选项 B：不迁，只抄 ① 和 ③我推荐这个

好处：① 几乎零成本，并且直接对着我们最近真实踩过的坑；③ 也很轻。两件都是在现有 Flywheel 里加东西，不推翻任何地基。（② 已经在 FLY-2782 里做，不算这张单的成本。）

代价：拿不到盒子级隔离。但说实话——隔离这件事我们用「一人一份代码副本 + 排队锁 + 护栏」已经买到了大半，剩下那部分不值 50 个盒子的价钱。

为什么推荐 B：Scion 对我们的价值是设计参考，不是替换方案。它的地基（容器）是我们最不需要的部分，它的上层设计（隔离档位显式化、状态分层）才是我们真缺的——而上层设计可以白嫖，不用搬地基。

我不确定的地方（不藏着）

  • 我没真正跑起来过一个助手盒子。所以「跑起来之后好不好用」这一格我是空的。不是因为难，是因为要填它得动这台生产机的底层环境（装 Homebrew 包被护栏正确拦下了，而且要先起容器服务、再下几个 GB 的镜像）。如果你想填这一格，那是单独一张单。
  • Scion 的闲置回收该抄多重，我没把握（这条留给 FLY-2782）。Scion 是「拆掉盒子留记忆」，我们的 tmux 会话比盒子便宜得多，可能只需要「自报在等 + 超时提醒」而不需要真的回收。
  • 它一周改 200 次，我今天读到的设计下个月可能就不长这样了。我抄的是思路，这一点对我们影响不大，但值得记一句。
