## 3. 关键的方法论教训(比结论更耐久)

三方(FLY-1443 原报告、FLY-1827、本单)每一轮都以为拿到了干净对照,每一轮都漏掉**同一个**维度:

- 原报告比 v2-vs-v3,漏了 transport
- FLY-1827 比 v1-vs-v3(E1/D3),仍然漏了 transport —— 两次都固定在 websocket
- 本单能补上,**不是方法更好**,是去读了二进制里那句 `AVAS realtime calls require realtime v1 or v3`,是那句话暴露了还有第三个维度

HL 定的判据是「只有一个变量不同的两次运行才叫对照」。本单指出它的适用前提:
**这条判据只在你已经知道变量空间有多大时才管用。控制变量控的是你列得出来的那些;列不出来的那个,再小心也控不住。**

⇒ **可复用的防呆顺序:先找「这个系统一共有几个维度」的权威来源,再设计对照。**

同源的错误在本单又犯了一次(见 §5 第 2 条):把「查了一个组件」当成「对整个系统下结论」。

### 本单夜里沉淀的另外两条(与上面同源,都是「拿手边的测量替代权威源」)

| 判据 | 怎么来的 | 怎么用 |
|---|---|---|
| **一个干净的零最需要对照组** | 我 grep 时 `\| grep -vi "test"`,而要找的哨兵就在 `__tests__` 里 → 把「被守护范围内没有」读成了「守护者不存在」 | 拿到零命中,先问:**我扫的范围包不包含我要找的东西?** |
| **一个 guard 的存在方向要单独问一句** | 「有哨兵测试守着」天然读起来像安全网,而这一个恰好相反 —— 它守的是「那层防护必须保持被拆除」 | 看到 guard 先问:它守的是**「这东西必须在」还是「这东西必须不在」**?两者命名和直觉上长得一样,**结论相反** |

## 4. 决定怎么做的过程

1. **先读证据,不重跑。** 发现 FLY-1443 的 D3 干净对照用的就是 `cove`(v3 合法音色),拿到的是服务端原话
   —— 也就是说 issue 对旧证据的质疑站不住,旧证据比转述更硬。
2. **但仍决定重跑**,理由换成了版本漂移(0.145.0 → 0.147.0),不是「旧结论不严谨」。
3. **写了一个只测准入的精简探针**(`evidence/admit.mjs`),拿到 `started`/`error` 就停 —— 零 model turn,
   额度消耗≈0。这一步是为了能多跑几组对照而不烧钱。
4. **跑 P1 复现了七月的拒绝**,本以为到此为止。
5. **转折点**:去 `strings` 扫二进制找拒绝语的出处,意外看到
   `AVAS realtime calls require realtime v1 or v3` 和 `Content-Disposition: form-data; name="sdp"`
   —— 才意识到 v1/v3 走 WebRTC。
6. **装了纯 JS 的 WebRTC 栈(werift,只在 scratchpad)生成真 SDP offer** → P6 当场 started,P7 复现。

## 5. 本单自己犯的错(留给后来人,别再犯)

1. **把 issue 对旧报告的质疑当事实带入。** 差点写成「旧报告不可靠」,读了原文才发现旧报告比转述谨慎得多。
   ⇒ 引用二手转述前先读一手。
2. **doc_flow 那次回答 scope 错了(已撤回)。** Annie 问「Docflow 没有打开吗」,我读成「这个项目开没开」,
   查了 canonical config 就答「开着的,你不用担心」。她问的其实是 FLY-1810 跨六个项目的 rollout,
   实际是**开 3 关 3**。那句话写上页面就是一句她会当真的假话。
   ⇒ **先确定她说的那个东西边界在哪,再决定查哪一层。**查一个组件不等于对系统下结论。
3. **第一版页面把实验写成了实验报告。** 她的原话:「我其实没有懂你这里到底做了什么,
   我们需要的不就是有个……和 CodeX CLI 打电话的功能吗?那个功能现在到底是好的还是没有好呢?」
   ⇒ 她要的是功能层面的一句话,不是六组对照表。
4. **写了一句绝对断言,而我只验了它的一部分。** 答她「Claude vs Codex 权限」时我写「权限跟 Claude lead
   **一模一样**……没有**任何**额外的笼子」。实际上 full-access 的可写范围被钉死在项目根目录
   (`writable_roots=[canonicalProjectRoot]`),Claude 则完全不圈 —— **差别虽小但真实存在**。
   ⇒ **「没有任何 X」的证明成本远高于它读起来的样子:要排除的是全部,不是给一个例子。**
   **能写「等价」就别写「一模一样」;能写「没有额外的门禁」就别写「没有任何笼子」。**
   (判据由 Honey Lemon 提出,他同一晚在「她批准过收紧」上栽的是同一个形状 —— 见 `decisions.md` D-4。)
5. **拿一个「零命中」当「不存在」。** 我 grep 时写了 `| grep -vi "test"`,而要找的哨兵测试就住在 `__tests__` 里,
   于是我把「被守护范围内没有」读成了「守护者不存在」—— **那个零恰恰是哨兵在起作用的证据**(详见 `decisions.md`)。
   ⇒ **一个干净的零最需要对照组:先问我扫的范围包不包含我要找的东西。**
   这与 §3 是同一个形状(用手边的测量替代权威源),只是这次落在我自己身上。
