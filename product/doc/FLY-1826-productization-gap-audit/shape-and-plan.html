② 一个陌生人从零到持续用,整条路长什么样

形态最容易理解不一致的地方不在定义,在具体每一站发生什么。

0他是谁 已定

自己做电商 / social 的一人公司老板,有技术直觉但不是程序员。他的痛不是「帮我做杂活」,是 「我得持续地建 + 养我的业务软件 / 自动化 / 内容系统」。明确不服务:想自己搭 agent 框架的程序员 · 想要通用知识助手的人 · 想要「零人自动赚钱」的人。

FLY-911 §1。MVP 还要再收窄一档(PRD §2「有技术直觉但非程序员」)—— 因为自托管要一台常开电脑,这条会挡掉纯非技术小白,PRD 自己写的已知取舍。

1他怎么拿到 事实如此

敲一条 npx 命令,然后被要求粘一把许可证钥匙。钥匙只在签发那一瞬间打印一次,要经你的手交给他。

也就是说:你是发钥匙的人,客户获取是手工的、没有自助注册。这形态从没被正式拍过,是实现时选的。

2他要自带什么 已定(平台边界)

一台 7×24 常开的电脑(Mac/Linux/Windows 走 WSL2)· Discord 账号 + 自己建 server + 自己建 bot + 开 2 个开关 + 点邀请链接(这 4 步 省不掉 —— Discord 不给 API,是边界不是偷懒)· Linear 账号(团队的后台小本子,他平时不用打开)· GitHub 账号 · 他自己的 Claude 订阅(刻意的:用他的账号,我们不收他密钥、也不替他付模型钱)。

3装的过程是什么体验 已定

不是一份说明书,是一个陪他装的助手,叫 Buddy。一次只让他做一件事 · 每步当场验 · 失败给具体原因不是「出错了」 · 中断能接着来 · 同一步失败两次转人工。

全程不许出现工程黑话 —— 他听到的词只有:向导(Buddy)/ 你的 Team(Captain + Crew)/ 后台清单 / 安置。Lead、Runner、Bridge、manifest、launchd、repo、token 一个都不许露。

4什么时候算「装好了」 已定,这条最重要

不是「环境 ready」,是他拿到第一个真结果,目标 ≤60 秒。

样例:他问「看看我今天有没有卡住的单」→ 几十秒后回他 「今天 26 单,1 单要注意:#1234 显示 pending 但不是丢单 —— 供应商已发货、确认邮件没读到才没更新。要我盯着到了自动更新吗?」
价值是一个结果,不是一个仪表盘。

5他电脑上到底跑着什么 事实如此

一个常驻后台服务 + 每个 Lead 一个常驻进程(挂了自动拉起) + 每天凌晨 3 点一次汇报;干活的 Crew 按需起。 他电脑上跑的是一整套完整的 Flywheel,不是精简版。

意味着:体验取决于他的机器;他关机 = 团队下班(Buddy 欢迎语里已经诚实说了这句)。这个形态没被单独拍过,是「自托管」的自然结果。

6他日常怎么用 · 凭什么敢用 已定

在 Discord 里,用手机就行。跟一个有名字的 Captain 说话,像跟员工/承包商说话。系统自己往前推,只在要他拍板时来找他,而且是用大白话说「我打算做 X,行吗」——他批的是听得懂的决定,不是一屏代码。

他敢用是因为六道能亲身感知的保障:可读的审批 · 能喊停 · 预算护栏 · 有名字能追问的 Captain · 结果他自己验得了 · 持续维护不是做完就扔。 一句话:「它动你的业务,但每一步你都看得懂、拦得住、验得了。」

7多个客户之间什么关系 已定,但后果没被讨论过

各跑各的,每人一套独立部署、天然隔离 —— 我们这边没有一个统一的后台。

后果:没有客户名册、没有计费、没有支持通道、我们看不见客户那边发生了什么。而现在程序让卡住的客户把摘要 「发给我们的支持同学」—— 这个角色目前不存在。

这条时间线里,哪一站跟你想的不一样?
