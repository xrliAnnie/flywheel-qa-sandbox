## 0. 给评审人的三分钟摘要

**原计划**:把机器负载打到 15 / 20 / 30 / 40 / 50…,看 Bridge 从哪一档开始不行,把 runner 放行阈值放在那一档下面。

**动笔前先在生产机上量了一遍,量到一件威胁这个前提的事**:

> 在**没有施加任何实验负载**、机器 load 只有 5.3 – 11.2(中位数 7.3)的情况下,生产 Bridge 有 **62.3% 的「事务时间占用率」**—— 即这次串行探测的墙钟里,有 62.3% 花在了单次耗时 ≥1 秒的 `/health` 请求内部。退化成段出现:约 130–155 秒坏、约 50–65 秒好。坏时单次 5–30 秒。
> **三套仪器互相印证**:
> - 仪器一(本单,curl 串行采样):600 样本,p50 2.7 毫秒 / p95 11.96 秒 / max 30.31 秒;
> - 仪器二(本单,node fetch —— 完全不同的 HTTP 客户端,另一时段):load 5.7–7.0 时 12 次里 11 次是 5.4–6.8 秒;
> - **仪器三(Tadashi 独立复现,非本 runner)**:连续 8 次 `curl /health` 得到 **15.9 秒 / 19.1 秒 / 14.6 秒,随后转 1 毫秒,load 6.75**。
>
> ⇒ 三套仪器、三个时段、两种客户端,**都看到同一个形状**:低负载下成段的秒级停顿,然后自己恢复。这不是测量方法的产物。
>
> **与 FLY-1971 记录的今晚实况一致**:「**有点慢 → 完全不响应之间没有预警期**」—— 上面这个形状正是它:健康段 1–3 毫秒,发作段直接跳到 5–30 秒,**中间没有渐变**。这也是为什么「先量出一条平滑曲线再取拐点」这个直觉在这里可能根本不适用。
>
> 原始 CSV、采集脚本、独立客户端的带时间戳输出、精确算法都在 `evidence/`。

**⚠ 三条限定,一条都不能在转述中丢掉**:

1. **它是「威胁前提的观测」,不是可以取代 FLY-1971 的因果模型。** 研究中几处更强的说法**已经撤回**(research.md §B.2 / §B.6)。
2. **62.3% 不是本方案的判据量。** 它是「事务时间占用率」,而本方案的判据量 `b` 是**按调度 tick 计的** `P(latency > 500 ms)`(§2.2)。**两者不可直接比较**,所以现有数据**不能**据此宣布阶段 0 的结局是 A —— 它只是**动机**,阶段 0 要重新量。
3. 已知四个缺陷:观察者效应未排除、串行采样让分位数偏乐观、单一时间窗且紧接一次舰队重启、「零施压」≠「零负载」(research.md §B.5)。

**方案因此变成**:

| | 原计划 | 本方案 |
|---|---|---|
| 第一步 | 直接打多档位 | **阶段 0:先用本方案自己的判据量重新量基线**(只读、多窗口、不需要 founder 排时段) |
| 第一个问题 | 拐点在哪 | **`load average` 够不够格当准入闸门的判据**(决策问题)。「谁导致了延迟」是因果问题,进程外测不了,已移出 |
| 实验数 | 1 个 | **2 个,因为它们互相冲突**:E1 剂量-反应、E2 迟滞(§4.1) |
| 对照 | 无 | E1 有**随机化的 N=0 假处理臂**(不只是前测零区块);E2 用前后基线 |
| 生产阶段 | 一次 42 分钟定阈值 | **阶段 2 只做可转移性检查(不出阈值),阶段 3 才是有重复的标定(出阈值)** |

## 2. 测什么

### 2.1 探针与逐条可执行协议(R3 HIGH-6:恢复完整协议表)

⇒ **只有 L1 < L2 这一段是严格嵌套的**;L3 / L4 走不同下游,分析不得假定单调嵌套。

#### ⚠ L4 降级为诊断,不参与区块判决(R3 HIGH-6)

- v3 给 L4 定的是每区块 6 次 + 「违约率单侧上界 ≤ 5%」。**这两条不可能同时成立**:6 次零违约的单侧 95% 上界是 **39.30%**(已独立复核)。
- 要把 L4 powered 到 5%,每区块需要约 **90 次**发送 ⇒ 远超 §2.3 的 Discord 副作用预算,而且**发送本身就是加给被测系统的负载**。
- ⇒ **L4 不进 §5.2 的区块判决**,只作为**诊断**用于 Q4(退化顺序)。若将来要用它定判据,必须先在 **`spec-stress.md`**(§5.5 的三次冻结之一)里预注册一个**更高层的聚合单位 + 簇感知的不确定性**。

**⚠ L4 没有幂等合同(R4 HIGH-3)**:在 `text` 里塞一个唯一串给的是**关联 nonce(对账用)**,**不是幂等** —— 该路由没有去重合同,**重试会真的发出重复消息**。

⇒ **L4 的超时后处理规则**:
- **禁止自动重试**;
- 先用 nonce **对账**:实际送达 ⇒ 记 `late_delivered`,**计入副作用预算,并作为 censored / 下界的诊断证据保留在尾部里**(不是从延迟分布里删掉);未送达 ⇒ 记 `failed`;对账不出来 ⇒ 记 `unreconciled` 并**按送达计入预算**(保守方向)。

### 2.2 采集架构(R3 HIGH-1 + R4 HIGH-1:采集器改为**区块级**分离)

**v3 的错误**:哨兵每 2 秒,诊断可在飞 60 秒 —— 空闲时启动诊断,下一个 tick 就要么跳过、要么超预算、要么把诊断掐掉。
**v4 的错误**:改成 30 秒子区块仍不成立 —— 一个在诊断子区块第 20 秒发出的 60 秒诊断,会**越过边界**跑进下一个哨兵子区块;在边界取消它又改变了已声明的 60 秒 censoring 合同,而且**取消也停不掉 Bridge 侧已在跑的同步工作**。

**v5:采集器类型在**区块**层面分离,并加排空间隔。**

```
[ 哨兵区块 300s ] [ 隔离 30s ] [ 诊断区块 180s ] [ 隔离 ≥60s ] [ 后置对照门 ] [ 下一区块 ] …
                                                   ↑ 最小隔离期,不是「保证排空」
```

- **一个区块只跑一种采集器** —— 不存在跨采集器的在飞冲突;
- **诊断区块的准入规则**:只有当**整个 60 秒超时都放得进本区块剩余时间**时才允许发起一个诊断样本,否则本区块不再发起;
- ⚠ **60 秒隔离期是「最小隔离期(quarantine)」,不是「服务端已排空」的保证(R5 MEDIUM-5)**:客户端超时到了并不代表 Bridge 侧或其下游的工作停了,系统里**没有**任何服务端最大执行时长或完成信号能给出 60 秒这个上界。
  ⇒ 因此隔离期之后必须再过一道 **后置对照门**:对推断用的结局量做基线等价 / 残留检验;**过不了 ⇒ 下一区块标 `contaminated`,并延长恢复或停止**。真正要证明排空,需要服务端的请求完成埋点(属 Q6 的另案)。
- ⚠ **A/A 检验的定位要说准**:它是「在给定的两种探针节奏下,观测到的差异有没有超过无害界」的**经验比较**,**不是**「服务端没有堆积」或「探针零影响」的证明。文档不得越过这个边界。

#### (a) SLO 截止哨兵 —— 唯一的判决数据源

| 端点 | SLO 截止 | tick 间隔(**严格 > 截止**) | 300 秒哨兵区块内的 tick 数 | 零违约时的单侧 95% 上界 |
|---|---|---|---|---|
| **L1** | 500 ms | **2 秒** | **150** | **1.98%**(⚠ **仅独立性假设下**) |
| **L2** | 2 s | **3 秒** | **100** | **2.95%**(⚠ **仅独立性假设下**) |

- L1 与 L2 哨兵在同一哨兵区块内**并行**跑(各自独立的单调栅格、各自的在飞预算 1)。这属于**固定的探针节奏**,由 A/A 覆盖;
- ⚠ **上面两个上界是「独立性假设下」的,不构成「留了相关性余量」的证明(R5 HIGH-3)**。判据要的**有效样本量**约 **59**(零违约时上界才降到 5% 以下:n=58 → 5.03%,n=59 → **4.95%**)。
  ⇒ 换算成设计效应(design effect)容忍度:**L1 只容得下 deff ≤ 150/59 = 2.54,L2 只容得下 deff ≤ 100/59 = 1.69**。
  ⇒ 而一个 300 秒区块只覆盖初步观测到的约 190 秒周期的 **1.6 个** —— **这两个容忍度都谈不上自明地保守**。
  ⇒ **必须先在阶段 0 用预注册的方法估计 / 保守界定设计效应**,再据此反推每个端点需要的区块数与时长(§5.3);**在拿到这个界之前,不得声称有相关性余量**。
- 结果四选一:**met** / **missed**(到截止仍未返回,主动取消)/ **error** / **timer_late**(调度器自身迟到 > 栅格的 20%);
- ⚠ **在飞预算是客户端侧的**。取消 `fetch` **不能**停止 Bridge 侧已在跑的工作(`/health` 根本不看请求对象)。

##### ⚠ `timer_late` 是「与处理相关的缺失」,不能直接从分母里删(R4 HIGH-2)

宿主负载本身就会让调度器迟到 ⇒ **被删掉的 tick 正是高负载那些**。所以:

- **认证用(安全方向)**:把 `timer_late` **计为违约**,得到**最坏情形上界** —— 判决用这个;
- **描述用**:另报把 `timer_late` 排除的**最好情形**下界;两个数都必须出现在汇总里;
- **因仪器失效而作废的区块** = **「未能认证为安全」**,它必须**把阈值往下压**(即阈值不得高于该区块的达成 load),**绝不能从剂量-反应证据里凭空消失**。

#### (b) 低频诊断样本 —— 只描述形状,不参与判决

只在诊断区块内跑,串行,每 10 秒一次;记四时间戳 + 在飞数;超 60 秒记 **censored**(带已等时长)。⚠ 有 censoring 时分位数可能**不可识别** ⇒ 报**下界**并明说。

#### (c) 对照数据 —— **不由本探针采集**(Tadashi 裁定,2026-08-23)

**外挂的协变量采样器已整个删除。** 判据量 `b` 由哨兵单独产出;解释 `b` 所需的对照数据**另有权威来源**:

| 对照量 | 权威来源 | 为什么不自己采 |
|---|---|---|
| 事件循环延迟 / CPU 元凶归因 | **Bridge 本体内建仪表(FLY-1995)** —— 事件循环归因 + CPU 元凶自动留证 | 内建仪表能看到进程**内部**,外部 `ps` / `top` 永远只能看到聚合数字。这正是 §2.4 说「真做机制归因需要可改代码的 Bridge」的那件事,现在它已经存在 |
| 机器内存水位 / 压力档位 | **`machine-watermark.ts` 现有传感器**(生产在跑,持续记录) | 它就是 FLY-1142 阈值的**判定者本人**;外挂再算一份只会有第二套口径 |
| `pressure_hold` 是否置位 | 探针 preflight **仍然读**(`mode=ro`),但作为**开跑前的安全闸**,不作为时间序列协变量 | 安全闸必须由要开跑的那个进程自己确认 |
| Bridge 身份 / `buildSha` / worker PID | 探针**仍然读**,作为**主体围栏**(采集前 + 采集后各一次) | 换了实例的数据不可比,这是判据有效性的一部分,不是协变量 |

**为什么砍**:① 它已经**冗余** —— 上面两个权威来源都在生产里跑着;② 外挂重算一份口径**容易错**,而且错了很难发现。实证:我这份采样器的 `free_pct` 把 `speculative` 放进了分子、分母漏了 `throttled` 和 `compressor`,同一份 fixture 上权威口径读 **20.0%**,我读 **43.0%** —— 差一倍多,而它本来正是要摆在权威传感器旁边做对照的那个数;③ 它是采集器里最后一处**后台进程生命周期**面,而真 Codex 已经**连续三轮**在子进程回收上找到缺陷。

##### 读数指南:free% 的权威口径

分析阶段读 watermark 数据时,`free%` 的定义以 `packages/teamlead/src/bridge/machine-watermark.ts:46-86` 为准:

```
free% = (free + inactive) / (free + active + inactive + speculative + throttled + wired down + occupied by compressor)
```

七个桶,**缺任何一个则整条读数作废**(不是用部分分母凑一个数)。⚠ 常见错法有两个:把 `speculative` 算进**分子**;分母漏掉 `throttled` 与 `compressor`。两者都会把机器读得比实际更宽裕。

> ⚠ **PID 语义仍是硬要求**(用于主体围栏):进程树是 `npm exec tsx` → `tsx cli` → **真 worker `node`**。量错 PID 会得到「Bridge 很闲」的假读数(实测:父进程 `%CPU 0.0`,真 worker 同时刻 `97.9`)。

### 2.3 L3 / L4 / L5 节奏与副作用预算

| | 每区块 | 全场预算 | 备注 |
|---|---|---|---|
| L3 | 6 次(**诊断区块内**,即 E3) | Linear 调用 ≤ 500 次 | **429 必须与 Bridge 延迟分开统计** |
| L4 | 6 次 | **实际送达**的 Discord 消息 ≤ 500 条 | **仅诊断**,不进判决 |
| L5 | 3 次 | 仅隔离房 | 见下 |

**L5 契约**:
- `t0` = **发出刺激之前**;刺激 = 向隔离房专用测试收件人投递带唯一 nonce 的 mailbox 消息;
- `t1` = 该 nonce 行的 `delivered_at` 可被**只读**读到的时刻(200 ms 轮询,`mode=ro`);
- 报两个数:**`enqueue→ACK`(= t1 − t0,主指标)**、`CLI返回→ACK`(次要);
- **必须记录 CLI 返回时 `delivered_at` 是否已置位** —— 若已置位,次要指标塌成约 0,**不得使用**;
- 精度 ±200 ms,随数字一起报。

### 2.4 ⚠ 机制归因(Q6)不在本方案内

`top` 报的是**整个进程**的 CPU(含 native / worker-pool 线程),不是主线程事件循环占用;并发请求延迟相近只说明排在同一个服务端队列;延迟与 CPU 都是同一 episode 的**结果**;load 的同期相关性接近零也**不能**排除滞后 / 非线性 / 取值范围截断的效应。

⇒ 这些量**只用于排除,不用于证实**。真做机制归因需要**可改代码的 Bridge** + `perf_hooks.monitorEventLoopDelay()` / `eventLoopUtilization()` + **嫌疑工作的开关对照**。**另案 = FLY-1995**(Tadashi 已立:「事件循环发作性烧满 + GatePoller orphan 无界重扫」,挂 1954 族,已提 Urgent;验收含「为 FLY-1986 方案提供测量面」)。**本节点不做。**

## 3. 阶段

### 阶段 0 —— 基线(只读;**不需要 founder 排时段**)

- **窗口** ≥3 个,每窗 ≥60 分钟,不同时段,**至少一个在舰队重启后 >4 小时**;
- 探针:**L1 + L2 哨兵**(首轮就跑这个)。诊断样本与 A/A 见本节末尾的裁定说明;**协变量不由探针采**,对照数据取自 Bridge 内建仪表(FLY-1995)+ `machine-watermark.ts` 传感器,见 §2.2(c);**L3 / L4 / L5 不跑**;
- ⚠ **阶段 0 不启用准入静默**(§6.1 第 3 条只适用于施压阶段)—— 它是只读的,不应挡住真实工作;
- **A/A 自校准**:同窗内交替疏 / 密两种探针节奏各 ≥10 分钟,判据是**有把握度的等价检验** + 预先声明的无害界,**不是「看不出差异就算过」**(后者可能仅因把握度不足而通过)。
  ⚠ **A/A 与诊断采样已按 Tadashi 裁定(2026-08-23)移出 Phase-0 采集器,列为阶段 0 之后的后续能力** —— 见 §16.1。阶段 0 首轮先只跑哨兵;要做 A/A 时另起一个独立工具或另一节点,**不再往同一个 bash 脚本里塞并发**。

**结局判定 —— ⚠ 用置信上界,不用点估计(R3 HIGH-4)**:

设 `b_ub(L1)` / `b_ub(L2)` = 该窗口两个端点各自违约率的单侧 95% **置信上界**,`SLO` = §5.2 的生产判据(建议 5%)。

⚠ **门必须是 L1 与 L2 的合取(R5 MEDIUM-6)**:§5.2 的安全区块要求**两个**端点都达标,所以阶段 0 的门也必须两个都过 —— 否则会从一个**根本不可能满足最终双端点合同**的基线放行去压测。L1 过而 L2 不过 ⇒ **不放行**。合取门的置信 / 多重比较处理写进 `spec-baseline.md`。

| 结局 | 判据 | 下一步 |
|---|---|---|
| **B** | **`b_ub(L1) ≤ SLO` 且 `b_ub(L2) ≤ SLO`**,且**两个端点**都过跨窗口等价检验 | 进阶段 1,**可产出阈值** |
| **A** | **任一**端点 `b_ub > SLO` | **不打高负载**,走 §3.1 |
| **N** | 跨窗口 `b` 差异超等价界 | **不打高负载**,报「基线非平稳」 |

> ⚠ **v3 的结局 C 已删除**。理由(R3 HIGH-4):C 的定义是 `5% < b ≤ 20%` 却仍放行去定阈值 —— 但如果**零附加负载**时服务本身就违反 SLO,那么**不存在任何一条负载阈值**能让上界通过。扣掉背景可以估出「增量伤害」,但**变不出一个可运行的工作点**。
>
> ⇒ 若团队仍想在 `b_ub > SLO` 的情况下做一次**科学性**的压测(只为理解剂量-反应),那必须:**单独标注为科学性运行、取得明确的风险批准、并在报告首页写明它不能产出准入阈值**,直到基线服务本身达标。

⚠ **现有 1032 秒的初步数据不能用来判结局** —— 它测的是「事务时间占用率」(62.3%),不是本方案的 `b`(按调度 tick 计的 `P(latency > 500 ms)`)。**两个量不可直接比较。** 阶段 0 必须用新判据量重新量。

## 4. 实验设计

### 4.1 ★ 为什么必须拆成两个实验

洗脱**成功** ⇒ 每个处理都从基线附近开始 ⇒ **没有连续的状态轨迹,迟滞无从谈起**;洗脱**失败** ⇒ 处理后的零区块被残留污染 ⇒ **它不是下一个处理的干净对照**。再加上「循环内档位随机化」,「上行」「下行」这两个词就没有意义了。⇒ 拆开。

#### E1 —— 剂量-反应(Q1 / Q2 / Q4)

**⚠ 必须有随机化的 `N=0` 假处理臂(R3 HIGH-2)**,不能只靠「处理前的零区块」:

- 每个随机化的**测量窗口**都收到一个 worker 处理,其中 **`N=0` 是一个真正的处理臂**(假处理 / sham):**同样的爬坡、静置、测量时序,只是不起 worker**;
- 没有它的话:所有测量窗口都带非零处理,**随机化只识别得出各非零档位之间的对比**,识别不出「相对于不施压」的绝对效应;而且在一个约 190 秒自发周期的系统里,「以恢复过的前区块为条件」本身就会造成**向均值回归**,哪怕根本没加负载。

**⚠ 每个臂必须有三段,不能只有「休息 + 测量」(R4 HIGH-4)**:v4 的 `休息 3 分 + 测量 3 分` 漏了**加载爬坡**。休息段必须在 `N=0` 才能证明洗脱,那么 worker 只能在测量开始时才起 —— 于是**瞬态混进了稳态响应**;若在休息段就起 worker,洗脱证明就作废了。

```
一个 E1 臂 = ┌ ① 基线 / 洗脱段 ┐ ┌ ② 处理爬坡段 ┐ ┌ ③ 测量段 ┐
             │  N=0,180 秒    │ │ N=k,180 秒   │ │ 哨兵区块  │
             │  过等价性洗脱门 │ │ **不采推断样本**│ │  300 秒   │
             └────────────────┘ └──────────────┘ └──────────┘
                                        ↑ 必须先过「达成 load 稳定门」才进 ③

一个 E1 循环 = 若干个臂,N 在 {0, 2, 4, 6, 9, 12, 16} 中随机排列;N=0 是其中之一(假处理臂)
```

- 臂长 = 180 + 180 + 300 = **660 秒 ≈ 11 分钟**;
- ⚠ 7 个臂 = 77 分钟 > §6.1 的 **50 分钟同机场次上限** ⇒ **必须做场次分层**:
  - 每个同机场次 **≤ 4 个臂(≈ 44 分钟)**;
  - **每个场次必须至少含一个 `N=0` 假处理臂**;
  - 臂在场次内随机、场次做分层;
  - **`session` 必须作为区组因子进入分析模型**(否则场次效应会被算成处理效应)。

- **因果对比 = 「N=k 的臂」vs「N=0 的假处理臂」**(**同一场次内**,随机分配 —— 跨场次比较必须在模型里带 `session`);
- **洗脱证明**:进入下一个测量窗口前的休息段,必须通过一个**有把握度的基线等价检验**(用的是**推断所需的那些结局量**,不是只看 L1 违约率的一个点),而不是 v3 的「违约率不超过基线上界」;
- **两种情况必须分开命名与记账**(v3 的 `carryover` 一词含混):
  - `contaminated_next` —— **后一个**区块因为前一个的残留而不干净 ⇒ 后一个出统计;
  - `persistent_effect` —— **前一个**处理造成了持续到休息段的退化 ⇒ 这是**该处理的一个结果**,**必须当作伤害记进结论**,不能悄悄剔掉。
- ⚠ **持续伤害必须进入安全规则本身(R4 HIGH-4)**:一个 `N` 即使在**测量窗内**满足 SLO,只要它之后造成 `persistent_effect`,**它仍然不能用来定义安全阈值**。`spec-stress.md` 必须写死持续伤害的**概率与恢复时长**上界,超过即该 `N` 不可用。

#### E2 —— 迟滞(Q3)

**⚠ v3 的「方向平衡」在物理上没定义(R3 HIGH-3)**:轨迹从基线出发上行到峰再下行 —— 那么「先下后上」的轨迹要怎么开始?不先把系统调到峰值就没有可下降的状态,而那个调节过程本身就是一段不同的历史。

**v4 改为:定义两种可独立初始化的扫掠。**

| 扫掠 | 初始化 | 过程 |
|---|---|---|
| **上行扫掠 (ASC)** | 从**已证明的基线**开始 | N 单调递增到峰 |
| **下行扫掠 (DESC)** | 从**固定时长的峰值调节段**开始(dwell,时长预注册) | N 单调递减到 0 |

- ⚠ **每条扫掠都必须独立初始化(R4 HIGH-5)**。v4 只规定「对与对之间」有门,那么 ASC→DESC 这一对里 DESC 继承了 ASC 的全部历史,DESC→ASC 那一对里 ASC 又需要 DESC 之后的恢复证明 —— **两者初始条件不同,「对内顺序平衡」并不能让 ASC/DESC 的对比可交换**。
- **v5 的扫掠协议(每条扫掠自成一个场次)**:
  ```
  ① 证明基线 → ② 该扫掠规定的调节(ASC:无;DESC:峰值 dwell 300 秒)
             → ③ 采集扫掠(5 个区块 × 300 秒)
             → ④ 证明恢复(过等价门)才允许下一条扫掠
  ```
  ⚠ **③ 的每一个测量区块之前也必须有非推断的爬坡 / 稳定段(R5 HIGH-4)** —— v5 让 E2 在相邻的 300 秒测量区块之间直接改 worker 数并立刻采样,而 `load1` 是平滑量、Bridge 还带着上一档的状态 ⇒ **同一达成 load 区间里的 ASC 区块与 DESC 区块,会含有不同的「上一档剂量 + 距离阶跃多久」的混合** ⇒ **把普通的阶跃响应滞后当成迟滞报出去**。独立初始化解决不了这个**扫掠内部**的混杂。
  ⇒ 每个 E2 测量区块 = **爬坡 180 秒(不采推断样本,过达成 load 稳定门)+ 哨兵区块 300 秒 = 480 秒**,与 E1 用同一套达成 load 合同。
  ⇒ **E2 的档位数减到 4**(否则装不进 50 分钟场次):
  - ASC 场次 ≈ 180 + 4 × 480 = **35 分钟** ✓;
  - DESC 场次 ≈ 180 + 300 + 4 × 480 = **40 分钟** ✓;
  - (若坚持 5 档:ASC 43 分 / DESC 48 分,几乎顶满 50 分钟上限,不留恢复余量 ⇒ **不采用**。)
  ⇒ **另一条合法路线**:把 E2 重新定义成**动态轨迹实验**,其估计量**显式包含「距离阶跃的时间」与「上一档剂量」**。本方案选前者(稳态分档),因为它与 E1 共用同一套合同,便于外包执行。
- **配对方式**:把**时间上相邻、各自独立初始化**的一条 ASC 与一条 DESC 配成一对;**对内顺序按场次随机并分层**;**`session` 与 `pair` 都进分析模型**;
- **≥3 对**;
- ⚠ 若 ④ 的恢复门过不了,**不许**开始下一条扫掠,也**不许**用重启来重置(§6.4)—— 以 inconclusive 收尾;
- **迟滞的估计量必须写死**:比较 **ASC 与 DESC 中达成 load 落在同一预注册区间的区块对**,估计其违约概率之差;
- **若下行结束仍无法证明恢复**:结论是三选一 —— **恢复点低于本次观测范围** / **存在持续效应** / **进入吸收态**,并**以 inconclusive 收尾**。⚠ **不能**读成「不是负载现象」,也**不得**为了继续跑而重启 Bridge(§6.4)。

#### E3 —— 诊断实验(**可选**;Q4 的唯一来源;R5 HIGH-1)

⚠ **v5 的漏洞**:§2.2 定义了 180 秒诊断区块 + 隔离期,Q4 又依赖 L3 / L4 的诊断分布,但 §4.1 的 E1 臂里**根本没有诊断区块**,§4.4 也没给它预算。加进去(180 + 60)会让臂变成 15 分钟,4 个臂就装不进 50 分钟场次了。⇒ 实现者只能要么漏掉 Q4 的观测,要么在预注册**之后**自己发明第二套日程 —— 后者会改变处理曝光、残留、Discord / Linear 预算、场次数和总风险窗。

**v6 的处理:把诊断数据做成一个独立、可选、可执行的实验 E3。**

```
一个 E3 臂 = ① 基线 / 洗脱 180s(N=0,过洗脱门)
           → ② 处理爬坡 180s(N=k,不采样,过达成 load 稳定门)
           → ③ 诊断区块 180s(L1/L2/L3/L4 的诊断样本)
           → ④ 最小隔离 ≥60s + 后置对照门
           = 600 秒 ≈ 10 分钟
```

- `N` 取值、顺序随机化、洗脱 / 残留规则、隔离与后置门:**与 E1 完全同一套合同**;
- **每场次 ≤ 4 臂(≈40 分钟)**,`session` 进模型;
- **与哨兵证据的配对方式**必须在 `spec-stress.md` 里预注册(按 `N` 与场次配对,不是按时间就近配对);
- ⚠ **诊断样本是串行发的 ⇒ 采集顺序本身就会制造出「谁先坏」(R6 MEDIUM-7)**,而 Q4 要描述的恰恰是这个顺序。
  ⇒ `spec-stress.md` **必须预注册**:诊断区块内**各端点的发射顺序每轮随机化**(或用足够轮次做拉丁方平衡),并在报告里**把「采集顺序」作为协变量显式呈现**;做不到就**不报 Q4**。
- **E3 是可选的**。⚠ **不跑 E3 ⇒ Q4 不在本单的结论清单里**,报告必须明写「未测」,不得用 E1 的哨兵数据去暗示退化顺序。

### 4.2 档位的定义

- **处理 = worker 数量 `N`**(A 轨并发度)—— 这是真正能控制的旋钮;
- **达成 load 只作为测量到的 x 轴**,不是设定值;
- 每区块报「N = k,达成 load 中位数 = x,IQR = y」;
- 稳定性容差:非零区块内 load1 的 IQR ≤ 该区块 load 中位数的 15%,否则标 `unstable`、出拟合、留原始数据;
- **`N=0` 区块有自己的规则**:没有「目标 load」,只有**本底稳定性**要求 —— IQR > 中位数的 25% 则该组标 `ambient_unstable`;绝对上限见 §6.1;
- ⚠ 「超目标 1.5 倍熔断」对 `N=0` 无定义,`N=0` 用绝对上限熔断。

候选 `N ∈ {0, 2, 4, 6, 9, 12, 16}`。**先做一次探路(pilot)** 把 N 映射到达成 load,确认能覆盖 15–50 区间。⚠ **探路数据必须永久排除在主推断之外**(§5.5)。达成 load 硬顶 **60**。

### 4.3 施压负载

| 轨 | 做法 |
|---|---|
| **A 轨** | N 个并发 worker 跑**预注册、白名单化、并发安全**的测试子集 |
| **B 轨** | 2–3 个档位用**真 runner** 复现同一达成 load |

- 明确列出允许跑的测试文件 —— **不是「跑仓库测试」**(仓库里有用 tmux、抢端口、打外部服务、依赖宿主状态的测试);
- 每 worker 用**隔离的临时目录与 repo 路径**;白名单先在无生产 Bridge 的环境验证过并发安全;
- worker **循环补跑**以维持负载(区块结束看**时间**,不看作业完成)。

> A/B 一致性是 Q1 的证据,但⚠ **未重复的 2–3 个匹配点不能支持「load 够格」**,且它测的是**工作负载可转移性**,**不等于**证明了 §5.8 的准入判据。

⚠ **场次长度受 §6.1 的 1 小时准入租约硬约束**(选项 1b / 阶段 2 / 阶段 3)⇒ **每场 ≤ 50 分钟**。
⚠ 因此 E1 / E2 都**必然跨场次**,所以 `session` **必须**作为区组因子进入分析模型(§4.1)。
⚠ 每区块 300 秒的测量是按 §5.3 的把握度定的**下限**;若 §5.2 的判据从 5% 收紧到 1%,时长要按 §5.3 反推加长。

> **减成本的正确旋钮(按优先级)**:
> 1. **不跑 E3**(省 ≈4 小时)—— 代价是**明确放弃 Q4**,报告写「未测」;
> 2. 把 `N` 的候选从 7 减到 5 ⇒ E1 降到 ≈3.3 小时;
> 3. **绝不减重复次数**(§10)。
>
> ⚠ 上表的区块时长是按**独立性假设**算的。**§5.3 的设计效应一旦估出来大于 L1 的 2.54 / L2 的 1.69,时长还要往上加** —— 届时必须重算本表,并按 §5.3 的决策规则处理「装不进一个场次」的情况。

## 5. 判据(全部在取数**之前**定死)

### 5.1 三个互不混淆的契约

| 契约 | 定义 | 用途 |
|---|---|---|
| ① 哨兵截止 | 到 SLO 截止即取消,记 met / missed / error / timer_late | **判决的唯一数据源** |
| ② 诊断 censoring | 低频样本超 60 秒记 censored | 描述长尾,不参与判决 |
| ③ 紧急熔断 | §6.2 | 安全,不是判决 |

### 5.2 区块级服务判决(建议值,**需 founder / Lead 拍板**)

| 探针 | 判据 |
|---|---|
| **L1** | `P(latency > 500 ms)` 的**单侧 95% 置信上界 ≤ 5%** |
| **L2** | `P(latency > 2 s)` 的单侧 95% 上界 ≤ 5% |
| L3 | **仅诊断**,不进判决(外部依赖) |
| **L4** | **仅诊断**,不进判决(§2.1 —— 6 次采样的上界是 39.30%,不可能达标) |

⚠ **「Bridge 本地服务拐点」这个结论必须有 L1 / L2 的本地证据支撑**;L3 / L4 的外部失败(Linear 429 / Discord 限流)必须单独归因。

### 5.3 样本量必须由把握度推导

零违约时 `P(违约)` 的单侧 95% 置信上界(已独立复核):

| n | 上界 |
|---|---|
| **6**(v3 给 L4 的采样数) | **39.30%** ⇐ 这就是 L4 被降级为诊断的原因 |
| 18 | 15.33% |
| 36 | 7.98% |
| **90**(3 分钟 × 2 秒 tick) | **3.27%** |
| 270 | 1.10% |
| 540 | 0.55% |

- §5.2 定 **≤5%**,因为 n = 90 时上界 3.27% < 5%,可证;
- **若 founder / Lead 坚持要 1%**,必须加长曝光或增加重复,时长按上表反推并写进 §4.4;
- 上表**假装样本独立**,实际有强序列相关 ⇒ **有效样本量更小**;
- 测量时长与重复次数由「SLO + MIE + 相关性假设」推导,§4.4 的数字是**下限**;
- **3 个区块对 block bootstrap 偏少**,除非把握度计算证明够用。

### 5.4 分析单位与背景扣除

- **分析单位 = 区块**(不是单个样本 —— 一个多分钟 episode 内的样本强自相关,当独立是**伪重复**);
- 效应量 = **`N=k` 的测量窗口 − 同循环内 `N=0` 的假处理窗口**;
- 不确定性用 **block bootstrap 或随机化检验**;
- 「没有显著差异」≠「没有差异」⇒ 说「无影响」必须用**等价检验**配预注册等价界;
- ⚠ 撤回 v1 的说法:**「b 大就一定测不了」是错的** —— 决定成本的是 **MIE**,不是 `b`。

### 5.5 ★ 预注册要分三次冻结(R3 MEDIUM-7)

v3 只要求「第一个处理区块之前冻结」—— **太晚**:阶段 0 的数据已经被用来判 A/B/N、估相关性、做 A/A 等价检验、定样本量。那等于**看过数据之后再定判它的规则**。

| 冻结点 | 文件 | 必须包含 |
|---|---|---|
| **① 第一个阶段 0 窗口之前** | `spec-baseline.md` | `b` 的精确估计量、置信方法、非平稳等价界、A/A 无害界与把握度、结局 A/B/N 的判据 |
| **② 探路之前** | `spec-pilot.md` | 探路怎么把 N 映射到达成 load、它可以改变最终设计的哪些部分。⚠ **探路数据永久排除在主推断之外** |
| **③ 第一个推断用处理区块之前** | `spec-stress.md` | 唯一主估计量 + 拐点定义、重采样单位与次数、缺失 / censored / unstable / contaminated_next / persistent_effect 的处理规则、多重比较规则、数值 α / 把握度 / MIE / 等价界、**数值化的可接受假放行率与假拒绝率**、Q1 的样本外评估方案 |

> 探索性方法**可以报**,但**不能用来选结论**。

### 5.6 Q2 / Q3 的估计

- **拐点**:按 `spec-stress.md` 冻结的主估计量拟合,产出**带置信区间**的拐点。**区间跨多个档位 ⇒ 报「未定位到档位精度」+ 还需多少重复。**
- **迟滞**:按 §4.1 E2 的估计量,≥3 对,区块级检验。
- **阈值建议 = 「违约概率单侧 95% 上界仍满足 §5.2 的最高达成负载」** + 单独论证的安全余量(余量是政策选择,由 founder / Lead 定)。
- 若测到迟滞:阈值取自**恢复侧**曲线 —— 落在触发与恢复之间的值是只进不出的陷阱区。

### 5.7 Q4

⚠ **Q4 是纯描述性的,不产出机制结论(R4 MEDIUM-8)** —— v4 写的「依次 ⇒ 排队饱和 / 同时 ⇒ 共享资源被占」与 §2.4 的机制边界自相矛盾,已删。而且 L3 / L4 **已经没有判决阈值**了,谈不上「越过各自的阈值」;它们的诊断区块也**与哨兵观测不同时**。

**v5 的做法**:在 `spec-stress.md` 里预注册一组**诊断性的退化摘要**(各探针的诊断延迟分布随 `N` 的变化)**并带时间对齐的不确定性说明**;报告里把探针之间的先后模式**只当机制线索**,交给 Q6 的另案。

### 5.8 ★ Q1 的精确估计量(R3 HIGH-5)

⚠ v3 只说「load 够不够格」,没说清是**什么时刻的 load**、**预测什么**、**误分类怎么定义**。而现行闸门做的是一个**很具体**的动作:在**准入一个 runner 之前**读 `loadavg()[0]`,决定放不放。

**Q1 拆成两问,并说明各自能支撑什么:**

#### Q1-concurrent(本方案一定能答)

> 给定**同期**达成 load,能否可靠地分开「本区块满足 SLO」与「不满足」?

- 特征 = 区块内 load1 中位数;标签 = 该区块是否满足 §5.2;
- 报 ROC / AUC,以及在**任何**一条 load 阈值上的假放行率与假拒绝率;
- **样本外评估**(leave-one-cycle-out);
- ⚠ **它能支撑的结论有限**:若**不存在任何**一条 load 线能同时把两种错误压到 `spec-stress.md` 规定的上界 ⇒ **load average 不够格**(这是一个有力的**否定**结论)。但**反过来不成立** —— 它通过了,**不等于**「准入前读 load 能预测准入后会不会坏」。

#### Q1-full(⚠ **与同机准入静默直接冲突,默认出范围**;R4 HIGH-6)

**先说冲突**:§6.1 要求同机施压期间**开着准入静默**(它拒绝**一切**新 runner),而 Q1-full 要求**随机地放进一个实验用 runner**。**两者不可兼得。** 绕过闸门去放,测的就不是真实的准入动作了。

⇒ **除非**存在一条**经授权的选择性准入机制**(只放实验候选、其它工作仍静止),否则:

> **Q1-full 明确出本方案范围**,本单只保留 Q1-concurrent 的(否定方向的)结论。

**若 founder 授权做 Q1-full**,它必须自带独立的执行与授权协议,至少写明:执行环境、候选工作负载的分布、隔离无关准入的机制、随机化单位、时间视界 `H`、停止规则、**以及是否真的走生产准入路径**。

> 给定**一次准入机会之前**那一刻的 `load1`,预测**再放进一个有代表性的 runner** 是否会让 Bridge 在 **H 分钟内**违反 SLO?

- **特征必须在决策时刻可得**:准入动作**之前**的 `load1`(而不是事后区块的中位数);
- **处理 = 随机化地「放 / 不放」一个增量 runner**;
- **标签** = 决策后 H 分钟内是否违反 §5.2(`H` 在 `spec-stress.md` 中预注册);
- ⚠ **假拒绝不是可观测的个体标签(R4 HIGH-6)**:「没放,但其实放了也不会坏」对**单次**准入机会**不可观测** —— 同一次机会的两个潜在结果不可能都看到。
  ⇒ 误差必须定义成**潜在结果框架下的组级风险**(如「放行臂的违约风险 − 不放行臂的违约风险」),由随机化的两臂估计并写明假设;**绝不能**给某个对照个体贴「本来是安全的」标签;
- **评估对象是「阈值 + 余量」这个完整策略**,样本外评估;
- ⚠ **leave-one-cycle-out 救不了一个在决策时刻拿不到的标签** —— 所以特征时刻必须是决策前,这不能靠事后分析补。

> **如果只做 Q1-concurrent**:报告必须明写 **「本单没有标定 FLY-1971 的准入动作,只判定了 load 与同期服务状态的可分性」**,不得让读者以为阈值已被验证。

## 6. 安全护栏

### 6.1 开跑前置(任一不满足则不开跑)

1. `/health` 的 `buildSha` == 被测目标。
2. `pressure_hold` 未置位 —— 经 §2.2(c) 的 `mode=ro` 途径读(**已实测,写被引擎拒绝**)。
3. ★ **全舰清空、单独跑(Tadashi 批注写死,来源:Annie 在频道亲口提的担忧)** —— ⚠ **仅适用于施压阶段(1b / 2 / 3),不适用于只读的阶段 0。**
   同机施压段的**硬前置**,三条缺一不可:
   - **founder 排出一个空窗**(不是「找个看起来闲的时候」,是明确排期);
   - **全舰清空**:窗口内**没有任何真实 runner / 评审 job / QA 房在跑**;
   - **单独跑**:压测是该窗口内**唯一**的负载来源。
   > 理由不只是数据干净(与真实工作重叠会污染达成 load 与服务结果),更是**风险**:我们是在故意把机器推向它已经会自发卡死的区域。
   ⇒ 下面第 3.1–3.3 条是把这个前提**机械化**的手段,不是它的替代品。

3.1 **无新工作会被准入**
   - ⚠ **源码实测**:`StateStore.setAdmissionPause()` 硬性要求 `durationSeconds` 为 **1..3600** 的整数,超出直接抛错 ⇒ **准入静默的租约上限是 1 小时**。
     ⚠ **这个上限是护栏,不动它**(Tadashi 批注)。方案只允许两种处理:**把场次切进上限内**,或**分段续租**(续租须单独授权且由独立监督进程执行)。**不得提议改源码上限。**
   - ⇒ **同机施压场次必须 ≤ 50 分钟**(留 ≥10 分钟的恢复余量),不得排 132 分钟的场次;
   - ⚠ **不能靠 `/health` 读剩余租约(R4 MEDIUM-7)**:`remainingSeconds` 在 L1 响应体里,而**正是在我们要诱发的那种故障下,L1 会超时、根本没有响应体** ⇒ 监督进程会失明。
     ⚠ **而且「权威到期时刻」在 HTTP 上根本拿不到(R6 HIGH-4,已复核源码)**:`StateStore.setAdmissionPause()` 内部有 `paused_until`,但 `plugin.ts` **把它剥掉了**,只回 `admissionPause.remainingSeconds`;而在 POST 路径上这个值是**请求的时长**,不是**响应到达时的剩余时长**。⇒ 若按 `响应时刻 + remainingSeconds` 算 deadline,会**比服务端真实到期更晚**(正是危险方向,在一个本就会自发卡顿的 Bridge 上更糟)。
     ⇒ **v7 的做法(不改生产代码就能拿到的保守 deadline)**:
     - 在**发出 pause POST 之前**记下监督进程的本地单调时刻 `t_req_start`;
     - **deadline := `t_req_start + 被授予的时长`** —— 必然**不晚于**服务端租约到期;
     - `mode=ro` 直读 `paused_until` 作**额外交叉校验**;`/health` 的 `remainingSeconds` 只作参考;
     - **读不到 / 陈旧一律 fail-closed(按最坏情形)**;
     - **验收**:必须有一个**故意拖慢 POST 响应**的测试,证明 deadline **不会**被这段延迟顺延(§15 第 4e 项)。
   - ⇒ **开跑前**必须满足 `剩余租约 ≥ 计划施压时长 + 恢复预算 + 静止取证时间`,否则不开跑;
   - ⚠ **准入静默只证明「不再放新的」,不证明「已有的已排空」(R6 HIGH-5)**。已准入 / 正在跨越准入屏障的工作、dispatcher 在飞、durable launch claim、readopt 候选 —— 都可能与处理重叠,既污染达成 load 与服务结果,也抬高生产风险。**租约不是资源静止证书。**
   - ⇒ **必须再取一份权威静止证明。代码里已经有现成的**(本轮复核发现):`GET /api/admission/quiescence`(`plugin.ts:1527`,需 token)—— 它**要求 pause 已激活**,并逐项报 `readoptCandidateSessions` / `dispatcherInflight` / `durableLaunchClaims` / `admissionCrossing`;`scripts/host-terminal-cutover.sh:230-236` 已示范**取两次快照**的用法。
   - ⇒ **同机施压阶段的开跑序列(顺序不可换)**:
     1. 建立 pause(按上面的保守 deadline);
     2. 取**两次相隔预注册间隔的 `/api/admission/quiescence` 快照,且两次的每一项分量都为零**;
     3. 才允许起第一个施压 worker。
   - ⇒ **409 / 503 / 任一分量非零 / 超时 / 快照陈旧 ⇒ fail-closed,不开跑**;取证时间**算进租约预算**;**只读的阶段 0 免除本条**。
   - ⇒ 本地 deadline **低于 600 秒即开始收尾**,归零前必须已停止施压(熔断见 §6.2);
   - ⇒ **删除 v3 的替代方案「不在可能来新活的时候跑」** —— 那不是机械可证的护栏。若要续租,必须是**单独授权、由独立监督进程执行**的续租协议,并写进方案。
4. 避开 **00:00 / 12:00** 的定时班车重启窗口;快照当期 launchd 定时任务与 SSE 连接数。
5. **数值化限额(全部钉死)**:

| 限额 | 值 |
|---|---|
| 磁盘可用 | ≥ 5 GB,且预估输出 < 可用的 20% |
| harness 输出速率 | ≤ 1 MB/分钟 |
| Bridge worker RSS | ≤ 2 GB(基线实测约 617–789 MB) |
| 达成 load 绝对上限 | **60** |
| `N=0` 区块本底 load 绝对上限 | **20** |
| 单区块墙钟上限 | 预算的 2 倍 |
| `timer_late` 占比 | > 2% ⇒ 该区块作废 |
| 准入租约剩余(**监督进程本地单调 deadline**) | < 600 秒 ⇒ 开始收尾;开跑前须 ≥ 施压时长 + 恢复预算 |
| **施压后恢复门** —— ⚠ **两段,不是一段(R5 HIGH-2)** | **① 认证段**:累积足够的施压后哨兵观测,把 **L1 与 L2 的违约率单侧 95% 上界都压到 ≤ SLO**。⚠ v5 写的「持续 120 秒」办不到:L2 每 3 秒一次,120 秒只有 40 个 tick,零违约的上界是 **7.22% > 5%**;要到 5% 以下需要 **n ≥ 59 ⇒ L2 至少 177 秒、L1 至少 118 秒** ⇒ **认证段 ≥ 180 秒**(再按 §5.3 的设计效应放大)。<br>**② 保持段**:此后**再持续 120 秒**,全部条件不得跌破。<br>**条件全集**:L1 上界 ≤ SLO **且** L2 上界 ≤ SLO **且** free% ≥ FLY-1142 的 HIGH 线 **且** swapout delta = 0 **且** `pressure_hold` 未置位。<br>**最坏情形总计 ≈ 300 秒 < 预留的 10 分钟** ✓;若设计效应把认证段推到装不下,**要么加大预留、要么缩短该场次的施压段**。 |

6. **dry-run**:所有探针跑通,**且每条熔断路径被人为触发过一次变红**。

### 6.2 运行中熔断(任一触发 ⇒ 降档并中止整轮)

| 触发 | 理由 |
|---|---|
| 任一探针连续 3 次诊断 censored(> 60 s) | 已不可用 |
| 内存进 danger(free% < 8 或 swapout delta > 0,FLY-1142 口径) | 下一步就是 OOM |
| `pressure_hold` 被置位 | **压测把自己的准入卡死了** |
| **监督进程本地租约 deadline 剩余 < 600 秒(施压阶段)** | **租约将到期,新 runner 会暴露在实验里**。⚠ 读不到 / 陈旧 ⇒ **按最坏情形熔断**,不 fail-open |

| 任一 §6.1 第 5 条的限额被越过 | — |
| **Bridge worker PID / start-time 变了** | **被测对象换了**(launchd 可能已把它重启) |

### 6.3 施压进程的强制回收

**shell trap 不够**(终端断了、控制器卡死,trap 不会跑):

- 施压子进程全部放进**记录在案的 process group**;
- **独立的监督进程**(不是 trap)按墙钟看守,在控制器退出 / 收到信号 / 超 deadline / 任一护栏失败 / **准入租约将到期**时,按 **PGID + PID-start-time** 杀掉该组;
- 收尾按 **PID + start-time** 逐个核对已退出,**不用 `pkill` 一把梭**。

### 6.4 授权边界(明确不做)

- ❌ **不重启 Bridge**。FLY-1959 之后重启只走定时班车或 founder 紧急票。
  > ⚠ **launchd 有 KeepAlive** —— 压测若把 Bridge 打崩,它会被**自动拉起**。「我们不重启」≠「不会发生重启」。§6.2 的 PID 变更熔断就是为此。
  > ⚠ E2 若因未能恢复而卡住,**也不许用重启来「重置」** —— 只能以 inconclusive 收尾(§4.1)。

## 10. 交付节奏的诚实说明

本方案比 issue 原设想贵。原因不是把事情做复杂了,而是:

- 自发退化周期(约 190 秒)与原设计的档位时长(6 分钟)是**同一量级** ⇒ 不做重复与对照,拿到的「拐点」可能是相位对齐的产物;
- 单次扫描**没有不确定性** ⇒ 没有不确定性的拐点不能定阈值,只能用来吵架 —— 而这张单的起因正是「不要再吵 144/88/48」;
- 剂量-反应与迟滞在实验设计上**互相冲突**,必须分开跑;
- 准入静默的租约上限是 **1 小时**(源码实测),所以同机场次必须切碎。

**若成本不可接受,正确的取舍是减档位数(牺牲拐点分辨率),不是减重复次数(牺牲结论有效性)。**

| **1** | **CRITICAL**:`--out` 之类**放在最后一个参数**时,`shift 2` 因为参数不够而**失败且不移位** ⇒ `while [ $# -gt 0 ]` **无限空转** | 实测 `timeout 5` 返回 124。一个**专门用来量机器负载**的工具,打错一个参数就变成 100% CPU 的死循环 |
| 2 | `--mode aa` 与 `sentinel` **逐字节相同** —— A/A 自校准**根本没实现** | 而 §3 把 A/A 列为阶段 0 的**必做门**。操作者跑完只会得到「没测出差异」——因为**压根没制造差异**。已实现为真的疏密两种节奏交替(实测 40 秒窗口:full 20 tick vs sparse 4 tick) |
| 3 | 诊断区块也被送进 `summarise_block`,**伪造出干净的认证行** | 一个**超时 60 秒**的 censored 请求会被汇总成「0 违约、`block_valid=true`」,与「诊断永不产出判决」的声明正好相反 |
| 4 | 网格校验**写死 L1/L2**,而 L3 的 deadline 是 0 ⇒ `curl --max-time 0` **完全关闭超时** | 请求再也无法在截止时被取消,「每端点在飞 1、不跨 tick」这条整个设计赖以成立的不变量就没了 |
| 5 | **缺 token 被记成 SLO 违约** | 只要忘记 export 一个环境变量,就会产出一份**看起来完全成立**的「100% 违约」认证结论 |
| 6 | HTTP `000` **把连接失败和截止超时混为一谈** | Bridge 若在区块中途死掉,会被**洗成一个延迟判决**而不是中止 |
| **12** | 契约检查用的 `code_only()` 从 `self_test()` 处截断,而 **`main()` 定义在它后面** | ⇒ 「不调用写端点」「token 不进 argv」「DB 必须 mode=ro」这几条契约**对整个 main 函数结构性失明**。在 main 里加一个写调用,**全部检查照样绿** |

第 12 条尤其值得记:这是**第二层**的「检查永远不会变红」——第一层是检查匹配到自己的源码,第二层是检查**扫描范围**根本没覆盖到最大的那个函数。修好之后,往 `main()` 里注入写端点与 token 泄露两种变异**都立刻变红**。

⚠ 另外,修第 12 条**当场暴露出一个潜伏的**:`set -o pipefail` 下 `code_only | grep -q X` 会因为 grep 命中即退出而 SIGPIPE 掉 sed,**整条管线报失败** —— 检查于是因为与被测属性无关的原因而失败。旧版 `code_only` 用的是 `sed -n '…/q;p'`(提前退出)所以恰好没暴露。已统一改成读完全部输入的 `grep -c` 谓词。

### ⚠ 实现过程中被自己的测试抓到 4 个真 bug

都属于「检查写得永远不会变红」或「用近似当属性」这两类:
   - 三条契约检查 **匹配到了自己的源码文本**,所以恒过 —— 改成只扫 `self_test` 之前的代码段后,变异体立刻变红;
   - `grep -c` 无匹配时**既打印 0 又返回 1**,`|| echo NA` 于是追加了第二行,把一条 CSV 记录劈成两行(字段偏移全错);
   - 「取进程树的叶子」这个 PID 规则是错的 —— **真 worker 自己也有子进程**;
   - **最严重的一个**:用 `pgrep -f 'run-bridge'` 选进程**根本不安全**。实验证实:起一个 argv 里只是**含有**这个字符串的无害 sleeper,它**确实被 pgrep 匹配到**,而且 pid 排在最前 —— 旧规则会**选中它去测 CPU**。(同一类误匹配在 FLY-1482 造成过真实事故。)
     ⇒ 改为**权威选择**:取**正在监听被探测端口**的那个进程 —— 它按定义就是我们在测延迟的那个 Bridge。这同时解决了「生产 vs QA slot」(各自绑不同端口)。多个监听者 ⇒ **fail-closed 拒绝猜**;`pgrep` 降级为只做旁证告警。
