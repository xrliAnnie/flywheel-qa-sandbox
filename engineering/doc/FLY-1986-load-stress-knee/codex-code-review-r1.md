## Summary

Reviewed exact head `dd578e6821ae5c46d49933ae5b97518222eaf945` against `main`. The current code is not safe to certify for production use yet. The most serious remaining defect is introduced by the prior SIGTERM fix: the trap kills the currently tracked children but does not terminate the parent, so the parent resumes and can start another block. A hermetic mock run proved three post-SIGTERM requests, exit code 0, and a one-tick interrupted block reported as `block_valid=true`.

Several requested properties are correct at this head: `pgrep -f 'run-bridge'` is corroboration only and cannot override the `lsof` listening-socket selector; the script parses and its self-test passes under macOS `/bin/bash` 3.2; `${!TOKEN_ENV:-}` removes the old eval injection; the fixed-grid `base + tick * interval` arithmetic is drift-free when its clock is stable; `curl_timed`'s here-doc consumes the first curl `-w` line as intended even when the non-zero curl path appends a fallback line; `summarise_block` counts `timer_late` in the conservative numerator, removes it from both the best-case numerator and denominator, and guards the zero denominator; and the CI step is in the correct exact-order inventory position. Those cleared points do not offset the blockers below.

## Issues & Recommendations

1. **HIGH — INT/TERM cleanup does not terminate the parent and can certify an interrupted partial block** (`scripts/qa-fly-1986-load-probe.sh:795`, `scripts/qa-fly-1986-load-probe.sh:825`, `scripts/qa-fly-1986-load-probe.sh:840`). The same trap body is installed for `EXIT`, `INT`, and `TERM`, but it only runs `kill`; a caught signal returns to the interrupted `wait`/loop. The parent ignores child wait failures with `|| true`, clears `SENTINEL_PIDS`, summarises whatever rows exist, and can start the next block. In a local mock run, SIGTERM during block 1 left the parent alive after two seconds, it issued three later requests, exited 0, and emitted `b1,L1,1,...,block_valid=true` although four ticks were scheduled. This is a new defect in the attempted orphan fix, not a repeat of the old “sentinels are not tracked” finding. Implement one idempotent cleanup function that disables its trap, terminates and waits/reaps all tracked children, and exits 130/143 for INT/TERM. Do not swallow collector failure; require the exact expected tick count/sequence before a block can be valid, and never summarise a signal-aborted block as clean.

2. **HIGH — the claimed hermetic SIGTERM test reaches the default production Bridge, cannot detect reparented or later children, and fails in CI when no Bridge exists** (`scripts/__tests__/qa-fly-1986-load-probe.test.sh:297`, `scripts/__tests__/qa-fly-1986-load-probe.test.sh:305`, `.github/workflows/ci.yml:216`). A3b invokes the real probe without `--url` or `--state-db`, so on the founder machine it probes `localhost:9876` and opens the production DB; on GitHub's runner preflight exits before creating children, making `CHILDREN_BEFORE=0` and the new CI step red. Running the suite in that CI-shaped closed-port environment produced `passed=43 failed=1`, exit 1. Even on a live machine, `pgrep -P "$ORPHAN_PARENT"` cannot see an orphan after it is reparented and does not prove that the parent stopped launching work. Replace this with a temp mock HTTP server plus temp state DB, at least two blocks, a request ledger, and assertions that the parent exits with the signal-specific code within a bound, no request occurs after the signal, and no uniquely marked descendant remains. Keep the current CI placement; the inventory/order wiring itself is correct.

3. **HIGH — the “monotonic” grid uses only adjustable wall clocks, and the last fallback knowingly produces uncertifiable data** (`scripts/qa-fly-1986-load-probe.sh:116`, `scripts/qa-fly-1986-load-probe.sh:129`, `scripts/qa-fly-1986-load-probe.sh:380`). `EPOCHREALTIME`, Python `time.time()`, Perl `time`, and `date +%s` are epoch/realtime clocks, not monotonic clocks. A backward clock step extends a block; a forward step turns the remaining grid into a tight burst of `timer_late` rows and local process load. The `date` path merely warns even though its one-second resolution cannot schedule or assess the 500 ms contract. Bash 3.2 compatibility is syntactically fine, but it selects Python and forks it for every `now()` call; the local four-second Bash-3.2 mock run already recorded one of two ticks as `timer_late`. Use a real monotonic sub-second source (for example `time.monotonic()`/`clock_gettime(CLOCK_MONOTONIC)`), fail closed if none exists, and add injected-clock tests for forward/backward wall-clock changes. Keep the absolute epoch timestamp as a separate reporting clock if needed.

4. **HIGH — preflight does not establish a healthy intended Bridge or a safe pressure state, and the subject is not fenced through the end of a block** (`scripts/qa-fly-1986-load-probe.sh:530`, `scripts/qa-fly-1986-load-probe.sh:535`, `scripts/qa-fly-1986-load-probe.sh:539`, `scripts/qa-fly-1986-load-probe.sh:800`). `grep -q '"ok"'` accepts `{"ok":false,"shuttingDown":true}`; `buildSha` is never parsed or compared; `pressure_hold=NA` (missing DB, missing sqlite3, query error) is accepted; a non-Bridge listener only causes a warning; and PID identity is checked only before each block, never after the last block or before its summary. The mock Python service returning `{"ok":true}` was accepted and measured despite failing the `run-bridge` corroboration. Parse JSON strictly, require `ok=true`, `shuttingDown=false`, and the expected `buildSha`; require a loopback URL and a Bridge identity; make unknown pressure state a refusal; and re-resolve the listening PID plus start identity after every block before emitting a valid verdict.

5. **MEDIUM — `mode=ro` prevents SQL data writes but does not make the production WAL database byte-read-only** (`scripts/qa-fly-1986-load-probe.sh:344`, `scripts/qa-fly-1986-load-probe.sh:349`, `scripts/qa-fly-1986-load-probe.sh:787`). The production `teamlead.db` is WAL-mode and has live `-wal`/`-shm` sidecars. In a scratch WAL reproduction, eight identical `sqlite3 "file:...?mode=ro"` reads left main/WAL unchanged but changed the `-shm` SHA and mtime. The sampler repeats this connection every ten seconds, so the comments, self-test, and docs overclaim literal zero mutation. If literal read-only is required, read `pressure_hold` through a Bridge GET backed by its existing connection rather than opening production SQLite from a new process. Otherwise narrow the guarantee to “no logical DB mutation,” explicitly disclose WAL SHM coordination/locking, and stop calling it zero-write.

6. **MEDIUM — token-name eval injection is fixed, but the token value can inject curl config directives and remains inherited by child processes** (`scripts/qa-fly-1986-load-probe.sh:287`, `scripts/qa-fly-1986-load-probe.sh:298`, `scripts/qa-fly-1986-load-probe.sh:720`). The identifier validation makes `${!TOKEN_ENV:-}` safe, and the token is not in curl argv. However, it is interpolated unescaped into a quoted `curl -K -` config line. A token containing a quote/newline can add `url`/`output` directives; a local reproduction caused curl to issue an additional URL and create/truncate a chosen temp file. Because the selected variable is exported, the secret is also inherited by curl, awk, top, and other children and is visible to same-user environment inspection (`ps eww`), so “not in the process table” is not established. Validate the value against the actual bearer-token alphabet (at minimum reject CR/LF, quotes, backslashes, and controls), capture it once into a non-exported shell variable, unset the exported source variable before spawning collectors, and add a malicious-token-value mutation/behavior test.

7. **MEDIUM — key covariates are wrong, permanently `NA`, or silently converted to zero** (`scripts/qa-fly-1986-load-probe.sh:323`, `scripts/qa-fly-1986-load-probe.sh:331`, `scripts/qa-fly-1986-load-probe.sh:335`). `free_pct` does not implement the repository's FLY-1142 metric: it puts speculative pages in the numerator and omits throttled and compressor pages from the seven-bucket denominator. `swap_delta` is assigned `NA` unconditionally despite being a required pressure signal. If `lsof` fails, `grep -c` still prints `0`, so an unknown connection count is recorded as a real zero; the count also does not deduct the probe's loopback connection as claimed in the plan. Port the exact seven-bucket/`Swapouts` parser and keep a previous cumulative swapout sample to compute the delta. Preserve probe failures as `NA` and distinguish/subtract probe-owned connections before using this covariate.

8. **MEDIUM — the mutation suite does not prove its advertised write-safety or A/A execution properties** (`scripts/qa-fly-1986-load-probe.sh:633`, `scripts/__tests__/qa-fly-1986-load-probe.test.sh:91`, `scripts/__tests__/qa-fly-1986-load-probe.test.sh:157`). The “no write-capable endpoint” predicate is a three-string blacklist, so an inserted `curl -X POST "${BRIDGE_URL}/api/actions/terminate"` passes every self-test; a local mutant confirmed rc=0. Likewise F2 only greps for `probe_mode="sparse"` and `SPARSE_FACTOR`; a mutant that always passes `"full"` from `main()` also passes every self-test. The diagnostic “behavior” check at lines 170–171 runs a hard-coded awk formatter instead of `summarise_block`. Replace blacklist/text-presence claims with an exact GET endpoint/method allowlist and a fake-curl recorder that executes each real mode. Every property should have a mutant at the production call site and must fail for the asserted reason.

9. **LOW — an unexplained empty database artifact is committed at the repository root** (`test.db:1`). `test.db` is a zero-byte file introduced by the prior fix commit and is unrelated to the documented change set. Remove it and add temp-path discipline to the test that created it.
