## 0. 为什么这些内容在**单独一个文件**里

⚠ **`spec-baseline.md` 一个字节都不能动。**

分析器要求 spec 的 blob 在「采集时的冻结 commit」与「分析时的冻结 commit」之间**逐字节相同**，不同即拒绝分析，理由写作「预注册在采集与分析之间发生了变化」。

W1 / W2 / W3 的 receipt 绑的是 `5ce14e9de`。**任何对 spec 的编辑都会当场作废这三个窗。**

⇒ 而那正是它该做的事。它不是碍事，它是在阻止「有数据之后规则还在动」。
⇒ 所以：**裁决与实现更正记在这里，规则本体一字不改。**

**判据是这样区分的**：
- **实现**可以在有数据之后被更正 —— 只要它是把 spec **已经写死**的规则执行对；
- **规则**不可以。

| 量 | 值 | 怎么来的 |
|---|---|---|
| 窗口下界的**理论最大值** | **0.154297** | 每块全违约：`max_c c·cpLower(30,30,0.000417)` = `0.20 × 0.77147` |

## 3. 【实现更正】R14 的三个 HIGH（**收紧，不改规则**）

R14 是 Tadashi 定的硬门：阶段 0 被当权威引用之前必须补一轮**完整对抗式**复核。它用自建反例找到三条**在证据不成立时仍能发出权威 A** 的路径 —— 而 R13 的只读复核**三条全漏**。

| # | 缺陷 | spec 早就怎么写的 | 修法 |
|---|---|---|---|
| 1 | 样本带 `no_token` 的区块，只要 summary 谎称 `block_valid=true` 就被当有效块 | §4.0 明列 `no_token` / `unreachable` / `invalid_auth` 是**无效终态** | summary **不得**与自己的样本矛盾 |
| 2 | canonical state 写 `disposition:"completed"` 却带 `reason:"health_unreachable"`、`exit_code:1` 时被当完成窗，**连一句诊断都不产生** | §9 把 canonical state 定为**耐久真相** | 终态记录按**状态机**校验，不是三个独立字符串 |
| 3 | 点估计填字面量 `not-a-number` 通过一致性检查（`Number()` 得 NaN，而与 NaN 的任何比较都为 false） | §4.1 要求计数与 summary **逐字相符** | 数值字段先验证**是数**，计数验证**是整数** |

### 3.1 为什么这不是「有数据之后改规则」

1. **spec 正文一个字不改** —— 三条修的都是「实现没有执行 spec 已经写死的规则」；
2. **三条全部是严格收紧** —— 只可能把结局从 A 推向 U，**不可能反过来**。所以它们在数学上不可能给我制造一个更有利的结果；
3. **采集完全不受影响** —— 分析器不参与采集，W1/W2/W3 的字节与它无关。

### 3.2 收紧必须自证没把一切推成 U（双向对照）

证据在 `evidence/r14-reverse-control/`：

| fixture | 结果 |
|---|---|
| `valid-a`（合法全违约窗） | ✅ **A**（冻结 M） |
| `legal-replacement-a`（合法具名替换） | ✅ **A**（冻结 M） |

## 5. 【实现更正】两处披露

1. **参数集门没有拒绝域**：它的实现包络是 `[0,1]`，而任何合法区块率都在 `[0,1]` 内 ⇒ 没有任何 pilot 值可能让它失败。称它「WEAK」低估了实情，输出改称 **NON-DISCRIMINATING** 并带 `has_rejection_region: false`。⚠ 它的通过**绝不可**被引用为参数集拟合的证据。
2. **重复数按 configuration 报**：顶层写一个 `M=20000` 是错的 —— N 的每个 replicate 抽三个窗，实际跑 `m/4 = 5000`。改为 `{"b_lb_A":20000,"range_lb_N":5000}`。
