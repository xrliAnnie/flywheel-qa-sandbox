## 2. ★ 最重要的一条审计发现：采集器出的不是判据量

`summary.csv` 的列叫 `violation_upper_conservative`，字面读像「上界」。**它不是置信上界。**

`scripts/qa-fly-1986-load-probe.sh:496` 的实际算式：

```awk
cons = (missed + err + late) / n
```

这是**点估计**，`upper` 指的是「timer_late 按违约保守计入」这个**计数口径**，不是统计意义上的 upper confidence bound。

而 plan §3 的结局判定逐字要求的是：

> 设 `b_ub(L1)` / `b_ub(L2)` = 该窗口两个端点各自违约率的**单侧 95% 置信上界**

⇒ **采集器与判据之间缺一层。** 而且 plan §17-① 已经点名这一层不能随便补：

> 本文所有的「单侧 95% 上界」都是**独立性假设**下算的。观测是强自相关的（初步观测约 190 秒周期），真实覆盖率会低于名义值 ⇒ **可能把不安全的档位判成安全**

⇒ 直接套 Clopper–Pearson 会给出一个**朝危险方向偏**的数。这一层必须是**簇/序列相关下覆盖率有效**的方法，且 §17-① 要求「在阶段 0 的真实数据上**验证其覆盖率**」。

**这就是本单在方法学上唯一的真活。** 其余都是执行。

## 4. 我预期基线不达标 —— 而这恰恰是要跑阶段 0 的理由，不是不跑的理由

> ⚠ **v2 更正**：本节 v1 的标题写的是「结局大概率是 A」。R1 之后这句话不再准确 —— 见 §6 与 research §C.3/§C.4：本轮曝光下更可能的结局是 **U（无法认证）**，而 **A（已认证不达标）** 需要一个单侧 95% **下界**超过 SLO。「我预期基线坏」与「结局代码会是 A」是两件事，v1 把它们混了。

开工时（2026-08-23 11:07 PT，load1 = 14.62）顺手打了几发，用的是**宽预算**（`--max-time 60`，避免 memory 里那条「短超时探针超时≠服务挂了」的老错）：

| 端点 | 结果 |
|---|---|
| `GET /api/sessions` × 3 | 200 / **26.10 s**、200 / **24.77 s**、200 / **18.49 s** |
| `GET /health` × 1 | 200 / **23.71 s** |

同一个 session 更早一发 `/health` 是**毫秒级**返回的。⇒ 与 plan §0 描述的形状一致：成段的秒级停顿，然后自己恢复。

**⚠ 三条限定，一条都不能丢**：

1. **这 4 个数不能判结局。** 它们是串行 curl 的**事务时间**，不是按调度 tick 计的 `b`；plan §0 限定②已经把这条钉死过一次。
2. **n=4，且全落在同一个约 190 秒周期内**——它连「今天这台机器是什么样」都代表不了。
3. 它**支持**「值得按方案去量」，**不支持**任何结局判定。

⇒ 所以：**「基线不达标」是我的预期，不是我的结论。** 我不会因为这个预期就跳过阶段 0 —— 因为这个结论要能拿去用（走 plan §3.1 返场流程、给 FLY-1995 定验收线），必须是**用判据量、多窗口、带置信界**量出来的，而不是我今天早上打的四发 curl。

⚠ 而且按 research §C.14，这 4 发 curl 与 FLY-1986 的 evidence 已被**永久排除在主推断之外** —— 它们只用于模拟器校准与设计启发，且**逐条列出了它们影响了哪些设计选择**。

**两轮各打掉一个我的方法**：

| 轮 | 被打掉的 | 致命处 |
|---|---|---|
| R1 | v1 的 deff 修正 Clopper–Pearson | Kish 只匹配方差、相邻块非独立、取整破坏精确性 ⇒ **没有 95% 覆盖保证** |
| R2 | v2 的 studentized 区块 bootstrap | **我把 bootstrap-t 的反演方向写反了**（`t*=(b̂*−b̂)/se*` 时上界该用**下尾**分位数）；且 IAT / `se` / 边界退化 / 跨块时间间隙**全是空的** |
| R3 | **没有打掉 v3 的判据** —— 它把两条不等式、CP 的作用对象与方向、网格 Bonferroni、跨窗区间算术、七个 headline 数字**自己推了一遍，全部验过** | 不批的是「这个正确的构造还没闭合成**可执行、fail-closed、错误率合同完整、并已取得上游授权**的判据」 |

**v3 的动作是「删」不是「补」** —— 依据是 FLY-1986 §16.1 的既有裁定（「简单 = 净删除」）：整套 bootstrap 删掉，换成**阈值-计数精确二项界**（用 `p_j∈[0,1]` 的恒真有界性把 `b` 夹住），无渐近、无数据依赖选择、在 `b̂∈{0,1}` 处不退化。**R2 的 8 条新发现里有 4 条因此直接消失，而不是被补上。**

**三轮都确认的算术**：**13 个块本来就认证不了 5%**（零违约时精确界 20.58%）。
⚠ **「最少 600 个单元」是 Hoeffding 的数，不是本判据的**（v3 混了，R3 抓到）：本判据全干净时只需 **`J ≥ 90`** = `ceil(ln0.01/ln0.95)`（J=90 → 4.99%，J=89 → 5.04%）⇒ **7.5 小时哨兵曝光 ≈ 7 个 65 分钟窗**。
⇒ 本轮曝光下 **B 不可达**，能拿到的是 **A** 或 **U**，加上一个**预注册的 exposure calculator** —— 那正是上游 §17-③ 留的空。详见 research §C.3/§C.4、plan §0。

⚠ **另一条我要更正自己的话**：v3 写过「精确界一致更紧、没有代价」。**那是假的** —— R3 给了反例（J=13、11 块 `p=31/150`、1 块 `1/150`、1 块 0 时，阈值界 98.84% vs Hoeffding 51.48%）。选它当唯一判据的理由是**有效性 + 简单**，不是支配性。
