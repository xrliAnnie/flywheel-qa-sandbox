## 发生了什么

跑到第 6 个区块时，运行采集器的**后台任务被 harness 停掉** —— 两个后台任务同时被 kill：采集窗口本身，以及负责自动接续后两窗的 chain runner。

**crash-safe 协议按设计工作了。** wrapper 的 TERM trap 把 attempt 干净地终结为：

```json
{"disposition":"aborted","reason":"signal","exit_code":143,"artifacts":{...四个哈希...}}
```

owner 租约已释放，**没有孤儿、没有非法 JSON、没有需要事后猜测的状态**。
（这一条恰好也是那套 crash 协议第一次在**非演习**的真实中断下被检验。）

## ⚠ 为什么另起一个 evidence 根，而不是原地重跑

冻结规则把 `reason: "signal"` 归为**服务/宿主类** ⇒ **不可被重跑替换**。
按规则字面，这个 attempt 会让**整个阶段 0 无法认证**。

那条规则存在的理由是防幸存者偏差：不让「机器不好时失败的窗口」被一次次重跑洗掉。

⚠ **而我没有把它改判成「harness 故障」（那一类是可替换的），尽管这个读法完全说得通 —— 打断它的是我自己的工具链，不是被测机器。**

理由只有一个：**宽松的读法对我有利**（它让今晚的采集还能算数）。一个由受益人自己做出的、恰好对自己有利的重新分类，正是这套预注册从头到尾在防的东西。所以这条由 Tadashi 裁，不由我裁。

⇒ 在他裁定之前：
- **本轮证据原样留在这里** —— 不删、不改、不搬进「先验观测」假装它是别的东西；
- 新一轮在**全新的 evidence 根**（`phase0/`）里跑，两根互不污染；
- 若裁定它确属 harness 故障、可替换，则需给 wrapper 补上写 `replacement_of` 的能力（R14 已指出目前没有这个 producer），并在**一个**根里重建谱系。
