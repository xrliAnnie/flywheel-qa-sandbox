## 两条值得先记下来的观察（⚠ 都是观察，不是结论）

1. **L1 与 L2 差了一个数量级。** `/health` 有 35.7% 的请求超过 500 毫秒，而 `/api/sessions` 只有 3% 超过 2 秒。
   FLY-1986 §2.1 记载 `/health` 每次约 18 次同步 SQLite（2 次 StateStore + 每 Lead 1 次 heartbeat × 16 Lead），
   `/api/sessions` 只是一次 StateStore 查询。⚠ 这**与**「代价集中在 `/health` 自己的同步工作里」这个假设**一致**，
   但一致不是证明 —— 机制归因明确不在本方案范围内（FLY-1986 §2.4，另案 FLY-1995）。
2. **这是在 load ≈ 6 的低负载下量到的。** 如果正式窗口重现这个量级，阶段 0 大概率能给出决定性的 **A**。
