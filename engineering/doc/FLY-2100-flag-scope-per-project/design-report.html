FLY-2100 设计:给 feature flag 加「范围」—— 一个开关,可全项目、也可逐项目

Epic FLY-2099 · Batch 1(A 单,地基) · 设计阶段报告 · 2026-08-27 · 状态:设计完成,待实施

① 一句话总结

给存开关值的那张表加一列「范围」:写 * 表示对所有项目生效,写项目名(如 flywheel)表示只对那个项目生效;查值时按「项目行 → * 行 → 默认」的顺序取;管理台和命令行都能对单个项目设值/清值,每一笔改动都带范围留审计。这样「给 flywheel 单独开 doc_flow、其他项目保持关」这类事,第一次有了正规、可审计、能在管理台上看到的做法。

先解释几个词(后文都会用到):
· feature flag(功能开关):不改代码就能打开/关闭某个功能的开关,下文简称 flag。
· Bridge:Flywheel 的常驻调度服务,所有 Lead/Runner 的总后台。
· flag_values 表:Bridge 自带的 SQLite 数据库(一个本地文件型数据库)里存放 flag 当前值的表,今天只有 6 行、全是全局开关。
· 范围(scope):本单新加的列。* = 全项目;项目名 = 只对该项目。
· 名册:~/.flywheel/projects.json,登记全部项目(现有 6 个)。写入时项目名必须在名册里,防手滑写错名。
· 管理台:这里指两个页面 —— 发到你手机的 flag 报告页(可交互:改动只「生成命令」,复制粘给 Lead 执行,页面本身不直接改任何东西,沿用你锁定的控制模型)+ 新版 management console(本单只读显示,改值指路命令行)。

② 核心流程 · 写入:页面只生成命令,命令行是唯一写入口

手机报告页上的「项目」下拉只生成命令,你复制粘给 Lead,由 Lead 执行命令行 —— 这是你此前锁定的控制模型(页面零直写、零网络回调),本单原样沿用。命令行打到 Bridge 的同一道闸门,过三条校验才落库。全局开关写项目行会被直接拒绝(HTTP 400,即「请求不合法」的标准报错)—— 比如 mailbox_queue 这种 Bridge 级开关,不存在「只对某项目生效」的说法,写了就是错,闸门当场拦下。

  • 单一写点:所有写入都经同一套「先预检、再确认」的两步提交(防误触、防并发互踩),不另造第二套写入协议。并发防护对逐项目行用改动流水号做栅栏 —— 即使一行被「删了又重建」,过期的提交也会被识破拒绝。
  • 审计:每笔写入在 changelog(改动流水账)里记一行,带范围、改动人、理由;流水账只增不删。「清值」在流水账里记为「回落继承」,不猜测回落后的具体值 —— 回落值永远由读取端现算,审计不写可能过期的预测。
  • 清值 ≠ 设为关:「清值」是把项目行整行删掉,让该项目回落到 * 行 / config / 默认;「设为关」是明确写一行「关」,能压过 * 行的「开」。两个动作在页面和命令行里都分开,且「清值」只在那一行确实存在时才会出现在下拉里。

③ 核心流程 · 取值:项目行 → * 行 → 默认

查「某项目这个 flag 现在什么值」时,按下图从左到右问四个问题,谁先有值听谁的。举例:给 doc_flow 写 flywheel=开 和 *=关 之后 —— flywheel 项目显示开,其余项目全部显示关(* 行盖住了它们各自 config 文件里的旧值)。这正是验收要测的场景。

③号位(config.yaml)是过渡期专属。config.yaml 是散在各项目仓库里的旧配置文件。本单保持「数据库没写过值时,一切照旧读 config」的兼容(byte-compat,行为逐字节不变),所以上线当天什么都不会变;等后续 C 单把 config 里的 flag 键删掉,这一级就消失,顺序简化为「项目行 → * 行 → 默认」。

④ 数据结构:三张表各加一列「范围」

不建新表,在现有三张表上加 scope 列:存值表和周扫描表的主键(表里每行的唯一身份)从「flag 名」扩成「flag 名 + 范围」;流水账表加列即可。现有 6 行全局开关一次性迁成 scope='*',迁移可重复执行不会重复迁(幂等),整个过程包在一个事务里,失败就整体回滚、库不落半迁移状态。

哪些 flag 允许逐项目设值?—— 显式白名单 5 个

「逐项目」只对本来就按项目生效的 flag 有意义。逐项目 flag 里再排掉不该从管理台改的,得到白名单:

flag管什么逐项目可写?
doc_flowRunner 写过程文档的流程开关白名单(验收主角)
pipeline_dag项目级 DAG 派工白名单
pipeline_work_kind派工 work-kind 强校验白名单
proofshotUI 改动的视觉验证白名单
xiaohongshu_learning小红书定期学习管线白名单
checkpoint_enabled审批门开关排除 治理门,永远只读,不进任何可写面
xiaohongshu_auto_create每个收藏夹是否自动建 issue排除 它是「每个收藏夹一个值」,不是「每个项目一个值」,一行表达不了
skill_framework_split_participationskill 实验分流退出杠杆排除 设计上只读(FLY-1356 的退出杠杆,有自己的读取纪律)

全局开关(如 mailbox_queue 等 20+ 个)一律不接受项目行 —— 这就是「名册 scope 生效为写入约束」。

⑤ 关键取舍(与被否掉的做法)

决策点选了什么否掉了什么 / 代价
范围存哪同一张表加 scope 列(FLY-2099 founder 定案)否:另建一张「项目值表」—— 那要复制一整套并发控制 + 审计 + 读取代码,两套账迟早对不上
开放范围显式白名单 5 个,名单写死在代码里、有机械校验否:只开 doc_flow(下拉只对一张卡有意义,C 单范围说不清);否:全开(把治理门、只读项也开了,语义站不住)。代价:名单是设计判断,若与 Epic 定案有出入,以 Epic 为准改名单即可,结构不动
清值语义项目行只在有值时存在;清值=删行;设值总写明确的开/关否:保留「空行」表示清过 —— 会出现第三种说不清的状态。删行后流水账仍留痕,不丢历史
config.yaml 的位次DB 一旦有行就盖过 config(哪怕是 * 行)代价:给某 flag 写了 * 行后,个别项目 config 里的旧值即刻被遮蔽。这是有意的 —— C 单本来就要删 config,遮蔽让「谁说了算」只有一个答案
管理台怎么改值页面只生成命令、Lead 执行(你锁定的控制模型原样沿用);命令行是唯一写入口否:给页面接直写通道 —— 评审发现那条通道在生产根本没有调用方,为它接线等于新造第二套写入协议;删掉这个承诺,不是实现它
周扫描计账稳定天数账本按 (flag, 范围) 逐行记在一张新增的账本表里;原扫描表和「摆到你面前问留不留」的全部逻辑一字不动好处:一个项目抖动不再抹掉其他项目的稳定账;报告能写出每个项目各稳定了几天。否:改造原扫描表的主键 —— 那张表还管着问答计数、退役记号等 flag 级状态,动主键会全部牵连;也否:候选逐项目摆(一个 flag 拆成 6 个问题轰炸)

⑥ 诚实边界:这个设计做什么、不做什么

做

  • 存值、写入校验(名册 + 全局拒项目行 + 白名单)、四级取值、管理台按项目显示与设值/清值、命令行 set/clear --project、带范围的审计流水、周扫描按 (flag, 范围) 计稳定天数。
  • 迁移幂等 + 事务保护 + 迁移前自动备份;逃生开关沿用现有 FLYWHEEL_FLAG_STORE=0(整个 flag 库旁路,不新造机制)。

不做(以及为什么要明说)

  • 不切换任何运行时行为。doc_flow 真正控制 Runner 行为的读取点今天在各项目的 config.yaml 里,本单不动它(C 单迁)。⇒ 存在一个过渡窗口:你在管理台把某项目的 doc_flow 改成开,页面显示开了,但 Runner 的实际行为还听 config.yaml 的。管理台会在这种行上打黄色标记「runtime 仍按 config,C 单切换」—— 如实显示分歧,不假装一致。
  • 不新增任何 flag;不动 env 类全局 flag 的存值方式(B1/B2 单);不删 config.yaml 的键(C 单)。
  • 项目被移出名册后,它已写的项目行成「孤儿」:不参与取值、不在管理台显示、也不自动删(流水账要留痕)。要清得人工清。
  • 新版 management console 的 flag 页本单只跟着「读」变(自动显示 DB 值),它的「写」仍指路命令行 —— 不在本单同时改两套提交协议。
  • 回滚不是「撤 PR 就完事」:数据库表结构一旦升级,旧版本代码不能再直接读这个库。降级只有两条路(都写进 PR 说明):用现有逃生开关旁路整个 flag 库,或从迁移前的自动备份恢复(丢弃其后的 flag 改动)。

⑦ 验收清单(实施单要交的证据)

  • 单测:主键迁移(6 行落 *、幂等)、名册校验、bridge_global 拒项目行、三级取值顺序、双读回落。
  • 真 Bridge:doc_flow 写 flywheel=开 + *=关 → 解析器与管理台显示一致;mailbox_queue 写项目行被 400 拒。
  • 管理台浅色截图附 QA 报告。
