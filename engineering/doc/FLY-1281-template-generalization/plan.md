## 0. 总验收

1. **泛化表达力**：schema_version 2 manifest 能声明非三段式链（generic/review、无 QA 全 no-write 链、node_done/review_pass 边、review_fail 回环）；三个新种子通过校验、可物化为 **typed v2 snapshot**（存取往返保 v2）。
2. **D2 不变量（单独成组，纯 capability）**：含写者节点（registry shared_branch_writer∨creates_pr，**含 design**）⇒ 恰 1 QA + qa_passed，否则 reject；全 no-write 才许无 QA，且 qa_exempt 政策 claim（bridge_policy/snapshot_digest/确定性 authority_id 幂等）在**钉 snapshot 同一事务**写入。
3. **node-id substrate**：8 面 enrolled 走 workflow_node_id + snapshot 新路径；node-id 由服务端从 execution binding 解析、**在所有可能创建 session 行的 lifecycle 路径上 set-once**（started/completed/failed 含 lost-start 恢复），校验先于 insertEvent；未知/缺失/不一致一律 fail-closed 绝不归一 main（S14）；legacy 逐面 byte-compat sentinel。
4. **generic 契约**：S11 · S12（admission null→拒；Blueprint 旧调用方 warn+fallback 字节不变）· S13 · S15（无产出 → completion **可重试**拒绝，事件不入库、marker 留存，补产出后同 ID 重放成功）· S16。
5. **统一泛化 admission + 可信身份**：一个原子 pre-spawn API；**Bridge 内部 GeneralizedExecutionContext（runId/nodeId/attempt/snapshotDigest）由选择产出、内部线程传递，绝不取自 HTTP body**；fresh=图唯一起点节点 attempt 1，retry=同节点 max+1（或同 execution 精确重放），**C 内拒绝任何后继节点 admission**；解析后的 vendor/model/effort/family 钉进**不可变 runtime 投影表**；跨厂商校验用已解析 family；C 可达凭证形态 = 零 或 output（decision/both 形态 C 不可达并显式拒绝——qa/review 节点执行属 D/B 既有 seam）。
6. **generalized completion 终局权威（两原语分立）**：**只有 explicit-complete 路径（认证的 flywheel-comm complete 提交 + complete-marker 重放）可以创建 completion 收据**——`commitEnrolledCompletion` 单事务原子写收据 + run-node 转 **done**（沿用既有终态词汇）+ 确定性 node_completed run event + session 投影，不派发后继；route 必须等于 snapshot capability 的 completion_route。**teardown 观察路径（DirectEventSink 进程收尾 + HTTP 里 TeamLeadClient 的 teardown 事件）走 `observeEnrolledTeardown`：只能重驱既有收据的幂等投影或（无收据时）fail-closed hold + 升级——teardown 永远不能创建收据、绝不把零 commit 翻译成 legacy decision**；HTTP sink 按事件来源判别两原语（explicit source 标记 vs teardown）。中间 generalized 节点不触发 legacy 整 issue completed 副作用；重复收据重驱幂等投影（真实崩溃边界 = 核心事务已提交、session_events 审计未插，同 ID 重放收敛且审计恰一次）。
7. **选择解析与权威（显式 auth-kind 契约）**：/api/runs/start 只接受 taskCategory/templateId/selectionReason + **v2 选择必带 idempotencyKey**（**founderOverrideTemplateId 不进公共 DTO**——selection_source 枚举保留 founder_override 值，提交面等 founder-authenticated 通道，C 不开；**运行时 forbidden-field 检查**拒带该字段的请求，不靠 TS 类型）；**请求 auth-kind 显式派生：master 认证才可触发 v2 选择；scoped（含 Gemini）/tokenless 遇 v2 候选 → 显式拒（无候选 ⇒ legacy 行为不变）**；记录的 actor 与归属 Lead 分开派生（master token 不冒充 Lead 身份；lead 选择对照 issue 归属 Lead 校验）；四级 lead→binding→default→裸 session 逐级；选择事实落 workflow_run 行；**物化前 active-run 对账**：同 issue 已有 legacy/不匹配活 run ⇒ 大声 hold（绝不嫁接 generalized snapshot）；同 v2 run 精确重放 ⇒ 复用；generalized 派发走 run 定向 fail-closed 方法（不走 shadow writer 观察型 safe() 路径），且不建 main 影子节点。
8. **default-off、字节兼容（候选先行的门序；start 选择 = v2-only）**：FLYWHEEL_WORKFLOW_GENERALIZED_TEMPLATES OFF ⇒ 四个 mutation seam + boot 导入 + 两条派发路径全拒/跳过，全链字节一致；**门序 = 先只读解析候选模板与其存储 schema_version：无候选 或 v1 候选 ⇒ 一律 null → 精确 legacy start 路径（零 workflow run/claim/ctx；OFF 与 ON 都如此——v1 候选在 C 永不接 start 线）；v2 候选 ⇒ 在 v2 物化事务之前整体校验 flag 组合（generalized ON ∧ claims_write ON），不满足 ⇒ 拒且零 v2 副作用（不建 run、不写 qa_exempt）**；materializeWorkflowRun 与 execution admission 内同谓词复检（纵深）；enrolled v2 run 事后关 flag → fail-closed hold 不归一；3 eng 种子与全部 v1 测试字节回归；**存储硬线（R7#3 精确化）= 不修改任何既有列/CHECK/trigger；仅有的既有表触碰 = 两组加性 nullable 列（sessions.workflow_node_id + workflow_run.selection_source/selected_by/selection_reason，幂等 ADD COLUMN），其余全部为新表**。
9. **C→D 边界**：C 不做后继派发/边解释/review 执行（review admission fail-closed 等 D）；启动对账仅识别 + 大声 hold。

## 2. 实施步骤（TDD）
