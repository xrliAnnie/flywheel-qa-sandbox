Codex 切号器为什么没起作用，以及怎么让它真正生效

FLY-2830 · 设计稿 · 2026-09-25 · 基于生产只读取证（不写任何东西、不消耗额度）

一句话结论

切号器从上线起在生产上就没有真正打开过。它每次动手前要先做一次安全自检，而 Codex 升到 0.157 之后，自检用来「认人」的那一步永远认不出人，于是永远不通过，只能等 Lead 手动切。另外额度页有一处「抢答」问题，导致正在用的号（school）20 小时没读到新数——其实 school 现在只用了 28%，10/01 晚上才重置。

这次设计修三件事：① 读数真实（在用号能读到、读不到时写清原因、卡到期显示到分钟）；② 自动切号真能开（修好认人那一步）；③ 每次切号（Claude 或 Codex、手动或自动）都把全部账号重读一遍（正常情况下 2 分钟内完成；没读完或失败时页面会明确标出来，不会静默显示旧数）。全部 Codex 号都打满时，告警会逐号写出几点重置。

病根为什么切号器「感觉没有作用」

几个词先说清：readiness（自动切号前的安全自检：确认每个正在跑的 Codex 进程都「有主」，免得切号时被某个没人管的进程把旧账号写回去）；socket（一个 Codex 执行体内部通信用的「门牌」，我们靠「谁占着这个门牌」来认出进程属于哪个任务）；lsof（系统自带的查询工具，回答「谁占着这个门牌」）；软链（一个指向别处的快捷方式）。

Codex 0.157（9-22 起）把我们给它的门牌做成了快捷方式，真门牌放在别处；lsof 不认快捷方式，于是对每一个新任务都回答「没人占着」。自检据此判定「有进程来路不明」→ 全舰队自动切号关着；同一原因还让已经做完的任务的后台进程收不掉（今天 FLY-2873 做完 11 小时了，它的后台进程还活着）。我在本机用只读方式把 lsof 换成「先顺着快捷方式找到真门牌再查」回放了一遍：原来认不出的后台进程马上认出来了。

核心流程修完之后

补充几个词：app-server / daemon（每个 Codex 任务在后台常驻的那个主进程）；TUI 客户端（你在 cmux 窗口里看到的那个 Codex 界面，它连着后台主进程）；generation（切号计数器，每切一次号 +1，系统看它变没变就知道有没有切号）；quota-monitor（管 Claude 账号的常驻程序，Claude 切号就是它决定的）；sweep（把所有 Claude 号的用量挨个读一遍）；Bridge（Flywheel 的中枢进程，额度页的数据也由它读）。

  1. 读数真实：读每个号前的「占用盘点」改成只信自己这次盘点的结果，不再被同时进行的别的盘点「抢答」成未知。
  2. 自动切号真能开：认门牌前先顺着快捷方式找真门牌；老式任务（本周早些时候启动的）连带认出它自己的 TUI 客户端；任务结束时它的后台进程当场就能被收掉（今天那个残留 11 小时的也会在上线后第一轮被收）。自检通过后，号打满就会先真探下一个号能不能用，再切过去并通知你。
  3. 切号后全量重读：Bridge 盯着两个切号计数器，任一变了就重读全部 Codex 号和 Claude 的卡/订阅，同时叫 quota-monitor 立刻把全部 Claude 号用量读一遍。

额度页会变成什么样你能直接看到的变化

  • 卡到期显示到分钟，例如「10/22 13:22」。
  • 每行都写「读于几点」；Claude 行分开写「用量读于 · 卡读于」（两个来源，两个时间）。
  • 读不到时写真实原因，例如「占用盘点失败（原因码），本次未读，沿用 14:02 读数」「被 chatgpt.com 拒绝（HTTP 403）」。
  • Claude 下次扣费日：「读不到：Anthropic 只在 claude.ai 网页账单页给出（需浏览器登录，已决定不取）」。
  • 切号后：每一格拿自己的读数时间和切号时间比，早于切号的标「切号后尚未刷新（切号 几点，读于 几点）」，从没读到的标「切号后尚未读到」；顶部写还有几格没刷新。
  • 后台每 15 分钟自动重读 Codex 全部号 + Claude 卡/订阅；Claude 用量按 quota-monitor 原节奏（在用号 20 分钟、其余 60 分钟），切号后立即全量。
  • 全部 Codex 号都打满：中文告警逐号列出「各窗口用量 · 几点重置 · 几点恢复」和全舰队最早几点恢复。

取舍选了什么、没选什么

选择没选的方案为什么
修「认人」那一步，让自检真能通过放宽自检，允许「来路不明」的进程存在自检防的是切号后被别的进程把旧账号写回去，这个风险是真的；病在认人工具，不在规则。
只认一种额外形状：该任务自己的 TUI 客户端凡是同一个任务编号的进程都放行形状越宽越容易放过不该放的；以后 Codex 再加新进程，自检会重新关上并写明是哪个进程，宁可停也不瞎切。
切号后请 quota-monitor 做一次 sweepBridge 自己再读一遍 Claude 用量同一个数两个来源会打架；切号器用的和页面显示的应是同一份。
切号重读用「计数器变了就读」，不存回执给每次切号记一张耐久回执重读做多少次都一样；万一切号时 Bridge 恰好重启，15 分钟定时读会补上。
Claude 扣费日继续读不到从浏览器取登录 cookie 调网页接口；按开通日推算前者违反 Anthropic 条款、你已否决；后者有反例（business 开通 8/19、实际 10/23 续费），你禁止推算。

诚实边界做什么、不做什么

会做到：在用号读得到；读不到写原因；每次切号都全部重读，没读完/失败时页面如实标出；自动切号的安全自检在今天的生产形状下能通过（实现后要用同一个只读回放脚本对生产连跑两轮证明）；全部打满时告警写清各号几点重置。

做不到 / 不做：

  • 自动切号打开后，第一次真打满、真切号会发生在生产上——那条「探号→切→通知」的路径 FLY-2869 已用模拟数据证明过，但从没在生产跑过。建议第一次时 Lead 盯一下。
  • 「切号后 2 分钟内读完」是正常情况下的目标，不是硬保证：如果唤醒 quota-monitor 的信号没送到、或 Anthropic/OpenAI 接口很慢，会超过 2 分钟——这时页面会标「切号后尚未刷新」，日志写明原因。某个号连续 3 轮读失败就停止强制重读（避免每分钟反复刷新所有号的登录凭据），那一格会一直标着直到下次读到。
  • Claude 下次扣费日继续读不到。已查来源：OAuth profile、OAuth usage（只给月付/年付且实测为 unknown）、OAuth 组织接口、本机凭据字段名、Claude Code 程序内接口、claude.ai 网页接口（只认浏览器登录）、收据邮件、社区工具。
  • 切号通知里附的那张额度页是「切号那一刻」的快照，不会等重读；页面每行的「读于几点」可以分辨新旧。
  • 不碰桌面版 Codex 的凭据问题（FLY-2729）、不改 Claude 切号的判断规则、不清理机器上与此无关的残留。
  • 如果某次任务结束时后台进程没收掉（少见），自检最多会关 2 小时，等兜底的收割器处理；那段时间会写明卡在哪。
  • 如果以后 Codex 再改进程结构，自检可能再次关上——但会写明卡在哪个进程，不会静默。
