runner 一轮做完→idle 空转,没人续跑 / 没人可靠告诉 founder — 路线对比 & 推荐

Issue FLY-818 · 2026-07-03 · Flywheel Eng · 决策文档(给 Annie 确认方向)

问题一句话

runner 是 turn-based:一轮回复结束就 idle 在 prompt,「我接着做」只是文字、turn 已结束。没人续跑,founder 也要自己去发现它停了。现 watchdog 是卡死检测器(≈1h 才报、只报警不续跑、绕 Lead relay 不直连 founder)。

Annie 定的方向:goal-driven 自动续跑——短阈值扫「turn 结束+idle」;有 pending question→等答;goal 没完→自动续;真卡住→升级。且 Annie 想 先试 /loop(runner 原生自循环),好用就可能不需要自造看门狗。

推荐 RECOMMENDED

混合:/loop-native 当续跑主力 + 保留最小安全网,不自造 Bridge Monitor。

  • 续跑 = 路 A /loop-native(claude runner 用 Claude 自带 /loop+ScheduleWakeup 自己续)——智能在模型里、代码最少、天然抗 Bridge 重启、对齐 Anthropic「thinnest wrapper」哲学。正是 Annie 首选。
  • 安全网 = 现有 StuckRunnerDetector 缩成纯安全网(只在「真卡住/续不动」时),经 FLY-368 alert channel 可靠直达 founder = item A 的真正硬要求。不删 watchdog。
  • 先跑便宜真机 spike(Phase 0)验 /loop 能不能干净套 runner = go/no-go(见下)。

「/loop 能替掉看门狗吗?」——能替掉「续跑」那半;替不掉「真卡住→可靠告诉 founder」那半(留给缩小成安全网的 stuck-detector)。都不用现在自造新 Monitor。

两条候选路

路 A /loop-native — runner 自己续跑

runner 的 Claude Code session 跑在「自循环到 goal、遇问题才停」模式(Claude 自带 /loop self-paced + ScheduleWakeup;codex 对应 /goal)。

可行性(已核实)

  • ✓ 注入点存在:runner 启动 claude [options] [prompt],ctx.prompt / --append-system-prompt-file 都能塞「自续跑契约」。
  • ✓ /loop+ScheduleWakeup 在 runner session 可用 —— 本 FLY-818 runner 自己就有(活证据)。
  • ✓ 与 Flywheel gate 天然互操作(gate CLI 阻塞 turn → 不会排续跑);天然抗 Bridge 重启(session 自持,比 Bridge-side 更 robust)。
  • ⚠ ScheduleWakeup 无人值守可靠 fire = 唯一没被生产证据覆盖的点 → Phase-0 spike 验。
  • ✗ backend 分裂:只 claude(/goal=codex;agy/kimi 无)。

复杂度 / 是否自造

代码最少:一条 bootstrap 约定 + 保留现有 stuck-detector 当安全网。不自造续跑引擎。

路 B Monitor-extension — Bridge 外部检测 + 审计 nudge 续跑

扩展 FLY-368:RunnerIdleWatchdog 短阈值扫 → quiet_unexplained → 审计 continue nudge(有界 budget+backoff)→ 续不动 → 经 FLY-368 升级。智能在 Bridge。

可行性

  • ✓ 全部原语已存在(idle watchdog + quiet-classifier + 审计 nudge + AutoRepairBot + AlertChannelHub)。
  • ✓✓ 唯一 backend-agnostic(nudge = tmux send-keys,claude/codex/agy/kimi 都行)。
  • ✓ 外部观察 fingerprint 能界定 runaway;全审计 + gate 互操作已内建。

复杂度 / 是否自造

中等代码:新短-idle 续跑路 + budget/backoff + escalation + 要跟 in-flight FLY-368 协调。是第二控制环(Bridge 启发式判「该不该续」,比模型自己粗)。

关键 reconcile:Annie 试 /loop vs FLY-512 finding F(「有意不做 Runner 自主续跑」)矛盾吗?——不矛盾。 F 反对的是「自主跑到 done / 合并」;Annie 版是「续到下一个 gate / PR 就停」(gate 仍阻塞、ship 仍 founder-gated)——不碰 F 那条红线;而 F 要借的 /goal 契约结构(outcome / verification / blocked-stop / 无 tool-call 就停),正好是 /loop-native 要落的。两者在「续到 gate 停」这个精确定义下一致。
