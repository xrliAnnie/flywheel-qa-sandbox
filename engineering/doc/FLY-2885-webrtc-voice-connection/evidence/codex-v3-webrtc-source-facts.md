# Codex 0.157.0: thread realtime, v3 over WebRTC (source facts)

Source: `openai/codex` tag `rust-v0.157.0` (ac21625d), compared with `rust-v0.156.1` (81e8e29b). Paths are relative to `codex-rs/`. Abbreviations: RC = `core/src/realtime_conversation.rs`, CALL = `codex-api/src/endpoint/realtime_call.rs`, WS = `codex-api/src/endpoint/realtime_websocket/`, BEH = `app-server/src/bespoke_event_handling.rs`.

| 4b | Size limits | **No size check or truncation applies to `prompt`.** A ~60 KB (~15k-token) prompt is sent as-is, so any rejection would come from the server. `initialItems` (v3 only): at most 128 items, each ≤8,192 tokens and ≤8,192 in total (`REALTIME_INITIAL_ITEMS_MAX_*`). ## Unverified / open

- Whether the ChatGPT-backend `/realtime/calls` route accepts `gpt-live-1-codex` for this account, and whether `api.openai.com/v1/live/{call_id}` accepts a ChatGPT bearer for the sideband. The code does exactly this, but acceptance is up to the server.
- Whether the server enforces a cap on `session.instructions` for a ~15k-token prompt. Codex does not.
- Whether the server sends `output_audio.delta` on the sideband in webrtc mode, which would duplicate audio over JSON-RPC.
- Server-side lifetime, idle timeout and `expires_at`.
- Whether the v3 server honors client-sent events on `oai-events`, for example a cancel.
- v3 server events beyond the eight in 6c, and `turn.done` fields such as truncation or `end_ms`.
