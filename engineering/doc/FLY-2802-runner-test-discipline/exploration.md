## 问题与已授权边界

全仓字面量迁移让 runner 想通过跑整包测试来寻找影响面，导致同机几十分钟的重复测试。FLY-2753 已写入禁止本机整包的规则，但它的验收只证明文字存在，未证明 runner 在诱导任务下遵守。

本节点只交付设计、有效设计评审和 founder HTML；不实现、不派发、不运行 529、不申请 ship。整个 issue 的成功仍要求新 prompt 下真实 529 行为 PASS。设计批准绝不代替该证据。

事实分层：
- 用户/Lead 提供 FLY-2775 Opus 5 transcript 的三次 `npx vitest run --exclude …`、耗时和未由 skill 强制触发的结论；本节点未重新读取该完整历史 transcript，不把假说升级为新观察。
- 当前代码确认 implement/qa/engineer 都有旧 targeted verification 文本，均没有明确禁止“发现受影响测试”的整包扫描。
- 当前源码确认 SkillInjector 生成的三个 skill 仍包含不带文件选择的 testCommand；这是独立冲突，并不推翻历史单中“不是 skill 强制”的事实。

## 选定方向

把禁止理由、可执行替代步骤和技能优先级作为一个版本化规则块，投影到共享协议与三节点。清理 Flywheel 自己生成的技能中的无选择测试指令；不改第三方缓存源码。

529 任务中保留真实模型、原有工具和技能，让它完成大量字面量断言迁移。独立判定器只读取结构化工具调用和过程证据：任何整包命令为 FAIL；只有完整任务完成、正向定向测试证据齐全、无未知调用时才为 PASS。构造旧行为 transcript 是检测器负对照，不冒充旧 prompt 真实复现。

## 不能省略的约束

- 不能用 `--exclude`、`-t`、单 worker、coverage、重定向输出或 package filter 冒充文件选择。
- 不允许通过枚举全部测试文件、递归 test alias、脚本包装绕过语义判定。
- 空日志、被截断日志、空测试集、仅启动成功、仅静态文字正确都不得 PASS。
- 诱导任务不能在末尾再次提醒“不许跑整包”，否则测的是特别提醒而非生产 prompt。
- 真正相关文件可能多；逐个执行有来源的文件是合法的，不能用“数量多”自动判违规。
- 全量测试继续由 PR CI 承担；529 行为验收不替代 frozen-head `CI OK`。
