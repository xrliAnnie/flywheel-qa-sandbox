Selected: replace legacy decision producer and card producer; reuse current judgment collector/evaluator and guarded approval infrastructure. Rejected: merely changing runtime's mode check (leaves dormant scanner, history-only delivery and old authority); preserving three gates as a second authority/audit card (contradicts founder); direct model-to-approve/merge (bypasses source and current-head guards).

Design phase delivers this plan and founder HTML only. No code, live DB/flag mutation, deploy, restart or ship request. Merge remains separate from independent updater deployment. Existing founder rework/rejection, revocation, cancellation, supersession and head-change guards stay effective. No new undo UI.

### 4.1 Currentness invariant

New `StateStore.commitShipJudgmentSourceIfEligible({questionId, at, writeSource})` reads, never accepts caller-supplied verdicts. In a short immediate transaction it checks:

1. Actual Flywheel mode auto, current control/opening and flag change sequence; current gate holder, source execution, open question, sealed manifest and all current targets. Current founder negative/deferred source, revoked claim, canceled run or changed holder/head/manifest makes it ineligible. Preserve the exact permanent founder rework block key (project, repo_identity, head_sha), across questions/attempts/runs, for every target; only a new head may escape that existing block.
2. Latest semantic input/current source revisions match current binding; durable successful evaluation and full evidence ledger; evaluation must match the latest input/source revisions, model snapshot and policy, with valid evaluation timestamp no later than now. Before each auto attempt re-collect authority materials; a changed requirement/design/QA revision expires the evaluation even if head is unchanged. Timestamp alone cannot refresh it; absent or expired evaluation fails closed. Mechanical evidence remains subject to the 60-second freshness bound; alignment/conflict/coverage all pass and overall can, with the independent reviewed-plan and actually-read QA/semantic-pass proofs in §4.3. Do not equate legacy aggregated pass or semantic non-veto with these proofs. Missing/unavailable/partial evidence, budget-exceeded, stale model input and primary or secondary mismatch deny.
3. Current delivery `posted_id=desired_id=opinionId`, delivered message receipt, validated presentation digest matches, `dirty_since IS NULL`, latest_candidate_json/digest NULL. No newer failed/pending/deferred candidate, unresolved delivery or newer semantic input. Require mechanical validation 0–60 seconds old. Fresh material must be re-collected/revalidated even for unchanged opinion, and its digest is frozen in the approval intent. An old mechanical_json checkedAt must not be relabeled fresh by a clock alone. All approval-time collection goes through the SAME opinions.offer dirty/candidate path as the scanner, before entering this writer. It may not privately consume a new mechanical snapshot. If evidence/presentation changes, even pass-to-pass, require the updated desired opinion to be actually delivered first. Changes only to collection time or nondisplay freshness may refresh validation without a PATCH because presentation content is identical; freeze the revalidated digest in the intent and compare it again transactionally.
4. Source/evidence preparation and CommDB insertion follow existing StateStore→CommDB lock order. CommDB atomically binds unresolved question/owner and inserts response plus source, checking unprojected founder feedback after the acknowledged source cursor and no competing response. All SQL uses parameters. No network/model wait in the lock.

Store a prepared immutable envelope before source insertion and reuse it on retry; never regenerate decision_at under an existing event ID. On retry: first inspect exact existing source/receipt. Already-written source replays byte-for-byte; do not manufacture a second approve. A prepared intent with no source must revalidate all guards (including age/control) before insertion; if invalid, retain its audit disposition and create no source. A fresh attempt after such terminal disposition uses normal new gate/question identity, not identity recycling.

Fail dominates undetermined; undetermined dominates pass; semantic pass cannot upgrade missing deterministic evidence. Model result/evidence IDs, frozen input and report/plan digests must all agree at writer and projection.

**Version/recovery boundary.** Introduce evidence ledger schema version 2 / `ship-judgment-evidence-v2`, carrying actual semantic alignment/coverage verdicts plus typed reviewed-plan/report proofs (or durable proof IDs), missing kinds `reviewed_plan_blob` and `qa_report`, and reason codes for unavailable/mismatched proofs.
