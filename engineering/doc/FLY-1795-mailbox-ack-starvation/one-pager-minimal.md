# FLY-1795 极简方案(一页纸,v2 redesign)

Issue: FLY-1795 (https://linear.app/geoforge3d/issue/FLY-1795/消息层bug-某个-runner-lane-的收件永不-ack-3-个-in-flight-槽被占死后续指令按租约每-10)
日期: 2026-08-20
基于: founder 整层打回裁定(回炉:极简 + generic,净删除思路);前版审计事实全部沿用,前版方案全部作废

## 问题(一句话)

给 runner 发的消息,投递成功、runner 也照做了,但「销账」要等 runner **自己想起来**跑一条命令——不跑,3 个在途名额被同一批消息永久占住,后面的指令每 10-30 分钟才漏进一条。

## 最小改动(两处,都是改一个函数里的一条 SQL)

**改动 1:投递成功即销账(删掉「等回执」状态)。**
现在:消息送进 runner 会话(durable,内容必达)后,行停在 LEASED 等 runner 自愿回执。
改后:投递成功的那笔更新直接把行置 ACKED(`recordRunnerBatchDelivered` 一处)。
runner lane 从此**不存在**「已送出、等回执」状态——楔死这个类别整个消失,不是被守住,是没了。

**改动 2:pull 消费同笔记投递账(Tadashi 锚点②的「消费即真投递记账」形态)。**
现在:runner 主动来取(inbox 拉取)会销账,但不记「送出过」——账上与静默丢弃同形,今晚三个 Lead 反复取证的根源。
改后:拉取销账的同一条 UPDATE 顺手补 delivered_at(一处 COALESCE)。
「送没送过」从此一条 SQL 可判。锚点①(2309 无护栏 ack)在此语义下自然闭合:runner lane 的每一种销账(投递即销 / 拉取即销)都自带投递事实,不存在「无凭据销账」可走的路径,无需再加谓词护栏。

净帐:**删**掉自愿回执契约、回执等待、重投循环、饿死路径、以及为它们准备的一切保证机制;**加**两条 SQL 内的字段变化。envelope 里「You must ack this batch」一句删除。

## 为什么够了

* 主病 = 槽在等一个可能永远不来的回执 → 改 1 后没有回执可等,楔死无处发生。复发间隔 ~20 分钟的活事故直接止血,且是根治不是止血。
* 副病 = 账上无法分辨「拉取消费」与「静默丢弃」→ 改 2 后同形消失,取证不再需要跨 Lead 多轮实验。
* 已证事实支撑(本轮取证物证):pull 是合法投递通道(整份落盘文件,秒级吻合);「投递但 session 死了没读」的场景,原有重投机制同样救不了死 session——那是换工人的领域(FLY-1628),不是重投的领域。回执机制在 runner lane 上买到的保证,transport 的 durable 写入本来就已提供;它的净贡献只剩这个 bug 类别。

## 不做什么(全部砍掉/不碰)

* **不加** Stop hook 机械回执(founder 点名错签风险——改 1 后它也失去存在理由)。
* **不加** dwell 告警层(watchdog 洪水史整层否决——且改 1 后「占槽超时」这个告警对象不复存在)。
* **不加** 迁移日志表 / 告警 outbox / episode 状态机 / replay 召回命令 / 安全禁令分类 / 新列(last_batch_id 等)——前版 P0/P1/P2 全砍。
* **不动** lead lane(Lead 的回执契约在用且自愈,~3 分钟延迟是烦恼不是事故,另日再议)。
* **不动** 租约、攒批、in-flight 参数。

## 风险与边界(如实)

1. 送达但 session 已死 → 行已销账,不再重投。如实说:重投给死 session 本来就无效,救济一直是换新工人;行为差异仅在账面(死信 vs 已销)。
2. in-flight cap 失去「等回执」含义(送完即空)→ 突发节奏由既有攒批窗(10 条/30 秒)兜底;cap 本是这个 bug 的放大器。
3. delivered_at 语义(送出那一刻,非「被看见」)与 FLY-1773 守卫的对齐属于裁定变更,实现 PR 里显式声明。
4. runner「取走后自己丢正文」的场景(75734239)不在本两处之内:正文本体在库里存活 72 小时 + 归档,永不因销账消失——要不要一条只读找回命令,单独小题另议,不捆绑本修。

## 验收(三条,沿用已定的证人纪律)

* 正对照:构造永不跑 inbox 的消费者,连发多批 → 全部按投递节奏送达销账,零楔死、零饿死。
* 阴性对照:lead lane 与 codex runner 路径行为逐字节不变;pull 拉取照常。
* 取证:任一销账行,delivered_at 非空且一条 SQL 讲清经哪条路送出。
