测试夹具（fixture）是为测试预先准备对象和状态的辅助代码。这里的辅助函数（helper）创建真实内存 Store，并补上该文件已经要求的绿色交接前置条件。

核心流程：两次正确改动为何合并后失败

Pull Request（PR）是把一组改动提交到主分支审查的单元。TypeScript（带静态类型的 JavaScript）会把 type StateStore 在生成代码时擦除；运行时（测试真正执行 JavaScript 的时刻）便没有名为 StateStore 的变量。

持续集成（CI）是在每次提交后自动构建和运行测试的流水线。精确头（exact head）指被测试的那一个完整提交 SHA，避免把祖先提交的绿色结果误算到新提交上。

数据 / 结构模型：只改变创建入口

handoff proof（交接证明）是一份测试用的密封凭证，表示某个代码提交已通过要求的检查，可以继续交给下一阶段。helper 只在 Store 明确说“缺少这份证明”时补证重试；其他拒绝不会被放行。

数据库 schema（表和字段的结构）不变；run、node、execution、activation、owner 等身份字段不变；测试读取的 API 与断言也不变。

关键取舍与拒绝方案

A · 复用绿色 helper（采用）一行替换；与文件既有语义一致；不碰生产代码。
B · 恢复运行时 import（拒绝）只能消掉未定义错误，却重新产生两套夹具语义，并绕过绿色交接前置条件。
C · 测试内手工补状态（拒绝）复制 helper 逻辑；后续契约变化时容易漂移，维护面远大于问题本身。

诚实边界：做什么、不做什么

本设计会做
  • 只替换目标测试的一个创建调用
  • 保留测试名称、步骤、输入与断言
  • 跑具体测试文件和 changed-TypeScript related 选择
  • 以精确头完整 CI OK 收口
本设计不会做
  • 不改生产 StateStore 或交接流程
  • 不改数据库或 feature flag
  • 不机械重写相邻测试
  • 不跑 529；记录 tests_only 豁免
