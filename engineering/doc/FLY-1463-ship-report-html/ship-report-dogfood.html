原来会怎样

02 · 怎么修

病根和修法

原病根判断“ship 前缺总账”是对的；错的是把作者固定成 QA。真正稳定的共同点不是角色，而是图结构：每种 DAG 都有一个最后执行节点，它完成后下一跳就是 founder_gate。

当前实现的 gap

当前义务只存在于 qa-executor.md，因此只覆盖 code / 三段式里的 QA；generic 的 execute、PRD 的 PM produce、design / prototype 的 produce 都会直接进入 founder_gate，却没有 ship-report 义务。

推荐的通用修法

保留模板与 publish-report --issue；新增一份共享 pre-ship contract，在 DAG snapshot / prompt 组装时自动注入给所有“直接连 founder_gate”的执行节点。仍不加 engine gate / feature flag，节点自持有、CI 用 reachability 测试守住。

具体改了什么

  • 已完成：qa-executor.md 旧方案——PASS 前先 publish；这段要退成通用 contract 的一个具体例子，不再是唯一绑定点。
  • 新增可复用模板 ship-report-template.html：Apple 浅色、逐段留言框、Ship/不 Ship 勾选、一键复制 SHIP-VERDICT 回传、CSP nonce 占位。
  • 已完成且可保留：flywheel-comm publish-report --issue；Bridge 按 issueIdentifier 唯一解析 parent thread，多 Lead 歧义或无命中一律 fail-closed（404），绝不误投大频道。
