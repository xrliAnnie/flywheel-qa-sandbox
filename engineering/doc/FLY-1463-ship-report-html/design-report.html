2026-08-09 更正:本页保留当时设计，其 ship / 不 ship 控件与回传文本已废止，请勿作为批准入口。现行批准只认 ship 卡片上的 founder ✅ reaction 或卡片 thread 内 founder 直接回复。
一句话:以后每次 ship gate 冒出来的那一刻,你会在同一个 thread 里同时收到一份 ship-report HTML —— 怎么修的(多张图)+ QA 怎么测的(数字/真机/529 铁证)一页看清,页面上直接留言、勾 ship 或不 ship,一键复制粘回 thread 就是你的裁决。不用再追着 Lead 问。

📱 这页本身就是那份 ship-report 的"试驾版"——每一节下面都有留言框,页尾有裁决区和复制按钮,交互形态跟以后 QA 交付的总账完全一样。

● 1 · 现在的痛 → 以后的样子

今天:gate 冒出来时你手里只有一张"⏳待批"卡。修了什么、测了什么全在各处,只能追着 Lead 问——今天一上午就是活证明。
图 1 · 现状:gate 到了,信息没到
以后:QA runner 在报 PASS 之前,先把总账 HTML 发进 issue thread。PASS 一发,gate 卡紧跟着落在报告后面——两条消息永远前后脚,你点开 thread 一次看全。
图 2 · 新流程:报告先落,gate 紧跟

● 2 · 为什么"永远一起到"是有保证的

关键是一个从代码里核实过的硬事实:QA runner 发完 PASS 后会被系统立刻自动清理(腾资源)。所以规则定为"先发报告,再报 PASS"——不是靠自觉,是发晚了就物理上没机会发了。顺序反过来根本行不通,这让规则天然自我强制。

报告发进 thread 的方式:给现有的报告发布命令加一个"按 issue 号投递"的小能力(--issue FLY-XX),Bridge 按号找到对应 thread。它只送信、不拦路——引擎永远不会因为"报告没发"而扣住你的 gate(你的铁律:不加引擎门)。万一发布失败,QA 会大声报给 Tadashi 人工补投,PASS 照常、绝不静默跳过。

● 3 · 机制怎么搭(照 FLY-1461 同一招)

跟 529 N-to-N 那条一样:规则写进 QA runner 自己的岗位说明书(qa-executor.md),它自持有、不靠 Lead 记性;CI 守卫盯着这条规则和模板,谁改坏了 CI 直接红。QA 不用每次现写页面——仓库里放一份现成模板(留言框/勾选/复制按钮都做好),填空即用,长相统一。

图 4 · 三层结构:规则 + 工具 + 守卫

岗位规则qa-executor.md 新硬规则:PASS 前必发 ship-report;发布失败必须大声上报,静默跳过 = QA 未完
HTML 模板现成的总账模板:苹果浅色卡片、逐节留言框、ship 勾选、一键复制;QA 只填内容

CI 守卫自动检查规则和模板没被删改坏(FLY-1461 同款)

● 4 · 那份总账 HTML 里有什么(你亲定的三块)

① 怎么修多张 Mermaid 图:病根在哪 → 改了哪条路 → 数据怎么流。founder 语言,不堆术语。
技术注:托管页出于安全不跑外部图库,图在生成时就预先画成 SVG 嵌进页面——你看到的本页 4 张图就是这么做的,效果即所得,手机秒开。
② 可互动每个区域下面留言框(跟本页一样)+ "是否 ship"勾选 + 一键复制。复制出来的文本自带区域标记(哪节的批注就标哪节)和 SHIP-VERDICT: yes/no,粘回 thread,Lead/runner 能精确定位"哪个区域有什么问题"并收到打回信号。
③ QA 测了什么固定清单:单测/集成数字 · 真机验证 · E2E/529 N-to-N(做了就贴 529 thread 链接 + 预算内直接内嵌 GIF/关键帧截图,不用点出去)· 诚实边界:什么没测、为什么、何时补。

● 5 · 关键取舍(和被否掉的路)

选了没选为什么
规则进 QA 岗位说明书 + CI 守卫引擎强制卡 gate你的铁律:不加引擎门。引擎卡会把"报告故障"升级成"ship 停摆"
QA runner 直发 threadLead 代发Lead 转发是概率性的——这正是本 issue 要治的病(FLY-1461 同一教训)
留言/勾选 → 一键复制粘回 thread页面按钮直连回传托管页出于安全被禁止对外发请求(手机也够不到本机 Bridge)。真·一键直达回传要新建公网收件通道,列为 v2 单独立项;复制粘贴多一步,但今天就能用、零新风险
图预渲染成 SVG页面现场画图安全策略禁外部脚本;整个画图库嵌进去会超 512KB 页面上限。预渲染零依赖、手机快
GIF 预算内内嵌,超了嵌关键帧+永远保留 529 链接无限内嵌页面硬顶 512KB;链接零成本永不丢

● 6 · 诚实边界

  • 只管 PASS 时刻。QA FAIL 不发总账(你本来也不会被打扰);修完复测最终 PASS 时照发最新一轮的。
  • 不改 gate 本身。批准动作还是现在的流程;HTML 是拍板的"决策弹药",不是新的批准通道。
  • 回传是复制粘贴,不是页面直连。验收标准(你留言 Lead 能定位、勾"不 ship" Lead 收到)都由复制的结构化文本闭环;页面直连回传 = v2。
  • 约束靠"岗位规则+CI 守卫",不靠引擎。跟 529 N-to-N 同一档强度——够硬,但理论上 runner 违规不会被引擎拦(是你拍板保留的取舍)。
  • Codex design review 已通过。APPROVED · 3 轮 账号修复后用钉死的审稿模型真跑了 3 轮(xhigh):第 1、2 轮共提出 10 项(含投递路由必须与 gate 同链、发布成功必须验回执不认 exit 0、旧流程/存量任务的生效前盘点、批注跨报告隔离等),全部采纳进计划;第 3 轮零遗留,结论 APPROVED — ready to implement。
  • 做完的验收(在一次真 ship 上跑):你留一条 comment → Lead 收到并定位区域;勾"不 ship" → Lead 收到打回信号;mermaid 图真渲染;529 GIF/链接真可见。
