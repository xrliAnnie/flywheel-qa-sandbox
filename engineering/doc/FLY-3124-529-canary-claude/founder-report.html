一句话：当前节点只完成设计；下游必须同时拿到服务器授予的独占写入权（TURN）、原生指令和受控通信数据库的只读副本，才可以把 marker（待记录的精确文本行）逐字追加到 probe.txt 并在本地 Git 提交。

1 · 为什么现在不写 marker

金丝雀（canary）是一项很小、隔离运行的探针，用来确认一条传输链路真的把消息送到正确的执行体。

TURN是服务器授予某个工作流节点的独占写入权。当前结果是 yours，所以 design 文档可以写，但 TURN 本身不包含 marker 内容。

执行体（execution）是一次有独立身份的 agent 运行。当前执行体是 Codex design；输入没有 exact marker，root probe.txt 也不存在。

结论：承认真实 TURN，拒绝伪造另一条 Claude execution 的收件证据。

2 · 核心流程

phase（阶段）是工作流中职责固定的一段。Design 只交付文档和审查；downstream 节点先取得自己的 TURN，再区分“没有收件”“只在普通 inbox 文本里出现”和“原生指令”三种情况。

CommDB 只读快照是通信数据库由受控工具创建的临时副本。下游只在副本里用参数化查询——把待核对的值作为参数传入、而不是拼进查询文字——核对 instruction id、收件 execution、发件 Lead、消息类型和原始正文；不会读取或复制正在运行的数据库，也不会用会消费消息的 inbox 命令做证明。

图中所有红色出口都是“停止写入并报告”。空输入可在服务器允许时走 no_code（零代码变更完成）；已有本地 probe commit 时只能由 Lead 关闭或取消这次限定运行。

3 · 数据与证据模型

provenance（来源证据）说明一条 marker 是谁、在什么 execution、通过什么指令送来的。它必须和 TURN、CommDB 快照、exact line、持久化回执及 local commit SHA 相互印证。

身份execution id、vendor 与 phase 防止拿别人的回执充数。
授权TURN 只回答“谁能写”；原生 instruction 与 CommDB 快照共同回答“写什么、是谁发的”。
内容marker 逐字保留；禁止首尾空格，让 exact bytes 与 diff-check 采用同一规则。
审计instruction id、正文 SHA-256、complete-line count、staged diff、probe commit SHA 与 completed 回执相互校验。

4 · 关键取舍与拒绝方案

  1. 采用：TURN + 原生指令 + CommDB 快照 + 条件式 append。 普通 inbox 文本不是原生证明；没有完整证据就不写。
  2. 采用：shell-safe exact-byte append。 marker 先进入临时文件，再用 read -r 与 printf '%s\n' 当作纯数据追加；禁止 eval 或把内容拼进 shell 源码。
  3. 采用：持久化幂等回执。 先保存 pending 的 instruction id 与正文 hash，提交后再保存 completed 状态和 probe SHA；同 id 同 hash 才能安全去重。
  4. 拒绝：从 issue title 推导 Claude BOOT / R4 marker。 那些文字绑定外部 driver 创建的另一条 Claude execution。
  5. 拒绝：自定义 owner + 时间戳 marker。 可读但没有发送方，不满足“requested marker”的逐字合同。
  6. 拒绝：让 design 直接写 probe。 会混淆阶段职责，让设计审查绑定到已经发生的实现。

5 · 诚实边界

DAG（有向无环工作流）把 design、implement、QA 等步骤按依赖连接起来；节点不能替 orchestrator 派发后继或扩大权限。

本设计会做到：三份设计文档、两张本地渲染图、设计审查、Founder HTML，以及一份可执行的 downstream append 合同。

本设计不会做到：创建或修改 probe.txt、声称收到 Claude native mail、改产品代码、创建 PR、请求 ship、merge 或部署。

若下游没有原生 marker 且仓库未变，只在服务器允许时走 no_code；若已有只含 probe.txt 的 local-only commit，no_code 不再真实，必须请 Lead 执行 server-authorized close/cancel。

两张图的 committed render 分别是 core-flow.svg 与 data-model.svg；HTML 内联的就是这两个本地 mmdc 产物，不依赖远程渲染器。
