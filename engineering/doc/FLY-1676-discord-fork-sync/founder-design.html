Discord 插件:追平官方 + 修好自动同步 + 根治"被冲掉"

FLY-1676 · 设计方案(已过 5 轮独立技术评审)· 2026-08-10 · 每节下方可留评论,页底一键汇总复制

0 · 一句话总结

按你的裁定不把插件搬回自己仓,继续跟着官方仓跑:把我们的插件副本仓一次性追平官方(落后 4 个月了),把烂了 3 个月的每日自动同步修好并让失败会"叫",再给运行中的插件搬一个官方刷新永远碰不到的新家——今天上午它又被官方刷新冲回原版两次,这已是第 3、4 次。

1 · 问题:为什么定制版反复被冲掉

我们的 Discord 插件带 20 处定制(allowBots 白名单、圆桌线程、回复守卫、消息收据等)——这些是 Lead 之间互通、圆桌讨论、卡片审批的命脉。但插件运行的目录,归 Claude Code 的"官方插件商店"管:每次有 Claude 会话启动,之后 0–10 分钟内商店可能自动刷新一次,把官方原版整个铺回来,我们的定制当场全被抹掉。这台机器整天都在起会话,所以是一天多次的持续威胁。调查当天上午 09:48 和 11:23 就实测发生了两次。

目前唯一防线:Lead 启动时会自检并铺回定制版。但正在运行的 Lead 如果插件进程中途崩溃重启,就会直接加载磁盘上的当前版本——赶上被冲窗口就中招,而且这类事件没有任何告警,全靠人肉撞见。

2 · 第一件事:修好每日自动同步(它烂了 3 个月,而且是静默烂)

你记得的"自动更新"确实存在——插件仓里有个每日同步任务。但它最近 100 次运行 100 次失败(从 5 月 3 日起可查的每一天),而且失败不发任何通知。审查发现真正的死因和 issue 里猜的不一样:不是代码冲突——把我们的定制叠回官方最新代码这一步每天都成功(官方 4 个月根本没碰 Discord 插件,天然不冲突);挂在最后"推回仓库"一步:同步任务用的默认钥匙(GITHUB_TOKEN)没有推送"自动任务定义文件"的权限,而官方这 4 个月恰好新增了这类文件,于是天天被 GitHub 拒收。

修法:换一把由你铸造的专用钥匙(SYNC_PAT,只对这一个仓有效),并把告警补全——任何一步失败都发 Discord 消息,不再静默;推送前还加一道"逐字节守卫":确认 Discord 插件内容与叠加前一丝不差才允许推,防止坏同步把定制弄丢。

3 · 第二件事:给插件搬家,官方刷新从此碰不到它

被冲的根因是"两个写入者争一个目录",打补丁永远在赛跑。根治 = 让插件搬进我们自建的"小商店":它只有一个条目,指向我们的插件仓(不是把代码搬进来,只是一个指针——完全符合你"不单独抽仓、继续跟官方跑"的裁定)。官方商店继续服务其他插件,想怎么刷新都行,与 Discord 再无关系。

切换纪律(评审重点打磨过的部分,并按"不做开关"的铁律定形):不引入任何模式开关——新家地址和配套自检由同一份代码一起换血,部署即生效;切换 = 全部 Lead 先停、翻转配置、再全部启动的一次性窗口,结构上不存在"一半 Lead 新家、一半旧家";每个 Lead 启动后都取证确认加载的是新家,全部确认才拆旧防线。出问题的回滚 = git revert + 恢复脚本反向翻转配置 + 再跑一轮重启,旧机制在验收通过前始终原样在位兜底。

4 · 你问的"之前那些改动还有需要吗"——逐条盘点结果

20 处定制全部仍在服役,没有一处被别的机制取代。按重要性分组:

定制作用结论
allowBots 白名单没有它,所有机器人消息被过滤 = Lead 互通/圆桌/卡片审批全断命脉保留

5 · 关键取舍 & 否决掉的方案

  • 否决:把插件代码搬进自己仓(vendor 化)——你已裁定,不再讨论。
  • 否决:改官方商店的源指向我们的仓——查了 Claude Code 程序本体:官方商店是保留名额,只认 Anthropic 官方源,改了也不算数。
  • 否决:加个看门狗,被冲后秒级恢复——那是在赛跑里跑快一点,不是退出赛跑;与项目"修结构、别加报警器"的纪律相悖。只有搬家方案彻底失败时才作为末路兜底。
  • 取舍:自建小商店(选中)——多维护一个指针文件,换来结构性安全:不依赖任何官方未承诺的行为。评审确认切换期旧插件始终在位兜底、一次性直切、随时可回退;按"不做开关"铁律,不留任何长期模式开关。
  • 取舍:同步失败告警走 Discord——告警通道自己也可能挂(那时发不出消息),已如实记档,兜底是 GitHub 邮件通知 + 例行巡检。

6 · 需要你亲手做的(只有一件)

铸一把专用钥匙 SYNC_PAT(GitHub fine-grained token,只对插件仓有效,含 Contents + Workflows 写权限)并存进仓库 secret。这涉及你的 GitHub 账号,只能你来;实施时会给你一张一步步的操作卡。约 3 分钟。钥匙一年后到期——到期时同步会失败并自动告警提醒换钥匙,不会再静默。

7 · 诚实边界:这个设计做什么、不做什么

做

  • 插件仓一次性追平官方(落后 2818 个更新),20 处定制原样叠加,内容逐字节验证。
  • 每日同步修复 + 全失败路径告警 + 推送前逐字节守卫。
  • 运行插件搬进自建小商店,官方刷新结构性无法再冲掉它;验收就用你的标准:自动更新跑一次之后,运行副本仍是定制版。
  • 顺带:真机验证 fetch_messages(拉历史消息)功能。

不做

  • 不改插件任何功能行为(纯基建单)。
  • 不动官方商店里其他插件(context7、playwright 等继续用官方原版)。
  • 不承诺"官方永远冲不进新家"依赖官方未公开的内部行为——依赖面已压到最小(自建商店没人刷),且长期哨兵在岗:万一 Claude Code 未来版本行为变化,Lead 启动自检会拦下并告警,不会静默坏掉。
  • 官方哪天真的改了 Discord 插件代码,同步会拦下等人工审(4 个月来发生 0 次)——想要的官方新功能仍需人工确认后合入,不会自动进舰队。
