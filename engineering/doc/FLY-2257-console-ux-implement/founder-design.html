FLY-2257:管理台四个改动怎么落地

工程设计说明 · 2026-09-03 · 分支 flywheel-FLY-2257 · 上游是 FLY-2071 的产品定义(你 9-02 拍板的那份)· Codex 设计评审 5 轮后 APPROVED · 每个卡片下方都可以留意见,页底一键汇总复制

1. 一句话总结

把你在 18982 原型上看过的四个改动,原样落进真正的管理台(/ 那一页),不另开第二个页面;页面需要的所有数据都从后端已有的那一次 snapshot(管理台打开时一次性拿到的全部状态)里来,不在前端拼、不在前端猜。21 个 flag 的值、默认值、解析方式一个字节不动 —— 改前改后各读一次,逐条比对必须相同。

四个改动:① DAG 模板(一条流水线的节点顺序图)产品/工程切换 + 所有节点框同一尺寸 + 不裁切;② 花名册每项可点,链接只用后端给的 sourceLink(后端按文件路径生成的 GitHub 链接);③ 删掉项目面板;④ Flag 页合成一个列表,每行一句「它现在是什么状态」,并删掉 governance_gate 类别、把规矩写进文档。

2. 核心流程:数据从哪来、页面怎么画

管理台的合同一直是「一个读口 + 一个写口」。这次不加任何新接口:原型为了演示临时开的两个读接口不落地,它们的数据并进 snapshot。页面打开只发一次请求,拿到后画三块。

「产品 / 工程」的归类不写模板名单:模板里只要出现 design / implement / qa 这三种类型的节点就归工程,否则归产品。规则本身印在页面上,而且印出来的那句话和代码用的是同一个常量,改一处两边一起变。按今天库里的真数据:「工程开发」「轻量开发」归工程;「产品设计」「产品需求」「原型验证」「通用」归产品。

3. 数据 / 结构模型:后端多给什么、少给什么

三处新增都是只读投影(后端把已经有的东西多抄一份给页面),一处删除是页面已经不再用的字段。

  • 模板 graph:现在 snapshot 只给「能改模型的节点」;画图还需要「创始人门」「合入」这两个不可改的节点和回环线,所以另给一份 graph。两份并存是有意的:可改的那份带写入能力,画图那份不带 —— 合成一份会让「创始人门」也长出一个假的模型下拉。
  • 花名册链接:后端早就在 snapshot 里给了每个角色的 sourceLink(实测 6 个项目 25 个角色 25/25 都有)。页面只做一件事:有链接就可点,没有就保持不可点并说明原因。前端里不会出现 github.com/ 这样的拼接,也没有「角色 → 链接」对照表 —— 新增一个角色 .md,链接自动就有。
  • flag 的「打开代表什么」:这是这次唯一动到 registry(flag 登记表,唯一权威)的地方:每个开关型 flag 登记一个字段 onMeans,取值 enables(打开 = 启用某功能)或 disables(打开 = 停掉某功能)。21 个里恰好只有 cmux_rebind_disabled、cmux_watcher_rebuild_disabled 是 disables。前端从此零猜测;原型里「名字带 _disabled 就当停用开关」那条猜法整个删掉。

4. 节点框为什么以前不一样、现在怎么算

你 8-26 看到「工程开发的框小、轻量开发的框大」,根因不是样式没统一,是原来每张卡各自缩放以求放得下 —— 卡越长框越小,机制上就保证了不一致。改法是做减法:全局只算一个尺寸。

两个容易丢的点都写进了验收:① 最长链路要看全部模板,不只当前那个 tab —— 否则只是把不一致从「卡与卡之间」挪到「tab 与 tab 之间」;② 验收必须含一条冷路径(直接打开在目标宽度、全程不动窗口)并报告 resize 事件次数为 0 —— 因为改窗口大小本身就会触发修复,靠改窗口测出来的「全绿」证明不了「一打开就对」。

5. Flag 页:一个列表,每行一句人话

不再分 feature / kill_switch 两组,不再出现分类标签。每一行按下面这棵树选一句话直接印出来,不是 tooltip、不是角标;旁边配一枚小标「维持默认 / 已偏离默认」。开关本身还是原来那个(能改的才能点),没有加任何新开关。

最后那条「没登记」分支在生产上不会出现:登记表有一条自动检查,开关型 flag 没填 onMeans、或者名字以 _disabled 结尾却填了 enables,提交就变红。这条检查还配了「故意改错一条必须变红」的对照,确保检查真的在起作用。

删 governance_gate:这个类别今天 0 个成员,机制(类型、两处策略分支、一处开关资格判断、界面上的图例)全删;同时在 flag 约定文档写上:治理性策略不做成 flag,写死在代码里,要改走 PR。删的是机制,不是规矩。

6. 关键取舍与被拒方案

方案判定原因
把原型当第二个页面并行挂到 /console-next拒同一份状态两个页面 —— 正是你删项目面板的理由。原型的路由、只读改造、两个临时接口都是演示脚手架,不落地。
沿用原型「名字带 _disabled ⇒ 停用开关」的猜法拒今天不错是运气:下一个反向 flag 只要不这么命名,页面就读反且不报错。改为 registry 登记 + CI 检查。
给每个 flag 手写一句自由文本「打开代表什么」拒21 处各写一句,文案散在 21 处;结构字段 + 一处 7 句模板更省也更不会漂。
页面再开两个读接口拿模板形状和 flag 语义(原型做法)拒破坏「一个读口」合同,现有测试已经断言页面只用 snapshot。数据并进 snapshot。
原型 V2 布局原样搬(模板卡下没有模型下拉)拒那是只读 mock 才看不出的漏洞:模型下拉是管理台唯一的 DAG 写路径。落地版每个节点保留模型行。
这次顺手把 registry 里 feature / kill_switch 两个类别也整体删掉另开单Tadashi 裁定本单不做:界面与 snapshot 已不再读它,删登记表字段是另一件事,挂 FLY-2071 后续。
「通用」模板落在产品栏照规则它的节点类型是 generic,按「否则 ⇒ 产品」的规则归产品;你在 18982 上看到的就是这样。若不认可,改的是规则(产品问题),回 Honey Lemon。

7. 诚实边界:这个设计做什么、不做什么

  • 做:四个改动区全部落进生产管理台;registry 加一个纯展示字段;删 governance_gate 机制 + 补规矩;真浏览器证据(三档宽度冷路径、跨 tab 框尺寸集合、不裁切、9 节点最坏情况换行、链接逐字比对)+ 21 个 flag 值改前改后 diff。
  • 不做(Honey Lemon 已明确):S1–S5 五条结构性产品问题(节点和手册连不上、面板选项比模板允许的多、模板挂在项目下、21 个开关 0 个能在这页改、flag 说明是工程语言)—— 带回给你单独定。
  • 不做(不在四个区):18982 上还有两处 FLY-2071 的小 polish(左侧项目栏重复的分组大写标题、节点旁的「模板绑定」小标),Tadashi 裁定另开单承接;手机版 flag 报告页的措辞不动。
  • 不做:窄屏(1024 以下)真正的响应式;头像;不加任何开关或旋钮。
  • 已知残余:registry 多了一个字段;管理台 snapshot 的合同版本号从 1 升到 2(删了一个字段、加了必填字段;后端生成时自检版本,页面也核对版本号,对不上就提示「请刷新」而不是静默读到空字段;唯一的跨版本读者是部署前就开着的旧浏览器页)—— 这些都是元数据,flag 的值不变;验收只比值。本设计经过 Codex(独立 AI 评审)5 轮设计评审:前两轮抓出 16 处(含框尺寸阈值算错、连线不能靠数组顺序、图节点 id 命名空间不一致、Flags 页样式漏迁、隐藏页面几何断言假绿),第 3 轮通过;之后按 Tadashi 要求补了三条验证(隐藏态断言要能自证、连线数随数据变、旧页面读新数据要实测),第 4 轮又抓出 1 处测试写法错误,第 5 轮通过,全部已进 plan,实现与 QA 由后续节点接力,这份说明不等实现完成就先给你看。
