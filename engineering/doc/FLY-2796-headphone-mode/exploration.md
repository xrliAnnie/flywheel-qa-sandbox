## 已发现的实质缺口

1. `HeadphoneDaemonCore.processGatewayMessage` 先推进 cursor，mode off 不 ingest；离线读取不等于能恢复关闭模式期间的积压。
2. 旧 Raya `InboxReader@f669d1b` 的非决策消息走文字旁路，不出声。本单要显式去掉这条旁路，问题和汇报都进入播报计划。
3. 房间有两套音频接法。voice-codex 已依赖 voice-bridge；直接让 voice-bridge 反向 import 会产生包环。需要提取同一实现，不只是统一类型名。
4. `TranscriptSink.append` 无可等待回执，JSONL 写错后只记错并丢弃后续写入，不能支撑副作用溯源。
5. 本地提交音频不证明人耳听到；`audibleTail`（估算）只提供调度估算，不能伪造远端交付。

## 选择

复用现有模式规则、Bridge StateStore、Lead 信箱和房间底座；补可靠接缝。拒绝另建语音 daemon 状态权威、复制 Raya 文件信箱、造第三套房间或把 V2 顺手扩成完整语音审批。

所有来源消息一开始全部纳入，不启用偏好筛选。保留正文与来源供追溯；三段播报稿“是什么 / 为什么 / 接下来”负责可听表达，不把超长或坏文案默默过滤掉。新消息在当前发言结束后主动排入，不在本单加入打断能力。
