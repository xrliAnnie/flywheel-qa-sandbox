# Design Review — FLY-2190 plan.md (Round 4)

Date: 2026-08-30
Author: Codex
Status: CHANGES REQUESTED

## Summary

R4 fixes the R3 safety overclaims: §0.0.1 now makes `brew link` an execution mutation, `qa-result` must become native-first, S2 has a defined classifier, and P1–P7 remain a complete set of S3 blocker classes at this level. I still cannot approve implementation because the S1 deploy gate is not mounted into the repository's automatic deployment transaction, and two claimed discovery closures omit live source formats; the plan is close, but those are correctness guarantees rather than wording polish.

## What's Good (Keep)

- The three-bucket treatment in §0.0.1 is now safe and clear. Installed Cellar bytes and shipped tools are reusable assets; bottle/closure evidence is non-mutating preparation; `brew link` and server restarts are execution-only. The standalone **DO NOT LINK** statement cannot reasonably be read as “S3 is nearly ready.”
- Requiring native-first order in `qa-result.ts` is the right disposition. Source confirms that its current first-match list is PATH-independent and that `buildGitHubAuthEnvironment` then seals the selected directory into `PATH`, so a comment-only Intel exception would have defeated the issue's deadline objective.
- The effective-selection criterion in A4b is the right policy: inspect the exact post-S1 PATH and require the selected client to be the 3.5a x86_64 binary. This correctly covers earlier user-bin shadows instead of treating one missing symlink as proof.
- The carrier/out-of-carrier split and the narrowed cmux observation are evidence-sized. The real brake branches, hermetic `npx tsx` bootstraps, read-only `gh` families, and functional codec smoke are proportionate to the consumers found so far.
- S2's registry plus discovery architecture is sound, and the plan now honestly names CI as its only delivered mount. Extending the existing read-only checker and existing alert pipeline remains consistent with repository conventions.
- The exact-pair tmux invariant is now correctly scoped to every relevant 3.5a client, including absolute-path pins. P1–P7 cover transactionality, full server ownership, executable rollback, mixed-version command behavior, runtime-client convergence, consumer compatibility, and launch-architecture provenance. I still do not see a missing P8 blocker class.
- Ignoring the earlier “rolling recommended / seconds, zero risk” instruction after its premises were disproved was the correct engineering decision. Recording and sending the correction was necessary; §0.0 and A9 also correctly prevent S1+S2 from closing the umbrella Rosetta risk.

## Issues & Recommendations

1. **BLOCKER — A4b is still a receipt specification without a deployed producer or enforcement point, so “merge S1 unconditionally” is false for this repository's delivery path.** `update-flywheel.sh:483-489` automatically deploys whenever `origin/main` differs from `deployed-sha`; its deploy path fast-forwards the live checkout at `:138` and only then invokes `restart-services.sh` at `:144`. The live Bridge and voice-Bridge launchd jobs point directly at wrapper files in that checkout (`scripts/launchd/com.flywheel.bridge.plist:9` and `com.flywheel.voice-bridge.plist:9`). Therefore a gate added in the same S1 commit cannot run before the old updater fast-forwards that commit, and a KeepAlive restart can consume the new PATH before an unspecified receipt check. The plan also names no receipt command, storage/schema, expiry duration, or exact fail-closed call sites. **Fix:** ship and deploy the host-selection gate as a prerequisite phase before the PATH reorder, then make S1 merge conditional on proof that this gate is active. Mount it before updater fast-forward and re-check under the restart transaction immediately before any converge/kickstart; cover manual `restart-services.sh` as well. Bind the receipt to host + target SHA + transaction, test user-bin shadowing/staleness/host drift, and make all relevant entry points refuse on missing or invalid evidence. Alternatively, explicitly pause automatic deployment and KeepAlive consumption under a founder-authorized transaction, but the current “unconditional merge” wording cannot remain.

2. **HIGH — A4b invokes the wrong executable-image primitive.** `host-terminal-cutover.sh:278-294` defines `extract_tmux_image(pid)`: it runs `lsof` against a live tmux PID. A4b instead has a selected pathname from `command -v`; it has no PID, and `host-terminal-cutover.sh` is a command-dispatching script rather than a sourceable function library. Passing a pathname cannot work, while passing an arbitrary existing server PID would prove the server's current image rather than the client's selected image. **Fix:** canonicalize the selected pathname directly and run `tmux -V`/`file` on that canonical target. If process-image proof is intentionally required, specify an isolated-socket positive control and refactor the extractor into a sourceable shared helper; do not claim a path was “extracted” by the current PID-only function.

3. **HIGH — the consumer sweep and S2 discovery closure still omit live code formats.** §1.5 scans only `*.sh/*.ts/*.js/*.mjs/*.plist`, excluding the load-bearing `*.py` files that can themselves spawn children (`restart-storm-gate.py`, persisted hooks, and other repository Python), plus extensionless executable wrappers and existing `*.cjs`/`*.mts` files. §2.2.1 is narrower still: it omits even `*.js`, so a new unregistered JS or Python PATH declaration would bypass the future-drift guard while the plan claims discovery closure. A read-only reverse check of current Python files found only already-known overlap tokens, not a proven ninth carrier command, but the stated method still does not establish the claimed boundary. **Fix:** define one reviewed source-file enumerator covering at least shell, Python, JS/TS variants (`js/cjs/mjs/ts/tsx/mts/cts`), plist, and extensionless shebang executables; use it for both sweeps where applicable. Re-run the 372-name reverse sweep and add source-tree negative tests in at least one Python/JS format and one extensionless wrapper so the closure cannot pass only because its test uses a scanned suffix.

4. **HIGH — the upstream correction banners still leave the withdrawn `brew link` safety conclusion recoverable.** `exploration.md:120`, outside the specifically withdrawn §6 block, still says “link 本身是安全动作.” More importantly, `research.md`'s banner says §2.1 remains valid while §2.1 line 73 says a new client drives the old server “完全正常” and that this makes step 0 safe. Those sentences exceed the measured handshake/`list-sessions` result and contradict R4's P4 gate and **DO NOT LINK** rule. **Fix:** correct the underlying sentences, not only the banners: retain only “the measured `list-sessions` call did not produce a protocol mismatch,” immediately state that production command safety and `brew link` safety are unproven, and remove the inference that step 0 is safe. This is especially important because these are the evidence documents implementers are told to read first.

5. **Non-blocking cleanup to carry with the fixes.** For `npx`, the selected target is a JavaScript entrypoint, so A4's “architecture triple” should record script identity plus the actual shebang/interpreter path and architecture (or mark file architecture not applicable), rather than pretending the script itself is arm64. Also align the risk table's `npm` row with the actual A4 split, and update the founder HTML's stale “two rounds / 19 findings” and “372 different programs” wording to the current review count and “different realpaths.” None of these requires a new design round by itself.
