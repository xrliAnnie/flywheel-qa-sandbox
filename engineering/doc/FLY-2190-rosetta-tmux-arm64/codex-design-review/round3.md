## Summary

R3 closes the substantive conceptual gaps from R2: S1 merge/deploy are separated, the consumer sweep is materially stronger, S2 no longer claims a nonexistent converge/provisioning mount, and P1–P7 now cover the S3 blocker classes found in this audit. Rejecting the Lead's pre-review “rolling recommended / zero risk” instruction and sending an explicit correction was the right call, but the plan still needs changes before implementation because §0.0.1 misclassifies `brew link` as preparation, A1b permits a deadline-defeating Intel exception, and the S2 discovery and S1 receipt/smoke contracts are not yet executable as written.

## What's Good (Keep)

- §0.0 correctly prevents the S1+S2 PR from closing the umbrella Rosetta risk. A9 gives that ownership rule a machine/checklist-visible acceptance point.
- §1.6 now makes the correct distinction: source merge is harmless, host deployment is conditional. The statement that today's absent ARM link is driftable state rather than an invariant is exactly the right model.
- The reverse overlap sweep is a substantial improvement over the prior whitelist guess. Source inspection confirms the load-bearing findings: Bridge and voice-Bridge boot through `exec npx tsx`; voice-Bridge resolves bare `ffmpeg`; Python is used in restart gates and persisted hook commands; and `qa-result.ts:363` independently prefers `/usr/local/bin/gh`.
- Finding the `qa-result` first-match list is valuable. It is genuinely PATH-independent and would otherwise leave one x86_64 GitHub credential path after the general switch.
- S2's registry-plus-discovery model is the right architecture, and retracting converge/provisioning as mounts is honest. CI really enumerates `check-global-path-hygiene.test.sh` at `.github/workflows/ci.yml:607`.
- The exact-pair tmux invariant is now evidence-sized. P1–P7 cover transactionality, full server ownership, executable rollback, mixed-version behavior, runtime-client convergence, final consumer compatibility, and inherited architecture preference. I do not see a missing eighth technical blocker class at this level.
- The correction banners are the right mechanism, and the plan is correct not to obey an earlier operational instruction after its premises were disproved. The explicit correction to the Lead was necessary to prevent the withdrawn story from reaching the founder as current fact.

## Issues & Recommendations

1. **BLOCKER — §0.0.1 can still be read as “S3 is nearly ready,” because `link` is not host preparation.** The installed 3.7c Cellar binary and shipped helpers are reusable assets; that is the valid Lead insight. But `/opt/homebrew/bin/tmux` linking immediately changes the selected client for every already-native-first carrier and is therefore a production cutover mutation gated by P1/P4/P5 and founder authorization. A “cutover receipt” is likewise evidence produced by the eventual transaction, not a missing file that can be created to make the host ready. The caveat at line 40 helps, but the heading “只差 link + cutover receipt,” the two-column “already have / still missing” table, and `design-report.html:209` still foreground the unsafe shorthand. **Fix:** retitle this as “reusable host assets already exist; no S3 mutation is authorized.” Separate (a) installed reusable assets, (b) preparatory evidence still to build/rehearse, and (c) execution-only mutations. Put `link` in (c), add an explicit **DO NOT LINK before P1–P7/runbook authorization** statement, and describe receipts as transaction outputs. This preserves the Lead's useful reuse point without implying operational readiness.

2. **BLOCKER — A1b's “change it or document Intel-first” choice is too weak for a Rosetta-removal issue.** If `qa-result.ts:363` keeps `/usr/local/bin/gh` first, it remains x86_64-only and fails when Rosetta disappears even though a native CLI exists. A code comment does not dispose of that deadline risk, and it would let an implementer satisfy A1b without fixing the split brain. **Fix:** make native-first order the required S1 disposition and add a deterministic test for default candidate selection. Include this non-PATH precedence list in S2's guarded registry/discovery closure so it cannot silently revert. If a real Intel-only compatibility need is discovered, treat it as a separately owned, expiring exception with evidence and a native fallback—not as a comment-only alternative.

3. **BLOCKER — S2's repo-wide “same line contains both prefixes” discovery rule cannot pass the current tree without a defined grammar and exception model.** The repository already contains intentional Intel-first fake-bin fixtures (`lead-alert-dirs`, `codex-log-guard`, `lead-alert-founder-timezone`), native-first test fixtures, comments mentioning both prefixes, the non-PATH `qa-result`/`git` candidate arrays, QA probes, and historical engineering evidence. A literal whole-repo line scan either flags all of these or silently grows ad hoc exclusions; neither behavior is specified. **Fix:** define the exact source roots/globs and candidate grammar, plus a reviewed exception registry containing path, line shape, and reason. Treat every discovered candidate as one of: guarded precedence declaration, explicit irrelevant/non-PATH occurrence, or violation; unknown is fail-closed. Add tests for comments, candidate arrays, the three intentional fake-bin fixtures, historical docs, and a genuinely new production declaration. Also name the concrete source-mode CLI (for example `--source-tree <validated-root>`) that CI must invoke and whose verdict A3 observes.

4. **HIGH — A4b still describes a policy, not a reproducible deploy receipt.** Checking only whether `/opt/homebrew/bin/tmux` exists misses an earlier `$HOME/.local/bin` or `$HOME/.npm-global/bin` shadow and does not prove what the post-S1 carrier PATH actually selects. Those shadows are absent today and the effective post-S1 command currently resolves to `/usr/local/bin/tmux` 3.5a x86_64, but that is also driftable state. “时效不得跨越部署窗口” has no defined window, producer, storage location, or binding to a deployed SHA. **Fix:** specify a fail-closed command/receipt that evaluates the exact post-S1 PATH and records host identity, target SHA, timestamp/expiry, `command -v tmux`, canonical image, `tmux -V`, and architecture. Re-run it immediately at the deployment/restart boundary and bind it to that deployment transaction. The verdict should require effective selection of the exact 3.5a x86_64 binary, not merely absence of one symlink.

5. **HIGH — the consumer-sweep and smoke acceptance still contain scope contradictions and unsafe/insufficient probes.** §1.5 says all eight commands “today resolve in `/usr/local` and all flip,” while four are then classified as not carrier-reachable and the cmux/log-janitor native-first trees already resolve some commands from `/opt`. A4 says every table row has smoke evidence, while §1.5 explicitly exempts four rows. The prompt's “table can only gain rows” rule and implement-time rerun are not actually present in `plan.md`, nor is the sweep command/exclusion method recorded, so the claimed reproducibility is not yet an implementation contract. Also, `verifyPlaybackStack` ultimately runs only `ffmpeg -version`; it proves the startup probe but not the `prism-media` decode/transcode path that actually needs codecs. **Fix:** call the result “eight statically discovered code-owned command names,” explicitly exclude dynamic agent/user commands and dependency-spawned commands from the completeness claim, check in or record the exact sweep procedure, and require an implement-time rerun where new hits add rows and removals require explanation. Split A4 into in-carrier commands requiring smoke and out-of-carrier rows requiring documented classification. Add a functional ARM ffmpeg codec-chain smoke, not only the version preflight. Make the `npx` bootstrap hermetic/bounded so it cannot start a second production Bridge. For `gh`, use real read-only operations; validate mutating verb/flag shapes with `--help` or hermetic tests, and discard `gh auth token` stdout so no credential enters receipts/logs.

6. **MEDIUM — §1.5.1 leans slightly too hard on “running without incident.”** The native-first cmux wrapper is good supporting evidence that arm64 Python can execute this one gate, but absence of a reported incident is not a health proof and does not establish that its brake-held/resume/error branches were exercised. It says nothing about the other persisted hooks or Python consumers. **Fix:** describe it as an observed existing convergence point, not behavioral certification, and explicitly state that it does not discharge the required real brake-path smoke or the 329-test evidence. With that narrowing, the section is useful and should remain.

7. **MEDIUM — clean up the remaining correction inconsistencies and harden the exact-pair invariant.** `plan.md:5` still labels the document R2, and §1.5's summary table still says “372 genuinely different binaries” even though §0.1 correctly narrowed that to distinct realpaths. `research.md`'s correction banner still lists `ffprobe` among consumers although R3 found zero code consumers, and its supposedly current recheck at line 26 still uses the disallowed `lsof ... | head -1` image heuristic. Replace it with the shared extractor/authoritative census. Finally, §3.1 should prohibit **any relevant 3.5a client**—PATH-selected or invoked by absolute path—from targeting a live 3.7c server; the protocol hazard is not PATH-specific. This does not require P8, only precise wording under P5.
