一句话:以后每开一场会,系统自动留下一条完整记录链 —— 自动开一张任务单(Linear issue,一件事一张单的工作台),会后一个note taker(记录员 AI,不在会上、会后读逐句转写)把会议要点和待办整理成一张互动卡发进这张单的讨论串(Discord thread,一单一串),你逐条批「要做 / 不做」,批完定稿归档进代码仓,任务单关闭。全程不用任何人按记录键。

① 全链一图

从「排会」到「归档」的完整链。绿色部分是这单要新建的,其余全是现成机制的复用。
你在这条链上只出现三次:开会本身 → 在卡上逐条批待办 → 最后点一次批准。其余全自动。
对这一节的意见:

② 你会看到的体验

  1. 排会时:说完「安排会议 12:30 和 Tadashi 聊 X」(V4 已有),几分钟内 Linear 里多一张任务单:[meeting] 2026-08-29 12:30 tadashi × Annie · X。
  2. 会结束后:约 10~20 分钟(自动侦测 + 记录员 AI 启动的时间),这张单的讨论串里出现一张互动卡:上半是讨论总结(看看就行,不用你操作),下半是逐条 action items,每条带三个按钮:要做 / 不做 / 有意见,还可以留言。
  3. 你批注完:点「一键汇总复制」,把汇总粘回讨论串 —— 记录员就会收到并修订,出新一版卡,直到你满意。节奏完全由你定,没有截止时间。
  4. 你批准后:notes + 每条待办的处置定稿,走正常 PR + Ship Card,你点一次批准,记录进 main 永久归档,任务单关闭。
  5. 错过或取消的会:也留痕 —— 任务单照开,写明「错过/已取消」后自动关闭,不派记录员。
出处:这条链是你自己在 PRD 里逐字定的四步(会一结束总结出 HTML → 你 iterate → finalize 成 doc → PR + Ship Card 你批准才进 main),本设计一步没加、一步没减。
对这一节的意见:

③ 数据从哪来,复用了什么

本单唯一新建的自动化是左下那个「定时对账器」:一个每两分钟醒一次的小程序,看一眼 V4 留下的会议存档,该开单的开单、该派记录员的派记录员。其余(任务单、讨论串、互动卡、意见回流、Ship 批准)全部是现成机制,一个轮子没造。raya(语音系统)的代码一行不改。
转写归属的安全规则(值得你知道的一条):逐句转写文件里混着所有语音会话。记录员只收「能证明是这场会说出的话」—— 证明用的是语音系统自带的进程互斥与会议信号(同一时刻只可能有一个语音进程在写记录);凡是证明不了归属的片段,宁可不收,并在 notes 里写明。这条是设计评审里被最严格打磨的部分(6 轮里有 3 轮在磨它),因为你不审 notes,错收进来的内容没人能抓 —— 所以宁缺毋滥。
对这一节的意见:

④ 你的意见怎么回到记录员手里(两步,如实说)

两件事是分开的,都是现有机制的原样复用:
  • 给意见 = 在卡上写完,点「一键汇总复制」,粘回讨论串。页面不会自动同步,不粘回来我收不到 —— 这是系统的诚实约定,卡上也会写明。
  • 给裁决 = 对当前那张卡回复「批准」或「打回」(或点 ✅)。只贴汇总不算裁决 —— 你还没批完,流程就继续等你。
对这一节的意见:

⑥ 诚实边界 —— 这个设计不做什么、做不到什么

  • 不是实时:会结束到卡出现有 10~20 分钟(对账间隔 + 记录员启动)。若你觉得太慢,提出来,我们再评估让 raya 主动通知(那是新的一单)。
  • 转写宁缺毋滥:容器异常崩溃的场,可能整场转写都判「归属不可证」→ 卡上只有元数据 + 说明,不猜内容。
  • 卡的链接约 7 天过期:那只是评审载体;永久记录在仓里的 notes 文档(批准合入后)。过期后可随时重新生成。
  • 不自动开后续任务单:「批了要做」的待办接下来怎么办,由你在讨论串里定;记录员只落记录,不替你立项。
  • 初期你逐条批 —— 这是你自己说的「初期」做法;以后不想批了,那扇门是开着的,不用重新争取。
  • 「note taker 读转写」你标过「暂时」 —— 想改回别的形态,改回来不需要新的理由。
  • 会中体验、语音质量、简报内容不归本单(分属 V4/2074/2030)。
对这一节的意见:
