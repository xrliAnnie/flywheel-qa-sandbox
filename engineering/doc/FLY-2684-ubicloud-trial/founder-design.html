02 · 五件事，哪些已经有答案

问题现在的结论下一份证据
能同时跑多少？未验证账户上限官方额度答复；不足时分级实测到 33 / 54 个任务同时运行。
能用私有仓吗？未找到明确官方保证授权后在 flywheel 私有仓真实取代码并通过测试。
任务结束会留文件吗？官方承诺每次新机器，结束销毁磁盘连续两轮检查固定哨兵文件不存在。哨兵就是用来探测残留的无害文件。
用哪种机器？先用 2核 / 8GB / x64与当前私有仓 GitHub 规格对齐；记录实际系统与机器类型。
缓存能继续用吗？官方支持现有写法验证依赖缓存首次写入、下次命中，以及回退后的重新安装。

缓存是主动保存、留给下次使用的依赖文件，不等于上一台机器的文件残留。保持分支隔离，也不缓存秘密。

03 · 测试要真跑，也不能误开合并门

金丝雀就是一个只手动启动的小范围真实测试。它完整运行 Quick Gate（构建和安全检查合集）、实际最慢的 Unit 分片（一组程序测试）、一个 Script Tests 分片（一组脚本测试）。

最近两次全量运行中，最慢的是 teamlead 第 1 片，分别为 14分44秒、14分52秒。我们按真实耗时选择，不按名称猜。

  • 同一个代码版本分别在 GitHub 和 Ubicloud 跑两轮，比较耗时、缓存与启动等待。
  • 前一轮写哨兵，后一轮先检查不存在；另用专用、无生产权限的测试秘密验证注入，日志不打印它。
  • 并发不足或无法验证时，停在小范围测试，不进入生产试跑。

金丝雀绝不叫 CI OK。这个检查名被现有合并门信任，小范围测试不能冒充全量通过。
