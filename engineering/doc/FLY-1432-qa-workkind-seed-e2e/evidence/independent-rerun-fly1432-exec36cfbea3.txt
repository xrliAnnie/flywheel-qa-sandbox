3. Negative control — is the flag-off 409 real, or vacuous?
------------------------------------------------------------
A 409 by itself does not prove the generalized flag caused it; a malformed body,
auth problem, or unrelated guard would also 409 and the assertion would go green
for the wrong reason. qa-control.mjs replays the byte-identical /api/runs/start
request over the same production Bridge stack with the ONLY difference being
FLYWHEEL_WORKFLOW_GENERALIZED_TEMPLATES=1:

  [ctl] PASS flag_on_same_request_is_not_generalized_rejected
        status=500 code=GENERALIZED_START_NOT_LIVE
  [ctl] dispatcher_start_calls=1

  With the flag on, the same request clears the gate, reaches the dispatcher, and
  fails only later at session registration. So:
    - the flag-off 409 GENERALIZED_WORKFLOW_REJECTED is specifically the flag gate;
    - the flag-off "zero spawns" result is meaningful, because the flag-on
      quadrant demonstrably DOES spawn (dispatcher_start_calls 0 -> 1).
