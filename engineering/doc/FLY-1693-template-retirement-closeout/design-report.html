FLY-1693 模板退役收尾 — 设计方案

Issue: FLY-1693 · 2026-08-11 · 设计节点交付 · Codex design review 5 轮 APPROVED · 全文档:engineering/doc/FLY-1693-template-retirement-closeout/

① 一句话总结

按你 8-11 拍板的清单,把 17 个 workflow 模板(派单时决定「一个单要经过哪些环节」的流程图纸)中的 12 个打上退役标记、保留 5 个;为了不炸生产,拆成一个 PR 里的五步原子动作:先解绑 → 再退役 → 摘掉启动时读文件的死机器 → 删掉指向它们的默认值 → 最后才删文件,并且顺手把「已退役的模板从此再也派不出新单」焊成硬规则。

保留 5:tpl_code · tpl_generic_menu · tpl_prd · tpl_design · tpl_prototype(全部由 menu 体系生成,是生产主力)。退役 12:tpl_eng_heavy 一族 ×7、tpl_eng 一族 ×2、tpl_product_v1、tpl_product_designer、tpl_product_prototype、tpl_generic。

② 为什么不能「直接删 12 个文件」

你最初的指令是直接删仓库文件。核实后没有照做,因为会当场炸,而且会把 8-10 晚上坑过 Product Lead 的事故形状放大五倍:

「BUNDLED_SEED_FILES」= 代码里写死的文件清单,Bridge(调度中枢)每次启动都逐个读这些文件,缺一个就起不来。

③ 核心流程:五步一个 PR,顺序不能反

比 issue 原文多出的第 0 步是审计新发现:数据库里有 5 个项目(geoforge3d / growth / joycon-typeless / personal-assistant / tidal-echo)各有一条旧绑定指着待退役模板,而退役接口遇到「还被绑着」的模板会直接拒绝——所以必须先解绑。

「幂等」= 同一个动作执行多少遍,结果都和执行一遍一样;Bridge 每次重启都会跑这段收敛逻辑,但第二次起自动零动作。

④ 数据与结构:改动前 → 改动后

关键事实(生产库只读实查)

  • 那 5 个项目的旧绑定从来没有真正派过单(引擎 run 历史约等于零)——解绑后它们自动走回今天实际在走的老路径,行为零变化。
  • 退役名单里只有 tpl_eng_heavy 有 9 个暂停中的历史 run,它们靠开工时固化的快照恢复,不回头读当前模板,退役不影响。
  • 退役是打标记不删记录:12 个模板的完整定义与历史永远可查,以后要复用(比如给保留模板补「founder 打回返工环」)随时能抄——那条返工环的定义已原样存档进 research.md 附录。

⑤ 关键取舍与弃案(两处对你原指令的显式修正)

决策点最终选择弃案与原因
5 条旧绑定怎么处理 解绑(删掉绑定,留审计) 弃改绑到 tpl_code——Codex 评审抓出硬伤:tpl_code 这类 menu 模板派单时必须读目标项目的 .flywheel/menus/ 角色配置,而那 5 个项目都没有这份配置,改绑等于把「以后不会用」变成「以后一用就报错」。解绑后走老路径 = 和今天完全一样。
「两处默认值」 直接删除(默认绑定播种机制 + 一个死常量) 弃按 issue 原文改指向——其一是全仓零调用的死代码,改完还是死的;其二(新项目默认绑定)同样撞上面的 menu 配置问题。删除后新项目不再自动拿到引擎绑定,派单走老路径,以后哪个项目接入 menu 体系时单独做接入(独立后续单)。
退役执行机制 Bridge 启动时的幂等收敛(自动、可重复、留审计) 弃一次性手术脚本——那套重仪式是给「改 run 台账」准备的;这里改的是配置层,底层接口本身会拒绝一切不安全操作。
退役后还能不能被派单 不能:候选解析拒 + 建 run 事务内复核(连并发竞态窗口也关掉) 弃初稿曾把「Lead 显式点名退役模板仍可派」留作口子——评审裁定这正是「看起来修好了」的形状,已改成硬边界。
回滚怎么做 随 PR 入库的回滚脚本:默认只读试跑,正式执行单事务、验够凭据才动手,绝不覆盖你手动改过的绑定 弃「出事再手写 SQL」——评审连追三轮把它钉成了带测试矩阵的可执行合同。

⑥ 诚实边界:这个设计做什么、不做什么

做

  • 12 退役 / 5 保留,含隐藏第 0 步解绑;全程审计可查
  • 「已退役 = 派不出新单」成为硬规则(含并发竞态防护)
  • 删净整套 bundled-seed 死机器、旧迁移代码、死默认值(净删除约 190 行 + 12 个文件)
  • build / CI / 40 来个测试文件 / 9 个历史脚本的连坐全部修好
  • 可执行、带测试的回滚脚本

不做(各有明确归属)

  • 不给保留模板补 founder 返工环——你已排期的后续单;定义已原样存档(含「3 次太少要调大」的备注)
  • 不给那 5 个项目做 menu 体系接入——未来各项目独立接入
  • 不删数据库里的模板行与历史 revision——退役只打标记,历史永远可查
  • 不动 FLY-1436 切换的历史存证;其「恢复到旧世界」按钮从此会被响亮拒绝(旧世界已被你判死,这是正确行为)
