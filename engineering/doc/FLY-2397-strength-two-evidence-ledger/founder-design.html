FLY-2397

强度二证据台账 —— 真环境跑过 + 外部可查可重跑的记录

设计节点交付 · 2026-09-07 · 上游:PR #1063 build-issues.md §B3 · 计划 v5(Codex 设计评审 4 轮全部吸收)

1. 一句话

给「这一单在真环境跑过、而且留下了别人能查、能重跑的记录」这件事建一张只追加、不可改删的台账;两半各是一个独立字段、各自单独判定,没有台账行就是不满足,填了地址但取不到也是不满足。它只记账不拦人,是影子跑(B4)的前置。

来源PR #1063 build-issues.md §B3;founder 2026-09-06 拍「2309 做,起 Epic」
founder 原话强度二 = 两半,缺一半就不算:① 在 529 房把链路从头到尾真跑一次 ② 留下外部可查、能被重跑的记录。第 2 半才是挡住「模型自称跑过」的那道墙。
今天的现状371 条 QA PASS 里,「跑过」只存在于一段自由文本(自称);没有任何一张表有「真环境」「记录在哪」「怎么重跑」三个字段。
Lead 两条裁定① 新命令 → Bridge 新路由 → 新表,不碰 qa-result 合同;② 半边 (b) 在写入时判定,之后地址过期不回溯改判,B4 报表分 live / verified_then_expired / unsatisfied 三态。

名词:529 房 = 本机上按槽位起的隔离测试环境(自带一个测试 Bridge),用来把整条流水线真的跑一遍;head = 被测代码的精确 40 位提交号;Bridge = Flywheel 的调度服务进程;credential = 每个 QA 节点独有的一次性凭据,拿它证明「我就是这个 QA」。

2. 核心流程

QA 跑手在房还开着的时候执行一条记账命令;Bridge 先核身份和 head,再自己去探两件事:房里跑的是不是这个 head、报告地址是不是真取得到;然后把两半各自的结论写进同一行。

  • 为什么 Bridge 自己探而不是信 QA 自报:探 529 房的 /health 能拿到房正在跑的代码版本(buildSha),必须恰等于被记的 head;房拆了就探不到 ⇒ 记不上。这把记忆库里「先拷证据再拆房」的纪律变成了硬规则。
  • 为什么记录地址要真去取:spec 明说 (b) 最容易退化成「填个字符串就算」;所以 Bridge 真发一次 HTTP 请求,要求恰好 200,正文的 sha256 还要等于 Bridge 本地存档的那份托管报告。
  • 记账的时机:驱动器一退出就记 —— 房还开着、这个工作树还没再提交任何 commit(head 要等于房的 buildSha)、还没发 qa-result(身份靠未消费的 credential)。

3. 数据模型

一行台账 = 绑定 + (a) 一组字段 + (b) 一组字段 + 合取结论。两半各有自己的 status 和 reason,原因词汇表互不相交;数据库层用 CHECK 约束把「结论不能脱离两半单独为真」「satisfied 的事实列必须非空且互相一致」钉死。

规则做法
只追加表上挂 no-update / no-delete 触发器;同一 (run, 仓, head) 允许多行,每次记账一行。
幂等行身份 = 命令生成的 UUID;同 id 内容全等 ⇒ 重放(不重探);同 id 内容不等 ⇒ 409 拒绝,零写入。
身份QA 自己那把一次性 credential 只读查询(不消费、不碰 qa-result 的重放摘要);必须是 qa_verdict 家族、当前 writer、durable QA 会话、未消费、未撤销、未过期,并且在写入事务里再验一次。
head 从哪来只认 QA 工作树的 git rev-parse HEAD;命令里的 head 只做交叉校验。
重跑配方结构化 JSON(没有重复信息),槽位 / head / 驱动器版本 / 起房参数全部由服务端派生并渲染成一行命令;任何人复制就能重跑。
retention登记到 protectedCurrentOrReference 组(照 spec),清理任务永不动它。

4. 判定逻辑(B4 怎么读)

判定是一个纯函数:输入只有台账行,不接收 QA 的自由文本。空集就是不满足;有行就分别看两半;只有两半都 ✓ 的行才算满足。

阳性对照 1「自称跑过但没有台账记录」⇒ 两半都是 no_ledger_row,不满足。验收脚本会在生产库只读副本上,对上线前全部 QA PASS(带托管报告地址的那些)逐条跑这个函数,要求 n > 0 且全部不满足。
阳性对照 2「有台账行但记录地址取不到」⇒ 行照样写进去,(a) ✓ 而 (b) ✗,结论不满足。三层都测:纯函数、路由端到端(假的 404)、验收脚本。
对称对照(a) ✗ 而 (b) ✓ 也必须不满足,且 (b) 的 ✓ 要单独可见 —— 证明两半真的没被一个布尔盖住。
三态给 B4写入时判定之外,再提供一个只读探测:现在还取得到且正文没变 = live;当时核过、现在过期 = verified_then_expired;当时就取不到 = unsatisfied。B4 报表分三列,期末重算不会把早期单子误判。

5. 关键取舍与被否掉的方案

取舍点选了否掉了为什么
谁来写这一行新命令 evidence-run record + 新路由 + 新表给 qa-result 加参数qa-result 消费一次性 credential 并用重放摘要做合同,改它的 payload = 改一条被反复评审过的合同;而且「跑过」和「判 PASS」是两件事,跑过但 FAIL 也该记。
(b) 什么时候判写入时判,存下时刻 / 状态 / 摘要判定时重探;或允许再登记一份 GitHub 副本Lead 裁定:托管报告 14 天过期正好等于影子跑长度,期末重探会把早期单子误判;写入时判 + 三态报表最干净,QA 不多做一步。
地址取不到怎么办照写一行,标 (b) 不满足直接拒绝不写spec 的阳性对照 2 要「有行但取不到 ⇒ 不满足」,行必须存在;也留下审计痕迹。
房的身份谁核Bridge 自己探 529 房 /health信 QA 自报的 buildSha自报就是「自称」;探不到就记不上,把「先拷证据再拆房」变成硬规则。
场地范围v1 只收 529 槽位房 + 主仓「其它场地」自由填写其它场地没有可派生的重跑配方、也没有可探的身份;宁可拒绝也不生成假配方(Codex 评审要求)。
驱动器退出码记录人自报,明写为残余让 Bridge 去读 /tmp 里的证据目录跨进程读易失目录不可靠;(a) 的机器证词到「房活着、built、head 恰等」为止,剩下靠重跑配方让任何人复核。

评审历程:Codex 设计评审 4 轮(R1 10 项 → R2 8 项 → R3 6 项 → R4 1 项),每一项都吸收、零拒绝,方向没有被推翻;剩余项已按 FLY-2395 先例报 Lead 裁定。

6. 诚实边界:这份设计做什么、不做什么

做

  • 一张只追加的台账,两半各是独立字段 + 独立判定 + 独立测试。
  • 「没有行 = 不满足」「取不到 = 不满足」两条 fail-closed 规则钉成代码与数据库约束。
  • Bridge 自己核房的身份、自己取记录地址、自己派生重跑命令。
  • 给 B4 的读接口:按 (run, 仓, head) 精确取行、纯函数判定、三态探测。
  • 验收脚本在生产库只读副本上跑阳性对照 1,固定 cohort、要求非空。

不做(照 spec 明写,实现不许悄悄声称覆盖)

  • 挡不住 flaky(FLY-1833 型):一个 flaky 的端到端测试照样会偶然全绿,台账照记「跑过 + 有记录」。本单没有新解法,验收文档保留这句。
  • 不接任何门:review-hold、land、founder 卡的行为零变化;不改 founder-only-authority。
  • 驱动器「跑到第 9 步」是自报项;机器只证明房活着、built、head 恰等。
  • 托管报告 14 天过期:写入时判定,过期不回溯;已告知 B4。
  • 记账后再推 docs commit ⇒ 新 head 无行 ⇒ B4 记入「绑定失败」栏,不猜、不放宽。
  • 只支持 529 槽位房 + 主仓;codex-runner 房与 nested 仓另立单。
  • 记账必须在 qa-result 之前(身份靠未消费的 credential);已记的行事后仍可重放确认。
