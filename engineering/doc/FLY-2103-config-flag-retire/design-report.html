FLY-2103 设计:config.yaml 最后 9 个开关的退役

Issue: FLY-2103 · 设计节点 · 2026-08-28 · 分支 flywheel-FLY-2103 · Codex 设计评审 4 轮后 APPROVED

一句话总结

把散在 6 个项目 config.yaml 里的最后 9 个功能开关清干净:2 个从没用过的直接写死进代码,7 个搬进数据库按项目存值(以后改开关 = 一条命令、秒级生效,不用改文件不用重启),config 文件里残留的旧开关会被大声报错。

背景:这是 flag 治理三批清理的最后一批(C 批)。A 批(FLY-2100)已给数据库表加了「按项目」的能力但只用于显示;B 批(FLY-2101/2102)清完了环境变量类开关。本单让数据库成为这 7 个开关的唯一真源,消掉「管理台显示一套、运行时读另一套」的分歧窗口。

① 9 个开关各去哪(处置图)

处置开关为什么
固化删checkpoints.*.enabled6 个项目所有检查点全是 true、从没关过 → 以后「声明了检查点就等于启用」,少一行没意义的配置
固化删collections[].auto_create从没有项目设置过 → 行为写死为 true(自动建 issue)
迁数据库doc_flow / pipeline.dag / pipeline.work_kind / proofshot / xiaohongshu_learning / ponytail / skill_framework.split还活着的逐项目开关,统一搬进 flag_values 表;config.yaml 只留「不是开关」的配置(部门名、超时、collections 清单等)

② 改完之后:值住在哪、怎么读(数据与结构)

读值顺序(每次用到时现查,不是启动时读一次):先看这个项目自己的行 → 没有就看 *(全项目)行 → 都没有就用名册里写死的默认值。「名册」= 代码里的 flag registry,每个开关的身份证(默认值、说明、读点)都登记在那里。

写入面不变:仍然只有一条路 —— CLI 命令经 Bridge 的 stage/apply 接口落库,每次改动都留审计流水(谁、何时、从什么改到什么)。没有第二个写入口。

迁移当天的现值(实查):doc_flow 在 flywheel / joycon-typeless / personal-assistant / tidal-echo 四个项目 = 开;pipeline.dag 与 work_kind 仅 flywheel = 开;其余全部没设置过。迁移脚本就写这 6 行 + ponytail 的 *=关 一行,共 7 行,一行不多一行不少。

③ 怎么安全切换(部署时序 = 硬门禁)

两道门 + 一张凭据:G1 在删任何 config 之前核验「数据库行集恰好等于 6 行」——多一行、少一行、值不对都停下人工裁决;只有 G1 真正通过才签发 receipt(凭据文件,绑定数据库路径、config 内容指纹、行集与时间);第二遍脚本必须出示并逐字段核验这张凭据才允许补第 7 行。G2 在放行前再核验 7 行 + 迁移前后行为逐项对照(文档流程注入、DAG 派工、恢复中的 DAG 任务、ProofShot、ponytail、分流、小红书计划)全绿。

为什么没有危险窗口:merge 不等于部署(FLY-1959 班车制)。外部项目的 config 清理 PR 只在班车停机窗内 merge 并同步到本机检出,然后直接用新代码启动 —— 「老代码读到已删 key 的 config」这个窗口被压成 0。

回滚有围栏:老版本代码启动时会检查数据库行的身份,认不出 ponytail/split 的行会直接起不来(这是实测出的事实,不是猜的)。所以降级必须先用新版本把这两个开关的行清空、复核为空,才允许回老版本;如果有「已退役项目」的孤儿行,CLI 清不掉,那就禁止降级、只能前滚。这些都会做成演练测试钉死。

④ 关键取舍与被拒绝的备选

决定选了什么拒了什么、为什么
ponytail 怎么迁把「项目层」接上数据库读,但用 *=关 保证所有项目仍然关(与今天逐字节等价,已核实 resolver 代码);FLY-615 的按 issue 打标签路完全不动「行进数据库但运行时不接线」被拒:一行没人读不算迁移,而且要为它在授权门上开豁免 = 长机制。副作用请你知情:以后按项目开 ponytail 从「改代码」变成「一条 CLI 命令」——如果你想保持「必须改代码才能开」,请在意见里说,退回方案已备好
pipeline.dag 的默认值名册默认从「关」翻成「开」,对齐 FLY-1981 之后的运行时真相(没写 = DAG 派工开)「写 6 行 *=开 来凑」被拒:用数据行掩盖名册说谎。今天管理台对 5 个项目显示「关(默认)」但它们实际在走 DAG——翻默认值后显示终于诚实,行为零变化
删掉的 2 个开关留不留墓碑不留,登记直接删(沿 FLY-2101 先例)tombstone 字符串本身会撞「全仓搜索零命中」的验收
迁移脚本怎么写库写死的 7 行清单为唯一目标;写入走既有 Bridge 接口;幂等靠精确读现有行(同值不重写、异值报错停)「从 config.yaml 现推要写什么」被拒:config 删 key 后脚本就失去恢复来源;「直写 SQLite」被拒:绕过唯一写入面、并发写有风险
split 开关的可写性readonly → conversational(CLI 可写):config 杠杆死后 CLI 是唯一杠杆;读库失败仍然「钉回 A 臂 + 告警」保守兜底保持 readonly 被拒:那等于没人能再改它。此开关是过渡品,FLY-1834 结账时连 skill_framework_mode 一起整体删除

⑤ 设计评审过程(Codex,4 轮)

意见条数逐轮收敛:R1 = 6 条 → R2 = 5 条 → R3 = 2 条 → R4 = 0 条(APPROVED),且全部是「收紧既有一次性脚本/门禁」而非新增机制。R1 抓到的最重要事实:初稿以为「旧代码会忽略新开关的行」,实测恰恰相反 —— 旧代码见到认不出的行会启动失败;回滚围栏因此整个重写。R2 补上了「多余行会在切换后变成权威」的 exact-set 校验;R3 把凭据(receipt)的签发时点钉死在 G1 真正通过之后。

⑥ 诚实边界:这个设计做什么、不做什么

做

  • 9 个开关全部离开 config.yaml;7 个的运行时真源变成数据库,改值秒级生效、全程留审计。
  • 验收含「迁移前后 6 个项目行为零变化」的真 Bridge 前后对照,和 config 残留 key 必报错的测试。

不做 / 需要知道的

  • 不动非开关配置(agents / roles / 检查点超时 / linear / collections 清单),不动 6 个环境变量类全局开关,不动 FLY-615 的按 issue ponytail。
  • 需要 5 个外部项目仓各出一个 config 清理 PR(实施节点开),并且它们只能在班车停机窗内 merge —— 这是运维合同,写死进 PR body。
  • 两处形状语义变化(现网数据都不受影响,但要说清):检查点「声明了但没写 enabled」今天=关、以后=开(现网全部显式写了 true);小红书「开了但没配 collections」从启动报错变成运行时记日志跳过。
  • 显示会变的一处:pipeline.dag 对 5 个项目的显示从「关(默认)」变成「开(默认)」——那是修正显示谎言,不是行为变化。
  • 小红书调度器仍是 gated pilot(launchd 未装),本单只把它的取值路径接到数据库,不启用它。
