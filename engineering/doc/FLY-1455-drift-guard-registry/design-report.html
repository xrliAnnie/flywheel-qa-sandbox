FLY-1455 · 不许野建 flag —— 登记强制补网 设计

Issue: FLY-1455 · 第 1 批「防野建」 · 2026-08-16 · 设计已过 Codex 独立评审 5 轮 APPROVED · plan: engineering/doc/FLY-1455-drift-guard-registry/plan.md

1 · 一句话总结

以后任何人(包括 AI)在代码里新加一个 flag 开关而不登记,CI 会当场变红 —— CI 指每次提交代码时自动跑的检查。现在的守卫只盯了 21 个代码包里的 4 个,shell 脚本完全没人看,换个写法还能绕过;这单把网补到全部生产代码,并立下一条硬规矩:要么登记,要么带着理由和归属人显式豁免 —— 没有第三种存在方式。

flag(功能开关):控制某个功能开或关的变量。「野建」= 新加了开关但不进登记簿,时间一长谁也不知道机器上有多少开关、哪个还有用 —— 这正是你说的「网有洞、野 flag 能溜过去」。

2 · 核心流程:洞在哪,怎么补

左边是现状的四个洞;右边是补完后的扫描面。任何一个 flag 读点(代码里读这个开关的地方)最后只有三个合法去处,否则 CI 红:

  • B0a(扩面):扫描目录从写死的 4 个改成自动枚举全部 21 个包(以后新增包自动入网,不再烂),外加全部生产脚本 —— 实测 shell 脚本里有约 40 个布尔形态的开关读点,今天完全是盲区。
  • B0b(认写法):现在的守卫用正则(按文字模式粗匹配)只认最朴素的写法;换成 AST(把代码解析成语法树 —— 能分清「真代码」和「注释里长得像代码的字」的分析方式)后,解构、封装、换参数名这些变体写法都认得出。另外把 project_config(每个项目自己的配置文件)里的布尔开关也纳入 —— 用 config 的类型定义自动枚举全部布尔键,一个都跑不掉。
  • B2′(收口):把上面所有检查收成一条 CI 断言:没入账 = 红。

3 · 为什么这张网骗不过(三层数据流)

评审里反复锤炼的核心:在注释或字符串里写一个 flag 名,不能骗过守卫、也不能给「挂空账的豁免」续命。做法是把「粗扫」和「权威判定」分开:

正则粗扫只当「护栏」用:它在真代码位置扫到的名字,如果权威集(AST)里没有,说明 AST 自己有洞 —— 守卫也红。两把尺子互相校验,谁坏了都藏不住。代码解析失败同样直接红(fail-closed:出错时宁可拦下,不放行)。

4 · 数据/结构模型:四本账

每个 flag 读点必须能在四本账里找到自己的位置 —— 这就是「一切在账面上」:

账本说的是什么必填
registry 登记簿(现有)「这是个 flag,已正式登记」—— 含它控制什么、默认值、在哪读全字段
分类账 ×2(env 现有 / config 新增)「这个变量/配置键不是开关」—— 是路径、ID、普通配置理由
豁免账(新增,Tadashi 要求)「这确实是开关,但刻意不登记」—— 比如 QA 故障注入接缝。以前这类是守卫碰巧没扫到的静默暗洞,现在变成有理由、有归属人的显式记账;豁免了却没有真实读点(预埋)也会红理由 + 归属人
墓碑(现有,扩到 shell)已退役的 flag 名单 —— 谁把它复活,红—

四本账两两不许重叠,理由不许留空白 —— 这些本身也是 CI 断言,账本自己烂不了。

5 · 关键取舍与被否掉的方案

  • shell 按「锚定形态」扫,不按提及扫。脚本里提到 flag 名的地方有 438 个,大多是透传和路径;只认五种真正当开关用的写法形态,首跑撞网量从 400+ 降到几十个。被否:全提及扫描(噪声淹死人)、写一个完整 bash 解析器(过度工程)。
  • AST 是唯一权威,正则降级为护栏。被否:「正则 ∪ AST 取并集」—— 评审第 3 轮发现并集会让注释里的假命中重新混进权威集,自相矛盾。
  • 豁免账和分类账分开,不合并。「不是开关」和「是开关但豁免」是两件事,混在一本账里账面会说谎(评审第 2 轮抓的)。
  • 普通布尔配置不强行登记。「哪些布尔配置算 feature 开关」机器判不了,由人裁决后落账;裁决记录(backfill ledger)随 PR 可审计。
  • 分两个 PR 交付:PR-1 = 扩面 + 豁免账(含全部当期可判防腐);PR-2 = 写法变体 + config 枚举 + 登记反向核验。防腐和放行口同批上线,不留可钻的中间态。

明确不做你 7-23 砍掉的那半一条不碰:不做「创建时必须声明退役条件」、不做自动建清理单、不做退役申报记账五件套、不碰 question checkpoint、不实现 longTermKeep(那是 FLY-1779,已完成)。现有测试里「不许在创建时强制 longTermKeep」这条断言必须原样保持绿 —— 这是红线的机器证据。

6 · 诚实边界:这张网防什么、不防什么

  • 防「顺手野建」,不防蓄意。本仓库是 GitHub 免费版,平台层面没有强制门禁 —— CI 红了照样有权限合并,靠的是「没人合红 PR」的纪律。有权合并的人也永远可以连豁免一起提交。
  • shell 扫描是启发式。五种形态覆盖当前仓库全部实测写法;但 bash 没法可靠静态分析,间接展开(eval、变量名拼接)这类写法认不出 —— 发现新写法就补形态和测试,属已知残余。
  • 只扫仓库文件。运行时手工塞进机器环境文件的变量不在网内(那是 flag console 和 FLY-1150 的地界)。
  • TS 计算键认不出。用变量拼出来的键名只能标成 dynamic,走最低限度核验,不能证明真读。
