四条各自的病因（本机只读实查）

#你看到的为什么会这样改法
1「token 状态」每行都是「正常」上一轮为了「不删没点名的列」保留了它两张表都删掉这一列（Claude 表本来就没有）
2Claude 充值卡「明细未提供」上一轮读的是「预付美元额度」接口，不是卡。真正的卡藏在用量接口的一个开关里（内部代号 cedar_ember），而且 Anthropic 只对 Claude Code 客户端返回改读这个开关：每个号现在各有 1 张「Opus 5.5 上线送的一次额度重置」，10/22 到期
3business「机器读数 5x / 你说 20x」档位读的是登录那一刻存在本机凭据文件里的旧值；升档后这个文件不会更新改读 Anthropic 实时的账户资料接口，返回的就是 default_claude_max_20x；页面和 /api/capacity 同时修好
4「订阅到期」几乎全是「未知」上一轮只有手填入口，从没录过数据Codex：ChatGPT 订阅接口直接给「下次续费日」，6 个号都读到了。Claude：Anthropic 只在网页登录态下给账单日，我们用的登录凭据被明确拒绝 → 按你选的 A，写「读不到」+原因

名词：接口 = 服务商提供给程序读数据的网址；只读 = 只查看，不改任何东西、不领卡、不扣钱；凭据 = 账号的登录钥匙。

数据怎么流到页面

你点刷新时，两个只读探针分别去问 Anthropic 和 ChatGPT，把结果存成本机小文件；页面和 /api/capacity 都从同一份「容量快照」（把所有读数拼在一起的一张表）里取数，所以两处不会不一致。

取舍与没选的方案

  • 不按开通日推算 Claude 扣费日。ChatGPT 的实例证明锚点会漂（某号开通日 08/19，下次续费却是 10/23），推算会给你错日期。你已选 A。
  • 不用余额、不用「预付美元额度」冒充充值卡。那些数据仍保存在后台，只是不再显示。
  • 档位不在页面上硬改。修在数据层，/api/capacity 也跟着对；档位仍然不参与分组、排序和自动切号。
  • 读卡时以 Claude Code 客户端身份发只读请求。这是 Anthropic 给出卡数据的唯一方式；版本号取本机实际安装的 Claude Code，不写死；永远不调用「领卡」接口。
  • ChatGPT 订阅接口要用 Node 的 https 模块读。实测 Node 自带的 fetch 会被 Cloudflare 的人机验证页挡住（403）。万一以后被挡，格子写「读不到（接口被拦）」，不留空。
