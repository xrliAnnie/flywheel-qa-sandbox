Epic 页面活化:事件 + 扫描双路更新、过期自报、卡住上页可见

一句话:让你收藏的那一个 Epic 页面链接自己保持最新、自己说出自己多旧;IC 卡住时「说一声」会落在页面上,你想看就看得到,系统不会主动来打扰你。

读法:每一节下面都有留言框,写了会自动保存在你的浏览器里;页尾有「汇总并复制」按钮,把所有留言一次复制出来发给 Lead。

1. 这一单做三件事

你定的要求落到页面上是什么
双路更新(你定的 hybrid:某件事做完就更新 + 到点扫描核对)runner 收工、派单、PR 合并后 Linear 变 Done、依赖改边、hold 解除 —— Bridge 亲眼看见就立刻刷一次;既有的巡检钟到点再刷一次兜底。两条互相兜,谁失灵另一条顶上。
过期自报(页面必须能说出「我这一格是什么时候的」)页头多一块「这页多旧」:本版号、上次成功刷新、之后失败几次和原因、下一次扫描预计;你打开页面时它还会自己算「你打开时它已 N 分钟旧」。
卡住可见、不打扰(R6)IC 自己声明的卡住出现在子单卡和「卡住说了一声的」总览格里;第一顺位收件人是 Lead(巡检信多一行);不会每次卡住给你发消息。

名词:Bridge = 跑在这台机器上的调度进程,负责派活、收工、发信;巡检钟 = Bridge 每小时(可调)替每个 Lead 看一眼现状的定时器;IC / runner = 真正干活的 AI 执行体。

2. 核心流程:两条路怎么把同一个链接刷新

  • 事件路:Bridge 自己写账本的那几个瞬间(收工、派单、Linear Done、改边、恢复)各触发一次刷新;5 秒内的一串变化合并成一次,同一项目排队,不会并发去打 Linear。
  • 扫描路:就是上一单(2108·B)已经在巡检钟上跑的那次生成,本单只在它成功后多做一步「重传固定链接」。你在 Linear 里手动拖单、改关系,Bridge 看不见,靠这条路在一个周期内追上。
  • 固定链接:每个项目一枚固定的 32 位随机 token,每次刷新都就地重传到同一个地址;你收藏一次就一直是最新页。链接从最后一次成功刷新起保留 14 天。
  • 失败也留痕:生成或发布失败时,账本记一行原因,固定页不动;Lead 用一条状态命令就能看到「上次成功是什么时候、之后失败了几次」。

3. 页面里多了什么(数据结构)

「这页多旧」九格
每一格都带出处和看到它的时间(延续 2108·A 的「格」模型:每个数都能说出从哪来、什么时候看的);「下一次扫描预计」和「来源最旧的那格」是推导出来的,页面上会标「未获 founder 裁定的默认规则」。
「说了一声」信号
五种:IC 声明卡住 / runner 停机(带枚举原因:额度、上下文满、报错、卡住)/ 有问题等 Lead 回 / run 被 hold / 在等 founder。最后一种单独显示、不算卡住——否则每张门口的卡都会被标成卡住。
只投影四样
种类、时间、执行体编号前 8 位、枚举原因。IC 写的自由文本(摘要、报错、问题原文)一律不进页面,要看原话去 Lead 收件箱。
两张小表
刷新账本(每次尝试一行:何时、哪条路、为什么、结果)和固定链接登记(项目 → token)。都不存页面内容本身。

4. 关键取舍与否决掉的方案

问题选了否决了什么、为什么
页面在哪里「活」固定链接就地重传你收藏一次永远最新,不发消息只让 Lead 端活你的那份永远是旧快照;每次刷新发一条新链接= 打扰,且收藏不了
「卡住」信号从哪来IC 自己的声明四种现成渠道Bridge 从沉默/时长推断会把安静思考当失败(既有规则明令禁止)
事件路怎么接在写账本的那几处各挂一次按「真的变了」判,不按 HTTP 返回码在数据库层挂钩子写点太多、会把数据库层变成有副作用;审计事件表与「页面会变」不等价
刷新失败时固定页怎么办不动旧页账本记原因,下一版页面和状态命令带出重传旧页加「失败」横幅会造出「时间没变、字节变了」的页面,和「刷新=就地更新」相撞
手动生成(Lead 用命令看一眼)只生成不发布不延长固定链接寿命看一眼也重传会让「Lead 看过」冒充「页面刷新了」
Lead 裁定的边界固定 token 用最小结构存;「指定 token 覆盖」只对 Epic 页面开放,普通报告仍每次新链接、不可覆盖;保留只按年龄(14 天)不按数量;CommDB 只读、有界、失败就标缺失;三类信号都做;不给你发消息、不建告警器。

名词:CommDB = Lead 与 runner 之间收发信件的那个数据库(IC 的「说一声」原件就在里面);token = 一串 32 位随机字母数字,只有拿到链接的人猜不到。

5. 诚实边界:做什么、不做什么

做

  • 两条更新路 + 固定链接 + 「这页多旧」+ 卡住信号 + Lead 巡检信一行 + 一条状态命令。

不做 / 做不到(你点过代价的那一面,如实写)

  • 页面是投影副本(你自己说的坏处):它靠每格出处 + 时间 + 失败账本来回答「会不会过期」,不靠「永不过期」。「多旧算过期」由读的人判,系统不替你定阈值。
  • 发布不是原子切换:重传固定链接要经过对象存储、本地登记、数据库三步,中途失败时新字节可能先于账本可见;靠下一次同地址重试收敛,不另做原子切换。
  • hold 刚被创建那一刻不触发事件(最多滞后一个巡检周期);Linear 里的人工改动也只靠扫描路追上。
  • 链接寿命跟着管线:Bridge 停摆 14 天,链接会过期——页面死在喂它的管线之后,而不是活得比管线久(那才是假新鲜)。
  • 今天生产还没通电:六个项目的 Linear 绑定仍是空的(与 2108·A/B 相同前置),补绑定归 Lead;绑定前所有新逻辑字节不变、只在启动时打一行日志。
  • 不做:多项目额度统管、分层调频、Linear webhook、新开关、新告警器、自动给你发消息、失败横幅重传。
