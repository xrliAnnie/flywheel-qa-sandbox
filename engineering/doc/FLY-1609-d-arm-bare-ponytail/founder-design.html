FLY-1609 开 D 臂:bare + ponytail

设计方案 · 2026-08-03 · Codex 设计评审 4 轮 APPROVED · 文档: engineering/doc/FLY-1609-d-arm-bare-ponytail/

① 一句话总结

在现有 A/B/C 三臂提示词实验里加第四臂 D = C 的裸提示词 + 自动开启「代码极简」规则,四臂随机均分新 issue,用同一套数据口径对比耗时/token/评审轮数 —— 直接测量「我们是否在过度工程」。

名词:「臂」= 实验分组(像药物试验的对照组);「ponytail」= 我们的代码极简规则包(FLY-615 已上线),让 AI 写最少、最直接的代码;「bare」= 不装任何技能框架、只给最裸提示词的 C 臂。

② 核心流程:issue 怎么进 D 臂

新 issue 按 issue 号做稳定哈希(同一个 issue 号永远算出同一个数,保证分组随机但可复现)均分进四个桶;已经分过臂的 issue 有 sticky(粘住:同一 issue 的所有环节永远留在同一臂,数据不串)保护。命中 D 的 session,提示词与 C 臂逐字相同,唯一区别是自动开 ponytail。

归因诚实红线:如果 ponytail 当时不可用(比如插件没装好),session 照样跑裸提示词,但会如实记录「没跑成」,这条数据不算进 D 组 —— 绝不把没开成极简规则的 session 冒充成 D 臂成果。

③ 谁说了算:五层优先级 + 急停

D 臂的自动开启被放在一个明确的优先级槽位里:人的显式指定 > issue 标签 > D 臂注入 > 项目默认。人说关就关,实验绝不越过人的意愿;标签读不到时宁可不开(防止看不见的「关闭」标签被实验盖过)。

急停:把全局开关设回 A 臂,秒级生效、不用重启 —— 之后所有「实验注入的 ponytail」立即停止(包括重试的旧 issue);但你手动给某 issue 打的 ponytail 标签仍然有效(实验急停不误伤正常功能)。

④ 数据/结构模型

不加任何新表新列 —— 全部复用现有两列,单列分组即可出四组对比:

列取值含义
skill_framework_modesuperpowers / matt / bare / bare-ponytail(新)这个 session 在哪个臂
ponytail_conditionon:arm(新来源)/ on:label / off:run / unavailable:… 等极简规则实际开没开、为什么
组统计口径
D 组臂 = bare-ponytail 且实际开成(on:%)—— flag 传了不算,以落库列值为准
A/B/C 对照组各臂里极简规则关着的 session(off:%)—— 标签/项目手动开了的进「排除桶」单列可见
排除桶没跑成(unavailable)、被手动干预、历史空值 —— 逐行可见,不混进任何组

分析入口:升级 1458 的 design_compare.py 为四臂通用脚本,强制从 D 臂上线时刻起算(防止新旧数据混算),自带自检(self-test)并进 CI(CI = 每次改代码自动跑的检查门)。

⑤ 关键取舍与被否掉的方案

决策点选定否掉的方案(为什么)
D 怎么归因新臂值 bare-ponytail,单列分组「仍记 bare、靠第二列区分」— C 臂也可能手动开 ponytail,单列分不开;「加新列」— 全链路双写,过度工程(讽刺)
注入在哪做装配层(唯一知道最终臂的地方)做,优先级写进纯函数可全枚举测试「HTTP 边界注入」— 边界看不到 sticky/回退改写,会与最终臂脱节 → 归因撒谎
ponytail 不可用时臂不降级、如实记 unavailable、数据排除「降级回 C」— 该 issue 从此永远留在 C,D 组被静默稀释
四桶重排接受(%3 变 %4,未分组 issue 重排;sticky 保护存量)「保序迁移」— 复杂度不值,分组本来就是随机的
重试语义补上「冻结 + 本次可信标签」双份携带,由装配层最终裁决(Codex 评审揪出的既有缺口)「声称自动保留」— 解码器此前根本没接进生产,显式关闭会在重试时被实验翻开

Codex 设计评审 4 轮:R1 六条(优先级语义/装配缝隙/重试缺口/脚本硬编码/运维承诺/边界测试)、R2 两条 HIGH(标签刷新失败冒充可读、冻结注入越过急停)、R3 一条 HIGH(重试数据载体)—— 全部采纳,R4 零阻塞 APPROVED。

⑥ 诚实边界:这个设计做什么、不做什么

做

  • 四臂随机分桶 + D 臂自动开 ponytail + 归因两列如实落库;
  • 重试/急停/标签读不到等边角全部 fail-closed(拿不准就不开、就排除);
  • 分析脚本四臂化 + 自检进 CI;C 臂行为逐字回归断言(零扰动)。

不做

  • 不动 ponytail 规则包本体(FLY-615 已交付,只走它的现成通路);
  • 不出终局分析报告 —— 数据攒够后按 1458 口径另出;
  • 不给 agy/kimi 后端开 ponytail(它们本来就不支持,如实记 unavailable);
  • 不加任何新开关、新表、新列;
  • 只停 D、不停实验没有热开关:急停会停整个四臂实验;只想停 D 需要回退代码重新部署(不加新 flag 的诚实代价,已在运维文档写明)。
