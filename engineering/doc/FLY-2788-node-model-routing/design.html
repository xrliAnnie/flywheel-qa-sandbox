每次分组，留一张可追溯记录

分组收据，就是保存“哪次运行、哪个节点、哪条规则、哪一组、哪个具体模型、何时决定”的记录。它随流程一起保存，启动时再核对。

关键取舍

设计、实现、QA 分开计算。分组输入都带节点名，避免三段被同一结果一起决定。

不随机重抽。首次结果保存后，比例改变也不让已有单悄悄换组。

人工决定优先。按 FLY-2769 的方向，人工指定持续到撤销；这类运行单独标记，不混入自动分组统计。

缺候选就明确失败。自动选中的模型不在该节点允许列表里，就报出具体原因，不偷换另一个模型。

QA 可以同家族，复审必须跨家族

QA 的工作是验收，实现与 QA 分到同一家族也照常运行；服务端确认这是合法 QA 节点，并留下同家族验收记录。

不打开全局同家族放行开关。代码复审仍跨家族：Claude 写的代码由 Codex 审，Sol 写的代码由 Claude 审。设计评审也跨家族：Astra 的设计交 Claude 审，Opus 或 Fable 的设计交 Codex 审。其他节点不能借用 QA 的许可。

实现 Sol 可明确降级到 Opus

只有系统确认所有 Codex 账号额度都已耗尽，自动分到实现 Sol 的工作才可降级为 Opus。网络错误、信息过期或单账号用完都不算。

原组别不改，另留一张降级记录，明确实际用了 Opus；成绩看板把它单列，不能算进正常 Sol 或 Opus 组。

不会给正在运行的进程强行换模型。降级后的代码仍由 Codex 复审，若它还没有额度，复审会等待。

怎样证明真正跑对了

隔离环境至少 30 张模拟单；计划使用 120 张，公开各组计数与三段之间的交叉计数。每单每节点分别重派、返工、拉起三次，核对组别稳定。

至少一张单走真实实现与 QA：终端首屏显示的模型、启动记录与分组记录必须一致。另补各模型组及产品节点的真实记录。

再故意删掉候选、放入旧模板、损坏分组记录，确认该拒绝的派单确实失败。配置正确、测试替身通过都不能代替真机证据。
