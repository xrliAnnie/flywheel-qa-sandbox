FLY-1775 · 529 隔离房补 generalized-DAG 能力 + 装房路书固化

设计方案(已过 Codex 设计评审 5 轮 APPROVED)· 2026-08-14 · Issue: FLY-1775 · 文档: engineering/doc/FLY-1775-529-generalized-dag-room/
一句话:给 QA 测试房的装房脚本加一个 --generalized 开关,一条命令就能起一间能跑「多节点流水线」的隔离测试房(今天要手工改数据库、手工调环境变量);再把三个 QA 实测踩出的 14 条坑逐条固化成自动化/预检/路书,并重写一个一键重放「九步活体演练」的驱动器。

§1 病 — 今天的隔离房跑不了 generalized workflow

generalized workflow(即 DAG 流水线:一张 issue 按「设计 → 实现 → QA → 审批合并」的有向图自动流转,是生产现在的主干工作方式)在 529 隔离房(一套与生产完全隔开的测试环境:独立的调度进程、独立数据库、独立 Discord 频道,用来在不碰生产的前提下做真机测试)里开箱跑不了。FLY-1768 的 QA 实测装一间能跑的房要手工做四件事,而且 8-14 号三个 QA 各自都把同一批坑重踩了一遍:

  • 5 个 workflow 开关全缺(0/5) — 生产的开关写在配置文件里,隔离房的启动方式收不到它们;
  • 「类别→流程模板」对应表 0 行 — 这张表决定「code 类的活走哪条流水线」,新房数据库里没人种;今天要停掉调度进程、手工执行 SQL、再重启;
  • API 口令没配 — 触发 generalized 流程的接口要求带管理口令,默认房根本不生成;
  • 项目配置缺 pipeline 段 — 生成器不产,手工补的又会被下次部署抹掉;
  • 唯一的端到端测试驱动器已被 FLY-1693 退役(旧模板体系下线时一并墓碑化,且依赖的符号已删,不可复活)。

§2 交付后 — 一条命令起房,零手工 SQL、零手工 env

装房脚本 test-deploy.sh 新增 --generalized 开关,把上面四件缺的东西全部自动补齐,并在部署终点做「到货自检」:开关是不是真的进了活进程、绑定表是不是真的有 5 行、健康检查里的代码版本号是不是就是你要测的那个分支 —— 任何一项不达标,部署按既有回滚流程整体失败,不留半成品房间。

14 条坑的归宿(每条都有去处,不再靠口口相传)

处置坑位
自动堵死socket 路径过长 · 生产告警 token 漏入(含 --alerts 场景,无条件清)· roundtable 环境残留 · 沙箱克隆卡死(增速看门狗+重试)· 拆房撞 cmux 租约(自动重试一次)· 部门标签精确匹配 403 · API 口令 401(口令落盘给驱动读)

§3 九步活体演练 — 一键重放的驱动器

FLY-1768 用真 AI 体人肉驱动了一次九步演练(实现节点真跑了 22 分钟、38 万 token)。新驱动器把「AI 干活」换成 stub 体(确定性假体:调度系统真起进程、真建代码工作副本、真发凭据 —— 只是进程里跑的是写死的脚本,不是 AI;所有控制面路径都是真的,只有「干什么活」是预先写好的),几分钟内可重复跑完整环路,每一步都从房间数据库取证:

  • 体是常驻可唤醒的:实现体完工后停驻不退出(和生产一样),QA 判 FAIL 后被引擎自动唤醒、同一个体补交第二版 —— 这正是 FLY-1765 修的返工环,演练的命门;
  • QA 放行有握手:第 8 步(QA 判通过 → 进合并闸)前,驱动器先核完全部前置条件才放行 stub 发判决,杜绝「抢跑导致诊断失真」;
  • 可连跑两次:第二轮开始前有一套「先终止上一轮 run 当栅栏 → 等在途启动落定 → 再清理」的收敛流程,专门防「上一轮残留半路杀出」;
  • 判决不进引擎:演练输出是证据文件和退出码,不冒充正式 QA 判决(沿 FLY-1768 纪律)。

§6 诚实边界 — 这个设计做什么、不做什么

做

  • 房间能力(一条命令、四项自检)、14 坑固化、九步驱动器、路书 —— 全部在测试脚本与文档层,生产代码零改动;
  • 验收分级:装房自检全绿(A1)+ 九步 1-7 一键全过、连跑两次(A2)+ 存量套件零回归(A4)。

不做 / 说清楚的

  • 坑 14(第 8-9 步)不保证过:FLY-1768 实测 QA 会话在房里拿不到 PR 身份,合并闸必拒(F2 finding)。机制根因在产品侧、不在房间侧 —— 本单把它做成「第 8 步前置断言 + 精确断点诊断」:能过就全绿;不能过,驱动器输出的诊断包就是给产品侧开单的证据。不假绿;
  • 不修 FLY-1768 的 F1/F2 产品机制(另行开单);
  • 两个附带发现只报不修:隔离房若用「开关热改」会写到生产配置文件(路书里写成禁令);某开关的启用合同还钉在已死的旧测试上(报 Lead 作 follow-up);
  • Discord founder 卡那条腿在默认演练里不覆盖(第 5 步断言是数据库级的 gate 状态;要测 Discord 腿走路书的可选章节);
  • generalized 与 mirror/roundtable 房互斥,不叠加。
