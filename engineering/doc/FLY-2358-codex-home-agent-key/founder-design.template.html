Codex 角色家:一个 agent 在一个项目里,永远回到同一个家

FLY-2358 · 设计说明 · 2026-09-05 · 分支 flywheel-FLY-2358 · Epic FLY-2355 · 上游 PRD FLY-2119 §5.2/§5.3/§5.5 · {{REVIEW_LINE}}

一句话总结

今天每张任务单的 Codex 都住在一个一次性的「家」(CODEX_HOME:Codex 存放登录凭据、配置、会话记录和记忆的那个目录)里,任务结束家就被遗弃,攒下的记忆一起被遗弃。本设计把家改成按「哪个 agent × 哪个项目」分配:同一个角色在同一个项目里,每张单都回到同一个家;家第一次用到才建、永远不随任务删除;两张单同时跑也共用这一个家 —— 这样 Codex 自带的记忆机制不用改一行就能把上一单学到的东西带进下一单。

背景:问题出在哪

本轮实测(2026-09-05):磁盘上有 867 个一次性家,其中 409 个真的攒出了原始记忆、383 个攒出了整理后的记忆索引。也就是说 Codex 的记忆机制一直在工作,问题不是「没开」,是「攒了但回不来」—— 下一张单换了家,什么都带不走。

PRD(FLY-2119)已经定了键 = (agent, 项目),并要求两件事同批上线:改键,以及「角色家不随任务删除」的保护。原因很具体:删家的函数已经写好、catch 是空的,今天没删是因为没人调它;一旦以后接上「跑完清理」,而家已经按角色命名、保护又没做,第一次清理就会无声地删光那个角色的全部记忆。

本单是三段式(设计 → 实现 → QA)的设计段,除了把改法写清楚,还必须先回答一道题:同一个 (agent, 项目) 同时跑两张单时,家怎么办?(这是常态:写这份文档时,flywheel 项目里就有 4 个 implement 角色的 Codex 在同时跑。)

并发裁定:选「共享持久家」,不选「一次性家 + 共享记忆点」

两条路都摆在桌上:(a) 一个 (agent, 项目) 一个家,几张单同时跑就同时住在里面;(b) 家仍然一次一个,只把记忆目录软链到一个跨任务的共享点。

{{D3}}

选 (a) 的决定性理由:Codex 的记忆流水线(phase1:启动时从本家的会话记录里抽取「闲置超过 6 小时」的会话写成原始记忆;phase2:拿一把全局锁把原始记忆整理进记忆索引)只在「同一个家的下一次启动」时才会处理上一轮的会话。(a) 让这件事零机制发生;(b) 的一次性家没有「下一次启动」,每张单最后 6 小时内的会话永远抽不到,要补就得再造一条回流路并且动 PRD 明令不许动的节流闸。

证据表:哪些是旧证据、哪些是本轮实测

问题来源结论
几个进程共用一家时,记忆整理的全局锁串不串行旧:FLY-2119 合成实验 + 真会话两臂(09-02);本轮:合成实验原样复现(E2)串行:8 个进程同时抢,恰好 1 个拿到、7 个被挡,5 轮全部如此
真二进制(codex 0.153.2)下两个 app-server(Codex 的常驻后台进程,runner 通过它下达任务)能否同时住一个家本轮 E1,零凭据能:双进程都活、各自的通信口都在、无锁冲突;阴性对照(同一个通信口起第二个)如期失败
同家两个真会话并发,登录凭据会不会互相打坏旧:FLY-2119 真凭据三臂(09-02,business 账号)正常使用下没撞:五个会话全部成功、无凭据类错误、且确认真的走到了刷新点
凭据文件写法有没有撕裂窗口旧:源码 + 饱和写实验(09-02)有,但形状是「瞬间读到空文件」而非坏文件;真实频率 = 几小时一次刷新 × 极窄窗口
(b) 路线的技术前提:软链的记忆数据库锁是否仍串行本轮 E3成立(5 轮恰好 1 个拿到锁);所以 (b) 不是因为「做不到」被否,是因为它更厚

真凭据臂没有重跑:上一轮已把实验账号的刷新票用旧,重跑需要 founder 再登录一次;工程 Lead 2026-09-05 裁定引用旧证据、不重登。剩余未证项写在「诚实边界」。

核心流程:一张单从派发到收尾

四个新动作:身份解析(把「哪个 agent × 哪个项目」算出来,直接复用 FLY-2147 给 Claude runner 做角色记忆时已经在用的同一条规则,不再发明第二套名字)、准入(在写数据库之前,拿着家里的一把毫秒级小锁一次性决定:建不建家、用哪个技能臂、登记本单的租约 —— 后面所有步骤只消费这个决定,不再第二次判断;那把小锁直接复用仓库里早已验证过的 mkdir 锁,不另造)、租约(lease:家里为每张正在跑的单放一个空文件,数文件就知道家里有几个活的)、臂继承(见「关键取舍」)。Codex 两轮评审把这里磨细了:互斥由那把小锁负责,租约只负责计数;技能包只在「决定的臂 ≠ 已装好的臂」时安装一次,所以正在跑的单永远不会看到技能目录被换;换臂之后还会为生效的臂重跑一次装配检查,查不过就让这张单在写数据库之前就失败,绝不悄悄回落到别的臂。

{{D1}}

数据与目录结构

旧的一次性家一个不动;新的角色家统一放进 agents/ 子树,按结构而不是按名字区分(根目录下早就混着几个非 UUID 的测试家,按名字判会出错)。根目录仍由现有的 codexHomesRoot() 决定,测试房用环境变量整体改根。

{{D2}}

租约的一生

共享家下「我们这一侧」会互相踩的七处冲突(擦令牌、Bridge 重启清扫、孤儿进程回收、恢复探针、工作区信任、技能臂、账号切换)由三样东西收口:小锁管互斥、租约管计数、session.json 里记下「家路径 + 项目 + 角色」管「这张单住在哪」(只许写一次;它在单子结束、租约删掉之后仍然在,所以删家保护永远认得出角色家;凡是要删东西、擦令牌的地方都必须拿数据库里这张单的项目和角色去核对这条记录,自洽但属于别人的家会被拒绝)。Bridge 重启后的恢复也先看这条记录:部署前起跑的单没有记录,就留在原来的一次性家里,绝不搬家。

关键取舍与放弃的备选

取舍选了什么放弃了什么、为什么
并发选共享持久家一次性家 + 共享记忆点:技术上可行(E3),但要新造回流并动节流闸,每张单最后 6 小时的会话会丢
「agent」是谁复用FLY-2147 的 (project, role):role = DAG 节点 id,没有节点时用 agent 名另造一套角色词表:PRD 明确要「一个来源」;解析不出身份时回落到今天的一次性家并记日志,不发明别名
GH_TOKEN(runner 用来推代码的 GitHub 令牌,写在家的配置里)什么时候擦选租约计数:最后一个活单退出才擦每单退出就擦(今天的做法):会把还在跑的同伴的令牌擦掉;永不擦:违反「退役的家不囤活令牌」这条早已定下的安全不变量
技能臂(A/B 臂:FLY-1395 正在做的实验,给不同任务配不同的技能包;Codex 侧的技能包安装在家里)选臂变成「家级属性」(只管装进家的三种技能包,不管每单自带的提示词附加态):家里有别的活单时沿用现有臂;这个决定在写数据库之前一次做完,所以 A/B 分析读的字段里就是实际生效的臂,并标记为 inherited(Lead 硬要求)把臂搬到命令行参数并常驻安装所有技能包:更厚;按臂分家:会把记忆按臂切碎,违反键的定义
账号轮换期间两张单住同一家接受凭据文件在两个账号间来回翻,各进程自身一致,只记日志按账号分家:同样违反键定义;阻止派发:会在额度最紧张的时候卡住整条流水线
删家选角色家一律拒删并大声报错;旧家照删;空 catch 改成可见告警只靠「没人调这个函数」:PRD 已经说明这把刀已上膛

怎么验收(QA 段执行)

  • 同对同家、异对异家:同一个 (implement, flywheel) 连续两次派发解析到同一路径;换角色、换项目、换大小写共四组对照全部不同。
  • 删家保护:对角色家调删除函数 ⇒ 拒绝、目录仍在、错误日志一行;对旧家 ⇒ 行为不变;删除失败 ⇒ 告警而不是沉默。
  • 租约:两张单同住,第一张退出后令牌仍在、日志写「推迟擦除」;第二张退出后令牌消失、租约目录为空。
  • 实际生效臂:数据库里能查到 skill_framework_mode_via = "inherited" 的行,且每一行的臂等于家里记录的臂。
  • 真机或 529 房(529 房:本机隔离出来的、用测试机器人跑真实 Flywheel 的演练环境):Codex runner 派发 → Bridge 重启后恢复 → 后台进程换号重起,三条路径各至少一次,三次都落在同一个家。
  • 零回归:全仓测试、类型检查、lint 绿;既有的家相关测试一个字不改。

诚实边界:这份设计做什么、不做什么

做

  • Codex runner 的家改键、懒建、不删、租约、启动清扫与孤儿回收适配、恢复与换号路径适配、实际生效臂写回数据库。

不做(交给谁)

  • 不清理今天的 867 个一次性家(它们是唯一证据);不动 founder 自己的 ~/.codex 与三个常驻 Lead 的家;不改记忆节流闸;不改凭据存储方式。
  • 「种回去」(把旧家攒下的记忆迁进对应的角色家)与最终的记忆验收 → 同 Epic 的 B2 单,它因本裁定缩成「种回去 + 验收」。
  • 常驻 Lead 的家仍由启动脚本管(PRD 说改配置即可);本单只让解析器能接 Lead 的名字。

已知限制(不隐藏)

  • 回滚不是零条件:旧代码不认识角色家,所以 revert 之前必须先让所有住在角色家里的单跑完(计划里给了三条可执行的判据)。
  • 没有 DAG 节点 id 的 Codex 运行(历史上只有 4 张「main」单)暂时还住一次性家。
  • runner 崩溃留下的租约要到下次 Bridge 启动才清掉,那段时间同家的令牌会多留一会儿(与今天「Bridge 被杀时来不及擦」同级)。
  • 未证项:两个进程在同一毫秒同时写凭据文件会怎样;高频下服务端是否仍容忍同一张刷新票被重复兑换(只有一次实验)。
  • Codex 源码行号引用的是本机 2026-02 的源码副本,生产二进制更新;真二进制实验(E1)用的是生产版本。
