# Design Review — plan.md (FLY-1707 E5) (Round 5)

Date: 2026-08-15
Author: Codex
Status: CHANGES REQUESTED

## Summary

The consolidating rewrite materially improves the design: the resume action union, immutable authority receipts, W10 lineage, dual Git carriers, land-effect fencing, and shadow cursor are now substantially coherent. It is still not implementation-ready because the current text leaves several concrete crash and concurrency holes—most notably a late S3 baseline, a dirty-only quarantine bypass, a non-atomic force-cancel receipt, and an overlapping-collector risk—and one inventoried write path contradicts the current StateStore contract.

## What's Good (Keep)

- Keep §2.1 as the single normative schema section and the T3 SQL action-union `CHECK`; this removes most of the prior patch-drift.
- Keep the immutable `workflow_run_event` receipt model with `receipt_kind` plus `receipt_digest`, the three-way W mutation tests, and W10's source/result lineage.
- Keep `effectiveAnchor` and `effectiveRuntimeSemantics`, the identity-free runtime projection, and frozen-runtime replay without calling the live dispatch resolver.
- Keep the strict `redispatch_execution` versus `reconcile_state_only` union, including no synthetic gate execution, a durable redrive generation, and an immutable redrive ack before T4 caching.
- Keep create-only local/store ref creation, same-value adoption, dual-carrier recovery ordering, and explicit refusal to push engine refs to origin.
- Keep the full land authority conjunction adjacent to every irreversible effect and the constituent-by-constituent mutation tests.
- Keep canonical collection episodes, one-open-receipt intent, owner/generation leases, and the distinction between in-progress snapshots and responded byte replay.
- Keep operator-only cascade authority, `held` precedence, one registered enforcement flag, request-path-free shadowing, opportunity-key fairness, and rebase sequencing after FLY-1772.

## Issues & Recommendations

1. **[BLOCKER] S3 is still stamped too late to be the input baseline of the authoritative target.** T1 records only S1/S2 in the target-changing transaction, while T2 lets a later rider fetch the then-current Linear body and establish S3. If the issue body changes after W2/W6 commits the target but before the first rider stamp, the changed body becomes the baseline; a later resume passes V2 and can reuse QA/gate work produced against the old body. The listed test begins at “stamp → admission” and misses this “target commit → first stamp” window. **Fix:** freeze `{Linear version/updatedAt, bodyDigest}` from an observation obtained before the authoritative W transaction and pass it into `commitAuthoritativeTargetChangeTx`, or bind an already-durable source observation that predates that transition. A rider may verify or complete transport, but it must not invent the historical baseline. If no trustworthy W-time observation exists, leave the attachment pending/non-recoverable. Add a test that edits Linear after the target transaction but before the first rider tick and requires `envelope_changed` rather than `ready`.

2. **[BLOCKER] The quarantine entry condition drops the most common A1 crash residue.** Section 2.4 runs both snapshot phases only when `suffixHead != anchor`. A node can crash with `HEAD == anchor` and staged, unstaged, or untracked work; that path skips quarantine and `removeIfExists()` destroys the half-done work. The same algorithm also says to skip Phase 2 when index equals worktree but then unconditionally points the ref at `worktreeCommit`, which does not exist in that branch. **Fix:** enter quarantine when `HEAD != effectiveAnchor OR porcelain-v2 is non-empty`; define `quarantineTip = worktreeCommit` when Phase 2 exists and `indexCommit` otherwise. Make A1 explicitly use `HEAD == anchor` plus dirty/staged/untracked residue. Reuse or factor the existing dirty detection and bounded process handling in `bridge/worktree-quarantine.ts` where practical.

3. **[BLOCKER] T7 creation was moved back out of the Phase-A transaction, reopening the force-cancel crash gap.** The plan now says Phase A leaves the existing transaction unchanged and creates the durable receipt in Phase B. A crash after the run becomes `terminated` but before T7/T7b exists loses the client association and the Phase-A live target set; a retry encounters a non-manageable run, while the observe-only sweep may not collect it yet. A later sweep can also freeze a different set, so exact replay no longer describes the original request. **Fix:** when `collectExecutions:true`, the same StateStore transaction that CASes the run terminal must adopt/create the canonical open T7 row, freeze the ordered live-session set and digest, and insert the request alias/digest. If the sweep already owns an open row, atomically alias to that row. Add crash-after-commit/before-response replay that starts from the original client key and proves the same receipt and frozen set are returned.

4. **[BLOCKER] The collector lease assumes a 60-second close bound that the current primitive does not have.** Current source explicitly documents that `closeRunner` can hang in the Terminal path, and `closeRunnerTerminalView()` invokes `osascript` without a timeout. A `Promise.race` at the caller would not cancel the underlying teardown; after the 120-second lease expires, a takeover collector can overlap the still-running first collector even though the stale outcome CAS is rejected. **Fix:** pass the T7 owner/generation through `closeRunner`'s existing `authorityCheck` seam, renew during a close, and recheck the claim before each destructive boundary. Make every underlying subprocess genuinely bounded/cancellable (including `osascript`) or define a total close operation bound that terminates the child work; do not rely on a detached promise timeout. Test a deliberately hung Terminal close across lease expiry and prove a second collector performs zero overlapping effect calls.

5. **[BLOCKER] W9 and `ledger_finalize` do not match `applyWorkflowLedgerBatch` on this branch.** `StateStore.ts:34493-34503` permits an explicitly targeted run—the only path that can name an engine-owned run—to contain only `side_effect` operations. The frontier-moving dispatch/wake/complete branches are for the compatibility `engine_owned=0` shadow ledger, while finalize is explicitly projection-only and the source comment forbids inventing a finalize run-event kind (`:34475-34478`). `WorkflowLedgerBatchInput` also has no `batchUid` from which the proposed receipt UID could be formed. **Fix:** remove `ledger_finalize` from T1's receipt enum and make W9 a guard-only exemption asserting that engine-owned explicit batches remain side-effect-only. If that contract is ever relaxed, the inventory guard should fail and force a real receipt mapping then; do not expand E5 attachments to compatibility shadow runs.

6. **[HIGH] The revised ref-liveness rule still makes every resumed ref immortal.** T3 is append-only, so “referenced by any T3 admission source/result chain” is permanently true once W10 runs—the same literal-history leak Round 4 asked to remove. The paragraph also calls every attachment younger than 90 days live but separately calls an invalid attachment non-live, without precedence. **Fix:** compute liveness per physical ref from live roots only: an attachment on a non-terminal run or a non-invalid attachment inside the retention window. Follow T3 lineage only from those roots, or more simply rely on source/result attachment rows grouped by the shared ref. Add a terminal run with a W10 chain older than 90 days that is reclaimed, plus an active/recent child that keeps the same shared ref alive.

7. **[BLOCKER] T7b's identity is under-specified and raw `client_key` would collide across runs.** Existing run-management idempotency is scoped as `run_...:<runId>:<clientRequestId>` (`StateStore.ts:24831-24835`), but the plan describes `client_key` as a global primary key. Reusing a perfectly valid client request ID on another run could therefore alias to the wrong receipt. The false→true conflict is also not durable when the first request used `collectExecutions:false`, because no T7 alias is defined for that path. **Fix:** make the immutable key `(run_id, client_request_id)` or a canonical run-scoped string, bind `principal`, action, `collectExecutions`, and frozen target digest in `request_digest`, and specify how the existing operator event and alias jointly reject false→true replay. Add cross-run same-client-key and false→true tests.

8. **[HIGH] The claimed normative schema is incomplete, and later lifecycle writes cannot satisfy T5's `CHECK`.** Section 2.1 provides full DDL only for T1–T3 and T5; T4 is a comment, while T6/T7/T7b are prose without foreign keys, append-only triggers, state/NULL unions, or the alias scope needed above. Separately, T5 allows only `probe_kind IN ('shadow','admission')`, yet §5 requires T6-expiry and cascade-no-op records in T5. Those inserts either fail or mislabel lifecycle evidence as a resume probe. **Fix:** add exact normative DDL for all eight tables, including state-discriminated NULL checks and append-only triggers. Keep T5 resume-only; record T6 expiry, cascade refusal, and residue-sweep diagnostics as typed immutable `workflow_run_event` rows (or explicitly widen a named general ledger, but do not overload the probe table). Update S1/S6/S7 ownership so each table is created exactly once.

## Verdict

CHANGES REQUESTED — address items above
