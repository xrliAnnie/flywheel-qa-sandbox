# Design Review — plan.md (FLY-1707 E5) (Round 6)

Date: 2026-08-15
Author: Codex
Status: CHANGES REQUESTED

## Summary

Round 6 materially closes all eight Round 5 findings: the S3 baseline is no longer invented by the rider, force-cancel receipt creation is atomic with terminalization, collector teardown is bounded and fenced, W9 now matches the real ledger contract, ref liveness has live roots, and the schema/ownership narrative is substantially cleaner. The design is feasible in the current architecture, but five remaining correctness gaps are implementation-blocking because the normative DDL and two source-facing protocols still permit cross-run aliasing, false idempotent replay, misattributed envelope evidence, stale collector effects, or incomplete quarantine.

## What's Good (Keep)

- Keep the `issue_observed` direction: a rider may transport or verify durable evidence but may not manufacture a historical S3 baseline after the target transition. The explicit “edit after target transaction, before rider” negative test is valuable.
- Keep T7 creation/adoption, frozen live-session selection, and T7b alias insertion in the same StateStore transaction as `active -> terminated`; this removes the most dangerous terminal-without-collection-receipt crash window.
- Keep passing the T7 owner/generation through `closeRunner.authorityCheck`, adding real cancellation to subprocesses (especially `osascript`), renewing during close, and rejecting stale outcomes by generation CAS.
- Keep W9 as a source-guarded exemption. `applyWorkflowLedgerBatch` currently limits explicit engine-run batches to side effects, so inventing a `ledger_finalize` authority receipt would have been inaccurate and unnecessary.
- Keep physical-ref liveness rooted only in active/recent non-invalid attachments, with T3 lineage traversed from those roots. This fixes the append-only-history immortality leak while preserving shared W10 refs.
- Keep the corrected quarantine entry predicate (`HEAD != effectiveAnchor` OR any porcelain residue), the valid `quarantineTip` selection, and reuse/factoring of the existing worktree quarantine code.
- Keep T5 resume-only, with close/cascade diagnostics represented as immutable typed run events, and keep the explicit S1/S6/S7 table-creation ownership.
- Keep the slice ordering, especially S2b as an isolated mutation-fence slice and S5/S8 after the FLY-1772 rebase.

## Issues & Recommendations

1. **BLOCKER — The normative T7/T7b DDL does not enforce run identity or the collector-lease state machine.** T7b's foreign key covers only `receipt_key`, so an alias whose `run_id='run-B'` can legally reference `episode:run-A:0`; the `(run_id, client_request_id)` primary key does not prevent that. I executed the DDL with `PRAGMA foreign_keys=ON`, and the cross-run insert succeeded. T7 also accepts `state='collecting'` with all owner/generation/lease fields NULL, so the claimed state-discriminated lease contract is not present in the schema. Add a parent `UNIQUE (run_id, receipt_key)` and a composite child FK `FOREIGN KEY (run_id, receipt_key) REFERENCES workflow_run_collect_receipt(run_id, receipt_key)` (or remove duplicated `run_id` from T7b and always derive it through T7). Add a discriminated CHECK requiring no claim in `frozen`, a complete claim tuple with positive generation in every claim-owned state, and the intended response/claim shape in `responded`. Add direct negative schema tests for cross-run aliases, partial/ownerless claims, and invalid responded shapes.

2. **BLOCKER — The stated durable `collectExecutions:false -> true` conflict does not exist in the current operator-event payload.** `changeWorkflowRunStateByOperator` currently compares reason, principal, status, clientRequestId, closeout digest, and closeout kind (`StateStore.ts:24843-24852`), and writes no `collectExecutions` field (`:25001-25010`). Therefore, without an explicit planned payload/comparator change, a later true request with the same key is an idempotent success at `:24856-24861`, not the promised 409. Make the projection normative: the true path writes `collectExecutions:true` (and its canonical receipt/frozen-set identity if needed) into the existing operator event in the Phase-A transaction; replay compares `(payload.collectExecutions ?? false)` to the requested boolean. Preserve the flag-absent legacy bytes by continuing to omit the field for false. Add a mutation test that removes only this comparator and proves the false-then-true test turns red before any `run_not_manageable` fallback can mask it.

3. **BLOCKER — S3 selects a run-wide “latest preceding” observation instead of evidence belonging to the intended launch authority.** The existing `workflow_run_event` already has `node_id` and `execution_id`, while `commitWorkflowTransitionTx` has the exact `(run,node,attempt,execution)` tuple. In contrast, the plan selects the latest run-level `issue_observed` by sequence. Current `createFetchIssue()` makes this unsafe: it returns no `updatedAt/version` and silently falls back to `session.summary` when Linear fails (`run-infra.ts:223-270`; `PreHydrator.ts:14-20`). A failed current launch can therefore inherit an older node's successful observation, and an interleaved launch can contribute a newer but unrelated one. Bind `issue_observed` to the exact node/attempt/execution/activation whose input it represents, use a deterministic checked event UID, and have each W path select or inherit only the observation authorized for that path. Only an authoritative Linear success with `updatedAt` and the exact delivered body may count; the existing StateStore fallback may still launch for compatibility but must produce no V2 evidence and must never cause a predecessor observation to be reused. The simpler acceptable alternative is one immutable run-level S3 baseline established by the first authoritative Linear fetch and inherited forever. Add negative tests for Linear-fallback-after-an-older-observation and interleaved observations from two execution tuples.

4. **HIGH — T7 fencing is not yet test-complete across `closeRunner`'s early success paths.** The current sticky authority helper is created only after the no-target return (`close-runner.ts:521-574`). A non-Codex `!target` path can insert the close event, mark detection clearing, and run `finalizeCommunications()` with no authority check (`:523-570`). The graceful phase path checks after its awaited shutdown, but then performs event/clearing/finalization and can await archive without another check (`:457-513`). “Every destructive boundary” in prose should explicitly require moving the sticky T7 check ahead of all early branches and rechecking before CommDB/gate finalization, detector mutation, archival, and post-await continuation—not only around tmux/Terminal kill. Add takeover tests for `!target` and graceful shutdown in addition to the hung-Terminal case; after generation takeover, the stale collector must perform zero event/finalization/archive effects.

5. **HIGH — The quarantine algorithm is not exhaustive over porcelain-v2 records and filesystem modes.** The plan describes ordinary staged/unstaged/deleted/untracked paths, but `--porcelain=v2 -z` also emits type `2` rename/copy records with a second NUL-delimited path and type `u` unmerged-index records. Treating a rename only as the new path leaves the old path in the seeded tree; an unmerged live index cannot be represented by a normal `write-tree`. The Phase-2 description also specifies mode `120000` for symlinks but not preservation of regular-file executable-bit changes. Define an exhaustive parser policy for `1`, `2`, `u`, `?`, and ignored records: consume both rename paths and apply source deletion plus destination entry, preserve the live mode (`100644`/`100755`/`120000`/supported `160000`), and fail closed before `removeIfExists()` for an unrepresentable conflict while durably preserving its manifest/blobs. Add rename, chmod-only, and unmerged-index tests; each must prove either exact GC-reachable quarantine contents or zero destructive rebuild.
