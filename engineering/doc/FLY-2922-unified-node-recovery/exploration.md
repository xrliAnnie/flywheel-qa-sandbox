## 问题与成功定义

本单承接 founder 2026-09-25 的「修」决定。盘点 K07 包含九张单、历史 37 次；不是本次复现结果。启动回滚、缺完成回执或关闭死体后，任务链应有一个明确出口：保留同一 run、当前节点及仍有效的审批，真正写出新派发。不能用 terminate/start 丢弃原任务链来代替恢复。

九张原单分别是 FLY-2329、2295、2116、2524、2095、2181、2191、2525、2545；每张必须独立构造原现象并从公共恢复入口贯通到调度消费。追加 FLY-2901 QA 读取 head 超时与 FLY-2914 设计体起步死亡。完整逐项矩阵在 plan.md §7。

## 不变量与边界

故障重派保留 runId、snapshot、branch、nodeId 与业务 attempt；替换 executionId 并递增物理 launch ordinal。先隔离旧体写权，后派新体；不凭终态字符串推断物理死亡。任何旧体迟到完成都不得推进后继。

关闭执行体不等于终止任务链；显式 run terminate 与真正完成仍保持终态语义。完成必须先提交真实 completion/transition，再投影 session 状态。恢复不能补造成功或审批。

人工暂停、审批探测、已完成节点上的业务决定，不是死体故障。R1 评审发现强行重派会让它们丢失出口；修订保留各自真实操作语义，共用 stage/apply 权限与回执，不谎称状态恢复产生了新执行体。审批节点无 execution 的现有表示保持不变。

投递协议、账号安装、非工作流 legacy 生命周期不在本单重写。仅对其阻断同一恢复事务的消费者做必要适配。旧已在途额度 terminate/start 以现有持久收据收敛；不新增该恢复路线。
