① 一句话总结

产品本身（「held 之后只留一个统一恢复口」）早已批准并实现；这次 QA 失败是测试脚本（driver）自己的毛病：它去宿主机的 tmux 里找房间里的 runner 窗口，当然找不到，于是把「活着」误判成「死了」，卡了近 2 小时。修法只有一处：让探活去房间自己的 tmux 里看，再把分支和 main 同步好。产品代码一行不动。

tmux：一个终端「窗口管家」，每个 AI runner 跑在它的一个窗口里。每个 QA 房间有自己独立的一套 tmux（靠环境变量 TMUX_TMPDIR 区分，等于房间的门牌号）。

③ 数据 / 结构模型

{{D2}}

房间门牌号只有一个真相来源：qa-slot-env-contract.json 里的 TMUX_TMPDIR = SLOT_DIR。探活函数直接用同一个值，不自己拼 socket 路径。

socket：tmux server 的「电话号码」文件；TMUX_TMPDIR 决定这个号码存在哪个目录。

⑤ 关键取舍与被否决的方案

选择否决的方案原因
子进程注入 TMUX_TMPDIR=slotDir自己拼 -S slotDir/tmux-uid/default拼路径等于复制 tmux 的规则（真实路径解析、uid 目录），多一处可能漂移
清掉宿主 TMUX / TMUX_PANE保留如果 driver 本身跑在 tmux 里，TMUX 会把查询钉回宿主 server，门牌号失效
slotDir 缺失/相对路径就报错静默回落到宿主静默回落 = 复现这次 bug
只修输入（死/活）放宽分类规则（不看死活）放宽会让真正死掉的实现体也被判「停车正常」，掩盖真问题
merge mainrebase保留 QA 已审的历史；不需要 force-push

⑥ 诚实边界：做什么 / 不做什么

做：修 QA driver 的探活命名空间；同步 main 并解冲突；补 RED→GREEN 测试和静态守卫。

不做：不碰产品代码（hold 前置、恢复处理器、complete 顺序、关死体级联）；不改分类规则；不 rebase/force-push；不 ship、不 merge。

已知风险：若将来房间设置 FLYWHEEL_TMUX_SOCKET_OVERRIDE，Codex runner 会换 socket，探活需同步读它（当前合同不设）。merge 冲突解错会导致起房失败，靠守卫测试 + QA@4 真房兜底。
