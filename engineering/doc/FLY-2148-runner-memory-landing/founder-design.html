一句话

上一单(B0)已经把「每个 runner 按『项目 + 角色』挂一个记忆文件夹、启动时自动读短索引」做进了引擎;这一单把它落地:定下「什么时候写」的规矩(每个节点收工前写一次,不强迫),让「写没写、写了多少、索引超没超」在收工那一刻变成一行看得见的回执并存进数据库(能直接查),再把「这次跑在实验的哪一臂」也一并记下来——这样你以后要拍板「role 还是 shared」时,手里有数,而不是靠感觉。

术语:runner = 干活的 AI 执行体(一个 Claude Code 或 Codex 命令行会话);Bridge = 调度进程,负责派工、起 runner、收结果;DAG 节点 = 一张 issue 被拆成的「设计 → 实现 → QA」三个阶段,每个阶段一个 runner、一个角色。

B0 之后到底还缺什么(2026-09-04 读代码 + 本机实测)

issue 要的B0 已经做了还缺(本单要补)
① 记忆目录读写机制:短索引自动送到眼前,正文按需翻,照 Lead 侧形状已做 起 runner 时算出 ~/.flywheel/runner-memory/<项目>/<角色>/,交给 Claude Code 原生装载;Codex runner 拿到目录路径与说明默认没开。B0 收尾时按你的「split run」原话改成了一个四态实验开关 runner_memory_mode(off / split / role / shared),默认 off——我这个 runner 自己的环境里就没有那个目录变量。本单不动这个默认值(何时翻、翻成什么由 Tadashi 操作),只保证「翻开之后落得下、看得见、能归因」
② 什么时候写(你倾向「一个 issue 写一次」,留给 Tadashi 判断)只有一句建议 提示词里写着「最好在收工时写」;plan 明说「引擎不做写入回执」没有时机合同、没有任何地方知道「这次到底写没写」。Claude Code 官方对它自己的记忆功能的描述是「不是每次会话都会存」——靠它自觉,满足不了「第二次跑读得到第一次写的」
③ 截断防护:索引注入有界、超界可见读侧已做 起 runner 前最多读 64KB,超预算时日志和提示词两面说「约从第几行起没进来」写侧只有 Claude 有。Claude Code 自己写完索引会量一次、超了立刻报错要求重写;Codex runner 是手写的,没有任何写侧守卫,写超了要等下一个 runner 起来才发现
(B0 留下、本单必须补)实验分流归因每次起 runner 打一行日志「这次在哪一臂」只在日志里,不在任何表里。这个开关的退役条件写的是「founder 根据 split 对比选定 role 或 shared」——可今天没有一张表能回答「这个会话跑在哪一臂、写没写记忆」,你拿不到对比数据,它就永远退不了役
所以本单的真实范围 = 写入时机合同 + 收口回执 + 分流归因入库 + Codex 写侧截断守卫 + 在 role 臂下把 PRD 那四条验收真机跑通。①的机制本身不重做。

核心流程:从派工到第二次读到记忆

图 1 · 一次 DAG 节点执行的完整链路;蓝色是 B0 已有的,本单加的是「拍快照 → 收口合同 → 收口回执 → 落库」这一串(Mermaid 本地渲染)

术语:快照 = 起 runner 那一刻给索引拍的一张「体检单」(行数、字节数、内容指纹、正文文件数),收工时再拍一张,两张一比就知道写没写;收口 = runner 跑「我做完了」那条命令(complete 或 QA 的 qa-result)的那一刻。

写入时机怎么定:「一个 issue 写一次」落到角色粒度

你的原话是「一个 issue 写一次会比较好,但不要写死,让 Tadashi 判断」。先把「一个 issue」落到正确的粒度:一张 issue 在 DAG 里是设计 → 实现 → QA 三个不同角色的 runner,而记忆按角色分文件夹。所以「一个 issue 写一次」在角色文件夹上的自然形状就是:每个节点的 runner 在收工前写一次——每个角色的文件夹里,这张 issue 恰好留一次痕。

方案处理理由
A · runner 自己写 + 收工时出回执,不强迫采用(Tadashi 裁定:「非阻塞是对的,没学到东西硬写 = 制造噪音记忆」)写的内容只有 runner 自己知道,只能它写。提示词把「最好收工时写」改成明确合同:「跑完成命令之前,写下这次学到的 ≤5 条可复用判断;没学到就不写,并在最后报告里说一句」。回执让「没写」从「不知道」变成「看得见」
B · 阻塞式:没写就不许收工先不做会逼 runner 写废话;重启续跑的 runner 会被误判;失败退出(blocked)这条路绝不能拦;而且要加一个「我真的没学到」的例外口子——和这个 Epic 两次「不加旋钮」的直令气质相反。回执数据攒一阵子,若「没写」占比高,再由 Tadashi 决定升级——那时只改一处
C · 收口时另起一个 AI 步骤读对话记录替 runner 写否决多一次模型调用、多一套「记忆生成器」,写进去的是二手转述;违背「一个真相源」
D · 用 Claude Code 的会话结束钩子写否决钩子触发时模型已经走了,没有内容可写;量索引的最好时点是 runner 还活着的收口命令里——它看得见提示、还能补写
对 Lead 那边的对齐:Lead 的记忆也是「模型自觉写」,从来没有时机合同。本单是第一个给「什么时候写」立规矩的,形状(一事一文件 + 短索引一行指针)与 Lead 完全同形。

收口回执:runner 说「我做完了」那一刻发生什么

图 2 · 收口时序:量一次、比一次、终端一行、随既有完成事件送到 Bridge、落成可查的列(Mermaid 本地渲染)

三态(外加一个兜底)什么意思runner 终端上看到的那一行
written索引指纹变了,或正文文件数变了runner-memory closeout state=written … delta=+2L/+1files
unchanged和起跑时一模一样同上 + 一句提示「这次什么都没写;如果学到了可复用的判断,现在写,再退出」——这一句是给「收工后、退出前」那个窗口的
over_budget索引超过预算(160 行 / 20,000 字节)——优先级高于 written,哪怕这次也写了同上 + 「先整理再收工;超硬上限时:下一个 runner 从约第 K 行起读不到」
unmeasurable量不到(目录没了 / 索引不是常规文件 / 起跑快照丢了)state=unmeasurable error=…——「挂载了但量不到」必须可见,不能悄悄退化成「没有回执」

这条回执不阻塞完成:四种状态都不改变完成命令的退出码和路由。它是 runner 自报的证据,Bridge 只校验形状(版本、枚举、路径、大小 ≤4KB),不复量——和今天的「改了几行 / 提交了几次」同一级别。

数据与结构模型:盘上一份、环境变量两个、数据库五列

项定案为什么

回滚代码回滚;五列留着(全部可空)与上一次实验列同策略;Bridge 与 runner 命令行任一方是旧版,结果只是回执缺席,不报错——不需要同时部署

截断防护:起跑面(B0)+ 收口面(B1),两面夹住,不静默

图 4 · 读侧守卫在起 runner 时,写侧守卫在收口时;任一面漏了另一面兜(Mermaid 本地渲染)

  • Claude runner:Claude Code 自己有写侧守卫(写完索引立刻量,超了报错要求重写);本单的收口回执是第二道。
  • Codex runner:没有原生守卫,收口回执是唯一一道。「实现」节点默认走 Codex,所以这一道主要是给它的。
  • 超软预算(160 行 / 20KB):回执说「先整理再收工」;超硬上限(200 行 / 25KB):再加一句「下一个 runner 从约第 K 行起读不到」。K 的算法沿用 B0,不另造。
  • Tadashi 硬要求 ②「截断要有可见标记,⛔ 不许静默」:起跑面(日志 + 提示词)与收口面(终端 + 日志 + 数据库列)共五处,任何一处单独看都能看出来。

诚实边界:这个设计做什么、不做什么

做

  • 写入时机合同(每节点收工前 runner 自写一次;提示词逐字合同,Claude / Codex 各一版)。
  • 收口回执:三态 + 变化量 + 超预算指令,终端、日志、数据库列三面可见;不阻塞完成。
  • 分流臂 + 目录 + 起跑快照入库;Codex 收口面的写侧截断守卫。
  • off / shared / 本单没碰的 runner 类型:提示词、启动参数、完成事件逐字节不变;五列幂等迁移;真机验收覆盖 PRD 四条与两条硬要求。

不做 / 不能保证

  • 写不写仍由 runner 遵守提示词决定——非阻塞是 Tadashi 的裁定。回执让「没写」可见、可统计;要升级成阻塞只改一处,但那是他看过数据后的另一次裁定。
  • 回执是 runner 自报:Bridge 校验形状、不复量;一个 runner 可以谎报。这与今天的「改了几行」同级,本单不给它加权威。
  • 回执记的是收工那一刻:收工后、退出前再写的不进回执(那句「现在写」的提示就是给这个窗口的);重启续跑各算各的;同角色两个 runner 同时在跑时,「写了」可能是对方写的(B0 不加锁,本单不变)。
  • shared 臂没有目录、没有回执,只记臂;你对比的是「role 臂的写入率与内容」对「shared 臂什么都不留」,不是两个对称指标。
  • 第一次起某个「项目 + 角色」读到的仍是 3 行空索引头,从第二次起非空;不从存量 573 条项目记忆里抽种子(混味、质量未审、B0 已给只读指针)。
  • 不改开关默认值:合入后生产仍是 off;要让记忆真的开始攒,Tadashi 得设 role 或 split。
  • 不做 founder 对比页:数据已在五列里,页面是后续单。不做跨角色互读策略(留你拍)、Codex 原生挂载(C1)、记忆迁移、远端备份(A 线)、记忆质量审计。
