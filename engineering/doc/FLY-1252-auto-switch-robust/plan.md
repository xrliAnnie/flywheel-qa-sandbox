## 3. 核心契约

### 3.1 候选资格分档、三分类与降落（P1）

- **分档**：tier0 = `fiveH < trigger5hPct && sevenD < 100`（status `qualified`）；tier1 = `fiveH ∈ [trigger5hPct,100) && sevenD < 100`（status `qualified_low_headroom`）。**`ranked = tier0 按 7d-reset-最早 ⧺ tier1 按 5h 余量最大`** —— 连接后整体作为 `preferredOrder` 交给 `switchAccount`，executor 既有候选循环（TargetStale/TargetQuotaExhausted 才继续）天然「先耗尽 tier0 再试 tier1」；tier0 全部在 apply 时刻失效时 tier1 兜底（Codex R1#4 后半）。
- **分类**（`PanoramaStatus` 封闭 union → 编译期穷尽映射）：`usable`（两档 qualified）/ `exhausted`（实测 ≥100）/ `unverifiable`（freshness_stale、became_active、usage_*——「验不了但 token 可能没问题」）/ `ineligible`（credential_missing、credential_unavailable、not_in_pool、not_in_store、auth_unusable——结构性不可切或 apply 必败）。
- **降落**（Annie 已授权；默认 OFF 落地，T 系列全绿 + 受控真机演练通过后翻 true——工程纪律非待决）：`ranked=[]` 且存在 `unverifiable ∩ store isQuotaUsable ∩ !isAuthUnusable` → `degradedOrder`（store `weeklyResetAt` 最早、null 最后、平手 config order）→ **同一个 `switchAccount`**。安全性完全依赖既有机制（freshness 硬闸、verifiedAt 闸、CAS、minSwitchInterval、commitSwitch 源账号 cooldown 防回切）；降落不引入新 Keychain 写路径、不加锁内网络调用。
- **结局分流（Codex R1#5）**：`switched` → `account_switch_degraded`；`no_account` → no_target episode；**`failed` → `account_switch_failed`（带 reasonCode 与降落上下文），绝不折进 no_target**——freshness_unavailable/apply_failed/lock_lease_lost 是切号平面故障，不是「没号」。

### 3.2 blockedEpisode 状态机（P2，送达回执驱动——Codex R1#3）

state 形态（R7#1 后权威版）：`blockedEpisode: { scope, startedAt, lastConfirmedAlertAt: string|null, alertCount, blockedRound: number, recoveryRound: number, activeDelivery: { kind: "blocked"|"recovered", round: number, attempts: number, lastAttemptAt: string|null } | null } | null`

**activeDelivery = 唯一的「未确认投递轮」判别器**（Codex R7#1）：存在 = 该 kind 的当前轮已开、未确认（persist-before-deliver 使 crash 后可无歧义续投同轮——`attempts` 与 `round` 都在里面，与「已确认等下次重报」的 `activeDelivery=null` 结构可分）；确认送达 → `activeDelivery=null` + 对应确认字段更新。旧字段 `deliveryAttempts/lastDeliveryAttemptAt/pendingRecovery` 全部收敛进 activeDelivery（pendingRecovery ≡ activeDelivery.kind=="recovered"）。

**每 tick 投递优先级契约（R7#1 + R8#1，防同轮双投/双推进、防新轮首发延迟）**：
1. preflight 保守清除先行（可整体清 episode）；
2. **唯一发送 helper + tick-local attemptedKinds**（R8#1）：一切 episode 告警投递都经同一个可复用 sole-sender helper；helper 维护 tick 内 attemptedKinds 集合，每 kind 每 tick 至多一次 attempt。服务点 = preflight 之后**无条件**对 carried-over 的未确认轮（persisted activeDelivery）各跑一次 helper；
3. **终局处理开新轮的同 tick 首发路径**（R8#1）：终局逻辑（首开 episode / interval 重报 / 首次 switch-failure / 开恢复轮 / 弃恢复续投阻塞）创建新 activeDelivery 时——先 persist，再查 attemptedKinds：该 kind 本 tick 未尝试 → **立即调同一 helper 首发（发现 tick 内即发 a0，绝不延到下一 poll 的 10-20min）**；已尝试（本 tick 早些时候服务过该 kind 的旧轮）→ 只 persist，下一 tick 服务点续投；
4. 终局处理对「本 tick 已尝试或仍 pending」的 kind **绝不绕过 helper 直发、绝不推进其 round**——它只更新条件观察（episode 保持 open / 记录复发）；
5. **开新轮的唯一入口**：前一轮已确认 且 interval/cap 允许；或显式迁移（首开 episode、进入恢复 recoveryRound+1、弃恢复后续投阻塞 blockedRound+1）——每个新轮都开新 activeDelivery 并走第 3 条首发路径；
6a. **attempt gate 键控例外（R11#4）**：`account_identity_mismatch` 是唯一多实例 episode kind——其 gate 按 kind+label 键控 + 每 tick 全局上限 2 + `identityAlertCursor` round-robin（§3.6.5）；其余 kind 仍按 kind 单键。
7. **同 tick 跨 kind 迁移显式定义**（R8#1）：blocked→recovered——即使 blocked 旧轮本 tick 已被服务（已尝试），恢复轮是另一 kind（quota_blocked_recovered），persist 后该 kind 未尝试即同 tick 首发；recovered→blocked（弃恢复续投）同理——recovered 已尝试不妨碍 blocked 新轮（blockedRound+1）同 tick 首发。attemptedKinds 按 kind 隔离，同一 kind 单 tick 绝不两发。

**签名轮次不变式（Codex R5#1 + R6#1，按 kind 各自成立；R8#2 措辞收敛到 canonical 形态）**：**任何开新投递轮（新 activeDelivery，attempts 从 0 起）的迁移——含「恢复被弃后续投阻塞告警」——必须推进该 kind 自己的单调轮次计数**；claims 的 event_id 永久，attempts 归零不换轮次段就会撞旧 claim 变 duplicate。为此阻塞投递用**独立于确认数的 `blockedRound`**（开场、每个升级轮、每次弃恢复后续投都 +1；`alertCount` 只做确认计数/上限，不进签名——R6#1 场景：r0-a0 未确认 → 转恢复 → 恢复未确认 → 阻塞复发续投，若签名用 alertCount 仍是 r0 → 永久 duplicate）。规范形态：`quota-no-target-<scope>-<startedAt>-r<blockedRound>-a<attempts>`；`quota-blocked-recovered-<startedAt>-r<recoveryRound>-a<attempts>`（每次进入恢复尝试——含弃后再恢复——`recoveryRound+1`）；switch-failure 见 §3.2b。

| open（activeDelivery 非 null） | **任意 tick**（含观察性 blind/backoff/rate_limited/error——Codex R5#3+R7#1） | **服务点**（preflight 后无条件）经 helper 按 burst/interval 规则续投该未确认轮——每 kind 每 tick 至多一次；之后的终局处理对该 kind 不再发不推进 round | 投递结果见下 |
| open | **scope 变化**（5h→both/weekly 等） | 关旧（发 recovered? 否——直接滚动）+ **开新 episode**（新 startedAt） | close+open（Codex R1#3） |
| open | 切换成功（正常或降落）或 scope==null（窗口自愈） | 丢弃未确认的 blocked activeDelivery（若有）、`recoveryRound+1`、persist `activeDelivery{kind:"recovered",round:recoveryRound,attempts:0}` → 经 helper 同 tick 首发 `quota_blocked_recovered`（blocked 本 tick 已尝试不影响——跨 kind，R8#1/#2） | 收尾见下 |
| any | state 保守恢复（corrupt/generation_advanced） | episode 清 null | 宁多报不静音 |

**送达回执规则**（核心——`duplicate` 不是送达证明；attempts/lastAttemptAt 均存于当前轮的 `activeDelivery`——R7#1）：
- 每次投递尝试（无论结果）先写 `activeDelivery.lastAttemptAt = now`（Codex R2#2：attempts 超阈值后的节流时钟锚）。
- 只有 `DeliveryReport.primary ∈ {sent, queued_transient}` 才算「本轮已确认」→ `activeDelivery=null` + 更新 `lastConfirmedAlertAt`、`alertCount+1`。
- `duplicate`/`dead_lettered`/`config_error`/`process_error`/`invalid_result` → **不确认**；`activeDelivery.attempts+1`，下一 tick 服务点用 `-a<attempts>` 新签名重试（新 event_id 绕过 claims 既有 claim）；attempts 1–5 可逐 tick 重试，**第 6 次起须距 `lastAttemptAt` ≥ episodeRealertMinutes**（防 config_error 无限重试刷 deadletter）。接受「宁可重复告警不可静默」。
- 恢复收尾同规则：`quota_blocked_recovered` 确认送达才清 episode；未确认 → `activeDelivery{kind:"recovered"}` 持久化，下一 tick 服务点重试；episode 期间若阻塞复发（again ranked=[]）且恢复轮未确认 → 丢弃恢复 activeDelivery、按 blockedRound+1 续投阻塞告警（阻塞根本没结束——R6#1）。
- **attempts 计数单调不封顶**（Codex R3#5）：5 只是「逐 tick 重试」的 burst 阈值；第 6 次起受 interval 节流但计数继续单调递增——`-a6`、`-a7`… 签名各自唯一，绝不复用 `-a5` 撞 claims duplicate。轮转（开新 activeDelivery）时 attempts 从 0 起、round 段已推进。
- 持久化顺序：**先 persist 迁移后的 state，再尝试投递，投递结果再 persist**——crash 窗口最多多发一条，绝不漏发。
- cooldown（minSwitchInterval 内触发）不开 episode，只写日志行。

**3.2b `account_switch_failed` 的失败 episode**（Codex R3#3 + R4#2——真 episode，非一次性投递记录；R8#2 形态收敛到 canonical activeDelivery 模型）：切换失败（正常或降落路径的 `failed`）→ 开 `pendingSwitchFailure{reasonCode, degraded, startedAt, lastConfirmedAlertAt, alertCount, activeDelivery{round, attempts, lastAttemptAt} | null}`（key = reasonCode+degraded；与文件表定义一致）→ persist activeDelivery 后经唯一 helper **同 tick 首发** `account_switch_failed`（R8#1；签名 `account-switch-failed-<reasonCode>-<degraded>-<startedAt>-r<round>-a<attempts>`——开轮时 `round`==当时的 alertCount，替换现日级签名；轮次不变式同 §3.2——开新轮 attempts 从 0 起必伴随 `-r` 段推进，第二/第三轮的首个 attempt 绝不 duplicate）。规则与 §3.2 同构：
- **确认送达后 episode 保留**（`activeDelivery=null`、`alertCount+1`——R8#2）；同一失败在后续 poll 持续发生 → 距 `lastConfirmedAlertAt` ≥ episodeRealertMinutes 才重报（开新轮 = 新 activeDelivery，round 随 alertCount 已推进），`alertCount` 上限 10——绝不每 poll 一条 severe。
- **未确认的告警不因观察性早退丢失且主动续投**（R4#2 + R5#3）：blind/backoff/rate_limited/error/no_target 等 tick 都不清 episode（它们不证明执行面恢复），且未确认轮在 preflight 后的统一投递服务点按 burst/interval 规则**继续重投**；已确认的 episode 则需要下一次匹配的失败观察才进入间隔重报。
- `reasonCode` 或 `degraded` 变化 = 关旧开新（新 startedAt）。
- **清除只认三种恢复信号**：(a) 切换成功（含降落成功）；(b) 前置事务判定外部账号切换（保守迁移统一清）；(c) 本 poll `triggerScope==null`（切换需求消失，episode 失去意义；下次再触发再失败 = 新 episode 新告警，语义正确）。
kind 不变、绝不折进 no_target 语义。

### 3.3 active-sync 与 daemon 对账（P4，单锁事务——Codex R1#2 + R2#1/#6）

- 唯一实现 `account-store.ts::syncActiveAccountInStore`（caller 持锁、strict 读、corrupt/missing 不写、name 必须精确匹配恰一条 accounts 记录否则 typed 拒绝、只动 activeAccount+generation）。两个调用者：guard CLI `active-sync`（bash 手动模式 post-commit，`use`/`next` 共享路径）与 daemon runtime 对账。
- **对账 = pollOnce 开场的前置事务**（Codex R3#1，先于 `runOpenReviveEpoch` 与 backoff 判断）：runtime 提供 `reconcileActive()`（自取一次 `withAccountsLock`：marker 读 → strict store 读 → 合法不一致 → sync → **每个合法结局含 noop 都返回权威 generation**）。**保守迁移的触发条件 = 返回的 generation > `state.observedGeneration`（不只 sync 真写时——R4#1：外部切换若落在 runtime 首读与 preflight 之间，marker==store 已一致、sync=noop，但 generation 已前进，同样是外部账号切换事实）**。迁移内容与 `generation_advanced` 保守恢复同款：切换 cooldown 重启、`reviveEpoch` 关闭（stale revive 授权绝无机会先跑）、`blockedEpisode`/`pendingSwitchFailure`/`identityMismatchEpisodes` 清 null（R9#2——否则无条件早跑的服务点可能给上一个 active 账号重发身份告警）、`observedGeneration=新 generation`，并**立即 persist**——之后的 backoff 早退、blind、限流、error 全部路径带的都是对账后状态（T-11 覆盖）。事务内单锁段消除「手动 A→C 插队后旧快照覆写 C」竞态；invalid_store/missing_account/invalid_name → typed 跳过不写。
- `readSnapshot` 回到纯读职责（现状不变）；`refreshNewActive` 无需感知（前置事务已持久化）。
- generation 自增使在途 CAS 观察失效——方向安全（丢观察 > 错观察）。

### 3.4 wake 协议（P3，能力发布——Codex R1#1）

- **能力发布**：daemon `main()` 先装 SIGUSR1 handler，再写 pidfile（record 含 `wakeProtocol: 1`）；**关停顺序反向对称：先 release pidfile（撤能力）再移 handler**（Codex R2#5——能力生命周期严格包含于 handler 生命周期，Bridge 绝无窗口对已无 handler 的进程发默认致死的 SIGUSR1）；pidfile 获取失败也先移 handler 再抛。老 daemon 的 pidfile 无 `wakeProtocol` 字段。
- **Bridge 侧**：`wakeProtocol >= 1` 缺席 → **noop**（绝不对无 handler 的旧 daemon 发 SIGUSR1——默认动作是杀进程）；三元组（pid/uid/processStartTime）校验不过 → noop；`FLYWHEEL_QUOTA_WAKE=0` → 整体关闭；60s 节流。
- 语义 = 「打断 sleep 立即 poll」；poll 进行中信号丢弃（wakeWaiter null），定时轮询兜底；**不携带数据**。
- 混版本矩阵（全部安全）：新 Bridge+旧 daemon = noop；旧 Bridge+新 daemon = 无信号（现状延迟）；daemon 回滚 = pidfile 无能力字段 → Bridge 自动停发。触发条件：alert kind `usage_limit` 或 payload.metadata.accountLimit 存在。

**3.6.5 mismatch 事实的传输通道与持久告警 owner（R9#2 + R10#2 收窄）**：state 加 optional `identityMismatchEpisodes: { [label]: { checkpoint, expectedKey, actualDigest, startedAt, lastConfirmedAlertAt, alertCount, round, activeDelivery{round, attempts, lastAttemptAt} \| null } } \| null`（**按 label 键控**，上限=池大小；fingerprint=(checkpoint,expectedKey,actualDigest) 变化 = close+open 新 startedAt）。canonical episode 语义（同 §3.2：helper 首发、轮次不变式 `-r<round>-a<attempts>`、loader round 校验、间隔重报、alertCount 上限）；签名 `account-identity-mismatch-<label>-<startedAt>-r<round>-a<attempts>`。**事实通道按调用形态分三类（R10#2——现实契约 `applyProfile:(name)=>Promise<void>` 无结构回传、capture_back 是 best-effort 可伴随 exit 0、capture_profile 根本不经 executor）**：
- **daemon 自察面**（候选验证、active 漂移）：daemon 直接观察 → 开/服务 episode。
- **daemon 委托 apply 面**：bash 子进程把核验事实写成**非密结构化 `ApplyProfileReport`**（JSON 单行，落 `FLYWHEEL_APPLY_REPORT_FILE` 指定的临时文件——不经 stdout 避免与既有 warning 文本混流；不含 token，只含 label/checkpoint/verdict/digest）；`claude-profile-cli.ts` 读取并把 report **附着在成功与每种 typed error 上**；executor 把事实带进每个 `SwitchResult` 结局（**含成功切换**——成功 apply 里的 capture_back mismatch 不能丢）；daemon 在锁释放后统一开/服务 episode——**绝不在持锁状态下投递 Discord**（R9#2/#4）。

**切后 byte 读回失败 ≠ 身份 mismatch（R10#2）**：payload 身份在预写闸已验过、读回失败没有 observed identity/actualDigest——归类为**切换完整性事实（switch-integrity）**：exit 36/37 走 §3.2b 的 `account_switch_failed` episode 语义（reasonCode=`keychain_readback_mismatch`/`identity_rollback_failed`），绝不伪造 identity fingerprint 进 identityMismatchEpisodes。恢复清 latch：同 label 同 checkpoint 观察到 confirmed match、或 audit reconcile、或 §3.3 前置事务的外部切换保守迁移（**identityMismatchEpisodes 与 blockedEpisode/pendingSwitchFailure 同清**——R9#2）。**多 label 公平调度（R11#4——防首 label 饿死后续）**：`account_identity_mismatch` 的 attempt gate 按 **kind+label** 键控（identity 是唯一多实例 episode kind，§3.2 契约的显式例外）+ **每 tick 全局上限 2 条 identity attempt** + state 持久 `identityAlertCursor`（round-robin 起点 = 上次已服务 label 之后）——永久未确认的 label 1 不能每 tick 独占 attempt；T-20 断言 label 2/3 在有界 tick 内被尝试。
