FLY-1498 门与派发模型

一句话总结

评审义务跟着「这次到底改了什么」走、在节点完成那一刻一次结清;ship 只剩三条对谁都一样的检查;派发器只看图,不认识"三段式"。
你的原话,逐条落成机制:
① "codex code review is a hard gate for implement session, not really a ship gate" → 代码评审=产出代码的那个节点的完成条件,ship 不再问。
② "the ship gate need to be very generic" → ship 前置恰三条,与内容、流程形状都无关。
③ "not design this for a specific scenario" → 引擎代码里 grep 不到 design/implement/qa 这些词(验收项)。
④ "we do not necessarily need codex code review for qa code" → 只改测试的改动,免跨族代码评审。

核心流程:一个节点怎么"完成"

1 · 干活节点(比如 QA)在自己的工作区提交改动
→
2 · 系统看 diff内核自己算这次改了什么(不信任汇报),按路径分三档:产品代码 / 测试 / 文档,混合取最严
→
3 · 按内容欠账产品代码→欠一次跨族代码评审;只有测试或文档→不欠(你已裁定)
→
4 · 一次结清完成时一笔账内同时校验:欠的评审证据齐 + 节点自declared的交付物(如 QA 的 verdict)齐 → 状态、证据、账本同一事务落定
ship = 动作,不是节点只查三条:① founder 批准且绑当前 head ② 图上所有节点都成功收尾 ③ head 没漂(用 GitHub 的 expected-sha 在世界边界原子核对)
→
ship 永不重问评审因为每段改动都在产出它的节点处被结清过——三条通过=构造上保证全覆盖
CI 不建成第四条 ship 门。v2 merge lane 只有在 target branch required checks 已启用、merge actor 是不能绕规则的 non-admin 身份时才激活;否则继续走 v1 lane。激活后红 CI 由 GitHub 原子拒绝。

作者集穷尽所有评审家族typed review_family_exhausted event + mailboxproduct code 保持未完成,直到认证的第三方 family 审同一 subject;披露/同族审/founder 批准都不能冒充证据

关键取舍与被否掉的方案

  • 按内容分档,不按节点名 —— 被否:v1 的做法(按 session 类型一刀切),就是它把 FLY-1497 的 QA 会话(只加了测试)挡在 ship 外。
  • 评审绑「被审 diff+作者集」的摘要,不绑裸 head —— 被否:只绑 head(同一 head 上换了范围/换了写者的旧评审会被错误复用)。
  • 作者集穷尽时选第三方 family、fail closed —— 被否:split review(没有逐贡献权威,也证明不了最终 exact subject)和「披露即放行」(会破坏 product-code 跨族合同)。
  • 返工=同一节点开新一轮,不在图上画循环边 —— 被否:FLY-1135 的四要素循环边;也不设最大循环次数(场景明说不限,卡死由超时告警兜)。
  • 系统自己算 diff,不信任何一方汇报 —— 被否:执行者自报清单(等于自我授权,可绕评审)。
  • ship 三条外零附加检查 —— 被否:在 ship 处"再确认一遍评审"(那正是要根治的病)。
供你砍的清单(设计里单列):测试评审档(未设)/文档评审档(未设)/循环上限(未设)/多工作区支持(首版不做)——都答不出"哪个场景需要",按你的反 over-reaction 规则默认不加。

诚实边界:这个设计不做什么

  • 分档看路径不看语义:藏在测试文件里的代码不经跨族评审(你已裁定;要收紧改一行映射表即可,不动引擎)。
  • 租约期间被别的进程偷偷写入,会记在租约持有者名下(单机可信环境接受;租约外的无主写入会被直接拦下)。
  • 首版每 issue 只支持一个工作区一个 PR;多工作区是显式的未来扩展,模型不用改。
  • agent 拿到的 merge credential 必须是不能绕 required checks 的 non-admin 身份;该结构探针不过就不启用 v2 merge lane。
  • history rewrite 让旧 span anchor 不再是 HEAD 祖先时会拒绝并重新 admission 新 worktree identity,不会把当前 HEAD 当新起点吞掉旧 diff。
  • 本单只定模型不写代码;v1 现行门照旧运转,接线在批次 3。

验收怎么证明它对

  • 通FLY-1497 重放:QA 节点只加测试 → 零评审义务,ship 三条全绿,全程没人再问"codex review record"。
  • 通纯 PRD 单(只有 .md)一路畅通到 ship。
  • 拒同族自审、评审后偷推 commit、绕节点写入、旧批准复用、并发打回/改图竞态——共 15 组拒绝矩阵逐项验证。
  • 拒Claude+Codex 都写过同一 product-code span 时,两族都不能自审;没有已认证第三方 family 就 typed fail closed。
  • 零特例:上面所有场景走同一条引擎代码路径;引擎里 grep 不到任何节点名。
