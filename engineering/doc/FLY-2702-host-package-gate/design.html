给同一台机器的全量测试设置共享名额，让等待看得见，让空位及时交给下一位。

等待时，看得到在等什么

每个任务的终端会显示：

等待第 3 位 / 前面 2 个 / 已等 45 秒
当前运行 2 / 2

入队、队位变化和轮到自己时立即更新，等待中每 10 秒刷新。共享账本记录是哪一个任务、哪个工作目录、何时入队和何时开始。不会因为等待太久就判测试失败。

一本主机账本，记录三件事

记录里面有什么用来做什么
容量同一用户共用的 N 个名额所有工作目录共用上限
排队请求唯一编号、顺序号、进程、目录、入队时间健康任务先到先服务，显示准确队位
运行记录运行进程组、开始与结束时间、测试结果确认工作全结束后再释放

SQLite 是单文件事务数据库，它让“检查空位”和“占用空位”一次完成，避免两个任务抢到同一个名额。另导出可读文件供人查看，实际调度和巡检都读取原账本。

进程退出了，也不能放错人进去

监督进程负责等待和记录。测试进程组是一组一起执行、一起收尾的进程。

开始前先登记运行组，再允许它运行。监督进程意外退出时：同一沙箱内的收尾进程通过生命线断开得知故障，结束本次测试组。测试还在跑就保留名额；确认整组已消失就自动回收。十秒没更新会触发检查。已运行的任务不会被夺走名额；尚未运行且冻结的队首会暂时挂起，恢复后重新排队。

进程身份看不清时，会显示原因并保留名额；不会杀掉身份不明的进程。正常前一个结束后，下一个必须在 5 秒内启动。

排队不是停滞，其他故障仍会报

巡检会同时核验任务身份、工作目录、队列状态和进程是否活着。核验通过的排队任务显示“正在等待”，不会收到因停滞而发出的催促。

旧任务遗留的记录、复用的进程号码和失效的排队信息不能替新任务挡告警。终端已死、额度耗尽、交互菜单阻塞等其他问题仍正常呈现。开始测试之后，也不再享受排队等待的豁免。

为什么选这个方案

选择取舍
主机共享事务账本公平取号，崩溃后有记录可查；需实现进程核验
每个工作目录各自加锁简单，但挡不住整机同时跑很多份；不选
由后台服务统一派测试会让本地交卷依赖后台服务可用性；本轮不选

N 暂以 2 为候选初值；最终并发数要实测 2 和 3 后再决定，不能把保守初值当成性能结论。

怎样证明真的变快

先把同样六份工作分别单独跑，得到独立基线；再模拟它们按 N 个并行位置运行所需的理论时间。六份同时交卷的实际总耗时，必须不超过理论时间的 1.2 倍。

每份列出排队、运行和总等待时间，并保存前后进程采样。第 N+1 份必须没有启动构建或测试，前任释放后 5 秒内启动。

RPC 是测试进程回传结果的内部通信。验收还要确认没有这类超时造成的假红，并保留原有规则，保证真正的测试错误不能变成通过。

何时生效，怎样回退

本次覆盖同一台机器、同一操作系统用户下的全部工作目录。CI 是远端自动构建测试环境，它继续走原来的路径。

先部署能识别排队的巡检，再打开排队开关。提供主机统一关闭与单次关闭开关；正常回退先停止新交卷并排空队列，保留账本用于诊断。旧版本任务不会自动受到新规则限制，切换前要逐一核对。
