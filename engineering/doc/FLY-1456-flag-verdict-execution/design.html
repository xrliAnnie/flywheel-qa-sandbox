③ 关键取舍(和被否掉的做法)

  • 只删「开关壳」,不拆「死通道机器」。13 个死开关背后那条废弃通道的机器代码(几千行)不在本单拆——拆它是另一个量级的手术(类似 FLY-1261),留 follow-up 单独立项。否掉的做法:顺手拆通道 → 爆炸半径大、每个 PR 不再小而可审。
  • 焊死 quota 开关 = 连救火脚本一起改成实话。Codex 评审抓到:旧救火脚本的「停用」模式会谎称「已恢复旧的自动切号兜底」——焊死后那个兜底永远不存在了。方案:脚本运行时明白打印「无自动切号兜底」,回滚只有两条有序路径(继续用守护进程 / 有序换回旧执行者),每条都验证「恰好一个执行者在场」。否掉的做法:只删两行配置写入、提示语不动 → 静默语义漂移,Annie 红线。Tadashi 已批,附 2 条硬要求已折入。
  • 5 个 PR 串行,不并行、不合并成一个大 PR。都改同一张登记表,串行免冲突(FLY-1243 撞过);小 PR 隔离审是本单 issue 的明文要求。
  • 台账取数钉死在裁决 commit,不用改到一半的活代码取数。否则边删边数会漏账。

④ 诚实边界 — 这个方案不做什么

  • 🛑 不碰 RESERVED 两个急停杆(FLY-1436),每个 PR 有自动检查作证。
  • 不做开关动态化(那是 FLY-1405,等 FLY-1150 的存储层;本单只把幸存者名单标记交接过去)。
  • 不拆死通道机器、不动更早批次(FLY-1136 基线前)的 76 个开关。
  • cmux_linked_view 冻结在 0、不删,它的活线索归 FLY-1446 处理。
  • 40 个跑默认值的开关:只担保「配置里没写」+「默认值是多少」,没有逐个验证运行时行为(与 FLY-1413 的口径一致,不冒充)。
  • 生产配置文件里 2 行旧开关的清理是上线时的运维步骤(体检工具会提示),不在代码 diff 里。
唯一的行为变化点在 PR-4:焊死后不能再用改配置的方式退回旧的切号路径——这不是副作用,这正是裁决本身(「关=倒退,不能关」)。生产现在就是开着的,上线当天行为零变化。
