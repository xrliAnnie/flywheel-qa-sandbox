# FLY-2280 — restart-services 跨版本 cutover ownership 收口

**Status**: ✅ Implementation complete; needs review
**PR**: pending creation from this milestone commit
**Date**: 2026-09-02

`restart-services.sh` 现在在 FLY-2264 legacy cutover receipt 存在时复用 receipt 中的稳定 reason，同时把它作为 `expectedLegacyReason` 交给 lease-aware Bridge 原子接管；phase-1 不再把 legacy reason 改写成带 PID/时间戳的 wave identifier。已经被新 Bridge 接管的 row 通过 0600 lease handoff 延续到 host transaction，旧 Bridge/unreachable Bridge 仍保持既有 best-effort 引导路径，HTTP 拒绝和不确定 transport failure 则在停 Bridge 前 fail closed。

## 交付内容

- 新增 `cutover_legacy_pause_reason`，只接受非空、无首尾空白、无 CR/LF、最长 200 字符的 receipt reason；无效 receipt 在任何 Bridge 请求前拒绝。
- fresh cutover phase-1 请求同时发送稳定的 `reason` 与 `expectedLegacyReason`；成功接管后写入 0600 handoff，并禁止本轮自动 resume。
- phase-1 仅把 curl rc=7 视为“旧 Bridge 未收到请求”的 best-effort 情况；HTTP error 或不确定 transport failure 在 destructive boundary 前拒绝。
- phase-1 若收到 `reacquiredAfterLapse=true`，先原子写回 owning cutover receipt，再写 handoff；lapse evidence 无法持久化时 fail closed。
- stateful fake Bridge 覆盖旧/新 Bridge、NULL owner/owned row、reason mismatch、回滚/重开票、lapse 与持久化故障；目标 suite 已加入 CI shell shard。
- 更新 FLY-2264 cutover runbook 的稳定 reason 约束与拒绝后的 inspect/recovery 路径；未修改 package runtime、数据库、部署/回滚主体、`CLAUDE.md`，也未执行真实 restart/deploy。
