## 交付

- payload endpoint 与客户端统一接受规范的强/弱 ETag，严格拒绝非 32/64 位实体标签；
  handler 把非法 `baseEtag` 明确映射为 400。beta 提交与 cleanup 因此不再把
  Cloudflare 弱 ETag 原样送进 `If-Match`。
- 新增零构建的 `payload-promote-commit.yml`，仅在 `environment: release` 中持有客户
  release token，按 `commit` / `abandon` / `withdraw` 执行。prepare 继续只上传 immutable
  staging key 并回读校验；commit 在窗口后重新回读，再用 manifest ETag 做 CAS 切换。
- onboard shell 发布改为 GitHub OIDC trusted publishing：只发布本轮 `npm pack` 产出的
  确切 tarball，版本解析唯一决定 `latest` / `next`，发布前后都从 npm registry 回读
  tarball bytes、sha256 与 dist-tag；相同字节重跑幂等，不同字节或标签 fail closed。
- beta reserve / dedup 在同次 CAS 中收敛其余 live beta operation；显式 abandon 与
  `--stale-days` 会先写 tombstone，payload cleanup 再按 retention 删除对象。cleanup
  继续复用同一 ETag 客户端，弱 ETag 下也能完成真实删除。
- release contract 以 2026-09-08 Amendment A1 固化 prepare / commit 分窗、客户与 beta
  凭据边界、staging retention，以及 schema 与 runtime validator 的 differential corpus。
  runbook、源码注释和 CI workflow 结构守卫已同步。

## 边界与后续验收

本实现没有执行真实 npm publish、客户 manifest commit/withdraw、生产 R2 上传或删除，
没有操作任何 token/trusted-publisher 配置，没有 dispatch QA、merge、deploy 或重启服务。
Cloudflare `release` environment token、npm trusted publisher 的 allowed action，以及客户
release token/真实 clean environment 仍须在独立受控阶段配置并验证。只有后续 QA 在
founder go 下完成 prepare → readback → commit，并与 B2 用真实 npm/R2 做联合 E2E，才可
主张生产激活；本 PR 的 hermetic evidence 不等于该验收。
