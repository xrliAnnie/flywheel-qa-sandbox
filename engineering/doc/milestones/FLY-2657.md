Raya updater 现在同时处理三种已观测的旧壳状态。launchd 明确报告服务缺失时，账本 PID 已不存在或已被复用即可按“已自行退场”继续 prestop；quiesce 会持久 disable，以同一观测时刻补齐 stop 三个时间字段，并发一条 warning。主机重启后 launchd 若以新 PID 拉起真实旧壳，则以 launchd 当前 PID 和匹配已验证 plist `ProgramArguments` 的进程命令为准，继续走原有 disable/bootout 路径，并在 stop intent 中刷新实际被停的 PID/start；live label 对应外来命令时零副作用拒绝。生产交接又确认 brain 已 disabled 且服务缺失、账本仍记 dead pid 54811，而 voice 是 loaded、首个 `state = not running` 且无 pid；后者现在也按已退场处理，但仍执行幂等 disable + bootout，并在确认服务消失后补时间戳和 warning。任何其他 loaded/no-pid、unreadable、active 或 foreign shape 继续 fail-closed。

QA 返工补上了第四种边缘：launchd 服务与账本 owner 都已消失，但仍有未记账、argv 与旧 plist 完全一致的遗留进程存活。owners、quiesce 与 retired 三道闸现在都会先做全进程 census，只允许 launchd 当前且已验证的 PID；其他精确旧壳 argv 一律 fail-closed，且不写 `stopped_at_ms`、不 disable。夹具同时覆盖 dead recorded PID 与 `pid:null` 两种账本形状，并用真实 Node 子进程证明该进程仍活。

复审 R3 指出的 HIGH `retired-gate-depends-on-legacy-plist-node-path` 已收口：稳态 retired 闸从 `RAYA_CODE_DIR + app` 直接构造旧壳 CLI 身份，不再读取已退役 plist，也不再要求 plist 中带版本号的 Homebrew node keg 仍存在。旧 plist 已删除或 node 路径已被例行升级清理时，只要全进程 census 可读且无匹配旧壳、label 已 disabled、launchd 明确报告 service missing 就通过；匹配旧壳仍活、`ps` 失败或 launchctl 返回非 service-missing 错误都拒绝。prestop 的 plist、digest、cwd/env 与可执行文件授权校验没有放宽。

`raya-migration-init --resume-from-failed` 只在 public standard Lead `verify --stage live` 通过且既有 cursor 是安全私有普通文件时复用它，账本写 `cursor.status="preexisting"`。复用验证要求每个 canonical boundary channel 都存在且不落后，但允许 live cursor 继续持有 roundtable、动态 thread 等额外 channel；少一个 channel 或任一 channel 落后仍 fail-closed，且普通 seed 路径继续要求精确 key 集。init 的 legacy census 也接受 launchctl 成功且首个 `state = not running`、无 pid 的 loaded owner，记录为 `loaded:true, pid:null, start:null`；其他零 pid shape 仍拒绝。后续 P3/P4b/P6 保留 boundary digest，proof 仍明确记录 `writerStopped:false`。
