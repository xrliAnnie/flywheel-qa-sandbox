# FLY-2941 — 接管探针不再撞 Node 默认缓冲上限

**Status**: ⏳ Pending code review, exact-head CI, and QA
**PR**: #1367
**Date**: 2026-09-26

换体接管脏工作区时，完整缓存索引探针 `git ls-files -z --cached -v` 的输出已经随
Flywheel 仓库增长到约 1.1 MiB，超过 `defaultAsyncExecFile` 默认 1 MiB 缓冲区；探针因而
在风险判定前失败，替身体被拒绝启动。本单在 `WorktreeManager` 默认执行器边界设置具名、
有界的 64 MiB `maxBuffer`，覆盖 takeover 的 status、ls-files、diff 与 worktree-list 等
规模增长探针，不改变任何接管、脏内容或 ignored-content 判定语义。

回归测试用真实 Git，仅包装缓存索引探针产生超过 1 MiB 的输出：无修复时两例确定性报
`stdout maxBuffer length exceeded`；修复后既能完成普通脏工作区救援，也仍会对 hidden index
flag / ignored-content 风险 fail closed。相关闭包 36 个测试文件、536 条测试通过，9 条宿主
条件用例跳过；affected package 加依赖构建、targeted Biome、root lint 与 diff check 通过。
本实现节点未请求 full CI、未派发 QA、未合并或部署；真实 Flywheel 规模换体复现由独立 QA
按派单验收。
