## 已实现

写者每小时在共享内核锁内按 Lead 目录独立提交，所有 Git child 非交互且受 600 秒总持锁
上限约束；普通 `write-memory.sh` 同锁等待预算为 660 秒。普通写路径在 mutation 前验证
`.githooks`、四个 hook、两份 policy、gitleaks 8.30.1、canonical raw/resolved fetch/push URL、
`main` 分支及无在途 rebase；wrong push URL 或 `insteadOf` 返回专用 10，detached/
`rebase-merge`/`rebase-apply` 返回 6，均不改 HEAD/index/任一远端。post-commit Python 校验
真实执行，无 owner trailer 的提交返回 6且不触碰远端。远端领先时，全仓任意 staged 或
tracked-dirty 路径都在 rebase 前以 3 defer 并保留 index；纯 untracked Finder residue 仍忽略。

到达事实只来自 push 后新的 `git ls-remote origin refs/heads/main`：远端 SHA 必须等于本轮
冻结的本地 SHA 才有 `arrived=true`。push 返回 0 但远端不动是 exit 5；push 命令失败但
远端已到是 `arrived=true` + exit 7。独立 arrival 看者不读写者日志或布尔值；`gh api`
提交日期失败只把日期降级为 `undetermined`，不会伪报 `remote_unreachable`。失败与 signal
都会清理 private `run.*` 并释放状态锁。Discord 投递失败先持久化 `post_status=failed`，再
返回专用 10，使 launchd 能识别告警器自身失败；下一轮仍重试该 episode。scheduled writer
使用独立投递依赖预检，observer-only `gh/curl` 缺失不会阻断记忆送达。

远端仓模板含每日 `09:05 UTC` 的只读 GitHub Actions witness；报告只认
`schedule/main/completed/success/attempt==1` 的自然首跑。冻结记录 create-once，并以 D/D+1
两棵远端树证明当天 marker 从“不在”变为“在”。两个 launchd 单元与防复活退役工具已纳入
closed manifest；退役固定为 `disable → bootout → hard-link archive → identity-safe unlink`。
