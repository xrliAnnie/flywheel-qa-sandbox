# FLY-2903 — 已结束的 Codex 体真正关掉

**Status**: ⏳ Pending review, exact-head CI and QA
**PR**: #1343
**Date**: 2026-09-25

FLY-2893 普查发现，会话进入终态之后 Codex 执行体又烧了约 12.07 亿 token。根因有两个洞：Bridge 终态路径直接杀 daemon 进程组，进程内的 goal runtime 当成「中途崩溃」自动重启并 resume（FLY-2814）；收尸结果被丢弃，CommDB 行一终结就再没有兜底能看到这个执行体。本单两个洞一起堵。

1. **先停 owner 再收。** 所有权登记加「请停」通道。terminate、closeRunner、进程退役、close-tmux 先请进程内 runtime 自己停下（有界等待 drain），再走原有 reap。终态原因会拒绝之后的 claim；进程退役不拒，因为 FLY-2808 standby resume 用同一个 executionId 重新 claim。
2. **不复活。** runtime 每次 transport death 后先问注入的判断函数；已请停或退役已批准就拒绝重启，判断函数出错也算拒绝。拒绝会记日志，并写进 transport-death 取证快照。
3. **终态收尸账本 + 巡检。** 新表 `codex_terminal_close`，唯一写入模块，状态每变一次写一条审计事件。维护 tick 巡检近 48h 的终态 Codex 执行体，以及快照里仍有活 codex 进程的任何终态执行体。两次采样都无进程、token 不涨，才判 closed。身份能证实的活 daemon 只用既有 reap 收掉，证不出身份的一律只告警。终态后 token 按 FLY-2893 口径增量读取。
4. **可见性。** 新告警 kind `codex_terminal_body_alive`，额度页加「终态 Codex 体仍在用额度」横幅，kill switch `codex_terminal_reap_enabled` 只控制巡检的请停和收掉。
