# FLY-2324 — Bridge 陈年投递与 divergence 风暴收敛

**Status**: Implementation complete; R3 findings and CI assertion fixed, pending requeued R4 exact-head review
**Date**: 2026-09-04

Bridge 启动与 watch 现在会先判定投递是否仍可达。绑定 active/held run 的投递继续受保护；recipient
进入 wake-terminal 状态，或无 run 且超过 7 天的陈年 source，会幂等收口为 `legacy_unreachable`。
经授权的 Linear 终态也不能绕过 7 天 age gate；缺失 recipient 与
`approved`/`rejected`/`deferred`/`shelved` 等非 wake-terminal 状态在 7 天内不会被提前关闭。已有 episode
与 severe 告警时间戳保持不变，因此同一存量重放不会再次铸造 episode 或重发告警。

run 的 issue UUID、identifier 与 entry root alias 被持久化到 `workflow_run_issue_alias`，不再依赖可能被
清理的 session 行；一次性 migration marker 防止每次启动重复 backfill，三条 run 创建路径都在创建事务
捕获 alias。alias 只供本 guard 的专用查询，不改变 patrol/resume/dispatch 的共享 issue identity。已收口
source 被 active/held run 重新认领时创建下一 generation，即使原 recipient 已终结也能恢复 FLY-2278 的
undeliverable/reroute 路径。新 generation 的 minted/stage clocks 以恢复时刻为下界，避免第一轮 watch
立刻重发陈年告警；`superseded_by_attempt_id` 保留完整历史链。

Linear 终态抑制只接受授权终态跃迁，首次看到 Done/Canceled 不会被误当作关闭授权。watch 若遇到收口
竞态失败会继续正常观测，不会静默跳过。

divergence 候选查询只返回 active/held run，terminated/completed run 不再进入每 tick 的提交路径。真实
event UID conflict 会以确定性的 conflict event 和 lifecycle revision checkpoint 在同一事务中一次性记账；
即使 fallback UID 也冲突，checkpoint 仍有界前移。普通 stale race 不再输出误导日志。

R3 修复的 TDD 与回归证据：FLY-2324 聚焦 27/27；单包邻接套件 111 passed、1 skipped；
`flywheel-teamlead` typecheck 与 build 均通过。此前全包覆盖两次均为 818/818 files、10,747 passed、6 skipped，
但 Vitest 在全部断言后两次都因 runner `onTaskUpdate` RPC timeout 返回 1；已用 clean-exit 的聚焦、邻接、
retention 套件及隔离复验排除改动回归。R3 修复复验使用 `VITEST_MAX_THREADS=1`。首轮 PR CI 进一步发现
FLY-2248 的一个旧断言仍期待已收口 generation 吸收后续 source clocks；将预期修正为 `advanced: 0` 后，
该文件在单线程隔离复验中 7/7 通过，和 settled generation 时钟不可变的 R3 约束一致。

本节点没有重启 Bridge、修改生产数据库、dispatch QA、merge 或 deploy。部署后对生产存量的“零新
