# FLY-2279 — 窗口脚本真机竞态修复

**Status**: ⏳ Implementation complete; pending independent QA
**PR**: #1041
**Date**: 2026-09-02

本单修复 FLY-2264 破坏性窗口在真机确认的竞态与 operator seat 冲突。supervisor bootout 现在接受
updater 为 loaded+enabled 或已安全卸载两种状态；按 FLY-1959 的现行 trigger policy，只要求唯一仍在
生产消费的 `self-ship-urgent.d` 不存在或为真实空目录。退役的 pending route 在 active tracked tree 中
零引用；emergency restore 只检查 updater state，不因 queued ticket 阻断，也不读取或消费 ticket。

全部 19 个 bootout request 会先发完，再让所有仍 loaded 的 label 共用一个 90 秒 convergence deadline，
逐轮检查直到全体 absent；unknown state 与 deadline exhaustion 都具名 fail closed。该共享 deadline 位于
`run-step --timeout 120` 的整体脚本预算内，并有两个永不退出 label 的 hermetic clock stub 证明不会退回
逐 label 重置计时。

verifier 统一把 `ps -o lstart=` 的两端 whitespace 去除并保留内部空白，cmux owner、heartbeat、sidebar、
owner reread 与 final identity 的每个失败边界都会写入稳定 artifact error。Lead 代表 child 改从完整
`ps -axo pid=,ppid=` snapshot 选择并单 PID 重证；shared inventory 与 host preflight 都使用 macOS
ancestor-inclusive `pgrep -a -x tmux`，因此从 tmux/Lead seat 发起时不再漏掉调用链祖先。

cutover runbook 改为只允许普通 Terminal.app operator shell，要求 founder 先退出自己创建的 tmux
session；本轮使用新的 `FLY-2264-window-FLY-2279` 私有目录并保全旧 window evidence。updater 必须在 ship
前以不依赖新代码的固定 urgent-queue/launchctl 检查完成 park，直到唯一 restart ticket 前才 bootstrap
exact plist。§5.5 supervisor restore 与 §6 updater/ticket 序列都包装在 `bash -euo pipefail` 中，守卫失败
会阻断后续 mutation；stop-old 的 PID/start/image/socket/coalition 重证与 Atlas 唯一豁免没有放宽。
