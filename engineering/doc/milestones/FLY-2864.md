1. **删掉 token 状态列。** Codex 表删掉这一列，Claude 表本来就没有。列数按表各自计算（Claude 7 列，Codex 6 列），colspan 跟着列数走。底层数据字段保留。
2. **Claude 充值卡读出真数据。** 明细探针原来就会调 usage 接口，现在改成 `usage?cedar_ember=1&skip_spend=1`，并用本机实际装的 Claude Code 版本声明为 CLI 客户端，读出额度重置卡。每张卡一行，写各自的到期日。只有服务端明确给出卡列表或明确说 `no_grant` 时才算张数；其余门槛一律写「读不到（原因）」。不拿余额顶替，也不调用领卡的 POST 接口。旧的「明细未提供」来自美元预付额度，那不是卡，已不再显示。
3. **business 档位读成 20x。** 病因是档位一直读 `.credentials.json` 里登录时写下的缓存，升档后没更新。现在快照优先用明细探针实时读到的 profile `rate_limit_tier`，页面和 `/api/capacity` 都是 20x。没有写死任何值，「待你确认」字样已去掉。档位仍然不参与分组、排序或任何自动决策。
4. **新增「下次扣费日」列，替代「订阅到期」。**
   - Codex：用 `node:https` 只读 `chatgpt.com/backend-api/subscriptions`（Node 自带的 fetch 会被 Cloudflare 挑战页拦下），显示 PT 日期加星期，例如「10/22 周四」。已取消的写「已取消 · MM/DD 周X 到期」，读不到的写「读不到（原因）」。日期已经过去的一律写「读不到（读数已过期）」。
   - Claude：OAuth 查不到续费日，查过 7 个来源都没有；founder 选了方案 A，所以写「读不到（Anthropic 接口不给）」。已取消的号写「已取消」。
