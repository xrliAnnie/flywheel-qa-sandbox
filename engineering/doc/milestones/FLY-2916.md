# FLY-2916 — QA Testing 分区测试 thread 空闲 1 小时自动归档

**Status**: ⏳ Pending code review, exact-head CI, and QA
**PR**: #1349
**Date**: 2026-09-26

Bridge 的空闲 thread 清扫按「频道组 → bot token 的 env 名」拆成两组，各自一个实例、一个调度器：
生产组（roundtable / unified alert）仍用 claw-infra-bot、同样的频道、日志前缀与告警文案；QA Testing 组用
`FLYWHEEL_QA_IDLE_THREAD_SWEEP_BOT_TOKEN_ENV` 指向的 bot（不设即关闭，代码里不写死任何 Lead），
每轮从同 guild 的 `test-slots.json` 分类发现频道，新旧 thread 一律按「最后一条消息后满 60 分钟」归档，
只写 `PATCH {archived: true}`，不删除、不改 thread 自带时长；有新消息时由 Discord 自动解归档，夹具可复用。
QA 的时钟只看最后一条消息：在 Discord 界面手动解归档但不发消息的 QA thread，会在下一轮被再次归档（预期行为）。

QA@1 发现 infra-bot 在 QA 频道没有 VIEW_CHANNEL（真跑 55 个 thread 全部 403）后返工：
父频道读取被拒时本轮整频道跳过、只探测一次；被拒的读取计入每轮 25 次上限（两组都适用，生产组唯一的行为变化，
只在权限被拒时生效）；QA 组告警用独立 reason `qa_idle_thread_sweep_denied`，按频道每 24 小时最多一次，
未投递（被通知器去抖）的会在后续轮次重试，不会吞掉生产组告警；两组预算互相独立。
生产配置需在合入后加一行 `FLYWHEEL_QA_IDLE_THREAD_SWEEP_BOT_TOKEN_ENV=CASS_BOT_TOKEN`（由 Lead 在班车前加）。

定向测试、受影响构建、lint 与依赖方类型检查通过；真 Discord 验收与冻结头全量 CI 归 QA。
