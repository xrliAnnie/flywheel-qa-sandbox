# FLY-2141 — Epic 残余扫描与空位拉活

**Status**: ✅ Implementation complete; code review approved; pending independent QA

巡检钟现在会在同一次 pass 中生成 Epic 残余事实，并把「还剩什么」三行放在容量之后、
名册声明之前。事实复用 FLY-2140 的 active scope 与 founder 已裁定的 `ready.v1`，列出范围内
未完成、可开始、等前置、账面在跑、未命中 Lead label，以及最多五张归本 Lead 的可开始子单；
它是判断输入，不会自动派单、排队或改写既有 admission。

同项目的多个 Lead 在一轮内共享一次 materialization，再按既有 Lead 归属规则切片。名册为空但
仍有归属残余时，Bridge 会铸一封 `trigger:"scope"` 的 tick；成功观测且归属残余为零时正常静默，
查询、schema 或 session 账本不可读则走独立的 allowlist unavailable token。binding 或 API key
缺席保持旧 payload 字节不变，并只在 Bridge 启动时输出受限告警。

共享 materializer 保留手动 route 的 fail-loud 语义，巡检回执写失败则 fail-soft；500-item 守卫、
两类时间戳、payload 结构断言和渲染 fail-closed 均有回归。Lead 规则补充了如何联合读取容量与
Epic 残余、如何通过既有 `POST /api/runs/start` 拉一件，以及 `general` 归属项的复核边界。
没有新增 flag、timer、配置键、路由、表、频率层级或告警通道，也没有修改 `projects.json`。
