# FLY-2302 — 回滚死体 CommDB 注册残留收敛

**Status**: ⏳ Implementation complete; code review R8 approved
**PR**: [#1061](https://github.com/xrliAnnie/flywheel/pull/1061)
**Date**: 2026-09-03

## 交付

- workflow engine 为「旧 execution 已终态、探针证实死亡、且已铸替换体」建立的 durable dead-watch 现在也负责
  收敛旧体的 CommDB session 注册。它只删除通信侧残留,不回写 StateStore 的 `blocked` 事故事实与
  `terminal_at`,所以不把本单扩大成 R2 状态修复。
- point finalizer 复用原有原子事务,并依次守住 project/status、当前 TURN、parked 声明、tmux 死亡证据与
  transaction 内 target/TURN 二次校验。旧体仍持有 TURN、runner 自报 parked、窗口仍活、探针不确定、target
  换绑或事务失败时全部 fail closed;TURN 转交后才会同时清掉 session、pending gate/ask、phase wake 和 shutdown
  残留,并通过既有 `commdb_ask_disposed` 审计面记录结果。
- 每秒巡检的资格检查使用只读 CommDB;只有确认 `eligible_dead` 后才打开写连接,避免把 migration、purge 和
  `BEGIN IMMEDIATE` 写锁带进安静轮询。成功或 `no_row` 后该 watch 在进程内 settle;长期不收敛结果按 watch
  以 1/2/4/8…秒退避并封顶 60 秒,结果变化重置为 1 秒。`kept_turn_holder` 始终保持固定 1 秒重试,所以 TURN
  转交后的收敛延迟仍满足 A1;持久失败只为每个 execution 记录一次日志。
- hourly/boot sweep 保持原有 probe-before-parked 次序、`kept` / `parkedVetoed` 计数与 FLY-1319 取证语义;
  point 模式仍可在 parked 时提前返回,避免无意义 tmux 探针。
