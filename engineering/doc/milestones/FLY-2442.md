## 交付

- Mufasa 的 windowed full-access launcher 默认从 `direct` 改为 `bridge`；`direct`
  只保留为显式 rollback，并在启动时打印绕过 Bridge 授权与审计的强警告。
- Bridge 出站授权扩到 Lead 自有 chat、project core、显式声明的
  `roundtableChannel` 及这些频道的 Discord thread；未知 Lead、未声明频道、父频道
  无法证明或 token 缺失均 fail closed。
- 线程父频道查询区分确定性拒绝与瞬时故障：Discord 401/403 继续返回 403
  fail-loud；429/5xx/timeout 返回可重试的 503 `channel_parent_lookup_unavailable`。
  两类均不回落 direct。

  每次结果写 metadata-only 审计。Codex runtime 在 intake/gateway 启动前并发探测 chat
  与 cross-dept 顶层频道；确定性拒绝不回落 direct，瞬时不可达按 4 轮、总预算 50 秒重试。
- `engineering/doc/FLY-2442-codex-outbound-bridge/mailbox-adapter-contract.md` 固化
  ingest → CommDB mailbox → 3 槽租约投递泵 → harness 最后一跳适配器 → 经 Bridge
  授权回程的合同，并逐字引用现有注释解释 Codex socket/journal 为何不能删除。
- Lead 已确认 Epic FLY-2441 引用合同页及三份设计链接；生产 `projects.json` 的
  `roundtableChannel` 登记按 Lead 决定留到 merge/deploy 同窗，与 summary receipt
