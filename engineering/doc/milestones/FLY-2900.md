# FLY-2900 — Codex 撞额度墙后自动续上：额度待命 → 同一 execution 新进程续原 thread，替身只作兜底

**Status**: ⏳ Latest-main conflicts resolved; fresh scoped merge review and new-head QA pending

Codex runner 撞额度墙（`goal_usage_limited`）后，engine-owned 的 Codex 节点不再判终态失败、不再盲换三具、不再 hold 等人，而是进入「额度待命」：进程退出，节点仍 running，TURN 不动。拿到放行证据后，系统用**同一个 exec id** 起新 Codex 进程，`thread/resume` 原 thread，`goal/set active`，再发一条带标记的 continue 回合接着干。按 Codex R4 APPROVED 的 plan v4 §9 C1–C8 实现。

1. **放行证据两种**：自动切号提交（`switch_committed` permit），或撞墙之后发出的只读读数确认当前号有额度（`reading_confirmed` permit，覆盖原号到点回血和人工切号）。全局因果计数器 `quota_causal` 给信号和读数请求编号，读数的 `requestSeq` 必须晚于撞墙信号才算证据。
2. **显式拉起授权**：`{executionId, claimId, entrySeq, resumeAttempt}` 沿真实调用图（StartRequest → RunDispatcher admission → CodexTmuxAdapter → `beforeCodexDaemonStart`）传给每个额度闸；每次 await 后重验；普通 launch 仍被同样的闸拒绝。
3. **成功只认首个模型产出**：claim → launching → identity_verified → continuing → 首个模型产出才算成功。continue 回合用持久化的 attempt id 作 `clientUserMessageId` 并写文本标记，Bridge 崩溃后用 `thread/read` 对账，保证最多一个 continue 回合在跑。
4. **兜底两阶段**：同一 permit 下机械失败 2 次 → 新 Codex 体；全池满且最早恢复 > 30 分钟且 `codex_quota_claude_fallback` 开 → 改派 Claude（走同一条 dispatch 解析路径，冻结 demand）。兜底前把脏工作树做一次本地 WIP 提交（临时 index + `update-ref` CAS，在 StateStore 围栏事务内）；任一拒绝点同事务回滚到待命。
5. **巡检消费者**：HeartbeatService、crash-reaper、CommDB prune、ghost reconcile、rework 协调、dead-exec 回滚、dispatcher sweep、session reowner、resident hold 过期、pane-loss、recovery nudge、turn-wake、host readiness、zombie scan、capacity snapshot 全部认得待命行，不收、不复活、不告警。operator 关闭 / hold / terminate / cancel 通过 SQLite trigger 加显式调用释放待命。FLY-2465 run-recovery 对待命 execution 让路。
6. **可见性**：续上后在 issue thread 说一句（outbox `resume_notice`）；只有失败才找 Lead（新 informational kind `codex_quota_standby_diagnostic`）；founder 没有新消息。额度页新增「额度待命中的节点」一节（HTML 转义）；STEP 2 新增 `CODEX_STANDBY` 行，读失败写 `unavailable reason=…`，不伪装成 0。
7. **开关**：`codex_quota_standby`、`codex_quota_claude_fallback`（bridge_global，默认开，均为 kill switch）。关掉 standby 时新撞墙走原失败路径，已有待命行由 loop 处理完。

与 plan 的偏差（PR 已披露）：writer_replacement 迁移放在 prepare 阶段做（launch 需要它），不在 commit 阶段；释放用 SQLite trigger 加显式 finalize；进度超时 = claim + 180s 身份 + 10min 首产出；续跑体不带 phase keep-alive（沿用 FLY-2808 语义）；STEP 2 行扩展现有 `scripts/lib/codex-quota-summary.mjs`，没有新建 helper（保持 managed-bin 闭包不变）。
