# FLY-2331 — Bridge 异步子进程稳态化

**Status**: ✅ Implementation complete; R3 findings fixed, ready for exact-head R4 review
**Date**: 2026-09-04

## 交付

- Bridge 可达的 `run-infra` evidence、adapter shell、phase branch-tip、progress-resume、
  approve、workflow-docs Git、WorktreeManager、Blueprint readiness、Codex adapter 与 fleet
  recovery 子进程改为有硬截止的异步执行；worktree/fetch/approve 最长 120 秒，短探针使用
  10–30 秒命名预算。
- 共享 async runner 使用独立 process group，并覆盖 timeout、parent 先退出但孙进程持有
  stdio、maxBuffer、ENOENT、非零退出、最小 replace-env 与回收边界。
- 仍有意保留的同步入口全部进入 checked-in repo-wide census，具备明确 timeout 与固定
  `last_sync_op` marker；Bridge 可达的 lead-lease `ps` 探针 timeout 被建模为
  indeterminate，不会误判进程死亡或撤销 fresh carrier evidence。
- workflow-docs Git 使用成对 async span 归因；Heartbeat maintenance 在 baseline 后以及
  每个项目完整 `projector → watch → operations` 链和 CommDB close 后让出事件循环，项目内
  顺序和 single-flight 语义保持不变。
- `BridgeEventLoopGuard` 的 60 秒阈值、stall 判定、取证 schema 与 SIGKILL 语义没有修改。

## 真时长验收

`scripts/__tests__/fly2331-bridge-async-child.test.sh` 使用 PATH 前置 fake Git 与真实 guard：

```text
PASS fly2331 async=70s sync-mutant=61s heartbeats=70 group=2/2 reap=1/1
```

异步臂连续运行 70 秒且 guard heartbeat 推进 70 次、无 terminal stall；相同 fixture 的同步
mutant 在 61 秒被 guard SIGKILL 并留下 stall forensic。process-group 与 detached reap 两臂
分别证明孙进程/pipe deadline 收敛和短寿命 detached child 被观察并回收。缩放预检同样通过。
