# FLY-2028 — Discord thread 按静默年龄归档

**Status**: ✅ Implementation complete; needs review
**PR**: pending creation from this milestone commit
**Date**: 2026-09-02

Bridge 现在自己兑现 thread 过期归档，不再把 Discord 原生 `auto_archive_duration` 当成行为保证：`#leads-roundtable` 与 `#flywheel-alerts` 由 10 分钟清扫器按各 thread 的 AAD 和最后活动时间归档；issue chat thread 则在终态且静默满 1 小时后归档，并能收敛被重新打开但 DB 已记录 `archived_at` 的线程。

## 交付内容

- 新增 guild active-thread 列表适配器和 Bridge-owned idle sweep：只扫描两个配置频道，fresh GET 复核后只发送 `PATCH {"archived":true}`，带 25 次写上限、60 秒 deadline、500ms spacing、429 not-before、abort 与 never-throw 结果计数。
- 403 按 thread id 隔离并跨轮闩锁：单条无权限 thread 不再饿死后续线程，同一条只告警一次直到它成功 PATCH；401 仍按凭证级 episode 处理。
- issue thread 首次归档和 re-archive 都执行 1 小时 quiet-window、消息 frontier 围栏与持久化补偿收据；首次归档的 Discord 预读对网络/429/5xx 做 3 次有界重试。
- post-ship quiet deferral 只有成功进入 targeted queue 才视为 settled；队列拒绝保持 resumable partial。close cascade 的 deferral 明确写日志。
- 6 小时 reconciler 增加 archive-only Discord-open discovery pass，补回 DB 已归档但 Discord 又打开的终态线程；复读 Linear、runner liveness、共享 cap/deadline，且不触碰 observation、gate retirement 或 lifecycle closeout。
- infra identity 对空 `DISCORD_GUILD_ID` 正确回退；active thread id 先验 snowflake；discovery 忽略空 `issue_id`。没有新增依赖、secret、migration、feature flag，也没有修改 `CLAUDE.md`。
