# FLY-2776 — dev-channels 确认框守卫在 49x16 的 Lead pane 上认不出框

**Status**: ⏳ Pending ship
**PR**: #1285
**Date**: 2026-09-22

报上来的原因是「Claude Code 升级后确认框文案变了」。不是 —— 三段文字在
2.1.277 / 2.1.278 / 2.1.280 的二进制里逐字都还在,而且 9-22 04:18Z `matched` 与
07:02Z `NOT_SEEN` 用的是**同一份二进制**。

真正的原因是**生产 Lead 的 tmux pane 只有 49 列 × 16 行**。在这个几何下,框比视口高,
标题 `WARNING: Loading development channels` 被顶出 `capture-pane -p` 的可见区域;
`Please use --channels to run a list of approved channels.`(56 字符)被软折成两行。
三段要求里只剩选项标签还能中 —— 正是日志里的
`match_warning=0 match_local_dev=1 match_channels_hint=0`。Aunt Cass 因此在两趟班车之间
停了约 17 小时:进程「在运行」,launchd 报健康,但收不到任何信,也不产生任何告警。

判定式改成三段互相独立、都必需的特征:**行锚定的选项行**(把活框和「转述这个框的
对话」分开)+ **模态证据**(模态底栏在屏、且 Claude 的 composer 指示符**不**在屏 ——
框是模态的,会挡住 composer)+ **一句正文**(折边框、压空白后匹配,软折行藏不住它)。
按键未变:单发 `1`,永不发 Enter。

所有匹配 `LC_ALL=C` 钉死且不用方括号表达式:启动器没有 locale,C locale 下 `[│┃|]` 是
**字节**集合,而 `│` 和 `❯` 的首字节都是 `E2` —— 方括号写法会把 `❯` 自己咬掉一个字节,
绿在每台开发机和 CI、死在生产。这一条是设计评审实测出来的。

同时把 NOT_SEEN 从一个静默出口拆成两件事。classification 改在归一化文本上算(它原来
自己也被折行骗,把根因带偏了一天),新增 `match_option_row` / `match_option_squashed` /
`match_modal_footer` / `match_live_prompt` 与 `geom=WxH`。告警有三条通路:选项行独占
一行、两句独立正文、或**折行后的标签 + 模态底栏**(后者专抓 43x16 / 30x16 —— 那里
选项行自己也折了,守卫刻意不按,但绝不能因此不吭声)。一条一票否决:屏上有 composer
指示符时不告警 —— 那个 Lead 正在收信,匹配到的是它**自己渲染出来的东西**。

告警走 `external_config_error`(不在 `LEAD_KINDS`,不会被 pane 分类器判成「已恢复」
自动关单)+ `warning`(`severe` 在去重前写入 observations,`severeHold=1` 会冻住
release soak),用 `--strict-delivery` 区分「已入队」和「永久死信」—— 同一个退出码 2,
相反的结果 —— 签名是「失败形状 + UTC 日桶」:形状挡重启风暴,日桶保证下次再犯还会响
(`alert_claims` 没有 pruner,纯形状等于永久静音)。

守卫的**判据**在 120x40 / 49x16 / 43x16 / 30x16 四种真实几何下都逐一验证过(全部用当前
安装的 claude 2.1.280 真起会话抓的 capture),并在 locale unset / C / en_US.UTF-8 三档
各跑一遍 —— 因为生产环境的 locale 就是「没设」。

判定式的每一条都有**变异负控**钉着:去掉归一化(F2/M1)、去掉行锚定(F3)、去掉 composer
否决(P15c),三者都必须让对应用例转红。最后一条是代码评审抓出来的 —— 原来的 P15 因为
fixture 带了引用前缀,行锚定先失败,composer 那一条其实从没被验证过。

设计与代码评审各经四轮 / 三轮,最终两轮 scoped 复评均 APPROVED;全部报告存档在
`engineering/doc/FLY-2776-dev-channels-dialog-guard/`。

pane 49x16 本身偏小,是这次翻车的触发条件,但守卫本来就该对任何几何成立。pane 几何另开单。
