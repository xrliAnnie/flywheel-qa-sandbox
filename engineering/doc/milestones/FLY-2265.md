## 结果

`flywheel-claude-profile use <name>` 的 `apply_failed` 根因已定位并修复：FLY-2240 的公开 Bash trampoline 没有把解析出的自身绝对路径导出为 `FLYWHEEL_CLAUDE_PROFILE_BIN`。detached Node launcher 因而回退到裸命令名；当 binary 不在 `PATH` 时，spawn 在 Bash 审计 `entry` 之前以 `ENOENT` 失败。

修复让公开 trampoline 把准确的绝对入口传给 Node 子进程，健康账号仍沿同一 `use` 命令完成 selector、apply、原子账本提交与通知。`apply_failed` 现在在保留稳定 reason code 的同时，将去敏后的内部错误写入 stderr；Bash 尚未接管审计时，Node 会追加失败 fallback。新建审计文件在 Node 与 Bash 两侧都显式收紧为 `0600`，通用已启动 child 的失败路径不会再产生重复 fallback。

分支已 rebase 到当前 `main`，与 FLY-2258 重复的 kill/inventory 改动已删除。PR：[#1032](https://github.com/xrliAnnie/flywheel/pull/1032)。状态为待独立 QA/review；本节点没有 merge 或 deploy。

## 已知项与 QA 边界

第二轮审查的六条非阻塞 advisory 已完整写入 PR「已知项」：四个类型化失败分支可能重复 fallback、child-started 不等于 audit entry 已写、首次创建的窄 umask/open 竞态会 fail closed、child stderr 全量透出、空 actor 默认差异、exit 31 不可达。本轮不再修改这些项。

独立 QA 必须按 `engineering/doc/FLY-2265-manual-switch-diagnostics/qa-handoff.md` 回填四项结果：

1. 隔离 store 的真实公开 `use` 同命令修前 `apply_failed`、修后 GREEN。
2. 不设 `FLYWHEEL_CLAUDE_PROFILE_BIN` 且 binary 不在 `PATH` 的回归。
3. `quota-monitor-runtime` daemon 自动路径经过同一 apply 入口。
4. 四条类型化失败出口各恰好一组 `entry/exit`，details 可诊断且去敏，审计文件始终 `0600`。

四项任一缺证或失败，QA 都不能通过。验证只能使用隔离 HOME/store/Keychain stub；不得切换 `personal1` 或任何生产账号，不得重启生产 daemon，不得把 fixture 阳性对照描述成线上切号成功。
