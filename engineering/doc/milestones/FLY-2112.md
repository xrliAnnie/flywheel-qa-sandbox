# FLY-2112 — 无 runner founder gate 自动收敛

**Status**: ✅ Implementation rework complete; exact-head review pending
**PR**: https://github.com/xrliAnnie/flywheel/pull/1099
**Date**: 2026-09-06

本实现为 engine-owned workflow 增加了一条有界、可重放的收敛路径：当 run 仍为
`active`、当前节点仍是未结束的 founder review、holder 仍为 `awaiting_review`，且
没有任何非终态归属 session、未决 dispatch、未完成 rework delivery 或残留 running node 时，
Bridge 会自动作废该 gate 并把 run 收口为 `terminated`。所有存活 veto 都在 SQL `LIMIT`
之前生效，不会让一条活 run 长期占住扫描窗口。

## 交付内容

- StateStore 以单个 SQLite transaction 原子完成 review node 与 gate holder supersede、
  ship-target 作废、carrier delivery 取消、run 终止、engine park 结算与稳定审计
  event。任一竞态会整体回滚；已完成形状可幂等 replay，半终态形状 fail closed。
- 跨 StateStore / CommDB 的部分通过持久 superseded holder 重放：真正调用既有
  `retireGateForTerminalAuthority`，保留 `response_won`竞态裁定，并在成功后写入
  `sessionless_gate_mailbox_retired` event。CommDB 暂时失败不会丢失待办项。
- reconciler 复用现有 workflow-gate materialization tick，按 StateStore 实例自节流为
  30 秒，每轮最多处理 20 条，不新增 daemon/timer。既有 9 条存量形状会在部署后
  被同一生产路径有界排空，没有在 implement 阶段直接改生产数据。
- Discord ship card 沿用现有作废 worker，新文案明确告知 founder：run 已无存活
  runner，本卡已作废，对它的任何批准都不会触发 ship。
- 范围严格限定在 issue 指定的 `active` run 形状；没有依赖 Linear Done 状态，
  没有扩展到已 `terminated` run 的历史 card 清理。
