# FLY-2283 — 每份托管报告稳定保留 14 天

**Status**: Ready for independent QA

## 交付结果

旧的“只把 TTL 改成 14 天、继续把全部报告塞进一个 Vercel deployment”的方案已被完整替换。
每份 hardened HTML 现在是一个 private Vercel Blob 对象；固定网关继续使用原有
`https://fw-reports-*.vercel.app/r/<token>/` 链接，并在原创建时间的精确 14 天边界返回 404。
count/bytes eviction 已删除，因此任何未满 14 天的报告都不会被别的报告挤掉。

正常 `publish-report` 恰好执行一次 Blob PUT，不调用 Vercel deployment API；发布成本不再随在保报告
数量增长，也不消耗 deployment 速率/配额。没有新增 tier、flag、retention env 或项目旋钮。
`publish-report`、`verify-report` 与 founder-html-delivery 的 URL/receipt 合同保持不变。

网关 server-side 读取 private Blob，不返回 Blob URL；它把报告内已 harden 的 CSP（包括 FLY-2276
自动 nonce）提升为 HTTP response header，并同时返回 no-store、nosniff、DENY 与 noindex headers。
publisher 与 gateway 共用同一个 head-scoped CSP 判据，不能被网关安全服务的 HTML 会在 publish 阶段
明确失败，不会铸出已交付却永久 502 的新链接。author CSP 含 CR/LF 时 publisher 以可操作的 400
拒绝；gateway 对历史坏对象也捕获 header construction 异常并显式返回 502，不再抛成 500。

## 旧链接迁移与失败边界

`pnpm migrate:report-hosting` 把 registry 中未满 14 天的正文以原 token 幂等上传，再部署一次固定
gateway runtime。deployment READY 后才写 durable cutover marker；marker 之前新 Bridge 拒绝 publish，
避免旧/新 hosting 分叉。上传、部署或 marker 之前的校验失败均可重试，marker 已存在时整条迁移 no-op。

生产切换必须按顺序执行：先把同一 Blob token 配给 Bridge 与原 gateway production target；再重启
新 Bridge；然后运行 migration；只有 READY 且 marker 写入后才验证旧、新 token。**从 Bridge 重启到
marker 成功写入之间，所有新 `publish-report` 都会返回 503，这是计划内的发布停机窗口。**任一步失败
都保持 503，修复后重跑幂等 migration，不能手工跳过 marker。

已有 report registry 复用原 `fw-reports-*` 项目名。空 reports 目录首次运行会生成并原子保存稳定的
`fw-reports-<6hex>` 名称，然后因尚无同名 Vercel project 在 production env preflight fail closed；运维方
用 registry 中的该名称创建 project、接入 `BLOB_READ_WRITE_TOKEN` production target 后重跑，迁移复用
同一名称完成部署。这个两步引导不部署半成品，也不会在重试时更换 canonical host。

时间损坏遵循 Lead 裁决的三层语义：

- 读路径无法取得有效 `createdAt` 时维持 fail-closed 502；
- registry/accounting 把无效时间条目当过期裁掉，但 publish 不把它列入远端 Blob 删除清单；
- 不可逆 Blob sweep 在 registry `createdAt` 无效时回落到 Blob `uploadedAt`，只有回落值也已满 14 天才删；
  回落值未满 14 天或两个时间都不可得时一律保留，并在无时间证据时于 store 生命周期内只写一次
  固定、无凭据告警。

A6 凭据探针覆盖 gateway `uploadedAt` accessor、publish stage/upload/commit/cleanup、定时 sweep 和
migration 顶层失败日志；上游异常正文不再插入这些日志，合成 Blob/Vercel 凭据不会泄漏。

上线前仍需要 founder/Lead 把同一个 private Blob store token 配给 Bridge 与 gateway project，随后按
上述顺序切换。本 implement 节点没有部署、合并或修改生产。

验收项 #3 **没有由本 PR 关闭**：外部已安装文件
`~/.claude/skills/founder-html-delivery/SKILL.md` 中仍需把 “7 天” 改成 “14 天”。该路径不属于本仓，
由 `flywheel-eng-lead` 负责跨仓同步，跟踪位置为 FLY-2283 thread 的
