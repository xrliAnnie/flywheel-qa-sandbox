本单按 FLY-2795 固定合同 `313befcfa3a7039dca2fc7eb1178803d47699026` 实现引擎 B。每场语音会话新建一个隔离的 Codex 0.156.1 realtime 容器，把指定 Lead 的身份、授权 memory 文件和开场状态快照装入会话；房间结束前关闭容器并把纪要交回本体。实现没有给 Lead 建常驻分身，没有重做进房、收音或放音，也没有修改舰队 `~/.local/bin/codex` 或 codex-242 current。

## 交付与 fail-closed 边界

- standalone Codex 0.156.1、release SHA、V2 与 `gpt-realtime-2.1` 的启动和回执核验；第 1 步实测证据继续使用已完成结果，没有重复消耗额度。
- 临时 0700 home/work、只读且无执行能力的 voice profile、逐场新 process/thread/realtime、generation fencing、确定性关闭；额度或认证不可用时明确返回「语音不可用」，不静默换引擎、模型或订阅认证。
- Bridge 按注册身份装配 Raya / Honey Lemon 的身份、授权 memory、当前事项与待决定问题，并拒绝路径逃逸、身份冲突、缺失/过期/超预算上下文。
- 在共用 VoiceBackend/ConversationSession 和通用房间层上接入 PCM16/24k/mono 输入及输出；播报回执绑定 `pendingKey`、`requestDigest` 与逐句 proof。
- `bargeIn` 用取消旧 generation、等待确认关闭、只重启 realtime、重放重启期间房间音频实现。重启缓冲若溢出，先把新 transport 的输入归因标成无效再送剩余帧；不会把有缺口的输入伪装成连续 owner。
- 实时输入背压只记录 gap/drop 证据，不再以 fatal backend error 关闭房间。可信归因只在 provider speech-start item、completed user item、同一 owner/utterance、全程无 gap 同时成立时产生；混人或缺口保持 unknown。
- 动作边界使用显式 `handoffToLead` seam。语音分身本身没有派单、批准或改动权限；fake trusted mode-layer E2E 证明只有显式 handoff 的动作进入 Raya 本体信箱，闲聊不进入。生产 initiator/authority 绑定仍归 FLY-2796/2797，CLI 保持 `capture:false`。
- B 的静态 `verbatim`、`attribution`、`bargeIn` 能力仍为 false，直到 live 准入矩阵逐项通过；RPC 存在、实现代码或抽样成功均不被冒充为能力准入。
- 转写、handoff、回执和会末纪要持久化具有幂等恢复与负向保护；模型口头声称“已执行”不会产生执行权限。
- `scripts/qa/fly2799-codex-container.mjs` 只接受 0600 私有 manifest、精确 HEAD、关闭的 G1/G2 receipt、固定 binary digest/version/features、两个互斥测试 slot 和 `productionRouting=false`。准入不全时只产出 `INCOMPLETE_CAPABILITY_GATES`，不会伪造整项 PASS。
