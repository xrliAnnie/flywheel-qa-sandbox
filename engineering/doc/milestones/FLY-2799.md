# FLY-2799 — Codex 临时语音容器

**Status**: ⏳ Implementation complete; pending final exact-head review, PR CI, and independent QA
**PR**: pending creation from this milestone commit
**Date**: 2026-09-23

本单按 FLY-2795 固定合同 `313befcfa3a7039dca2fc7eb1178803d47699026` 实现引擎 B。每场语音会话新建一个隔离的 Codex 0.156.1 realtime 容器，把指定 Lead 的身份、完整授权 memory 文件和开场时刻状态快照装入该会话；房间结束前先关闭容器，再结束现有通用房间层。实现没有给 Lead 建常驻语音分身，也没有重做进房、收音或放音。

交付内容包括：

- 固定 standalone Codex 0.156.1、release SHA、V2 与 `gpt-realtime-2.1` 的启动和回执核验；不修改舰队 `~/.local/bin/codex` 或 codex-242 current。
- 临时 0700 home/work、只读且无执行能力的 voice profile、逐场新 process/thread/realtime、generation fencing、确定性关闭，以及额度/认证不可用时明确返回「语音不可用」，不静默换引擎、模型或订阅认证。
- Bridge 侧可信上下文装配：按注册身份解析 Raya 与 Honey Lemon 的身份和 memory 来源，加入当前事项与待决定问题，记录来源摘要和快照时效，并拒绝路径逃逸、身份冲突、缺失状态、过期或超预算上下文。
- 在共用 VoiceBackend/ConversationSession 上接入 Codex realtime；外部 PCM16/24k/mono 音频进入现有房间链路，播报返回绑定 pendingKey/requestDigest 的 SpeakReceipt。B 的 `verbatim`、`attribution`、`bargeIn` 仍按固定合同 fail closed，未把 RPC 存在或抽样成功冒充能力准入。
- 持久化转写、动作 handoff 和本体回执状态机。语音分身没有动作权限；派单、批准和修改请求只能由可信模式层投到对应 Lead 本体信箱。ACK 丢失和进程恢复可按同一幂等键回读，不会因模型文字声称“已执行”而产生权限。
- 会话结束纪要持久交给 Lead 本体，并为崩溃、发送成功但 ACK 丢失、重复恢复和错误身份建立幂等与负向保护。
- `scripts/qa/fly2799-codex-container.mjs` 的有界测试房驱动：只接受 0600 私有 manifest、当前精确 HEAD、关闭的 G1/G2 receipt、固定 binary digest/version/features、两个互斥测试 slot、Raya 与 Honey Lemon 的精确身份和模型，以及 `productionRouting=false`。它复用已有隔离测试房 carrier，在 `finally` 中停场，收集容器开关、proof receipt、转写和纪要。当前能力矩阵关闭时只能产出 `INCOMPLETE_CAPABILITY_GATES`，不会伪造整项 PASS。
