# FLY-2876 — 同一 slot 重新部署后，孤儿语音房锁让 start 永远 already_owned

**Status**: ⏳ Pending ship
**PR**: #TBD
**Date**: 2026-09-25

**范围。** FLY-2867（PR #1323）已覆盖本单 QA 判据 2（别的 slot 的锁仍拒绝）与判据 3（teardown Step 6b 释放本 slot 的锁）。
本 PR 只补剩下的事故本体：同一 slot 被拆后重新部署，`/tmp/flywheel-voice-room-<guild>-<channel>.lock` 的 `owner.slotDir`
仍等于本 slot，回执随旧 slot 目录删掉、也没有存活进程 —— `acquireVoiceRoomLease` 对同 slotDir 返回 `created:false`，
`start` 报 `voice_room_lease_already_owned`，正规路径只剩「再拆一次」能清。会话自然结束（daemon 退出、回执仍 `STARTED`）同样被挡。

**修复（只动 `scripts/qa/fly2655-voice-room.mjs` 的租约函数）。** 同 slot 租约只有在三者都不活时才经 #1323 的墓碑流程回收并重建：
新增的 `owner.holder`（执行 start 的 CLI 进程，覆盖 daemon/回执尚未写出的窗口，并发 start 仍被挡）、
`owner.daemon`（#1323 的判定，函数体抽成 `recordedProcessAlive` 复用，行为不变）、
`<slot>/voice-run-receipt.json` 为 `STARTED` 且 pid + `ps` 身份仍一致。回执读不了 / 软链接 / 越界 / 字段畸形一律按「活」处理，宁可不回收。
异 slot 规则、teardown、`start()`、voice-codex 均未改。

**验证。** 先红后绿：事故场景改前 `created:false`。`node --test scripts/__tests__/fly2655-voice-room.test.mjs` 22/22（新增 3 条 + #1323 全部用例），
4 个变异（忽略 holder / 回执永不算活 / 读不了的回执不算活 / 完全不回收）全部被杀；kill-path 清册新增 1 条 qa-only，守卫 5/5；
`pnpm lint` exit 0。排除的消费者：`test-deploy-fly1389.test.sh`（重型 529 E2E，其驱动的 test-deploy / teardown / `release-slot-leases`
与基线逐字节相同）、`ci-structure.test.sh`（ci.yml 未改）。真实 `/tmp` 语音锁全程未触碰。

**已知限制。** 合入前遗留、既无 holder/daemon 记录、回执也已删除的租约，若其旧 daemon 实际仍在跑，本判定识别不出，会按孤儿回收；
