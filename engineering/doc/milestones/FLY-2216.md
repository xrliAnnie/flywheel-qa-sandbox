# FLY-2216 — Resident Codex Lead 常驻、自愈与可观察日志

**Status**: ⏳ Pending independent QA

**Date**: 2026-09-01

FLY-2216 现在提供一个所有 resident Codex CLI Lead 共用、默认关闭的 residency 机制，而不是
Raya 专用旁路。每个 target 由 `projects` roster 的严格布尔 `codexResidencyPatrol:true` 显式启用；
只有 `codex-app-server`、`canSpawnRunners:false` 且具有已识别 tier 的 Lead 才会被枚举。未 opt-in 的
现有 Lead 保持原启动路径，返工没有修改生产 registry。

carrier identity、plist 与 wrapper 仍是各 Lead 已审核的既有实现。Raya 继续使用 `raya/raya`、
`com.flywheel.lead.raya-raya` 与 canonical `raya-raya` 真 TUI 会话，并由既有 cmux watcher 管护；
本单没有另造 daemon、timer 或告警层，也没有把任意 wrapper 纳入重启权限。

每个 opt-in runtime 都有独立 lifecycle observer，把上线、gateway poll、最近消费消息、turn 与
generation 状态写入各自可 tail 的 `brain/lifecycle.jsonl` 和 atomic `brain/heartbeat.json`。Bridge
在既有 GatePoller rider 上为每个 target 构造独立 patrol；通用告警固定为
`codex_lead_residency_stalled` / `machine/codex-lead-residency`，event id 含 lead key，某一 target 的
异常不会共享或阻断另一 target 的 episode。

只有 `poll_loop_stalled`、`turn_stalled`、`heartbeat_stalled` 三类业务停滞可进入共享连败恢复门。
通用 helper 在 mutation 前二次核验 roster authority、plist/wrapper、CODEX_HOME、pid+lstart、argv 与
generation evidence，先写 durable receipt，再对 exact launchd label 执行有界 kickstart，并等待新
generation 收敛。测试用 Raya 与 Mufasa 两个不同 target 独立证明 detection + alert + recovery
authority；未 opt-in InfraBot 在读取 process 之前 fail closed、零 mutation。

独立 QA 已证明病案里的“我下线了”来自 `com.xrli.raya.voice` 的正常语音退出，不经过本载体的
assistant output。实现因此保持净删除 offline declaration detector、heartbeat 字段与 classifier
branch；legacy heartbeat 即使残留未知字段，也只按 poll、turn、heartbeat 证据分类。

cross-family review 在 `bd64fb4a7` 发现并阻断一个真实兼容性风险：TUI runtime 无条件加载整个
projects registry，可能因无关 invalid row 让未 opt-in Lead 启动失败。`5da329148` 通过 RED→GREEN
回归把可选 roster load 改为 fail-safe disable observer；fresh review round 4 在 exact code head
`f49dd20dbd566da3bf98f0c3064a9f3326003afe` `APPROVED`。4 个 MEDIUM 与 6 个 LOW 非阻塞 advisory
已按 findingKey 报告 Lead 后续分单。
