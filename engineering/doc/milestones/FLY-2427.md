## 交付

- `flywheel-comm respond` 对 founder-only `approve_to_ship` gate 的 Lead
  任意文本一律 fail closed；Bridge writer 在实际 storage call site 保留相同后卫，
  直接 HTTP 绕过也不能写 response、dispose question 或伪造 founder source event。
- 新增只读 CommDB question inspection，以 parameterized prefix-range 查询区分
  missing、disposed、superseded、resolved、已有 response、健康 question 与已存在
  founder source event。
- 新增 project-level、默认开启且读取失败 fail closed 的
  `workflow_gate_question_recovery` kill switch，以及 30 秒 durable throttle、
  每轮候选硬上限和单候选失败隔离。
- StateStore 在同一 SQLite 事务内 CAS 当前 active land holder，冻结 origin
  inspection receipt，推进下一 gate attempt，重铸普通 successor holder，并把旧
  holder 标成 `question_unanswerable_recovery`；任一写点失败都完整回滚。
- replacement 继续走生产同源 PR preflight 和既有 materializer，不复用 receipt
  绕过外部检查；旧卡只有 successor durable completed 且已有 card id 后才进入
  void，并显示“旧卡已坏并自动重铸，请使用新卡”。
- 同一 `(run,node,head)` 最多恢复 3 次；第 4 次保持 holder 不变并写 stable-dedup
  durable alert，避免与外部错误退休形成无限补卡循环。
- 同步修正 Lead/CoS/runner 规则与 CLI help，不再引导 Lead 用 ship gate
  `respond --kickback`；普通 checkpoint 回复合同保持不变。

既有死门仍只能由其 PR head 变化后按正常引擎路径重铸；本 implementation phase
不操作该 PR 或线上状态。
