# FLY-2210 — 三小时节点停留巡检

**Status**: ⏳ Pending ship
**PR**: [#1013](https://github.com/xrliAnnie/flywheel/pull/1013)
**Date**: 2026-08-31

现有 Lead 巡检钟新增独立 `STEP DWELL`，按 active run/node 的严格谓词计算
`now - max(started_at, latest examined_at)`，阈值由 project → `*` → 默认 3 小时的
`node_dwell_threshold_hours` 提供。project-scoped、conversational 的 `node_dwell` 总开关默认开启，
每个 tick 重新读取；关闭后不产生 `NODE_DWELL` 行、reminder、强制 action/finding，重新开启无需重启，
读取失败则显式 `UNAVAILABLE`。新的 `node_dwell_review` 账本用
`(run_id,node_id,attempt,cycle_no)` 记录四类处置收据；批量写入会复核 active node、owner、project
与同 issue 归属，任一目标不合法即整批回滚。

超阈节点会进入内容级 deep dive；`founder_gate/review` 或可安全归因的未答
`approve_to_ship` 则按 issue + route 合并为 thread 提醒。同一等待 episode 只提醒一次；只有 thread
投递成功后才写持久 `waiting_founder` 收据，纯时间流逝永不重新武装。founder 在该 issue thread
发言、canonical founder gate 状态/head 变化，或 node 新 admission 会开启新 episode；从该动作起再等满
当前阈值才允许下一条合并提醒。缺 helper、缺表、归属不完整、输出截断或历史 gate 无法唯一映射时均显式 fail closed，
不会回落默认值或伪报完成。Lead 规范同时固化 FLY-2178 的三小时空转教训：必须读终端内容、
workflow transition 与工作日志判断推进/空转，禁止只看画面刷新。

## 部署顺序

1. 构建 TeamLead dist。
2. 运行既有 convergence，把无扩展名 `flywheel-node-dwell-control` strict symlink 指向 committed
   `scripts/flywheel-node-dwell-control.mjs`。
3. 重开/重启 Bridge，使 StateStore migration 创建 `node_dwell_review`。
4. respawn Leads，载入新的 patrol rules。
5. 验证至少一轮巡检报告含 finalized `STEP DWELL`。

若 snapshot 在 helper 或表 ready 前先加载到新代码，只允许产生未完成的 unavailable/candidate
报告；不得 fallback 到默认阈值、不得写成功收据、不得把该 tick 视为完成。本实现节点未执行生产
迁移、重启、部署、提醒投递、merge 或 ship。
