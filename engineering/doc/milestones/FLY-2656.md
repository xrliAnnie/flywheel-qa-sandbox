本单修复了三个相互独立、共同造成 Codex 体视图长期缺失的阻断点。生产 tmux 3.7c 会把 format 里的 tab 改写成 `_`，导致 exec/node inventory 长期 `indeterminate`；两个当前 generation 的合法 `claim_intent` WAL 在 canonical 与 staging session 都已不存在时仍永久挡住 additive sync；1405 行 cleanup-pending 又在每 tick 重复做 tmux/registry/node-presence 工作，把 heartbeat 拖过 300 秒。2026-09-16 指定六次重启的 restart ledger 与 Bridge patrol 均显示 302.2–358.6 秒 stale 后 kickstart；最近 3000 行日志有 2881 行 fence waiting。旧 watcher stdout 已被覆盖，因此这里把根因表述为与全部可用证据自洽的调度阻塞，不伪称拿到了进程退出栈。

实现把两份 runner inventory 改成 printable `|` 分隔，并让无实体 WAL 只在成功的 exact session census 与 generation 复核后 retire，不对任何 tmux object 取得 destructive authority。cleanup admission 现在使用 pass-local、验证过的 registry owner snapshot 与 Lead roster snapshot：精确命中任一 authority 的标题可进入共享清理路径；`*-realtest-*`、两个 snapshot 均结论性无 owner 的 `issue-*`/普通窗口、控制字符、delimiter 与超过 247 bytes 的标题均不入队，任一 snapshot 不确定时仍 fail closed。同一冻结 event batch 只装载一次 snapshot。预剪枝先原子提交队列，7 天 TTL 只依赖 marker 年龄，过期行写 `cleanup-pending-ttl-reaped` episode 后直接删除。第四个健康 tick 先跑 additive mirror/rebind，再处理 cleanup；前三个 tick 与即时 create hook 顺序不变。

terminal transaction 额外把精确 `pane_dead=1` 作为 teardown 必需条件；`pane_dead=0` 的活 canonical runner 即使遇到陈旧 terminal roster 也不 teardown、不 dismantle、不关 pin。首次 registry 补账会重新启用 node 分类、summary TTL/cap 与 terminal transaction，因此这条负向 guard 是补账安全边界，而不是放宽既有 close authority。启动 wrapper 另以 5 秒 bound 读取 launchd reason/last exit/terminating signal；timeout、nonzero 与缺字段降级为 `unknown`，watcher 再做 delimiter 与组件长度清洗。`watcher-started` 是 latest/suppressed episode，逐次启动时间仍由既有 append-only restart ledger 承担。

首轮 exact-head review 指出一个 HIGH：Lead 窗口按设计没有 runner exec id，若只信 node registry，它们的 pane 退出会被 admission 拒绝，且 Lead 又不属于 orphan-pin reaper 的 managed-runner 范围。修复复用同一轮已验证的 `LEAD_ROSTER_ROWS` 作为独立 authority；精确 roster 标题不需要伪造 exec id，未入 roster 的空 exec-id 窗口仍不能入队。回归先在旧行为下得到 1 个失败，再在修复后转为 25/25，并由主套件同时钉住 Lead 可清理与 ownerless issue/realtest 被拒绝。
