# FLY-2757 — 附件逐项判定

**Status**: ⏳ Pending exact-head code review, QA, and full CI
**PR**: #1317

Discord 入站附件读取原先先用严格 schema 解析整条消息的全部附件，再按 ID 选目标。因此同批次
只要有一个 sibling 缺少类型或元数据不合格，合法图片也会在目标选择前被整批拒绝。修复保留
message/channel snowflake、附件数组上限和每项必须为对象的消息边界，只按原始 ID 选择唯一目标，
再对该目标执行原有严格 schema、MIME、大小、URL、超时与内容校验。坏附件仍返回属于自己的
显式 `invalid_metadata`，但不再影响合法 sibling 的内容交付。

新增真实同批回归：同一 Discord metadata response 同时包含合法 PNG 和无类型附件；读取合法 ID
返回精确 PNG bytes 与 `image/png`，单独读取坏 ID 返回 `invalid_metadata`，且坏附件 CDN URL
从未被访问。TDD RED 证明旧整组解析让合法图片失败；最小修复后 focused 19/19 通过；再临时恢复
整组严格解析，新增测试重新变红，恢复当前实现后又回到 19/19，证明阴性对照有效。
