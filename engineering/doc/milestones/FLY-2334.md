# FLY-2334 — 审查体 Vitest 限流与同头复用

**Status**: ⏳ R1 findings fixed; exact-head R2 code review pending
**PR**: https://github.com/xrliAnnie/flywheel/pull/1079
**Date**: 2026-09-04

跨族 Claude 审查体现在固定继承 `VITEST_MAX_THREADS=4`、`VITEST_MIN_THREADS=1`、
`VITEST_MAX_FORKS=4`、`VITEST_MIN_FORKS=1`，即使 Bridge 环境里已有更高值也会被覆盖；审查
提示词同时限定只运行改动包及相关测试文件，并明确禁止 `pnpm -r`。同一项目、issue、真实仓库
identity 与冻结 head 已有 running code-review job 时，替身 execution 的新 request 不再启动第二个
reviewer，而是持久化独立 gate 绑定；源 job 的 verdict 通过每个绑定自己的 nonce/outbox 投递，并为
各 execution 写入精确 head 的审查凭据。

R1 的 1 HIGH、2 MEDIUM、3 LOW 已全部落实：源 job 失败、跳过、head moved 或 gate 被取消时，
复用绑定会原子释放为替身 execution 自己的 standalone review job；Bridge 重启会恢复这条释放路径；
投递 verdict 前重新读取替身 execution 的当前 head，漂移时改审它自己的新 head；request-bound
authority 恢复也会扇出复用绑定。复用不再继承 skipped verdict，仓库键不再用 `__main__` 跨 worktree
碰撞，线程与 forks 两类 Vitest pool 都被硬限为 4/1。新增 schema 均为 additive migration，释放写入
与 job 创建处于同一事务，并覆盖幂等 replay。

## 边界与交接

本实现没有恢复全局 reviewer slot 上限，也没有修改其他 runner、部署配置或 `CLAUDE.md`。真机验收由
独立 QA 在两个替身 execution 同 head 同时请审时确认只有一个 Claude reviewer 进程，并观察该进程
派生的 Vitest worker 不超过 4。本 implement 节点没有 dispatch QA、请求 ship、merge、deploy 或重启
Bridge/Lead 服务。
