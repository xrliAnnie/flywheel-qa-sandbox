# FLY-2661 — 机器试判历史改为按需生成

**Status**: ⏳ Pending ship
**PR**: #1233
**Date**: 2026-09-16

移除 `ShipJudgmentHistoryRuntime` 的定时托管发布生命周期与 Epic 刷新联动，Bridge 启动不再因机器试判历史写 report registry 或 Vercel Blob；生产 `next_due_at` 止血值因此不再驱动任何发布副作用。新增 `flywheel-comm ship-judgment-history render --project flywheel --out <file.html>`，通过 master-token 保护的只读 Bridge 路由生成完整本地 HTML，使用同目录临时文件原子落盘，失败时保留既有目标文件，后续是否上传由 Lead 显式执行既有 `publish-report` 决定。

Epic 固定页只保留“按需生成”说明与机器试判摘要，不再展示托管历史链接或发布状态；旧迁移的过滤条件收紧为“registry title 为空且 HTML 标题精确为旧版机器试判历史”，同时应用于初始迁移、retarget snapshot 与 gateway-only manifest，避免搬运历史自动发布残留而不误伤新的手动报告。机器试判 dry-run 意见、卡下评论、founder 决定学习及证据链未改。验证覆盖 lint、23 workspace build、focused 77/77、CLI 3/3，以及 package aggregate 全绿（TeamLead 1366 files / 16,685 pass / 7 skip）。

首次 exact-head CI 发现根级计时器回归测试仍借用已退役的 history runtime 来启动主机器试判计时器；测试已拆开验证“运行中模式读取失败后继续下一 tick”与“Bridge 启动边界包含同步失败”，生产计时逻辑未作改动。
