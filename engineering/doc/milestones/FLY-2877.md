# FLY-2877 — Codex lease 与 codex 进程同生同灭

**Status**: ⏳ Pending review, exact-head CI and QA
**PR**: #1327
**Date**: 2026-09-25

共享 agent home 里，一个 Codex runner 的 codex 进程还活着，它在 `.flywheel-leases` 里的 lease 却可能被删掉。FLY-2523 的证据规则要求每个 codex 进程都有 lease，于是 FLY-2869 的就绪判定对该 home 恒为 unknown，runner 在跑时自动切号永远不会触发。本单让 lease 跟着进程走，**不放宽** FLY-2523 的证据要求（`packages/teamlead/src/codex-quota/` 零改动）。

1. **删除前先看进程。** 新增 `codex-process-snapshot.ts`，逐字复制 FLY-2869 的进程判定合同：按内核可执行名 `ucomm` 认 codex；环境变量只从前后两次 argv 快照一致的进程里读；任何对不上的进程都算 unattributed（fail-closed）。`releaseCodexAgentHomeLease` / `retireCodexExecutionHome` / 新的 janitor 原语 `scrubCodexAgentHomeLeaseEntry` 删除前都会探测：该 exec 在该 home 仍有 codex 进程，或者探测给不出确定答案，lease 就保留并记日志，不算失败。janitor 原语不依赖 session.json 和 token：它先只读校验 marker 与 canonical 路径（校验失败时零写入），拿到锁后再复验一次，然后在锁内探测进程。
2. **adapter 收尾顺序。** 固定为 `runtime.stop → 杀 founder TUI → drain → 有界等待持有者退出（总共 5 s，含探测）→ retire`。每条释放路径都透传 adapter 的 probe（快照失败、owner 准入失败、prepublished、unresolved+createdLease、keyed 正常收尾）。如果 founder TUI 的创建尝试超过 teardown join 仍未结算（它可能在收尾之后才起一个 `codex resume`），这次收尾不删 lease，记 `reason=late_tui_window`；并且该 exec 的进程内 ownership 一直持有到晚到窗口结算、被 late cleanup 杀掉为止，维护清扫（它跳过 owned 的 exec）因此不会抢在窗口启动前删掉 lease，之后才由清扫收走（代码审查 R1、R2 的 HIGH）。
3. **运行期自愈。** 被外部删掉的 lease（旧 worktree 的 janitor、在真 homes 根上跑的测试）由持有 token 的 adapter 放回：它用独立的 60 s wall-clock 定时器检查，不跟 daemon 流量走，同一时间只跑一个；token 被换掉时只报冲突，不覆盖。收尾时先停定时器、等在途检查结束，所以不会把 lease 复活。
4. **残留清扫。** 维护 tick 在 orphan reaper 之后调用 `sweepStaleCodexHomeLeases`，受同一个总开关控制。只处理不在 readopt 集合、不被本进程持有、且超过 10 分钟的 lease，由 janitor 原语在锁内复验。reown 回滚和 Blueprint 未交接回滚也改走带守卫的释放。
5. **测试隔离。** teamlead 的 `vitest.setup.ts` 为每个测试隔离 `FLYWHEEL_CODEX_HOMES_ROOT` / `FLYWHEEL_CODEX_SESSION_DIR`。之前任何启动 Bridge 的测试都会让启动 janitor 拿空 StateStore 去对照生产 lease，把它们全部删掉。

验证只在本机跑了定向测试：claude-runner related 633 条，teamlead related 1277 条，外加 reaper / reown / 隔离 / 结构测试、edge-worker Blueprint、config 结构测试和 8 个脚本测试，全部通过。`pnpm lint` 0 error，依赖方 typecheck 通过。收尾 join 用例做过变异验证。代码审查用 `codex:rescue` 做，R1、R2 各提出 1 条 HIGH（晚到的 TUI 窗口；清扫与晚到窗口的竞态），均已修复并补了回归测试。详细记录见 `engineering/doc/FLY-2877-codex-lease-lifecycle/verification.md`。

实现节点没有请求 full CI、没有派 QA、没有合并或部署。QA 判据 2（两个 runner 同 home 并行时 collector 判 ready）依赖 FLY-2869 的 census 提交 `2d5d24efc`，按 Lead 裁定用 sandbox 分支验证。本文件是 PR 的 literal-last commit。
