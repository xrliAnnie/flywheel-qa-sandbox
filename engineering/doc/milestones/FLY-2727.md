# FLY-2727 — Epic 页面机器运行态可信化

**Status**: ⏳ Pending exact-head CI and post-sync HIGH-only re-review
**PR**: [#1262](https://github.com/xrliAnnie/flywheel/pull/1262)
**Date**: 2026-09-18

Epic 页的「在跑」现只来自机器账本中的新鲜 `running` heartbeat，并统一使用项目 `stuckThresholdMinutes`；存在 workflow run 时还必须是 active run 当前 running attempt 所绑定的会话，不能被同 issue 的停驻/旧会话顶替。启动宽限期内但尚无 heartbeat 显示「说不准」，heartbeat 过期或宽限期结束仍无 heartbeat 显示「停着·卡住」，已完成/评审但 Linear 尚未 Done 显示「停着·等验收」。Linear 状态继续单独显示，不再冒充机器运行态；汇总行的「在跑」也改为真活会话数。Discord 三处入口统一复用 FLY-2639 的 app deeplink + HTTPS fallback helper，未改 Epic 其它布局、lead-note、托管或发布流程。

生产形状复验：FLY-2598 的机器活会话数为 0、当前工作流节点活会话数为 0，最终头页面显示 `0 在跑 · 1 停着 · 0 说不准 · 0 未开始 · 共 1`；StateStore 对 held run 投影出的 `run_held` 信号使卡片显示「停着·卡住」，进度行是「流程被 held·请看 land 重试耗尽·卡住」，Linear 仍单列 `In Progress`。反向变异把 Linear `started` 恢复成 `live` 后，创始人场景测试按预期变红；最终片段与三数对账已同步到生产证据文档。

QA attempt 2 的唯一内容返工不改判活：所有非 live 子单的徽章和进度行都禁止出现「在跑」字样，心跳缺失/过期改为「账面未收尾」；渲染测试遍历 `stopped_acceptance`、`stopped_stuck`、`evidence_gap` 与 `idle` 卡片逐行断言。另补 `last_activity_at` 不能替代 heartbeat 的双层守卫：session aggregate 与当前 workflow attempt 都构造新鲜 activity + NULL/过期 heartbeat。按 QA 精确 M3v3 同时把两处读数改成 `COALESCE(heartbeat_at,last_activity_at)` 后，StateStore suite 分别把 `machine_running_count` 错算为 1、把 missing attempt 错算为 fresh/live，2 条断言同时变红。

复审补充修正了另一种误导：同 issue 存在新鲜但未绑定当前 node/attempt 的会话时，当前节点仍不得显示「在跑」，但也不能断言「没有机器在动·卡住」。该形状现在归为「停着·等验收」，进度行明确显示「当前节点停着·另有会话活着·等验收」；只有机器账本明确给出 `machine_running_count === 0` 才允许显示「卡住」，计数缺失则回退为「说不准」。关闭这两条分支的变异体分别让新增规则/渲染断言按预期变红。

最终复审裁定把显式 `run_held` / `declared_blocked` / `runner_stopped` 恢复为更高优先级的卡住正向证据：即使同 issue 另有新鲜会话，也显示对应的卡住原因与「另有会话活着」，而不是误报等验收；没有卡住信号时仍显示「当前节点停着·另有会话活着·等验收」。测试 fixture 同步改用 StateStore 可产出的 `review/not_applicable`、`pending/not_applicable` 与 `running/fresh` 组合，派工 residual 也恢复用 `ledger_live_count` 抑制已停驻的会话。`machine_running_count` 改为必填，并补齐 E2E scan 的 `stuckThresholdMinutes`。

最后一轮把进度原因也绑定到实际定类信号：`run_held` 指向 held / land 重试耗尽，`declared_blocked` 指向 IC 声明，`runner_stopped` 指向 runner 停机，不再把 land pending 误说成「起跑后无心跳」。任一 `signal_sources` 读取失败都会 fail-closed 到「执行证据不足·说不准」，不会静默降级为等验收；所有 held 语义 fixture 均带真实 `run_held` 信号。
