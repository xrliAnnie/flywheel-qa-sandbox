# FLY-2796 — Engine-independent headphone mode minimum

**Status**: Pending exact-head code review and independent QA
**PR**: [#1309](https://github.com/xrliAnnie/flywheel/pull/1309)
**Date**: 2026-09-24

This branch establishes one exported `RoomIO` v1 contract and
`ROOM_IO_VERSION = 1`, moves the physical Discord room implementation into
voice-bridge, and leaves voice-codex as a compatibility adapter. The same room
implementation now backs the preserved `/gemini` and `/eleven` paths. Its
contract covers attributed input frames, versioned audio formats, streaming
output with backpressure, local playback cancellation, presence, receive
health, audible-tail estimates, barge-in observation, and generation/lease
fencing. Resident session ownership provides the single-session slot and emits
mechanically comparable room identity receipts.

The restored and refactored Raya `InboxReader` and `SpeechBrief` rules feed an
engine-independent `HeadphoneMode` through the complete V1 session surface.
Entry speaks the current pending questions and reports, new durable inbox items
are inserted without waiting for a user prompt, and the configurable heartbeat
defaults to five minutes with the explicit note that this is an engineering
default pending founder use. A durable Bridge collector, snapshot cursor,
claim-before-speak attempt, content-proof receipt, and ack fence preserve
at-least-once delivery without treating a speech request as proof that audio
played. Source failures and voice failures remain explicit rather than being
reported as successful status.

Founder-directed durable questions now retain their CommDB question identity
through projection and Discord-card ingestion. Pending/resolved state comes
from that persisted authority rather than message-text heuristics, while
ordinary Runner-to-Lead questions remain outside the founder headphone feed.
The same identity coalesces an uncarded projection with its later Discord card.
Invalid or stale bindings are isolated per message, and a bad projected row
cannot block later questions or trigger a partial resolved-state reconciliation.

The same public layer adds durable final-transcript receipts, guarded spoken
exit, and the typed `handoffToLead` carrier. Handoffs validate a current room
binding and founder transcript before persisting, use a deterministic mailbox
identity before I/O, reconcile ambiguous dispatch without blind retry, and
expose a per-handoff replayable result stream. An authenticated production SSE
transport now implements
`subscribeReplies(binding, listener): () => void`; wake events contain only
`sessionId`, `generation`, and `handoffId`, so durable result replay remains the
content authority. Runtime disconnects are recorded and reconnected without a
polling fallback, reconnect wakes each registered handoff once, and the
unsubscribe function is idempotent.

`HeadphoneSession` also exposes the public
`createUtteranceProjection(session): HeadphoneUtteranceProjection` assembly
seam. It passes the unmodified V1 utterance source to an injected projection,
owns projection start/close with the session, and lets FLY-2798 attach its
`LiveCaptionProjection` and room TIV `CaptionSink` without a circular package
dependency. The focused proof sends `frontend` and authoritative `lead:<id>`
utterances through the same session and preserves the distinct `🤖 前台` and
`💬 Lead` labels at the sink. Query, judgment, and action are carrier
classifications only; no ship-specific spoken authority, filtering memory, or
interruption behavior was added.
