# FLY-2190 — 为 Rosetta 退场建立原生 tmux 迁移安全门

**Status**: ⏳ Pending ship
**PR**: #1002
**Date**: 2026-08-30

交付原生 tmux 迁移的 S0 前置安全层：六类生产 carrier 在启动与重启事务中都必须通过
host 级 tmux 选择门和短时、绑定 SHA 的收据校验，并以实际 loaded Lead plist 做全舰 census。
安装、converge、prebuilt provisioning 与 updater 均覆盖门脚本；未来经 founder 授权的 S1
切换另有最长 15 分钟、`0600`、带原因且过期 fail-closed 的 break-glass。本 PR 不调整 PATH，
不安装原生 tmux，也不触发 17 个现存 server 的破坏性重启。

## QA rework 与最终验证

- 六个生产 wrapper 都保留环境 override 只用于隔离临时 state root，并显式回退到
  `${FLYWHEEL_DIR}/scripts/host-tmux-selection-gate.sh`。新增的 first-birth 回归从空的
  `state/bin` 启动 prebuilt InfraBot carrier，证明 converge 尚未安装 gate 时仍会使用
  checkout gate、校验 packaged SHA 并启动 carrier。
- prebuilt 包现在携带由 assembly HEAD 生成的 `.flywheel-build-sha`；release gate 会拒绝
  缺失、格式错误或与 source HEAD 不一致的身份。这样无 `.git`、无 deployed-sha 的安装
  仍可向 host gate 提供 40 位 build SHA。
- `packages/config/src/feature-flags/truth.ts` 同时保留 `origin/main` 的 FLY-2168 QA allowlist
  与本单三个 hermetic seam；`git merge-tree --write-tree HEAD origin/main` 生成 clean tree。
- FLY-2190 shell suites、`package-onboard.test.sh`、`pnpm lint` 与 `pnpm -r build` 均通过。
  Quick Gate 的 CI structure 精确 inventory 也已登记 `Test — FLY-2190 host tmux selection S0`
  并由 `ci-structure.test.sh` 验证；version-injection packaging fixture 也以真实 committed HEAD
  和 `.flywheel-build-sha` allowlist 覆盖新的 source-identity 前置条件（10/10 通过）。
  扩展后的 converge managed-file inventory 也已同步到 FLY-1389 与 FLY-1577 的 synthetic
  checkout fixtures；对应 suites 分别为 22/22、31/31、7/7，并完整重放 fleet/setup shard。
  完整 packaging shell step 也已重放通过；`gate4-allowlist-masking.test.sh`（9/9）与
  `gate4-forms-probe.test.sh`（12/12）的 positive fixtures 均携带 committed source identity，
  覆盖 release gate 新增的 `.flywheel-build-sha` 前置条件。
  CI 的 `teamlead 3/3` shard 另捕获 Mufasa wrapper 中已退役的
  `FLYWHEEL_CODEX_LEAD_READ_DENY` token；删除该残留后，本地精确 shard 为 249/249 files、
  2862 tests 通过（2 skipped），FLY-1241 sentinel 2/2 通过。

## S1 开工前先读 — R3 non-blocking follow-up
