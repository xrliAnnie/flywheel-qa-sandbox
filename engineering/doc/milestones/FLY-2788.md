代码复审 R1 / R2 发现 HTTP 路由把策略自动解析值混进了调用方 override：既会让新请求的手动
model 与同节点自动 arm 冲突，也会让已有冻结 arm 在策略变化后因空 override 或另一节点的 effort
返回 409。最终修正只增加一条稀疏边界：调用方 override 只保留实际提交的字段，自动选择器跳过
手动 model 节点，其他节点继续按冻结 receipt 重放并合并手动 effort；既有真实冲突检查不变。
端到端回归证明手动 implement model 返回 200 且不生成伪 arm receipt，策略变化后带无关 design
effort 的新 run 仍复用三个冻结 arm。

arm 后在合并时丢失，静默落回模板默认。修正只把自动解析节点作为合并底值，再由稀疏手工字段
覆盖；直接回归从默认 Opus 的 RED 变为实际 Fable/high，且仍不生成 implement 自动 arm receipt。
