## 交付

- Claude Lead 的 Discord 插件在 mailbox 三项接线缺任一或 capability probe
  失败时，不再绕过 mailbox 直接推进会话；消息先持久化 rejected intent，再用
  `⛔` 明示未投递。
- 主仓 `chat-ingest` 把恢复消息写成 held mailbox 行，stale 行事务性转 DEAD 并产生
  告警；CLI 协议 v2 显式返回 delivery state，DEAD 不 nudge 会话。
- 接线恢复后，插件按原始顺序和单头阻塞规则重放。相同 Discord chat 的同一故障消息
  用专用 collapse key 合成一条恢复补充说明，原始时间戳、分区、幂等键和批量上限不变。
- malformed attachment 不能通过 rejected-intent 校验时，仅丢弃非法附件元数据，保留
  消息、route、ID 与时间，仍走 persist-before-receipt 的 hold + `⛔` 路径。
- 健康路径保持 mailbox → batch → MCP channel 注入；Codex 入站代码未修改。插件版本
  从 `0.0.6` 升至 `0.0.7`，本阶段未部署或重启 Lead。
