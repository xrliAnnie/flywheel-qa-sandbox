# FLY-2096 — rework stall clock 退役与完成结算

**Status**: ⏳ Pending independent QA and ship
**PR**: pending creation from this milestone commit
**Date**: 2026-09-03

FLY-2096 点名的故障是 rework 替换体已经准入、拿到 TURN、收到 issue 并持续工作，
旧 dispatcher 却只按 delivery 停在 `wake_delivered` 的时长计龄：30 分钟告警、60 分钟把
整个 run 打成 `held`。替换体超过一小时后即使健康完工，也会被
`completeWorkflowRunNode` 以 `engine_run_not_active` 拒绝。

旧的 30/60 分钟 rework stall scanner 已由 FLY-2278 退役。本单没有再造第二套活性规则，
而是把退役行为钉成跨树回归证据，删除 `listWorkflowReworkDeliveries()` 无调用方使用的
`includeDeferred` 绕过，并补齐一个完成边界：rework 验证成功，或验证失败后链出下一轮
rework 时，delivery 的 `completed` CAS 会在同一事务内复用既有
`settleWorkflowDeliveryAttemptIfPresentTx()` 结算当前 attempt。这样已收工体在窗口消失、
心跳过期后不会继续产生幽灵 `delivery_contract_stalled` 告警。

没有新增 flag、helper、依赖、schema、migration、event kind、告警层或 hold 形状；
没有修改 `CLAUDE.md`。
