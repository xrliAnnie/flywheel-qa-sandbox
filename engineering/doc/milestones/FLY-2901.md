# FLY-2901 — 替身接管共享工作树失败时，先证明零丢失、保全，再原地清理或重建

**Status**: ⏳ Pending review, exact-head CI and QA
**PR**: #1346
**Date**: 2026-09-26

DAG 工作流的替身接管共享 branch-B 工作树时，只要树脏、有嵌套仓、HEAD 漂移、目录丢失，或未登记分支上有独有提交，Blueprint 就返回 `worktree_takeover_failed`：节点卡在 admitted，直到被判 held，再等 Lead 手工保全、清理（FLY-2893 统计约 138 单×节点小时，40 次里 21 次是额度撞墙死掉的前任连带出来的）。本单把这件事变成**能证明零丢失就自动做，证明不了就原样停手**。

1. **一次持锁的事务**（`WorktreeManager.runTakeoverTransaction`）。依次是：修复 exclude 的两条精确行 → 处理重入 → 按登记×存在分类 → 两次内容指纹（间隔 5 s）→ 两层快照（抽出 FLY-1707 算法）→ 把救援 ref 推到 `flywheel-rescue/<issue>/<前任8>-<替身8>-<时间>-<kind>`（原子推送、「必须不存在」租约、`ls-remote` 复核）→ 零丢失断言 → 规范 manifest（确切字节的 sha256 只放在事件里）→ 带校验的持久事件 → **之后才进入破坏阶段**（把嵌套仓挪走；原地 `reset --hard` + `clean -fd`；目录已丢的沿用原 generation 重建）→ 写证据镜像 → 写 cleaned 回执。崩溃后重入先核 manifest 字节哈希，再逐字段比对。
2. **关不掉的损失防线**：未登记但目录存在的，绝不 `rm -rf`；未登记分支上有独有提交的，不先推救援就绝不 `branch -D`；登记、分支尖、HEAD 任一探不准，就停手。
3. **Bridge 本地权威**：`DirectEventSink` 提供 pending 查询和 rescued / cleaned 两个 checked 事件；HTTP `/events` 对这两个 kind 返回 400；`head_diverged` 和 `nested_repo` 两类发 info 告警 `worktree_takeover_rescued`。
4. **派发器**：计算「前任不会再写」的许可证（停驻的放行；判死的必须拿到 `dead` 证明；活着的一律拒绝）；在调用时读取总开关 `worktree_takeover_rescue_disabled`；前任 head 读不到时，按 权威 → binding HEAD → 分支尖 的顺序回退，全部失败只告警一次。
5. **替身合同**：提示词新增「Worktree takeover rescue」一节，附恢复命令；进度账本接受 `--pointer rescue=…`。FLY-2122 根治：嵌套评审目标放在已 exclude 的 `.flywheel/review-targets/<repo>/` 下。
