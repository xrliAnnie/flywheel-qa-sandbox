# FLY-2313 — pending closeout 正向死亡证明与安全收账

## 交付

- `closeRunner` 与 post-merge cleanup 对 terminal `:pending` 身份先保留 tmux 的安全拒绝，再使用
  runner-family-aware quiescence policy：Codex 必须先证明 detached daemon 的 process group 与 socket 都消失，
  然后所有 family 还必须通过 tmux/discovery/host absence。只有最终 verdict 为 `dead` 才执行完整 CommDB
  finalizer，并允许 archive / Linear Done 收敛；`alive | unknown` 或缺少受保护的终态证据都 fail closed。
- 普通非 pending 身份只在 terminal CommDB evidence 加 `absent | dead_pin` 正向探针下走 ledger-only finalizer；
  `alive | indeterminate` 一律不处置通信义务。transaction 在同一个
  `BEGIN IMMEDIATE` 中复查 exact target、terminal lifecycle、当前 TURN、effective parked 与未消费的
  founder-origin wake。任一 veto 都零写并返回结构化 outcome。
- StateStore 的 durable `commdb_finalize_failures` episode 现在显式要求 `runnerDeathProven`。没有死亡证明的
  ledger-only 失败只保留 ask-disposal audit，不创建、更新或误消除“物理死亡后卡住”的告警 episode；通用告警
  文案也不再声称 runner 已死。
- kill 拒绝与 finalizer 失败同时发生时，两段错误都保留；cause 分类优先识别
  `window_identity_pending`，不再被 `commdb_finalize_failed` 或空 errors 吞成 `unknown`。
- 非 pending 的 target-local `absent | dead_pin` 可能来自 stale mapping；它只能在 terminal evidence 下触发
  ledger-only 收账，结果仍为 `physicalGone:false`，不能删除 session、归档 thread 或完成 lifecycle。
- lifecycle closeout 只接受显式 `runnerDeathProven:true + commDbFinalized:true` 为 `proven_gone` teardown，使
  post-ship thread archive 与 Linear Done 只在 execution-level 死亡已被证明时完成。
- 返工 3 把 lifecycle 的死亡证明默认值改为 fail-closed：`closeRunner` 的 crash-preserve 返回或 throw/catch
  若没有 `closed | alreadyGone | runnerDeathProven:true`，不再进入后续 target probe，也绝不调用会删除 session
  identity 的完整 finalizer。`physicalGone` / `runnerDeathProven` 缺字段不再被当作 gone。
- `:pending` 的 generalized liveness 现在先按 execution id discovery；若实际窗口已经物化，就探测真实窗口并让
  `alive` 否决死亡。只有 discovery 明确 missing 后才允许 host-wide process absence 作为最后一臂。
- 返工 4 为 crash-preserved 节点恢复合法收口：只有 family-aware execution probe 返回 `dead` 才允许
  `confirmedGone=true`。它不再直接探测 `:pending` 占位串；`alive | unknown` 与 probe 抛错都保持 blocked。
  返工 5 补齐两种合法收口：exact target 仍在时走 guarded full finalizer；identity 已缺失时走幂等 full
  finalizer，只清理孤立 ledger，不再把“没有可删除的 session 行”误判为永久失败。
- 所有由探针授权的 identity 删除现在和 ledger-only 路径共用同一个 `BEGIN IMMEDIATE` 事务守卫，原子复查
  exact target、terminal evidence、TURN、effective parked 与 founder wake；直接 kill 成功的既有路径不变。
- `blocked + ended_at` 纳入合法终态。若 StateStore 已是 `failed | blocked` 且 execution death 已独立证明，
  但 CommDB exact row 仍因镜像延迟停在 `running`，同一 guarded transaction 会先通过 TURN / parked /
  founder-wake 零写 veto，再原子 CAS 为权威终态并删除 exact identity。最终写入前会重新读取 StateStore；
  若异步探针期间状态离开 `failed | blocked`，以 `state_store_terminal_changed` fail closed。
- ledger-only stale-target absence 只结通信账，不再删除 receipt wake、shutdown control 或 stop declaration；
  这些 physical-execution 状态只在独立死亡证明也授权 identity 删除时处置。
- stale-blocker guard 不再硬编码 `runnerDeathProven:true`：缺 StateStore、已终态或 lookup gone 均记录 false，
  只有实际 teardown 成功才记录 true。post-merge 对经 family-aware probe 证明死亡的 pending runner 标记
  `tmuxClosed=true`，仅移除精确的 pending 安全拒绝，其他 cmux/tmux 错误继续阻断。
- lifecycle 单元测试的默认 `probeExecutionLiveness` seam 固定返回 `unknown`，测试不再意外 shell out 到真实
  tmux / pgrep；需要验证死亡的用例必须显式注入证据。
- `lookupTmuxTarget` 改用共享 `commDbPathForProject`，lookup、terminal evidence 与 finalizer 在
  `FLYWHEEL_COMM_DIR` / `FLYWHEEL_COMM_ROOT` override 下不再读写两份数据库。

## 存量处置的明示决定

- 同一个 `close_runner` 对“终态 + 精确非 pending target + `absent | dead_pin`”只结通信账，仍返回
  `closed:false, physicalGone:false` 并保留 session 行；`indeterminate` 不再触发这条路径。
- FLY-2152 / FLY-2166 / FLY-2169 这类 pending 存量行只有在 generalized execution probe 明确返回
  `dead` 时才会收敛；发现物化后的真实窗口、host process 存在、probe unknown/throw、TURN、parked 或 founder
  wake 都继续 fail closed。`pending` 字符串本身从不构成死亡证据。
- CommDB 镜像仍为 `running` 不再单独造成永久 held；StateStore `failed | blocked` 加独立死亡证明可以在 guarded
  transaction 内完成权威 promotion。上游“为何真实窗口名从未替换 pending”仍不在本单范围。
