## Delivered scope

- Decoupled the authenticated chat-thread HTTP capability from
  `TEAMLEAD_CHAT_THREADS_ENABLED`; that switch now remains an
  automatic/background `session_started` policy.
- Kept manual create/register/archive writes fail-closed without a configured
  `TEAMLEAD_API_TOKEN`. Manual create accepts either a Linear UUID or identifier,
  reuses the canonical thread, and remains available while automatic creation is
  disabled.
- Kept reply-by-issue independently controlled by
  `TEAMLEAD_REPLY_BY_ISSUE_ENABLED`; `/send` reuses a stored thread or creates one
  on a mapping miss even when automatic creation is disabled.
- Preserved the existing role-agnostic automatic path and added explicit
  `main`, `qa`, `designer`, and custom-role characterization coverage.
- Documented the automatic Runner, ad-hoc Lead create, reply, lookup, and archive
  triggers; their configuration; restart requirement; rollback switches; and
  placeholder-only smoke tests.

## Operational and security boundary

- Automatic create rollback: set `TEAMLEAD_CHAT_THREADS_ENABLED=false` and
  restart Bridge; Runner startup continues without thread creation.
- Reply rollback: set `TEAMLEAD_REPLY_BY_ISSUE_ENABLED=false` and restart Bridge.
- Manual privileged writes require `TEAMLEAD_API_TOKEN`; create additionally
  validates project/Lead/channel, Linear issue existence, alert-channel policy,
  and Discord bot-token availability.
- Lookup routes expose only stored issue/thread mappings and use the global
  Bearer middleware whenever a Bridge API token is configured.
- Real Bridge restart/spawn smoke testing belongs to the independent QA phase;
  this implementation node did not restart Bridge or dispatch QA.
