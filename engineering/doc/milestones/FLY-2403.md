## 最终交付

- Model registry 新增独立 alias `astra` → canonical `gpt-6-astra`，`runtimeVendor: codex`，开放 `workflow` 与 `runner` surface；`codex` 仍固定解析为 `gpt-5.6-sol`。
- `code.eng_design` 的 registry policy 内置 `modelSplit` 兜底默认：规则版本 `fly2403-v1`，奇数 issue = A/Astra，偶数 issue = B/Fable。运行时可在 `~/.flywheel/models.json` 顶层写入同形 `modelSplit` 覆盖 `enabled`、规则版本及奇偶 arm/model；每次派单重新读取配置快照，无需改代码、发版或重启。运行时段缺席时使用 registry 默认；运行时段存在但无法读取或校验失败时 fail closed，记录 warning、零分臂并回落模板固定模型 Fable；`enabled: false` 同样零分臂并回落 Fable。
- 分臂决定权位于引擎的 `resolveWorkflowTemplateSelection`：任何选择到 `tpl_code` 的 schema-v2 新 run 都按人类可读 issue identifier 解析 arm，不依赖 Lead、menu route 或外部脚本。menu route 仍负责 caller override/effort 校验；显式模型与规则冲突时 fail closed。
- 同一 issue 的重复解析稳定得到同一 arm；selection digest 同时纳入实际 node override 与 assignment receipt，防止相同 idempotency key 携带不同规则依据。
- Run materialization 事务内写入既有 append-only workflow event `design_model_arm_assigned`，payload 包含 arm、model alias、canonical model，以及 issue identifier/number、parity、rule、rule version。每次 `dispatch_vendor_resolved` 再携带相同 receipt，供运行时审计；没有新增 authority column。
- 旧的 Lead 手工 allocator、Linear issue-family Bridge route 及派单规则依赖已经删除。`simple_code` 没有设计节点，因此不参与分流；QA 跨 vendor 校验、merge/authority 均未改动。
- 对比报表仍为原四指标/十七列只读 SQL，没有改口径或输出结构。文件首页注明 `fly2403-v1: odd issue = A/Astra; even issue = B/Fable`；arm authority 继续来自 immutable `workflow_execution_runtime`，assignment/dispatch event 仅作审计依据。

运行时覆盖示例（也可把 odd/even 都指向 A/Astra 做阴性对照）：

```json
{
  "version": 1,
  "modelSplit": {
    "enabled": true,
    "rule": "issue_number_parity",
    "version": "fly2403-v2",
    "odd": { "arm": "A", "model": "astra" },
    "even": { "arm": "B", "model": "fable" }
  }
}
```

## 四项报表口径

1. 设计审通过轮数：Astra 读取 completed APPROVED `codex_review_job`；Fable 读取已交付的 current `design_review_manifest`，并共同要求 retained `eng_design node_completed` evidence。
2. 实现后 QA 打回：既有 `qa_retry` / loop evidence。
3. Founder 打回：既有 `founder_feedback_kickback` / founder-review evidence。
4. 设计节点耗时：`eng_design started_at → ended_at`。

每项同时输出 Astra/Fable 样本 N、观察窗 N、coverage 与排除计数；某臂 N=0 时明确显示 `0 样本 · 不可结论`。此前在 production 只读副本的验证结果仍为 Astra N=0、Fable 有样本；本 revision 没有伪造线上 Astra observation。
