本单完成 FLY-2248 拆出的 M3 半段。Bridge 现在从 launch commit 到 execution terminal 持续持有 `ResidentReceiverSupervisor`；首次 registration 尚不可见时保留待武装资格，Bridge boot、reown watch 与 reown revive 都会按 exact/current activation 重建 ownership。turn 进行中到件只 durable 入队为 `deferred_midturn`，不会冒充实时注入；下一 turn 边界必须提升并读取，连续 receiver 失活则复用既有 delivery-operation stalled 面兜底。

CommDB 的 `three_stage_turn` 复用为 durable turn belt：`grantTurn` 在同一事务提升 `turn_generation` 并清空旧 `active_turn_id`，首次 INSERT 明确从 generation 1 开始；runner 侧的顺序 barrier 用 RPC 返回的 turn id 与 daemon notification 幂等确认 started/completed。写入失败时不 push、不离 hold、不开下一 turn，超出固定重试期限按 `setup_failed` fail closed；reown 会先用严格解析的 `thread/read(includeTurns:true)` reconcile durable 状态，再允许 supervisor 投递。

loop 入边节点完成后，Codex 与 Claude 都进入同一 `loop_park` 路径，使用代码内固定 `RESIDENT_GRACE_MS = 30 * 60_000`，没有 env 或 flag。wake 以 revision + boundary fence 幂等恢复；过期复用既有 `workflow_delivery_operation` saga 的 `resident_expiry` kind，按 exact shutdown request 重驱到 ACK/projected。`runner_shutdown_controls` 现在以 `(execution_id, request_id)` 为主键；runtime 看到任一 pending request 就退出，并一次 ACK 全部 pending，saga 只读取自己的 request。

完成提交现在先签发 drain challenge。mailbox 与 phase-wake 水位线内仍有未消费项时返回 `consume_pending_mail`；receipt 校验、challenge `issued → consumed`、completion 插入与 DAG 推进位于同一个 StateStore 事务，业务 digest 明确剔除 `drainReceipt`，因此事务回滚和 HTTP 响应丢失都能安全重放。

R3 review 暴露的五个边界已在同一批次关闭：drain 只捕获 runner 实际可 pull/ACK 的未过期 inbox instruction/response（包括 `expires_at IS NULL` 的永久 instruction）；receiver 在 durable consumer 拒收时抛错，让 transport 保留未 ACK 消息；旧 CommDB 缺少 settlement 列时 expiry saga 进入 durable failed + 既有 alert 路径，不再无限重试；completion disposition 重建只在当前 activation/node 确实存在 resident hold 时恢复 `loop_park`；已 consumed/superseded 且超过 retention cutoff 的 drain challenge 复用 FLY-2006 sweep，issued 与近期记录继续保留。

旧 shutdown 主键的迁移由共享 `openCommDbWritable` 早期门保护。Bridge preflight 只有在 source main/WAL 的 backup 前后 hash 一致、备份 `quick_check` 通过时才写 source-bound receipt；所有 writable open 都在任何 PRAGMA/schema 写入前验证 receipt，并在 `BEGIN IMMEDIATE` 写锁内复验 source binding、schema 与 backup hash。成功后 receipt 被消费，缺失、陈旧、跨库或篡改证据全部 fail closed 且源库逐字节不变。实现没有新增 CommDB 表、env/flag 旋钮或告警家族，也没有触碰 `CLAUDE.md`、重启 Bridge/Lead、dispatch QA、merge 或 deploy。

## 独立 QA handoff

1. 启动一个 loop 入边节点的真实 worker，完成 goal 后确认 disposition 为 `loop_park`，无需人工轮询或唤醒。
2. 在 30 分钟 grace 内发一条返工欠条；确认 receiver 已常驻接收、信件 durable 入队，并在下一 turn 边界读到后重新派活。StateStore 应呈现同一 execution 的 `resident(r=1) → woken(r=1)`，且没有 replacement materialization。
3. 在 mid-goal 顺序对照中发送消息，确认当前 turn 不消费、下一 turn 必读；不要把该结果描述为实时注入。
4. grace 中途重启 Bridge，确认 boot/reown watch/revive 在一个维护节拍内重新 `receiver_armed`，并分别覆盖 Codex、Claude 与非 loop receiver ownership。
5. 阴性臂不发送 wake，30 分钟后确认 hold 为 `closed(expired)`、`runner_shutdown_controls` 中本次 exact request 为 `acked`、expiry operation 为 `projected`，held loop 确实退出；重放 cleanup 保持幂等。
