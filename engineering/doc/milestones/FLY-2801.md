# FLY-2801 — 排除 prototype raw 取样的 Biome 格式检查

**Status**: ⏳ Pending renewed effective code review and QA exact-head CI
**PR**: #1297
**Date**: 2026-09-23

PR #1291 的 Quick Gate 失败不是既有 `useTemplate` 诊断在 merge ref 上升级，
也不是 CI 缓存或 Biome 版本漂移。Biome 2.1.4 的 JSON reporter 在 main
`c5f2becd` 上给出 5128 files、0 errors、26 warnings；在 #1291 merge ref
`516f0fcd` 上给出 5134 files、6 errors、26 warnings。六个 error 全部是该 PR
新增的 `product/doc/FLY-2782-resume-standby/prototype/raw/*.json` 的 `format`
诊断；日志里可见的 `useTemplate` 均为 information，因默认 diagnostics 上限
与输出顺序被误当成了六个 error。

修复只在根 `biome.json` 增加
`!product/doc/**/prototype/raw/**/*.json`，沿用既有 evidence 原样存档豁免的做法。
这些 JSON 是探针原始取样，格式化会改变需要保留的原始字节；因此仅排除 raw
下的 JSON 比改写六个捕获文件更符合其用途，也不修改 #1291 的 head。
该精确 glob 不会豁免将来放入同目录的脚本或其他非 JSON 文件。

红侧在未改配置的 `516f0fcd` 上精确复现 5134 files、6 format errors、exit 1；
把同一行精确 JSON 配置放入隔离的该 merge-ref worktree 后，重放得到 5128
files、0 errors、26 warnings、exit 0。另外的范围负例证明：旧的整目录 glob
会跳过 `prototype/raw/probe.mjs`，收窄后同一文件被 Biome 扫描并产生预期的
format error。临时 probe 已删除。本分支 `pnpm lint` 同样通过（5128 files、
0 errors、26 既有 warnings），`biome check biome.json` 与 `git diff --check`
均通过。该 Biome 配置改动没有 TypeScript/API/package 消费者，因此当时没有
相关 package build、typecheck 或 Vitest 用例可运行；没有把聚焦验证称为
full CI。

QA 的首轮 exact-head full CI（run `35825897208`）证明 Biome 修复与 Quick Gate
均已通过，但 `Unit (teamlead 2 of 4)` 在 3508 个测试中的唯一失败是既有 real-tmux
测试在 `pane_dead=1` 时仍未拿到退出码，得到 `"1"` 而非 `"1 42"`。原来的
30 次采样不是约 1.5 秒；因每次真实 tmux 调用本身约 130ms，实测 wall-clock
预算为 4.6–5.4 秒（文件注释估算约 3.4 秒）。首轮 rework 复用同文件已有的
20 秒证据预算与 deadline 轮询，仍保留严格的 `"1 42"` 断言且不改生产行为。

第二轮 exact-head full CI（run `35834235481`）再次证明 Quick Gate 与 Biome
四组证据均为绿色，但同一测试在 `parallel` 项目耗尽 20 秒后仍只得到 `"1"`；
该文件总耗时 21348ms，`Unit (teamlead 1 of 4)` 因这一项失败。继续加等待预算
因此被否决。复审进一步推翻了 CPU 争用假设：同一 parallel worker 内，使用同一
20 秒预算读取同一 `pane_dead`/`pane_dead_status` 的兄弟测试，其子进程先
`sleep 1` 再退出，并在 1096ms 拿到 `1 42`；只有微秒级立即退出的 fixture
耗尽 20115ms。21348ms 是失败时烧掉 timeout 后的文件总耗时，不是
`ci-test-costs.json` 所声明的 single-fork 正常成本，因此尝试用该数值强制
serial 的改动已完整回退，真实 728ms 登记保持不变。

实际不对称来自 fixture：`/bin/sh -c 'exit 42'` 可能在 tmux pane 完成绑定前就
退出，出现 `pane_dead=1` 而 status 永久为空。该用例要证明的是无 client locale
时保留 pane 的可打印协议，不要求覆盖“进程立即退出”这一额外条件。最小修复仅把
fixture 改为 `/bin/sh -c 'sleep 1; exit 42'`，与已在同一 CI worker 证明有效的
兄弟用例保持一致；严格的 `"1 42"` 断言、20 秒失败预算、parallel 分类与生产
代码均不变，也没有 skip 或能力探测。

分类负例确认该文件不在 serial，阳性确认它仍在 parallel。原失败断言在 parallel
下连续 3 次通过（约 1.3–1.4 秒），owning file 30/30、`vitest related` 30/30、
`scripts/__tests__/teamlead-shards.test.mjs` 9/9 均通过；
`pnpm --filter "flywheel-teamlead..." build`、`pnpm lint`（5128 files、
0 errors、26 既有 warnings）、目标文件 Biome 检查与 `git diff --check` 均通过。
full-suite 证据仍只由 QA 的新精确头 CI 提供。

消费者搜索分别使用变更测试文件的完整路径、文件名和父目录。命中项全部排除：
`engineering/doc/**`、`product/doc/**` 与 `engineering/doc/FLY-2681-*/data/**`
只是历史文档/清单；`packages/claude-runner/test/fixtures/kill-path-inventory.json`
是静态 kill-path 盘点；`packages/teamlead/ci-test-costs.json` 是
`vitest.shards.mjs` 实际读取并决定 serial/parallel 的可执行输入，因此本轮也
明确验证并保持其 728ms 正常成本不变；
`scripts/lib/path-hygiene.sh` 是路径清单；`scripts/qa-fly-1239-e2e.mjs` 只有注释；
`scripts/__tests__/v2-retirement-cleanup.test.sh` 仅命中父目录且不引用本文件。
其余命中不执行本断言。直接覆盖为 owning test file 的 30 个测试；分片守卫
9 个测试另证分类和文件集未被这次回退改变。

实现节点没有关闭/重开或推送 #1291，没有触发其 CI、land、merge、ship，也没有
dispatch QA、deploy、restart 或生产状态变更。本文件是 PR 的 literal-last
commit；后续 review 与 CI 必须绑定此精确头。修复合入 main 后，#1291 需要生成
