# FLY-204 implementation milestone

**Issue**: FLY-204 — [Bridge watchdog observability — idle heartbeat / health exposure](https://linear.app/geoforge3d/issue/FLY-204/bridge-watchdog-observability-idle-heartbeat-health-exposure-fly-195)
**Date**: 2026-08-30
**Reviewed implementation head**: `ed1b1cbd5c6c672ad38820257faee6e08ff91136`

## Delivered scope

- Added a read-only `RunnerIdleWatchdog.health()` snapshot with timer lifecycle,
  configured poll interval, in-flight state, last completed poll timestamp/result,
  and the count of sessions whose status is `running`.
- Records successful empty polls as `ok` with `activeRunningSessions: 0`, records
  contained top-level poll failures as `error`, and preserves the overlap guard.
- Added a late-bound watchdog health provider to `startBridge` and exposed its
  snapshot as the additive nested `/health.watchdog` object.
- Standalone `createBridgeApp` callers and the pre-bind boot window receive a
  stable unavailable snapshot (`pollIntervalMs: null` and null observation
  fields) instead of omitting the watchdog surface.

## Preserved behavior

- No watchdog cadence, timer count, idle/stuck detection, deduplication, alerting,
  event payload, or environment-variable behavior changed.
- No periodic log heartbeat or additional polling loop was added.
- `/health` remains unauthenticated and returns HTTP 200; its existing `ok`,
  `shuttingDown`, `uptime`, and `sessions_count` semantics are unchanged.
