## 交付

- Codex launch snapshot 现在持久化原始出生 label；fresh dispatch 在任何凭证或 `CODEX_HOME` 写入前拒绝缺失
  label。legacy recovery 只从同 execution marker 的真实 tmux inventory 恢复窗口名；无法证明时继续恢复
  resident App Server，但显式 suppression founder window 并发送一次准确的 `label-unavailable` 告警。
- founder TUI 创建成功前必须在新窗口上写入并回读 `@flywheel_exec_id`。marker 写、读和 rollback 都使用裸的
  immutable `@N` target，窗口在 settle probe 后消失时会 fail closed 为 `marker_unproven`，不会让 tmux
  回退到 shared session 的 active window、覆盖别的 runner marker 或返回 ghost success。
- 创建前 purge 同时按 base session 的同名轴和全机 execution-id 轴收敛，linked cmux alias 按 immutable
  window id 去重；只 kill 两轴命中的 `@N`，随后重新确保 base session，并在两轴都为空后才创建。
- legacy inventory 恢复出的已清洗窗口名作为 exact `windowName` 传入，不再二次 sanitize 导致尾部 `-`
  消失和 cmux workspace 分叉。全局 recovery inventory 先按 execution marker 选行，再验证匹配行，单个无关
  malformed tmux row 不会让所有 Codex recovery suppression。
- claude-runner 的全机 execution-id purge 同样改成 marker-first：先跳过不属于本 execution 的行，再验证命中行
  的 session/id；别的 session 一条畸形数据不再毒化本 runner。rollback residual probe 现在区分 `undefined`
  （探针失败）、空 stdout（确认已消失）和非空 id（仍有残留），不再对真实 tmux 的空结果发假告警。
- live recovery 同时传回 human-readable `label` 与 exact `windowName`：transcript header 恢复 label，同时 adapter
  仍优先使用原始窗口名，不会重新 sanitize。
- 两个既有 QA harness 已补齐新必填的 `executionId`。旧的 adapter 后置 marker publisher 已删除，CommDB
  只有在创建函数完成 marker proof 后才从 `:pending` pin 到 immutable window id。

window 有意 suppression，CommDB 保留 `<session>:pending`；现有探活轴可能因此报告 absent。在 FLY-2303
落地前，巡检会看到更多这种假红。Lead 接受该临时代价（假红优于假绿）；消化该输入的探活轴明确归
FLY-2303，本单已在写入该 `:pending` 的代码点留下所有权注释。

本实现没有操作 production tmux/socket、kill production runner、修改凭证或 secrets、重启 Bridge/Lead 服务，
也没有 dispatch QA、请求 ship、merge 或 deploy；FLY-2303 所属的 probe-axis/self-heal 不在本单实现范围。
