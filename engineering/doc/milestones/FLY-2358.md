## 交付

Generalized Codex runner 的 `CODEX_HOME` 现在按 `(project, workflow role)` 稳定解析到
`codexHomesRoot()/agents/<project>/<role>`。同一对跨执行复用同一家，不同 project / role（包括仅大小写
不同）不会相撞；家只在第一次准入时创建。没有可信 workflow role、或部署前已经起跑的执行继续使用原
`<executionId>` 家，恢复时不迁移。

并发裁定采用共享持久家路线 (a)。Codex 自身并发依据包含真实双 app-server、09-02 真凭据双臂和锁/
软链实验；Flywheel 侧用每家短 mkdir lock、原子 marker、每执行租约与持久 session 反查处理装配臂、
凭据清扫、恢复和 reaper。8 个独立 Node 子进程同时首次 `admit + provision` 同一家，得到同一路径与同一
生效臂、8 份租约、唯一 marker、可解析 config 和 8 条 worktree trust。

键式家不随任务删除：删除入口明确返回 `agent_home_protected` 并记录拒删；unknown 身份 fail-closed；
旧式 executionId 家删除语义不变。最后一个租约退出才擦除家内 GH_TOKEN；Bridge 启动清扫按 durable
session 身份处理终态/孤儿租约，活执行身份漂移时拒动并告警。没有清理任何既有一次性家，没有触碰公共
`~/.codex`、节流闸或 `CLAUDE.md`。
