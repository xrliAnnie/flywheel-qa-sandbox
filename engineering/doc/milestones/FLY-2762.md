# FLY-2762 — Codex 号池改为 profiles 目录枚举

**Status**: ⏳ Pending exact-head CI and QA
**PR**: https://github.com/xrliAnnie/flywheel/pull/1294
**Date**: 2026-09-22

本单删除了运行时对 `school` / `personal` / `business` 三号名单的依赖。Codex 号池现在从
`~/.codex/profiles/*/auth.json` 枚举，目录名就是 profile 名；`personal1`、`personal2`、
`shopping` 与原三号走同一套逻辑，未来新增目录和登录凭据也不需要再改代码。重复 profile、
重复邮箱、primary 不唯一、符号链接与非普通凭据文件继续 fail closed。

`codex-profile list/use/save/status` 已切到动态号池。list 保留离线身份信息，并结合 Bridge
真探快照显示邮箱、plan、token 状态、额度与重置时刻；刷新入口只允许 loopback Bridge，
不会把 bearer token 发往外部主机。use/save 对枚举出的任意 profile 一视同仁，测试夹具已
覆盖 shopping 与 personal1，不接触真机账号。

Teamlead 的 observer、候选选择、切换通知、outbox、恢复、capacity snapshot 与账号页都改为
消费同一动态 pool。账号页不再写「Codex 三号」，会渲染快照中的全部账号，并把吊销、未登录、
已打满拆为不同 token/额度状态。历史 v1 capacity fact 仍可按注释明确的 legacy 三号顺序读取，
但新快照写 v2 的显式 `{profile, accountKey}` pool，legacy 常量不参与当前枚举。

代码复审先发现两个 HIGH：pool-exhausted 观测超过 60 秒后会误绕过 backoff，以及 real-tmux
测试仍按旧 `.profiles` 结构读取 v2 注册表。前者改为只有上次事实中不存在的新
`{profile, accountKey}` 才提前重探，并以 61 秒老化回归证明旧号池继续服从 backoff；后者改为
从测试自己的临时 profiles 目录调用生产 loader。随后首个 PR CI 的 FLY-1663 shell lane 又真实
暴露最小 source home 没有 profiles 目录的兼容性回归；runner 现仅在根目录确实缺失时回退到
既有 account-id 身份推导，测试夹具则创建动态 business slot。Lead 指定修复的
missing/read_failed 页面语义也已补测试，坏号保持红色不可用。
