# FLY-2819 — Voice launchd migration waits, records errors, and retries

**Status**: ⏳ Pending exact-head review, PR CI, and QA
**PR**: pending creation from this milestone commit
**Date**: 2026-09-23

The deploy-time voice migration no longer runs `launchctl bootstrap` immediately
after `bootout`. It waits up to 40 bounded polling attempts for launchd to report
the old `com.flywheel.voice` label absent, then retries bootstrap up to five times
with linear backoff. Every failed bootstrap attempt records its exit code and
verbatim stderr in `VOICE_RESTART_DETAIL` and the restart log. After a successful
bootstrap, a separate five-attempt visibility budget waits for the complete
on-demand registration contract, so reducing the bootstrap retry count does not
remove the post-bootstrap grace period.

`restart_voice_managed` now distinguishes the deployed residual that blocked the
2026-09-23 shuttle: when the on-demand plist is byte-identical to the repository
contract but the label is explicitly absent, it restores the registration and
verifies the complete contract. Before that recovery, it reuses the authoritative
non-Lead disabled-override parser. An explicitly disabled label and an unreadable
override database both fail closed without bootstrap or fleet rollback. A
bootstrap that returns non-zero but actually registered the correct label is
accepted after an identity re-probe instead of being retried into a false failure.
The active-call deferral, unknown-session deferral, dormant on-demand behavior,
and unknown-drift refusal from FLY-2701 are unchanged.

TDD evidence is causal. Against the pre-fix baseline, the ten original FLY-2819
scenarios all fail. Against code-review R1 head `e1d129ae1`, the four review
revision scenarios fail: disabled recovery, unreadable disabled overrides,
registration despite bootstrap error, and visibility grace with one bootstrap
attempt. The current implementation passes all 14 FLY-2819 scenarios. Direct
consumer verification also passes: voice wrapper 32/32, voice installer 9/9,
and restart-services 175/175. `pnpm lint`, Bash syntax checks, targeted shellcheck
(excluding the two pre-existing dynamic-source/declaration patterns), and
`git diff --check` exit zero. No TypeScript API or package build changed, so no
package build, dependent typecheck, or Vitest-related run applies.

Consumer discovery retained the executable matches in `restart-services.sh`,
its aggregate shell suite, the voice wrapper and wrapper suite, the launchd
installer and installer suite, and the focused restart suite. The remaining
matches are historical design/review documents or the current FLY-2819 docs and
do not execute this seam.

Code review R1 requested the disabled-override guard and identified the
post-error registration race; both have executable regression coverage. R2
approved implementation head `c9a0d9393` with non-blocking advisories, which were
reported to the Lead. Exact-head review is repeated after this literal-last
milestone commit. Exact-head aggregate CI and QA remain downstream-owned.

Implementation did not dispatch QA, merge, ship, deploy, restart services, or
touch a production launchd domain. Real-machine launchctl validation was not run
because the issue explicitly limits it to the 529 slot or a pure test domain;
this implementation node had neither authorized target. All launchctl evidence
here is hermetic and stateful.
