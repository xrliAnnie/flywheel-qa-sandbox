## 交付

`test-deploy.sh` 现在给所有 slot Bridge 固定使用 owner-only 的
`/tmp/flywheel-test-slot-<N>/tmp`，不再继承 runner 的长 `TMPDIR`；按最长 slot
编号计算的 tmux/tsx IPC socket 仍低于 macOS `sun_path` 上限。三个 Bridge 启动边界都显式清除
ambient `VERCEL_TOKEN` 与 `FLYWHEEL_REPORT_HOST_OVERRIDE_URL`，默认房型不会误接生产 token、其它
slot 的 loopback host 或调用方临时目录。

有 API token 的 generalized / reply-by-issue 房型会生成独立的 0600 report token，并通过既有
Bridge launch spec secret 文件注入。一个只监听 `127.0.0.1`、使用 Node 标准库的 slot-local report
host 实现报告发布所需的 Vercel API 子集和静态页面服务；Bridge 只接受精确
`http://127.0.0.1:<port>` override，远端、别名、路径、query、userinfo 和越界端口均在任何状态
mutation 前拒绝。生产默认仍逐字走 `https://api.vercel.com`，QA override 下旧
`/api/publish-html` 明确返回 503，避免出现第二条混杂发布路径。

report host 是 Bridge 的直接子进程，由 wrapper 启动后 `exec` 原 Bridge 命令；Bridge 正常退出、
被杀、cycle 或 teardown 后，host 通过真实 PPID 监视自退，不新增 stop 脚本、pid 账本、daemon、
timer 或生产生命周期分支。部署以完整站点 staging + rename 替换并串行化并发写入，bearer、请求体、
文件数量、schema、路径 containment、symlink 与 partial-body 失败均 fail closed。

slot Bridge、Lead 和 playbook 的 operator recipe 都传递同一个 slot-local
`FLYWHEEL_REPORTS_DIR`，因此 registry、HTML 与 proofshot preview 不会落到生产
`~/.flywheel/reports`。`test-deploy.sh` JSON 同时公开 `bridgeTmpDir`、`reportsDir` 与不含 secret 的
report-host 坐标，供 QA 按文档执行真实 `publish-report → 截图 → Discord` 验收。
