# FLY-2111 — runner patrol pane-SHA safeguard 返工

**Status**: ⏳ Pending ship
**PR**: #969
**Date**: 2026-08-27

本次有界返工把 FLY-2080 修复配方的事后接力证明改为 event-first：只有 baseline 后由引擎写入的非 patrol `workflow_run_event` 才能支持 `fixed` / `advanced`。事务前的真实性保证仍保留；pane 只允许 40 行有界诊断，不留原文、不建指纹、不做前后比较。

> **已知范围风险**：STEP 2 仍保留全 scrollback SHA 比对这一同形操作。批准方案将它留在本单范围之外，因此静态测试通过不代表黑盒 safeguard 已消失；部署后的 Fable 100 条消息观察才是唯一结论。

| rewritten passage | original FLY-2080 guarantee | new evidence |
| --- | --- | --- |
| Step A 事后接力规则 | 修复 transaction commit 后必须证明引擎真的接力；SQL `changes()==1` 不能单独支持 `fixed` / `advanced`。 | 新 event 必须满足 `seq > BASELINE_SEQ` 且 `event_uid NOT LIKE 'patrol:%'`；没有 event 时只留下有界诊断和下一动作。 |
| 附录 A 事务前真实性与事后接力 | pane/commit/TURN 必须证明 `preferred_actor_execution_id` 完成 rework，否则 receipt 为伪造；事务后必须证明 Bridge launch/advance。 | 事务前保证原样保留。pane 限于 `capture-pane -p -S -40 ... \| tail -40`，不落原文、不哈希、不做前后比较；事后只认新的非 patrol engine event。 |
| 附录 B replacement 与 predecessor 分支 | replacement 补账、dispatcher launch 与 predecessor recovery 必须可审计、可行动，不能把 rows changed 当进展。 | 两条分支复用 event baseline，只认新的非 patrol engine event；event 为空时只记录 `pane_marker`、`observed_at` 与 `next=inspect\|repair\|retry:<token>`。 |
