# FLY-2177 — code review 配额失败自动恢复

**Status**: ⏳ Pending ship
**PR**: #996
**Date**: 2026-08-30

为 code review 的 Claude 配额失败补齐了后续 consumer：Bridge 从真实 429/session-limit
错误中解析 reset 时间，持久化 `retry_at`，并在 reset 后对同一 request id 做带 grace、jitter
和次数上限的自动重试；重启会恢复 durable timer，执行前重新校验 gate、PR head 与托管
feature flag，异常路径保持 fail closed。失败同时进入结构化 Lead 告警，巡检 STEP 4 也会列出
仍可行动的 failed review job，并避免无归属行拖黑整个项目快照。

QA 首轮发现告警虽已生成，但 emitter 把 `flywheel:<issue>` 当作 `sessionKey`，而生产 router
按 execution id 查 session，导致 `review_job_failed` 的 issue-thread 路由不可达并退化成 ticket。
rework 将 emitter 改为携带 `session.execution_id`，用真 StateStore、真 emitter 和真
`buildInfraAlertRouting` 补了 owning issue thread 正例与错误 key 退回 ticket 的对照，并把
该 kind 的 fallback owner 合同对齐到 human issue-progress lane。QA 固化探针已从 ticket 翻为
`ISSUE_THREAD`，FLY-2155 真实 429 failure replay 仍为 20/20。

跨模型 code review 在代码头 `4dcdcdb59` 上 APPROVED。最终验证包括 `pnpm lint`、
`pnpm -r build`、75 个直接路由/合同/effect 测试、195 个巡检脚本断言，以及除
Terminal.app 真机用例外的 core 219/219。完整 `pnpm test:packages:run` 已执行并在两条未修改
的 macOS Terminal.app 自动化用例上失败；补偿性的 non-core 全量并行运行达到 9852 通过，
其中 2 条负载敏感超时均单独复跑通过（19/19、22/22）。因此不把当前本机环境记为全绿：
这类负载/env 敏感集成测试在隔离运行时通过，但并行全量仍可能受宿主状态影响。

已知边界：周限额 reset 超过 review gate 72 小时 TTL 时仍有意 fail closed，由告警/巡检通道
兜底；无 CommDB owner 的失败目前安全剪枝，但尚未输出聚合计数；统一改用 execution id
也会让四个 sibling review alert 在部署后采用新的 correlation key，可能留下旧 active mapping，
但不影响 event-id 去重或本次 failed-job 的 issue-thread 可达性。
