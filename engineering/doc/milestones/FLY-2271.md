## 交付

- A：切号子进程的启动状态、exit code 与脱敏 stderr marker/detail 现在贯穿 typed result、quota-monitor 日志、状态与告警，Bash 也会在 atomic-apply 合同检查前写审计 entry。
- B：旧 daemon 调用新脚本造成的 atomic-apply 合同错配现以独立 exit 48 / `apply_contract_mismatch` 分类，不再伪装成 `active_marker_drift`。
- C：daemon 对真正的 marker identity drift 在锁外执行与手动入口相同的严格 identity probe、anchor 唯一匹配 reconcile，并只重试一次，未放松 FLY-1201 的委托零 mutation 边界。
- D：可摘除的 restart helper 以 launchd domain、进程身份和 runtime tree hash 判断旧码，并由部署脚本的一处最小 hook 重启 stale quota-monitor，不触碰 FLY-2280 的 takeover/admission 区域。
- E：隔离台架覆盖 token rotation、true identity drift 和正在运行的 old daemon，保存脱敏的 baseline/current 对照证据并检查 fixture token 零泄漏。

## 关键结论：token 轮转假设被否定

1. token rotation 台架中，baseline 与 current 的手动入口都成功切号，并各写一对正常审计 entry/exit。
2. 同一 token rotation 台架中，baseline 与 current 的 daemon 入口也都成功切号，而不是 baseline 46。
3. 四条成功路径都通过唯一身份匹配把 rotated live credential 严格 capture 回 active slot；真正失败的是跨身份 drift，以及 old daemon 与新脚本的 atomic-apply 契约错配。
