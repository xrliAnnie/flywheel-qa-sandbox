# FLY-2076 — Claw Alerts 全队列值守与热开关

**Status**: ⏳ Pending ship
**PR**: #963
**Date**: 2026-08-27

Claw 不是新 agent；原有 `claude-infra-bot` 拿到 Alerts 频道唯一全队列值守职责。
接入复用 FLY-2075 修复后的主管道：普通告警进入 durable Claw mailbox，
`workflow_engine_escalation` 继续走既有 Hub/Discord，不新增告警层、噪音判断层、指标或
值守 hard limit。Cass 退出初审，“谁都不救自己”边界不变。

## 落地内容

- 角色合同只允许三种初审去向：① 确定能解则直接处理并立刻写 runbook；② 不能解则查
  contact book 后转负责人；③ 查不到则兜底转 Tadashi。无 runbook 且不确定时只读日志与
  状态，不修改系统状态试错；堆积必须主动报告，收场必须补 R8 根因线。
- capability-scoped duty API/CLI 支持 outstanding、ack、handoff、resolve；episode fence
  防止旧 thread 误改复发告警。outstanding 单批有界但不限制最终处置总量。
- store-managed `alert_system` 加入 `flag_values` / `STORE_MANAGED_FLAGS`，默认 ON，逐次读取，
  修改后无需重启。OFF 时告警仍落既有账本，但不进 Discord、不建工单、不投 Claw mailbox；
  queue、workflow/land outbox 与 founder `emit_alert` action 均保留，ON 后继续投递。
- OFF 审计使用独立 `alert-system-suppressed:<eventId>` 身份，不占正常投递去重槽；同一稳定
  event ID 可在热开启后成功进入主管道。
- OFF 同时是 drain supervisor 的有意静音状态：即使旧 alert queue 非空或超过容量，也不把
  `remaining > 0` 误报成 `drain_stuck` / `queue_overflow` founder 桌面元告警；队列仍原样保留，
  ON 时真实的 stuck 检测照常工作。
- 本单没有实现 flag 的 CI 拦截或存量迁移，也没有部署、重启或触发紧急 restart。
