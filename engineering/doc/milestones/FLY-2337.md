# FLY-2337 — 终态收件死信不再冻结活 run

## 交付

- 发给终态 execution 的 runner mailbox 只有在 successor 不存在、grace 已过、recipient 已终态且
  无近期 liveness 时才产生一条 non-holding warning；物理 source 必须先为 DEAD。warning、
  `source_terminal` settlement 与 episode close 在同一 StateStore 事务完成，run 始终 active。
- Bridge maintenance 重扫已终结 attempt 时 `examined=0`；升级前已写 warning 但仍 open 的 DEAD
  episode 也会经过同一 safety gates 后补 settle/close，不重复告警、不复活 late successor。
- `cancelMailboxDelivery` 把任何已 DEAD runner 行视为幂等成功，包括已有 reroute fence 的 source；
  精确 cancellation replay 仍返回 `idempotentReplay:true`，foreign-terminal no-op 不改写原字段。
- DEAD response 不再进入 mailbox reroute：attempt 以 `response_reroute_unsupported` settle，episode
  关闭为 `terminal:settled:response_reroute_unsupported`，并写一条明确要求改发新 instruction 的
  guidance warning。既有 staged `reroute_to` hold-resume 也走同一收口并推进到 projected；物理 DEAD
  row 的 `dead_reason`、`ref_id` 与 `superseded_by` 不变。
- project-scoped legacy reconcile 只扫描仍 held 且尚无 `hold_resumed` receipt 的目标 hold，并要求
  running/review node、无 `held|needs_lead` rework/carrier（包括 `run_inactive:*` carrier）、无独立
  run hold。它固定 canonical cancel，绝不
  自动 reroute DEAD response；后者会撞 `mailbox_unique_response` 的 `ref_id` partial unique fence。
- scanner 快照后的全部 eligibility guard 会在 operation insert 事务内复核，并在
  `applied → projected` 激活事务内再次复核；竞态出现时不写 receipt、不激活 run，已完成 physical
  cancel 的 operation 保持 applied，blocker 清除后可重试 projection。
- failed reconcile operation 最多生成两次独立 retry generation；耗尽后只写一条 deduped
  `legacy_dead_mail_reconcile_exhausted` warning。settled/superseded/missing attempt 对 operator 仍
  `resumable=true` 并走 canonical terminal no-op；live attempt 缺 physical projection fail closed。
- caller 的 source-resolution hint 必须与 StateStore 权威状态完全一致，不能把 live source 伪装成
  terminal no-op。schema 只新增/迁移既需的 `resolution_reason`，未引入 reroute authority 字段。
- FLY-2332 / FLY-2324 / FLY-2259 / FLY-2146 四种生产形状均有 fixture；其中 FLY-2324 覆盖
  LEASED mailbox source，FLY-2146 的 terminated-run 负控保持 fail-closed。
- founder-review gate response、当前 design manifest 与未知 recipient 状态仍受原有保活守卫保护；
  每条拒绝 terminalization 的 row 会以 `terminalization_refused:<sourceId>` 确定性 identity 写一条
  durable Lead notice，重复 tick 不重复。terminal no-op 语义严格限制在 mailbox family，未修改
  authority/approval/claim 表，也未改变有活收件人的其他 FLY-2278 reroute 语义。
