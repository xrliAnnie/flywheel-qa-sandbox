# FLY-2807 — 额度页 E20–E23 只读探测修复

**Status**: ⏳ Pending QA@2-rework exact-head code review
**Date**: 2026-09-23

本单按 FLY-2777 E20–E23 修的是数据源，不靠排序、灰标或角标遮缺口。
Codex 正在使用的账号此前在 observer 中命中 `inUse !== false` 后直接
`continue`，因此一项窗口都不读；现在 `inUse === true` 走固定 WHAM origin 的
GET，只读 access token 与 account identity，不刷新、不写 auth、不拿 lease，
inventory unknown 仍 fail-closed。401/403/身份不符/网络或畸形响应都有安全枚举，
不会用猜测值补洞。

Claude `personal1` 从 9/08 起不是普通瞬时失败：usage 返回
`forbidden:oauth_not_allowed_for_organization`，而同一凭据的 profile 明确返回
`subscription_status=canceled`。新增的页面专用 detail observer 同轮独立读取
usage/profile/prepaid，只把无秘密的订阅枚举与逐卡到期日写进 store；取消状态只
影响额度页 observation，不写账号 unavailable、不改变 failover 或切号。页面只在
profile 明确 canceled 且同轮 usage 非 ok 时用「已取消」遮旧值；usage 已恢复 ok 时
继续显示新额度，旧的 canceled observation 也按 detailObservedAt 灰标，不把陈旧结论
伪装成新结论。

并入本单的 E20/E21 同时落地：Claude 第五列改为真实 prepaid
`tranches`/`promo_tranches`（null、空数组、多张严格区分），接口返回 null 或 unknown
时才允许带 `confirmedBy`/`confirmedAt` 且位于受限 state dir 的手填回退；显式路径
和中间目录 symlink 不能逃出该目录。Claude 表仍保留 Fable 周用量列。Codex
`rateLimitResetCredits` 改按对象的 `availableCount` 与 `credits` 解析，保留
null/empty/truncated 语义与 version-1 legacy `{known,value}` 回滚字段；携带旧兑换卡时
单独保留该字段的 observedAt，不再借用本轮账号读取时间。两类卡片到期日均带年份。
页面只展示兑换卡张数/到期明细，从未调用 consume RPC。

真机验收全程未切 canonical、未登录/登出、未写凭据：Codex 修后只读得到
plan=`pro`、weekly=`35%`、reset=`2026-09-29T23:51:17.000Z`（该次响应未暴露
兑换卡）；Claude `personal1` 得到上述 forbidden + canceled，其他四个 Claude slot
读取成功。三份受控 auth/credential 文件的 SHA-256、mtime、size 在探测前后逐项
相同。Claude 真机没有非空 prepaid 样本，因此不伪造；多张逐行与 null/empty 由
contract tests 覆盖。

首轮 effective code review 的两项 HIGH 与五项 advisory 已逐项处理：null 手填回退、
canceled/usage 同轮守卫、pool root 读失败不清空、Fable 列、兑换卡字段级时间、年份、
显式路径与 symlink 边界都有回归断言。

QA@1 claim 1421 又发现两处 E21 上游 schema 误读：逐卡 `expiresAt` 实际是 epoch
seconds，旧 parser 当成 milliseconds；对象省略 `credits` 键时，旧 parser 还会连已知的
`availableCount` 一并丢弃。修订后到期秒数乘 1000 再转 ISO；`credits` 缺失或 null
统一保留已知张数并表示“明细未知”，而显式空数组仍保持“已查且为空”。对应测试先以
2 个失败断言复现，再在最小 parser 改动后转绿。

QA@2 claim 1422 补出同一 schema 的最后一个可选字段分支：单张
`RateLimitResetCredit.expiresAt` 可以省略。旧 parser 把 `undefined` 当成畸形时间，导致
整组兑换卡退回 unknown 并丢失有效的 `availableCount`。新增红臂用例先稳定复现
`known:false`；最小修订把缺失字段与显式 null 一样映射为该卡 `expiresAt:null`，保留
张数与其余已知到期日，其他非空畸形类型仍 fail-closed。修后页面可显示
“2 张”以及该卡“到期未知”，不会退回“兑换卡未暴露”。
