## 交付

Bridge 在 `session_started` 已持久化 running session 后，会通过统一路径把 Linear 的 backlog/unstarted issue
推进到该 team 排位最前的 started state，并回读确认 `statusType=started` 且 `startedAt` 非空。路径不按 role 或
adapter 分支，因此同时覆盖今晚失效的 implement/codex-tmux 与 design/claude-tmux。

写入前后各读取一次 issue：triage、canceled、completed、不可读或并发变更都 fail closed；已经 started 且
`startedAt` 有值时不重复写，started 但时间缺失时也不降级重写。Linear SDK 错误或 15 秒超时不会回滚已在跑的
session。每次实际尝试只持久化一条 `linear_issue_start_outcome`，只含稳定 error class，不保存上游原始错误文本。

功能默认开启，只有 `FLYWHEEL_LINEAR_STARTED_SYNC=0` 关闭。隔离 QA Bridge 在共享 env block 中显式关闭写入，
同时保留 Linear key 供原有只读 hydration 使用；该一行位于最终 slot-local `FLYWHEEL_STATE_DIR` append 之前，
保持三条 Bridge 启动分支一致。没有新增依赖、schema、重试队列或历史 issue 自动修复。
