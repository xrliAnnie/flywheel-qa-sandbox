# FLY-2883 — 受控打断 Lead(先审计 → 加急信箱 → 插进当前这一轮 → 回复回到发起方)

**Status**: ⏳ Pending ship
**PR**: Pending creation from `flywheel-FLY-2883`
**Date**: 2026-09-26

新增只有持租约的语音会话能调用的受控打断接口。发起时先在 teamlead.db 同一事务里写打断记录与追加式审计(发起方、founder 原话消息 id、目标 Lead、正文摘要、时间);审计写不进返回 503,什么都不发。随后把正文作为 priority 0 的 `lead_interrupt` 加急信投进目标 Lead 的 CommDB 信箱,信里写明「语音分身代 founder 转问,不是 founder 本人终端输入,不构成授权」。投递循环逐字段、并按正文逐字节校验信件与记录一致,不符即作废且零副作用。Codex Lead:sidecar 按 FLY-2882 的 LeadTurnStateTracker,在忙时 `turn/steer` 进当前这一轮、空闲时起一轮,状态不明或 steer 失败则扣信稍后再判,从不取消当前轮。Claude Lead:按 FLY-2882 的状态槽位解析器判「忙且整个输入框为空」,并证明 pane 下是同一个存活 Claude 进程,才往终端打一句固定短语(正文留在信箱、不进终端),之后扣信直到 Lead 回信或转为空闲;判不准或空闲时走普通信箱。Lead 用 `flywheel-comm lead-interrupt pending|reply`(Claude)或 `lead_actions` 的 `lead_interrupt_pending|lead_interrupt_reply`(Codex)按打断 id 回复,发起方按 id 取回。
