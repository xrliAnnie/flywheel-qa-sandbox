**Status**: ✅ Implementation frozen; exact-head review and CI required

## 交付

- 保留现有 `POST /api/runs/:runId/rework` 与全部批准语义，只修正 operator
  rework 的来源署名；Lead 提交不再写成 founder-verbatim，也不产生
  `founder_approval` source event。
- rework request、authority context、wake/event payload 与 replacement dispatch
  统一携带 `authority: "lead"`、`actor`、`lead_feedback`、显式可空的
  `founder_quote`，并在展示文本中分块标明 `lead:<id>`。
- 路由优先使用显式 `leadId`，缺省才使用 run 的 `selected_by`；两条路径均经过
  project roster 与 reserved/snowflake attribution 后卫，未分配的历史 run 可由
  显式合法 Lead 接管返工，不能冒充 `bridge` 或 Discord snowflake。
- StateStore schema/migration 对 Lead 行实行条件完整性约束，并把署名字段继续传播到
  chained replacement writer；replay 对旧 receipt 保留滚动兼容，但新 receipt 按
  authority-aware 字段比较，冲突时不写入。
- dispatcher 在 spawn 前交叉校验 request 行与 authority context；任何署名、反馈或
  founder quote 漂移均 fail closed。founder 原有替换文本路径保持逐字不变。
- Lead 代交仍保留既有 `workflow_founder_gate_verdict` 审计行：request authority 保持
  `lead`，而 gate ledger 继续按引用证据分别记录 `founder_authored=0|1`，不造成
  FLY-2396 回溯证据断档。
- runbook 已补充新字段映射、显式 Lead fallback 与 legacy unassigned run 的操作方式。
