## 结果

Claude account-heal 的手动 `use` / `next`、quota/model 自动触发与既有 repair 入口已收敛到
同一个 live selector 和 atomic switch executor。账号切换成功时，active account、generation、
cooldown/quota 投影与 notification intent 在同一次 store commit 中落盘；通知在账号锁外投递，
失败由既有 daemon 重放。手动与自动路径不再各自维护切号或成功播报逻辑，也没有新增 daemon
或告警层。

候选不再依赖写死账号顺序。selector 从 pool/store 交集出发，对每个非 active 账号执行 live
freshness、quota、cooldown、model-bench 与 identity witness 校验，在可用集合中按有效 weekly
reset 最早排序。live weekly reset 缺失时可使用账本观测值；未知 reset 保守排在已知值之后。
stale、quota-exhausted、不可验证与 malformed 候选都会被排除并写入 panorama；全灭时发出
`quota_no_target`，不会静默停摆。

显式 `use <name>` 只绕过指定目标的 cooldown。freshness 与 quota bypass 已退役：手动路径与
daemon 一样 fail closed，旧环境变量不能削弱 live 校验；对应 exemption census 从 29 收紧到
27。`next` 与自动触发均不绕过 cooldown。

## 实现要点

- `flywheel-claude-profile use|next` 通过 Bash trampoline 进入 account-heal TypeScript CLI；
  quota monitor 与 repair 调用同一 selector/executor。
- executor 将 durable `account_switched` intent 与切号状态一起提交；`sent`、`duplicate`、
  `queued_transient` 与终态 `dead_lettered` 都有明确 receipt/outbox 处理，避免坏事件永久 wedge
  后续切号。
- 手动 CLI 只从 `~/.flywheel/.env` 补 notification allowlist，兼容 `set -a`、
  `export KEY=value` 与无关/格式损坏行，不读取或打印非 allowlist secret。
- `restart-services.sh` 仅在真实 build 后校验 launcher 与 compiled runtime；skip-build、rollback
  和 source-only 路径不被误拦。新 shell test 已登记到 CI 的 FLY-1434 restart/quota caller
  套件。
- 旧 freshness/quota bypass 的生产读取、恢复文案与 exemption 已移除；遗留输入只会被防御性
  清理并由负向测试证明不能生效。
- QA attempt 5 撤回了 attempt 4 的 shared-group descendant fence：独立 mutation leader 仍以整组
  存活为 fence；non-detached writer 与调用 shell 共用 PGID 时，只以实际 mutation leader 的 PID +
  start time 判定 writer 是否仍活着。profile 对 `security(1)` 与 Node helper 都是同步等待，leader
  退场后没有仍能提交的在飞 descendant；继续 fence 共享组后出现的任意成员只缓解低危理论竞态，
  却已在三头 drill 中造成全舰级健康重试锁死，因此恢复 attempt 3 已验证的 leader-identity 判据。
