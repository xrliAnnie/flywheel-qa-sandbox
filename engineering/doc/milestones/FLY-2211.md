# FLY-2211 — Codex 重启传输隔离与恢复所有权

**Status**: ✅ implementation complete; code review approved; awaiting independent QA
**PR**: [#1016](https://github.com/xrliAnnie/flywheel/pull/1016)
**Date**: 2026-09-01

本批次修复 Bridge 重启波间接杀死在场 Codex worker 的病根：runner 窗口虽然存活，但其
app-server transport/daemon 会随波消失，TUI 失去传输后再延迟退出。实现把 durable session、
CommDB TURN、process-local owner 与 daemon liveness 组合成默认开启的 re-owner，并为所有纳入
范围的信号路径增加先落盘、后 mutation 的 kill ledger。

## 交付内容

- 持久化不可变 recovery launch snapshot 与 rehydration context；缺失或漂移时 fail closed，
  不猜测旧 runner 参数。
- Bridge 启动与周期维护执行 Codex session re-owner：排除已有 process-local owner、superseded
  execution 与 529 slot；对 gate-free healthy runner 只 watch，对 absent daemon revive，对需要
  recycle 的 parked/gate-held runner 先审计 reap、再恢复同 execution/thread。
- StateStore 内实现 token-bound recovery claim、episode attempt cap、lifecycle revision 与共享
  execution mutation lease；CommDB TURN 在 destructive/spawn 边界前后复核。
- TURN writer 继续持有跨 CommDB/StateStore 的 mutation lease，但不再递增无关
  `lifecycle_revision`；founder lifecycle 与 pane-loss CAS 不会被一次 TURN grant 误判过期。
- recovery 只在 daemon 给出真实 ownership receipt 后 commit：fresh turn、持久化 phase hold、durable
  gate hold、authoritative resumed goal 与 terminal goal 均有独立确认 seam；callback 全程 await 且
  fail closed。transport restart 重放 hook 时幂等，clean pre-mutation fence abort 会原子退还 attempt，
  不会把健康 parked session 误判 exhausted。
- recovery episode 耗尽走既有 canonical terminal sink，记录 `failureKind=reown_exhausted` 并由
  workflow engine 决定 replacement，避免双 owner/双 execution。
- transport close、zombie 宣告与 rollout mtime 取证落盘；lsof/ps 改为并发异步探针，每条
  3 秒 timeout、1 MiB command buffer，持久化仍限制 32 KiB，不阻塞 Bridge 主线程。
- 合入最新 main、FLY-2174 与 FLY-2237 后，552 个 mutation/probe/QA 命中完成机械 inventory，生产
  runner mutation 收敛到 audited choke point；新增 71 条 cycle/slot 命中逐条确认均为 `qa-only`，
  kill-ledger shell gate 已显式进入 CI shard 与结构 inventory。
- FLY-1955 身份栅栏完成互查：broker 保活与 zombie/orphan reap 均按 execution、canonical
  CODEX_HOME/socket、精确 argv/PGID 与 fresh lsof holder 判定，绝不按 `codex`/`app-server`
  进程名豁免或 signal；active runway 消失后仍可从 canonical socket 反向回收精确 orphan。
- 新增隔离 529 attach/adopt 探针与真实 Codex room 开关。QA 在 Codex 0.152.0 证明 attach 可
  继续 live goal loop，但重复 kick 不具 exactly-once receipt；本批不在有 double-kick 风险时启用
  attach/re-kick，后续升级由 Lead 另立 follow-up。
- QA rework 收口 truthful diagnostics：shell mutation 测试 seam 不再由 production env 控制，
  `lsof` 的空 rc=1 正确表示 no-holder，parked 非 TURN holder 不再误记 fence lost。
- Lead attempt 5 必修已按 TDD 收口：recovery confirmation 在 socket death 时保留
  `transport_closed`；daemon teardown 把结构化 death cause 与稳定 cause hash 写入事件；529 排除
  改为读取并校验 room 自身的 generalized marker，不再猜目录/项目名；rollout mtime 跨 pass 保存
  advancement 状态，10 分钟未推进才进入既有 fail-closed unknown/alert 通道，且不会触发
  claim/reap/revive。
- FLY-2174 PR #1021 落 main 后完成依赖收口：529 generalized room 生成并投影独立 slot-local
  ingest credential，runner 得到 `FLYWHEEL_INGEST_TOKEN`，且不复用 master token、不继承 ambient
  production auth；重复 Lead 身份来源已移除。精确 cherry-pick 与合入 main 的 patch 一致，②/③
  依赖套件全绿。
- FLY-2237 PR #1028 与 FLY-2245 四分片布局已通过合入 main 落到本分支：529 room 具备 slot-only
  Bridge cycle 与 launch-spec capture，CI shell suites 从 2 路拆为 4 路；本节点只做依赖集成与
  inventory 同步，没有触发真实 restart wave。

实现遵守 Lead 裁决：re-owner 默认开启且没有 runtime flag；分阶段通过 merge 顺序与独立 QA
