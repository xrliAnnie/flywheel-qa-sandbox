# FLY-2147 — Runner 按项目与角色挂载记忆目录

**Status**: ✅ Implementation and code review complete; pending independent QA
**PR**: #1056
**Date**: 2026-09-03

本单在 runner spawn 链路加入由 `(projectName, role)` 唯一决定的持久记忆目录。Claude runner
通过启动 settings 显式获得 `autoMemoryDirectory` 与 `autoMemoryEnabled:true`；Codex runner
获得同一目录的环境指针和按需读取说明。目录名使用可逆、大小写折叠安全的单射编码，因此同一角色跨
issue、worktree 与一次性 execution ID 复用同一份记忆，而大小写不同的合法身份不会在 macOS 文件系统上
碰撞。

记忆索引沿用 Lead 侧的短索引、按需读取正文形状，但注入面有固定软预算、Claude 硬上限和有界扫描。
首跑创建空索引；预算内也留结构化日志；超预算同时在日志与 prompt 标出，从约第几行开始未被加载。
五类 Claude settings 来源按固定顺序做“存在即冲突”探测，不合并也不求解优先级。managed 来源不可读或
任一来源出现 auto-memory 策略键时，spawn 结构化失败、日志与 prompt 都 fail-loud，并尽力传入
`autoMemoryEnabled:false`；其有效状态明确标为 UNKNOWN。

无 `projectName`、无角色、非法身份、根不可用或文件系统失败的 Claude 执行不再回退到原先可读写的
项目共享自动记忆，而是显式关闭自动记忆。这包括无 `projectName` 的 legacy 执行，是有意删除的行为：
失败路径若回退到项目共享写入，会破坏角色隔离并制造静默半开状态。未触碰的 backend 保持 prompt、argv
与 adapter context 字节级不变；旧项目共享记忆仅在实际存在时作为只读按需指针显示。

TDD 证据覆盖身份解析、首次创建、目录与索引失败、五类 settings 冲突、日志/prompt 可见性、adapter
settings/env，以及 FLY-1188 全 prompt 快照只新增确定性 fail-closed 段。单射证明测试读取仓内全部 Lead
identity，再加入对抗样本、大小写穷举与 5,000 个固定种子语法串，证明零碰撞且逐字节解码相等。真实
Claude CLI 用三个独立 cwd 完成 nonce 写入、复读、删除首个 cwd 后再复读，确认记忆与 execution/worktree
生命周期解耦。
