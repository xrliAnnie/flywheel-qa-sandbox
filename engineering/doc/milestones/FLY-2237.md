# FLY-2237 — 529 房内 Bridge 单独循环

**Status**: ⏳ Implementation complete; pending independent QA

**Date**: 2026-09-01

本批次为既有 529 slot 补齐只循环房内 Bridge 的台架原语。`test-deploy` 的三条 Bridge
启动分支现在都会把最终实际生效的普通环境、owner-only secret 引用、工作目录、命令、端口、
日志与 ownership PID 文件固化为 mode-0600 launch spec；`scripts/test-cycle-bridge.sh <slot>`
据此只对旧 Bridge 进程链发送 SIGTERM，并在同一隔离 session 中重启同一房 Bridge，不触碰
在飞 worker、Codex daemon 或 tmux。成功后会原子地把 room/campaign ownership 转交给新 PID；
旧 Bridge 不健康、listener/ancestry/identity 不唯一、端口未释放、替代进程不健康或清理无法证明时
均 fail closed，并保留 `cycle-failed` 供显式 teardown 恢复。

cycle 与 teardown 共用 retained per-slot advisory guard，按 `lockf` → `flock` → Python `fcntl`
选择可移植后端，避免 PID 目录删除与重建间的空窗竞争。替代进程显式关闭 guard fd 后再 exec，
不会把 teardown 锁带入 Bridge 全生命周期。最终 review 修复同时容忍 npx/tsx 一类 wrapper 在收到
TERM 后先转发并 reap listener：已消失的实测 descendant 视为成功，仍存活但 start identity 已变化的
PID 继续按 foreign/recycled process fail closed 拒绝发送信号。

Founder QA 定向复核随后把「替代进程组 TERM 前的 start identity 重验」从 advisory 提升为本轮必修：
cycle 现在在取得 `NEW_PID` 后记录 `NEW_START`，隔离进程组建立后再次确认，并在 launcher fallback TERM
与 process-group TERM 两个信号点分别调用 `qa_slot_bridge_pid_matches`。任一重验不一致都会明确报错、
零信号并保留 `cycle-failed`，不会把 recycled PID 对应的外来进程组当成替代 Bridge 清理。
