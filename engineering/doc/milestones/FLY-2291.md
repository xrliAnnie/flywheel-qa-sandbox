## 交付

- Claude 审查输出在没有任何平衡 JSON 候选时，只允许修复一种已经闭合 `findings` 数组的形状：trim 后以
  `{"verdict"` 开头、以 `]` 结尾，且只追加一个外层 `}`。合法 verdict 和本对象自己的 findings 数组仍是
  硬门；缺 `]}`、引号、数字、逗号、冒号或大段正文的真实截断继续判 `no_verdict`。
- 修复不是静默成功：job row 持久化 `repaired_trailing_brace=true`，canonical gate response 带
  `repairedTrailingBrace` 和 `reviewAudit`；修复后若另一个硬门关闭，原有 failure alert 同样保留该审计标记。
  terminal job 不允许后来补写 marker。
- `no_verdict` 与 `reviewed_wrong_head` 统一计入 execution + review type + repository identity 的连续 integrity
  failure streak。第二次连续失败会原子提升显式 session generation、保存 retired UUID、清空当前 UUID 与
  streak；同 requestId scheduled retry 与新 requestId 都会在下一轮取得新 reviewer session，不以 NULL 本身
  充当 generation 标记。
- reviewer session lookup 只继承当前 generation、同 repository identity 的 UUID。fresh session prompt 携带
  最近一轮 durable findings 及其 source round，既切断坏 continuation，又不丢审查上下文。
- 连败后的 alert 改为准确指令：reviewer session 已经自动替换，重试同一个 requestId 会启动 fresh session；
  不再建议继续撞旧会话。
