# FLY-1955 — Codex Lead 吊销凭据停车与连败告警

**Status**: ⏳ Pending ship
**PR**: [#1015](https://github.com/xrliAnnie/flywheel/pull/1015)
**Date**: 2026-08-31

查明两个 Codex Lead 的共同故障并非 socket 自身，而是 `remote-control start` 所用 refresh token
已被服务端吊销。`ensure-daemon` 现在只读取本轮 start 新写入的 stderr 证据：按新文件、纯追加、
原 inode truncate/rewrite、未变化四态区分，并仅在命中固定 auth-dead code 时发出脱敏的
`login_expired` 告警。命中后进程以 30 秒分片停车 15 分钟；每片复核原父进程身份，父进程退出、
换代或探针失败即在 30 秒内停止，不再写计数或继续告警。

所有 `ensure-daemon` 失败出口共用一个 home-local 连败计数器：第三次起尝试日去重的
`crash_loop` 安全网告警，健康启动会清零。计数写入使用 Python 标准库的同目录临时文件与原子
replace；目录、symlink、读写故障均 fail visible，且不会跟随或改写敌对目标。既有基于 PID、
start time、命令形状与 home fence 的 zombie reap 保持不变，也没有新增依赖、配置键、daemon
或账户切换动作。

QA criterion-5 返工补齐了快照探针不可用的诚实边界：start 失败且 stderr 身份快照无效时，不再
落入「stale-daemon evidence incomplete」误诊，而是复用现有 15 分钟分片停车；第三次及以后
的兜底告警正文追加 `reason=snapshot_unavailable`。计数文件仍只存十进制整数，未知原因不伪发
`login_expired`，也不新增重试、配置或后台机制。
