# FLY-2397 — 强度二证据台账

**Status**: ⏳ Implementation and local verification complete; exact-head code review and CI pending
**PR**: https://github.com/xrliAnnie/flywheel/pull/1113
**Date**: 2026-09-07

Flywheel 现在有一套 append-only 的强度二证据台账。每行精确绑定 workflow run、目标仓和
head，并把「真环境跑过」与「外部记录可查且可重跑」保存为两组独立状态与原因；任一半缺失、
失败或没有台账行，综合判定都 fail closed。旧 `qa_passed` claim 和文字自称不能替代台账。

## 交付内容

- StateStore 新增 append-only 台账、精确绑定查询、事务内 current-writer/credential 重验与 replay 合同；
  登记本身不消费 QA verdict credential。
- Bridge 新增认证记录入口；CLI 新增 `evidence-run record`，发布一次性 0600 receipt 并按结果区分
  安全重试、冲突和 credential 已消费。
- 真跑半边验证 529 房、build SHA、链路和 driver exit；记录半边独立验证 HTTPS URL、redirect、
  私网拒绝、有限响应流、rerun spec 与固定 artifact 路径。
- QA workflow prompt 明确记账必须发生在房 teardown、HEAD 变化和 `qa-result` 消费 credential 之前。
- 台账已登记为 `protectedCurrentOrReference` retention 资产；后续消费者通过纯函数 judge 与只读
  liveness probe 使用证据，不回写历史事实。
- 首轮跨模型审查发现并已修复两个 HIGH：ingest bearer 只挂在精确 evidence route，不再拦截
  `/api/workflow` sibling；本地 receipt 的 `schemaVersion` 不再泄入 wire body。CLI→真实路由落行、
  sibling route 可达、认证 evidence route 可达均有回归测试。
- 同轮 MEDIUM/LOW 已收口：quote-heavy probe detail 最终序列化后仍严格不超过 4096 bytes；GitHub
  错误分类只从 stderr 识别 HTTP 状态，不把 comment id `403/404` 当状态码；非法注入时钟由
  credential preflight 在探针前 fail closed。
- 恢复执行时发现 GitHub PR conversation comment 的外部地址形状是
  `/pull/<number>#issuecomment-<id>`，而分类器只接受 `/issues/<number>`。新增先红后绿回归后，
  分类器同时接受两种 GitHub comment permalink，并继续通过 `/issues/comments/<id>` API 验证
  返回的 `html_url` 与登记地址完全一致。
- 已按 founder 要求 rebase 到 `main@4bbd7c1f0`。冲突处理只组合保留 FLY-2427 的
  `workflow_gate_holder_recovery_evidence` authority 表与本单的 `strength_two_evidence_record`
  reference 表；合并后 retention inventory 为 179，未改变本单行为。
