# FLY-2405 — Bridge 起房、拆房与沙箱外验证服务

**Status**: Implementation complete; targeted verification, effective review and QA handoff pending
**Date**: 2026-09-26
**Design**: [approved plan](../FLY-2405-room-service/plan.md), including C7 alert duty and C8 generalized drill

Codex 与 Claude runner 均通过认证的 `flywheel-comm room deploy|drill|status|teardown` 请求 Bridge。Bridge 使用独立精确头源码、受控环境与持久化操作在沙箱外执行起拆房及固定 generalized driver；runner 不再自行 bootstrap launchd 或写宿主 pretrust 锁。

实现涵盖房位归属/借位锁、生产 label 拒绝与审计、负载队列、重启恢复、拆房前 DB/证据快照、残留检查后释放、悬空 Codex socket 与陈旧 runtime marker 修复、告警值守 Lead、原始 drill exit code / evidence copy / rerun spec，以及两类 runner 的 QA 指引。只开放固定 driver，rescue 与通用嵌套诊断仍为设计中的后续工作。

Lead 裁定将服务回退接入 `qa_room_service` bridge-global flag store：生产默认 on；隔离默认 off，显式 TEST_ opt-in 仍受 store off 约束。关闭后每次 admission 与实际启动边界即时读取，异步取消期间关闭也不会启动新 job。

局部证据见 [verification.md](../FLY-2405-room-service/verification.md)，完整消费者选择见 [verification-consumers.json](../FLY-2405-room-service/verification-consumers.json)。相关 build、下游 typecheck、lint 与核心/CLI/守卫专项已通过；大范围 owning `related` 与最终 HEAD 打包身份检查仍待完成。已记录基线 protocol fixture 不一致与 sandbox `ps` EPERM，均未弱化断言。最终验证和 review/PR/route 身份以 PR 正文与 registered handoff 为准。

本文件是本次开 PR 的 literal-last commit。独立 QA 仍须证明 Codex/Claude 真起房→房内验证→拆房零残留、实际 Discord 告警与拒绝审计；本节点不 dispatch QA、不请求 ship、不合并、不部署，也没有请求 full CI。

部署/回退：由既有 ship/updater 交付；紧急停止新请求使用 `node "$FLYWHEEL_COMM_CLI" feature-flags set --name qa_room_service --to off --reason "FLY-2405 rollback"`，无需改 `.env` 或重启；恢复用 `--to on`。运行中的 job 继续按归属与收据规则安全收敛。
