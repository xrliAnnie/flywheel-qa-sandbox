# FLY-2774 — 消除 retained tmux 退出证据测试假红

**Status**: ⏳ Pending effective code review and exact-head CI
**PR**: #1307
**Date**: 2026-09-23

本单仍严格只改测试侧。`tui-window.test.ts` 的两个 real-tmux 用例现在显式
区分平台：当 `process.env.CI` 存在时直接动态 skip，并在 stderr 与 Vitest
skip note 中写出稳定的 `FLY-2774 ci-real-tmux-skipped` 原因——Ubuntu CI 的
tmux 3.4 在负载下可能不记录 retained child exit code；生产使用 macOS tmux
3.7c，所以这两条真 tmux 断言只在非 CI 环境执行。CI 仍运行同文件内模拟
dead-pane 输出的解析测试，不把 skip 冒充成 real-tmux 通过。

非 CI 路径保留严格三态：`pane_dead_status` 非空但不是 42 立即失败；预算
耗尽时 `pane_dead=0` 立即失败；只有 `pane_dead=1` 且 status 始终为空才销毁
整个隔离 tmux server 后有界重试一次，第二次仍为空才以可检索原因动态 skip。
生产 `tui-window.ts`、CI 配置、分片归属和退出码语义均未修改。

`scripts/test-cmux-sync.sh` 的既有修复保持不动：仅把
`pane-exited[500]` 检查从 `echo | grep -q` 换成 Bash 原生模式匹配，避免
`pipefail` 下写端收到 SIGPIPE。FLY-2770 #1283 仍未进入 main，因此本分支
没有吸收或改写它的其他 cmux-sync 变更。

当前代码头的本机证据：单文件非 CI 连跑 20 次全部 36/36、零 skip；退出码
43、退出码归零 0、把关键等待预算移除三个 mutant 都让两个 real-tmux 用例
同时失败，随后文件逐字恢复并再次 36/36。`CI=1` 模拟为 34 passed、2
skipped，日志两次打印完整平台原因。`vitest related` 只收集同一文件并
36/36；完整 `test-cmux-sync.sh` 为 596 passed、0 failed；受影响 teamlead 包
及其依赖 build 通过；根 lint 退出 0（26 条 main 已有 warning）；changed-file
Biome、branch-wide `git diff --check` 均通过。这些是聚焦本地证据，不冒充
exact-head CI。

消费者搜索按两个变更文件的完整路径、文件名和父目录完成。保留并执行的直接
消费者是 owning Vitest 文件和完整 cmux shell 脚本。`ci.yml`、
`qa-tmux-3.7c-compat.sh` 与 hooks integration 是 CI/兼容入口；kill-path
inventory、path-hygiene、ci-test-costs 和历史文档是路径或盘点元数据；其余
命中仅为注释或静态合同，因此没有扩成额外本地测试。
