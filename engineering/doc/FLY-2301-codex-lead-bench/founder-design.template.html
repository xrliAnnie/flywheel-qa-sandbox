529 房台架支持 Codex 形状的常驻 Lead

FLY-2301 · 设计说明 · 2026-09-03 · 分支 flywheel-FLY-2301

一句话总结

把 529 测试房(529 房:我们在本机隔离出来的、用测试机器人和测试频道跑真实 Flywheel 的演练环境)的「常驻 Lead 台架」从只会起 Claude 形状,改成按 Lead 的身份数据自动分成 Claude / Codex 两条启动链,这样以后 Raya 这类 Codex(云脑)形状的常驻 Lead 也能在房里起来、验活、演练自愈,而既有 Claude 房的行为一个字节都不变。

为什么现在做

FLY-2259(Raya 脑迁常驻)的 QA 发现:529 房的台架和生产上的 Codex 常驻 Lead 在三个地方形状不一样,所以任何 Codex 形状的东西都进不了房、测不了。founder 2026-09-03 直令:开单改台架(A 路线),不加开关,先把台架搭好;退旧脑那一半归 FLY-2259 B 路线。

差异529 房今天生产 Codex 形状
plist argv(launchd 的启动配置里「运行什么命令」那一栏)wrapper manifest 两参/bin/bash wrapper 两参,没有 manifest
env 注入集(启动时塞给进程的环境变量)7 个 Claude 侧变量,Codex 一族(CODEX_HOME 等)一个没有plist 里几乎为空,一切从 .env 文件 + 启动器读
验活判据(怎么证明 Lead 真活着)manifest 里的 pid + 私有 tmux socket 的 =main 会话launchd 进程就是 node …tui-runtime.js,环境里 CODEX_HOME 精确匹配,外加 heartbeat(Lead 自己定期写的心跳文件)

核心流程:两条启动链,一个分派点

分派依据是 Lead 身份数据里的 backend(后端种类),缺省或 claude-code 走上面那条既有链,一个字节不改;codex-app-server 走下面新链。没有任何命令行开关。

新链每一步在做什么

  • .env 追加 Codex 一族:Codex 的启动壳(wrapper,launchd 直接运行的那个小脚本)只读 ${FLYWHEEL_STATE_DIR}/.env,而 529 房的 .env 恰好就是这个路径,所以把 Codex 需要的变量写进这个文件即可,和生产一样。
  • 渲染 slot 固定 wrapper:生产的 Codex 壳是每个 Lead 一份、身份写死在里面的(不能靠环境变量冒充身份)。房里用一份模板 + 三个经过校验的标识符渲染出一份同样形状的壳。
  • codex-lead.sh:仓库里现成的通用 Codex 启动器,以前 FLY-259 的隔离 QA 就是用它起过 Codex 界面型 Lead。本单只改它一行:状态目录的根从写死的 ~/.flywheel 改成先看 FLYWHEEL_STATE_DIR(生产没设这个变量 ⇒ 路径不变,有实测)。
  • slot tmux 窗口:Codex Lead 会在 tmux(终端多窗口工具)里开一个可见窗口。房里必须把它钉在 529 房自己的 tmux 服务器上,否则会开进生产的 flywheel 会话里被 cmux 同步出去。

验活、就绪与自愈演练

Codex 形状的判据和生产上的恢复脚本 resident-codex-lead-recover.sh 用同一套「精确身份」检查,不另造一套。

{{SVG_D2}}
验活
launchd 报告的进程号,就是那个 node 运行时进程;它的环境里 CODEX_HOME 等于房里的隔离 home;心跳文件里的 processPid 等于它。
就绪
心跳文件 state == "online"(Codex 后端不写 Claude 那种就绪 lease 文件,所以不能沿用)。
自愈演练
两式:强杀进程(考 KeepAlive 自动拉起)和 launchctl kickstart -k(生产巡逻器判定假死后执行的正是这一步)。收敛判据 = 新进程号、新启动时间,且心跳里的 generationId、carrierInstanceId 都换了。
拆房
先 bootout(让 launchd 放手),再停掉 Codex 的 remote-control daemon(Codex 常驻在后台的守护进程,它的 socket 藏在 CODEX_HOME 里,Bridge 的孤儿收割器看不见它),最后随房目录一起删除。

数据 / 结构模型

形状怎么声明:在本机的 ~/.flywheel/test-slots.json 里,给某个 slot 条目加 backend 和 codexSourceHome(隔离 Codex home 的来源路径,拒绝三个生产 Lead 的 home)。缺省不写 ⇒ 生成的一切与今天逐字节相同。

{{SVG_D3}}
  • CODEX_HOME 铸造:从来源 home 只拷 auth.json(登录凭据,600 权限)和 standalone 二进制目录(APFS clonefile:同一磁盘卷上的零拷贝克隆,436M 秒级完成),放在 ${SLOT_DIR}/cdxh/<agent>。路径刻意短,因为 Unix socket 路径上限 103 字节。
  • registry(拆房唯一权威的登记簿)加三个可选键,旧条目没有这些键 ⇒ 走原路径。

关键取舍与被否决的替代方案

取舍选择为什么
形状怎么声明选Lead 身份数据 backendfounder 不加开关;生产上也是 backend 决定载体(wrapper-v2 会拒绝非 claude-code;重启权威按 backend 分支)
房里跑哪个 Codex 启动器选通用 codex-lead.sh唯一不绑死具体 Lead 的生产启动器;有隔离 QA 前例
直接复用 Raya 生产 wrapper + launcher否决它把状态目录写死在生产路径、跨部门频道缺省是生产圆桌频道、还要 Raya 的人设文件;要么在生产启动器上开一串「仅测试可覆盖」的口子(和 FLY-2216「路径不可注入」的安全决策对撞),要么房里冒出一个叫 raya 的假身份和房自己的身份打架
把 Codex 变量塞进 plist否决生产 Codex plist 几乎零变量,一切走 .env;那样测的就不是生产链
自愈边界选launchd 层(强杀 + kickstart -k)+ 生产同式收敛判据Bridge 侧的 RayaBrainPatrol 巡逻链权威绑在真 HOME 和三个固定 wrapper 上,进本单等于改生产自愈边界(见下一节「决定不做」)
Codex 能力层级选缺省 companion(只读陪伴层,Mufasa 同形),full-access 作为数据选项真机验收跑最少依赖的生产形状;full-access 的额外部件(lead-actions MCP、治理规则包)属于启动器 / 运行时,已有自己的测试,与载体形状无关

怎么算验收通过

  • A1–A3在 529 房起出一个 Codex 形状的受管常驻 Lead:plist 两参、RunAtLoad + KeepAlive 生效、验活与就绪判据通过。
  • A2隔离:home / 状态 / tmux 窗口全在房目录;生产的 Codex 状态目录、生产 tmux 会话、三个生产 Codex home 零写入(前后对照)。
  • A4两式自愈演练收敛。
  • A5拆房干净:label 不在 launchd、进程不在、窗口不在、目录已删。
  • A6守卫:Claude plist 逐字节黄金快照测试,且它的「变异体对照」必须变红(把缺省分支故意改坏一处,测试要能抓到——不然守卫不算存在);来源 home 命中拒绝名单必须被拒。
  • A7既有 Claude Lead 房回归全绿:四个 shell 测试套件 + 真 529 房 Claude slot 启动 / 验活 / 拆除,其 plist、.env、manifest 与改动前逐字节相同。
  • A8codex-lead.sh 那一行改动:同一输入下改前改后的状态路径逐字节相同(拿 git 里的旧版本和工作副本双跑比对,不靠推理)。

诚实边界:这个设计做什么、不做什么

做

  • 529 房台架按载体形状分支;Codex 形状的起、验、就绪、演练、拆全链路;Claude 形状字节不变并有带阳性对照的守卫。
  • 生产代码只动 codex-lead.sh 一行(状态目录根),并附实测证明生产路径不变。

不做(决定,不是遗漏)

  • 不做退旧脑 / 生产单实例切换 —— FLY-2259 B 路线。
  • 不做让 Bridge 侧 RayaBrainPatrol / resident-codex-lead-recover.sh 对房里的 Lead 生效 —— 它们的权威绑在真 HOME 与固定 wrapper,改它等于给生产自愈开口子。承接:FLY-2259 QA 用已有的 fixture 测试覆盖巡逻分类;若要真机演练巡逻本身,另立 issue 讨论。
  • 不做529 房造 Codex 工人(FLY-2224 域)。
  • 不做full-access 层级的真机验收(只做环境投影的 hermetic 断言)。

风险

  • 前置现成的隔离 home ~/.codex-259-qa 登录凭据可能过期,验收前需操作者重新登录;台架遇到会大声失败,不会代劳。
  • 环境进程环境探针在被沙箱的 shell 里读不到子进程环境(本会话实测),在 launchd 起的进程上可以(对生产 Mufasa 实测可读);hermetic 测试在 Linux CI 走 /proc。探针不可用时显式报错,不静默降级。
