Codex 号池：从「写死三个」改成「目录里有几个就是几个」

FLY-2762 · 设计阶段 · 2026-09-22 · 本页只讲设计，还没有写代码

一句话

以后 ~/.codex/profiles/ 里有哪些文件夹，系统就认哪些 Codex 号；六个号（将来第七个也一样）用同一套规则切换、保存、查状态、被自动切号选中，账号页也能分清「吊销 / 未登录 / 打满」。

今天的问题：代码里有 11 处把号池写死成 school、personal、business 三个。你另外三个已登录的号（personal1、personal2、shopping）用 codex-profile use 会直接报错，自动切号也永远不会选它们。

我实测复现了这个错误（用临时目录，没碰真凭据）：

命令今天的结果
use shopping报错：expected school, personal, or business
save personal1同上
list只列三个号，另三个标成「Untracked（未跟踪）」

核心流程：一个号池，所有地方都从它读

现算号池：每次要用号池时，程序现场去读一遍 profiles 文件夹，而不是查一张提前写好的名单。所以新建文件夹后不用改代码、不用发版，下一次用到就能看到。

真探：用这个号的登录凭据真的去问 OpenAI「我还剩多少额度」，能问通就说明凭据有效。这件事只让 Bridge（后台常驻服务）做，因为它知道哪个号正在被在跑的 Codex 使用；两个进程同时用同一个号的凭据，会让其中一个被 OpenAI 踢掉。

账号页的 token 状态怎么分

你 9/19 指出页面上看不出「吊销」「未登录」「打满」的区别。新设计给 Codex 表加一列「token 状态」，每种情况文案不同：

页面显示意思你要做什么
正常凭据有效，额度没用完无
打满凭据有效，但 5 小时或每周额度用到 100%等到显示的恢复时刻
已吊销 已过期 凭据失效登录凭据被 OpenAI 作废了（原因不同，处置相同）重新登录这个号
未登录文件夹建好了，但里面还没有登录凭据登录这个号
凭据损坏文件夹里的凭据文件读不出是哪个号重新登录这个号
重复登录两个文件夹登的是同一个邮箱；为防两边互相把凭据弄作废，两个都不用、也不去探删掉其中一个文件夹
在用未探 未探这次没去问（正在被用，或超时）；不是号本身的状态稍后刷新

数据结构

id_token：登录后 OpenAI 发的一张「身份证」，里面写着邮箱和订阅档位。我们只读它，不改它。

注册表：以前是一张写死三个号的名单；以后只剩一行规则「默认用 personal」，不再列任何号。

关键取舍与否决的方案

方案结论原因
把名单从 3 行扩到 6 行否决新号还要改代码发版；名单和文件夹是两份真相，今天的问题正是这两份对不上
让 codex-profile 自己去真探否决它不知道哪个号正被在跑的 Codex 使用，可能把正在干活的 runner 的凭据弄作废
给原来三个号保留「邮箱钉死」保护否决那样三个号有别的号没有的保护，违背「每个号一视同仁」；改用对所有号一样的规则：save 只能存回同一个账号的文件夹
用 save 把凭据存进一个空文件夹否决评审发现这一步要同时锁住新旧两个身份，复杂易错；直接在文件夹里登录更简单，效果一样
两个文件夹登的是同一个邮箱两个都排除不猜哪个是对的，list 里明确显示原因
自动切号要不要单独加开关不加沿用已有总开关 codex_quota_auto_switch，出问题一键关

诚实边界：做什么、不做什么

会做

  • 六个号都能 use / save / status；list 每个号一行：邮箱、档位、token 状态、重置时刻、探测时间。
  • 自动切号的候选从 3 个变成全部可用号。上线后自动切号可能切到 personal1 / personal2 / shopping（它们是 prolite 档，额度比 pro 小）。这是本单的目的，但你会在切号通知里第一次看到这些名字。
  • 账号页多一列 token 状态；只建了文件夹还没登录的号也会出现一行「未登录」。
  • 新号流程：建文件夹 → 在这个文件夹里登录（CODEX_HOME=~/.codex/profiles/新名字 codex login）→ 马上可用，不改代码。
  • save 只能把凭据存回「同一个账号」的文件夹（邮箱和账号编号都要一致），防止把 A 号存进 B 号的位置。

不做

  • 不动 Claude 账号那一套（Claude 的切号和额度监控）。
  • codex-profile list 显示的是 Bridge 最近一次真探的结果，带探测时间；要最新数据用 list --refresh，Bridge 不在时会明说「未刷新」，不会拿旧数冒充新数。
  • 不在上线检查里切换共享的 Codex 号；切换功能的证据来自测试环境。
  • 本页只是设计。代码、测试、QA 在后续阶段。
