核心流程

Execution 是一次独立 runner 运行身份；历史 execution 收到的 marker 不能自动转授给当前 execution。Managed snapshot 是系统 helper 创建的只读 mailbox 数据库副本，让 writer 能用参数化查询核对 sender、recipient 与原文，而不触碰 live database。没有 marker 或 completion route 不兼容时，流程明确 fail closed 并 park 给 workflow owner。

数据与结构模型

Exact marker 是不做 trim（删首尾字符）或 normalize（改写字符形式）的原始标记字节。Native instruction 是系统直接投递给同一 execution 的原生指令。Marker file 是 parser 生成的单行临时文件：它把可打印字符安全地作为数据传给 grep -F -f 与 cat，即使内容含引号、反引号或 $() 也不会被 shell 执行。

一条已核验 instruction 生成 snapshot evidence 与 marker files，最多授权一个 local-only probe commit；workflow contract 单独决定 runner 能否完成或必须 park。

采用：owner handoff没有 marker 或 tpl_code route 与 local-only/no-PR 边界冲突时，runner 结构化报告并 park，由 workflow owner close、cancel 或 retemplate。
拒绝：从 owner 与 driver 模板推导能生成“看起来正确”的 `${owner}-native-BOOT`，却不能证明当前 execution 收到了它。
