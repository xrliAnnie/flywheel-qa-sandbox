1 · 这次到底做什么

金丝雀（canary）是一项很小、隔离运行的探针，用来确认传输链路真的把任务送到了正确执行体。

TURN是服务器授予某个工作流节点的独占写入权；没有返回 yours 就不能碰共享工作树。

marker是必须逐字匹配的一整行文字。这里有两行：一行表示启动落盘，一行表示 Claude case 完成。

FLY2127-CANARY-eeb549be-1af1-44c6-93d3-a0cb7f40022c-CLAUDE-BOOT FLY2127-CANARY-eeb549be-1af1-44c6-93d3-a0cb7f40022c-R4-CLAUDE

2 · 核心流程

先确认写入权，再从唯一 source of truth 读取 exact lines；只追加缺失行，逐行验证，最后提交到 feature branch。

这张图由 Mermaid 源文件在本机预渲染成自包含 SVG；Mermaid 是一种用文字描述流程图的格式，托管页运行时不加载任何画图库。

3 · 数据 / 结构模型

没有数据库迁移，也没有新 schema。四个小对象串成一条证据链：

Ownerissue + nonce + claude case，防止证据串单。
Probe file根目录 probe.txt，只保存两条完整行。
TURN receiptphase=design、epoch=1、结果 yours。
Git evidencefeature branch 上的不可变提交快照；不进入 main。

4 · 关键取舍与拒绝方案

  1. 采用 driver 派生的两条 literal。测试代码本身生成并逐行检查它们，因此不靠人猜格式。
  2. 拒绝自定义 owner / TURN 文本。虽然信息更多，但 harness 不认，不能成为通过证据。
  3. 拒绝写完整工具输出。它会把易变格式与潜在敏感字段永久写入 Git。
  4. 拒绝只写一个 marker。会丢掉“已启动”或“已完成”的一半证据。
幂等规则：如果某条 exact line 已存在，就不重复；如果文件已有其他内容，完整保留并只追加缺失行。

5 · 诚实边界

这个设计会做：证明当前 design node 收到了 server-authorized TURN，能把本次 Claude canary 的两个 exact markers 写入并提交。

这个设计不会做：不会修改 FLY-2127 的 native wake 产品代码，不证明跨重启恢复、完整 mailbox 语义或生产部署；不会创建 PR、请求 ship、合并 main、部署或跑测试套件。

回滚边界：推送前可撤销新 commit；推送后只允许新 corrective commit，不擅自 force-push。
