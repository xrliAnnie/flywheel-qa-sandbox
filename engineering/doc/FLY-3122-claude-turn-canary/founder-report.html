2026-10-01 · design node · bounded transport exercise

只做设计marker 必须有出处不 PR / 不 ship / 不部署

一句话：当前节点只确认自己拿到了写入权并设计后续合同；只有收到明确文字的下游执行体，才可以把那段文字逐字追加到 probe.txt 并在本地提交。

1 · 为什么现在不写 marker

金丝雀（canary）是一项很小、隔离运行的探针，用来确认一条传输链路真的把消息送到正确的人。

TURN是服务器授予某个工作流节点的独占写入权；当前返回了 yours，所以 design 文档可以写，但 TURN 本身不包含 marker 内容。

执行体（execution）是一次有独立身份的 agent 运行。当前执行体是 Codex design，不是外部 driver 启动的 Claude fixture；onboarding 时 inbox 返回 No instructions.，但 inbox 既不是下游原生消息的来源，也不能证明后续消息是否已送达。

结论：记录真实的 TURN 回执，拒绝伪造另一条 Claude 链路的完成证据。Lead 已确认这条边界。

2 · 核心流程

phase（阶段）是工作流中职责固定的一段。Design 只交付文档和审查；后续 implement 阶段先拿到自己的 TURN，再从当前回合的原生 Lead 信封读取 instruction id 与原文。它不能用 inbox 替代这项传输证明，并且会先把原文的 hash 与 base64 写进 progress 真正支持的 handoff 字段。

橙色菱形是授权或内容门；红色节点表示必须停下，不能自行补值。

3 · 数据与证据模型

provenance（出处链）说明一段文字是谁发给谁、为什么允许落盘。它把 TURN、原生 Lead 信封、受支持的 handoff 回执、文件和 commit 连成可核查的证据，而不是只看文件里“像不像”成功。

commit（提交）是 Git 中不可变的一次本地快照。Probe commit 只能包含 probe.txt，并且明确不 push；marker 若已由旧 commit 正确写入，则必须证明 exact line 是该 commit 新增的内容，不接受“较长字符串碰巧包含它”的 substring 证据，也不制造空 commit。

身份execution id + vendor + phase，防止拿别人的回执充数。
授权TURN 只回答“谁现在能写”；原生 Lead 信封才回答“写什么”，并先存进 progress 的 handoff。
落盘唯一 grammar 提取 exact literal；临时文件安全承接 `$`、引号和反斜杠等字符，不做 shell 插值。
审计exact added line、实际 probe SHA、路径清单和带 instruction id 的结构化回报互相印证。

4 · 关键取舍与拒绝方案

  1. 采用：TURN + 原生信封 + 条件式 marker。 用 progress 支持的 handoff 保存 id、状态、hash 与 base64，再按唯一 grammar 提取；没有 literal 就不写。
  2. 拒绝：用 inbox 发现 native-proof marker。 已原生送达的行不会出现在 inbox；尚未送达的行又会被 inbox 抢先 ACK，两种结果都会破坏证据。
  3. 拒绝：从 issue title 推导 Claude BOOT / R4。 外部 driver 会同时检查原生消息、ACK 和 Claude 身份；只抄文字会制造假阳性。
  4. 拒绝：自定义 owner + 时间戳 marker。 可读但没有发送方，也不满足“requested marker”的逐字合同。
  5. 拒绝：让 design 直接写 probe。 会混淆阶段职责，让设计审查绑定到已经发生的实现。
  6. 拒绝：把 marker 直接拼进 shell assignment。 printable ASCII 允许 `$`、反引号、反斜杠与引号；插值可能改写原字节，所以用逐行临时文件安全加载。

5 · 诚实边界

DAG（有向无环工作流）把 design、implement、QA 等步骤按依赖串起来；节点不能替 orchestrator 派发后继或扩大权限。

这份设计会做到：完成三份设计文档、设计审查、Founder HTML；design 完成后 park；为后续 exact marker append、幂等回执与 Lead close/cancel 给出可执行合同。

这份设计不会做到：创建或修改 probe.txt、声称收到 Claude native mail、改产品代码、创建 PR、push probe、请求 ship、merge 或部署。

如果后续执行体没有收到原生 exact marker，它必须报告 TURN 已确认、park 等待，不能改用 inbox 或猜值。若存在 recovery residue，它进入 staged expected set；若 marker 已提交，则核验 exact added line。完成后用 handoff 保存 done receipt，报告真实 SHA，再由 Lead close/cancel 这条 no-PR run；正常不进入 QA。
