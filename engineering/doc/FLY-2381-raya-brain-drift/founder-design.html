● 3. 核心流程:一次巡视怎么走
图 1 · 触发 → 采样 → 证据门 → Codex 三选一 → 信封校验 → 才发一条 🔔。任何一关不过都是零输出。

三个触发点

  • 6 小时到点(PRD §8.7.2 你圈的 a);间隔写在一个你或运维能手改的文件里,改完 1 分钟内生效,不用重启。
  • 你刚记了一条目标:马上对一次,你能预期这次开口。
  • 进程启动:先做一次「启动探针」读数(不开口),证明这台机器上真的读得到;上次巡视不新鲜才顺手巡一次。

Codex 只能回三种

【无话】(没分岔)· 【证据不足】(读数不够支撑判断)· 【偏离】 + 一行「依据」(快照 id、目标 id、引用了哪些读数键)+ 正文。写成别的样子一律当无效,不发。

名词:快照(snapshot) = 某一时刻六个项目读数的一份存档,带 id 和采样时间,你和 QA 都能翻出来对。证据门 = 程序层的硬检查:没有活跃目标、快照过期、一个项目都读不到活动、目标文件损坏,四种情况直接跳过,连 Codex 都不问。

● 5. 目标怎么记(PRD §7 两阶段的第一阶段)
图 3 · 你在对话里自然地说,模型识别后写一行标记,程序逐字落盘、git 提交、回你一条 📌 收据;要撤就撤。
  • 不是填表(PRD §10.4 你否掉了填表):没有「目标:xxx」这种命令;你怎么说都行,Raya 在回答里写 【记目标】你的原话,程序才记。
  • 逐字:存进 goals.md 的是你那句话的原样(连首尾空格、全角字符都不动);只有发回 Discord 的显示副本会做脱敏。原话看起来像含密钥 ⇒ 拒收,不会偷偷改写后说「记下了」。
  • 存在 Raya 自己的记忆仓(raya-memory,和 MEMORY.md 同目录),每条带日期、你那条消息的链接、状态;撤销是改状态,不删行,历史可溯。
  • 幂等:同一条消息重放不会记两条;程序崩在半路也能靠「操作号」对账。

名词:幂等 = 同一件事做两遍和做一遍结果一样。git 提交 = 把这次改动存成一个带时间和说明的版本,以后能回看、能撤回。

● 7. 什么时候闭嘴(PRD §3 硬约束的机械保证)

你说过:「信息太少还出来说话,反而是干扰源。」这一条在代码里有五道闸,不靠模型听话:

  1. 证据门:没活跃目标 / 快照过期 / 没读到任何活动 / 目标文件坏 ⇒ 不问 Codex。
  2. 三选一信封:回复不是精确的三种之一 ⇒ 无效,不发。
  3. 依据校验:【偏离】里写的快照 id 必须是本次、目标必须是活跃的、每个读数键必须真的读到了值 ⇒ 任一不成立,不发。
  4. 巡视回合的中间碎碎念一律不出:只有最后那一条 🔔 能发。
  5. 节流 + 宁漏勿重:两次开口之间至少隔一个巡视周期(你刚记目标那次除外);发送结果不明时不重发。

到点没东西说就不说(§6.3 你圈的 A);「我看了,没有」那句附带项你没表态,本版不做。

● 9. 诚实边界:这版做什么、不做什么

做

  • 六个项目逐仓读数(git / GitHub / Linear 可选 / summary 文件观测),读不到明写原因。
  • 你说的目标逐字入库、可撤、有收据。
  • 6 小时巡视 + 记目标即巡 + 启动探针;偏离时一句可否掉的话,尾行写依据。
  • 你问「接下来一周该推什么」时,回答里带最新读数(快照 id、采样时间)和你的目标。

不做(每条是决定,不是遗漏)

  • 不排序、不做硬规则(§10.3);不做跨项目依赖/重复劳动检测(§10c 你砍掉的)。
  • 不做自动校准节奏、不做每日 Report(§8.7.3 另单)、不做「我看了,没有」心跳。
  • 不做 summary 未读/已读状态(FLY-2131 合同)。
  • 巡视回合不主动追问 Lead(PRD §5.3 主动侧的缺口,明写);追问只在你发起的对话里发生(FLY-2379)。
  • 不做「语音控制电脑」(等 FLY-1453 OS 级隔离)。
  • 不改 IDENTITY.md 本体、不改 summaries 合同、不改 FLY-2379 的对话/追问/安全语义。

已知的模糊处

  • 「chore」是启发式,可能把某个 Lead 真正的整理工作算成「非推进」——所以两条都给你。
  • 【偏离】的依据受控、正文自由:快照/目标/读数键机械校验,但正文里的措辞是模型写的;你能当场否掉,这就是设计边界。
  • goals.md 在记忆仓里,模型理论上能直接改它;程序的保证是「提交的内容一定是程序写的那份」+「外部改动会显成未提交改动、并在收据里告诉你」,不是互斥锁。
● 10. 上线怎么确认、你怎么验收

上线(9-06 教训:合入 ≠ 部署)

  • 顺序:FLY-2379 先合入并部署 → 本单合入 → 停 brain → 拉记忆仓 → 切到合入的版本并构建 → 补一行 RAYA_PROJECTS_FILE → preflight 通过 → 起 brain → 等 daemon 自己产出的「启动探针」事件(带新进程 id),核 GitHub 读数是「ok」还是明确的「读不到 + 原因」。
  • 运行期改巡视间隔:改一个 JSON 文件,1 分钟内生效;关主动开口也在同一文件。
  • 回滚:切回旧版本重建重启;目标文件用 git revert。

验收(真机,以你为准)

  1. 你在 #raya 问「接下来一周该推什么」→ 回答引用各仓真实读数(QA 用同样命令独立复采对数)与你的目标;读不到的项目明说。
  2. 你说一句目标(故意带个首尾空格或全角字符)→ 📌 收据;记忆仓最近一次提交只含 goals.md,原话逐字一致;说「撤掉」→ ↩️。
  3. 记下目标后 5 分钟内出现一条 🔔,引用具体日期/PR/目标原话、末尾二选一问题、尾行写依据;你回「不对,因为…」→ 她接得上。
  4. 撤光目标再触发 → 事件里是「证据不足跳过」,#raya 零新消息。
  5. 语音三命令与文字聊天照常;改间隔文件不重启即生效。
