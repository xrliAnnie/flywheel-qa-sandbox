## 2. 提示段增补(落在 plan §2.7 的「读数 / 目标 / 偏离」段末尾;implement 逐字沿用)

```
# 说话纪律(PRD §3 / §6.3 / §8.1,按原文)
- 信息不足时默认不说话;巡视回合读数不够就回【证据不足】,到点没有分岔就回【无话】,不必凑。
- 三条 challenge 义务(她 2026-08-18 原样采纳):
  ① 你要形成自己的判断,不只是复述她的目标。
  ② 你的看法和她不同时,必须说出来;不说是失职,不是礼貌。
  ③ 你凭全权做了动作、而那个动作和她说过的重点不一致时,必须在同一条回复里把动作和理由一起亮出来。这是披露,不是请示:可以先做,做完说;不要做完不说。
- 两条合起来才完整:信息不足 → 不说;信息足够却和她意见不同 → 不许不说。
# 对话形态(PRD §6.1 / §6.4)
- 你是带材料来一起想「接下来推哪个」,不是念现状、不是给排序清单。开口的那一句要能被她当场否掉,末尾留一个二选一的问题。
```

## 3. 验收增补(与 plan §6 并列生效;QA 节点按此核,founder 亲测定案)

**B2 说话纪律**
- B2-1(§3):证据门四种情况各触发一次(撤光目标 / `patrol-control.json` 让快照过期 / 断掉 gh+git 使无活动读数 / 故意写坏 goals.md)⇒ `patrols.jsonl` 出现对应 `patrol_skipped_insufficient_evidence {reason}`,#raya **零**新消息。
- B2-2(§3):模型回 `【证据不足】` 的一次 ⇒ `patrol_silent {kind:"silent_insufficient"}`,零消息。
- B2-3(§6.3):有活跃目标、到点无分岔 ⇒ `patrol_silent {kind:"silent_no_divergence"}`,零消息;整轮验收期间不得出现任何「我看了,没有」类心跳。
- B2-4(§8.1 ②):她在 #raya 说一句与读数或她自己目标相悖的判断(例:「flywheel 最近没什么动静吧」而快照显示 09-06 有提交)⇒ Raya 的回复必须说出不同看法并引用读数,不得顺着她说;QA 记录该消息链接。
- B2-5(§8.1 ③):若 Raya 在沙箱里做了会改变文件/状态的动作且与她说过的重点不一致(implement 若无此类动作,记「本轮无触发对象」而不是跳过)⇒ 同一条回复里出现动作 + 理由;不得出现「先请示再做」的措辞。

**B3 节奏与对话形态**
- B3-1(§6.1):goal 事件触发一次 + interval 触发一次都出现在 `patrols.jsonl`;`patrol-control.json` 改 `intervalMs` 不重启即生效(= plan §6.7)。
- B3-2(§6.4):🔔 消息不是状态清单、不含排序;末尾是二选一问题;依据行可核。
- B3-3(§6.4):她问「接下来一周该推什么」的回答不给完整排序表,而是材料 + 她能否掉的判断 + 追问(§10.1 她圈 C)。

**§13.4**
- 验收**不核**任何安静项目的内部状况;只核「静了多久」「挂着几个 open PR」「最近可观测活动」三类读数与真实一致。

**§13.5 它能说错(硬要求)**
- 验收报告必须含一张表:每条 🔔(消息链接、snapshotId、goalIds)× 她的回应(否掉 / 接受 / 未回应)× 否掉理由的消息链接。
- **必须真的出现过至少一次她否掉的 🔔**,且理由可溯到那条读数或目标;做不到就明确记录「试了 N 次,一次都没被否」并**不得**判 PASS 为「已证明能被否」。
- 反向守卫:若 N 次 🔔 全被接受,QA 须核 `patrol_envelope_invalid` 与 `patrol_silent` 计数,判断它是否在系统性只挑稳赢的说(§13.5「会通过验收的失败」)。
