报告页验证,不再泄漏 Chrome

FLY-1828 · 设计方案(已过 3 轮 Codex 独立评审)· 2026-08-17

一句话总结

给所有 agent 一条「验证报告页」的便宜正路(一条命令,默认零浏览器),配一个每分钟巡逻的收尸兜底 —— 验证规矩不放松,但那晚桌面上冒出来的 Chrome 大军不会再出现。

1 · 那晚发生了什么

8 月 16 日晚,你发现 dock 里冒出 8 个 Chrome 图标,追问「是谁一直在开 Chrome?我们在做什么视觉验收?」。实测:

Chrome 进程

17 个
卡死的截图进程(1.9GB)
10+ 小时
最长存活(设计寿命只有几秒)

这些截图进程本来应该「打开页面 → 拍一张 → 几秒内退出」。它们卡住不退,一晚上越堆越多。而且你的质疑很准:那晚的活大多是纯代码工作,真正需要看渲染效果的只有极少数 —— 大量浏览器是「过度验证」开出来的。

2 · 根因:三层叠出来的

  1. 规矩只算了收益,没算成本。「发给你的 HTML 必须先验证再交付」这条规矩是对的(是被「发过打不开的页」的事故逼出来的)。但执行时,agent 们把「验证」层层加码成了「开一个后台浏览器截图看看」,有时甚至拉起整套自动化浏览器(每个都在 dock 占一个图标)。
  2. 截图命令天生会卡死。agent 用的截图命令自带一个「虚拟时间预算」参数(本意是页面加载 3~4 秒后强制拍照)。但这个预算只在页面开始渲染后才开始计时 —— 实测那两个活了 10 小时的进程,访问的是一个已经关掉的本地预览服务:页面永远加载不出来,计时器永远不启动,进程就永远挂着。
  3. 没有人收尸。系统里已有一个 Chrome 回收器(FLY-766 建的),但它当时的任务范围是另一类浏览器(QA 自动化专用的 "Chrome for Testing"),代码注释里明确写着「正牌 Chrome 永不匹配」—— 这次泄漏的恰恰全是正牌 Chrome。不是它的 bug,是范围没覆盖到。

3 · 修法三件套(最小改动)

A 正路一条统一验证命令 flywheel-comm verify-report:默认零浏览器(只发一次网络请求,检查页面打得开、模板占位符没残留、交互脚本的安全许可证(nonce,浏览器允许页面脚本运行的一次性口令)齐全)。真需要看渲染时加 --screenshot:拍一张就走,30 秒硬超时,到点把整组进程杀干净、确认死透才收工。

B 兜底收尸巡逻:扩展现有回收器,新认一类目标 ——「一次性截图形态 + 已存活超 5 分钟」= 必然卡死,杀。正常截图几秒就退,5 分钟是 75 倍余量;QA 正在用的浏览器和你桌面开着的 Chrome 因为不带截图标记,永远不会被误杀。

C 规矩分级验收写进共享操作手册(skill,所有 agent 共用的操作指引文本):自产报告页 → 轻量校验就够,截图非必须;你要亲手点按的交互页 → 才做真视觉验收。并明令禁止再手拉无超时的裸浏览器命令。

4 · 收尸兜底怎么判「该杀的」

巡逻复用 Bridge 现有的节拍(零新定时器),对每个进程走这套判据 —— 设计原则是宁可漏杀、绝不误杀:

进程形态处置为什么
一次性截图 + 活过 5 分钟杀(先温和后强制,确认死透才记账)设计寿命几秒,活过 5 分钟 = 必然卡死
一次性截图 + 5 分钟内放过正常截图还在跑
QA 自动化长驻浏览器放过(走 FLY-766 原有逻辑,行为零变化)不带截图标记,可能正在干活
你桌面开着的 Chrome永不触碰不带后台标记
身份指纹对不上(进程号被复用)放过宁可下一轮再看,不杀错新进程

每杀一个都留一笔脱敏的审计账(记「杀了什么形态、活了多久」,但不记录网址里的访问口令 —— 报告链接是不可猜网址,不能把口令抄进长期账本)。

5 · 关键取舍与被拒绝的方案

决策选了拒了原因
验证入口flywheel-comm 子命令仓库里放个脚本agent 在任何目录都能调;脚本依赖仓库路径,QA 隔离环境够不着

6 · 诚实边界:这个设计不做什么

  • 不放松验证规矩 —— 发给你的 HTML 仍然必须先验证。
  • 不管 dock 图标问题的另一半 —— 图标来自 QA 自动化的「带界面」浏览器实例(正在干活,不能杀);「per-runner 浏览器不得产生可见图标」的硬约束由 FLY-1825 落地。时序上本单应先于或同批于 1825,否则 1825 把开浏览器的主体扩大后泄漏会成倍。
  • 不动 FLY-766 原有回收逻辑 —— QA 自动化浏览器的生命周期管理保持原样。
  • 操作手册(C)是另一个仓库的 PR —— 本仓代码先上线,手册文本随后跟进(顺序不能反,否则手册引用的命令还不存在)。
  • 各 agent 记忆里的旧习惯不能一键清除 —— 只能靠新手册文本逐步纠正;收尸兜底(B)就是为过渡期兜住的。
