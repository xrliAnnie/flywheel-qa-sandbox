一句话说明

同一个岗位在同一个项目里，首次开场就能找到它过去的经验；其他岗位、其他项目的经验不会被带进来。

home 是 Codex 保存个人文件的目录。上一单 B1 已让后续任务复用同一个持久 home；本单补上首次历史导入，并验证不会串人、串项目。

保存什么有什么用
项目键 + 岗位键只认系统中确定的身份，不从名字、任务标题或文字内容猜。
来源清单记录每份历史来自哪次执行，哪些资料没导入及原因。
内容快照保存当时的 Markdown 文件；Markdown 是用纯文本写文档的格式。
阅读索引与完整目录开场最多列 8 份近期经验，显示任务日期与名称；更早经验按任务号或主题检索，再打开相关快照。

重复与冲突怎样处理

内容指纹 是由文件字节算出的固定标识。同样一套文件只存一份，所有来源仍记下来；只要文字不同，就分别保存。

目录按任务发生日期排列，帮助找到相关经验；开场索引限制在 8 KiB 以内。KiB 是文件大小单位，8 KiB 约为八千字节，避免开场读入几百条来源清单。

两份旧经验互相矛盾时，两份都保留，当前任务的明确要求优先。我们不把“哪份更正确”的决定交给自动合并模型。

没有采用的做法原因
直接拼进 Codex 原生记忆自动整理可能重写或删除它们，不能保证历史一直在。
搬整个旧 home 或数据库会带入凭据、会话和无关状态，远超过记忆导入所需。
从显示名称猜归属可能把别的岗位或项目的经验带进来。
新增持续回流服务B1 已让后续任务住同一家，本单无需再造一套。

怎样证明它真的有用

RED / GREEN 指同一份测试在接线断开时失败、接好后通过。验收要在隔离测试房或真机跑真实文件和真实开场读取，不能只看路径不同。

四条都要留下什么证据
① implement 完成后经验还在任务结束后，持久 home 中仍有本次记忆标记。
② 下一任务开场读得到开场前文件已在；首轮实际读取并报告只存在历史中的标记。
③ qa 不见 implement 的经验qa 自己的正控可读，同时它的原生与历史记忆均无 implement 标记。
④ flywheel 不见 joycon 的经验joycon 自己的正控可读，同时 flywheel 的记忆均无 joycon 标记。

还要放入接近生产规模的夹具：605 条候选、217 份不同快照。把答案放在近期 8 份之外，验证 agent 能从完整目录找到并读取旧经验。

RED 分两层：一次性家且不回流，证明原来的跨任务丢失；单独关闭 B2 导入，证明首次旧历史读不到。真实蒸馏格式夹具证明运输，不代表 Codex 自动蒸馏已经即时发生。

明确的边界

2026-09-08 只读盘点：127 个旧家有候选历史，但缺少可靠的岗位身份（flywheel 126 个、sub 1 个），所以不会自动导入；原文件继续保留。这是设计阶段的盘点，没有执行迁移。

保留旧家，不接任务结束删除，不动公共家，不改记忆生成的等待时间或额度门槛。资料没有可信身份就留在原处，首次快照之后旧任务追加的内容也仍留在原处。

历史档案通过 shell 读取；shell 是执行本机读文件等命令的工具。它不会冒充 Codex 原生记忆工具支持的目录，也不会把全量旧文字塞进每次开场。

本单保证自动导入和开场提供的内容不串身份。它不是操作系统权限隔离；有其他文件访问权限的 agent 仍可能主动读取别处。
