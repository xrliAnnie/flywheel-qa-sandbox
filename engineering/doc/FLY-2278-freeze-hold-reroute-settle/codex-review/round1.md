# Design Review — plan.md (Round 1)

Date: 2026-09-03
Author: Codex
Status: CHANGES REQUESTED

## Summary

The plan has the right high-level shape: it maps all six rejected defects to named invariants, reuses the append-only attempt ledger and the existing operation table, centralizes the hold digest, and proposes unusually strong real-stream positive controls. It is not ready to implement yet, because the current projector makes the undeliverable path unreachable, the milestone order makes M3/M4 fail their schema constraint, and several transaction boundaries still allow a live or newly admitted recipient to be halted.

## What's Good (Keep)

- Keep the explicit A1-A9 acceptance matrix, especially the 12-cell hold predicate test, real producer paths, crash-injection tests, and the ban on direct attempt/episode fixture inserts.
- Keep `CMUX_LIVE_SESSION_STATUSES` as the StateStore authority. It already includes `ship_parked`, `awaiting_review`, and `design_done`, so the founder's legitimate-recipient rule can be tested against one shared set (`packages/teamlead/src/operational-terminal-status.ts:15-22`).
- Keep the single `StateStore.canonicalizeHoldResume` owner for both canonicalization and digest production. Preserving receipt lookup before consuming a one-shot confirm token is also the correct idempotent replay order (deleted reference `37dc5bd63^:packages/teamlead/src/bridge/hold-routes.ts:173-197`).
- Keep the decision to use real physical primary keys in `contract_ref`, reuse `workflow_delivery_operation`, and add no second saga table. The proposed controlled CHECK widening is preferable to weakening the constraint or creating another table.
- Keep settlement at the common settlement writer rather than inferring it from absence in watch. Closing the episode in the same transaction as the attempt is the correct semantic boundary.
- Keep M2+M3+M4 as one deployment/rollback unit. The detector, reroute path, and official resume door are not independently safe production features.

## Issues & Recommendations

1. **[BLOCKER] The terminal-unread mailbox path is unreachable in the proposed maintenance order.** `listRunnerDeliveryProjectionRows` excludes `DEAD`, superseded/dead rows, and terminal recipient sessions. More importantly, the projector runs before watch, exact-reads an excluded mailbox row, and settles it when the row is `DEAD` or its recipient is terminal. M1 then removes settled attempts from `listLiveWorkflowDeliveryAttempts`, so M2 cannot open the required `undeliverable` episode. Adding only the inflight columns while explicitly retaining the projection WHERE does not change this. **Recommendation:** define a terminal-unread ownership rule before implementation: for `acked_at IS NULL && (DEAD || recipient terminal)`, projector must not settle the attempt; watch must exact-read the physical row by the live attempt's `contract_ref.pk` and open `undeliverable`; settlement occurs only after reroute/cancel/other explicit resolution. Add a positive control that runs the real projector-first maintenance order and proves the episode remains visible. **Evidence:** `packages/flywheel-comm/src/db.ts:2617-2642`, `packages/teamlead/src/bridge/delivery-contract/projector.ts:114-134`, `packages/teamlead/src/bridge/plugin.ts:7439-7462`, `engineering/doc/FLY-2278-freeze-hold-reroute-settle/plan.md:63-72,147`.

2. **[BLOCKER] `freezeRunTx` cannot provide the claimed same-decision revalidation with its planned inputs.** The signature carries precomputed `evidence` but no recipient execution id, shape-entered timestamp, age, or threshold. Current attempt refs contain only table/pk/runId, so StateStore cannot re-read the intended recipient session from that input. CommDB is a separate store, which also means the plan cannot literally re-read all three evidence sources in one StateStore transaction. In addition, `hasRecentMessagesFrom` uses SQLite's real `datetime('now')`, while the classifier and tests use injected `now`; the proposed `+31min` controls therefore compare different clocks. Finally, watch is specified to open the frozen episode and enqueue its one warning before calling the writer, even though the warning text claims to know whether the run was frozen. **Recommendation:** pass `recipientExecutionId`, `shapeSince`, `thresholdMs`, and a CommDB evidence snapshot with `observedAt` into one StateStore method. Inside its transaction, re-read run plus session status/heartbeat/activity, recompute age and verdict at one decision time, then atomically write episode, run status, run event, and alert. Replace or extend the CommDB probe so it accepts the same explicit cutoff. Add barriers where session status or activity changes after detection but before the transaction; both must refuse the hold. **Evidence:** `engineering/doc/FLY-2278-freeze-hold-reroute-settle/plan.md:31-32,41,62,69-70,134`, `packages/flywheel-comm/src/db.ts:4577-4587`, `packages/teamlead/src/StateStore.ts:1082-1110,8692-8703`, `packages/teamlead/src/HeartbeatService.ts:1920-1927`.

3. **[BLOCKER] `recordWorkflowDeliveryRerouteOperatorRequired` remains an unconditional, multipurpose hold path.** The plan resolves a successor outside the hold transaction and then restores the old recorder “unchanged”; that recorder only rechecks the open episode before changing an active run to held. A successor can therefore be admitted between lookup and commit. The deleted operation loop also invokes the same holding recorder for reroute-cap exhaustion, apply failure, and unsupported family; the plan retains “third reroute -> operator_required” without a threshold or liveness check, even though that branch already has a live successor target. This is a remaining path that can halt a live recipient. **Recommendation:** reserve a holding transition for one precisely named invariant: grace elapsed, original recipient terminal, no current CMUX-live successor at commit time, and original liveness absent/unknown. Re-resolve or CAS the current activation inside that StateStore transaction. Reroute cap/apply/stall failures should use the existing outcome/stalled alert without halting the run unless they separately pass an explicit hold predicate. Add a successor-admitted-between-scan-and-commit barrier test and a third-reroute-with-live-successor negative hold test. Also rewrite the global goal so freeze and undeliverable policies are distinct; the original recipient cannot be both terminal (A2) and nonterminal (line 8). **Evidence:** `engineering/doc/FLY-2278-freeze-hold-reroute-settle/plan.md:8,18,20,72,79,124-126`, deleted reference `37dc5bd63^:packages/teamlead/src/StateStore.ts:36429-36452`, deleted reference `37dc5bd63^:packages/teamlead/src/bridge/delivery-operations.ts:99-127,147-171`.

4. **[HIGH] `deferred_alive_at` is specified as a permanent suppression latch for evidence that naturally expires.** After grace, the plan says an `alive` verdict sets the column once and an already-set row is skipped. If that terminal recipient stops sending messages ten minutes later, the undeliverable episode remains open but is never reconsidered or escalated. This turns one transient signal into permanent immunity and adds a schema column without closing a named defect. **Recommendation:** reclassify every open undeliverable episode on every post-grace pass. If the column is retained, make it audit-only and never a skip predicate; simpler is to delete it and perform zero writes while the recipient is alive. Add `alive at T`, then `absent after the activity window` as a positive transition test. **Evidence:** `engineering/doc/FLY-2278-freeze-hold-reroute-settle/plan.md:18,37,72,106,124`.

5. **[BLOCKER] The schema migration is sequenced after its first writers.** M3 inserts `kind='reroute'` and M4 inserts `kind='hold_resume'`, but the current table accepts only `resident_expiry`; the widening is deferred to M5. Under the stated rule that every milestone reaches GREEN before the next one, fresh and migrated databases must reject M3/M4. **Recommendation:** move both the fresh DDL change and the legacy table rebuild ahead of M3, ideally into M0/M1 as a schema prerequisite. Keep retirement in M5. Test a non-empty legacy table containing a valid `resident_expiry` row plus its referenced attempt, not only an empty database, and verify row contents/index/FK after two startups. **Evidence:** `packages/teamlead/src/StateStore.ts:20013-20035`, `engineering/doc/FLY-2278-freeze-hold-reroute-settle/plan.md:38,50,75-95,107`.

6. **[HIGH] Real primary keys fix defect 4 only halfway; current projection and settlement are not generation-aware.** The proposed rework/carrier refs add `routeRevision` or `redriveGeneration`, but every current helper that finds, advances, or settles the live attempt matches only family/table/pk. A late event from the old physical generation can therefore advance or settle the new child that shares that pk. Restoring the old stage/apply split also mints and exposes the child before the State-native physical row is rerouted, leaving a crash window where the live ledger and authority disagree. A `SELECT 1` pk test cannot detect either failure. **Recommendation:** for State-native rework/carrier, perform physical reroute, parent supersession, child mint, and operation transition to applied in one StateStore transaction, following the existing carrier-redrive atomic pattern. Make subsequent clock/settle selectors use attempt id or verify the version field, and add stale-old-generation event tests. Retain the cross-store saga only for the three CommDB families. **Evidence:** `engineering/doc/FLY-2278-freeze-hold-reroute-settle/plan.md:20,44-45,77-80,126`, `packages/teamlead/src/StateStore.ts:35542-35632,48638-48687`, deleted reference `37dc5bd63^:packages/teamlead/src/StateStore.ts:36008-36143,36218-36424`.

7. **[HIGH] Restoring the old hold registry logic “except for digest” cannot satisfy A3 for all 19 shapes.** The deleted `listWorkflowHolds` required `run.status === 'held'` for every descriptor, but `carrier_needs_lead` is a delivery-level hold produced while the run can remain active. The old resume path also unconditionally reactivates the run after resolving any one hold. With two current run-level holds, resuming one both unfreezes the run and makes the remaining hold fail its `run_held` precondition, so it cannot be resumed through the promised door. **Recommendation:** add an explicit shape scope/effect to the registry and make preconditions shape-specific. Delivery-level carrier holds must be listable/resumable from authoritative delivery state without requiring a held run. After a repair, reactivate the run only when no other current run-scoped hold remains. Add a real `carrier_delivery_exhausted -> needs_lead` positive and a two-simultaneous-holds test. **Evidence:** `engineering/doc/FLY-2278-freeze-hold-reroute-settle/plan.md:19,35,84-88`, deleted reference `37dc5bd63^:packages/teamlead/src/StateStore.ts:36905-37013,37728-37753,37918-37934`, `packages/teamlead/src/StateStore.ts:49627-49715`.

8. **[HIGH] M5 deletes unique rework `wake_delivered` stall coverage under an incorrect duplication assumption.** The legacy dispatcher scans `wake_delivered` and alerts at 30 minutes. The generic contract maps that state to `received`, but received-stage deadlines are explicitly limited to launch and carrier, so it does not replace the rework alert. FLY-2268 is excluded and unstarted, making the deletion an immediate observability gap. The unsafe hold branch should go, but the alert branch is not currently duplicate. **Recommendation:** resolve the pending Lead switch in the plan before implementation. Either wire rework received-stage stalls into the existing contract with the planned liveness classifier and real-stream control, or retain a non-halting, fixed-policy alert path until FLY-2268 lands; in both cases delete the destructive legacy hold and its env knob. **Evidence:** `engineering/doc/FLY-2278-freeze-hold-reroute-settle/plan.md:14,46,93,117,145`, `packages/teamlead/src/bridge/workflow-engine-dispatcher.ts:1129-1261`, `packages/teamlead/src/bridge/delivery-contract/policy.ts:3-15`, `packages/teamlead/src/bridge/delivery-contract/classify.ts:42-56`, `packages/teamlead/src/StateStore.ts:35289-35309`.

9. **[MEDIUM] A3's auth status contract is not true at the production mount.** `/api/runs` is already behind `tokenAuthMiddleware`; an arbitrary wrong bearer is rejected there with 401 before the proposed per-route `requireMaster` can return 403. A router-only test can therefore pass while the deployed route has different behavior. Also, `loopbackSelfOrigin` validates only Host; it is not the old Origin/Referer same-origin guard. **Recommendation:** state whether the accepted boundary is “loopback Host” or “loopback Host plus same Origin,” then test the fully mounted app and CLI headers. Preserve the outer middleware and change A3 to its real 401 invalid-token behavior unless there is a deliberate, repo-wide auth change. **Evidence:** `packages/teamlead/src/bridge/plugin.ts:1033-1062,4207-4230`, `packages/teamlead/src/bridge/runs-route.ts:350-363`, `packages/teamlead/src/bridge/loopback-origin.ts:21-46`, deleted reference `37dc5bd63^:packages/teamlead/src/bridge/hold-routes.ts:213-252`.

10. **[MEDIUM] The settlement move needs an explicit timestamp/attempt contract and a complete caller sweep.** The helper currently has no `now`, identifies its target only by family/table/pk, and returns immediately after a successful attempt update. Adding episode closure after that return would silently skip the common case. There are more concrete callers than the three logical test categories named in A5, including baseline, gate-holder, land, launch rollback/abandon, carrier completion, and projector paths. **Recommendation:** change the helper to resolve the exact attempt id, update it, close its episodes with an explicit authoritative timestamp, and only then return; make replay verify the same reason. Update every caller and retain crash rollback coverage. **Evidence:** `packages/teamlead/src/StateStore.ts:35602-35633,26580-26585,35320-35329,35696-35712,47678-47684,55215-55221,56229-56234`, `engineering/doc/FLY-2278-freeze-hold-reroute-settle/plan.md:21,63-64,127`.

11. **[MEDIUM] M2 cannot be GREEN under its own end-to-end acceptance before M3 exists.** M2 says a successor must reroute and cites A2 as its positive control, while the reroute writer and physical-family implementations are introduced only in M3. This is separate from deployment atomicity: it makes the required RED/GREEN commit history internally inconsistent. **Recommendation:** either combine M2 and M3 into one implementation chunk or constrain M2 GREEN to episode/grace/hold-refusal behavior and move the successor-reroute positive control to M3. **Evidence:** `engineering/doc/FLY-2278-freeze-hold-reroute-settle/plan.md:18,50,66-80`.

12. **[MEDIUM] The code map points new run event kinds at a nonexistent whitelist.** `StateStore.ts:58253` is the `WorkflowEngineAlertPayload.metadata.workflowEngine.disposition` union, not a run-event kind whitelist; run-event appenders accept `kind: string`. Following the plan literally would mix event kinds into alert dispositions while still omitting the three actual new alert dispositions. The claimed reusable HeartbeatService timestamp helper is also a private inline parser. **Recommendation:** replace the stable-identifiers row with two accurate tasks: run event kinds need producer/replay tests but no whitelist edit; `delivery_contract_frozen`, `delivery_reroute_outcome`, and `delivery_operation_stalled` must be added to the alert disposition union. Name the existing shared SQLite timestamp parser or explicitly extract one instead of referring to a nonexistent helper. **Evidence:** `engineering/doc/FLY-2278-freeze-hold-reroute-settle/plan.md:40,62`, `packages/teamlead/src/StateStore.ts:43093-43143,58198-58254`, `packages/teamlead/src/HeartbeatService.ts:1920-1927`.
