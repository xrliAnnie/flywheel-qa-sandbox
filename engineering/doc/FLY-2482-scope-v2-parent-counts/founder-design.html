一句话结论

今天那份自己会刷新的 机器页,在取数那一层就把所有「还没开始」的子单扔掉了;本单让它把这些子单捡回来,并给每张子单加一格「我挂在哪个 Epic 下」、给每个 Epic 加一格「下面 6 种状态各几张」—— 只动数据,不动页面长相;你已经在看的三样东西(现在可以开始的、依赖要减法的、卡住说了一声的)和 Lead 每小时巡检信里的数字一个字都不变。

PRD 里你定的本设计怎么落
§6.5 · 洞 E:范围规则不再按状态排除子单,「显不显示」交给页面取数规则升 scope.v2:删掉那一行 backlog 过滤;每张子单进文档
§6.1 · 洞 A:每张子单要有 parent,出处是 Linear,缺了要明说子单查询多要一个字段 parent;缺 ⇒ 显式 no_parent 并进「缺什么」清单
§11 G · 每个 Epic 一格 counts:在跑 / 等依赖 / 可起跑 / 未开始 / 已完成 / 已取消 / 共计派生规则 counts.v1,按你在样子稿上看过的分法数,只看 Linear 状态与依赖线
§6.2 · Epic 徽标照抄 Linear,不另算第二个状态不做 rollup 不新增;计数在徽标旁,不是状态
「日常」筐规则保留不动不碰

今天丢在哪儿,丢了多少

取数代码在把 Epic 子树全部走完之后,有一行 filter(state.type !== "backlog"),把 Backlog 状态的子单直接丢掉,然后才算「谁在范围内」。所以:

  • PRD 2026-09-09 实核:5 个 In Progress 的 Epic 在 Linear 共 28 张子单,机器页里只有 17 张 —— 少的 11 张全是还没开始的(FLY-2360 / 2370 / 2389–2393 / 2399 / 2447 / 2448 / 2459)。
  • 这些子单之间的依赖线也一并看不见:比如 FLY-2459 在等已经做完的 FLY-2445,页面上无从知道「它其实可以起跑了」。
  • 文档里每张子单没有 parent 字段;PRD 做样子稿时只能把父子关系硬编码进脚本。
这不是页面的问题,是数据层的问题:F2(每个 Epic 挂它的子单)、F9(未开始排下面)、F10(依赖显示)在这一层就做不到。所以先修这一层,页面长相留给后面的单。

核心流程:一次刷新会发生什么

图 1 · 蓝色是本单改动的步骤;红色是「宁可这一轮不出页」的两道闸;绿色是既有的发布闸门
  1. Bridge 去 Linear 找所有 In Progress、且有子单的父单(今天 6 个)。
  2. 逐个父单把子单翻页取完;新增:每张子单顺便要一个 parent 字段,并跟「我是从哪个父单底下取到它的」对账 —— 对不上说明取数中途有人把单挪走了,这一轮不出页,等下一次刷新(不发布一份自相矛盾的页)。
  3. 新增:快照包含全部后代,不再按状态丢;每张子单一格 parent,每个父单一格 counts。
  4. 你已经裁过的规则(现在可以开始的 ready.v1、依赖减法 subtraction.v1、卡住信号 signals.v1)和 Lead 巡检信,只看「非 backlog」的子单 —— 这正是它们一直以来的定义域(你 2026-09-03 裁的「范围 − backlog」),本单只是把它从取数层的副作用变成规则里的一行显式判断。
  5. 文档自检:把 counts / ready / stuck / review 全部重算一遍比对;不符就不出页。
  6. 回执 + 固定页发布;HTML 超过 512KB 会被拒(既有闸门)。

数据模型:文档里多了什么

图 2 · 每个字段都是一格 Cell:带值、带出处、带看到它的时间;缺了写明为什么缺
items[].parent新增。值 = 父单号(如 FLY-2441);出处 = Linear 的 issue.parent;缺 ⇒ no_parent,并进「缺什么、缺在哪」。 header.root_counts[]新增。每个父单一格,顺序与父单列表一致;出处 = 派生规则 counts.v1,列出它读了哪些格。PRD 写的 roots[].counts 就是它。 header.scope_definition规则号 scope.v1 → scope.v2;值里明写 item_state_filter: "none"(用「明说不排除」而不是「字段消失」)。 不变文档版本号、表结构、固定链接、渲染;rollup 不新增。

每个 Epic 的六个数怎么数(counts.v1)

沿用你在样子稿上看过的那一行「0 在跑 · 1 等依赖 · 0 可起跑 · 1 未开始 · 共 2」的分法,只看 Linear 的状态和依赖线,不看机器账本 —— 这符合你定的「排期决定的唯一真相是 Linear」。

数怎么判
在跑 liveLinear 状态是 In Progress(started)
等依赖 waiting还没开始(Backlog / Todo / Triage),且至少有一条依赖线指向没做完的单
可起跑 free还没开始,有依赖线,但它们全部已 Done —— 依赖已解开
未开始 idle还没开始,没有任何依赖线
已完成 done / 已取消 canceledLinear 终态
共计 total六者之和 = 这个 Epic 下的子单数;没有子单 ⇒ 全 0

与样子稿唯一的差别:样子稿把「已取消」的前置也当「解开」;这里对齐你裁过的 ready.v1(只有 Done 才算解开),避免同一页出现两套「解开」的定义。Linear 将来若加了第七种状态,该 Epic 这一格整格写「不认识这个状态」,不出半对的数。

什么变、什么不变(回归边界)

图 3 · 绿色:值逐字节不变;橙色:如实变宽;蓝色:新增;灰色:不碰
  • 不变:「现在可以开始的」「依赖要减法的地方」「卡住说了一声的」三块的值,以及 Lead 巡检信里「范围内 N 张未完成 · 可开始 · 等前置 · 在跑」四个数。做法是一个共享判断 isSchedulable(= 不是 backlog),四处都引用它,一处真相。
  • 如实变宽:「谁在等我」(blocks)会多出还没开始的下游;「缺什么」清单会多出这些子单缺的验收节。这是把真相补全,不是回归。
  • 新增:parent 与 counts,给后面的 F2 / F9 / F10 页面用;本单不渲染它们,今天只在原始 JSON 和回执里看得到。
Codex 评审第 1 轮抓到两处会让「不变」失守的漏口(依赖减法里一位「是否在范围内」的抄写、卡住信号对 backlog 单的聚合),第 2 轮抓到验收断言与规则自相矛盾;都已改进 plan,并各有一条测试固定。

关键取舍与被否掉的方案

问题选了否掉了,为什么
backlog 子单怎么进来取数层删过滤,规则升 scope.v2「保留过滤、另附一份被排除名单」—— 仍是取数层静默丢弃,依赖线还是拿不到
parent 从哪来向 Linear 多要一个字段,并与遍历上下文对账「从我是在哪个父单底下取到它推出来」—— 推出来的不是读来的,PRD 明写出处是 Linear
对账不一致怎么办这一轮不出页,等下一次刷新「按 Linear 说的算」—— 可能把子单算进错的 Epic;「按遍历说的算」—— 出处不诚实
六个数看什么只看 Linear 状态 + 依赖线「在跑」看机器账本的会话 —— 账本读失败会把计数弄缺;且与「Linear 是排期唯一真相」相悖
三块既有规则怎么保证不变规则内部显式钉域「非 backlog」「让它们自然变宽」—— Lead 巡检信数字会跳,验收也明写了回归
计数放哪每个父单一格,与父单列表同序「塞进父单列表那一格里」—— 一格里放不下第二个出处;「整体一格」—— 一个 Epic 算不出会拖垮所有 Epic

容量与风险

  • 固定页体积:今天真页 261KB = 固定 36KB + 21 张卡 × 约 10.7KB。把 backlog 子单加回来后估 32–40 张 ⇒ 363–445KB,仍在 512KB 之内;天花板约 45 张卡。超过时固定页会停在上一版并留下一个明确的失败记号(epic_html_too_large),不会悄悄发一份坏页。
  • 瘦身不在本单(不改渲染);Lead 已把「卡片瘦身」记为 E3 候选后续。
  • 设计期数不出 FLY-2481 名下有几张 backlog 子单(本机没有 Linear 读权限,Bridge 的 issue 列表不带 parent);验收当天由 QA 记实数。
  • 零迁移:数据库只存回执和摘要,不存整份文档;新字段上线后第一次刷新自然产生新版本、同一个链接重新发布。回滚 = revert 一个 PR。

验收怎么看(QA 当天,不写死「28」)

  1. 新页的子单数 = 用与引擎同一套递归查询在 Linear 数出来的全部后代数;每张子单的 parent 与 Linear 一一相等(不抽样,全量)。
  2. 每个 Epic 的六个数与 Linear 子单状态手工分类逐个相等,共计 = 后代数。
  3. 三块既有规则的值里没有任何 backlog 子单(依赖减法里的「前置」可以是 backlog 单,但必须标「不在范围内」);Lead 巡检信的四个数与最近一份文档对得上。
  4. 固定页 HTML 字节数 ≤ 512KB,把实数写进报告。
  5. 单测全绿的命令输出;固定页版本号前进。

PRD 写的「5 个 Epic / 28 张」是 2026-09-09 04:40Z 的数;之后 FLY-2481 进了 In Progress,今天已是 6 个父单。验收按当天实数对账。

诚实边界:本单做什么、不做什么

做不做
取数层捡回 backlog 子单(scope.v2)不改页面长相、不排序、不碰「现在要你看」(attention)
每张子单一格 parent,缺失显式 no_parent不渲染 parent / counts(F2 / F9 的事)
每个 Epic 一格 counts(六个数 + 共计)不新增 rollup(Epic 徽标照抄 Linear,§6.2 已裁)
三块既有规则 + Lead 巡检数字逐字节不变,各有测试固定不给卡片瘦身、不动 512KB 上限(E3 候选)
顺手把 PRD 需求表 F3 那行「待裁定」改成 §6.2 的已裁结论不动「日常」筐规则、不动依赖账本、不动数据库、不动命令行工具

一条刻意保持的旧行为:一张被挪回 backlog 的单,若 14 天内还有停机/提问信号,Lead 巡检信仍然不会看到它 —— 与今天一致;要把它们抬进巡检是另一张单。
