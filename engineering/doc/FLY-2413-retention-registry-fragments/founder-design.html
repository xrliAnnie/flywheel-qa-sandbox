01 / 一句话

每张表各写自己的分类文件，共同检查仍能发现漏登记。

目前，几个并行功能只要新增数据库表，就会改同一份分类表、测试和总清单。方案将登记按表拆开，让不同表进入不同文件。

一表一文件漏登记仍报错保留现有清理规则

稳定身份：数据库名 + 表名
例如 comm 库的 mailbox_identity 表。不同数据库允许同名；同一数据库同一张表只能登记一次。
保留分类：人工审查的处理结论
每个小文件只写数据库、表名、保留类别。分类说明能否清理；文件本身不能新增删除规则。
摘要：文件内容的标识
固定顺序记录全部分类文件和加载代码。它绑定激活凭证与待执行清理计划；文件变化，旧证据不能继续授权删除。

04 / 为什么这样选

选择：每张表一份 JSON 文件
JSON 是保存结构化数据的文本格式。文件由目录自动发现，不需要再维护一个集中导入清单；不同表可以分别追加。
不采用：从数据库自动批准分类
数据库只知道表存在，不知道哪些记录是授权依据。若实际状态同时生成期望答案，漏登记也可能一直绿。
不采用：每个模块一份大表
同一个模块里的并行工作仍会争抢同一份文件。按表划分才与这次冲突原因对应。

05 / 怎样证明防线还在

变异体测试是故意破坏一项条件，确认测试会发现错误。本单要求保留正常通过、故意破坏后失败、恢复后通过的三段证据。

  • 两项独立变更各加一张表的登记，合并后得到完整并集，共同测试无需修改。
  • 数据库多一张未登记表、登记重复、必需表缺失，分别报出明确错误。
  • 故意关闭未知表检查或缺表检查，对应负向测试必须失败。
  • 只改分类文件，旧激活凭证与未完成清理计划分别拒绝；待删记录仍在。

这些是后续实现的验收要求，当前没有声称新实现已通过。

06 / 迁移与回退

一次性将现有分类拆成小文件，逐张核对分类完全一致；移除会反复冲突的总清单和总数量断言。原有专属保护测试继续存在。

新格式会使旧激活凭证和未完成清理计划失效。系统不得自动重新签发；需要继续清理时，沿用既有授权流程。已经完成的历史回执保持可读。

回退时成组回退分类文件、读取代码和摘要规则。数据库结构与历史证据不改写。

临时建库检查能发现实际创建表中的未登记项。延迟创建和历史表仍由专属测试与真实清理入口检查覆盖，不能把一次初始化当作完整生产证明。移除旧总清单后，单独多登记一张不存在的表可能直到真实清理入口才被发现；这项覆盖限制已列入评审建议。
