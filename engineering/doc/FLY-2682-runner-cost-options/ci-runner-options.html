👉 我的建议：不买机器

先把按需矩阵（FLY-2681）做完，同时把 CI 从 GitHub 自家的 runner 搬到 Ubicloud —— 一家按分钟收费、比 GitHub 便宜约 6 倍的托管 runner。 月账单从今天的约 $1,486 降到约 $104（其中一半是按需矩阵省的，另一半是换供应商省的）， 你只需要开一个账号、绑一张卡、点一次授权。

为什么不买机器：省下的那点钱（租一台服务器 $77/月 vs Ubicloud $104/月，差 $27） 换来的是我们多花 3–5 个人日去搭隔离环境、以后我们自己扛机器的健康， 而如果放你家里，停电断网死机都得你去重启。为了每月 $27 不值得。

什么情况下改选别的：如果 Ubicloud 上线一周后并发跟不上或不稳定 → 换 Blacksmith（贵一些但同样零运维）。 如果两家都不行，或者用量再涨 3 倍以上 → 那时才去租一台 OVHcloud 独立服务器（$77/月）。 任何时候要回头，都是改一行 runs-on: 的事。

📇 每个方案展开说

1 · 什么都不买

现在就该做
今天用量 $1,486/月  ·  矩阵之后 $669/月  一次性 $0

继续用 GitHub 自家的 runner，只做两件事：把按需矩阵（FLY-2681）做完，把 Actions 预算上限调高到不会再撞。

好处

  • 零风险、零新账号、零新供应商，今天就能生效
  • 省下的那一半（$817/月）是纯赚，不管后面选哪家都保留
  • CI 停摆这个最疼的问题当天就解决

代价

  • 就算砍一半，每月还是 $669 —— 比第三方托管贵 6 倍
  • 用量再涨（多几个 Runner 并行开发）账单就跟着涨
你要做
GitHub → Settings → Billing → Spending limit，把 Actions 的上限调到 $400/月（或干脆不限）。一次，5 分钟。
够不够用
够。这是今天的状态，实测峰值 54 个 job 同时跑也没排队。
安全
无新增风险。
退路
不需要退路，这就是现状。

2 · 换 GitHub 自家更大的 runner / 预付

省不了钱
今天用量 $1,560/月起  ·  矩阵之后 $702/月起

GitHub 的大号 runner：4 核 $0.012/分钟、8 核 $0.022、16 核 $0.042 —— 分别是 2 核价格（$0.006–0.008）的 2 倍、3.7 倍、7 倍。 问题是我们最重的 job 是 shell 测试，它们是一条一条串着跑的，多给核心不会快一倍。 给 4 核只能快大约 30%，账反而更贵。

关于「预付折扣」：GitHub 的 Actions 价目表里没有任何按量或预付的折扣档。 唯一的「预付」就是把 spending limit 调高，单价一分不变。（只有 Enterprise 合同能另谈，我们不在那个盘子里。）

好处

  • 唯一真实收益：最长那个 19 分钟的 job 大概能缩到 12–13 分钟，等 CI 的体感变好
  • 改一行就能试，不用开任何账号

代价

  • 总账更贵，跟「省钱」这个目标反着走
  • 大号 runner 不吃计划里赠送的免费分钟，一分钟都要付
你要做
什么都不用做。
结论
可以作为「哪天等 CI 等到烦」的单独小改动，但不是成本方案。

3 · 租一台独立服务器

备胎，暂不做
$77/月（OVHcloud RISE-S）  一次性 $77 开通费 + 3–5 个人日工程

价格不随用量变 —— 跑多跑少都是这个数。我比了两家：

OVHcloud
RISE-S
$77/月 + $77 开通费。AMD Ryzen 7 9700X（8 核 16 线程）、64 GB DDR5 ECC、2×512 GB NVMe。美国公司、美元结算、机房在美国 —— 对你最省事。
Hetzner
AX42-1
€97.30/月（≈ $112）+ €49 开通费。8 核 16 线程、64 GB DDR5 ECC。注意：Hetzner 2026-06-15 刚大幅涨过价，以前的「欧洲最便宜」已经不成立了。
Hetzner
竞拍区
€108/月（≈ $124），Ryzen 7 7700 / 64 GB / 2×1 TB NVMe，开通费 €0。但竞拍区是捡剩的，型号和价格每天变，不适合长期依赖。

一台 8 核 16 线程够不够？ 我按实测算过：今天的全量需要每月 6,192 个 vCPU-小时，一台 8 核 16 线程的机器满打满算能提供 11,680 —— 用到 53%， 平时够，但峰值 54 个 job 同时来的时候会排队。矩阵之后只需要 2,786，利用率降到 24%，就很宽裕了。 所以这个方案必须等 FLY-2681 上线之后再评估，现在上会被峰值噎住。

好处

  • 成本封顶。用量翻倍账单也不变，这是它唯一真正的优势
  • 硬件比 GitHub 的共享 2 核快得多，CI 整体会明显变快
  • 机器在数据中心，坏了对方换硬件，不用你管物理

代价

  • 我们要花 3–5 个人日搭：一次性 runner + 每个 job 一个用完就扔的容器 + 监控 + 一键切回的开关
  • PR 里的代码会跑在我们自己的机器上 —— 必须做隔离，不然任何人提个 PR 就能在我们机器上执行代码
  • 机器的健康从此是我们的事：磁盘满了、系统要更新、卡死了要重启（是我们 ssh 上去，不是你）
  • 省下的钱不多：比 Ubicloud 只便宜 $27/月
你要做
去 OVHcloud 开账号、绑卡、下单（可能要做一次身份验证）。大约 20 分钟。之后的一切都是我们的事，不会有人来找你重启机器。
安全
这是自托管最大的一条：PR 代码跑在我们自己的机器上。做法是每个 job 开一个一次性容器、跑完即毁、机器上不放任何 secret、出站网络限白名单。这也是那 3–5 个人日的主要去处。
退路
workflow 里把 runs-on 写成变量，一行切回 ubuntu-latest，几秒生效。

4 · 租云 VM，用完即关

不划算
今天用量 $61–159/月  ·  矩阵之后 $34–61/月  一次性 5–8 个人日

Hetzner Cloud 按小时计费：CCX33（16 个独占 vCPU / 64 GB）€0.2219/小时 —— 只在需要时开 8 小时/天就是 €53/月（≈$61）； CX53（16 个共享 vCPU / 32 GB）干脆包月 €29.49（≈$34）封顶。数字很漂亮。

但「用完即关」这四个字要我们写一套自动伸缩：监听 GitHub 的 job 事件 → 开机 → 注册 runner → 跑完 → 关机， 还要处理开机失败、僵尸机器、并发打架。5–8 个人日，换来比方案 3 每月再省 $20–40。 拿工程时间换这点钱，不值。（同样提醒：Hetzner Cloud 在 2026-06-15 涨价很凶，CCX 系列涨了 120%–170%。）

你要做
开 Hetzner Cloud 账号、绑卡、过身份验证（Hetzner 对新账号有人工验证流程，可能要一两天）。
够不够用
够，但每次冷启动要等 1–2 分钟，PR 的第一个反馈会变慢。

5 · 买一台机器放家里 / 办公室

最不推荐
一次性 $1,400–2,000 价格未验证  ·  之后每月 $10–20 电费  + 4–7 个人日工程

价格标「未验证」是因为：今天（2026-09-17）Apple 的商店页面价格是脚本渲染的，我读不到； 而且新的 M6 Mac mini 9 月 22 日才开始预订。上面的区间是量级估算，不是查到的官方价。

更关键的是这里有个技术错配：我们的 CI 全部跑在 Linux 容器里。 Mac mini 是 macOS，要跑 Linux 容器得再套一层虚拟机，慢且多一层会坏的东西。 真要买，该买的是一台 Linux 小主机，不是 Mac mini。

好处

  • 付一次钱，之后每月只有电费，两年摊下来单看钱是最便宜的
  • 机器是自己的，想怎么用怎么用

代价（这栏才是重点）

  • 你会变成这台机器的运维。停电、断网、路由器重启、机器死机 —— 都得有人走过去按一下，而那个人只可能是你
  • 家里网络一断，所有 PR 的 CI 一起停 —— 跟现在撞账单上限一样疼，但这次没有「加预算」这个快速解法
  • 它会发热、会响、会占地方，要一直开着
  • 硬件坏了没有远程换件的人，返修期间 CI 全停
  • 钱花出去就收不回来了，选错了只能吃下
你要做
选型、下单、收货、找地方摆、接网线和电源、以后长期负责它还活着。这正是你说不想要的那种事。
结论
除非你本来就想在家放一台可以干别的活的机器，否则这一档我建议直接划掉。

6 · 第三方托管的 Actions runner

推荐
Ubicloud $232/月 → 矩阵之后 $104/月  一次性 $0 + 半个人日

跟 GitHub 一模一样的用法 —— 他们提供机器、我们按分钟付钱、机器每跑完一个 job 就销毁。 区别只有单价。我们这边要改的就是 workflow 里那一行 runs-on: ubuntu-latest → runs-on: ubicloud-standard-2。

Ubicloud
$0.00125/分钟（2 vCPU / 8 GB）—— 比 GitHub 便宜 4.8–6.4 倍。高配版 $0.002/分钟。按我们的量：今天 $232/月，矩阵之后 $104/月。
Blacksmith
$0.004/分钟（2 vCPU），每月送 3,000 分钟，号称硬件比 GitHub 快 2 倍。按我们的量：今天 $731/月；如果真快 2 倍、分钟数减半，实际约 $366/月。矩阵之后约 $161–322/月。作为备选：更贵，但公司更成熟一点。

好处

  • 钱省得最狠：同样的用量下 GitHub $669 → Ubicloud $104，每月省 $565，一年约 $6,800（按需矩阵本身再省一半，那部分不管选哪家都有）
  • 你只做一次性的三件事（开户、绑卡、授权），之后再也不用管
  • 没有任何机器归我们养 —— 不用做隔离、不用监控、不用半夜重启
  • 不满意就改回一行，两分钟退回原状，零沉没成本

代价 / 风险

  • Ubicloud 是家小公司，出问题的赔付和响应速度不能跟 GitHub 比
  • 还是按分钟计费 —— 用量涨账单就涨（但基数低 6 倍，涨得起）
  • 代码会经过第三方的机器，多了一个要信任的对象
  • 未验证 官方文档没写清楚：并发上限多少、私有仓是否全支持、VM 是不是每次都销毁。切之前我会先跟他们确认这三条，确认不了就不切。
你要做
注册 ubicloud.com、填账单信息、在 GitHub 上授权他们的 App 访问 xrliAnnie/flywheel。约 15 分钟，一次性。
安全
跟今天用 GitHub 托管的模型一样：机器是他们的、一次性的、我们不持有。风险从「我们要自己做隔离」变成「要信任一家供应商」—— 对我们这个规模，后者更划算。
退路
改一行 runs-on 切回 ubuntu-latest。这是所有方案里退路最干净的一个。
✅ 如果你同意「不买机器 + 用 Ubicloud」，接下来你要做的三步
  1. 今天，5 分钟：把 Actions 预算上限调高
    GitHub → Settings → Billing and licensing → Spending limits → Actions，调到 $400/月。 这是为了在按需矩阵落地前不再出现「全部 PR 的 CI 一起停」。矩阵上线后这个额度会用不完。

    我们会先跟 Ubicloud 确认并发上限 / 私有仓支持 / VM 是否一次性这三条，然后改 runs-on、 跑一周、把「实际账单省了多少、CI 变快还是变慢」做成一份回执给你。不行就改回去，一行的事。
    我们做 —— 不需要你参与
