FLY-1884 · cmux 显示层完整性 — 设计方案

design 节点交付 · 2026-08-19 · Codex design review 9 轮 APPROVED · 文档:engineering/doc/FLY-1884-cmux-display-visibility/(exploration / research / plan 三件)

一句话总结

把 cmux 侧栏从「只照活窗的镜子」升级成「节点真相面板」:先拆掉让 tab 成批卡死/空白的两个结构病,再让每一个活跃节点——包括没有窗口的——都在侧栏可见,完工的节点留下终态摘要;任何「系统知道坏了」的状态必须告警,不许静默。

对应你 08-19 的硬要求:「我需要那些活跃的节点,都可以在 CMux 上看到才可以。」

查明的两个根子病(都有现网实证)

实证这次不是猜的:两个病都在 watcher 日志、账本文件和 cmux 现场抓到了活证据。

病 A · 账本死循环 —— 为什么 tab 成批卡死/看不见

同步器给每个 tab 记账(账本:一个记录「哪个 tab 属于哪个节点」的凭据文件)。建 tab 分三步:新建 → 记「prepared」凭据 → 改名成节点名后记「committed」。问题在:cmux 新版会给新 tab 自动起名「Terminal N」,而改名守卫只认识「空名」——看到「Terminal N」就拒绝改名。于是凭据永远停在 prepared,还占着这个节点的名额,连重建都被挡住。你手工修的 workspace:49/55/56/59/60 和现在还卡着 Mufasa tab 的 workspace:52,全是这一个病。那 7 条 QA 镜像「都在但看不到」也是它。

日志证据(08-18 21:40,十连):prepared ledger title drift … observed=Terminal 17…26; preserving + Rename-lag receipt already owns logical slot; create deferred。账本现场:prepared|…|workspace:52|growth-mufasa-lead(ref 已不存在,至今每 90 秒刷一次「preserving」,Mufasa 至今没有 tab)。

病 B · 一次性接线 —— 为什么打开是全空

每个 tab 里跑的是一条一次性的「接线」命令(tmux attach:把画面接到后台终端会话上)。镜像会话(专门给 cmux 看的那份终端视图)一旦被重建,这条命令就退出了,tab 的画面随之死掉——全空。自愈机器只会「往活着的命令行里打字」,对死画面无能为力;更糟的是自愈还要求 committed 凭据,被病 A 饿死。两个病是串联的。

顺带查的「镜像为何会中途重建」:日志证实 08-18 19:51-19:54 cmux app 自己重启过一次,叠加当晚全舰重启潮;21:42 那一次的精确触发行已滚出日志。设计选择让这个问题不再重要——见下一节。

方案:三层修法(P0 先治病,P1 补显示)

P0-A账本三刀:①守卫学会认「Terminal N」= 还没改名,直接补改名(只在有凭据钉死的场景放行,绝不会误收你自己开的终端);②凭据指向的 tab 确认不存在,连续 3 轮后自动注销、让出名额;③凭据卡在「标题漂移」超 5 轮,自动让出名额 + 告警,tab 留给人工。上线后 workspace:52 这类卡死会在几分钟内自愈,不再需要手工修账本。

P0-B重连 helper:tab 里那条一次性接线命令,换成一个「断线自动重试」的小循环脚本(Lead 侧同款方案 FLY-1663 已在生产跑了很久)。镜像会话重建后 ≤5 秒自动接回;断开期间 tab 显示明确的文字状态,绝不静默空白。「镜像为什么重建」从此不承重——重建变成无感事件。

P1节点显示层:同步器本来就每分钟从 Bridge(调度中枢)拉一份「活跃节点名册」。现在把名册渲染成 tab:没有窗口的活跃节点显示状态 tab(「等待重生 / 停驻中 / remote 形态」),完工节点留终态摘要 tab(结果 + PR + 时间,保留 24 小时或你手动关)。

一个节点在侧栏的一生(数据/结构模型)

每个节点用「issue 号 + 角色」做稳定身份(比如 FLY-1884-design),跨换体/换模型不变。同步器为它维护一份状态文件,三种 tab 形态按下图流转:

支撑它的几份小账(都是纯文本文件,坏了按「宁可保守」处理,不引入数据库):视图账本(现有,镜像 tab 归属凭据)、节点账本(新,节点 tab 归属凭据,与镜像账本完全隔离——互不误伤)、节点注册表(新,每个节点的身份、tab 形态与最后所见)、状态文件(新,每节点一份,状态 tab 显示的内容)、清理分类快照(新,关任何 tab 前必须出示的「它确实不属于任何活跃节点」的完备证据——没有证据一律不关)。Bridge 只加一个只读查询(「最近完工的节点」),现有接口一个字节不动。

诚实边界 —— 这个设计不做什么

  • 只有 Bridge 名册里的节点才可见。如果某个 remote-control 体根本不被 Bridge 追踪,侧栏给不出它的表示——那是数据源边界,需要单独立项接入,不是显示层能凭空造的。
  • 不改 cmux app 本体(第三方软件):app 内原生的「置灰/角标」做不了,断开可见性由 tab 内文字状态承担。
  • cmux 侧「Terminal N」的行为细节要在实施前用真机取证确证(这是实施的硬前置:取证通过才动手;若 cmux 提供的字段不足以安全区分「我们的 tab」和「你自己开的终端」,实施会先停下上报换方案,绝不冒险改名你的 tab)。
  • 21:42 那次镜像重建的精确触发者没有抓到(日志已滚)。设计让重建变得无害,而不是声称查清了它。
  • QA 隔离房(独立 socket)的可见性不在本单——隔离本来就是它的合同。
  • watcher 侧 hooks 每 ~90 秒重注册(was 1/2)的现象记为 follow-up 线索,本单不展开。
