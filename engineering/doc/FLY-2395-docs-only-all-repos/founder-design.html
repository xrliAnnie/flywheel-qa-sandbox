1 · 一句话

今天 Bridge 判一单是不是「纯文档」时只看主仓那一个 PR;可这类单常见的长相是主仓放文档锚点、代码进子仓(raya 等)。 改后:runner 完工时把子仓 PR 一并声明出来,Bridge 对每一个 PR 都问一遍 GitHub,全部纯文档才算纯文档; 任何一个拿不到、或子仓有 Codex 评审过的 commit 却不在任何一个声明 PR 里,就按「有代码」处理(fail-closed,即拿不准就往严的一边判)。

只读副本上回溯:被判纯文档的 35 单里 8 单其实在子仓有过真代码 PR,改后这 8 单全部翻成非纯文档,其余 27 单照旧纯文档。

为什么会这样:runner 完工命令 complete --pr N 一次只能报一个 PR,而落地(land,即把 PR 合进主分支)只认主仓,所以 runner 自然报主仓那个文档 PR。子仓代码 PR 的唯一痕迹是 Codex 评审记录(codex_review_record,记录每次 AI 代码评审的表),它只有 commit 号,没有 PR 号。

先澄清一句 spec 里已撤回的话:这 8 单没有因此绕过 QA 证据门——它们的快照全挂在 QA 角色的会话上,在更早的角色门就退出了。B1 是给未来自动合并道补的前置,不是修一条现行漏洞。

4 · Lead 点名的两问,答案与一个没被 spec 看到的耦合

① 为什么库里早就建好的「多 PR 声明表」从来没人用

因为从没接写入方。它是 FLY-1434 设计的「Lead 派单时登记这单要交几个 PR」的接口,全仓零调用方(命令行工具没有子命令、脚本与插件零引用)。不是开关关着,不是废弃——它的读侧全活,只是「没登记 = 单 PR 语义」让它一直沉默。

② 声明要绕开「只记主仓」的绑定层——对,但不能落到那张表

那两张表(workflow_pr_manifest / workflow_declared_pr)是收口授权台账:一旦有行,finalization(单子收尾)会等所有声明 PR 都合并才收口;land 门只接受「恰好一个 PR」,多 PR 直接拒绝落地。⇒ 把子仓 PR 写进去 = 改 land 规矩,撞「影子跑期间一条规矩都不改」和「不动合并授权契约」两条红线。

所以取 B′:声明形状照 Lead 拍的方案 B,落点换成一张新的分类证据表(ship_relevant_declared_pr),列形状与授权表对齐——将来「放手那天」若要让收口也认子仓 PR,一对一能铸过去。Lead(Tadashi)2026-09-06 已回复「批 B′,不要字面 B」,附四条要求(事实段、retention 登记、负向护栏单独阳性测试、复现数字写进验收),计划里逐条对应。

5 · 数据模型

图 2 · 两张新表:声明表只追加不改,一行 = 「哪次完工事件声明了哪个子仓 PR」;快照表一行 = 「gate 会话对某个仓某个 PR 的当前分类」,键里带仓名与 PR 号,同一个 commit 出现在两个仓也不撞。旧快照表冻结不读不写。两张新表都归 retention(数据保留策略)的「受保护」组,不会被 14 天清理吃掉影子跑窗口。

6 · 判定阶梯(严的一边优先)

图 3 · 前三道全是「拿不准 ⇒ unknown」。G1 = 子仓每一条 Codex 评审过的 commit,都必须落在主 PR 或某个声明 PR 里(精确到 commit,不是只看仓名;多轮评审的旧 commit 靠 PR 的 commit 列表覆盖)。零新 I/O,历史 8 单全靠它翻。

反一刀切:无声明、无证据、主仓纯文档 ⇒ 必须仍判纯文档,测试钉死;否则「8 单全翻」就没有判别力。

9 · 诚实边界:做什么,不做什么

  • 做:判定看全部 PR;拿不到就 unknown;历史快照自动失效;新表登记 retention;回溯脚本给出阳性 / 反向两组数。
  • 不做:不改合并授权契约、不改 land 门、不让子仓 PR 成为收口条件、不改写历史行、不给 runner 新增硬失败、不承诺 GitHub 上全部 PR 的全集(没有独立于 runner 自声明的清单来源)。
  • 看不见的:子仓代码既没被 Codex 评审、也没被声明 ⇒ 本单看不见;B4 影子跑台账要把「事后发现的子仓 PR」记成分母卫生指标。
  • 回溯的诚实说法:库里没有那 8 单子仓 PR 的号码,回溯不是重新分类子仓 PR,而是靠「有子仓评审却没声明 ⇒ unknown」翻的;这是把机制套回历史算出的结果,不是影子跑两周的表。
  • 没核的:25 条挂在 main 角色会话上的纯文档快照,当时有没有真走到免 QA 那一支——没核,本设计不引用。
  • 待 Lead 确认的一项:子仓 PR 的「纯文档」复核租约设 30 秒(主 PR 维持 FLY-1251 裁定的 10 秒)。子仓 PR 不由 Bridge 落地,30 秒只影响 hold 早晚,不影响任何合并动作。
