① 一句话

在 Bridge 里另开一扇只读的小窗（只在本机、端口 9877），它只给「看」不给「改」，而且每次都亲自检查你是用名单里的 Google 邮箱登录进来的；外网的隧道只接这扇小窗，永远不接本机完整控制台。

Bridge：Flywheel 在你 Mac 上常驻的总调度程序，控制台就是它提供的网页。
隧道：你 Mac 主动连到 Cloudflare 的一条加密通道，外面的请求顺着它进来，你的 Mac 不用对外开门。
端口：同一台电脑上不同服务的「门牌号」；本机控制台是 9876，新的只读小窗是 9877。

② 你在手机上打开时，发生了什么

Cloudflare Access（登录门）：挡在网址前面的登录页，只放名单里的邮箱。
JWT（签名通行证）：登录门发给每个请求的一张带数字签名的小纸条，写着「这是谁」，别人伪造不了。
{{D1}}

通行证一共被验三次：登录门、你 Mac 上的隧道程序、只读小窗本身。即使前两道哪天配错了，最后一道也会把没通行证的请求挡回去。

另外两道保险：① 隧道的配置不让人手写，每次启动都由程序按固定格式重新生成——设计评审时发现隧道程序有一个隐藏选项，能在网址看着没错的情况下把请求转去别处，固定格式让这类选项根本写不进去；② 本机完整控制台（9876）一旦收到任何「从 Cloudflare 过来」的请求，直接拒绝。

③ 只读小窗怎么判断放不放行

{{D2}}

「默认拒绝」：小窗里只存在两条路——打开页面、读一份数据快照。批准 / 终止 runner、改 Lead 级别、开关功能……这些路在小窗里根本不存在，所以手机上即使有人想改也无处可改。

GET：网页「读取」的请求方式；改东西一般用 POST / PUT / DELETE，小窗一律拒绝。
DNS rebinding：一种骗浏览器把恶意网页当成本机网页的手法；检查「网址名必须是 console.你的域名」就是专门防它的。

④ 数据从哪来、哪些不给手机看

{{D3}}

手机看到的和本机是同一个页面、同一份数据（只是切到只读模式），所以以后控制台加了新板块，手机上也会自动出现。唯一拿掉的是两条本机文件路径（只在本机「复制命令」时有用）。

快照：控制台某一刻的全部状态打包成一份数据，页面拿它来画卡片。
FleetConsole / ConsoleSnapshot：程序里「控制台数据」和「快照」的名字，图里照原名写，方便工程对照。
.env：你 Mac 上存放 Flywheel 设置的那个文件；远程开关默认是关的。

⑤ 取舍：为什么这样做、放弃了哪些做法

做法结论原因
隧道直接接本机控制台 9876放弃审计发现 9876 上「批准 / 终止 runner」那组接口没有任何登录检查（今天靠「只在本机」当锁）。接上隧道 = 登录门成了唯一的门，而且远程能改。
在 9876 里加「远程模式」开关放弃以后谁新加一个接口，默认就对远程开放；「远程不能改」守不住。
定时把快照发到托管网页放弃不是活的控制台，托管页也没有登录门（拿到链接就能看）。
让人手写隧道配置、程序检查几个关键字段放弃评审实测：隧道程序有个「跳板模式」选项，写上后网址字段看着正常，实际转发目标却由访问者决定，能绕到本机完整控制台。改为每次由程序从零生成固定格式。
单独做一个手机版页面放弃会和本机页面越长越不一样；复用同一个页面的只读模式，内容天然一致。
另开只读小窗 9877 + 小窗自己验通行证采用和本机控制台物理隔离、默认拒绝、不加任何新依赖；远程坏了本机照常。

⑦ 怎么关掉远程访问（一句话）

运行 scripts/remote-console.sh off：隧道马上停掉、不再开机自启，本机控制台完全不受影响。

默认状态就是关的：不打开 FLYWHEEL_REMOTE_CONSOLE 开关时，Bridge 和今天一模一样。

⑧ 诚实边界：这次做什么、不做什么

做：

  • 手机登录后看到项目、Lead、Runner 默认设置、定时任务模型、功能开关——和本机一致；
  • 没登录 / 名单外邮箱打不开；远程任何「改」都做不了；Bridge 仍只听本机；远程断了本机照常；
  • 一个开关、一条关闭命令、一份你照着点的 Cloudflare 设置清单。

不做：

  • 手机上改东西（要另开一张单，把「改」的接口改成认登录门的身份再加确认）；
  • runner 运行状态的实时推送、日志、Discord 内容——只放控制台快照；
  • 自动买域名 / 自动建登录门（要你本人在 Cloudflare 上点一次，清单会写好）；
  • 多台电脑（属于多机方案 FLY-1005）。

要说清楚的风险：上线需要你先完成 Cloudflare 那边的设置，再重启一次 Bridge；在那之前代码合进去也不会有任何变化。
