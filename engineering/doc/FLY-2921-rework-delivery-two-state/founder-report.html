名词：run = 一张单在引擎里的一次完整执行链；执行体 = 真正干活的 Claude/Codex 会话；返工 = QA 判不过、把活打回实现体重做；返工投递 = 把返工内容真正交到执行体手里的过程；held = 把整条 run 冻住等人处理；替身 = 原执行体死了，同一节点另起一个新体接手。

核心流程：协调器每一轮怎么决定

协调器（Bridge 里每秒扫一遍返工投递、把它推进一步的那段代码）现在每一步只有一个出口：要么等（不计失败，但等替身启动有超时、判不出死活超过 30 分钟会告警）、要么换替身、要么记一次失败；失败满 5 次或换体满 3 次，交还 Lead。没有任何一条路会把 run 冻住，也没有一条路会悄悄卡住。

写入权（TURN）：共享工作树同一时刻只许一个体写，先把它授给目标体再叫醒它。签收：目标体跑 flywheel-comm turn 拿到「轮到你」，证明它确实收到了这次返工。

状态机：从 8 个状态收成 5 个

字面值显示含义
pending待投引擎要把返工交给当前指定体（含退避等待、替身启动中）
turn_granted已发待签收已授写入权；新增的 wake_sent_at 记录推送时间
wake_delivered送达体已签收，或替身带着返工内容启动
completed已交卷关账返工被节点交卷消费
returned_to_lead交还 Lead自动投递放弃；run 继续运行；Lead 一键重投

删掉：awaiting_receipt（改成一列时间戳）、replacement_pending（换体当场做完）、needs_lead 和 held（合并为唯一的「交还 Lead」，且不冻 run）。

数据与结构

没有新表、没有新 API、没有新的 run 状态。只新增两列事实：wake_sent_at（推送时间）和 liveness_unknown_since（活性判不出的起点，超过 30 分钟就告警，保证卡住时 Lead 一定知道），并新增一个「不冻 run 的投递级暂停」形状 rework_returned_to_lead，Lead 用现有的 flywheel-comm hold resume 就能重投。

路由版本：这次返工投给哪个执行体，每换一次对象（换体或重投）就追加一版。Lead 重投时把原来那条唤醒消息的推送次数清零再发（每次重投只清一次），不新造身份，所以不会读到上一轮的旧失败，也不牵动其它账。

迁移、回滚与兄弟单

  • 现存行：生产库只读查询，活着的 run 上停在将被删状态的只有 8 行，全在已冻结的 run 上（FLY-2152 ×3、FLY-2031 ×2、FLY-2461、FLY-2390、FLY-2803）。迁移只改字面值，不自动解冻任何 run，并给每一行补一扇可用的门。已终态 run 上约 170 行只改字面值。

诚实边界：做什么、不做什么

做：返工投递状态机收成 5 态；失败只有「交还 Lead」一个终点且不冻 run；投给死体当场换替身（预算 3 次）；返工交卷必须带新提交；取消门不再静默卡住；现存行迁移和回滚脚本。

不做：

  • 不改 ship 载体的投递状态，也不改 mailbox 家族（#1084 已修）。phase_wake 家族「投不到」冻 run 的问题不在本单。
  • 不给「已发、体活着、迟迟不签收」加截止时间；Codex 体不消费唤醒的问题归 K04。
  • 不自己判死：若 2919 迟于本单实现，按活性换体这条路先关着，只在「替身确定没启动」时换体，其余等待并告警，最终交还 Lead。
  • 不自动解冻现存 held run，不自动关闭 6 张 Linear 单（合入并部署后由 Lead 逐张复核）。
  • 本页是设计：尚未实现、未跑测试、未部署。盘点的 ×46 是历史次数，不是本次测试结果。
