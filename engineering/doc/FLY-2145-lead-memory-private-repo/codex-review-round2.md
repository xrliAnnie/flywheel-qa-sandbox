# Design Review — plan.md (Round 2)

Date: 2026-09-03
Author: Codex
Status: CHANGES REQUESTED

## Summary

Round 2 resolves most of the original guard, bootstrap, CI-registration, scanner-version, privacy-test, and no-ACK findings. The architecture remains feasible, and the new actor-independent range check, root/merge/trailer rules, exact-root bootstrap fixture, real/manual scanner split, workflow contract test, and `--no-verification` decision are all strong improvements.

The plan is still not ready to execute because the replacement for stopping writers does not actually bind the bytes read by gitleaks/trufflehog to the bytes later staged, and the literal C5/C6 commands cannot complete the intended admin import and snapshot acceptance. These are fixable without stopping Leads: make an immutable Git index/tree snapshot the scanner input, bind the import evidence to its exact commit SHA, and run destructive guard acceptance in a disposable clone.

## What's Good (Keep)

- Keep the exact-root bootstrap invariant, enclosing-parent-repository fixture, explicit `git init -b main`, exact `origin`, preflight-before-local-mutation rule, and temp-sibling clone approach.
- Keep `SCAN-LEDGER.md` as a runtime artifact and the byte-preservation test; remove the remaining contradictory template inventory entry rather than weakening this decision.
- Keep `diff-tree --root --no-renames`, merge and empty-commit rejection, exactly one owner trailer, unknown-actor rejection, actor-independent `check-range`, and hook-driven lead/sync/admin tests.
- Keep unconditional deletion/non-fast-forward rejection and the complete removal of the ACK variable.
- Keep the CI/manual scanner split, `ci-structure.test.sh` update, pinned/checksummed gitleaks download, and the dedicated `guard.yml` contract test.
- Keep exact scanner versions, per-sample positive controls, `--fail-on-scan-errors`, `--no-verification`, private atomic reports, a disposition ledger, and a final full scan.
- Keep the corrected authenticated-private plus anonymous-404 evidence and the honest distinction between local prevention and CI detection.

## Issues & Recommendations

1. **BLOCKER — The live-tree manifest does not prove that the committed bytes are the bytes both scanners read.** `scan.sh`, gitleaks, trufflehog, and the manifest generator independently traverse a directory that Leads continue to mutate. A file can change after trufflehog reads it but before `manifest.tsv` hashes it; staging then matches the manifest even though the staged bytes were never seen by trufflehog. The later staged gitleaks hook does not close the trufflehog-only gap. The manifest scope is also undefined: a full target manifest includes `.git` and generated/top-level artifacts, while `SCAN-LEDGER.md` is finalized after the terminal scan and therefore cannot both match that scan's manifest and contain its completed result. **Suggested fix:** keep the no-stop decision, but reverse the authority: stage the twelve Lead folders into an index, capture its tree/subtree OID, materialize that exact index/tree into a private temporary snapshot, run both scanners and generate `manifest.tsv` from that immutable snapshot, and repeat from a newly staged tree after any remediation. Immediately before commit, require the staged Lead-folder tree OID to equal the terminal scanned tree OID; writes that arrive later remain unstaged for A2. Define a two-way path-set comparison, explicitly prune `.git`, and handle generated repository files/`SCAN-LEDGER.md` through a small explicit allowlist plus the staged gitleaks check. Add a mutation test that changes a source file between scanner traversal and manifest generation and proves the unscanned version cannot be committed.

2. **BLOCKER — The literal actor and snapshot acceptance commands do not execute the intended sequence.** `FLYWHEEL_MEMORY_ACTOR=admin git add -A` scopes the variable only to `git add`, which invokes no commit/push hooks; the following plain `git commit` enters lead mode, and the following plain initial `git push` also enters lead mode. The admin import will therefore be rejected. Separately, C5 deliberately pushes a later smoke commit before C6's default clone, so that clone checks out the smoke SHA and cannot equal the terminal-scan/first-import manifest. Finally, `git ls-files -z` emits paths only, not the claimed path-plus-blob-OID records. **Suggested fix:** run add/commit/push in an explicitly admin-scoped block or prefix the actor on every hook-bearing command; do the same for Lead identity on separate commit/push commands. Record `IMPORT_SHA` immediately after the first commit. Compare `git ls-tree -rz --full-tree "$IMPORT_SHA"` (or an equivalently precise command) on source and clone at that exact SHA before the smoke commit, or explicitly check out `IMPORT_SHA` in the clone. Then perform the smoke commit, record `SMOKE_SHA`, verify remote main and CI at that SHA, and keep the two evidence rows distinct.

3. **HIGH — The terminal-zero scan loop has no disposition mechanism for retained trufflehog findings.** The documented false-positive path writes a fingerprint only to `.gitleaksignore`; that does not suppress trufflehog. A trufflehog false positive or a reviewed non-secret value that remains in place will recur forever, so “terminal scan must contain 0 findings” cannot be reached. In addition, because the gitleaks config is resolved from the flywheel source, the scan must explicitly point to the memory repository's runtime `.gitleaksignore`; relying on the caller's current directory can silently ignore the approved fingerprints. **Suggested fix:** define terminal success as zero *open/new* findings and provide a value-free, reviewable per-tool fingerprint disposition for trufflehog, or require retained trufflehog matches to be transformed so the raw terminal run is genuinely zero. Pass the exact gitleaks ignore path explicitly. Test one retained false positive from each tool, rerun the real parsing path, and prove it is recognized as disposed while a new neighboring finding still fails closed.

4. **HIGH — The wrong-folder acceptance mutates and contaminates the live memory repository.** C6 edits a real `sub-lead` file, then creates a deliberately invalid local commit with `--no-verify` on the live main branch. The rejected push leaves that invalid commit, staged/working-tree state, and another Lead's content mutation behind; no cleanup or concurrency-safe restoration is defined. This is unnecessary blast radius on the asset being protected. **Suggested fix:** perform all three negative cases in a disposable fresh clone with the shipped hooks configured and an isolated `FLYWHEEL_STATE_DIR`. Separately prove the live repository's `core.hooksPath` and installed hook/library hashes equal the tested copies. If a live smoke is mandatory, use a new sentinel in the acting Lead's own folder and specify exact cleanup, never another Lead's existing file or an intentionally invalid live-main commit.

5. **HIGH — The plan and its source context still contain mutually exclusive implementation instructions.** The file inventory still lists `repo-template/SCAN-LEDGER.md`, while C2 says the template directory must not contain it. Research still describes rename-before-clone and live-tree `diff -r` acceptance, aggregate positive-control thresholds, and a pending founder decision, all superseded by Round 2. Research's target layout includes a top-level `bootstrap.sh`, but C2's sync list does not copy it. Plan §2 says a trufflehog version mismatch makes bootstrap and pre-commit refuse, while C3 and the ongoing-hook design require only gitleaks there. C3 also says an initial child of the enclosing `~/.claude` repository is uninitialized and allowed, then says a target “belonging to another repo” is refused. **Suggested fix:** reconcile the file tree, C2 copy list, version applicability, and exact-root wording in one pass; either sync `bootstrap.sh` or remove it from the target layout/README contract. Update the operative research sections or mark their old commands explicitly superseded so an implementer cannot legitimately follow the unsafe Round 1 path. State that an enclosing parent repo with no target-owned `.git` is the expected initial case; a target-owned foreign `.git`/gitfile or symlink is the refusal case.

6. **MEDIUM — Two fail-closed behavior contracts need tightening.** Setting `SKIP_SCAN=1` is an environment change, not an unknown command-line argument; unless production code explicitly recognizes that forbidden identifier, it cannot emit “unknown argument.” Recognizing it also conflicts with a static rule that the identifier must not exist. The meaningful proof is that arbitrary skip-like environment variables do not alter behavior and both scanner spies are still invoked. Also, C1 promises every successful sync writes an audit row but only makes an unwritable admin audit fail closed; sync is also an R3-bypassing actor and needs the same durable-audit rule if the promise is literal. **Suggested fix:** keep “unknown argument” for unsupported argv only; set skip-like environment variables and assert identical scanner invocations/results. Require both admin and sync exception paths to refuse when their success audit cannot be written. Add a post-clone swap-failure injection that proves an already-renamed original directory is restored if the final temp-to-target move fails.

## Verdict
