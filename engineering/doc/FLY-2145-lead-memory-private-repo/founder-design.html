① 一句话

把 12 个 Lead 的记忆(今天 12 个文件夹、1137 个文件、29MB,只存在这台机器上,零副本)原地变成一个私有 GitHub 仓, 所有 Lead 都能读全部,每个 Lead 只能写自己那个文件夹;上仓之前先用真正的密钥扫描工具扫一遍并逐条记台账。

「原地」的意思是:文件一个都不搬、不改名,只在那个文件夹里加一个 .git(git 用来记录版本历史的隐藏目录)。 Claude Code 写记忆的路径完全不变,回滚就是把 .git 删掉。

定时自动推送、判断「到没到远端」是 A2 那张单的事;本单只把 A2 要遵守的提交合同写好。

② 核心流程:从盘上到 GitHub

  • 先扫描,再提交。顺序不能反:先提交再脱敏,密钥会留在版本历史里,洗历史要强推,本单不做。Lead 不停机:扫描的不是活文件夹,而是 git 先「拍」下来的一份不可变快照(git 里叫 tree,一棵内容树有唯一编号);提交前用同一段算法把暂存的 12 个夹重建成一棵「合成根树」,编号必须和扫描时那棵完全相同,不同(有 Lead 在扫描后又写了)就重扫,直到扫过的就是提交的。之后到达的新写留给 A2。
  • 阳性对照(先往一个临时目录种 8 条假密钥,看工具能不能全抓到)是扫描的第一步。我第一次种的假密钥在工具白名单里,两把工具都报 0,那个 0 没有任何意义。换合规样本后 gitleaks 抓到 8 条、trufflehog 抓到 4 类,真实目录再扫仍是 0,这个 0 才算数。
  • 台账(SCAN-LEDGER.md)每条命中一行:文件、规则、行号、处置、处置人、日期,不写命中的值。0 条时也要记工具版本、扫描字节数、对照结果,以及每个夹抽 3 个「出现过 token/key/secret 字样」的文件人工看过的清单。

③ 结构:一个仓、十二个夹、谁能动什么

东西在哪谁能改
12 个 Lead 夹仓根下,名字 = Lead 名(如 flywheel-eng-lead/)只有同名 Lead(身份来自 Lead 进程自带的 FLYWHEEL_LEAD_ID 环境变量)
护栏脚本、CI 审计、扫描规则、台账、README仓根顶层只有 admin 模式(显式声明,留痕)
GitHub 上的仓xrliAnnie/lead-memory,私有GitHub 只认得一个账号(你的),分不出 12 个 Lead —— 所以「只写自家」靠本地护栏 + 推送后 CI 审计,不靠 GitHub
另一台机器bootstrap.sh --clone 拉到同一路径 ~/.claude/agent-memory那台机器要先用同一个 GitHub 账号登录

CI(Continuous Integration,推送后在 GitHub 上自动跑的检查脚本)跑的是和本地护栏同一段脚本,只有一份规则源。

④ 写权护栏:一次提交怎么被放行或拒绝

三条规则,本地钩子(git 在提交/推送前自动运行的小脚本)和 CI 各跑一遍:

  1. 单夹:一次提交改的文件必须都在同一个夹里;顶层文件只有 admin 能动。
  2. 归属:每个提交自动带一行 Memory-Owner: <Lead 名>(提交信息末尾的归属标记),必须等于那个夹。
  3. 自家:Lead 模式下那个夹必须等于 FLYWHEEL_LEAD_ID;没设身份就拒绝,不猜。

三种身份声明:Lead(默认)、sync(给 A2 的定时器用:一夹一提交,归属直接取那个夹,不能碰顶层)、admin(仓维护与首搬:可以多夹,提交记 admin,放行也必须写进审计日志,写不进就拒;CI 会把 admin 提交单独列出来给你看)。改写远端历史(非快进)和删分支一律拒,没有任何放行变量。 没有任何取值能关掉扫描或审计——这是「我是谁」,不是开关(你的直令:不加任何开关)。

⑥ 验收:PRD 里的五格怎么证

PRD 原文怎么证本单能做到的程度
另一台机器拉下来见 12 夹同内容本机 git clone 到临时目录并切到首搬那次提交,两边用 git 列出「路径 + 内容编号」逐字节比对,零差异;用同一段算法把 12 个夹重建成一棵「合成根树」,编号 = 扫描时那棵;12 个夹齐等价验证:比的是提交快照,不是比较那一刻的活文件夹(Lead 不停机,首搬后可能又写了新东西,差异会如实列出);真的第二台机器由你按 README 步骤拉,本单写明没做真机
任一 Lead 读得到别家在工作树和 clone 里各读一次别的 Lead 的 MEMORY.md能读;仓里没有任何读限制
写别家写不进三条各自留证,全部在一个用完即删的临时 clone 里做,不碰活的记忆仓:以 eng-lead 身份改 sub-lead 的文件 → 提交被拒(退出码非 0,首行 lead-memory-guard: refusing commit,审计日志多一行);再用绕过钩子造一个违规提交 → 推送前被拒(远端没变);对同一提交跑 CI 用的那段检查脚本 → 判红。另证活仓装的钩子和临时 clone 里测的那份哈希一致前两条是本地阻止;第三条是 CI 的检测——推上去之后才标红,拦不住。都是事故护栏,不是安全边界(见 ⑦)
无权限者打不开两条:带你的凭据查 GitHub API,仓的 private 字段 = true;不带任何凭据用 curl 访问仓地址 → 404(同账号现有私有仓实测就是 404)成立
扫描结果逐条有处理记录仓根 SCAN-LEDGER.md,每条命中一行有处置人和日期;0 条时有对照与抽样复核清单成立;台账不写值,原始报告只留本机

⑦ 诚实边界:这个设计做到与做不到的

  • 护栏拦得住事故,拦不住故意。git commit --no-verify(跳过本地钩子)和 admin 声明任何进程都能用;绕过会留痕、CI 会标红,但那时提交已经在远端历史里。GitHub 只认一个账号,服务端做不到按 Lead 拒写。这和 issue 里写的「git 本身不做目录级写权」一致。
  • runner 会被当成它的 Lead。实测 runner 继承了 Lead 的 FLYWHEEL_LEAD_ID。runner 的记忆不在这个仓里,正常不会碰到;真碰到时护栏分不出来。
  • 「另一台机器」本单用本机 fresh clone 做等价验证,没有真机。
  • 扫描只能证明「两把工具当前规则下 0 条 + 抽样人工看过」,不能证明里面没有任何敏感内容 —— 所以仓是私有的,这才是第一道防线。
  • 首搬之后、A2 上线之前,新写的记忆仍只在本机。本单不解决「每天都到远端」。
  • Codex Lead(mufasa / raya / codex-infra-bot)的记忆不在这个仓。它们在 ~/.codex-*/memories,PRD 里 C1 你没勾。
  • Lead 转达的硬约束已并入:扫描与 pre-commit 写死必跑,没有任何跳过参数;测试从命令行接口和行为上验证(传跳过类参数就报「未知参数」退出,admin 提交也照样跑扫描)。
  • Codex 设计评审:四轮,9 → 6 → 1 → 0 条,第四轮 APPROVED;残留 1 条 LOW(风险表里一句旧措辞,规范条文已正确,为不让已批准的版本漂移没再改)。四轮原文在同文件夹 codex-review-round1.md … round4.md;本页按批准的 plan(rev 6)写。
