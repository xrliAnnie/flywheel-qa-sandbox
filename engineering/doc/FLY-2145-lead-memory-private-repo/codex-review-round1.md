# Design Review — plan.md (Round 1)

Date: 2026-09-03
Author: Codex
Status: CHANGES REQUESTED

## Summary

The core design is feasible and appropriately scoped to A1: an in-place private repository, one folder per Lead, local accident guards, commit ownership trailers, CI audit, and a pre-import scan can all be built with the current shell/Git architecture. The plan also correctly preserves the explicit boundary that this is not server-side per-Lead authorization and that scheduled delivery belongs to A2.

It is not ready to implement yet. The current sequence has three blocking problems: bootstrap can mistake the enclosing `~/.claude` repository for the memory repository and the shown `gh repo create` command does not configure `origin`; the finalized scan ledger can be overwritten by `sync-template.sh`; and the fresh-clone equality check is incompatible with allowing live writers throughout the import. There are also concrete range-check, scanner, and CI-registration gaps that would permit false-green evidence or deterministically break the existing CI structure guard.

## What's Good (Keep)

- Keep the A1/A2 boundary. The README contract for A2 is useful, while timer and remote-arrival monitoring correctly remain out of this issue.
- Keep the in-place repository. It preserves Claude Code's fixed `memory: user` path and avoids a symlink cutover on the live memory tree.
- Keep the shared rule implementation for hooks and CI, the one-folder-per-commit contract, `Memory-Owner` trailers, old-path handling for deletes/renames, and the `--no-verify` negative control.
- Keep the explicit fail-closed identity behavior and the honest statement that hooks/CI are an accident guard and audit surface, not a security boundary.
- Keep scan-before-first-commit, two real scanners, positive controls, a value-free ledger, human disposition fields, and the decision to import the media files without LFS.
- Keep the fresh-clone, cross-folder read, wrong-folder write, privacy, and scan-ledger acceptance categories; their commands need correction, but the matrix covers the right outcomes.

## Issues & Recommendations

1. **BLOCKER — Bootstrap does not safely distinguish the nested memory repository or fully wire the initial repository.** `~/.claude/agent-memory` starts inside the existing `~/.claude` Git repository. From a non-repository child, `git -C <target> rev-parse --show-toplevel` resolves to the parent repository; a conventional “already a repo” check could therefore configure `core.hooksPath` on `~/.claude`, the exact blast radius this design must avoid. Separately, `gh repo create xrliAnnie/lead-memory --private ...` creates only the remote; without `--source/--remote`, it does not add local `origin`. The plan also assumes, but does not establish, a `main` branch. **Suggested fix:** make exact-root ownership a bootstrap invariant (`--show-toplevel` must equal the physical target, or the target must own its `.git`); reject symlink/foreign-repository cases; add a C3 fixture with an enclosing parent repository; run all tool/version preflights before mutation; initialize explicitly with `git init -b main`; add `origin` when absent and fail on any mismatched URL; and assert `HEAD`, `origin`, hooks, and no-mutation-on-failure in tests. For `--clone`, clone to a temporary sibling first and make backup/swap failure recovery explicit so a failed clone never strands or overwrites an existing directory.

2. **BLOCKER — The C4/C5 order can destroy the completed scan ledger.** C4 writes and then manually finalizes `<memory-root>/SCAN-LEDGER.md`; C5 subsequently runs `sync-template.sh`, whose stated input includes `repo-template/SCAN-LEDGER.md`. A normal copy will replace the evidence just produced, and future idempotent template syncs could repeat that loss. **Suggested fix:** make the ledger a create-once/runtime artifact that `sync-template.sh` never overwrites, or install the template before scanning and have `scan.sh` populate it afterward. Add a test that puts non-template reviewed content in `SCAN-LEDGER.md`, runs sync twice, and proves the file is byte-identical.

3. **BLOCKER — “No stop needed” conflicts with the stated clone-equality acceptance and leaves a scan/import race.** The plan permits Leads to keep writing while `scan.sh`, `git add`, push, and `diff` run, but C6 compares a fresh clone to the live working tree. Any write after staging or during the comparison makes the two sides legitimately different; a new secret written after the two-tool scan may also receive only the later gitleaks staged check. This makes a required acceptance cell nondeterministic and can produce a snapshot that was never equal to the live tree at one defensible point. **Suggested fix:** define a short, bounded writer-quiescence window for the final two-tool scan, remediation closure, final `git add`, commit, push, and manifest/fresh-clone comparison, then resume Leads and explicitly hand subsequent writes to A2. If stopping writers is rejected, change the claim and evidence to equality with an immutable captured commit snapshot and acknowledge that literal live-tree parity was not verified; do not retain the current `diff` claim.

4. **HIGH — Commit path enumeration needs explicit root-commit and merge semantics.** On the repository's Git version, `git diff-tree --no-commit-id --name-only -r <root>` returns no paths unless `--root` is supplied; the same default command returns no paths for a merge commit. A range check can therefore be vacuously green. Multiple `Memory-Owner` trailers and empty commits are also unspecified. **Suggested fix:** use and test `diff-tree --root --no-renames` for every commit; reject merge commits outright (the A2 contract already requires rebase) or deliberately inspect every parent; define empty-commit behavior; and require exactly one parsed `Memory-Owner` trailer. Add root, merge, duplicate-trailer, and empty-commit negatives to C1, including the initial zero-remote-SHA path.

5. **HIGH — The `sync`, CI, admin-audit, and force-push contracts are incomplete or contradictory.** A sync process is only told to set `FLYWHEEL_MEMORY_ACTOR=sync`, yet `prepare-commit-msg` must emit the folder name as owner and no source for that name is defined. CI must check R1/R2 without a runtime actor, while local pre-push must also enforce R3. The plan says admin declarations leave an audit trace but tests only rejection rows, and it says there are no switches while “non-fast-forward without ACK” implies an unlisted ACK path. **Suggested fix:** define each entry point precisely: lead requires `FLYWHEEL_LEAD_ID`; sync either derives the sole staged folder or requires an explicit validated ID; `check-range` is actor-independent commit attestation; admin emits `admin` and a successful admin exception fails closed if its audit row cannot be written. Reject unknown actor values. Either always reject non-fast-forward pushes, or document the inherited exact-branch ACK variable and carry over the FLY-1718 wrong-branch, durable-audit, and one-command tests. Add real hook-driven sync/admin commits, not only direct library calls.

6. **HIGH — The CI registration plan is incomplete for this repository and disagrees with the scanner-test plan.** `ci-shell-suite-enumeration.test.sh` is only one gate. `scripts/__tests__/ci-structure.test.sh` also pins the exact named step inventory and order for all four script shards; adding a normal FLY-2145 step to `ci.yml` without updating that inventory will fail Quick Gate. The file is absent from the plan's change list. In addition, research says only gitleaks is installed/run in Linux CI while C4 describes a suite that requires real gitleaks and trufflehog positive-control counts. **Suggested fix:** add `scripts/__tests__/ci-structure.test.sh` to the file list and name the target shard/step and budget update. Decide explicitly whether the scan suite uses PATH fakes plus a separate real-gitleaks integration, or CI installs both pinned tools; do not claim real two-tool CI coverage while omitting trufflehog. Add a contract test for the copied `guard.yml`: `push` on `main`, `contents: read`, `fetch-depth: 0`, zero-`before` handling, invocation of the shared guard, pinned/checksummed gitleaks installation, and admin summary output.

7. **HIGH — The official scan needs a closed, fail-loud run protocol, not one pass followed by edits.** C5 says scan, disposition, and finalize, but never requires a second real scan after rotation/redaction/ignore changes. Also, the first scan occurs before `.gitleaks.toml` is copied into the target, so the Discord rule is not guaranteed to run unless `scan.sh` explicitly points to the source template. The documented trufflehog command omits `--fail-on-scan-errors`; positive controls are accepted by aggregate thresholds rather than by exact planted-rule/file mappings; and the “local pin” risk mitigation only checks that gitleaks exists, not that it is 8.30.1. **Suggested fix:** have `scan.sh` resolve its config relative to its own source, validate exact supported tool versions, enable fail-on-scan-errors, assert every planted sample maps to the intended rule/detector, and loop scan → disposition/remediation → full rescan until the final run is clean. Record both initial findings and the final clean run in the ledger. Use a unique run ID below the UTC date, `umask 077`, atomic report/ledger publication, and a stale-ledger check. Unless outbound credential verification was explicitly approved, add `--no-verification` for trufflehog so candidate values are not sent to provider APIs.

8. **MEDIUM — Several acceptance commands measure the wrong thing.** `find -type f | wc -l` includes each clone's `.git` internals, so it does not count imported content. The proposed “no token” `gh api` command will use credentials stored by `gh auth` even when token environment variables are unset, so it is not an anonymous privacy test. “Three layers reject” also needs an explicit local `check-range` invocation; CI detects a bypassed push after remote receipt and cannot truthfully be described as preventing it. **Suggested fix:** count/manifest the twelve Lead directories while pruning `.git` and repository-management files (or use a NUL-safe `git ls-files` manifest); verify authenticated `gh api ... --jq .private` is `true` and separately use credential-free `curl` for the anonymous 404; and record pre-commit, pre-push, and actor-independent range-check results as distinct evidence, keeping CI labeled detection/audit only.

9. **MEDIUM — The no-bypass source test is self-contradictory and too broad.** The plan proposes grepping for no `--no-` parameters, but the required trufflehog command already contains `--no-update` (and may correctly need `--no-verification`). Such a test either fails valid code or will be weakened into a low-value string check. **Suggested fix:** test the public CLI surface and behavior: usage lists only the supported positional/mode arguments; `--skip`, `--no-scan`, and skip-like environment variables have no recognized path; bootstrap always installs hooks; and an admin commit still executes a stubbed gitleaks binary whose invocation is asserted. Keep static checks limited to exact forbidden identifiers rather than a generic `--no-` substring.

## Verdict
