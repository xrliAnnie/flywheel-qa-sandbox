● 评测框架提案
3 任务 × 2 变体 × 2 模型 = 12 runs（本轮不跑）
  • 任务：T1 有界代码变更（FLY-1242 删 dead flag）· T2 设计（FLY-1245 kill-switch）· T3 QA（FLY-1246 PR #584，重放历史 head）。三个起点都不含答案文档，且晚于两模型 knowledge cutoff。
  • 指标：双盲评 rubric（两位各评全部 12 份）+ 客观评估器；轮数/token 仅模型内比较；插手拆成 gate_compliance / discretionary_asks / simulated_human_decisions 三个独立字段，不相加；findings 带 severity + ground-truth 证实。
  • 预注册（跑前冻结，看到数据前定死）：非劣界 B−A > −1.0；触发重复的阈值 |B−A| ≥ 2.0；n=1 结论上限 = 方向性，「强证据」只来自客观不变量。
  • 隔离：per-run 独立 clone（不用 linked worktree，会污染主仓 .git/config）· claude 腿零生产 hook 执行（带哨兵）· codex 腿不用 codex-with-fallback（它会改写宿主 auth.json）· 对抗性冒烟实证隔离，而不是声明隔离。
⚠️ 一个必须你/Lead 拍板的范围问题（执行单开跑前）
提案的 pilot 只变换 Blueprint 注入块，角色文件 / lead-rules / skills 两臂字节一致。 但本次审计的主结论恰恰是「角色文件约 1/3 可动」 —— 也就是说按当前范围跑， 验证的是框架本身，验不到主结论（层 A 可动 <600 B，效应大概率淹没在噪声里）。
(a) 保范围：12 runs 只验框架（也会顺带证明「Blueprint 层没什么可砍」）。
(b) 建议：把角色文件纳入处理面 —— 但这是 scope 变更，要你或 Lead 点头，我不自决。

● 局限与已知缺口
  • 全部建议无 A/B 数据背书，一律「审计假设」。这是本单的设计，不是疏漏。
  • 审计深度不齐：层 A/B 是逐字（本 runner 自己收到的注入原文）；层 C 只到结构（章节 + 实测字节，没逐字读完 32KB/24KB）；层 D 只到口径（description/body 分列测量，没逐条评 22 份 body）。结构/口径的行，置信度明显更低 —— 每张卡都标了深度。
